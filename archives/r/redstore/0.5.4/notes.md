- 第十轮真机根因（2026-09-29 08:48 UTC，同一指纹复现：/bin/sh ./configure 下 configure[140] 仍报 hnp bash inaccessible, exit 127）: 上一轮“tc.environment() 钉 SHELL + 前缀放 cd 之前”被证伪两处——① `VAR=x cd dir && cmd` 的赋值只作用于 cd 内建，到 configure 时已丢失；② tc 生成的 toolchain 脚本拼不过 profile buildenv 聚合（DRAFT-6487 classads 定论：profile 向 conanbuild 注 CONFIG_SHELL=/data/service/hnp/bin/bash），RUN 行前缀纵使写对，configure 内重 exec（上游 configure 第 135 行 `exec $CONFIG_SHELL`）拿到的仍是坏值。本轮换不同路线（radcli/1.2.11 已验证模式）：generate() 不再碰 SHELL（只留 PkgConfigDeps + toolchain 旗标供 load_toolchain_args 复用）；build()/vendor/package 所有 configure/make/make check/make install 改经 `cd dir && umask 022 && TMPDIR=… CONFIG_SHELL=/bin/sh SHELL=/bin/sh "绝对configure" 参数`（赋值紧贴命令，逐命令覆盖聚合）并 `env="conanbuild"`；configure 改 umask 077→022（radcli/zzuf 口径，替代上轮的 mktemp 垫片与剥离）；make 用 PATH 裸 make；check 落盘 hmbs_make_check.log 供尾部取证，计数仍走 test-suite.log 汇总块。

- Nineteenth-round fix (2026-09-30, vendored redland `make install` install-includeHEADERS Error 64): compile itself passed (libraptor2.a/libredland built, libtool install of .a OK); failure is the install program, not sources.
