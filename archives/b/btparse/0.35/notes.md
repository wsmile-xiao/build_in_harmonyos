## 探索过程（每项修改的依据）

1. `./configure` 无参 → `no acceptable C compiler found`: configure 只探测 gcc/cc，
   设备为 clang → `CC=clang`。
2. `cannot guess build type`: 2005-05-15 版 config.guess 不含 HarmonyOS/aarch64。
   先试 `scripts/patch-autotools-ohos.pl`（E007 标准入口），对 2005 版仅部分命中
   （config.guess 1 处 / config.sub 0 处，输出 Score 1/5）；且该脚本注入的分支用新版
   `GUESS=` 赋值风格，2005 版 case 之后没有统一 echo，导致静默无输出。最终按 2005 版
   文件结构手工改写：config.guess 增 `*:HarmonyOS:*:*` 分支（`echo …; exit ;;` 风格）
   + config.sub 参数解析后插入 aarch64-*-linux*/ohos 早退 case（对齐 a52dec 0.7.4
   的 CI 验证写法）→ 知识 E007/E072。
3. config.guess 在 `$TMPDIR/cgXXXXXX` 里写 dummy.c 报 `can't create … Permission
   denied`、configure 的 `./confstatXXXXXX` 里写 config.h 同样被拒、且 configure 退出
   码 0 但所有生成物缺失（config.h/Makefile 无一存在）——退出码不可信，必须查生成物。
   根因：HMDFS setgid 目录属主漂移，`umask 077` 产生的 0700 目录对任何身份都不可写。
   修复：config.guess 3 处 + configure 2 处 `umask 077` → `umask 022`（对齐 a52dec
   0002 补丁与知识 E011/E129/E136/E206；E206 已记录完全相同的 uid 漂移机制）。
   设备实测矩阵：umask 077→写失败；007/022→写成功；普通 mkdir -m 700 被 FS 强制为
   setgid 2771 → 写成功。
4. antlr/dlg 未触发：tarball 内 src/bibtex.g 与生成物 bibtex.c/scan.c mtime 相同
   (2005-04-05 02:54)，make 不重建；构建日志无 antlr/dlg 痕迹。设备无需 PCCTS 工具。
