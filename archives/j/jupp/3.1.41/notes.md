## ★更正本任务登记备注的旧结论
旧备注写"release 件**不含** configure（有 autogen.sh）⇒ 走 `autoreconf -fi` 自举路线，
需复用 ledmon 的 avahi/0.9_rc5 ELF perl launcher 方案"。**本轮实测否定**：源件内有

## 遇到的问题与解决方案

| # | 现象（逐字） | 根因（源码级） | 解决方案 |
|---|---|---|---|
| 1 | `Couldn't open '*joerc'` + `rc=1`，连 `--version` 都过不去 | 上游把**运行期数据目录当编译期常量烤进二进制**：`Makefile.in:270` `INCLUDES = -DJOERC="\"$(sysconf_joedir)/\""`（`COMPILE` 在 :116 用到 `$(INCLUDES)`），`sysconf_joedir = $(sysconfdir)$(sysconfjoesubdir)`，真机生成的 `Makefile:247-248` 逐字
`sysconfdir = ${prefix}/etc`、`sysconfjoesubdir = /joe`。conan 默认 `--prefix=/` ⇒ `strings bin/joe` 实测常量被烤成 `//etc/joe/`；而 `make install DESTDIR=<包>` 只把文件装进包里 ⇒ 二进制找的绝对路径上什么都没有。且 `rc.c:954 procrc()` 只做 `jfopen(路径)`（`*` 前缀**不是**"内建资源"机制），`path.c:408 init_JOERC()` 的 argv[0] 兜底整段在 `#ifdef __cygwin32__` 内 ⇒ **OHOS/POSIX 没有运行期 rc 搜索路径** | `generate()` 传 `--prefix=<package_folder>`；`package()` 传 **`DESTDIR=`**（空）把框架注入的 staging 前缀压掉 —— `conan/tools/gnu/autotools.py:87` 的命令拼装是 `make install <框架 DESTDIR> <我方 args>`，GNU make 规则**同名后者胜出** ⇒ 文件按 prefix 直接落在包根，编进去的常量与安装位置天然一致。**零补丁文件、零上游源码逻辑修改**（唯二原地动作是 #4 的 umask 与 chmod 执行位，见下）。反证：若保留 DESTDIR，产物路径会叠成 `<包>/<包>/bin/joe`（第 4 轮实测到该双份形态并因此失败） |
| 2 | `Invalid configuration 'aarch64-unknown-linux-ohos': machine 'aarch64-unknown-linux' not recognized` | `config.sub` 虽是 2019 版仍不认 OHOS 三元组（逐字报错见左） | 显式传 `--build/--host=<autoconf CPU>-unknown-linux-gnu`（由 settings.arch 经映射表得到：conan 的 `armv8` → autoconf 的 `aarch64`；实测直接拼 armv8 会被 config.sub 原样回显成 `armv8-unknown-linux-gnu`，非规范名）。⚠ 这是**偏离**检查清单 §12.1 常规写法的实测决定（同仓 ledmon 等 host 侧写 `-linux-ohos`），原因即左列逐字报错；真实目标由 CC 侧 OHOS clang wrapper 决定。**不是** E467/P-AUTOTOOLS-001 禁止的"用 `--host` 绕过 `cannot run C compiled programs`"——本包无该症状，无 run 探测需要绕 |
| 3 | `./config.guess: can't create /storage/Users/currentUser/cgXXXX.../dummy.c: Permission denied` | 自动探测会往 `$HOME` 根写临时件（家根禁止落新文件，且该处不可写） | 由 #2 的显式 `--build` 顺带绕开：传了 `--build` 就不再调 `config.guess` |
| 4 | `make: *** [.../aclocal.m4] Error 127`（同类包必犯，本包按预防姿态处理） | automake 维护者规则解包后判定生成物过期，去跑 OHOS 上不存在的 `aclocal` | `make` 与 `make install` 两处都传 `ACLOCAL=: AUTOMAKE=: AUTOCONF=: AUTOHEADER=:` |
| 5 | `Couldn't load termcap entry; using ansi default` | 默认档零依赖 ⇒ jupp 用**自带** termcap 解析器，设备无 `/etc/termcap` | 上游已自处理（回落 ansi 默认，仅告警不致命），未做任何"补 termcap 文件"的伪适配 |
| 6 | 无控制终端环境下 `joe` 一律 `Couldn't open /dev/tty` rc=1 | 上游在**参数校验之前**就开 `/dev/tty`（实测 `--version`/`-help`/非法选项尾串一律相同）⇒ 非交互调用不可能 rc=0 | 不伪装通过：CI 侧可断言 rc=0 的真实行为面改用 `bin/termidx`（stdin→解析器→stdout）；`joe` 在无头下**断言其失败签名**含 `Couldn't open /dev/tty`；真机可用性另做一次性 pty 验证（见已知限制 #2） |
| 7 | 首次 `test()` 崩：`ConanException: The conanfile ... doesn't declare any requirement` | `test_package/conanfile.py` 漏 `requirements()` | 补 `self.requires(self.tested_reference_str)`（AGENTS §9 要求的写法） |

## 对上游件的实际改动（`patches: []` 不等于零改动，故显式申报）
1. **已应用的唯一一处源码文本改动**：`build()` 内 `_relax_umask()` 原地把 `configure` 的
   `umask 077` 改成 `umask 022`（E011/E114：HMDFS 下 `config.status` 的 077 临时目录不可写）。
   不经 `patches` 机制 ⇒ 不出现于 `patches_applied`，在此申报；同仓 ledmon 0.97 用同一 helper
   并同样申报。
2. **执行位**：`configure` 解包后常为 660（E543 同族），配方 `chmod 0755`（失败不致命，
   `Autotools.configure` 以 `$SHELL` 起）。属文件模式，不改内容。
3. **未改动**：`Makefile.in`、`config.sub`、任何 `.c/.h` 均零改动；#1 的修法完全在 conan
   配方层（`--prefix` + 空 `DESTDIR=`），无 `.patch` 文件。

## 已知限制
1. `joe` 是交互式 TUI，在无控制终端的环境（CI worker、非交互 SSH）**无法完成任何调用**，
   实测逐字 `Couldn't open /dev/tty`；故 `test_package` 不在该路径上断言 rc=0，只断言其
   失败签名。
2. 真机一次性 pty 验证（不进 CI，仅留证）：`ssh -tt` 分配 `/dev/pts/1` 后 `joe --version`
   的 TUI 完整起来，画面逐字 `[ Joe's Own Editor v3.1jupp41 | utf-8 | © 2022 mirabilos ]`、
   状态栏含 `Ctrl-K H for help` ⇒ 产物在本机可执行、可初始化终端界面。
3. `N_static=0` 属上游事实（本包无自动化测试），适配未新增上游层测试；真实行为面由
   `test_package` 的 5 条消费者断言承担。
4. 包内 `JOERC` 常量绑定**构建期包目录**（#1 的修法所致）。这是上游"编译期常量 + 无运行期
   搜索路径"的设计后果；若换机器构建，该常量为那台机器的包路径。CI 与本机各自构建自己的
   包 ⇒ 行为一致。
5. `--enable-curses/--enable-termcap` 未启用（默认零依赖档）。若后续需要完整终端能力
   （颜色/复杂 termcap），应改为依赖 `ncurses/6.4` 并重新验证，本轮不改口径。
