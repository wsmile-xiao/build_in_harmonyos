## 编译步骤

```bash
# 配方实际执行（build()/package()，全部前缀 env -u CONFIG_SHELL SHELL=/bin/sh）
cd <source_folder>
sh ./configure --prefix=/ '--bindir=${prefix}/bin' '--sbindir=${prefix}/bin' \
    '--libdir=${prefix}/lib' '--includedir=${prefix}/include' '--oldincludedir=${prefix}/include' \
    --build=aarch64-unknown-linux-gnu --host=aarch64-unknown-linux-gnu
make -j1
make install DESTDIR=<package_folder>/
```

- `--build/--host` 都显式写 `aarch64-unknown-linux-gnu`：tarball 自带 2001-08-13 版
  `config.sub`，不认识 `linux-ohos*`，而 `config.guess` 在 HarmonyOS 上直接
  "unable to guess system type"（units/vo-aacenc/direvent 同族先例）。
- CFLAGS 追加 `-fcommon`（见下表 #4）。
- `package_type = application`：交付 `bin/isoqlog`、`etc/isoqlog.{conf,domains}-dist`、
  `share/isoqlog/{htmltemp,lang}` 与 `share/doc/isoqlog`，无库/无头文件，故 `package_info()`
  的 libdirs/includedirs/libs 置空。

## 遇到的问题与解决方案

| # | 问题 | 根因 | 解决方案 |
|---|------|------|----------|
| 1 | `configure: error: cannot run /data/service/hnp/bin/bash ./config.sub` | 设备 OHOS profile 的 `[buildenv]` 把 `SHELL/CONFIG_SHELL` 指向 hnp bash，autoconf 用它 re-exec configure；本机 `/data/service/hnp/bin/bash` 实测不存在 | 与 direvent/5.5 同法：configure/make/install 一律 `env -u CONFIG_SHELL SHELL=/bin/sh` 前缀（E386 家族） |
| 2 | `configure: error: C compiler cannot create executables`（Error 77） | 首轮误用仓库 CI profile：其 `compiler_executables` 指向 `/data/service/hnp/bin/clang`，本机 `/data/service/hnp` 整体 Permission denied | 本地验证改用影子 profile（指向 `~/usr/local/bin` 的真实 clang），CI 仍用仓库 profile；本条是本地操作事故，不进配方 |
| 3 | `rm: /storage/Users/currentUser/csoBGkDg/in: Permission denied` + 8× `./config.status[1006]: can't open Makefile` + `make: No targets specified and no makefile found.` | autoconf **2.53** 的 config.status 用 `(umask 077 && mktemp -d -q "$TMPDIR/csXXXXXX")`；HMDFS 上 077 继承父目录 setgid 变成大写 S、目录不可写，于是 config.status 静默产不出 Makefile（E011/E114） | 配方内 `replace_in_file(configure, "umask 077", "umask 002")` 一次改到**该文件里全部 2 处**（pristine `configure:4386` mktemp 与 `:4391` mkdir 回退，实测 `grep -n umask` 只有这两行；`replace_in_file` 默认全量替换），保留真实临时目录创建逻辑；并把 `TMPDIR` 钉到 build_folder：设备 `TMPDIR=$HOME` 且 `/tmp` 只读，不钉会把 `csoXXXXXX` 散件落在家根（AGENTS §4）。E011/E114 的受控豁免口径见正文"源码改动" |
| 4 | `ld.lld: error: duplicate symbol: cur_month`（Store.o vs Dir.o 的 `.bss`） | clang 15 默认 `-fno-common`，而上游把**暂定定义写在了头文件里**：pristine `isoqlog/Dir.h:9` 一行 `int cur_year, cur_month, cur_day, cur_hour, cur_min, cur_sec;`（非 `extern`、非 `static`），该头被 5 个 TU 包含（`Dir.c`、`Html.c`、`Store.c`、`loadconfig.c`、`main.c`）⇒ 每个 .o 都在 `.bss` 里发一份同符号（经验汇总 §12.21/§12.49(f) 的同族形态） | `tc.extra_cflags.append("-fcommon")` 恢复合并语义；同时 `conan remove 'isoqlog/2.2.1' -c` 清掉旧 build 目录——残留 .o 会让症状一模一样 |
| 5 | 打包件能跑、`-h/-v/配置校验` 全过，但**只要日志里有 ≥1 条可解析邮件行就 SIGSEGV（rc=139）**；空日志反而 rc=0 并产出 13 份报表 | `Data.h` 把排序表声明成 `struct SortDomain { int *allusers; }`，`Data.c` 以 `SortDomain.allusers[n] = (int)usr` 存指针：LP64 下设备 jemalloc 堆地址远超 32 位（两次取证均在 `0x63_xxxxxxxx` 量级：诊断期 `6377001000-6377201000`，2026-09-24 19:3x 复取 `6386a01000-6386c01000 [anon:native_heap:jemalloc]`，见 `~/tmp/uc2/hw-2/isoqlog-2.2.1/heapaddr-evidence.log`；ASLR 让每次具体值不同，但恒 > `0xFFFFFFFF`），截成 int 再符号扩展即非法地址，Html.c 的 `u = (user *)SortDomain.allusers[i]; u->from_cnt` 必然段错误。32 位时代两型同宽故从未暴露，编译/链接期也无任何告警 | `patches/0001-isoqlog-Data.h.patch` + `0002-isoqlog-Data.c.patch`：元素类型改为真实指针类型 `user **allusers`，`addUserToSortTab()` 的 `int *u`/`(int *)malloc(sizeof(int *))`/`(int)usr` 与 8 个 `sort*()` 的 `int tmp` 一并改成 `user *`，语义零改动（纯类型修正，不改算法、不改输出）。修复后 create-10.log 12/12 断言通过 |
**问题 #5 的定位手法（沉淀为路径 B 草稿）**：本机 `lldb` 不可用
（`Error relocating .../liblldb.so: PyExc_AttributeError: symbol not found`），拿不到回溯，
于是按"**数据量二分**"收敛：同一份配置下依次喂 0 条 / 1 条 `from=` 无 size / 1 条 `from=` 带 size /
1 条 `to=` 带 size / `from=` 无 @ 域名 —— 结果"无 size"这一格 rc=0（它在
`parseSendmailFromBytesLine()` 里 `checkUser()` 之前提前 return），其余全 139，
把故障面精确夹到 `checkUser()` 下游的记账/报表路径，再读 `Data.h` 容器元素类型即锁定。

**该二分的完整取证留档**（逐 case 原始输出在 `~/tmp/uc2/hw-2/isoqlog-2.2.1/probe/<case>.run`；
8 组输入、同一份配置、只改日志内容，修复前二进制 `sha256` 前缀 `7e684e38` 于
2026-09-24 19:5x 复测的 rc 与 `*.html` 产出数逐行留档
`~/tmp/uc2/hw-2/isoqlog-2.2.1/bisection-htmlcount-evidence.log`）：

| case | 日志内容 | rc | 产出 html |
|---|---|---|---|
| `empty` | 0 行 | **0** | 13 |
| `no_size` | 1 行 `from=` 但**缺** `size=`（在 `checkUser()` 前提前 return） | **0** | 13 |
| `from_only` | 1 行 `from=…, size=1024` | **139** | 1 |
| `to_only` | 1 行 `to=…, size=2048` | **139** | 5 |
| `both` | 上面两行 | **139** | 1 |
| `no_at` | 1 行 `from=<alice>`（无 @，走 hostname 分支）带 size | **139** | 9 |
| `to_no_at` | 1 行 `to=<bob@nodomain>, size=512` | **139** | 9 |

即：只有"0 条"与"缺 `size=` 的早退分支"两格 rc=0 且把 13 份报表全部写完，其余 6 格一律
`Signal 11 (core dumped)` 且报表在途中断（产出数 1/5/9 取决于崩在哪一张表）——
崩溃与记录条数强相关、与内容无关。修复前 `conan create` 的同批断言计数：

"空数据集能产出完整报表"正是本缺陷的**假绿面**，也是本条知识最值得记住的一点。

12. 非当月的日志行被忽略（`check_syslog_date()` 日期闸门成立）

**测试日志必须在运行时生成**：`Parser.c:check_syslog_date()` 只接受"月份缩写 + 日"与本机
当天都相等的行，静态 fixture 会随日期腐烂、每月 1 号在 CI 上必失败；断言 12 因此改用
"必然不等于本月的月份缩写"（`Jun`，当天恰为 Jun 时取 `Jul`）而不是设备不支持的
`date -d yesterday` / `date -v-1d`（toybox date 两者皆无）。

## 注意事项

- **不带 `-f` 时找不到配置，属预期行为**：`main.c:27` 的 `getopt(argc,argv,"f:hv")` 循环里只有
  `case 'f'` 会置 `f=1`，`main.c:53-56` 于是在 `f == 0` 时回退到 configure 期烘死的 `CONFIGFILE`
  （`configure:3845` 逐字 `#define CONFIGFILE "${prefix}/etc/isoqlog.conf"`，源头 `configure.in:39` 的
  `AC_DEFINE_UNQUOTED`）；
  本包 `--prefix=/` 使该宏展开成 `//etc/isoqlog.conf`，真机实测 `isoqlog`（无参数）打印
  `loadconfig: cannot open isoqlog configuration file //etc/isoqlog.conf, exiting...`（`loadconfig.c:43-45`
  的 `fopen` 失败分支，`exit(-1)`）并以 255 退出。
  ⇒ 使用者必须 `-f <conf>`（或把样例配置装到 `etc/isoqlog.conf`），消费者测试的 12 条断言全部显式传 `-f`。
- **`-h` / `-v` 是 `exit(0)` 短路**（`main.c:29-35`，打印点分别在第 30 与 34 行）：`-v` 打印
  `VERSION_STRING`（实测 `EnderUNIX Isoqlog 2.2.1`），`-h` 打印 `Usage: isoqlog [-f isoqlog.conf]`，
  两者都不读配置，
  因此这两条冒烟在修复前后都会通过——这也是本包"崩溃要等到有记录才现形"的直接印证。
- **`htmldir`/`langfile` 必须显式配成绝对路径**：isoqlog 不像多数工具那样查安装前缀，
  报表模板与语言文件路径完全取自配置文件（`CONFIGFILE` 只固定了配置文件自身的位置）。
- **`logtype` 只认 5 个值**（`qmail-multilog`/`qmail-syslog`/`sendmail`/`postfix`/`exim`），
  其他值打印 `Invalid logtype:` 并以 255 退出。
- **sendmail/postfix 路径下 `to=` 行不计字节**：`parseSendmailToLine()` 以 0 字节调用
  `checkUser()`，所以报表里的容量统计只覆盖发送侧，写断言时期望值不能把 `to=` 的 `size=` 加进去。
- 配方不依赖设备上的 hnp bash；`env -u CONFIG_SHELL SHELL=/bin/sh` 前缀对健康环境无副作用。
- 本包无上游自动化测试，功能证据完全由消费者测试承担；若后续上游发布带 `make check` 的版本，
  应改为在 `build()` 内真实执行并按五维账本重报数字。
