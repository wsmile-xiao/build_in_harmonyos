## 高难度分析

DOSBox Staging 不是单一命令行包装，它同时覆盖动态指令重编译、图形与输入、音频合成、网络设备模拟、跨平台构建探测和目标 ELF 签名。适配必须在不引入 `OHOS` 名称条件编译宏的前提下维持上游行为，并把依赖、构建、测试、签名和安装包消费绑定为同一快照。

1. **AArch64 动态重编译与目标可执行文件闭包**

命中 `HD3_COMPLEX_ARCHITECTURE`：含汇编、闭源二进制、特殊调度等复杂架构。上游动态核心会在运行时生成主机指令并管理代码缓存、页保护和失效逻辑，源树还包含 AArch64 动态重编译实现与汇编文件；目标测试 ELF 和最终安装 ELF 均需保留执行权限并按最终字节签名，不能用编译成功替代运行验证。

2. **十一项直接依赖与完整目标测试成本**

命中 `HD4_LARGE_DEPENDENCY_TEST_COST`：依赖链庞大、全量测试校验成本极高。当前配方固定 11 项直接 Conan 依赖，选定闭包包含 16 个 Conan 引用，W0 图共 17 个节点并下载 15 个非跳过包；必须在禁止依赖回退构建的条件下核对每项 RREV、package ID、PREV、包清单和链接，再执行 24 项上游测试及 1 项安装包消费者流程。

3. **发布归档、测试框架与证据身份的跨阶段一致性**

官方发布包没有 Git 元数据，但 Meson 配置需要版本来源；GoogleTest 1.14.0 与 WrapDB 补丁也必须由官方 URL 和 SHA-256 预置并禁止运行时下载。历史事务暴露过 pkg-config 嵌套头目录、最终 ELF 重签名、Conan cache key 与 package ID 混淆、候选清单排序及验证器常量漂移等问题，因此当前通过结果必须由同一 HEAD/tree、单次 launch、完整 WAL/receipt 链和释放后 clean scan 共同证明。

4. **图形、输入、音频和动态核心的能力边界不能由 dummy 后端代替**

DOSBox Staging 的目标价值在于真实运行 DOS guest，而不是只生成一个可启动二进制。SDL 图形与输入事件、MIDI/音频合成、网络设备模拟和 dynrec guest workload 分别依赖不同的目标运行时能力；当前 24 项上游测试与安装包消费者能够证明冻结范围内的构建和基础执行，但不能自动证明非 dummy 音频、真实图形呈现或动态重编译负载。验收必须把已执行、expected failure、能力缺失和未覆盖项逐项列明，禁止用静默禁用后端、空实现或消费者启动成功替代功能证据。

5. **HMDFS、安装布局、执行位与最终签名形成不可拆分的制品完整性链**

历史适配已暴露 HMDFS 硬链接/符号链接物化、POSIX mode 丢失、安装后 ELF 需要重新签名、Conan cache 路径形态和包清单排序等问题。其共同根因是“源码树中正确”不等于“安装包最终字节、权限和签名正确”：复制、Meson install、Conan 打包或远端转移中的任一阶段都可能改变目标身份。影响是测试二进制可以通过而最终消费者仍以 RC126、路径错配或清单漂移失败。验证必须绑定最终安装 ELF 的 SHA-256、owner execute 位、签名后字节、包清单与目标端消费者结果，并在 release 后再次确认本任务远端根和进程均已清零。

6. **当前候选与历史事务必须按完整身份区分**

r71/r172 的测试快照、事务回执和清理结果是有价值的历史证据；当前候选 r178 已在完整 HEAD `3901f085f182354cc7033f34cec8acb8507d192e`、tree `a95623dfa420e596f4c9fe521088b7a02a4fc3e1` 上独立完成目标验证。根因是每次 W3/Review/CI 只对其绑定的完整身份有效；影响是旧 W3、旧 Review 或旧 CI 不能仅凭“属于同一分支”自动升级为当前 HEAD PASS。后续仍必须对 HEAD 变化做实质 diff 分类，并按绑定合同决定重跑定向验证、完整 W3 或仅更新非代码材料。
