本次提交以单一 Conan 配方为原子变更单元，并将平台差异限制在可审计的补丁、测试入口和源获取闭包内。路径 A 对应 OHOS arm64 的配方、工具链和签名闭包；路径 B 对应可迁移的源获取回退与动态代码权限验证知识；路径 C 对应图形、音频和动态重编译三个具有独立运行时边界的能力验证。三种路径描述的是同一候选中的不同贡献维度，不代表多个软件或多个独立交付物。

本轮 CI 修复补丁进一步约束两个可复核的跨平台边界：SDL2_net 的生成式 pkg-config 元数据必须同时暴露头文件与 provider library，POSIX 路径转换必须通过目录枚举恢复大小写保持的实际条目。两项修复均保持功能开启并在缺失或歧义时失败关闭。

针对 Buildbot 49526 在 dynrec 消费阶段暴露的 headless 输出边界，dynrec 与 normal-core 探针现在显式选择 `output=texture`，从而避免 dummy 视频环境尝试创建窗口；动态核心阶段标记、guest sentinel 与非零退出码的 fail-closed 校验保持不变。该修复只更新 CI 消费入口，不改写已封存的真机 W3 结果。

### 构建、依赖与源完整性

W0 依赖闭包包含 17 个图节点，`info_invalid=0`、`Missing=0`，15/15 个非跳过包以 `--build=never` 成功解析。OHOS 配方使用绝对编译器、归档器和签名工具路径，Meson toolchain 同时为 C/C++ 链接器写入目标 sysroot 与 `native_image` 库路径。源归档保留官方 GitHub URL 与 SHA-256；GoogleTest 下载在官方地址超时后只允许使用同一字节摘要的批准镜像候选，失败候选被删除，摘要不匹配或所有候选失败均立即终止，不会以未校验文件继续构建。

### 图形渲染能力

GUI 能力的验证对象不是版本字符串，而是 SDL 生产渲染链的最后可观察边界。消费者先在目标应用内部建立 NativeWindow surface tuple，再初始化 SDL 视频子系统及 OpenGL ES2 renderer；帧计数器只在生产渲染循环中的 `SDL_RenderPresent`/等价交换返回后递增，并通过 frame observer 读取 `frame_available=1`。因此，初始化日志、静态宏、离屏缓冲或人工写入的标志都不能单独构成通过。测试同时保留有界事件循环，使首帧提交不会因立即退出而被截断；驱动和 renderer 名称在输出中被绑定，确保断言来自目标图形栈而非 dummy provider。该设计覆盖 surface 创建、上下文建立、纹理提交、交换完成和观察者通知五个连续阶段，可定位“能启动但无呈现”“renderer 创建成功但交换失败”等不同故障。

### 音频输出能力

音频验证沿真实 mixer 到 OHAudio callback 的数据路径进行。测试在应用混音输出端注入受限幅度的确定性信号，依据协商后的采样格式、声道数与 frame size 计算回调缓冲区；回调仅读取有限帧并检查存在非零样本，不写入伪造数据，也不把设备打开成功解释为声音交付。`mixed_nonzero=1` 只在 OHAudio provider 已创建、回调实际被调度且最终转换前后保留非零能量时输出。格式协商失败、零帧、非法声道、回调超时和 provider 缺失均走显式失败路径并关闭设备。该过程能够区分“SDL 音频模块可加载”“mixer 产生数据”和“鸿蒙音频后端消费数据”三个层次，避免 dummy 音频或静态标记造成误判。

### 动态指令重编译能力

dynrec 验证选择生产 dynamic core，并要求两个相互独立的证据：其一是 dynamic core 进入并完成代码块执行的阶段标记，其二是 guest autoexec 实际输出 `DOSBOX_DYNREC_GUEST_SENTINEL`。动态代码缓存遵循 W^X：普通生产路径从 RW 映射开始，经既有权限转换路径切换为 RX；仅 capability probe 为隔离目标能力而保留 RWX。无效 block return 仅在探针环境下受控回退，默认生产路径仍保持原有错误语义。缓存初始化、代码生成、执行前后各阶段均使用 probe-only trace，且 trace 缺失、guest sentinel 缺失、动态核心未进入或退出码异常都会 fail closed。这样可将“选择了 dynrec”“生成了 host block”“host block 返回”和“guest 指令流真正推进”分开核验。

本候选的高难度判定基于四项可复核条件。HD1：OHOS 图形与音频能力要求 NativeWindow、OpenGL ES2 和 OHAudio 的私有运行时边界，通用 SDL 抽象不能替代目标 provider 的实际提交；证据为 NativeWindow/OpenGLES2 帧观察和 OHAudio 非零回调记录。HD2：OHOS arm64 构建必须同时满足 Meson、clang、llvm-ar、sysroot、native_image 链接参数和 binary-sign-tool 的组合约束，普通 Linux 配方无法直接复用；证据为绝对工具路径检查、签名 ELF 读回和安装后重新签名逻辑。HD3：dynrec 涉及动态代码页权限、host block 生命周期、无效返回回退及 guest 指令推进，错误可能表现为执行权限异常、静默回退或进程终止；证据为 W^X 映射、阶段 trace 与 guest sentinel 的联合断言。HD4：上游测试、依赖闭包和目标消费者具有不同分母，且图形事件循环、音频 callback 调度和 dynrec guest workload 均需有界运行窗口；证据为 24 个 Meson/CTest 目标、607 个 GoogleTest 实例、17 节点依赖图和消费者 1 个流程/4 个断言的分层记账。当前新增的 E6406 路径修复进一步证明，测试入口还必须在大小写不敏感 POSIX 挂载上保持目录项语义，不能以 `path_exists()` 的可达性替代规范路径。上述条件使该任务不适合仅以 `--version` 或单一静态扫描判定适配完成。

知识查重已覆盖 `knowledge/graph`、`knowledge/drafts`、`knowledge/doc` 与 `knowledge/operations`。E6401 记录了“辅助下载源超时时保留官方 provenance、按候选顺序执行、逐项 SHA-256 校验并清理部分文件”的通用机制；E6405 记录了依赖头文件可见但 pkg-config 缺少 provider library 时的链接闭包修复；E6406 记录了大小写不敏感 POSIX 挂载上必须通过 glob 目录枚举恢复规范路径的边界；toybox `mktemp` 条目记录了模板后缀差异及其边界。相关配对草稿随同一软件 PR 提交，不修改正式知识索引，也不执行任何制品仓上传。历史 r16、r62-r70、r174 仅用于诊断与失败溯源；它们不与当前候选拼接，不作为当前 CI 或真机通过的替代证据。
