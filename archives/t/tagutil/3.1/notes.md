# tagutil 3.1

- 上游：<https://github.com/kAworu/tagutil>，官方 v3.1 源码包 SHA-256：`a5a88f8f40c3654e902066e4aba8e6c4e2c89fcf64ca823d81db80c3dad41a80`。
- 构建：CMake；启用 libyaml、jansson、TagLib、FLAC 与 Ogg/Vorbis 后端。
- 鸿蒙适配：`src/CMakeLists.txt` 第 34 行无条件写入 `add_compile_options(-fstack-protector-strong -o aslr -fpie)`，没有按编译器分叉。`-o aslr` 会被 Clang 当成输出文件名，不是 ASLR 开关。补丁删除 `-o aslr`，保留 `-fstack-protector-strong -fpie`。可执行文件按 HarmonyOS 要求签名，并在签名覆写后恢复可执行位，否则 Cucumber 在场景开始前就因 EACCES 退出。
- 上游测试入口：`test/Makefile` 的 `bundle install --deployment` 在 Bundler 4 已删除；`Gemfile.lock` 的 `BUNDLED WITH 1.16.1` 会让 Bundler 4 改去执行已删除 `String#untaint` 的旧 Bundler。Ruby 4 不再默认提供 `ostruct` 与 `logger`。补丁 0007 仍在 Gemfile 声明这两个 gem 并去掉 1.16.1 锁定。实际安装不再调用 Bundler：配方用 Python 解包锁定版本，Makefile 改为执行 `vendor/prepared/run-cucumber.sh`。
- CI worker 的 Ruby 是 `/data/service/hnp/ruby.org/ruby_3.4.5`。构建 #74838 在 Bundler 的 17 个线程里，于 `open_file_with_flock` 收到 SEGV，处理函数里再收到 ILL。把 job 数固定为 1 之后，构建 #74913 不再进线程池（只剩 2 个 Ruby 线程），但在 `rubygems/package.rb` 的 `extract_tar_gz` / `copy_stream` 解包 `.gem` 时同样 `ILL received in SEGV handler`，`make vendor` 退出 134，场景汇总仍为 0。构建 #74987 已能跑到场景步骤，但 Ruby 3.4.5 在 `Open3.capture2e` / `Process.spawn` 里再次 `ILL received in SEGV handler`（当时只有 1 个 Ruby 线程）。补丁 0008 把这三处调用改成 libc `system()`，命令和退出码语义不变。场景文件不改，失败仍会使 `conan create` 失败。配方不调用 Bundler，也不调用 `make vendor` 里的 `bundle install`，解包留在 Python/Conan。
- 源码主机：CI #75002 能从 codeload 下到 tagutil 源码，但读取 `https://rubygems.org/gems/backports-3.11.3.gem` 超时。同日通过 CI 的取源是 codeload（puredata #13882）、`www.gnupg.org`（gpgme #13444）和 `github.com` 归档（libbtrfs-dev #13778）。因此 17 个 Cucumber 依赖写在 `conandata.yml` 的 `vendor_sources`，URL 用各仓库的 codeload tag，SHA-256 是该 tag 压缩包。`tag-expressions` 1.1.1 与 `cucumber-expressions` 6.0.1 的 Ruby 树在 `ruby/lib`。这些 tag 的 `lib/` 与 `bin/` 已与原先 51 场景所用 gem 逐文件对过，只有 cucumber 包里两个不被加载的 `*.rb~` 编辑器备份不在 git tag 中。`github.com/rspec/rspec` 没有 `v3.9.0` tag（codeload 返回 404），metagem 只有 `lib/rspec.rb` 与 `lib/rspec/version.rb` 两个文本文件，放在 `vendor-ruby/`。PR 不再提交 `.gem` 二进制：GitCode 的 pull diff 不含二进制数据，`git apply` 会在 checkout-pr 报 `missing binary patch data`。
