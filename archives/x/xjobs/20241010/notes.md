## Focused behavior corrections

Code inspection of the fixed upstream release shows clear_job() increments Failed and, with -e, stops scheduling, but does not update the process exit status. The job runner also hard-codes `/tmp/xjobs-XXXXXX` for captured output, which fails for sandboxed users when `/tmp` is root-owned and not writable. It now honors `TMPDIR` and falls back to `/tmp` when unset or empty. Both changes are captured by the framework-generated `ohc-run.py refresh-patch --auto` patch; its local `patch --dry-run` passed. The consumer checks nonzero parent status and that `-e` stops queued work, while the H1 harness sets a private writable `TMPDIR`. These are general fixes for upstream behavior and sandbox compatibility, not OHOS-only workarounds.

The `parse_args()` routine also advanced `optind` for a one-character ordinary base argument such as `0`, because it selected the next token as a redirection value before checking whether the token contained `<` or `>`. This shifted all subsequent command arguments and could place a null pointer in a job's base argument vector. Patch 0003 consumes the next token only for a standalone redirection operator and reports a missing redirection target. The consumer's zero-delay case guards this single-character template argument regression.

The framework's real staging verifier invokes every executable in `bin/` as `<binary> --version`. Upstream xjobs only accepts `-V`, despite printing a version string for that option. Patch 0004 adds `--version` as a compatibility alias while preserving `-V`; the consumer suite now checks the alias directly. This is required for the framework's real staging check and does not replace running that check.
