- 策略周期 4存档（2026-09-09，已被真机证伪）：上轮 shim 直调被真机证伪——`shim invocation failed: [Errno 8] Exec format error`，即 `HMBS_INSTALL`（`<runtime>/bin/install`）是个缺内核可用 shebang 的脚本，直接 execve 报 ENOEXEC；而 `/bin/sh` 在真机畅通（preflight.sh 自身就跑在上面）。本轮改经解释器显式驱动 shim（`/bin/sh shim -m 755 src dst`，另试不带 `-m` 形式），并输出 shim 头字节魔数；同时上轮“构建目录拷贝仍 EACCES”说明落点也可能 noexec，故依次尝试构建目录、HMBS tmpdir、`~/.local/share`（pipx python 在此子树可执行，为最佳可执行候选）三个落点，只接受通过 `--version`（≥18）探活的副本，成功后前置 PATH。缺可运行 `node` 仍抛错不跳过。tinyqueue vendoring、TAP 标记硬要求不变。
- 审查注意：本包非传统 C/C++ 库，无 `cpp_info.libs`、`commands.json` 不适用；`package_type` 沿用 `header-library` 表示无编译产物，`package_id` 已 `clear`。

- 策略周期 5（2026-09-09）：上一周期连续三次未通过，停用相同假设。证伪说明：周期4把“shim缺shebang+落点noexec”当根因，经shell驱动并试三个/ storage落点后，真机仍“Plain-copy fallback installed=True”且三处probe均为Permission denied（含pipx python可执行的~/.local/share子树），证明mode位/落点不是门禁。改走不同路线：OHOS对未签名ELF同样报Permission denied（abbtr/balboa先例），且runtime tmp为noexec、HMDFS缺mmap（numen先例）。本轮落点优先ext2可执行分区（/data/storage/el2/base/haps/entry/files、cache），HMBS_INSTALL改回直接调用（balboa正统，shell仅回退），拷贝后经llvm-objcopy清段+binary-sign-tool selfSign再探活--version。缺可运行node仍抛错不跳过。

- 策略周期 6（2026-09-09）：周期5证伪点不同。shim经shell返回rc=0但任务隔离目录下文件缺失（shim内部走只读/tmp），而纯拷贝处处installed=True；共享~/.local/share下签名成功后探活前文件消失（ENOENT），疑为并发客户端清理共享路径。改走不同路线：copy2优先、shim仅回退，落点只用任务隔离的build_folder与任务独立TMPDIR，删掉全局ext2与.local/share，探活前校验存在/大小/魔数。
