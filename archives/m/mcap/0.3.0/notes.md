# mcap 0.3.0 适配笔记

## 编译环境
- 构建系统: header-only（上游 CMake + Conan v1，仅编译/执行测试，无库产物）
- 编译器: clang/clang++ 15（OHOS profile，aarch64）
- 状态: built（待真机预检回填实测数字）

- 目录结构: 全仓归档（含 cpp/go/python/rust/swift/typescript/tests），C++ 头在 `cpp/mcap/include/mcap/`，C++ 测试在 `cpp/test/`，conformance 数据在 `tests/conformance/data/`

## 依赖说明
- 上游 `cpp/mcap/conanfile.py`（v1 语法）声明 `lz4/1.9.3` + `zstd/1.5.2`，`cpp/test/conanfile.py` 另需 `catch2/2.13.8` + `nlohmann_json/3.10.5`
- 制品仓已发布最接近的兼容版本为 `lz4/1.10.0.3`（R37 同上游 v1.10.0 适配后缀，锁定纯 Makefile 修订，详见第 19 行）、`zstd/1.5.7.1`、`catch2/2.13.10`、`nlohmann_json/3.12.0`，API 稳定（lz4/zstd 压缩 API、Catch2 v2 宏、nlohmann ordered_json 未 breaking），故 bump 到上述版本
- 本配方对运行时压缩库用 plain `requires()`，对上游测试库（catch2/nlohmann_json）用 `test_requires()` 以便 `build()` 内可用且不污染 `package_info()`（2026-09-27 真机实证：plain 会在 `package()` 后报 `direct dependency 'catch2' is not used`）；`package_id()` 已 clear，header-only 包 ID 不受影响

## 上游测试分析
- 官方 C++ 测试闭环为 `make test-host` → `./test/build/Debug/bin/unit-tests`（Catch2），共 8 个 `TEST_CASE`：
  1. `internal::crc32` [writer]
  2. `internal::Parse*()` [reader]
  3. `McapWriter::write()` [writer]（8 个 SECTION）
  4. `McapReader::readSummary()` [reader]（3 个 SECTION）
  5. `McapReader::byteRange()` [reader]（2 个 SECTION）
  6. `McapReader::readMessages()` [reader]（2 个 SECTION）
  7. `LZ4 compression` [reader][writer]（2 个 SECTION）
  8. `Read Order` [reader][writer]（1 个 SECTION）
- `cpp/test/CMakeLists.txt` 未调 `add_test()`，故 `ctest -N` 为 0；计数口径为 Catch2 `TEST_CASE` 宏（8），`upstream_test_count_method: auto`（单一可解析框架）
- conformance runners（`streamed_reader_conformance.cpp` / `streamed_writer_conformance.cpp`）为单文件 JSON 转换器，需 `tests/conformance/scripts/run-tests`（Node.js + TypeScript）做跨语言 diff，不在 `make test-host` 闭环内；本配方对其做 smoke：编译 reader runner，对 `tests/conformance/data/**/*.mcap` 取 5 个样本逐个运行，要求 exit 0 且 stdout 含 `"records"` 且长度 ≥32（非空 JSON），失败即判负
- 证伪预案：Catch2 汇总行必须为 `All tests passed (N assertions in M test cases)`；无该行、空输出、或 `FAILED` 即判负，不做 returncode 猜测修正

## 配方要点
- `package_type = "header-library"`，`no_copy_source = True`，`package()` 拷贝 `cpp/mcap/include/*.hpp` + `LICENSE`
- `validate()` 限制 `os in ("Linux", "OHOS")`（R32），C++17 及以上
- `build()` 内手动 `clang++ -std=c++17` 编译 `unit_tests.cpp`（include 含 mcap + lz4 + zstd + catch2 + nlohmann_json，link `-llz4 -lzstd`），运行并用正则解析 Catch2 汇总行，发射 `HMBS_UPSTREAM_TEST_RESULT`（framework `catch`）并持久化到 `res/upstream_test_result.json` 供缓存命中时重放
- OHOS 工具链注入的链接参数用 `-Wno-unused-command-line-argument` 抑制（沿用 magic_enum/mapbox-geometry 做法，不动测试语义）
- `test_package` 用 CMake + `CMakeDeps`，两个消费者程序均真实调用 `mcap::McapWriter`/`mcap::McapReader` API，失败 return 1
