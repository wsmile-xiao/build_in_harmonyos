# maeparser 1.3.3 adaptation notes

- Upstream is Schrodinger's official `maeparser` (https://github.com/schrodinger/maeparser), MIT-licensed C++11 library for parsing Maestro `.mae`/`.maegz` structure files. The v1.3.3 release tarball SHA256 is verified in `conandata.yml`.
- Zero patches. The upstream CMake build is used as-is with `MAEPARSER_BUILD_SHARED_LIBS=OFF` (static, repo convention) and `MAEPARSER_USE_BOOST_IOSTREAMS=ON` (gzip `.maegz` support via `boost::iostreams` + zlib).
- Two target-name mismatches between upstream CMake expectations and Conan CMakeDeps are resolved consumer-side in `generate()` via `cpp_info.set_property("cmake_target_name", ...)` (precedent: MilkyTracker): upstream `find_package(ZLIB)` expects `ZLIB::ZLIB` (Conan provides `zlib::zlib`), and upstream uses the `Boost_LIBRARIES` variable form (covered by overriding the boost aggregate target name).
- Upstream tests: the 7 test translation units from `test/` are compiled and executed in `build()`. Because the repo `boost/1.84.0` package does not ship a prebuilt `libboost_unit_test_framework`, the Boost.Test implementation is statically compiled from the official `boost/test/impl/*.ipp` sources shipped in the boost package (`test_package/ut_stub.cpp`, exported to the recipe as `test_sources/ut_stub.cpp` with `#define BOOST_TEST_SOURCE` — Boost.Test's documented manual static compile mode). `BOOST_SP_NO_PTHREAD_SETCANCELSTATE` is defined (OHOS musl lacks that API; same handling as the repo boost recipe).
- Test binary links `libmaeparser.a` + `boost_iostreams` + `boost_filesystem` + `zlib`; runs natively on the OHOS aarch64 host. Result: 69 test cases / 320 assertions, 0 failures, 0 skips (BufferSuite 10, MaeBlockSuite 7, MaeParserSuite, ReaderSuite, WriterSuite, DemoSuite 1).
- `test_package/example.cpp` uses only the installed public API (`maeparser/*.hpp`): `Reader::next`, `Block::getStringProperty/getIntProperty`, `getIndexedBlock`, `IndexedBlock::getIntProperty/getRealProperty`, `IndexedProperty::at/isDefined/at(i,default)`, and `Writer::write`. The MAE fixture is plain text embedded in the source (grammar verified against `MaeParser.cpp`: indexed blocks require a `[N]` size suffix; `<>` marks undefined values). It covers real parsing, exact value comparison, undefined-value semantics, EOF handling, truncated/malformed negative inputs, and a Writer round-trip.
