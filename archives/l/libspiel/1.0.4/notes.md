# libspiel 1.0.4 on HarmonyOS PC

Source: the upstream `SPIEL_1_0_4` tag (`2ab0230a7e685c57b5cca0498e9ddbad56c2f61e`), verified with the SHA256 in `conandata.yml`.

The published `libspeechprovider/1.0.3` recipe and OHOS armv8 binary were downloaded from `ohpcd`. The installed package contains `speech-provider-1.0.pc`, the C headers, and `libspeech-provider-1.0.so`. `gstreamer/1.28.3` and `gst-plugins-base/1.28.3` supply GStreamer and GStreamer Audio. The root recipe overrides their `zlib/1.3.1` requirement to `zlib/1.3.1.1`, which preserves the published speech-provider/GLib package graph. `conan create` downloaded matching binary packages; no other package was built from source.

Upstream 1.0.4 unconditionally generates a GIR and typelib. The published speech provider has no typelib, and the GI tool graph conflicts with the released GLib binary graph. The recipe makes introspection optional and turns it off; the public C API remains built and tested. Upstream's public `spiel.h` references `spiel-registry.h` and generated `spiel-provider-proxy.h`, but did not install those headers. The recipe installs them. It also repairs whitespace in Meson placeholders that otherwise leaves invalid version macros in the installed `spiel-version.h`.

On 2026-10-09, `conan create` with OHOS 6.0, armv8, Clang 15, libc++ and C++17 settings for both host and build completed. The package contains the static `libspiel-1.0.a`. The upstream schema validation test passed **1/1**. Ten separate installed C API consumer tests passed **10/10**, covering version, utterance properties, voice metadata and identity, and voice attachment. Total executed Meson tests: **11/11** (one upstream, ten added). The full native log is `/storage/Users/currentUser/libspiel-review-20261009/create-static.log`, SHA256 `f9e1a6f980585f5cc3a0f24f68e6fb36b05812b8a5651e052cb4bebb8685e602`; Conan package revision is `dc971d350c83d1ad4e0c0991a4f03ffd`.

The upstream census must count individual cases inside each Python TAP file, rather than just Meson test targets. At tag `SPIEL_1_0_4`, the seven normally registered Python files contain **29** `test_*` methods: `test_audio.py` 4, `test_errors.py` 2, `test_settings.py` 1, `test_speak.py` 8, `test_types.py` 3, `test_voice_selection.py` 6, and `test_voices.py` 5. Three D-Bus C executables and one schema validation make **33 upstream cases** in the base configuration. Meson registers these as 11 targets (seven TAP files, three C executables, one schema). With D-Bus >= 1.14.4, `test_provider.py` adds two conditional Python cases, making 35 cases / 12 Meson targets. The source census was taken from the SHA256-verified upstream archive in `conandata.yml`, using `tests/meson.build` and the `def test_*` methods in `tests/test_*.py`.

Only the upstream schema case ran on the HarmonyOS PC: **1/1 passed among executable upstream cases; 1/33 of the upstream base cases executed**. The other 32 base cases were not run: 29 Python cases need GI, `dbus-python`, `tap`, and `dasbus` modules unavailable in the published dependency graph, and three C cases need a D-Bus session. The HarmonyOS PC denied an independent Unix-domain socket `bind()` with `EPERM`; `dbus-daemon` failed for the same reason. No D-Bus speech playback, provider activation, or physical audio device test is claimed as passed. The ten package consumer tests exercise public C behavior without a session bus and supplement the one runnable upstream test; they do not replace the unexecuted upstream cases.

The recipe builds a static library to avoid Meson's shared-library install step rewriting the ELF RUNPATH and invalidating its OHOS loader signature. A source patch changes `shared_library()` to `library()`, and the Meson toolchain selects `default_library=static`; no generated Ninja file or linked ELF is modified. All four source patches were generated by the repository's `refresh-patch --auto` tool on the HarmonyOS PC and passed its dry-run checks. They are exported and declared in `conandata.yml`, then applied by `apply_conandata_patches`. The optional CLI is disabled because speech operations require a D-Bus session that is unavailable for verification on this HarmonyOS PC.
