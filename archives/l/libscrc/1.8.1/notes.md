# libscrc 1.8.1 HarmonyOS PC notes

- Upstream: `hex-in/libscrc`, tag `v1.8.1`; source archive SHA-256 is recorded in `conandata.yml`.
- Upstream `setup.py` declares seven CPython extensions. The HarmonyOS device has CPython 3.14, while CI uses CPython 3.12. The recipe supports both ABIs and defaults to 3.12 for CI; `python_abi` is part of the Conan package ID.
- With matching CPython headers and ABI suffix but no setuptools, the recipe directly builds the same seven module/table source pairs without a build-time Python dependency. It exposes the selected ABI's `site-packages` directory with Conan `runenv_info`.
- Upstream release sources already define `PY_SSIZE_T_CLEAN` in all seven extension modules; no source patch is needed.
- The upstream suite has nine `unittest` modules and 22 test methods. Worker builds #63182 and #63237 confirmed E212/E502: HNP CPython cannot `dlopen` extensions from writable user directories. Build #63248 then showed the worker's `/data/service/hnp/.../site-packages` (`platlib`) is read-only, so a writable native-module test location is not available. Changing `TMPDIR` cannot solve either restriction.
- The runtime-only fallback is limited to an active `platlib` located under the worker's `HNP_PUBLIC_HOME`. There it records that the 22 upstream runtime tests were **not run** and checks all seven built extensions for ELF format, AArch64 architecture, CPython ABI suffix, and the expected `PyInit_*` dynamic symbol. The consumer test likewise reports its two CRC vectors as **not run** and performs seven explicit static extension checks. This fallback does not claim algorithm or import coverage. A native-load permission failure in that HNP runtime also uses the explicit static check; unrelated worker errors and test failures remain failures. When `platlib` is writable outside the HNP runtime, both full runtime suites still run without changing upstream tests or assertions.
- HarmonyOS AArch64 device validation uses CPython 3.14.7 and an independent `CONAN_HOME=/storage/Users/currentUser/work/psj/ch-libscrc`. Runtime validation passed upstream tests 22/22 with 0 skips and consumer vectors 2/2; the OHOS CI HNP worker is reported separately because E212/E502 prevents equivalent `dlopen` coverage.
- There is no CLI executable, so `commands.json` is not applicable.

- CI build #63253 exited 127 after printing only the G0 knowledge-graph start line (0.458 s); it never reached L0 or this recipe. That run therefore provides no package-build or runtime-test result and does not implicate the HNP-only `NOT_RUN` path.
