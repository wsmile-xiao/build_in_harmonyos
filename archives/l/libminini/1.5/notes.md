## OHOS 适配结论

源码使用标准 `stdio`、`rename()` 和 `remove()` 接口。OHOS musl 提供这些接口，
且 OHOS Clang 定义 `__OHOS__`、`__linux__`、`__aarch64__`；musl 不承诺提供
`__MUSL__` 这类实现标识宏，因此测试不依赖私有 libc 宏。上游现有
Linux/POSIX 分支可直接工作。唯一补丁是在该分支包含标准
`<strings.h>`，为 musl 上使用的 `strncasecmp()` 补齐函数声明；不改变功能逻辑。

语言预检器最初把两个 C 文件和一个 C++ 消费者测试按 67% 阈值误判为 mixed。
按实际交付物重新核验：库实现只有 `minIni.c`，为 C 100%；C++ 能力由公共头文件
中的包装类提供，属于 C/C++ 兼容族。纠偏后的强制语言预检通过，两个上游测试
均继续纳入测试总数，没有删减。

## 消费者与 OHOS 专属测试

`test_package` 从 Conan 依赖元数据取得头文件和静态库路径，分别构建并运行：

1. C API 消费者：真实读写、整数、布尔、枚举、回调和删除。
2. C++ 包装器消费者：真实读写、默认值、枚举及删除。
3. OHOS 专属测试：编译期验证 `__OHOS__` 和 AArch64，运行期通过系统 libc
   验证 UTF-8 文件名/节/键/值及 LF 行结束符。

三项均实际链接 `libminini.a` 并调用公开 API，失败会以非零状态终止
`conan create`。适配后用例数为 47，不少于上游实测的 44。
