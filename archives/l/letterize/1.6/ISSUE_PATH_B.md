## 一、为什么这是"可跨仓库复用的知识"

本仓库 `test_package` 里存在一种默认心智模型：**"不可逆的输出只能靠硬编码期望值验证"**。
对枚举型/组合型工具（输入展开成大量候选），这会让判据退化：

- 一条断言只覆盖 78 行输出里的 **1 行**，其余 77 行完全不校验；
- 期望值往往从一次运行结果**反抄**，一旦实现有 bug，测试把 bug 固化成"期望行为"；
- 输出到 246 行时人工列举不可行，判据干脆退化为"能跑、有输出"。

**不可逆 ≠ 无约束**。本条给出替代方案：把判据写成**对每一行逐位校验的结构不变量**，
覆盖全部输出而不依赖任何期望值。它与本批次另一条草稿
（`DRAFT-LUNAR-ROUNDTRIP-PROPERTY-CONSUMER-TEST`，往返一致性）互补，共同覆盖
"可逆"与"不可逆但有约束"两类输出。

## 二、两条不变量

letterize 把电话号码展开为所有可发音助记词，输出**不可逆**（无法从一行助记词反推
唯一号码——实际上可以，但输出是集合而非单值）。但它的输出有两条硬约束：

| 不变量 | 内容 | 为什么必然成立 |
| --- | --- | --- |
| **P1 长度守恒** | 每行助记词长度 == 输入长度 | 逐位 1:1 映射；任何长度漂移都是实现缺陷 |
| **P2 键位约束** | 第 i 位字符要么 == 输入字符（输入位不是 2–9 时原样透传），要么 ∈ 该键位字母集合（2→abc … 9→xyz） | 美式电话键盘映射的定义 |

```c
static const char *g_keypad[10] = {
    "0", "1", "abc", "def", "ghi", "jkl", "mno", "prs", "tuv", "xyz"
};

static int line_ok(const char *line, const char *input, char *why, size_t whycap)
{
    size_t i, n = strlen(input);
    if (strlen(line) != n) {                       /* P1 */
        snprintf(why, whycap, "行 \"%s\" 长度 %zu ≠ 输入长度 %zu", line, strlen(line), n);
        return 0;
    }
    for (i = 0; i < n; i++) {
        unsigned char in = input[i], out = line[i];
        if (in >= '2' && in <= '9') {              /* P2 */
            if (!strchr(g_keypad[in - '0'], out)) {
                snprintf(why, whycap, "第 %zu 位：输入 '%c' 映射到 \"%s\"，输出却是 '%c'",
                         i, in, g_keypad[in - '0'], out);
                return 0;
            }
        } else if (out != in) {
            snprintf(why, whycap, "第 %zu 位：非数字键输入 '%c' 应原样透传，输出却是 '%c'",
                     i, in, out);
            return 0;
        }
    }
    return 1;
}
```

## 三、两个真实踩坑（已修）

### ① 字母集合大小写必须与被测输出一致

首版判据把集合写成大写 `"ABC"`，实测 **6 个用例全 FAIL**：

```
[FAIL] 逐位映射属性 (P1/P2) 全部行成立 — 第 0 位：输入 '2' 映射到 "ABC"，输出却是 'a'
```

这是**判据自身的缺陷**而非程序缺陷。修法：集合改小写 `"abc"`，同时保留一条 golden
首行断言（`adg`）锚定大小写约定——下次约定变化时先由 golden 断言报警，而不是让属性
判据产生一串难以定位的 FAIL。

### ② 属性成立时必须打印"校验了多少行"

否则 `0 行通过` 与 `246 行通过` 在日志里无法区分——**这正是假绿的来源**：

```
  [PASS] 逐位映射属性 (P1/P2) 全部 246 行成立     ← 真覆盖
  [PASS] 逐位映射属性 (P1/P2) 全部 0 行成立       ← 假绿，必须能区分
```

## 四、golden 断言的新定位：辅助锚点，不是主体

保留的 golden 部分只有 **非空行数 + 首行**（锚定词表过滤行为），属性覆盖每一行的
每一位。两者互补：

| 断言 | 数量 | 作用 |
| --- | --- | --- |
| golden 行数 | 8 | 锚定词表过滤行为（词表变化时会失败） |
| golden 首行 | 8 | 锚定大小写/格式约定 |
| 属性判据 | 8 | 逐行逐位校验，覆盖全部输出 |

**34 条断言，0 失败**；属性判据共校验 **353 行**输出的每一位，且**不含任何完整词表副本**。

外部对照表。
