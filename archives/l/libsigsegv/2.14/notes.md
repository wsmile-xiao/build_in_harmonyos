## 关键问题与修复（3 个补丁）

### 0001/0002: config.guess + config.sub（E007 标准适配）
GNU 官方 config.guess(2021) 无 HarmonyOS 分支，输出 aarch64-unknown-linux-ohos 需：
- config.guess：`*:HarmonyOS:*:*` case 分支
- config.sub：`ohos-linux` 解析 + `ohos*` OS 列表 + `linux-ohos*` kernel-OS 组合

### 0003-configure.patch: configure HMDFS tmp umask（核心坑，与 libffi 3.5.2 0002 同类）
- 现象：conan create 中 config.status 报 `./confXXXXXX/subs1.awk: Permission denied` → `could not setup config files machinery`
- 根因：HMDFS 用户存储区（~ 即 /storage/Users，目录 setgid 2771）上 `umask 077 && mktemp -d "./confXXXXXX"` 产生 **2700 权限目录**（无 group/other 且 setgid 继承），后续 shell 重定向写入被 SELinux/HMDFS 拒绝
- 实验证据：同目录下 `umask 022 && mktemp -d` 产生 2751 可写；`umask 077 && mkdir` 继承父目录 2771 也可写；仅 mktemp+077 组合不可写
- 修复：configure 中内嵌 config.status 模板的 tmp 段（位于 `cat >>$CONFIG_STATUS <<\_ACEOF` quoted heredoc 内，约 18931 行）按 `$host_os` 分支 umask：linux-ohos* → 022，其余保持 077。补丁 configure 一处即同时修复 configure 主流程与生成的 config.status
- 注意：refresh-patch 将 configure 判定为生成文件（头部 'Generated by' marker）不自动出补丁，需手动 `diff -u` 生成（libffi 3.5.2 先例同样直接补丁 configure）

### 工具陷阱：init-build 硬链接
`.orig`/`.work` 由 `copytree(copy_function=os.link)` 创建——直接编辑 .work 源文件会同步修改 .orig（同 inode），导致补丁 diff 为空。修改后必须 `rm .orig/<file> && tar -xzf tarball` 恢复基线。

## 平台差异观察（OHOS musl vs glibc，路径 B 素材）

configure 检测结论（aarch64-unknown-linux-ohos）：
| 检测项 | 结果 | 说明 |
|---|---|---|
| fault handler | fault-linux-arm.h | aarch64 走 arm 分支 |
| sigaltstack / stack_t | yes / yes | musl 实现完整 |
| working sigaltstack | yes | 备用栈可用 |
| correct stack_t interpretation | yes | |
| longjmp + sigaltstack 逃逸 | yes | |
| siglongjmp + sigaltstack 逃逸 | yes | |
| **setcontext 逃逸** | **no** | **musl 无 setcontext（glibc 有）**，属预期差异，不影响 libsigsegv 功能（走 longjmp 路径） |
| supports catching stack overflow | yes | 栈溢出可捕获 |
| stack direction | grows down | |

**栈溢出测试要点（消费者视角，可跨库复用）**：
1. 无限递归触发栈溢出前必须 `setrlimit(RLIMIT_STACK, 1MB)`（上游测试 test-catch-stackoverflow1.c 同款做法）。不限栈时递归一次越过 guard page 过深，SIGSEGV 故障地址远离栈区，libsigsegv 无法识别为栈溢出（emergency 判定失败），longjmp 恢复后再次崩溃——实测段错误。
2. 备用栈按上游 altstack-util.h 规范：SIGSTKSZ + 2×8KB crumple zone，传给 stackoverflow_install_handler 的指针 32 字节对齐。

**make check 5/5 PASS**：test-catch-segv1 / test-catch-segv2 / test-segv-dispatcher1 / test-catch-stackoverflow1 / test-catch-stackoverflow2。
平台报告行：`libsigsegv: aarch64-unknown-linux-ohos | yes | yes | 2.14`

## knowledge_gained（跨库复用模式，路径 B 素材）
1. **HMDFS mktemp+umask077 陷阱**：/storage/Users（用户存储区，目录 setgid）上 `umask 077 && mktemp -d` → 2700 目录不可写。影响一切 autotools 项目在 conan 缓存目录（~/.conan2 也在用户存储区）的构建。修复模式：configure tmp 段按 host_os 分支 umask（libsigsegv 0003 = libffi 0002 同型）。**这是继 libffi 后第二个实例，模式成立。**
2. **config.sub kernel-OS 校验缺口**：patch-autotools-ohos.pl 的 §2.3 补丁在部分 config.sub 版本上被 "already present" 误判跳过，`Invalid configuration: Kernel 'linux' not known to work with OS 'ohos'` 时手动补 `| linux-ohos*`。
3. **musl setcontext 缺失**：信号处理器经 setcontext 逃逸不可用，longjmp/siglongjmp 可用——影响依赖 ucontext 逃逸路径的库。
4. **musl 栈溢出触发规范**：setrlimit 限栈 + crumple zone 备用栈，参照上游 altstack-util.h。
