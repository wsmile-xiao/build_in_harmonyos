# libkal 0.9.0 notes

## Upstream census

- Source: the authoritative Debian/Launchpad copy of the original libkal 0.9.0
  archive, 22,678 bytes, SHA-256
  `cd2dea58cf3998abb6e61771584cfa9b424f598383e8b6e78ee99fbc99c73d30`.
- Build system: a handwritten Makefile producing the static `libkal.a`.
- Runtime dependencies: C standard library and the platform `date` command used
  by `kal_getdate()`.
- Measured upstream tests: 7 independent invocations. `check` is run once for
  each of `jul`, `gre`, `ar`, and `jew`; every invocation exhaustively checks
  5,000,001 Julian Day values from -1,000,000 through 4,000,000. The interactive
  `test` and `test1` examples are driven with deterministic Gregorian dates, and
  `test-dw` exercises all seven weekday helper paths.
- Baseline result on Linux before adaptation: all four exhaustive checks print
  `0 errors found`; the three examples produce the expected non-empty output.
  The original `void main` leaves the four `check` processes with undefined
  status 19 despite their successful results.

## Build adaptation

- The recipe invokes the C compiler from
  `tools.build:compiler_executables`, as required for raw Makefile projects, and
  derives `llvm-ar`/`llvm-ranlib` from the same toolchain directory.
- Direct argument-vector execution avoids shell and `/bin/sh` assumptions.
- A writable task-local `TMPDIR` is propagated for the HarmonyOS device.
- Link commands derive the active compiler's SDK `llvm/lib`, verify its `lld`
  with GNU flavor, and prepend the matching `libxml2.so.16` only while linking.
  This prevents a worker's ambient library path from shadowing the SDK runtime
  without leaking host-tool libraries into execution of target test binaries.
- The package contains the static library, all six public headers, and COPYING.

## Source and upstream-test modifications

- `kal_getdate.c`: adds the missing `stdlib.h` and `kal_main.h` declarations.
- `kal_procs.c`: replaces old unprototyped dispatch pointers with exact typed
  pointers; the Julian Day argument remains `long` to preserve the LP64 ABI.
- `check.c`: adds `stdlib.h`/`string.h`, changes `void main` to `int main`, and
  returns failure when its existing error counter is nonzero.
- `test.c`, `test1.c`, and `test-dw.c`: use conforming `int main` entry points;
  the first two also include the standard declarations they call. Test inputs,
  algorithms, ranges, and expected results are unchanged.
- All source changes were generated by `ohc refresh-patch --auto` as six
  per-file patches and apply cleanly with `patch -p1`.

## Test evidence contract

- The main recipe builds and really runs all 7 upstream invocations on native
  HarmonyOS, checks their semantic success markers, and emits
  `HMBS_UPSTREAM_TEST_RESULT` with measured counts.
- `test_package/test_libkal.c` contains 8 functional API groups covering every
  calendar family, generic dispatch, validation, weekday helpers, and metadata.
- `test_package/test_libkal_ohos.c` is an additional HarmonyOS-only test. It
  requires `__OHOS__`, `__aarch64__`, and LP64 at compile time and confirms the
  ABI while calling the packaged Gregorian conversion API at runtime.
- No tests are disabled or replaced by stubs. Cross-host builds only compile and
  link the target tests; the required native execution is performed on the
  connected HarmonyOS PC.
