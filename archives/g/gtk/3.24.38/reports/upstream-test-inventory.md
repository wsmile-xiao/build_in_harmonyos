# Upstream test inventory and HarmonyOS results

## Upstream source inventory

The contest review independently enumerated 453 source-level test cases in the
upstream GTK+ 3.24.38 tag. This is the comparison baseline used by the PR
template. It is a pre-configuration inventory: it includes cases guarded by
platform backends and optional features that are not part of the HarmonyOS
Broadway-only package graph.

| Inventory stage | Count | Meaning |
|---|---:|---|
| Upstream tag source inventory | 453 | All source-level cases reported by the contest review for tag 3.24.38 |
| HarmonyOS Broadway Meson registrations | 237 | Concrete tests generated by the selected package configuration |
| Not registered in this configuration | 216 | Cases gated by disabled platform backends or optional features |

The 453-case source inventory and the 237-test Meson inventory are therefore
different measurements. The former must be used as upstream `N` in the PR
comparison table; the latter is the executable topology that the recipe can
validate and the HarmonyOS device can schedule.

## Concrete Meson inventory

GTK+ 3.24.38 conditionally enters both `tests/` and `testsuite/` when
`tests=true`. The verified source tree contains 192 files directly under
`tests/` and 1,524 files recursively under `tests/` and `testsuite/`. Those
file counts are not test counts: fixture files, reference images, CSS, UI data,
helpers, and generated-loop inputs are included.

Meson introspection after the HarmonyOS configuration reports exactly 237
concrete registered tests. The default setup selects 192 tests; the remaining
45 carry the `gtk+:flaky` suite tag and are excluded by the upstream default
setup. Suite membership overlaps:

| Suite | Registered memberships |
|---|---:|
| `gtk+` | 4 |
| `gtk+:a11y` | 44 |
| `gtk+:flaky` | 45 |
| `gtk+:gdk` | 8 |
| `gtk+:gtk` | 43 |
| `gtk+:reftest` | 136 |
| `gtk+:tools` | 2 |

The recipe fails if the concrete registration count changes from 237 or if a
required HarmonyOS-safe test disappears. This makes upstream test topology
changes visible during package builds.

## Full HarmonyOS device sweep

All 237 registered tests were actually scheduled on the HarmonyOS aarch64
device from the signed build tree. Meson project and test introspection selected
219 ELF executables/shared objects for incremental self-signing; every selected
ELF was verified to contain exactly one `.codesign` section. Build-tree
`libgtk-3.so`/`libgtk-3.so.0` and `libgdk-3.so`/`libgdk-3.so.0` aliases were
created from the signed versioned libraries before execution.

`/storage/Users/currentUser/ohpc-ci-shadow/runs/8875e428a2bc-20260820T105332Z-run-9240`

| Selection | Scheduled | OK | FAIL | TIMEOUT |
|---|---:|---:|---:|---:|
| Upstream default | 192 | 7 | 0 | 185 |
| `--suite gtk+:flaky` | 45 | 0 | 0 | 45 |
| Total | 237 | 7 | 0 | 230 |

The full sweep used Broadway and `--timeout-multiplier 0.1`. The multiplier
reduces an otherwise roughly 68-minute serial reftest wait while preserving
the original test binaries, selection, and assertions. It is sufficient to
identify the observed deterministic block: display-dependent tests enter
`gtk_test_init()` or a rendering path and then wait because the device has no
browser connected as a Broadway output client. There were no assertion
failures and, after the build-tree aliases were added, no dynamic-loader exit
127 failures.

The seven display-independent upstream tests passed in a second serial run
with their normal timeouts:

- `gtk+:bitmask`
- `gtk+:rbtree`
- `gtk+:typename`
- `gtk+:c++ keywords`
- `gtk+:rgba`
- `gtk+:test-simplify`
- `gtk+:test-settings`

## Enforced package gate

Every HarmonyOS package build enables the upstream suite, verifies all 237
Meson registrations, signs the concrete Meson project/test ELF targets, starts
an isolated Broadway server, and requires the seven display-independent tests
above to pass. The explicit Conan `test_package` remains a separate installed
artifact gate for the public CMake target, headers, shared libraries, version
API, `GtkWindow` type registration, ELF signing, and runtime dependency load.

The remaining 230 tests are not reported as passed or silently dropped. Their
full true-device execution and environment-limited timeout result are recorded
above. Converting them into pass/fail gates requires a real Broadway browser
output client (or another supported display server) plus deterministic theme,
font, accessibility, input, and reference-image conditions; that environment
is outside this library-only package recipe.
