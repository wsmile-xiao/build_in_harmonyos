An Alpine/musl investigation was deliberately not used as final evidence: stage1 could execute there, but stage2 self-hosting failed at `tokenize.c` because this fork assumes glibc header and linker layouts. Repeating the run on Ubuntu/glibc produced a clean `13/13` bootstrap and both complete driver suites, proving that the earlier stage2 failure was an environment mismatch rather than a project CI defect.

## Root Cause And Boundary

The package is a host/target split compiler:

- the executable itself is built for and runs on OHOS/armv8;
- its generated code is x86-64;
- OHOS/armv8 libc headers cannot validly describe generated x86-64 programs;
- native execution must use a matching x86-64 libc and runtime.

The completed Ubuntu/glibc run confirms that the previous `0/1962` result was a missing execution environment, not absence of upstream tests. It also gives real failure evidence: 23 programs do not compile, 19 built entries fail at runtime, and six Csmith entries lack their separate dependency.

No current project infrastructure blocker was observed. Earlier G0e/JC1 issues #2141 and #2142 were unrelated `main` defects, were repaired outside this branch, and CI #24519 passed afterward. WHPX is unavailable on the local Windows host, but QEMU TCG completed the full run; this is a local acceleration limitation, not a CI defect.
