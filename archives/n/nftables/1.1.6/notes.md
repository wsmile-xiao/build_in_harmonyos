# nftables 1.1.6 适配笔记

## 编译环境

- 构建系统: autotools
- 编译日期: 2026-09-14
- 编译器: clang/clang++ 15（HarmonyOS PC 真机 /data/service/hnp 工具链，与官方 CI 同源）
- 状态: built（待真机预检日志确认后升级）

## 编译步骤

1. 同步上游 main，切分支 `feat/nftables-1.1.6`。
2. 源码：`https://www.netfilter.org/pub/nftables/nftables-1.1.6.tar.xz`（sha256 `372931bd…ac2530c`）。
3. 依赖：`libmnl/1.0.5` 来自制品仓；`libnftnl 1.3.1`（官方 `https://netfilter.org/projects/libnftnl/files/libnftnl-1.3.1.tar.xz`，sha256 `607da28d…2f0bcffba8`）在配方 `build()` 内私有静态编译到 `build_folder/vendor/prefix`，`PKG_CONFIG_PATH` 指向其 `lib/pkgconfig` 与 PkgConfigDeps 生成目录。
4. 配置（最小依赖，OpenWRT 最小先例）：
   `configure --enable-static --disable-shared --with-mini-gmp --without-cli --disable-python --disable-man-doc --disable-debug`
5. `make -j1`，随后 `make check`（上游官方测试入口，真机实测计数以预检日志为准）。
6. 不调 `make install`（HMDFS 下 `install-libLTLIBRARIES` 落盘缺失，见问题 14）：`package()` 纯 Python staging；`.la` 永不进包；交付 `sbin/nft`、`lib/libnftables.a` 与头文件。

| 1 | `libnftnl` 制品仓无包，`requires` 会触发 R36/PF4 依赖闸 | 仓库内无 `libnftnl` 配方，单 PR 只允许一个库 | 不声明 `requires`，配方内用官方 tarball 私有静态编译（R49 私有 prefix，不碰 `/usr/local`），保持单 PR 原子性；待 `libnftnl` 独立发布后可改为 `requires` |
