## 一、正向：把"包含性契约"当判据（免对照表）

数值工具（插值、拟合、平滑、重采样）的**输出是一大串浮点数**，看上去只能靠
golden 向量验证。但这类工具的手册里常写着一条**包含性契约**：

> aspline: "It produces a similar set … and **includes the input set** on standard output."

翻译成判据就是：**每个输入点 (x, y) 都必须出现在输出中**。这条完全自闭合——
不需要任何期望表，且直接验证了工具最核心的语义（插值曲线必须过给定点）。

```c
/* P1 输入点包含性：遍历全部输出行，逐个核对输入点 */
for (j = 0; j < n_input; j++) {
    int found = 0;
    for (q = 0; q < lines; q++) {
        double x, y;
        if (!get_point(buf, q, &x, &y)) continue;
        if (fabs(x - XS[j]) < 1e-9 && fabs(y - XS[j]*XS[j]) < 1e-6) { found = 1; break; }
    }
    expect(found, "输入点出现在输出中", "");
}
```

实测（y=x²，5 个输入点，全部命中）：

```
  [PASS] 全部 5 个输入点都出现在输出中（实际命中 5 个）
  [PASS] 首点 x == 输入最小 x (0)
  [PASS] 末点 x == 输入最大 x (4)
  [PASS] 首末 y 与输入端点一致 (0 / 16)
```

### 配套的第二条：常量保持性

输入全为同一常量 `y = c` 时，**任何**正确的插值器都必须输出恒为 `c`
（插值曲线在两点间是直线，而两端相等 → 恒等）。这是一条极强的数值不变量：

```c
for (k = 0; k < 3; k++) {                  /* c ∈ {5, 0, -3.25} */
    /* 输入 5 个点全为 (x, c) */
    for (j = 0; j < lines; j++) {
        get_point(buf, j, &x, &y);
        if (fabs(y - c) > 1e-9) { bad = 1; break; }
    }
    expect(lines > 0 && !bad, "常量保持性", "");
}
```

实测 3 个常量 × 各 101 行全部通过：

```
  [PASS] 常量保持性：y=5 的全部 101 行输出仍为 5
  [PASS] 常量保持性：y=0 的全部 101 行输出仍为 0
  [PASS] 常量保持性：y=-3.25 的全部 101 行输出仍为 -3.25
```

★ 这两条**联合覆盖了插值器的两个方向**：P1 保证"过给定点"，P2 保证"不改动已确定的
值"。二者都是自闭合的，且对任意输入规模成立（可参数化）。

## 二、负向：三类"派生值"绝不能进断言

本包落地时**真实踩中三次**，全都是把**由环境/实现派生的值**写成了期望值。

### ① 程序名（取自 `argv[0]`）

用法行与版本串里的程序名来自 `argv[0]` 的 **basename**：

| 调用方式 | 输出 |
| --- | --- |
| `/tmp/aspline -h` | `usage: aspline …` |
| `/tmp/vf/spline -h`（复制成 spline） | `usage: spline …` |
| `-V` | `spline version 1.2` ← 不是 `aspline version 1.2` |

**本地验证时二进制叫 `aspline`，测试把包内二进制复制成 `<包名>` 后名字就变了**，
于是 3 条断言在 qemu 上直接挂：

```
[FAIL] -V: 输出含 "aspline version 1.2" — 实际输出: spline version 1.2
[FAIL] -a 缺参打印用法: 输出含 "usage: aspline"
```

**改法**：断言只取与程序名无关的部分——选项规格 `[-hv][-a [xstep]]…`、
`version 1.2`、`supply abscissas automatically`。同类派生值还有：绝对路径、
时间戳、PID、临时目录名、hostname、随机数。

### ② 单调性（想当然的"参数越大输出越多"）

`-n N` 的语义是"大约 N 个区间"，但**输出必须包含输入点**，所以当 N 要求的区间数
少于输入点数时无法再压缩，行数被输入点数托底 —— 于是行数**不随 N 单调**：

| `-n` | 2 | 3 | 4 | 5 | 10 | 20 |
| --- | --- | --- | --- | --- | --- | --- |
| 输出行数 | 5 | **7** | **5** | 9 | 14 | 21 |

`-n 3 → 7 行` 而 `-n 4 → 5 行`。断言单调性会假失败。

**改法**：改断言两条真实成立的属性——**行数 ≥ 输入点数**、**行数 ≤ 2n+2**
（"approx." 的合理上界），另在 n 远大于输入点数的**稳定区间**断言精确值
（`-n 20` → 21 行，实测成立）。

### ③ 退出码（上游未把它当错误）

`-a` 缺参数时，上游打印 `option requires an argument: a` **与用法块**，但
**退出码仍是 0**。把"错误路径必须非 0 退出"写进断言会假失败。

**改法**：断言"**报错信息 + 用法块 + 未因信号终止**"，并把实测退出码打印出来
留痕：

```c
rc = run_capture("-a", buf, sizeof buf);
printf("     [INFO] -a 缺参时实测退出码 = %d\n", rc);
expect(rc >= 0, "-a 缺参未导致进程异常终止", "");
expect_contains("-a 缺参", buf, "option requires an argument");
expect_contains("-a 缺参打印用法", buf, "[-hv][-a [xstep]]");
```

## 三、判别清单（写数值/CLI 判据前过一遍）

| 准备写进断言的东西 | 是否安全 | 处置 |
| --- | --- | --- |
| 输入点必须出现在输出中 | ✅ 安全（契约） | 直接断言 |
| 常量输入 → 常量输出 | ✅ 安全（不变量） | 直接断言 |
| x 递增 / 行列数关系 | ✅ 安全（结构） | 直接断言 |
| **程序名 / 路径 / 时间 / PID** | ❌ 环境派生 | 改断言与名字无关的部分 |
| **"参数变大输出必变多"** | ❌ 未验证的单调性 | 改断言上下界 + 稳定区间精确值 |
| **错误路径必非 0 退出** | ⚠️ 需实测 | 先测再定；若为 0 则断言"报错信息 + 未崩溃"并留痕 |

## 五、可套用范围

| 工具/场景 | 包含性契约 | 常量保持性 |
| --- | --- | --- |
| 插值 / 拟合（aspline、plotutils spline、gnuplot 平滑） | 曲线过给定点 | ✅ |
| 重采样 / 抽稀（`ts` 类、数据降采样） | 端点与关键点保留 | 常量输入→常量输出 |
| 图像缩放 / 卷积 | — | 单色图必须保持单色 |
| 单位换算 / 坐标变换 | 恒等变换点 | 零点保持 |
| 排序 / 归一化 | 元素集合不变（置换） | 常量数组不变 |
| 压缩（无损） | 往返一致（见往返一致性草稿） | — |

★ 通用原则：**先找手册里的"契约句"（includes / preserves / exact for / …），
把它翻译成属性判据；再把所有由 argv[0]、环境、时间派生的值从断言里剔出去。**
