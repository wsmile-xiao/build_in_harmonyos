# snooze

`snooze` 是"**在特定时刻运行一条命令**"的工具，设计目标是配合 runit 之类的
**服务监督系统**替代 `cron(8)`。它用**助记式时间语法**表达调度计划，并支持
ISO 周与年积日过滤。

## Versions

| Version | Status | Assertions |
| --- | --- | --- |
| 0.5 | built | 180 |

Homepage: https://github.com/chneukirchen/snooze

## 相对 cron 的差异

- 助记式语法（`-H 22` 而不是 `0 22 * * *`）
- **不可能出现重叠运行**（由监督系统保证，没有需要加锁的并发窗口）
- 可按 **ISO 周**（`-W`）与**年积日**（`-D`）过滤
- 无需中心守护进程；可被立即强制触发；可自定义日志
- 对系统时间跳变鲁棒
- 可用时间戳文件保证两次运行间的最小等待（跨重启有效）
- 支持随机延迟（`-R` / `-J`）、可变 slack（`-s`，因而不需要 `anacron`）
- 可临时从命令行直接运行

## Rosetta stone

| 需求 | cron | snooze |
| --- | --- | --- |
| 每天 00:05 | `5 0 * * *` | `-M5` |
| 每月 1 号 14:15 | `15 14 1 * *` | `-d1 -H14 -M15` |
| 工作日 22:00 | `0 22 * * 1-5` | `-w1-5 -H22` |
| 每 2 小时的第 23 分 | `23 0-23/2 * * *` | `-M23 -H0-23/2` |

## 用法

```bash
# 干跑：打印接下来 5 次会运行的时刻，然后退出（不进入等待）
snooze -n -H 0 -M 0 echo hi

# 工作日 22:00 执行备份
snooze -w 1-5 -H 22 /usr/local/bin/backup.sh

# 每月 1 号 14:15
snooze -d 1 -H 14 -M 15 /usr/local/bin/report.sh

# 分钟列表语法
snooze -M 1,3,5 echo hi

# 带抖动（真实执行时最多延后 30 秒）
snooze -J 30 -H 0 -M 0 echo hi
```

> ⚠ **测试或脚本中请务必使用 `-n`**：不带 `-n` 时 snooze 会 `sleep` 到下一个匹配
> 时刻才执行命令（可能是 19 小时后）。本包的消费者测试全部走 `-n`，零次真实睡眠。

## 时间模式

| 选项 | 含义 | 合法范围 |
| --- | --- | --- |
| `-d` | 月内日 | `1 ≤ n < 32` |
| `-m` | 月 | `1 ≤ n < 13` |
| `-w` | 星期（周日为 0 和 7） | `0 ≤ n < 8` |
| `-D` | 年积日 | `1 ≤ n < 367` |
| `-W` | ISO 周 | `1 ≤ n < 54` |
| `-H` | 小时 | `0 ≤ n < 24` |
| `-M` | 分钟 | `0 ≤ n < 60` |
| `-S` | 秒 | — |

支持范围（`1-5`）与列表（`1,3,5`）两种写法；越界时报
`number outside <lo> <= n < <hi>` 并以退出码 1 结束。

干跑输出格式（时区随环境，UTC 与 +0800 均可）：

```
2026-09-19T00:00:00+0800 Sat  0d 19h 23m  9s
2026-09-20T00:00:00+0800 Sun  1d 19h 23m  9s
2026-09-21T00:00:00+0800 Mon  2d 19h 23m  9s
2026-09-22T00:00:00+0800 Tue  3d 19h 23m  9s
2026-09-23T00:00:00+0800 Wed  4d 19h 23m  9s
```

带 `-J 30` 时每行末尾追加 ` (plus up to 30s for jitter)`。

## OHOS 适配

| 项目 | 说明 |
| --- | --- |
| 目标 | `aarch64-linux-ohos`（musl）|
| 源码 | 单 `.c`（`snooze.c` ~8.6 KB）|
| 外部库 | 无（零依赖）|
| patch | 无 |
| 构建 | 直驱 clang：`clang -O2 -w -std=gnu99 -o snooze snooze.c` |
| 产物 | `bin/snooze`（约 25 KB）；`share/man/man1/snooze.1`、`share/doc/snooze/README.md` |

上游 `Makefile` 只有 `all` / `clean` / `install`，其中 `install` 依赖
`mkdir -p` 与 `install -m0755`（交叉编译环境不需要），因此 `build()` 直驱 `clang`
只编译二进制。

## 测试

上游**不含任何测试套件**：`Makefile` 只有 `all` / `clean` / `install` 三个目标，
**没有 `check` 或 `test` 目标**；源码 tarball 内的 `sv/` 是 runit 监督脚本，
不是测试。

`test_package/test_snooze.c` 提供 **180 条断言，零次真实睡眠**。核心是四条
**时间无关不变量**：

| 编号 | 不变量 |
| --- | --- |
| P1 | `-n` 干跑恰好输出 **5 行**（上游定义即契约）|
| P2 | 每行形状匹配 `YYYY-MM-DDTHH:MM:SS[+-]ZZZZ Ddd …`（**只校验结构不校验数值**；时区偏移通配，CI 的 UTC 与本机 +0800 都能通过）|
| P3 | 5 个时刻**严格递增**（用 `days_from_civil` 折算成绝对秒后比较，跨月/跨年成立）|
| P4 | 打印的星期缩写与日期**自洽**——测试内**独立实现**日期→星期换算，不依赖任何历法对照表 |

P4 让测试自身成为历法正确性的**独立裁判**。实测覆盖跨年点：

```
  [PASS] 星期自洽 2027-01-01：打印 Fri / 独立计算 Fri
  [PASS] 星期自洽 2027-04-10：打印 Sat / 独立计算 Sat
  [PASS] 星期自洽 2028-04-09：打印 Sun / 独立计算 Sun
```

此外还覆盖：

- 8 组时间模式的字段约束（含范围 `-w 1-5` 与列表 `-M 1,3,5` / `-D 1,100,200`）
- 7 个越界选项的精确范围文案与退出码
- `-J` 抖动后缀的**正/负向对照**（有 `-J` 必须出现，无 `-J` 必须不出现）
- 无任何时间模式时的默认行为（每日午夜）

判据全程用 `popen` 内存管道直读，**不写任何临时文件**（OHOS 上 `/tmp` 只读）。
