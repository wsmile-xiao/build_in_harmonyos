## 关键适配点

### 1. GitHub tag tarball 不含 Makefile.in（自举）
GitHub archive 只有 configure.ac/configure，没有 Makefile.in/ltmain.sh/
config.guess。构建时必须自举：
`libtoolize --copy --force → aclocal -I m4 → autoheader → automake --foreign
--add-missing --copy --force-missing → autoconf`
用 `tool_requires automake/1.18 + libtool/2.5.4`（制品仓已发布；
abiword-plugin-eml 同款先例）。

**坑 A**：aclocal 必须能看到 pkg.m4（`PKG_CHECK_MODULES` 宏定义）。
系统 pkg-config 的宏在 `/data/service/hnp/pkg-config.org/pkg-config_0.29.2/
share/aclocal`，不在 automake 包的 ACLOCAL_PATH 里。不注入则 autoconf
报 11 处 `possibly undefined macro: AC_MSG_WARN/AC_DEFINE`，configure
中残留未展开宏 → 运行时 syntax error。已在 `_bootstrap()` 内联注入。

**坑 B**：automake --add-missing 会安装它自带（不识别 OHOS 的）的
config.guess/config.sub 到 build-aux/。对策：显式传
`--build=aarch64-unknown-linux-ohos --host=aarch64-unknown-linux-ohos`
（tre 先例），configure 不执行 config.guess，E007 规避。

### 2. E097: configure 临时目录权限
configure 的 `AS_TMPDIR` 用 `umask 077 && mktemp -d "./confXXXXXX"`；
在 HMDFS setgid 构建目录下 config.status 子进程写 `subs1.awk` 被拦
（Permission denied → "could not setup config files machinery"）。
配方内联 replace 为 `umask 022 && mktemp -d "$TMPDIR/confXXXXXX"`
（configure 是自举生成文件，refresh-patch 会丢弃其 patch，故不入 patches/；
tre 0002、unbound E129 同族）。

### 3. musl 无 `_res` 全局变量（patch 0001）
OHOS musl 的 resolv.h 是 stub：有 `res_init()/res_query()` 符号（实测
链接+运行 OK），但**没有** `_res` 全局变量、没有 `res_ninit`。
`dkim_res_init()` 的 `#else /* HAVE_RES_NINIT */` 分支里
`_res.options |= RES_USE_DNSSEC` 编译失败。RES_USE_DNSSEC 只是请求
DO bit 的可选优化（musl stub resolver 本来不返回 AD bit），用
`__GLIBC__` 守卫（portability 而非 OHOS 专属，R8 合规——有实质逻辑）。

### 4. libunbound.la 死路径（unbound 包遗留问题）
unbound/1.22.0 conan 包里 `libunbound.la` 的 dependency_libs 带
`//lib/libevent.la`（unbound 打包时 conan --prefix=/ + DESTDIR 烤死）。
libtool 链接 `-lunbound` 时解析 .la → `cannot find the library
'//lib/libevent.la'`。
对策：`generate()` 构建 shim 前缀目录（copy libunbound.a + include/ +
重写 .la，dependency_libs 指向真实 conan 传递依赖包的 -L 与
`-lssl -levent -lexpat -lpthread -lcrypto`），configure
`--with-unbound=<shim>`。
注意 .la 前 4 行必须有 `# Generated by *`（libtool `func_lalib_unsafe_p`
校验），否则 "is not a valid libtool archive"。
libevent/expat 必须显式声明为直接 requires（传递依赖的 package_folder
为 None，abiword 先例）。

### 5. E002: 上游测试 KEYFILE（patch 0002）
libopendkim/tests 的 t-testdata.h 硬编码 `KEYFILE "/tmp/testkeys"`，
/tmp 只读 → t-setup 66 个测试连锁失败。patch 改为相对路径
`"testkeys"`（落在可写的 tests 构建目录）。

### 6. E002: DKIM_TMPDIR（配方注入）
z-tag 测试（t-test52/t-test141）与 stub-DNS 测试（t-test73）通过
DEFTMPDIR（默认 /tmp）落临时文件。make check 注入
`DKIM_TMPDIR=<tempdir>/opendkim-dkim-tmp` 后 161/161 全过。
（t-test73 初判为 musl 兼容性问题，设 DKIM_TMPDIR 后实为临时文件问题，
已确认通过。）

### 7. --disable-filter 的取舍
opendkim 二进制（milter filter 守护进程）需要 sendmail/postfix MTA
运行环境才有意义；本包定位为库 + 工具，`--disable-filter` 关闭
（libopendkim/opendkim-genkey/opendkim-genzone/opendkim-testkey/
opendkim-testmsg 均正常构建）。这也让构建不依赖运行期 milter 环境。
其余可选功能（SQL/LDAP/Lua/memcached/rrdtool/jansson/curl/sasl/
lmdb/erlang/stats）全部保持默认关闭（R1 参数最少化）。

### 8. sbin → bin 归一化
上游把工具装到 sbin/，conan 布局用 bin/（L2/L4 门禁扫描 bin/）。
package() 里移动。包内不保留 libopendkim.la（其 libdir 指向构建树，
下游 libtool 会解析失败——与坑 4 同族）。

## libbsd 不声明依据（notes 存档）

configure.ac:211-283 的逻辑：
```
AC_CHECK_FUNCS([strlcat strlcpy], [strl_found="yes"],
  [AC_SEARCH_LIBS([strlcat], [bsd], ...)])
```
musl 原生提供 strlcat/strlcpy（glibc≥2.38 也有），AC_CHECK_FUNCS 命中
→ strl_found=yes → 跳过 AC_SEARCH_LIBS([bsd]) → 不需要 libbsd。
实测 build-config.h: `#define HAVE_STRLCAT 1` / `#define HAVE_STRLCPY 1`。
