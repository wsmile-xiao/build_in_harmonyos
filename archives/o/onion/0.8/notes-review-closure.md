# PR 14507 target test closure

The original consumer had seven checks in one HTTP roundtrip, not seven
independent test cases. It used fixed port 18099 and did not cover the real
HarmonyOS HMDFS export-local flow. Replacement checks stay active with NDEBUG,
use a private prebound port 0 listener, validate exact HTTP payload bytes, and
exercise a real UTF-8 file from a signed native library. Native r012 passed
89/89 upstream cases, 1/1 ordinary consumer and 1/1 Harmony-specific test.

Optional HTTPS and other optional backends remain disabled, but pthread-only
was an incorrect product closure: non-TLS WebSocket needs real SHA1 even when
TLS is off. A published OpenSSL public API supplies that mandatory hash.
The supported upstream suite is
enabled, including the optional HTTP-test curl provider (fresh --build=never
curl/OpenSSL/zlib closure verified). Explicit epoll selects the supported backend
instead of accidentally adding an undeclared libev dependency on HarmonyOS.

Source edits under onion-source-r001 are exploratory: modern CMake minimum;
shell invocation of git-version-gen; HarmonyOS actual-basename SONAME without
version symlinks; explicit test curl linkage; prerecorded fixture argv separated
from function selectors; private per-run loopback ports for network fixtures;
and no kill(-1) if an upstream child fork fails. All 17 final patches were
generated by the official refresh-patch entry. A fresh Conan patch replay
matched all 289 native-run source files byte-for-byte. The prerecorded fixture
fixes preserve malformed-content-length negatives, correct a valid bare POST
key expectation and request-method dispatch, and remove a double free of the
listenpoint-owned buffer. They are disclosed rather than described as unchanged
assertions. Native r011's genuine failure is retained separately.

and L0o misclassified the local variable named curl as an external command.

variable, keeping source patches and CMake arguments unchanged. No platform
