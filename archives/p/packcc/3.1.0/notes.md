# packcc 3.1.0 — HarmonyOS PC 适配记录

## 软件概况

- packcc = Packrat PEG 解析器生成器（arithy/packcc，MIT）。
- 读 `.peg` grammar → 生成自包含 `parser.c` / `parser.h`；支持直接/间接左递归、捕获/替换/位置/谓词、`-I` import 目录。
- 单翻译单元 `src/packcc.c`，无第三方依赖；上游提供 CMake 构建（`bin/packcc` + `share/packcc/import` install）。
- 用途：C/C++ 项目用 PEG 语法生成解析器（DownGoer/JSON/… 类工具链）。

## 适配要点

### CMake 构建原样可用
- `cmake.configure()` + `cmake.build()` 即可；conan CMakeToolchain 指向 OHOS SDK clang。
- install：`bin/packcc`、`share/packcc/import/*`（上游 install(DIRECTORY import)）。
- 许可证 MIT：package() 补 `licenses/LICENSE`。

### 版本信息与冒烟锚点
- `packcc --version` → `packcc version 3.1.0`。
- 生成文件头 `/* A parser generated by PackCC 3.1.0 */`。
- test_package：运行安装产物 `--version` + 用自带 `calc.peg` 生成 parser 并断言 `.c/.h` 落盘。

### 上游测试为何不整包进 conan build()（rule4 说明）
- 上游测试入口 `make check`（CMake custom target）执行 `bash tests/test.sh`，链路为：
  1. `test.sh` 为每个 `tests/*.d` 动态生成 `.bats` 文件（Bats-core 语法）；
  2. 调用 `bats tests/*.d`（需 **bats** 已安装）；
  3. `utils.sh` 的 `test_compile`/`run_for_input` 会用宿主 C 编译器**编译并运行生成的 parser ELF**，并与 `expected.txt` diff。
- OHOS CI 沙箱两个前置都缺失：无 `bats`；沙箱内新编译的 ELF 无 `.codesign` 无法执行（平台限制，vala 先例同）。
- 因此 build() 不集成上游 check（与 vala 0.56.19 同策略），真实端到端验证下沉到 test_package：运行安装产物对自带 grammar 生成 parser（真实消费场景）。详见 `test_package/MANIFEST.yml`。
- 若未来 CI 提供 bats 且允许执行签名后 ELF，可直接 `cmake.build(target="check")` 接入 46 目录全量回归。

### 已核实的统计
- 上游 `tests/` 共 46 个 `*.d` 目录（45 个测试组 + README），其中 38 个含 `input.peg` grammar。
- `make check` 需外部依赖：Bats-core、Uncrustify。
