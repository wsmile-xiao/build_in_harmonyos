## 遇到的问题与解决方案

| # | 问题 | 根因 | 解决方案 |
|---|------|------|----------|
| 1 | configure 报 cannot guess build type | autoconf 2.61 内联 config.guess 不认识 `uname -s`=HarmonyOS | configure 命令行带 `ac_cv_build=aarch64-unknown-linux-gnu`（生成的 Makefile 不消费 build/host，配方内按 arch 映射；不改源码） |
| 2 | config.status 生成 Makefile 时 `can't create ./confXXXX/out: Permission denied` | config.status 用 `(umask 077 && mkdir $tmp)` 建临时目录，OHOS/HMDFS 沙箱下 0700 目录不可写 | patches/0001 把 umask 077 改 022（与 ncurses/a52dec 配方同款修法） |
| 3 | configure.in 无条件 `LDFLAGS="-s -lncurses"`，烧死非宽字符库且丢外部链接路径 | 上游硬编码；env LDFLAGS 被覆盖（实测 configure 后 Makefile LDFLAGS=-s -lncurses） | make 命令行变量覆盖 `LDFLAGS="-s -L<lib> -lncursesw"`（命令行赋值优先于 Makefile 内赋值） |
| 4 | Makefile 编译规则只用 `$(CXX) $(CFLAGS)`，无 CXXFLAGS/CPPFLAGS | 上游 Makefile.in 如此 | ncurses 头文件路径并入 CFLAGS 覆盖值 |
| 5 | lib/timeRoutines.cpp 9 处 `non-constant-expression cannot be narrowed` 错误 | 2009 年代码在初始化列表收窄（uint32_t→int / int→double），新 clang 按标准拒绝；上游无 -Werror | make CFLAGS 加 `-Wno-c++11-narrowing`（不动源码；收窄截断语义与旧编译器一致） |
| 6 | 无参运行 SIGABRT（rc 134，uncaught std::string/const char* 异常） | OHOS 策略拒绝读 /proc/interrupts、/proc/diskstats、/sys/class/net；readFile() 打不开就 throw string、getDiskStats 读不到就 throw、findInterfaces() opendir 失败就 throw，均未捕获 | patches/0002 通用健壮性降级：三处改为返回空数据跳过对应渲染节（任何硬化 Linux 同样受益，无平台宏） |

## /proc 口径实测（OHOS 设备, 2026-09-25）

| 文件 | 状态 | procinfo 使用 |
|---|---|---|
| /proc/stat | 可读（cpu 汇总+cpuN 标准 10 字段） | CPU 占用/uptime |
| /proc/meminfo | 可读（MemTotal/MemFree/MemAvailable 等标准字段齐全） | Memory 节 |
| /proc/loadavg | 可读 | Load average |
| /proc/uptime | 可读 | uptime |
| /proc/vmstat | 可读（键值式，字段齐全） | page in/out 等 |
| /proc/net/dev | 可读（标准 2 行头+接口行） | 网络节（但受 /sys/class/net 限制，见下） |
| /proc/cpuinfo | 可读 | （procinfo-ng 实际用 /proc/stat cpuN 计数） |
| /proc/interrupts | **Permission denied（OHOS 策略）** | IRQ 节 → 补丁后优雅跳过 |
| /proc/diskstats | **Permission denied（OHOS 策略）** | 磁盘节 → 补丁后优雅跳过 |
| /sys/class/net | **Permission denied（OHOS 策略）** | 接口枚举 → 补丁后优雅跳过（网络节无数据） |
| /proc/stat btime 字段 | 缺失 → 报告 Bootup 显示 1970-01-01（仅显示瑕疵，不影响功能） | Bootup 行 |

结论：非全屏模式下 6/8 数据源可用，程序可运行且输出合理；被策略挡住的三个节优雅缺省。

## 注意事项
- 全屏模式（-n N/-d/-S 等带全屏的用法）需要 TERM 与 terminfo，且运行期经 initscr 进入
  curses 界面；本适配未改 curses 逻辑，交互全屏功能在真机终端下可用性以真机 TERM 环境为准
  （test_package 只覆盖非全屏模式，避免 CI 无 tty 假失败）。
- `procinfo -n N < /dev/null` 在 stdin EOF 时 select 立即可读、getchar() 得 EOF 循环不止 ——
  上游原样行为（健康终端下按 q 退出），不要在无 tty 环境用 -n 长跑。
- ELF 已 strip（LDFLAGS -s，上游默认），CI 签名由流水线处理。
