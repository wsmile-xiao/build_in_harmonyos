## Dependencies and build system

PortSMF has no third-party dependencies. The library comprises seven C++ translation units and uses only the C++ standard library.

The historical snapshot contains `configure`, `Makefile.in` and Autotools helper scripts, but the SVN import preserved the helper scripts with CRLF endings. On POSIX shells, `autotools/missing` fails before dependency files are generated. Rather than patching generated files or changing upstream sources, the recipe creates a minimal CMake build description using the exact source list from `Makefile.am`. It supports both shared and static Conan options, installs the four public headers, the BSD license and relocatable pkg-config metadata.

## HarmonyOS adaptation

- OHOS clang 15 builds all seven sources without source changes.
- The default package installs `libportSMF.so`; static builds install `libportSMF.a` through `shared=False`.
- The consumer target is exported as `portsmf::portsmf` and the pkg-config module is `portSMF`.
- No platform macro, stub or library behavioral workaround is used.

## Upstream test census and execution

The official tree contains one test source, `portsmf/trunk/portsmf_test/portsmf_test.cpp`. It defines exactly 33 named test functions (`test1` through `test33`); there is no CTest, pytest or Automake `TESTS` registration. The historical `main()` invokes only `test33` interactively, so the recipe renames its `main` symbol at compile time and links a separate driver that invokes each of the 33 functions independently.

The snapshot's `make_score()` fixture omits `seq->set_dur(2.0)`. Consequently tests 17, 19 and 21 request regions beyond the sequence's recorded zero duration and dereference a null return. Upstream later added exactly this initialization when reviewing all 33 tests. Patch `0001` backports that one-line test-fixture correction; it does not change any library source or test assertion.

Tests 32 and 33 expect external MIDI filenames that are absent from the snapshot. The driver supplies a valid MIDI file produced by the unmodified upstream `test4` setup before invoking those functions; their test bodies are unchanged. All 33 test cases execute and pass.

## Consumer and HarmonyOS-specific tests

The Conan `test_package` links the installed `portsmf::portsmf` target and runs eight independent cases:

1. default sequence construction
2. note creation and insertion
3. seconds-to-beats conversion
4. tempo-map update and query
5. time-signature measure conversion
6. binary serialization and unserialization
7. Standard MIDI File write/read round trip
8. HarmonyOS PC AArch64 little-endian ABI serialization and MIDI round trip

The adapted suite therefore contains 41 cases: the original 33 plus seven general consumer cases and one HarmonyOS-specific case. All 41/41 pass.
