# Channel.stop patch validation

Device attempt 4 failed exactly one upstream case: the immediate idle assertion
after `Channel.stop()` with queued audio. The final correction is a C source
patch, not a queue-test skip or delayed assertion.

## Patch checks

- Generated by repository `refresh-patch --auto` using the exact 2.6.1 sdist.
- Windows-only helper path rendering was normalized without modifying repo
  infrastructure; patch whitespace was normalized mechanically.
- The final Git-style patch SHA256 is
  `33faeec6584a4f542466d31b8b558a7c198bb57a146fbe1990399676f4199849`.
- Default `git apply --check` and GNU `patch --dry-run -p1` both pass; only
  `src_c/mixer.c` changes.
- Applying with `core.autocrlf=false` produces a byte-for-byte match with the
  target-validated work source, whose SHA256 is
  `50f4fcfc4704cdc73e1c85e2c0e820c7068b573b5ac8697aa0d168edcfd40e7a`.
- Queue ownership is transferred under the GIL before public `Mix_HaltChannel`.
- The finished callback also obtains the GIL before reading the queue.
- The detached reference is released after the halt; no private SDL API is used.

## Host regression

The exact original and patched C functions were compiled against a deterministic
SDL_mixer 2.8 callback-order model. The original failed immediately because it
restarted queued audio; the patched function passed seven scenarios including
reference release, repeated stop, idle stop, shared sound ownership, natural
queue progression, and the uninitialized error path. This is a host model,
not an execution of the OHOS wheel.
