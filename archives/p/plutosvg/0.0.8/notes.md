# plutosvg 0.0.8 适配笔记

## 编译环境

- 目标 worktree：`feat/plutosvg-0.0.8`
- 构建系统：CMake（上游同时提供 Meson，本配方以 CMake 为唯一构建入口）
- 适配日期：2026-09-13
- 目标平台：HarmonyOS PC arm64（OHOS/aarch64）
- 编译器：clang 15（`ci/conan/profiles/ohos-aarch64`）
- Conan：2.x（OHOS 适配版）
- 状态：built（配方与测试已编写，待 HMBS 真机预检）

## 编译步骤

1. W0 依赖检查：plutosvg 唯一的库依赖是 plutovg（`find_package(plutovg 1.0.0)`，失败回退到 `add_subdirectory(plutovg)`）；freetype 集成默认 OFF。plutovg 在本仓库仅有 `built` 状态、无可直接引用的已发布版本，且 GitHub 源码归档不含子模块内容，因此本配方不声明 Conan `requires`，改为在 `source()` 中把官方 plutovg 1.3.3 发布包 vendor 到 `plutovg/`（与 ableton-link vendor asio-standalone 同一模式）。
2. `source()` 解压 plutosvg 0.0.8（`strip_root=True`），再把 plutovg 1.3.3 解压到 `plutovg/` 子目录，对齐上游子模块布局。
3. `generate()` 经 CMakeToolchain 设置 `BUILD_SHARED_LIBS`（跟随 `shared` 选项，默认静态）、`PLUTOSVG_BUILD_EXAMPLES=OFF`、`PLUTOSVG_ENABLE_FREETYPE=OFF`、`PLUTOVG_BUILD_EXAMPLES=OFF`。
4. `build()` 执行 `cmake.configure()` + `cmake.build()`。上游无测试套件（无 `enable_testing`/`add_test`/`check` 目标，审计见 `test_package/MANIFEST.yml`），故不调用 `cmake.test()`，注释中写明原因（buildtorrent 同款处理）。
5. `package()` 执行 `cmake.install()` 并附带 `LICENSE`；一次安装产出 `libplutosvg` + `libplutovg` 两个库与两套 CMake config。
6. `test_package` 以 `find_package(plutosvg CONFIG REQUIRED)` 链接 `plutosvg::plutosvg`，ctest 运行 `test_plutosvg`（17 项真实 API 检查），`test()` 输出 `HMBS_TEST_PACKAGE_RESULT` 与 `HMBS_UPSTREAM_TEST_RESULT(no_tests)` 双标记。
