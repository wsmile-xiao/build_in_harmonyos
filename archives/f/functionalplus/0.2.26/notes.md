## 编译步骤

header-only 库，配方侧无编译动作，全流程四步：

1. `source()`：`get()` 官方 tag 归档
   `https://github.com/Dobiasd/FunctionalPlus/archive/refs/tags/v0.2.26.tar.gz`
   （sha256 `119894b4ab521d22e7dbd4692c364dc911cf206fca011071575658d4053e61f2`，
   与 conan-center-index `recipes/functionalplus/all/conandata.yml` 逐字一致）。
2. `build()`：仅 `apply_conandata_patches()`（`patches: []`，本版本零补丁）。
3. `package()`：把源 `include/` 树（49 个文件，含 `.hpp` 与 `.autogenerated_defines` 生成件）
   原样拷入 `include/`，`LICENSE` 拷入 `licenses/`。
4. `test_package`：CMakeDeps 消费 `find_package(FunctionalPlus)` +
   `FunctionalPlus::fplus`，编译并执行 10 断言消费者程序。

上游 doctest 测试套件在**配方外**、沙箱 HOME 下独立构建运行（与同上游已发布包
`archives/f/fplus/0.2.28` 的 `upstream_test_in_build: false` 先例一致）：

```sh
cmake -S test -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH=<doctest pkg>
cmake --build build -j4
HOME="$TASK_DIR/test-home" ctest --test-dir build -j4 --output-on-failure
# 100% tests passed, 0 tests failed out of 423
```

## 遇到的问题与解决方案

| # | 问题 | 根因 | 解决方案 |
|---|------|------|----------|
| 1 | 被审 tag 的源码宏数 423 与上游当前 HEAD 的 424 不一致 | 上游在 `test/result_test.cpp` 新增用例 `result_test - compose_first_error_and_result`（v0.2.26 之后的提交） | 按「声明 N 下界 = 上游当前 HEAD 注册数」取候选数法最大值 **424**，差 1 逐项归因 → NOT_RUN；被审版本注册的 423 例全部实跑全过 |
| 2 | `test_package` 若用 `assert()` 在 Release 下会整体失效 | CMake Release 默认加 `-DNDEBUG`，`assert()` 被编译为空操作 → 失败判通过 | 改用显式检查 + 计数器 + 非零退出码，10 条断言逐条打印 `[consumer] PASS/FAIL` |
| 3 | 同一上游已存在 `archives/f/fplus/0.2.28` 包 | `fplus` 是本仓既有包名，`functionalplus` 是平台任务卡与 CCI 的包名 | 按平台任务名建包；别名同源关系在 `manifest.yaml` 头注、本文件与 PR 正文三处披露 |
| 4 | doctest 断言数（1662）与用例数（423）数值不同 | 断言位于循环与宏内，同一用例可执行多条断言 | 四口径并列单列：N 采用用例口径，断言数作次口径，不与用例数混用 |
| 5 | 上游 `test/CMakeLists.txt` 需要 doctest CONFIG 包与 `include(doctest)` 模块 | 上游 conanfile.txt 声明测试依赖 doctest，本机未预装 | 用 ohpcd 远端已发布的 `doctest/2.4.11` 走 `CMAKE_PREFIX_PATH` + `CMAKE_MODULE_PATH`，不改全局环境 |

### 上游测试四口径（并列不混用，申报 N = 候选数法最大值）

| 口径 | 数值 | 取数命令 |

| 框架注册数 @被审 v0.2.26 | 423 | `ctest -N` → `Total Tests: 423` |
| 断言数（doctest 运行期，次口径） | 1662 | 39 程序 `[doctest] assertions:` 行求和 |

差额归因（424 − 423 = 1）：`test/result_test.cpp` 的
`result_test - compose_first_error_and_result` 为上游 HEAD 新增用例；其依赖的
`fplus::compose_first_error_and_result` 在被审 v0.2.26 的 `include/fplus/result.hpp`
中不存在（`grep -rn compose_first_error_and_result include test` → 0 命中），
无法对被审源码编译运行 → NOT_RUN。
