## 测试背景

### V3 → V4 的唯一变化

自 V3 测试后，SKILL.md 发生了**唯一**的重要结构变化：

**新增 §0 流程自省**（位于 SKILL.md 最顶部，固定元数据头之后，原有 §1-§7 之前）。

§0 内容概览：

| 子章节 | 核心内容 | 信息量 |
|--------|---------|--------|
| §0.1 双重身份 | 质检员 > 执行者；发现问题比完成任务更重要 | 高 |
| §0.2 监控什么 | 8 个监控类别（流程缺失/冲突/冗余、脚本不好用、知识导航错误、约束不生效、模板不完整、文档矛盾） | 高 |
| §0.3 什么时候记录 | 实时记录，不是等到最后 | 中 |
| §0.4 记录到哪里 | `reports/skill-feedback.md`（含模板格式） | 中 |
| §0.5 Phase 4 额外步骤 | 汇总 feedback → 回顾卡壳点 → 写入 manifest.yaml | 中 |
| §0.6 主编 AI 处理流程 | 提取 → 去重 → 排序 → 批量修复 → 关闭反馈 | 低 |

### 为什么这个测试很重要

§0 在 SKILL.md 中被标记为 **"🫀 这是你最重要的任务"**，优先级高于编译任务本身。但：

1. **PROGRESS.md 没有嵌入任何 §0 内容** — 致命约束速查 D1-D7 中没有提到"流程自省"或"skill-feedback.md"
2. **restore-session.sh 没有提到 §0** — 脚本输出的约束速查中不含任何流程质检相关内容
3. **KNOW_YOUR_WHY.md S12 虽然引用了 §0**，但 S12 本身也不在 PROGRESS.md 的速查清单中

这意味着 §0 是一个**纯记忆依赖**的高优先级内容——如果 V3 的防遗忘体系有效，§0 应该在 PROGRESS.md 和 restore-session.sh 中被提及；但实际上它不在。这是防遗忘体系的一个**结构性盲区**。

### 测试假设

> **假设**: §0 虽然在 SKILL.md 中被标记为最高优先级，但由于未嵌入 PROGRESS.md 和 restore-session.sh，其遗忘率将与其他未受保护的纯记忆内容类似（40-70%）。

### 4. §0 遗忘曲线的独特性

§0 是唯一一个**声明优先级与实际保留率严重倒挂**的内容：

```
声明优先级:  §0 (🫀最高) > D1-D7 (💀致命) > S1-S9 (🔴严重) > 工具 (🔧常规)
实际保留率:  §0 (21%) < S1-S9 (67%) < 工具 (100%) = D1-D7 (100%)
                                    ↑
                            完全倒序！
```

这个倒序揭示了 AI 遗忘的核心规律：

> **遗忘抗性 = 外部记忆覆盖率 × 信息独特性**
> 
> - PROGRESS.md 覆盖率高 → 抗压缩性强（A, D = 100%）
> - 信息独特性高 → 纯记忆阶段保留好（§0 的"质检>执行"在 R2 仍 100%）
> - 两者都没有 → 极速遗忘（§0 H2 监控类别 R4 = 0%）
