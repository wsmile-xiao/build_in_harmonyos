# E083: BiSheng JDK ELF 签名校验导致 JNI 库加载失败

## 问题

Java 应用通过 `System.loadLibrary()` 加载 JNI 库时报 Permission denied：

```
java.lang.UnsatisfiedLinkError: /path/to/libfoo.so: Permission denied
```

但同样的 .so 文件在 C 程序中通过 `dlopen()` 加载正常。

JNA/Py4J 等 JNI 框架在鸿蒙上报 Permission denied 加载 native library。

## 根因

BiSheng JDK 的 `NativeLibraries.load()` native 方法内部在调用 dlopen 之前，
额外校验 .so 的 ELF 签名（.codesign 段）是否与 JVM 自身签名匹配。

系统预装的 JDK（/data/service/hnp/）拥有系统级签名，而用户编译的 .so 只有
`binary-sign-tool -selfSign 1` 生成的自签名，签名不匹配导致拒绝加载。

注意：C 层 dlopen 不校验签名，所以 C 程序加载正常。

## 解决方案

### 即时修复

将 JDK 拷贝到用户可写路径，批量签名所有 ELF 文件，并使用签名后的 JDK 运行：

```bash
# 1. 拷贝 JDK 至可写路径
cp -a /data/service/hnp/bishengjdk17* $HOME/usr/local/bishengjdk17

# 2. 批量签名 JDK 所有 ELF 文件
python3 $SKILL_ROOT/scripts/ohc-run.py sign-elf --batch $HOME/usr/local/bishengjdk17

# 3. 签名 JNI 库（同一签名体系）
python3 $SKILL_ROOT/scripts/ohc-run.py sign-elf libfoo.so

# 4. 使用签名后的 JDK 运行
$HOME/usr/local/bishengjdk17/bin/java -cp app.jar Main
```

### 影响范围

- 所有使用 JNI 的 Java 应用（JNA, JNR, JFFI, Py4J 等）
- BiSheng JDK 17.0.13 on HarmonyOS
