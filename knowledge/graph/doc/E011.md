# E011: HMDFS 文件系统 umask 077 权限问题

## 问题

autotools 项目的 `configure` 脚本在 HMDFS 文件系统上运行时报 Permission denied：

```
./config.status: cannot create temp file: Permission denied
config.status: error creating tmp
cannot create `subs1.awk': Permission denied
cannot create `subs1.sed': Permission denied
```

这是因为 configure 脚本执行 `umask 077` 后用 `mktemp -d "./confXXXXXX"` 创建临时目录，
在 HMDFS 上新目录无法被当前进程写入。

## 根因

HMDFS 文件系统的 UID 映射机制导致 umask 077 创建的临时目录无法被当前进程写入。
autotools 的 configure 脚本在生成 config.status 时，使用 `mktemp -d "./confXXXXXX"`
创建临时目录，并先执行 `umask 077` 设置权限。

在 HMDFS 上，目录所有者 UID 被映射为 20001006，而进程实际 UID 为 20020083，
导致 0700 权限的目录对当前进程不可写。此外 HMDFS 可能给目录设置 setgid 位（02700），
进一步加剧权限问题。

## 解决方案

### 即时修复

将 configure 脚本中的 `umask 077` 修改为 `umask 022`：

```bash
sed -i 's/umask 077/umask 022/g' configure
./configure --prefix=$DEFAULT_PREFIX
```

umask 022 允许同组用户写入，在无多用户场景下安全。

### 备选方案

先运行 `configure --no-create`，然后编辑 config.status 中的 umask 值：

```bash
./configure --no-create --prefix=$DEFAULT_PREFIX
sed -i 's/umask 077/umask 000/g' config.status
./config.status
```

### 影响范围

**所有使用 autotools 的项目**在 HMDFS 上 configure 时均会遇到此问题
（xz, tar, wget, texinfo, vala, tmux, zsh, hwloc, gdb, nmap, flex, bison,
sparsehash 等已确认）。

## 补充方案

### 方案 D：修改 config.status 使用固定目录

在 HMDFS 上，`mktemp -d "./confXXXXXX"` 创建的临时目录权限为 `drwx--S---`
（仅 owner 权限 + setgid 位），`chmod` 命令也无法修改 HMDFS 上的目录权限。
当修改 umask 仍无法解决时，可以直接修改 `config.status` 使用固定的预创建目录：

```bash
# 1. 创建固定工作目录
mkdir -p tmp_work

# 2. 修改 config.status 中的 mktemp 调用
sed -i 's/mktemp -d ".\/confXXXXXX"/mkdir -p "tmp_work"/g' config.status

# 3. 运行修改后的 config.status
./config.status
```

此外，`configure` 脚本本身也存在 `umask 077` 的设置，需要同步修改：

```bash
sed -i 's/umask 077/umask 000/g' configure
```

此方案已验证适用于：**tmux, zsh, hwloc, gdb, nmap, flex, bison** 等软件。

### Header-only 库的解决方式（sparsehash 案例）

对于 header-only 库（如 sparsehash），由于不需要编译二进制文件，可以完全绕过
`config.status`，手动创建配置文件并安装头文件：

```bash
# 1. 手动创建 config.h
cat > src/config.h << 'EOF'
#define PACKAGE_NAME "sparsehash"
#define PACKAGE_VERSION "2.0.4"
#define HASH_MAP_H <unordered_map>
#define HASH_NAMESPACE std
#define SPARSEHASH_HASH HASH_NAMESPACE::hash
/* 根据 config.log 添加其他必要的宏 */
EOF

# 2. 手动安装头文件
mkdir -p $PREFIX/include/google
mkdir -p $PREFIX/include/sparsehash
cp -r src/google/* $PREFIX/include/google/
cp -r src/sparsehash/* $PREFIX/include/sparsehash/
```

验证方法：

```cpp
#include <google/sparse_hash_map>
#include <iostream>
int main() {
    google::sparse_hash_map<int, std::string> map;
    map[1] = "test";
    std::cout << "OK" << std::endl;
    return 0;
}
```

```bash
clang++ -std=c++11 -I$PREFIX/include test.cpp -o test && ./test
```

### 关键要点

- HMDFS 上 `mktemp` 创建的目录权限为 `drwx--S---`，`chmod` 无法修改（平台限制）
- 修改 `config.status` 使用 `mkdir -p` 创建固定目录是有效的绕过方式
- 不仅 `config.status` 中需要修改，`configure` 脚本本身的 `umask 077` 也需同步修改
- header-only 库可以完全绕过 autotools，手动安装头文件
