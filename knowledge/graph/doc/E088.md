# E088: HarmonyOS musl namespace 忽略 RUNPATH/LD_LIBRARY_PATH

## 问题

Python 3.12 预编译包解压后，`_ctypes` 模块无法加载 `libffi.so.8`：

```
ImportError: Error loading shared library libffi.so.8: 
  (needed by .../lib-dynload/_ctypes.cpython-312-aarch64-linux-ohos.so)
```

尽管设置了正确的 RUNPATH (`$ORIGIN/../..`)，并且 `libffi.so.8` 存在于上级 `lib/` 目录。

## 根因

HarmonyOS 的 musl 动态链接器 (`ld-musl-aarch64.so.1`) **完全忽略**：
- ELF 文件的 `RUNPATH` / `RPATH`
- `LD_LIBRARY_PATH` 环境变量

它使用 `/etc/ld-musl-namespace-arm.ini` 配置文件管理库搜索路径：

```ini
[acquiescence]   # /vendor/bin 下的程序
    namespace.default.lib.paths = /vendor/lib64:...:/usr/local/lib:/usr/lib

[systemscence]   # /system/bin 下的程序  
    namespace.system.lib.paths = /system/lib64:/lib64:...
```

用户安装的库在 `/storage/Users/currentUser/usr/local/lib/`，不在任何 namespace 路径中。

## 解决方案

### 即时修复

将外部依赖库拷贝到目标模块同目录（`$ORIGIN` 始终可用）：

```bash
cd $PREFIX/lib/python3.12/lib-dynload/
cp -L ../../libffi.so.8 .
python3 ohc-run.py sign-elf --batch .
```

### 打包脚本修复

在 `package_python.sh` 的 Step 4（收集外部依赖）后增加 Step 4.5，自动将 `lib-dynload/` 模块所需的外部库拷贝到同目录。

### 影响范围

- 所有依赖外部共享库的 Python 扩展模块
- 任何通过 dlopen 加载非系统路径库的程序
- **不影响**静态链接的程序
