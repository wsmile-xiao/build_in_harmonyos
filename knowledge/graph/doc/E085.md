# E085: musl pthread_cancel 缺失导致线程检测失败

## 问题

编译使用 GNU 线程检测机制的软件（如 libgpg-error）时出现链接错误：

```
undefined reference to 'pthread_cancel'
posix-lock.c: pthread_cancel weak symbol not found
```

部分软件在 configure 或编译阶段使用 `#pragma weak pthread_cancel` 检测 pthread 可用性，
在 musl 上检测逻辑失败。

## 根因

musl libc（OpenHarmony 使用）不实现 POSIX 线程取消 API，包括：
- `pthread_cancel` — 取消线程执行
- `pthread_testcancel` — 测试取消点
- `pthread_setcancelstate` — 设置取消状态
- `pthread_setcanceltype` — 设置取消类型

部分 GNU 软件（如 libgpg-error）使用 `#pragma weak pthread_cancel` 来运行时检测
pthread 是否可用。但在 musl 上，链接器找不到 pthread_cancel 的 weak symbol，
导致检测逻辑失败或链接错误。

musl 认为线程取消机制设计有问题，故不实现这些函数。

## 解决方案

### 方案 1: 定义 PTHREAD_IN_USE_DETECTION_HARD（推荐，适用于 libgpg-error）

在 config.h 中定义 `PTHREAD_IN_USE_DETECTION_HARD=1`，将线程检测从 weak symbol 方式
切换到 pthread_create 运行时检测：

```bash
echo '#define PTHREAD_IN_USE_DETECTION_HARD 1' >> config.h
```

### 方案 2: 提供 stub 函数（通用备选方案）

创建 `pthread_compat.c` 提供 POSIX 线程取消 API 的空实现：

```c
/* pthread_compat.c — stub implementations for musl libc */
#include <pthread.h>

int pthread_cancel(pthread_t thread) {
    (void)thread;
    return 0;  /* 返回成功但不执行实际操作 */
}

int pthread_testcancel(void) {
    return 0;
}

int pthread_setcancelstate(int state, int *oldstate) {
    if (oldstate) *oldstate = PTHREAD_CANCEL_ENABLE;
    return 0;
}

int pthread_setcanceltype(int type, int *oldtype) {
    if (oldtype) *oldtype = PTHREAD_CANCEL_DEFERRED;
    return 0;
}
```

编译并链接：

```bash
clang -c pthread_compat.c -o pthread_compat.o
# 链接时添加 pthread_compat.o
clang ... pthread_compat.o -lpthread -o <target>
```

**优点**：快速解决，不修改原有源码
**限制**：线程取消功能失效（影响异常终止场景，正常使用影响较小）

### 影响范围

- libgpg-error 及所有使用 gnulib/gcry 线程检测的 GnuPG 生态软件
- squashfs-tools 4.6.1
- redis 7.4.2
- mosquitto 2.0.18
- iperf3 3.18
- 其他使用 POSIX 线程取消功能的 C/C++ 软件

## 补充说明

### 直接链接失败场景

除了 weak symbol 检测失败的场景外，许多软件在源码中直接调用 `pthread_cancel` 等函数，
在链接阶段会遇到 ld.lld 报错：

```
ld.lld: error: undefined symbol: pthread_cancel
>>> referenced by restore.c
ld.lld: error: undefined symbol: pthread_testcancel
>>> referenced by mksquashfs.c
ld.lld: error: undefined symbol: pthread_setcancelstate
>>> referenced by thread.c
ld.lld: error: undefined symbol: pthread_setcanceltype
>>> referenced by thread.c
```

此类错误在以下软件中出现过：
- **squashfs-tools 4.6.1** — 直接调用 pthread_cancel / pthread_testcancel
- **redis 7.4.2** — 后台线程管理中使用线程取消
- **mosquitto 2.0.18** — MQTT 线程模式中使用线程取消
- **iperf3 3.18** — 测试线程控制中使用线程取消

### 完整的 stub 函数代码

以下代码覆盖 musl libc 中所有缺失的 POSIX 线程取消 API（4 个函数），
已验证在多个软件中可用：

```c
/* musl-compat.c — POSIX 线程取消 API 的 stub 实现
 * 适用于 OpenHarmony / HarmonyOS（使用 musl libc）
 * musl 不实现线程取消机制，这些空实现仅用于满足链接要求
 */
#include <pthread.h>

int pthread_cancel(pthread_t thread) {
    /* musl 不支持线程取消，返回成功但无实际效果 */
    (void)thread;
    return 0;
}

int pthread_testcancel(void) {
    /* 空操作 */
    return 0;
}

int pthread_setcancelstate(int state, int *oldstate) {
    /* 返回默认值 */
    if (oldstate) *oldstate = PTHREAD_CANCEL_ENABLE;
    return 0;
}

int pthread_setcanceltype(int type, int *oldtype) {
    /* 返回默认值 */
    if (oldtype) *oldtype = PTHREAD_CANCEL_DEFERRED;
    return 0;
}
```

| 软件 | 版本 | 错误模式 | 使用方案 |

| libgpg-error | 1.55 | weak symbol 检测失败 | PTHREAD_IN_USE_DETECTION_HARD=1 |

### 注意事项

- 线程取消主要用于异常终止场景，正常使用影响较小
- stub 函数返回 0（成功）但不执行实际取消操作
- 对于 mosquitto，也可通过 `-DWITH_THREADING=OFF` 禁用线程来规避
