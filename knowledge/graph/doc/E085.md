# E085: musl pthread_cancel 缺失导致线程检测失败

## 问题

编译使用 GNU 线程检测机制的软件（如 libgpg-error）时出现链接错误：

```
undefined reference to 'pthread_cancel'
posix-lock.c: pthread_cancel weak symbol not found
```

部分软件在 configure 或编译阶段使用 `#pragma weak pthread_cancel` 检测 pthread 可用性，
在 musl 上检测逻辑失败。

## 根因

musl libc（OpenHarmony 使用）不实现 `pthread_cancel()`。
部分 GNU 软件（如 libgpg-error）使用 `#pragma weak pthread_cancel` 来运行时检测
pthread 是否可用。但在 musl 上，链接器找不到 pthread_cancel 的 weak symbol，
导致检测逻辑失败或链接错误。

## 解决方案

### 即时修复

在 config.h 中定义 `PTHREAD_IN_USE_DETECTION_HARD=1`，将线程检测从 weak symbol 方式
切换到 pthread_create 运行时检测：

```bash
echo '#define PTHREAD_IN_USE_DETECTION_HARD 1' >> config.h
```

### 备选方案

添加空的 pthread_cancel() stub 函数以满足链接：

```bash
echo 'void pthread_cancel(void* t) { (void)t; }' >> src/stubs.c
```

### 影响范围

libgpg-error 及所有使用 gnulib/gcry 线程检测的 GnuPG 生态软件。
