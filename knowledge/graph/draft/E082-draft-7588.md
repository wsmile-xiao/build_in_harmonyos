# E082: Perl ldflags 中 -fstack-protector-strong 导致 ld.lld 失败

## 错误现象

```
ld.lld: error: unknown argument '-fstack-protector-strong'
Warning: ExtUtils::CBuilder not installed or no compiler detected
This distribution requires a C compiler, but it's not available, stopped.
```

## 根因分析

OpenHarmony 上的 Perl 5.42.0 在配置时将 `-fstack-protector-strong` 同时放入了：
- `ccflags`（正确——这是编译器标志）
- `ldflags` 和 `lddlflags`（错误——这些值被直接传递给 ld.lld）

ld.lld 不识别 `-fstack-protector-strong`（它是编译器标志，不是链接器标志），导致链接失败。当 `ExtUtils::CBuilder::have_compiler()` 尝试编译并链接测试程序时，链接步骤失败，编译器检测返回 false。

### 关键技术细节

1. **ExtUtils::CBuilder 的配置读取机制**：CBuilder 在 `new()` 中通过 `$self->{config}{$k}` 直接从 hash 读取配置值，绕过了 `Module::Build::Config->get()` 方法。因此通过 `$args{config}` 传递的覆盖值不会被 CBuilder 使用。

2. **Module::Build 编译器检测缓存**：`have_c_compiler()` 在 `_set_defaults()`（`SUPER::new()` 内部调用）中被首次调用，失败结果缓存在 `$self->{properties}{_have_c_compiler}`。后续调用直接返回缓存值。

3. **系统库路径缺失**：OpenHarmony 的系统库（libc.so、libunwind.a）位于 `/system/lib64` 和 `~/usr/local/lib`，但 ld.lld 默认不搜索这些路径。

4. **musl 头文件路径缺失**：系统 C 库头文件（sys/types.h 等）位于 musl 安装目录 `~/usr/local/include`。

## 解决方案

在 Module::Build 子类中覆盖 `cbuilder()` 方法：

```perl
sub cbuilder {
    my $self = shift;
    my $s = $self->{stash};
    return $s->{_cbuilder} if $s->{_cbuilder};

    require ExtUtils::CBuilder;
    require Config;

    # 复制 Perl Config 并修复链接器标志
    my %config = %Config::Config;
    if ($config{ldflags} =~ /-fstack-protector-strong/ ||
        $config{lddlflags} =~ /-fstack-protector-strong/) {
        $config{ldflags} =~ s/-fstack-protector-strong//g;
        $config{lddlflags} =~ s/-fstack-protector-strong//g;
        $config{lddlflags} .= ' -L/system/lib64 -L'
            . ($ENV{HOME} || '/data') . '/usr/local/lib -lunwind -lc';
        $config{ccflags} .= ' -I' . ($ENV{HOME} || '/data') . '/usr/local/include';
    }

    return $s->{_cbuilder} = ExtUtils::CBuilder->new(
        config => \%config,
        ($self->quiet ? (quiet => 1) : ()),
    );
}
```

同时在 `new()` 中清除编译器检测缓存：

```perl
# 在 SUPER::new() 之后，have_c_compiler() 之前
delete $self->{properties}{_have_c_compiler};
```

## 验证

```bash
perl -MModule::Build::XSUtil -e '
  my $mb = Module::Build::XSUtil->new(
    module_name => "Test", dist_name => "Test",
    dist_version => "0.01", license => "perl");
  print "have_c_compiler: ", $mb->have_c_compiler ? "yes" : "no", "\n";'
# 输出: have_c_compiler: yes
```
