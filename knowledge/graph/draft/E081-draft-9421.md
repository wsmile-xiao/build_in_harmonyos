# E081: Python subprocess posix_spawn 权限错误

## 基本信息

| 字段 | 值 |
|------|-----|
| 严重度 | 2 |
| 类别 | platform \| python \| subprocess \| selinux |
| 触发工具 | meson \| python \| build-system |
| 阶段 | build \| configure |

## 错误模式

### 典型错误日志
```
[Errno 13] Permission denied: [Errno 13] Permission denied
Traceback (most recent call last):
  File "/path/to/meson/mesonbuild/mesonmain.py", line XYZ, in run
    subprocess.run([tool, args...], check=True)
PermissionError: [Errno 13] Permission denied
```

### 典型场景
```bash
# Meson 构建系统调用 Python 脚本工具时
meson setup builddir
# 内部调用：subprocess.run(['glib-genmarshal', ...])
# 结果：Permission denied
```

## 触发条件

1. **构建系统**: Meson（使用 Python 编写）
2. **调用方式**: subprocess.run() 或 subprocess.Popen() 调用可执行工具
3. **平台**: HarmonyOS / OpenHarmony
4. **Python 版本**: 3.9+ (特别是 3.12，默认使用 posix_spawn)

## 根因分析

### 第一层：SELinux 域转换限制

HarmonyOS 的 SELinux 策略限制：
- Shell 进程（`hishell_hap:s0`）执行用户二进制时域转换为 `adhoc_bin:s0`
- `adhoc_bin:s0` 无权执行 `hnp_file` 类型的 SDK 工具（如 clang, glib-genmarshal）
- **关键发现**：通过 `fork() + execve()` 执行时被拦截

### 第二层：Python subprocess 实现变化

Python 3.12 在 musl/HarmonyOS 上：
```python
# Python 3.12 subprocess.py
_USE_POSIX_SPAWN = True  # 在 musl 上默认启用
```

| 行为差异 | fork+exec | posix_spawn |
|---------|-----------|-------------|
| errpipe 机制 | ✅ 子进程通过 errpipe 传错 | ❌ 父进程直接报错 |
| shell 内建命令 | ✅ shell 处理后 exec | ❌ `true`/`cd` 不可直接 exec |
| SELinux 限制 | ❌ 被 SELinux 拦截 | ⚠️ 行为不一致 |

### 第三层：历史演变（知识证伪）

**⚠️ 重要发现（2025-03-25 证伪）**：
- **早期知识（3.9.0）**：记录"posix_spawn() 不受 SELinux 限制"
- **实测结果（3.9.25）**：所有子进程创建方式均被阻止
- **结论**：pipe 绕过法 `cmd \| cat` 是唯一可行的临时方案

## 解决方案

### 方案 A：Pipe 绕过法（推荐 - 已验证）

**原理**：管道强制 shell 创建有权限的子进程

```bash
# Python 调用时
python3 -c "import subprocess; r=subprocess.run('clang --version | cat', shell=True); print(f'rc={r.returncode}')"
# 成功: rc=0

# 替代原始调用
python3 -c "import subprocess; r=subprocess.run(['clang','--version']); print(f'rc={r.returncode}')"
# 失败: rc=1
```

**适用场景**：
- Python `os.system()` / `subprocess`
- Makefile 中调用 SDK 工具
- Shell 脚本子进程

**限制**：
- 仅用于构建阶段（bootstrapping）
- 生产环境不推荐

### 方案 B：ELF 签名方案（实验性）

```bash
# 检查 Python 是否已签名
ls -la /data/service/el2/usr/bin/python3

# 尝试签名（可能失败）
python3 $SKILL_ROOT/scripts/ohc-run.py sign-elf /data/service/el2/usr/bin/python3
```

**注意事项**：
- 并非所有工具都能成功签名
- 签名后仍需测试

### 方案 C：环境变量绕过（待验证）

```bash
export POSIX_SPAWN_SETPGROUP_DISABLE=1
```

**状态**：需要进一步验证是否有效

### 方案 D：手动生成文件（适用于 glib-genmarshal/glib-mkenums）

当工具调用完全失败时：
1. 预先在其他平台生成输出文件
2. 复制到构建目录
3. 修改 Meson build 文件跳过工具调用

```bash
# 示例：手动生成 gdk-pixbuf-marshal.h
# 在 Linux 上预生成
glib-genmarshal --header --pragma-once gdk-pixbuf-marshal.list > gdk-pixbuf-marshal.h
# 复制到 HarmonyOS 构建目录
```

## 禁止做法

❌ **直接忽略错误**
- 原因：会导致后续编译步骤失败

❌ **修改系统 SELinux 策略**
- 原因：违反 HarmonyOS 安全模型，且普通用户无权限

❌ **使用未签名的二进制**
- 原因：HarmonyOS 强制要求 ELF 签名

## 验证方法

```bash
# 1. 测试基础 subprocess 调用
python3 -c "import subprocess; r=subprocess.run(['clang','--version']); print(f'rc={r.returncode}')"
# 预期失败: rc=1

# 2. 测试 pipe 绕过
python3 -c "import subprocess; r=subprocess.run('clang --version | cat', shell=True); print(f'rc={r.returncode}')"
# 预期成功: rc=0

# 3. 检查 Python posix_spawn 设置
python3 -c "import subprocess; print(subprocess._USE_POSIX_SPAWN)"
# 输出: True
```
