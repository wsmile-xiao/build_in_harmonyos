# E110: Rust cargo 在 OHOS 上无法加载 libz.so

## 问题描述

在 OHOS 系统上，cargo 二进制（musl-linked）无法加载 libz.so，报错：
```
Error loading shared library libz.so: (needed by /path/to/cargo)
Error relocating /path/to/cargo: zlibVersion: symbol not found
```

## 根因分析

OHOS 的 musl ldso (`/lib/ld-musl-aarch64.so.1`) 使用 namespace 机制进行库路径解析。
该机制基于 `/etc/ld-musl-namespace-aarch64.ini` 配置，对不同路径的二进制使用不同的库搜索路径。
LD_LIBRARY_PATH 对不在标准 namespace 路径中的二进制无效。

cargo 的 RUNPATH 是 `$ORIGIN/../lib`（指向 Rust 安装的 lib 目录），但该目录中没有 libz.so。

## 解决方案

### 方案 1: patchelf 修复 RUNPATH（推荐）

1. 复制 cargo 到可写目录
2. 用 patchelf 添加用户 lib 路径到 RUNPATH
3. 用 ohc-run.py sign-elf 签名

```bash
cp /data/service/hnp/rust.org/rust_1.95.0/bin/cargo ~/tmp/cargo-local
patchelf --set-rpath '$ORIGIN/../lib:/storage/Users/currentUser/usr/local/lib' ~/tmp/cargo-local
python3 $SKILL_ROOT/scripts/ohc-run.py sign-elf ~/tmp/cargo-local
```

### 方案 2: 使用独立 CARGO_HOME

并行编译时，多个 cargo 进程共享 .cargo 目录会导致文件锁冲突。
使用独立的 CARGO_HOME 可以避免此问题。

```bash
export CARGO_HOME=/storage/Users/currentUser/tmp/cargo-home-${软件名}
mkdir -p $CARGO_HOME
cp -r ~/.cargo/registry $CARGO_HOME/  # 复制已有的 crate 缓存
cp -r ~/.cargo/git $CARGO_HOME/        # 复制已有的 git 缓存
```

## 影响范围

所有 Rust 项目编译（cargo 无法运行 = 所有 Rust 编译阻塞）

## 验证命令

```bash
~/tmp/cargo-local --version
# 输出: cargo 1.95.0 ...
```

## 注意事项

- OHOS 的 `/lib/` 目录是只读的，无法放置 libz.so
- `/usr/local/lib` 目录不存在系统级路径，需要通过 RUNPATH 指定
- 修改 cargo 后必须重新 ELF 签名才能执行
