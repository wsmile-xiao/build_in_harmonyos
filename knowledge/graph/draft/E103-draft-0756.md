# E103: __packed 重复符号错误（OpenHarmony binder.h/userfaultfd.h）

## 问题现象

链接阶段报错：
```
ld.lld: error: duplicate symbol: __packed
>>> defined at stress-binderfs.c
>>>            stress-binderfs.o:(__packed)
>>> defined at stress-syscall.c
>>>            stress-syscall.o:(.bss+0x0)
```

## 根因分析

OpenHarmony 内核头文件 `linux/android/binder.h` 和 `linux/userfaultfd.h` 中，`__packed` 被定义为全局变量而非宏：

```c
// linux/android/binder.h
struct binder_handle_cookie {
  __u32 handle;
  binder_uintptr_t cookie;
} __packed;  // 这里 __packed 是变量声明，不是宏
```

而在标准 Linux 内核头文件中，`__packed` 定义为宏：
```c
#define __packed __attribute__((packed))
```

当多个源文件包含这些 OHOS 头文件时，每个编译单元都会生成一个名为 `__packed` 的全局符号（B 类型，未初始化数据段），导致链接时重复符号错误。

## 影响范围

所有包含 `linux/android/binder.h` 或 `linux/userfaultfd.h` 的 C/C++ 软件：
- stress-ng（stress-binderfs.c, stress-userfaultfd.c, stress-syscall.c）
- 其他使用 binder/userfaultfd 接口的系统工具

## 解决方案

### 方案 1：宏重定义（推荐）

在包含冲突头文件前，将 `__packed` 重定义为宏，include 后取消定义：

```c
#if defined(HAVE_LINUX_ANDROID_BINDER_H)
#ifdef __OHOS__
/* OHOS: binder.h defines __packed as a variable, causing duplicate symbol errors */
#define __packed __attribute__((packed))
#endif
#include <linux/android/binder.h>
#ifdef __OHOS__
#undef __packed
#endif
#endif
```

### 方案 2：禁用模块

如果不需要 binder/userfaultfd 功能，可通过编译选项禁用：
```bash
make CC=clang WITHOUT_BINDER=1 WITHOUT_USERFAULTFD=1
```

## 验证方法

检查目标文件是否有 __packed 符号：
```bash
nm stress-binderfs.o | grep "__packed"
```

预期结果：修复后应无 __packed 符号。

## 禁止做法

❌ 不要删除头文件中的 `__packed` 定义
❌ 不要修改系统头文件

后果：binder/userfaultfd 功能完全丧失
