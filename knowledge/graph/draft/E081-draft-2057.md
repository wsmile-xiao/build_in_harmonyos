# E081 — OpenHarmony SDK 中 sockaddr_storage 重复定义

## 错误特征
编译时报错：
```
error: redefinition of 'struct sockaddr_storage'
note: previous definition of 'struct sockaddr_storage' was here
```

常见于网络编程相关的软件，当源文件同时包含 `linux/socket.h` 和 `sys/socket.h` 时触发。

## 触发条件
- 构建系统: autotools, cmake, meson, 或任何 C/C++ 编译
- 阶段: compilation
- 平台: OpenHarmony / HarmonyOS
- 触发文件: `external/corefx/src/Native/Unix/System.Native/pal_maphardwaretype.c` 或类似文件

## 根因分析
OpenHarmony SDK 的系统头文件组织与标准 Linux 不同：
- `linux/socket.h` 定义了 `sockaddr_storage` 结构体
- `sys/socket.h` 也定义了 `sockaddr_storage` 结构体
- 当源文件同时包含这两个头文件时，会导致重复定义错误
- 通常由 `linux/netlink.h` 通过 `linux/if_arp.h` 等头文件链间接包含 `linux/socket.h`

## 解决方案

### 推荐方案
在源文件中添加条件编译宏，跳过 `linux/socket.h` 并手动定义必要的类型：

```c
#ifdef __OHOS__
// On OpenHarmony, sys/socket.h defines sockaddr_storage
// linux/socket.h also defines it, causing redefinition
// We need to prevent sockaddr_storage redefinition from linux/socket.h
// but linux/netlink.h (included via linux/if_arp.h chain) needs __kernel_sa_family_t
// Solution: define _UAPI_LINUX_SOCKET_H to skip linux/socket.h entirely,
// and manually define __kernel_sa_family_t (typedef unsigned short)
#define _UAPI_LINUX_SOCKET_H
typedef unsigned short __kernel_sa_family_t;
#endif
```

**插入位置**：在 `#include <sys/socket.h>` 之后、`#include <linux/if_arp.h>` 之前

**关键点**：
- 使用 `#ifdef __OHOS__` 守卫（符合 R8 源码"四不"准则）
- 定义 `_UAPI_LINUX_SOCKET_H` 跳过 linux/socket.h
- 手动定义 `__kernel_sa_family_t` 以满足 linux/if_arp.h 的需求

### 禁止做法
- ❌ 不要删除 `#include <sys/socket.h>` 或 `#include <linux/if_arp.h>`
- ❌ 不要使用 `#undef sockaddr_storage` 强制取消定义
- ❌ 不要修改 SDK 系统头文件

## 验证
```bash
# 验证修复后的源文件编译通过
cd /path/to/source
make clean && make

# 检查是否仍有重复定义
grep -n "sockaddr_storage" file.c | head -10
```
