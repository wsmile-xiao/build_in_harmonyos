# 归档迁移执行方案

> 日期: 2026-04-28 | 状态: 执行中

## 1. 迭代迁移流程

```
┌──────────────┐
│  更新模板     │◄──────────────────────────┐
│  ARCHIVE-SPEC │                            │
└──────┬───────┘                            │
       ▼                                    │
┌──────────────┐    ┌──────────────┐        │
│ 子任务N      │───►│ 主任务审查    │        │
│ 迁移一批软件  │    │ 模板是否OK？  │───否───►│
│ 返回结果摘要  │    │ 是否需要回溯？│        │
└──────────────┘    └──────┬───────┘        │
                           │ 是(OK)          │
                           ▼                 │
                    ┌──────────────┐         │
                    │ 启动子任务N+1 │         │
                    └──────────────┘         │
                           │                 │
                    （如需回溯）               │
                    ┌──────────────┐         │
                    │ 回溯子任务    │─────────┘
                    │ 补充已迁移条目│
                    └──────────────┘
```

**核心循环**：
1. 主任务启动子任务处理一批软件
2. 子任务返回：迁移摘要 + 发现的问题 + 模板改进建议
3. 主任务判断：
   - 模板是否需要更新？→ 更新后触发回溯
   - 一切正常？→ 继续下一批
4. 回溯：对已迁移但信息不足的条目补充新字段

## 2. 分批策略

按版本数量分批，每批 ~20-25 个版本，保证子任务上下文可控。

| 批次 | 字母范围 | 预估软件数 | 预估版本数 |
|------|----------|-----------|-----------|
| 1 | 7, a(前半) | ~18 | ~20 |

| 4 | f, g | ~28 | ~32 |

**总计**: ~276 个软件, ~309 个版本

## 3. 子任务指令模板

每个子任务接收：
- 归档根目录路径
- ARCHIVE-SPEC.md 规范路径
- 当前模板（manifest.yaml 和 notes.md 的字段定义）
- 要处理的软件范围

子任务对每个软件执行：
1. **读取** — 所有旧文件内容（manifest, PROGRESS, README, _meta, patches/, reports/）
2. **理解** — 提取有价值信息
3. **生成** — 按模板写新文件
4. **清理** — 删除冗余文件
5. **返回** — 迁移摘要 + 发现 + 建议

## 4. 模板版本控制

每次模板更新时：
- 在 ARCHIVE-SPEC.md 中记录模板版本号和变更日期
- 记录新增/修改了哪些字段
- 触发回溯时明确标注哪些批次需要回溯

## 5. 回溯策略

当模板新增字段时：
- **必须回溯**：新增的是必须字段（如 manifest 中新增 source.sha256）
- **建议回溯**：新增的是推荐字段（如 notes.md 新增"编译环境"章节）
- **不回溯**：新增的是可选字段，已迁移的条目保持原样
