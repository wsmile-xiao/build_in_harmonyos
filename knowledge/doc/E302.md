# E302: Gate open_memstream on its close and flush contract, not symbol presence

## 基本信息
- **严重度**: 3
- **类别**: detection, libc
- **作者**: 2301_80739235
- **来源 PR**: source_commit:

## 错误特征
```
PosixMemstreamTest\.CanCheckBufferWithContents|HAVE_OPEN_MEMSTREAM=1|Actual: ''
```

## 根因分析
A target libc can export open_memstream while fclose rejects its cookie stream before flushing buffered data, so symbol-only CMake detection enables a capability whose observable contract is broken.

## 推荐方案
**方法**: behavior-probe-or-evidence-bound-disable

**说明**: Prefer a target behavior probe that verifies write, fclose, and buffer publication. When cross configuration cannot run it, use an evidence-bound target override to disable the capability and retain the upstream fallback path.

**验证/命令**:
```
Set HAVE_OPEN_MEMSTREAM=OFF only for a target whose runtime probe or libc implementation proves the close and flush contract is unusable.
```
