# E450: Keep OHOS host metadata separate from an AVR target sysroot and validate it with the target toolchain

## 基本信息
- **严重度**: 3
- **类别**: cross-compile, sysroot-packaging, test-boundary, tool-dispatch
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !6700

## 错误特征
```
avr-gcc: error trying to exec 'as'|cannot find ld|cannot open linker script file|architecture: aarch64|multilib directory escapes package root|undefined reference to (memcpy|strlen|sin)
```

## 根因分析
avr-libc produces headers, CRT objects, linker scripts, device archives, libc and libm for the AVR target even when Conan runs on an OHOS aarch64 host. Treating those files as native Conan C library metadata lets the OHOS compiler consume incompatible paths. In addition, avr-gcc -B searches its prefix for unprefixed as, ld and nm plus avr/lib/ldscripts, so merely placing avr-prefixed binutils on PATH is insufficient.

## 推荐方案
**方法**: cross-target-resource-boundary-and-explicit-driver-dispatch

**说明**: Model the result as a target resource package rather than an OHOS native library; keep cpp_info include, lib and libs empty; expose the sysroot through resdirs and an explicit root environment variable; construct an ephemeral avr-gcc -B dispatch root containing unprefixed binutils and linker scripts; and make test_package compile and link a real AVR ELF before checking target architecture, package-root containment and strong or weak symbol bindings.

**验证/命令**:
```
conan create archives/a/avr-libc/2.2.1 --build=missing
```
