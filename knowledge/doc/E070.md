# E070: 无 32 位兼容层

> **来源**: build-systems.md §10.2 | **严重度**: 🟡 medium
> **触发工具**: configure / cc | **阶段**: configuration / compilation

## 问题现象

在纯 aarch64 鸿蒙系统上编译时：

```
cannot create executable
invalid arch aarch64-linux-musl/m32
-m32: unsupported option
```

软件默认启用 32 位兼容支持（m32 personality），但鸿蒙无 32 位兼容层。

## 根因

部分软件（如 strace）默认启用 m32 personality 以支持多架构调试。
鸿蒙是纯 aarch64 系统，不存在 32 位兼容层。

## 影响范围

strace、gdb 等支持多架构调试/追踪的系统工具。

## 推荐方案 (priority 1)

**通过 configure 选项禁用 32 位支持**：

```bash
# 先检查是否有相关选项
./configure --help | grep -i "32\|m32\|multi\|personality"

# strace 示例
./configure --disable-mpers --prefix=$HOME/usr/local
make -j$(nproc)
make install
```

## 回退方案 (priority 2)

**过滤 CFLAGS 中的 -m32 标志**（当无 configure 选项时）：

```bash
export CFLAGS=$(echo $CFLAGS | sed 's/-m32//g')
export CXXFLAGS=$(echo $CXXFLAGS | sed 's/-m32//g')
./configure --prefix=$HOME/usr/local
```

## 禁止事项

| 禁止模式 | 原因 | 后果 |
|---------|------|------|
| 强制启用 `-m32` 编译 | 鸿蒙无 32 位兼容层 | linker error: cannot create executable |

## 验证命令

```bash
# 检查编译产物架构
llvm-readelf -h $(which strace) | grep Class
# 期望输出: ELF64-class (非 ELF32)
```
