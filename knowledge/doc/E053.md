# E053: cc1plus 不可用，必须使用 clang++

> **结构化数据**: [graph/E053.kv](../graph/E053.kv) | **原则**: [P-TOOLCHAIN-001](../graph/principles.kv)
> **严重度**: 🟡 medium | **分类**: toolchain/compiler/compat | **自动修复**: ✅ set-env-var

---

## 错误特征

```
cc1plus: error: unrecognized command-line option '-Wno-deprecated-register'
CXX compiler cannot create executables
configure: error: C++ compiler cannot create executables
```

或在软件内部调用 C++ 编译器时失败：

```
cc1plus: error: unrecognized option '-Wno-unused-result'
```

## 根因

鸿蒙 SDK 工具链**不提供 `cc1plus`**（GCC 的 C++ 编译器前端）。鸿蒙使用 LLVM/Clang 工具链，`clang++` 是 C++ 编译器。但部分 autotools 项目硬编码调用 `cc1plus`，或 configure 的 C++ 编译器检测逻辑在 clang++ 上误判。

**问题链**：
```
configure 或 Makefile 调用 C++ 编译器
    → 默认使用 g++ 或检测到 cc1plus → 不存在 → 失败
    → 或 clang++ 被检测为 C++ 编译器但编译参数不兼容 → 编译报错
```

## 解决方案

```bash
# 方案 1（推荐）：显式指定 C++ 编译器
export CC=clang CXX=clang++
./configure --prefix=$HOME/usr/local CXX=clang++

# 方案 2：Makefile 硬编码了 cc1plus 时批量替换
sed -i 's/cc1plus/clang++/g' Makefile*
```

## 验证命令

```bash
which cc1plus    # 不存在
which clang++    # /data/service/hnp/bin/clang++
clang++ --version
```

## 禁止模式

❌ 在鸿蒙目标平台上调用 `cc1plus` 作为 C++ 编译器 → not found

## 涉及软件

Python 3.9.0（`_ctypes` 模块编译）、其他包含 C++ 代码的 autotools 项目。
