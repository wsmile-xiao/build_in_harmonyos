# E341: OHOS SDK lld host-runtime repair must preserve target linker semantics

## 基本信息
- **严重度**: 3
- **类别**: ohos, toolchain, linking, testing, elf-execution
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !5118

## 错误特征
```
Process not started.*\[permission denied\]|[0-9]+% tests failed.*BAD_COMMAND|The active OHOS SDK linker failed its GNU-flavor probe
```

## 根因分析
Repairing the OHOS SDK lld host runtime has two independent scope hazards. A bare invocation of the generic lld driver can return nonzero because no linker flavor was selected, falsely activating a GNU ld fallback. That fallback bypasses the configured SDK clang/lld path and can produce target test executables rejected by HarmonyOS execution policy. Separately, keeping the SDK host LD_LIBRARY_PATH active during CTest leaks host-only libraries into target process startup and makes otherwise valid tests report BAD_COMMAND.

## 推荐方案
**方法**: preserve-sdk-lld-with-scoped-host-runtime

**说明**: Derive llvm/lib from the active Conan compiler, require its ABI-matched libxml2.so.16, probe the generic driver with -flavor gnu, and prepend that directory only while CMake configures, builds, or installs. Restore the environment before CTest and fail fast if the SDK linker remains unusable.

**验证/命令**:
```
SDK_LLVM_LIB="$(dirname "$(dirname "$("$CXX" -print-resource-dir)")")"; LD_LIBRARY_PATH="${SDK_LLVM_LIB}:${LD_LIBRARY_PATH:-}" "${SDK_LLVM_LIB%/lib}/bin/lld" -flavor gnu --version
```
