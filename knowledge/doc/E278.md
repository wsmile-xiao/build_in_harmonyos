# E278: CMake 条件排除内部目标后将目标名静默降级为 -l 库名

## 基本信息
- **严重度**: 3
- **类别**: cmake, linking, packaging
- **作者**: 2301_80739235 <2047361658@qq.com>
- **来源 PR**: source_commit:

## 错误特征
```
CMAKE_INTERNAL_TARGET_MISSING:|CMAKE_BARE_LINK_ITEM:-l
```

## 根因分析
消费者仍在 target_link_libraries 中引用内部目标，但定义该目标的 add_subdirectory 被测试或可选功能条件排除；CMake 将未定义的裸名称视为外部库名并生成 -l<name>，使配置阶段无报错而在最终链接时失败

## 推荐方案
**方法**: restore-cmake-target-definition

**说明**: 沿 target_link_libraries 反查目标定义和 option 值；运行时必需组件应移出仅测试条件，或者用同一条件同时守卫目标定义与消费者链接，再重新生成目标图确认目标存在且链接行不含裸 -l<target>

**验证/命令**:
```
INTERNAL_TARGET=target_name BUILD_DIR=build; cmake --build "$BUILD_DIR" --target help | grep -F "$INTERNAL_TARGET" && ! grep -R -F -- "-l${INTERNAL_TARGET}" "$BUILD_DIR"
```
