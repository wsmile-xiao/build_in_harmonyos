# E481: Adapt a zero-dependency Meson C library to OHOS with a shared-only toolchain, LLVM archive tools, and ELF signing

## 基本信息
- **严重度**: 2
- **类别**: ohos, meson, conan, relocatable, zero-dependency
- **作者**: zhangbowl-JW <406099677@qq.com>
- **来源 PR**: !6738

## 错误特征
```
Dependency .* not found|Library m found: NO|shared_library.*cannot be linked|C compiler cannot create executables
```

## 根因分析
A Meson library that declares no pkg-config dependencies still needs four OHOS-specific fixes: (1) the SDK profile often only names clang, so Meson cannot find ar/ranlib for the native file and fails the static or shared archive step; (2) the OHOS worker has no usable /tmp, so clang and ninja fail creating temporary files unless TMPDIR points inside the build folder; (3) math functions live in bionic libc, so the upstream optional cc.find_library('m', required:false) must not abort configure; (4) shared libraries installed by Meson are unsigned ELF and refuse to load on the device until binary-sign-tool stamps a .codesign section.

## 推荐方案
**方法**: shared-only-meson-toolchain-with-llvm-tools

**说明**: Build with MesonToolchain and default_library=shared, inject llvm-ar/ranlib full paths into conan_meson_native.ini when the profile only declares clang, pin TMPDIR/TMP/TEMP into the build folder, install meson via pip when absent, and ELF-sign every packaged .so (and bin/) with llvm-objcopy --remove-section .codesign then binary-sign-tool sign -selfSign 1.

**验证/命令**:
```
CI_PACKAGES="archives/l/libxcvt/0.1.3" zsh ci/conan/build_and_test.sh
```
