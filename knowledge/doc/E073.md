# E073: 动态库符号链接运行时无法加载

> **类别**: filesystem/hmdfs/runtime-linking | **严重度**: 🔴 | **触发**: ld/运行时 | **阶段**: runtime
> **来源**: operations/debug-methodology.md

---

## 错误现象

编译安装成功，`.so` 符号链接文件存在且路径正确，但运行时报：

```
error while loading shared libraries: libmagic.so.1: No such file or directory
```

关键特征：
- ✅ `ls -la` 确认 `.so` **存在**，且显示为符号链接 (`lrwxrwxrwx`)
- ✅ `LD_LIBRARY_PATH` 已正确设置
- ✅ `readlink` 能正确解析到目标文件
- ❌ 运行时 dlopen **仍然失败**

## 根因分析

鸿蒙 **HMDFS 文件系统**对符号链接的运行时加载支持不完整：

| 阶段 | 操作 | 结果 | 对应条目 |
|------|------|------|----------|
| 安装时 | `ln -s libfoo.so.1.0 libfoo.so.1` | 可能成功 | — |
| 安装时 | `ln -s` 被 HMDFS 拒绝 | Permission denied | **E018** |
| 运行时 | dlopen 跟随符号链接 | **无法解析到目标** | **E073（本条）** |

即：**符号链接在文件系统层面存在，但动态链接器无法通过它找到实际库文件**。这是 HMDFS 对符号链接语义的实现差异，不是权限问题也不是路径搜索问题。

## 解决方案

### 方案 1（推荐）：静态链接

从根本上避免符号链接问题：

```bash
./configure --enable-static --disable-shared LDFLAGS=-static
make && make install
```

### 方案 2：安装后 cp 替换符号链接

将 `.so` 符号链接用 `cp -p` 替换为实体文件：

```bash
# 单个处理
cp -p /real/path/libfoo.so.1.0 /install/path/libfoo.so.1

# 批量处理整个库目录
find $HOME/usr/local/lib -type l -name "*.so*" | while read link; do
    target=$(readlink "$link")
    if [ -f "$(dirname "$link")/$target" ]; then
      cp -p "$(dirname "$link")/$target" "${link}.tmp" && mv "${link}.tmp" "$link"
    elif [ -f "$target" ]; then
      cp -p "$target" "${link}.tmp" && mv "${link}.tmp" "$link"
    fi
done
```

> ⚠️ 缺点：库升级时需要重新执行 cp，不会像符号链接那样自动跟随新版本。

## 诊断流程（区分相似条目）

```
运行时报 "error while loading shared libraries"
    │
    ├─ Step 1: ls -la 确认 .so 存在？
    │       ❌ → 不是 E073，可能是 E019（路径问题）
    │       ✅ ↓
    │
    ├─ Step 2: 是否为符号链接？
    │       file 输出包含 "symbolic link"
    │       ❌ (是实体文件) → 可能是 E042（RPATH 遗漏）或 E068（Python ctypes）
    │       ✅ ↓
    │
    ├─ Step 3: readlink 能否解析到存在的目标？
    │       ❌ 目标不存在 → 符号链断裂，修复链接即可
    │       ✅ 目标存在但仍加载失败 → **E073**
    │
    └─ 结论: HMDFS 符号链接运行时不可解析 → 用 cp 或静态库
```

## 涉及软件

- **file 5.45**（libmagic.so.1）
- **htop 3.4.1**（动态链接版本）
- 其他依赖 .so 符号链接的 C/C++ 软件

## 相关条目
