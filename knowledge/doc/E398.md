# E398: XSyncValueSubtract result and overflow flag are separate compatibility contracts

## 基本信息
- **严重度**: 2
- **类别**: compat, api-contract, consumer-test, x11
- **作者**: 2301_80739235 <2047361658@qq.com>
- **来源 PR**: !5840

## 错误特征
```
XSyncValueSubtract.*overflow|sync_value_contract.*RC 8|1 - 2.*overflow
```

## 根因分析
The historical libXext XSyncValueSubtract implementation can
                        set its overflow output on a sign-changing subtraction such as
                        1 - 2 even though the returned XSyncValue is the exact
                        representable value -1. A consumer test that treats the flag
                        as the sole arithmetic-validity result rejects a working
                        public API and creates a target-only false failure.

## 推荐方案
**方法**: result-first-overflow-boundary-validation

**说明**: Validate the exact subtraction result separately from the
                        overflow output. Do not require a particular overflow bit for
                        the historical 1 - 2 sign transition. Retain explicit
                        overflow assertions for operations that cross the numeric
                        limits, so the consumer still exercises both contracts.

**验证/命令**:
```
conan create archives/l/libxext/1.3.7 -pr:h=ohos-aarch64 -pr:b=ohos-aarch64
```
