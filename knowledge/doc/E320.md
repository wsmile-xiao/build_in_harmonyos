# E320: HarmonyOS fmemopen 符号存在但运行时不可用，AC_CHECK_FUNCS 误判，需 AC_RUN_IFELSE 探测并回退临时文件

## 基本信息
- **严重度**: 2
- **类别**: platform, detection, ohos, libc, autotools
- **作者**: Fish_bone233 <Fish_bone233@noreply.gitcode.com>
- **来源 PR**: 2099

## 错误特征
```
fmemopen.*EBADF|fclose.*EBADF.*fmemopen|bad file descriptor.*fmemopen|fmemopen.*write.*fail|cob_get_field_str.*truncat|ac_cv_fmemopen_works=no|HAVE_FMEMOPEN.*runtime.*unusable|field not allocated
```

## 根因分析
HarmonyOS libc 导出 fmemopen 符号且链接成功，但运行时对缓冲区写入无效、fclose 返回 EBADF，即符号存在不等于语义可用。AC_CHECK_FUNCS 仅做链接级检测，误判 HAVE_FMEMOPEN=1，导致源码走 fmemopen 路径产生坏输出或运行时失败。交叉编译/真机构建中 configure 无法直接运行宿主程序时此类误判尤其隐蔽。

## 推荐方案
**方法**: configure-runtime-probe

**说明**: 用 AC_RUN_IFELSE 在 configure 阶段真实写读 fmemopen 缓冲验证可用性，仅在运行时探测通过时才 AC_DEFINE(HAVE_FMEMOPEN)；失败则源码回退临时文件实现，不依赖平台宏。

**验证/命令**:
```
cd $BUILD_SRC_DIR && patch -p1 < archives/g/gnucobol/3.2/patches/0006-configure-ac-fmemopen.patch && patch -p1 < archives/g/gnucobol/3.2/patches/0007-configure-fmemopen.patch && patch -p1 < archives/g/gnucobol/3.2/patches/0004-libcob-call.c.patch && ./configure --prefix=$DEFAULT_PREFIX && make -j1 && make install DESTDIR=$TEST_PREFIX
```
