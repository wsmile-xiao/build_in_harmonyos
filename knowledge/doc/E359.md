# E359: 将 Conan 构建上下文编译器映射到自定义 HOSTCC/HOSTLD

## 基本信息
- **严重度**: 2
- **类别**: cross-compile, conan, build-context, custom-build-system
- **作者**: wingsluo <wingsluo@noreply.gitcode.com>
- **来源 PR**: !5467

## 错误特征
```
checking for program gcc\.\.\. no|check_host_cc.*failed|HOSTCC.*not found|Exec format error.*build tool
```

## 根因分析
自定义构建系统在生成目标产物之外，还需编译并立即运行构建机工具；上游使用 HOSTCC/HOSTLD，而 Conan GNU 工具链在 build profile 显式配置原生 compiler_executables 时可导出 CC_FOR_BUILD。变量未映射时会默认探测不存在的 gcc；异构交叉编译中缺失 CC_FOR_BUILD 时若回退目标 CC，会生成无法在构建机执行的工具。

## 推荐方案
**方法**: map-conan-build-compiler-to-upstream-host-variables

**说明**: 用 cross_building(self) 区分上下文。原生构建映射工具链 CC；真正交叉构建只接受由 build profile compiler_executables 或构建上下文 tool_requires 显式提供的 CC_FOR_BUILD，缺失时立即失败，禁止回退目标 CC。HOSTLD 使用同一原生编译器驱动。映射必须在 env=conanbuild 中展开。

**验证/命令**:
```
if cross_building(self): require_nonempty("CC_FOR_BUILD"); host_compiler = "$CC_FOR_BUILD"
                        else: host_compiler = "$CC"
                        self.run(f'./configure LD="$CC" HOSTCC="{host_compiler}" HOSTLD="{host_compiler}" ...', env="conanbuild")
```
