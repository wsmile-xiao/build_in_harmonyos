# E078: musl BIND_NOW 导致扩展模块符号解析失败

> **类别**: libc/linking/musl/dynamic-linking | **严重度**: 🔴 | **触发**: cc/python/perl/ruby | **阶段**: linking/runtime**
> **来源**: musl-compat.md §3 + Python 3.9.0/3.9.25 编译经验

---

## 错误现象

```bash
$ python3 -c "import _struct"
ImportError: Error relocating _struct.so: _PyType_Name: symbol not found

$ python3 -c "import _ctypes"
ImportError: Error relocating _ctypes.so: _PyStructs_InitStubOut: symbol not found
```

关键特征：
- **import 时**立即报错（不是调用函数时报错）
- 错误信息格式固定：`Error relocating <module>.so: <symbol>: symbol not found`
- 缺失的符号都是**主解释器 API**（`_Py*` / `Perl_*` / `rb_*`），不是系统或第三方库符号
- `llvm-readelf -d module.so` 显示 NEEDED 只有 `libc.so`

## 根因分析

### glibc vs musl 动态链接行为差异

```
┌─────────────────────────┐     ┌─────────────────────────┐
│         glibc           │     │    musl (鸿蒙)           │
│                         │     │                         │
│  默认: BIND_LAZY       │     │  默认: BIND_NOW ⚠️       │
│  (延迟解析)              │     │  (立即解析)               │
│                         │     │                         │
│  dlopen(.so)            │     │  dlopen(.so)            │
│  │  检查 NEEDED         │     │  │  检查 NEEDED         │
│  │  记录未解析符号       │     │  │  立即解析所有符号 ❌   │
│  │  ✅ 加载成功          │     │  │  _PyType_Name? → 💥   │
│  │                      │     │  │  ImportError!         │
│  │  首次调用时才解析     │     │  │                      │
│  └──────────────────────┘     │  └──────────────────────┘
```

**问题链**：

```
musl ld-musl 默认启用 BIND_NOW
    ↓
dlopen("module.so") 要求所有符号立即可解析
    ↓
module.so 的 NEEDED: [libc.so] ← 没有 libpython!
    ↓
_PyType_Name 定义在 libpython 中，不在 libc 中
    ↓
无法解析 → ImportError: symbol not found
```

### 为什么 glibc 上没问题？

glibc 使用 `BIND_LAZY`：
- dlopen() 成功，不检查符号是否可解析
- 首次调用 `_PyType_Name()` 时才解析
- 此时 Python 已初始化完成，libpython 已加载，符号可找到

musl 使用 `BIND_NOW`：
- dlopen() 时就要求所有符号可解析
- Python 可能还没完全初始化，或者 module.so 根本没声明对 libpython 的依赖

## 解决方案

### 方案 1（推荐）：修正 LDSHARED

在构建系统中正确设置两个变量：

```makefile
# BLDSHARED — 构建主共享库（libpython.so 本身）
# ❌ 不能包含 -lpython（循环依赖！）
BLDSHARED = $(CC) -shared

# LDSHARED — 构建扩展模块（_struct.so, _ctypes.so 等）
# ✅ 必须包含 -lpython（让 NEEDED 包含 libpython）
LDSHARED = $(CC) -shared -L. -lpython$(LDVERSION)
```

**configure.ac 中的标准写法**：

```m4
case $ac_sys_system in
    HarmonyOS*)
        BLDSHARED='$(CC) -shared'
        LDSHARED='$(CC) -shared -L. -lpython$(LDVERSION)'
        LDCXXSHARED='$(CXX) -shared'
        ;;
esac
```

### 方案 2：验证修复效果

```bash
# 修复前
llvm-readelf -d _struct.so | grep NEEDED
# 输出: NEEDED: libc.so

# 修复后（重新编译扩展模块）
llvm-readelf -d _struct.so | grep NEEDED
# 输出:
#   NEEDED: libpython3.9.so.1.0  ✅
#   NEEDED: libc.so              ✅

# 运行验证
python3 -c "import _struct; print('OK')"  # OK
```

### 方案 3：Perl/Ruby 同理

```bash
# Perl XS 模块
LDDLFLAGS="$LDDLFLAGS -lperl"  # 让 .so NEEDED 包含 libperl

# Ruby 原生模块
DLDFLAGS="$DLDFLAGS -lruby"    # 让 .so NEEDED 包含 libruby
```

## BLDSHARED vs LDSHARED 关键区别

| 变量 | 用途 | 能否含主库链接？ | 含了会怎样 |
|------|------|------------------|-----------|
| **BLDSHARED** | 构建主库本身（libpython.so） | ❌ **不能** | 循环依赖 → 链接失败 |
| **LDSHARED** | 构建插件/扩展（*.so） | ✅ **必须** | 不含 → BIND_NOW 下 ImportError |

**记忆口诀**：**B**uild **L**ibrary = 不含自己；**L**ink **D**ynamic = 必须含主库。

## 排查流程

```
import 报 ImportError: symbol not found
    │
    ├─ Step 1: 确认缺失的是解释器 API 符号？
    │       _Py*, Perl_*, rb_* → 是 → 继续
    │       其他符号（如 libssl）→ 不是 E078，可能是 E068(find_library)
    │
    ├─ Step 2: 检查 .so 的 NEEDED
    │       llvm-readelf -d module.so | grep NEEDED
    │       只有 libc.so？→ **确认是 E078**
    │       有 libpython？→ 可能是 RPATH 问题 → E042
    │
    ├─ Step 3: 确认 BIND_NOW
    │       llvm-readelf -d module.so | grep BIND
    │       有 BIND_NOW？→ **确认是 E078**
    │
    └─ Step 4: 检查当前 LDSHARED 设置
            grep LDSHARED Makefile
            是否包含 -lpython？→ 否则就是根因
```

## 适用范围

| 解释型语言 | 扩展类型 | 典型症状 |
|-----------|---------|---------|
| **Python** | C extension (.so) | `Error relocating xxx.so: _Py*: symbol not found` |
| **Perl** | XS module (.so) | `Can't load module: undefined symbol: Perl_*` |
| **Ruby** | native gem (.so) | `undefined symbol: rb_*` |
| **Lua** | C module (.so) | `symbol 'lua_*' not found` |

## 相关条目

- **E042**: RPATH 设置不当导致运行时找不到库（同属动态链接问题，但 E042 是路径问题，E078 是符号解析时序问题）
- **E068**: ctypes find_library 无法定位 ldconfig（同属动态链接器差异）
- **E032**: _GNU_SOURCE 未定义导致 dirent API 不完整（同属 musl 宏需求类）
- **E026**: TLS 差异（同属 musl/glibc 行为差异）
