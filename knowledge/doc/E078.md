# E078: build-var-override

## 错误特征
```
Error relocating.*symbol not found|ImportError.*symbol not found|cannot find symbol|undefined symbol.*_Py|BIND_NOW
```

## 根因分析
musl libc 的动态链接器默认使用 BIND_NOW（加载时立即解析所有符号），而非 glibc 的 BIND_LAZY（首次使用时延迟解析）。
                        解释型语言（Python/Perl/Ruby）的扩展模块（.so）通过 dlopen() 加载时，
                        其 NEEDED 列表通常只有 libc.so，不包含主解释器库（libpython/libperl/libruby）。
                        BIND_NOW 要求所有符号在 dlopen 时即可解析，但 Python API 符号（如 _PyType_Name）
                        定义在 libpython 中而非 libc 中，导致 ImportError。

## 推荐方案
**方法**: build-var-override

**说明**: 在 LDSHARED（构建扩展模块的链接标志）中显式添加主库链接参数，
                        使扩展模块的 NEEDED 包含主解释器库。
                        关键：必须区分 BLDSHARED（构建主库本身，不能含主库链接否则循环依赖）
                        与 LDSHARED（构建扩展模块，必须含主库链接）。

**验证/命令**:
```
|
  # Python 示例：修改 Makefile 或 configure.ac
  # LDSHARED 用于构建 .so 扩展模块 — 必须包含 -lpython
  LDSHARED='$(CC) -shared -L. -lpython$(LDVERSION)'
  
  # BLDSHARED 用于构建 libpython.so 本身 — 不能包含 -lpython（循环依赖！）
  BLDSHARED='$(CC) -shared'
```
