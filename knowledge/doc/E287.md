## 错误特征
```
pcap_activate:.*CAP_NET_RAW|
                        Timeout while waiting for ACK|
                        afl-fuzz: command not found|
                        tmux: command not found|
                        sudo:.*not found|
                        sysfs.*not available|
                        TFTP.*timeout|
                        no CAP_NET_RAW|
                        Cannot open raw socket
```

## 根因分析
部分 C/C++ 命令行工具（如 nmrpflash）上游提供 AFL 模糊测试
                        入口（fuzz.c + fuzz.bash + fuzzin/ 语料），但原样运行依赖
                        AFL/tmux/sudo/Linux sysfs/CAP_NET_RAW/TFTP 网络交互环境，
                        这些在 OHOS 交叉编译 CI 中无法满足。具体障碍：
                        1) AFL 编译器（afl-clang-fast）不可用
                        2) tmux 终端复用器不可用
                        3) sudo 无 raw socket 权限（鸿蒙 sudo 为自研简化版）
                        4) /proc/sys/kernel/core_pattern 等 sysfs 不可写
                        5) CAP_NET_RAW 未授予，pcap_open_live 失败
                        6) TFTP 网络服务无法在 CI 中部署
                        7) /tmp 只读（erofs），AFL 需要可写临时目录

## 推荐方案
**方法**: fuzz-corpus-deterministic-runner

**说明**: 使用上游 fuzz.c + fuzzin/ 语料，替换 AFL 编译器为
                        标准 CC 编译，构建确定性 corpus runner。fuzz.c 本身无
                        AFL 依赖（仅需标准 C 库和项目头文件），AFL 依赖仅在
                        Makefile 的 fuzz target 中（afl-clang-fast）。编译后
                        运行 fuzzin/ 语料文件，验证无崩溃（segfault/abort）即
                        通过。注意：这不是上游原样测试通过率，不能替代真实
                        网络服务测试。

**验证/命令**:
```
# 见 verification_cmd 编译命令。运行：
                        # NMRP 模式：./fuzz nmrp
                        # TFTP 模式：./fuzz tftp <path/to/fuzzin/tftp.bin>
```
