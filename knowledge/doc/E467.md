# E467: AutotoolsDeps exports LIBS, so autoconf's earliest run probe links the whole dependency closure and fails at configure

## 基本信息
- **严重度**: 2
- **类别**: autotools, toolchain, conan
- **作者**: Awstme <awstme@qq.com>
- **来源 PR**: !7080

## 错误特征
```
checking whether we are cross compiling... configure: error: cannot run C compiled programs|Error loading shared library .* \(needed by \./conftest\)
```

## 根因分析
Conan 的 AutotoolsDeps 会把依赖闭包写进 LIBS/CPPFLAGS 环境变量，autoconf 最早的 AC_PROG_CC 交叉编译判定会沿用这些 LIBS 去链接 conftest。于是本应只跑一个空 main 的探测变成需要真正加载整条共享依赖闭包；只要闭包里有任一库在本机不可加载，错误就在 configure 阶段以 rc=77 暴露，而不是在测试阶段，容易被误判为编译器或三元组问题。

## 推荐方案
**方法**: read-config-log-then-fix-loader

**说明**: 先读 config.log 里 conftest 的完整链接命令与第一条错误，区分是签名/别名/路径问题（见 E257、E321），再在任务私有视图内修好可加载性；不要改成静态链接、不要预设 cross_compiling 缓存变量、也不要加 --host。

**验证/命令**:
```
grep -B2 -A8 'cannot run C compiled programs' $B/config.log
```
