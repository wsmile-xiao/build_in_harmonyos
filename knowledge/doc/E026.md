# E026: 线程局部存储(TLS)差异

> **结构化数据**: [graph/E026.kv](../graph/E026.kv) | **原则**: 无
> **严重度**: 🟡 medium | **分类**: libc/compat | **自动修复**: ❌ 需源码修改

---

## 错误特征

```
error: thread-local storage not supported
error: '__thread' is not supported (with certain attributes)
TLS definition mismatch
```

## 根因

musl 的 TLS 实现与 glibc 有差异：

| 特性 | glibc | musl (HarmonyOS) |
|------|-------|------------------|
| `__thread` | ✅ | ✅ |
| `_Thread_local` (C11) | ✅ | ✅ |
| `thread_local` (C++) | ✅ | ✅ |
| `tls_model` 属性扩展 | ✅ | ❌ 不支持 |
| 动态 TLS | 完整支持 | 有限支持 |

## 解决方案

使用标准语法替代 glibc 扩展：

```c
// ❌ 错误：glibc 特有，musl 不支持
__thread int *ptr __attribute__((tls_model("initial-exec")));

// ✅ 正确：标准 C11 语法
_Thread_local int my_tls_var;

// ✅ 正确：POSIX 标准
__thread int my_tls_var;

// 条件编译（兼容两种平台）
#if defined(__OHOS__) || !defined(__GLIBC__)
    __thread int var;
#else
    __thread int var __attribute__((tls_model("initial-exec")));
#endif
```

## 禁止策略

❌ 禁止使用 `tls_model(...)` glibc 扩展属性。

## 验证

```bash
echo '_Thread_local int x;' | clang -x c - -fsyntax-only -
# 应该成功（无输出）
```
