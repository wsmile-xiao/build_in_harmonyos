# E370: Unified keyed inventory for platform-conditioned Meson fixtures

## 基本信息
- **严重度**: 2
- **类别**: upstream-test-integrity
- **作者**: 2301_80739235 <2047361658@qq.com>
- **来源 PR**: !5532

## 错误特征
```
top-level tests OK while nested fixtures contain SKIP|fixture inventory counted as passed|platform-conditioned fixture totals double counted|Meson test dependency target ambiguous
```

## 根因分析
A successful Meson suite process does not prove every nested fixture passed because the upstream runner returns success for source-declared platform skips; adding totals from complete runs also repeats most official fixture keys, while hand-written compile targets can omit executables the fixtures invoke.

## 推荐方案
**方法**: source-keyed-terminal-map-and-target-id-projection

**说明**: Derive the official fixture key set from source, require one nested terminal per key in each raw log, reject unexpected PASS/SKIP/FAIL and missing or duplicate keys, unify only real PASS terminals without repeated counting, bind expected-failure RC and markers, and compile every Meson test dependency through a unique name:type selector.

**验证/命令**:
```
meson introspect build --tests && meson introspect build --targets && meson compile -C build -j 1 <name:type selectors> && meson test -C build --no-rebuild --num-processes 1
```

Meson testlog.json, PASS, SKIP, FAIL, SkipPlatforms, fixture inventory, unique suite fixture key, expected failure returncode, target selector
