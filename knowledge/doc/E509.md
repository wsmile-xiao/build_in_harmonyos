# E509: harmonybrew 动态二进制依赖 OpenSSL 3.x 符号，系统旧版 libssl 缺符号

## 基本信息
- **严重度**: 2
- **类别**: musl, linking, security
- **作者**: 2401_87095818 <zhaowenxiang06@outlook.com>
- **来源 PR**: !4753

## 错误特征
```
Error relocating.*symbol not found|OBJ_nid2sn.*symbol not found|SSL_CTX_new.*symbol not found|OSSL_PROVIDER_try_load.*symbol not found|CRYPTO_malloc.*symbol not found
```

## 根因分析
harmonybrew 提供的 cargo/rustc 等工具链二进制是动态链接 ELF，
            NEEDED 列表含 libssl.so/libcrypto.so。其 RUNPATH 指向
            harmonybrew openssl@3/lib（OpenSSL 3.6.3），但鸿蒙系统动态
            加载器在解析 RUNPATH 前可能已从 /usr/lib 或 /system/lib 加载
            了旧版 libssl.so.3（缺少 OBJ_nid2sn、SSL_CTX_new、
            OSSL_PROVIDER_try_load 等 OpenSSL 3.x 符号），导致
            "Error relocating cargo.real: symbol not found"。
            
            与 E078 不同：E078 是解释型语言扩展模块通过 dlopen 加载时
            BIND_NOW 导致 Python API 符号缺失；本条是原生动态二进制
            （cargo）的 RUNPATH 解析顺序问题，加载器优先用了系统旧版
            OpenSSL。

## 推荐方案
**方法**: set-LD_LIBRARY_PATH-to-harmonybrew-openssl

**说明**: 在 conanfile.py build() 开头显式设置 LD_LIBRARY_PATH 指向
                 harmonybrew 的 OpenSSL 3.6.3 库目录
                 （~/.harmonybrew/opt/openssl@3/lib），强制动态加载器
                 优先用 harmonybrew 的匹配版本，而非系统旧版 libssl.so.3。
                 关键：RUNPATH 不可靠（加载器可能优先系统路径），必须用
                 LD_LIBRARY_PATH 覆盖。

**验证/命令**:
```
|
  import os
  brew_lib = os.path.expanduser("~/.harmonybrew/opt/openssl@3/lib")
  if os.path.isdir(brew_lib):
      existing = os.environ.get("LD_LIBRARY_PATH", "")
      os.environ["LD_LIBRARY_PATH"] = brew_lib + (":" + existing if existing else "")
      os.environ["DYLD_LIBRARY_PATH"] = os.environ["LD_LIBRARY_PATH"]
```
