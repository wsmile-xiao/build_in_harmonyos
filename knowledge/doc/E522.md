# E522: Build a task-local recursive Libtool metadata closure

## 基本信息

## 错误特征
```
is not a valid libtool archive|library .*\.la was moved|sanitized .*\.la.*missing archive|bad escape \\H
```

## 根因分析
A relocated Conan package can contain a direct Libtool
                        archive whose dependency_libs points to current or stale
                        transitive .la files. Repairing only the direct archive
                        is insufficient because Libtool recursively opens each
                        transitive archive. Cross-host graph checks add two traps:
                        regex replacement strings interpret Windows backslashes,
                        and Windows Path treats //lib/foo.la as a UNC anchor.

## 推荐方案
**方法**: task-local-recursive-libtool-shadow

**说明**: Enumerate dependency .la files by unique basename,
                        copy every declared library artifact into a build-local
                        directory, rewrite the complete dependency_libs closure
                        to shadow paths, bind each shadow libdir locally, and put
                        the shadow directory before dependency libdirs. Use a
                        callable regex replacement for host paths and
                        PurePosixPath for leading-slash target tokens.

**验证/命令**:
```
conan create <recipe> -pr:h=ohos-aarch64 -pr:b=ohos-aarch64 --build=missing
```
