# E470: cppitertools 2.3 三问题组合：上游配方版本元数据 vs 官方 tag、大小写不敏感 FS 下 Bazel BUILD 与 build 目录冲突、header-only 配方与消费者测试

## 基本信息
- **严重度**: 2
- **类别**: build-system, conan, packaging, filesystem, provenance
- **作者**: junshi_liu <junshi_liu@users.noreply.atomgit.com>
- **来源 PR**: !7190

## 错误特征
```
"NotADirectoryError: [Errno 20] Not a directory: '.../b/build/Release'|上游 conanfile.py version 与官方 tag 不一致|package_type 未声明 header-library 或消费者 include/命名空间写错"
```

## 根因分析
上游 conanfile.py 的 version 字段由作者维护、滞后于官方 tag，不作为发布事实来源，官方 Git tag 才是。cmake_layout 默认使用名为 build 的构建目录，上游仓库根目录存在 Bazel `BUILD` 文件时，在大小写不敏感 FS 上 `build` 目录创建被既有文件阻断（NotADirectoryError），conan create 在 generate 阶段失败。header-only 库无编译产物，配方需显式 header-library 类型并以真实头文件 API 做消费者测试。

## 推荐方案
**方法**: tag-as-provenance-source + non-default-cmake-build-folder + header-library-recipe

**说明**: 版本号以官方 tag 为准并记录 tag commit 与 SHA-256（conandata.yml），不沿用上游 conanfile 版本；cmake_layout(self, build_folder="build_dir") 规避与 Bazel BUILD 文件碰撞；配方 package_type="header-library"，package_info 仅暴露 include 与 cmake_target_name，test_package 以 iter::range/enumerate/zip/accumulate 真实 API 断言（C++17）。

**验证/命令**:
```
conan create archives/c/cppitertools/2.3 -pr:h ohos-aarch64 -pr:b default
```
