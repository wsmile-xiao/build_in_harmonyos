# E248: patch 致 Makefile.in mtime 早于 Makefile.am，无 automake 时触发重生成崩溃

## 基本信息
- **严重度**: 2
- **类别**: build-system, autotools, patch, timestamp
- **作者**: GoliWie <GoliWie@noreply.gitcode.com>
- **来源 PR**: source_commit:          e81b42ab7c26c1e6207f7b4099d5739ff7c2a6bf

## 错误特征
```
automake-1\.[0-9]+: command not found|WARNING.*automake.*is missing on your system|Makefile:.*Makefile\.in\].*Error 127|cd.*&&.*missing automake
```

## 根因分析
当 Conan 的 apply_conandata_patches 按 patch 文件内 hunk 顺序应用时，若 Makefile.am 的 hunk 排在 Makefile.in 之后，应用后 Makefile.am 的 mtime 会晚于 Makefile.in。GNU make 的标准依赖规则 Makefile.in: Makefile.am $(am__configure_deps) 据此判定 Makefile.in 过期，调用 build-aux/missing automake-1.16 重生成；而鸿蒙 PC 的 /data/service/hnp/bin 仅有 autoconf 系列而无 automake/aclocal，重生成以 exit 127 失败，连带 make all / make check 崩溃。这与"automake 版本不匹配"(E041/E071)或"编译 automake 自身的循环依赖"(E069)不同：本条是普通 autotools 库在 patch 触及 Makefile.am/Makefile.in 时的 mtime 倒挂问题，设备根本不提供 automake。

## 推荐方案
**方法**: fix-mtime-after-patch

**说明**: 在 conanfile.py 的 build() 方法中，apply_conandata_patches(self) 之后立即用 os.utime 把 Makefile.in 的 mtime 对齐到 Makefile.am（atime=mtime=Makefile.am 的 mtime_ns），掐断 make 的重生成触发条件。零新增依赖、不碰源码逻辑、不跑 autoreconf，符合"发行包构建不应要求完整 autotool 链"的成熟做法。

**验证/命令**:
```
os.utime(makefile_in, ns=(os.stat(makefile_am).st_mtime_ns,)*2)
```
