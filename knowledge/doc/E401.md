# E401: MLton real 回归 golden 由 amd64-linux/glibc 生成，OHOS musl 正确舍入的 atan2f x<0 值低 1ULP，需新增 {arch}-{os}.ok 平台 oracle 变体

## 基本信息
- **严重度**: 2
- **类别**: compat, portability, libc, testing, golden-file
- **作者**: GoliWie <GoliWie@noreply.gitcode.com>
- **来源 PR**: !5084

## 错误特征
```
real\.ok.*fail|expected.*got.*ULP|real.*difference with -type-check
```

## 根因分析
MLton 回归框架 bin/regression 的 oracle 选择逻辑默认回退到通用 real.ok（等价于 real.amd64-linux.ok），该 golden 由上游在 amd64-linux（glibc）上生成：对 Real32.atan2/atan2f x<0 有限输入记录 0x3fc90fda（低 1 ULP 舍入）。OHOS 由 clang + musl libm 对相同输入返回正确舍入 0x3fc90fdb，与上游自带的 real.x86-linux.ok / real.amd64-darwin.ok 一致。两者 bit 级差恰好 1 ULP（expected 1.570796251 vs actual 1.570796371），make check 的 real 回归因此报 "real: difference"。C 探针与最小 SML（Basis Real32.Math.atan2 与 FFI atan2f）逐位一致，证明无包装/类型提升/格式化参与；差异 100% 来自上游默认 oracle 生成平台的 libm 舍入特性，属平台精度机制差异，非 MLton 缺陷、非格式化缺陷。

## 推荐方案
**方法**: add-{arch}-{os}-ok-platform-oracle-variant

**说明**: 新增 regression/real.{arch}-{os}.ok 平台 oracle 变体（OHOS 为 real.arm64-ohos.ok，25884 行，行数与 real.ok 一致，值取自 OHOS 实际输出且与上游 x86-linux/darwin 变体语义一致），并在 conandata.yml 注册该补丁。bin/regression 的 oracle 选择循环依次探测 $OBJPTR_REP/a$ALIGN/$TARGET_OS/$TARGET_ARCH/$TARGET_ARCH-$TARGET_OS，real.{arch}-{os}.ok 命中最后一项、优先级最高，其它平台不受影响。禁止修改通用 real.ok / real.amd64-linux.ok、禁止放宽容差、禁止跳过 real 测试。

**验证/命令**:
```
新增 regression/real.arm64-ohos.ok（diff --git a/regression/real.arm64-ohos.ok，new file）并在 conandata.yml 注册；校验：bin/regression -test-reg real rc=0 且无 "real: difference"，完整 CI real 差异计数=0；再 diff 对比 real.arm64-ohos.ok 与 real.ok，确认差异仅限 atan2f x<0 相关行的 ±1ULP。
```
