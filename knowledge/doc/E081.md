# E081: secure_getenv 在 musl libc 上不可用

> **结构化数据**: [graph/E081.kv](../graph/E081.kv) | **原则**: [P-PATCH-001](../graph/principles.kv)
> **严重度**: 🟢 low | **分类**: libc-compat | **自动修复**: ❌ source-patch

---

## 错误特征

```
tmpdir.c:108:11: warning: call to undeclared function 'secure_getenv'
tmpdir.c:108:9: error: incompatible integer to pointer conversion assigning to 'const char *' from 'int'
```

## 根因

`secure_getenv()` 是 glibc 扩展函数，在 setuid/setgid 程序中返回 NULL 以防止环境变量注入。musl libc 未实现此函数。

**问题链**：
```
gnulib tmpdir.c → #define __libc_secure_getenv secure_getenv (非 _LIBC 构建路径)
    → 调用 secure_getenv("TMPDIR") → musl 无此符号 → 隐式声明为 int
    → int 赋值给 const char* → 编译错误
```

## 影响范围

所有使用 gnulib `tmpdir` 模块的软件，包括：
- **wget** (lib/tmpdir.c)
- **coreutils** (lib/tmpdir.c)
- 任何包含 gnulib 并使用 `path_search()` 的项目

## 解决方案

### 方案 1（推荐）：修改宏定义

将 `__libc_secure_getenv` 映射到 `getenv` 而非 `secure_getenv`：

```diff
-# define __libc_secure_getenv secure_getenv
+# define __libc_secure_getenv getenv
```

**安全性说明**：鸿蒙上没有 setuid 场景，`getenv` 降级安全。

### 方案 2（快速）：CFLAGS 全局替换

```bash
export CFLAGS="$CFLAGS -Dsecure_getenv=getenv"
```

## 验证

```bash
# 确认 musl 无此函数
echo 'int main(){secure_getenv("x");}' | cc -xc - -c 2>&1 | grep undeclared

# 确认修复
grep "__libc_secure_getenv" lib/tmpdir.c
# 应输出: # define __libc_secure_getenv getenv
```
