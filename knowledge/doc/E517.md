# E517: Published Conan package .so can carry a signature the consuming device rejects (dlopen: Permission denied)

## 基本信息
- **严重度**: 1
- **类别**: security, dynamic-loading
- **作者**: Awstme <awstme@qq.com>
- **来源 PR**: !7080

## 错误特征
```
Error loading shared library .*: Permission denied|Permission denied .needed by
```

## 根因分析
OHOS 拒绝映射签名不被本机接受的共享库，且错误文案是 Permission denied 而不是 No such file。与 E135（完全未签名）不同：本例中文件确实带 .codesign 段（llvm-readelf -SW 计数为 1），但该签名在消费端设备上无效——已发布包在构建机上签名后随二进制分发，落到另一台设备就可能不被接受。同一目录里其他依赖库可正常 dlopen，因此极易被误判为路径问题或符号链接问题。

## 推荐方案
**方法**: remove-then-resign-in-task-local-view

**说明**: 把目标库复制进任务私有视图后，先用 llvm-objcopy --remove-section .codesign 去掉旧段（binary-sign-tool 无法覆盖已有段），再用 binary-sign-tool sign -selfSign 1 重新签名，最后校验 .codesign 计数恰为 1 且保留 owner 可执行位。绝不修改依赖包本体。

**验证/命令**:
```
llvm-objcopy --remove-section .codesign $VIEW/libfoo.so.1 && binary-sign-tool sign -inFile $VIEW/libfoo.so.1 -outFile $VIEW/libfoo.so.1.signed -selfSign 1 && mv $VIEW/libfoo.so.1.signed $VIEW/libfoo.so.1 && llvm-readelf -SW $VIEW/libfoo.so.1 | grep -c codesign
```
