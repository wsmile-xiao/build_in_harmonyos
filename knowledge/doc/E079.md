# E079: HMDFS 不支持硬链接

> **类别**: filesystem/hmdfs/runtime-linking | **严重度**: 🟡 | **触发**: ln/git/ccache/cargo/pnpm/make | **阶段**: installation/runtime**
> **来源**: filesystem-analysis.md §10.1 + 实机验证

---

## 错误现象

```bash
$ echo "original" > ~/tmp/src
$ ln ~/tmp/src ~/tmp/dst
ln: cannot create hard link: Operation not permitted
```

关键特征：
- `ln` **不带 `-s` 参数**时报错（软链接可能也受 E050/E073 影响）
- 错误码固定为 `Operation not permitted`
- 在 `/tmp`(tmpfs) 或 `/dev/shm` 上正常，在 `$HOME`(HMDFS) 上失败

## 根因分析

```
$HOME = /storage/Users/currentUser → HMDFS（分布式文件系统）
    │
    ├── HMDFS 挂载选项: rw, nodev, relatime, hmmac=genfs
    │       └── nodev: 禁用设备文件
    │       └── 分布式架构: inode 跨设备不唯一
    │
    └── ln(无-s) 尝试创建硬链接 → 多个目录项指向同一 inode
            └── HMDFS 无法保证跨设备 inode 唯一性
                └── 返回 EPERM/Operation not permitted
```

**与 E050（符号链接限制）的区别**：

| 维度 | E050 符号链接 | E079 硬链接 |
|------|-------------|-----------|
| 操作 | `ln -s` | `ln`（无 -s） |
| HMDFS 行为 | 可能创建但无法 follow/执行 | 直接拒绝创建 |
| 运行时影响 | .so 加载失败(E073)、命令执行失败 | 安装别名缺失、缓存失效 |
| 替代方案 | `cp` 复制实际文件 | `cp` 复制 |

## 受影响场景

| 场景 | 受影响软件 | 表现 | 解决方案 |
|------|-----------|------|---------|
| **make install** man 页 | GNU autotools | man1→man8 等别名安装失败 | `make install DESTDIR=` 后手动 cp |
| **git clone --local** | git | 本地克隆硬链接优化失败 | `--no-hardlinks` |
| **git fsck** | git | 报告对象完整性问题 | `--no-hardlinks` |
| **ccache/sccache** | 编译缓存 | 缓存原子替换失败 | `CCACHE_DIR=/dev/shm/ccache` |
| **cargo/rustc** | Rust 工具链 | 编译缓存退化为复制 | 性能下降但功能正常 |
| **pnpm** | Node.js 包管理 | content-addressable store 失败 | `store-dir` 设到 `/dev/shm` |
| **fdupes/rdfind** | 文件去重 | 无法合并重复文件 | 仅报告不执行 |

## 解决方案

### 方案 1（推荐）：configure 层面禁用硬链接

```bash
./configure --prefix=$PREFIX ac_cv_prog_ln_s="cp -p"
```

`ac_cv_prog_ln_s` 是 autotools cache 变量，控制 `LN_S` 的值。设为 `cp -p` 后所有需要创建链接的操作都改为复制。

### 方案 2：make install 使用 DESTDIR

```bash
make install DESTDIR=$PWD/staging PREFIX=$PREFIX
cp -rP staging/$PREFIX/* $PREFIX/
```

### 方案 3：各工具独立 workaround

```bash
git clone --no-hardlinks <repo>
export CCACHE_DIR=/dev/shm/ccache
npm config set store-dir /dev/shm/pnpm-store
```

## 排查流程

```
ln / make install / git 报 Operation not permitted
    │
    ├─ Step 1: 确认是硬链接还是软链接？
    │       ln -s 报错？→ 可能是 E050
    │       ln（无-s）报错？→ 继续 ↓
    │
    ├─ Step 2: 确认文件系统类型
    │       mount | grep $(df . | tail -1 | awk '{print $NF}')
    │       是 hmdfs？→ **确认是 E079**
    │
    └─ Step 3: 验证
            echo test > /tmp/t && ln /tmp/t /tmp/t2 && echo "tmpfs OK"
            echo test > ~/t && ln ~/t ~/t2 2>&1 || echo "HMDFS fails as expected"
```

## 注意事项

- **mv/rename 正常工作**：`mv src dst` 使用 rename()，不依赖硬链接
- **SQLite 正常工作**：原子写入依赖 rename() 而非硬链接
- **chown 静默无效**：返回码 0 但实际未生效（见 E046 补充场景）

## 相关条目

- **E050**: HMDFS 符号链接不可靠（同源——HMDFS 文件系统限制）
- **E073**: 动态库符号链接运行时无法加载（E050 的运行时后果）
- **E074**: FIFO 创建被禁止（同属 HMDFS 操作限制）
- **E046**: chmod/chown 不生效（chown 静默无效可作为 E046 子场景）
