# E423: OHOS 宿主交叉 Binutils 的双架构与包所有权闭环验证

## 基本信息
- **严重度**: 1
- **类别**: ohos, toolchain, cross-compile, consumer-testing, host-target-classification
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !6385

## 错误特征
```
cross tool.*resolved outside package|target architecture mismatch|package ownership negative test.*unexpectedly passed|cannot execute target.*OHOS
```

## 根因分析
交叉 Binutils 包同时包含在 OHOS 宿主运行的工具和面向其他架构的输出。仅检查 --version 不能证明工具来自当前 Conan 包，也不能证明其输出目标正确；直接执行目标 ELF 又会把“不可在宿主运行”的预期行为误判为失败。若测试依赖 PATH，还可能由系统同名工具代替被测包而产生假阳性。

## 推荐方案
**方法**: package-owned-host-target-closed-loop

**说明**: 从 Conan 依赖的 package_folder 解析每个工具的绝对路径，先验证宿主工具可执行与版本，再用真实目标参数完成汇编、链接、格式转换和静态检查。由 objdump/readelf/nm/size 断言目标格式、架构、符号和段，并验证 Intel HEX 等交付格式。最后暂时移除被测包的 bin/lib 内容，要求同一消费者测试失败，以排除 PATH 或系统工具造成的假阳性。目标 ELF 不在 OHOS 宿主执行，测试结果只声明静态目标语义。

**验证/命令**:
```
package absolute tools -> assemble target object -> link target ELF -> convert delivery format -> inspect target metadata -> remove package tools and require failure
```
