# E015: gettext/libintl 链接缺失 (dgettext undefined symbol)

## 错误特征
```
ld.lld: error: undefined symbol: libintl_dgettext
>>> referenced by argp-parse.c
>>>               argp-parse.o:(argp_parse) in archive libargp.a
```
或:
```
undefined reference to `dgettext'
undefined reference to `libintl_dgettext'
```

## 触发条件
- 构建系统: autotools
- 阶段: make 链接阶段
- 前提: 系统中安装了 gettext/libintl（提供 libintl.h）

## 根因分析

软件的 `configure.ac` 使用 `AC_CHECK_HEADERS(libintl.h)` 检测 libintl.h，
当检测到时，源码通过 `#include <libintl.h>` 使用 `dgettext` 函数。
但 configure.ac 没有调用 `AM_GNU_GETTEXT` 来检测并自动添加 `-lintl` 到链接标志。
导致编译通过但链接失败。

## 解决方案

### 方案 1（推荐）：显式链接 libintl

```bash
./configure --prefix=$DEFAULT_PREFIX LIBS="-lintl"
make -j$(nproc)
```

### 方案 2：禁用 NLS（不需要国际化时）

```bash
./configure --prefix=$DEFAULT_PREFIX --disable-nls
make -j$(nproc)
```

### 禁止做法
- ❌ 不要删除 libintl.h 让 configure 检测不到它（会禁用 i18n 功能并影响其他软件）

## 验证
```bash
# 验证 libintl 可用
echo 'extern char* dgettext(const char*, const char*); int main(){dgettext("","x");}' | clang -xc - -lintl
```
