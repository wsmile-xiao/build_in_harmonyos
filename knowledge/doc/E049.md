# E049: 脚本 shebang 硬编码绝对路径导致不可移植

> **结构化数据**: [graph/E049.kv](../graph/E049.kv) | **原则**: 无
> **严重度**: 🟡 medium | **分类**: portability/shell/build-system | **自动修复**: ✅ batch-sed

---

## 错误特征

```bash
#!/data/service/hnp/bin/perl -w
# 或
#!/usr/local/bin/python3
```

脚本在构建机器上能运行，但换一台 perl/python 路径不同的机器就全部失效。

## 根因

构建脚本（如 automake 的 `gen-all.pl`）在生成输出脚本时，将解释器路径硬编码到 shebang 中：

```perl
# gen-all.pl 中的问题代码（修复前）
my $perl_path = '/data/service/hnp/bin/perl';          # ❌ 硬编码平台特定路径
s|^#!.*perl.*|#!$perl_path -w|;                        # ❌ 写死到输出脚本
```

## 影响范围

| 场景 | 影响 |
|------|------|
| 换机部署 | 解释器路径不同 → 所有脚本无法执行 |
| 多 Perl 版本共存 | 绑定特定版本 → 无法切换 |
| 可移植包分发 | 接收方无该路径 → 包不可用 |

## 解决方案

```bash
# 修复已有硬编码 shebang → 可移植格式
sed -i 's|^#!.*perl.*$|#!/usr/bin/env perl|' bin/automake bin/aclocal
sed -i 's|^#!.*python.*$|#!/usr/bin/env python3|' bin/*

# 注意: 若目标平台无 /usr/bin/env(如鸿蒙), 按 E037 策略降级为直接 shebang
```

**与 E037 的关系**：
- **E037** 处理 `/usr/bin/env` 存在性问题（鸿蒙没有 → 降级为直接 shebang）
- **E049** 处理硬编码路径问题（构建生成 → 改为 `/bin/env xxx`）
- 两者互补构成完整的 shebang 兼容方案

## 禁止模式

❌ 构建系统生成脚本时将解释器绝对路径硬写入 shebang → 换机即废

## 通用规则

> **所有构建系统生成的脚本、以及手动编写的安装/配置脚本，shebang 必须使用可移植格式。**
> 硬编码解释器路径是可移植性头号杀手。

## 涉及软件

automake 1.16.5（gen-all.pl 生成的 automake/aclocal 脚本）、通用。
