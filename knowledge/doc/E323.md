# E323: "Qt6DBus 不可消费修复：FEATURE_dbus 开启 + dbus/1.14.10 依赖 + Qt6::DBus 组件（qtbase 6.11.1 案例）"

## 基本信息
- **严重度**: 2
- **类别**: build-system, cmake, conan, qt6
- **作者**: junshi_liu <liujsh2023@lzu.edu.cn>
- **来源 PR**: !7199

## 错误特征
```
>
  find_package\(Qt6DBus.*REQUIRED.*NO_MODULE.*not found|
  Failed to find required Qt component "DBus"|
  Qt6DBusConfig\.cmake.*does NOT exist|
  Qt6_FOUND.*FALSE.*DBus|
  Qt6DBus\.so.*No such file
```

## 根因分析
>
  qtbase/6.11.1 配方 generate() 硬编码 "FEATURE_dbus": "OFF"，Qt6DBus
  模块未参与构建，已发布制品包无 libQt6DBus.so、无 lib/cmake/Qt6DBus/
  Qt6DBusConfig.cmake、package_info 无 dbus 组件；依赖 Qt6DBus 的下游
  find_package(Qt6DBus 6.9.0 REQUIRED NO_MODULE) 必然失败（Qt6_FOUND 被
  Qt6Config.cmake 置 FALSE："Failed to find required Qt component 'DBus'"）。
  并非 dbus 未发布，而是 qtbase 自身功能开关关闭导致的不可消费。

## 推荐方案
**方法**: >
  (1) requirements() 新增 self.requires("dbus/1.14.10")；(2) generate() 将
  FEATURE_dbus 改为 ON，并把 dbus package_folder 追加进 CMAKE_PREFIX_PATH
  使 find_package(DBus1) 命中；(3) package_info() 补 dbus 组件
  (libs=["Qt6DBus"], requires=["core"], cmake_target_name="Qt6::DBus")；
  (4) conan create 复验 libQt6DBus.so 与 Qt6DBusConfig.cmake 产出后下游
  find_package(Qt6DBus REQUIRED NO_MODULE) 可消费。

**说明**: >
  通用模式：Qt 组件缺失不可消费时，定位首错（缺失组件 Config 文件）→
  检查配方 generate() 中对应 FEATURE_ 开关与依赖声明 → 开启开关 + 补齐
  Conan 依赖并暴露给 CMake 探测 + package_info 补组件元数据。

**验证/命令**:
```
>
  conan create archives/q/qtbase/6.11.1 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing; test_package: find_package(Qt6 6.9.0 REQUIRED COMPONENTS DBus NO_MODULE)
```
