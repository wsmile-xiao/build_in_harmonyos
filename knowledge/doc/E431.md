# E431: Prove whether a Conan source cache is pristine before patch replay

## 基本信息
- **严重度**: 2
- **类别**: conan, source-boundary
- **作者**: 2301_80739235 <2047361658@qq.com>
- **来源 PR**: !6534

## 错误特征
```
reverse patch fails because Conan source cache was mistaken for patched postimage
```

## 根因分析
A successful Conan build can apply patches in a separate build copy while retaining pristine downloaded bytes in the cache source directory. The directory name and build log do not establish postimage semantics.

## 推荐方案
**方法**: byte-proven-pristine-forward-replay

**说明**: Determine cache semantics from exact bytes. If pristine, copy only existing preimages, leave declared additions absent, and apply the current ordered patch set exactly once.

**验证/命令**:
```
compare known preimage/postimage anchors; forward-apply all patches; verify target count and postimage hashes
```

## 关键词
Conan source folder, pristine source, patch postimage, reverse replay, /dev/null addition, ordered patches
