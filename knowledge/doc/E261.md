# E261: Transaction rollback must retain the old output when the installed target is untrusted

## 基本信息
- **严重度**: 3
- **类别**: java, runtime, security
- **作者**: 2301_80739235 <2047361658@qq.com>
- **来源 PR**: #3928

## 错误特征
```
installed Native Image output must not be a symlink|Native Image output changed during install|Native Image transaction rollback failed|signed-output.*without.*recovery
```

## 根因分析
After an exchange commit the backup path carries the previous user output. If rollback trusts only the path, catches only OSError, or cleans temporaries unconditionally, a concurrent symlink, non-regular object, identity error, or same-byte replacement can bypass recovery and cause the previous output to be deleted.

## 推荐方案
**方法**: identity-bound-recovery-and-cleanup

**说明**: Verify both exchange sides, treat OS and domain identity errors as recovery conditions, move the old-output backup to a unique no-replace recovery path, revalidate it, and clean only identities recorded by the current invocation.

**验证/命令**:
```
Add identity-bound recovery around installed-target checks and reopen the committed target with no-follow semantics after directory fsync.
```
