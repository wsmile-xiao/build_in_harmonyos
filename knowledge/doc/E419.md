# E419: Target plain-char signedness can change INT8 API results without changing stored bytes

## 基本信息
- **严重度**: 2
- **类别**: abi, c-language, signedness
- **作者**: 2301_80739235 <2047361658@qq.com>
- **来源 PR**: !6320

## 错误特征
```
expected.*-[0-9]+.*actual.*[12][0-9]{2}|INT8.*char|plain char.*unsigned
```

## 根因分析
C leaves plain char signedness implementation-defined. A target compiler may default plain char to unsigned while upstream code uses char variables and char pointers as signed 8-bit samples. The stored byte remains unchanged, but integer promotion turns values such as -120 and -17 into 136 and 239, so comparisons and API results fail only on the target.

## 推荐方案
**方法**: consistent-target-signed-char-mode

**说明**: When the upstream source and public API intentionally use plain char for signed 8-bit values, add -fsigned-char through the package toolchain so every affected C translation unit uses one consistent semantic mode. Preserve upstream source and test expectations, and verify the full target suite.

**验证/命令**:
```
toolchain.extra_cflags.append("-fsigned-char")
```
