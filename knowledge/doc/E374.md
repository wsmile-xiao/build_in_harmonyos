# E374: Separate Conan consumer compile-link proof from unavailable signed runtime execution

## 基本信息
- **严重度**: 2
- **类别**: detection, conan, runtime
- **作者**: 2301_80739235 <2047361658@qq.com>
- **来源 PR**: !5532

## 错误特征
```
OHOS runtime execution requires signing tools: objcopy, readelf, signer
```

## 根因分析
Conan can_run() establishes build/host compatibility, but it does not prove that an OHOS worker has the complete ELF signing toolchain required to execute newly linked binaries. A same-OS worker can therefore compile and link a real consumer while being unable to safely execute that consumer or packaged commands.

## 推荐方案
**方法**: artifact-first-capability-gated-runtime

**说明**: First require the linked consumer and every packaged command to exist. Resolve the complete signing tool set. If and only if a signing tool is absent, report runtime as NOT_RUN while retaining the truthful compile-link result; when tools exist, sign every runtime ELF and execute the original assertions. Missing artifacts, signing failures, command failures, and assertion failures remain fatal.

**验证/命令**:
```
validate consumer and command paths; resolve objcopy/readelf/signer; emit explicit NOT_RUN only for missing tools; otherwise sign and run
```
