# E411: compat/export_sources 目录残留 libtool 构建产物导致 conan create 链接失败

## 基本信息
- **严重度**: 3
- **类别**: autotools, conan, libtool, compat-shim, export-sources
- **作者**: mkz--mkz <ak74A3WKxU__vozN.mkz--mkz@noreply.gitcode.com>
- **来源 PR**: !5224

## 错误特征
```
not a valid libtool object|Copied .*\.lo file|invalid libtool object
```

## 根因分析
explore 阶段直接在源码树 compat/ 内执行 make 后，compat/ 残留 .lo/.o/.dirstamp/.Plo 等 libtool 构建产物；conanfile.py export_sources 用 copy(self,"*",...) 全量复制 compat/，把构建产物当作源码发布进 recipe，conan create 在干净源码树重建时混入脏 .lo，链接报 not a valid libtool object

## 推荐方案
**方法**: 归档前清理 compat/、tests/ 下全部构建产物（find .deps/.libs -type d -exec rm -rf + 与 *.lo/*.o/*.Plo/*.Po/*.dirstamp 删除），只保留源文件；或 export_sources 用白名单复制 *.h/*.cpp

**说明**: explore 阶段在源码树内执行 make 后，compat/ 会混入 libtool 构建产物；export_sources 全量复制会把脏 .lo 当源码发布。归档前必须清理，或用白名单只复制源文件。

**验证/命令**:
```
find compat tests -type d \( -name .deps -o -name .libs \) -exec rm -rf {} + 2>/dev/null; find compat tests -type f \( -name '*.lo' -o -name '*.o' -o -name '*.Plo' -o -name '*.Po' -o -name '*.dirstamp' -o -name '*.la' -o -name '*.lai' \) -delete
```
