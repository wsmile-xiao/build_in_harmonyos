# E236: Isolate non-relocatable Libtool dependency metadata

## 基本信息
- **严重度**: 2
- **类别**: autotools, linking, conan, libtool
- **作者**: 2301_79503900 <3308319887@qq.com>
- **来源 PR**: source_commit:

## 错误特征
```
library .*\.la was moved|is not a valid libtool archive|archive member .*\.a is neither ET_REL nor LLVM bitcode|undefined symbol: (pcre2_|sqlite3_)
```

## 根因分析
Libtool gives visible .la files precedence over sibling static archives. A relocated Conan
                        dependency can retain an invalid libdir or dependency_libs path in that metadata, so Libtool
                        follows a path that no longer exists. Passing the dependency as an absolute .a path is not
                        equivalent to a normal -l dependency when another Libtool static archive is being built:
                        llvm-ar can embed the complete dependency archive as a member, leaving the later executable
                        link with a non-ET_REL member and unresolved dependency symbols.

## 推荐方案
**方法**: scoped-la-free-static-archive-directory

**说明**: Copy only the required dependency .a files into a build-private directory that contains no .la
                        metadata. Pass that directory through the upstream dependency-scoped CFLAGS and LIBS variables
                        as -L<dir> -lname, leave the Conan dependency cache unchanged, and remove generated .la metadata
                        from the final package.

**验证/命令**:
```
mkdir -p <build>/.dependency-archives; cp <dependency>/lib/libfoo.a <build>/.dependency-archives/; FOO_LIBS='-L<build>/.dependency-archives -lfoo' ./configure
```
