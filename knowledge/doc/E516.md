# E516: OHOS libc omits _res/__res_state and <linux/ip.h> — provide custom resolver state and skip IP options

## 基本信息
- **严重度**: 2
- **类别**: ohos, libc, build-system, ndk, resolver
- **作者**: bellaaa_ <bellaaa_@noreply.gitcode.com>
- **来源 PR**: !6702

## 错误特征
```
undefined symbol: _res|undefined reference to ._res.|cannot find -lresolv|incomplete type .struct ip_options.|linux/ip.h: No such file
```

## 根因分析
OHOS libc (bionic-derived) provides res_init()/res_search()/res_query()
    but does NOT export the legacy global `_res` symbol nor the `__res_state()`
    thread-local accessor that glibc exposes; software using `return &_res;` to
    obtain a resolver-state pointer fails to link (undefined symbol: _res).
    Separately the OHOS NDK headers ship no `<linux/ip.h>`, so `struct
    ip_options` is an incomplete type and code referencing it fails to compile.

## 推荐方案
**方法**: provide-custom-resolver-state

**说明**: Define OS_GET_DNS_RESOLVER_RES to skip the generic _res path,
    then provide a process-wide static struct __res_state accessor; for
    ip_options define NO_IP_OPTIONS and undef GLIBC_IP_OPTIONS to skip the
    deprecated IPv4 source-route path.

**验证/命令**:
```
add to OS/os.h-<plat>: #define OS_GET_DNS_RESOLVER_RES \n #undef
    GLIBC_IP_OPTIONS \n #define NO_IP_OPTIONS ; add to OS/os.c-<plat>:
    static struct __res_state s; res_state os_get_dns_resolver_res(void){
    return &s; }
```
