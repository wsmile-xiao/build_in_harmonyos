# E072: config.sub 三元组验证失败

> **类别**: autotools-config | **严重度**: 🔴 | **触发**: configure | **阶段**: configuration
> **来源**: troubleshooting.md §4.2

---

## 错误现象

```
configure: error: invalid triplet aarch64-unknown-linux-ohos
```

或：

```
checking host system type... Invalid configuration `aarch64-unknown-linux-ohos': unknown operating system
config.sub: error: unknown operating system `ohos'
```

## 根因分析

Autotools 构建系统的配置验证分两步：
1. **config.guess**（E007 已覆盖）：根据 `uname` 输出**猜测**目标三元组
2. **config.sub**（本条目）：**验证**三元组的每个字段是否合法

当 config.guess 成功生成 `aarch64-unknown-linux-ohos` 后，config.sub 不认识 `ohos` 这个操作系统值，拒绝该三元组。

**与 E007 的区别**：

| 维度 | E007 (config.guess) | E072 (config.sub) |
|------|---------------------|-------------------|
| 文件 | config.guess | config.sub |
| 功能 | 猜测目标平台 | 验证三元组合法性 |
| 错误信息 | `cannot guess build type` | `invalid triplet` / `unknown operating system` |
| 触发顺序 | 先 | 后 |

两者通常成对出现——修复了 config.guess 后紧接着就会遇到 config.sub 问题。

## 解决方案

### 方案 1（推荐）：patch config.sub

config.sub 需要修改 **3~4 处**（取决于版本），确保 `ohos` 在所有验证点都被接受：

#### 修改清单

| # | 位置 | 修改内容 | 版本差异 |
|---|------|---------|---------|
| 1 | **maybe_os 行**（~第 145 行） | 在 `linux-* | uclinux-*` 条件中追加 `linux-ohos*`；单独添加 `ohos*` | 所有版本都需要 |
| 2 | **OS 有效性白名单**（~第 1730 行） | 在 `gnu* | android* | bsd* | mach* | ...` 行前面追加 `ohos* \|` | **部分版本需要**（如 rsync 3.3.0 的 2023 版 config.sub） |
| 3 | **kernel-os 白名单**（~第 1780 行） | 在 `linux-musl* | linux-relibc* | linux-uclibc*` 行追加 `linux-ohos* \| ohos*` | 所有版本都需要 |
| 4 | **android-linux case**（如有） | 在 `android-linux)` 分支后添加 `ohos-linux)` 分支 | 仅含该 case 结构的版本 |

#### 快速定位

```bash
# 1. maybe_os 行
grep -n "linux-\*.*uclinux" config.sub

# 2. OS 有效性白名单（如果存在这行）
grep -n "gnu\*.*android\*.*bsd\*" config.sub

# 3. kernel-os 白名单
grep -n "linux-musl\*.*linux-relibc" config.sub

# 4. android-linux case
grep -n "android-linux" config.sub
```

#### 典型修改示例

```bash
# 1. maybe_os（第 145 行附近）
sed -i 's/nto-qnx\* | linux-\* | uclinux-uclibc\* \\/nto-qnx* | linux-* | uclinux-uclibc* | linux-ohos* \\\n\t\t\t| ohos* \\/' config.sub

# 2. OS 有效性白名单（第 1730 行附近，仅部分版本需要）
sed -i 's/^gnu\* | android\* | bsd\*/ohos* | gnu* | android* | bsd*/' config.sub

# 3. kernel-os 白名单（第 1780 行附近）
sed -i 's/linux-musl\* | linux-relibc\* | linux-uclibc\* | linux-mlibc\* )/linux-musl* | linux-relibc* | linux-uclibc* | linux-mlibc* \\\n\t\t   | linux-ohos* | ohos* )/' config.sub
```

> **经验**：如果修改了 1 和 3 后仍然报 `OS 'ohos' not recognized`，检查是否遗漏了第 2 处（OS 有效性白名单）。rsync 3.3.0 就属于这种情况。

### 方案 2：下载最新 GNU Config

GNU Config 上游仓库的最新版本已包含 HarmonyOS 支持：

```bash
curl -o config.guess 'https://git.savannah.gnu.org/gitweb/?p=config.git;a=blob_plain;f=config.guess;hb=HEAD'
curl -o config.sub   'https://git.savannah.gnu.org/gitweb/?p=config.git;a=blob_plain;f=config.sub;hb=HEAD'
chmod +x config.guess config.sub
```

> ⚠️ 注意：下载的版本可能与项目原版有其他差异（如新增的架构支持），建议仅替换 config.sub 而非整套。

## 验证修复

```bash
# 测试三元组验证
./config.sub aarch64-unknown-linux-ohos
# 期望输出: aarch64-unknown-linux-ohos

# 如果返回错误信息则说明修复未生效
```

## 涉及软件

所有使用 Autotools (autoconf/automake/libtool) 的 C/C++ 项目。典型受影响软件：
- libffi 3.4.4
- gettext 0.21
- 其他需要手动修改 config.sub 的 GNU 工具链软件
