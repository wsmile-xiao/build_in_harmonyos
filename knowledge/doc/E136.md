# E136: patch-script

## 基本信息
- **严重度**: 2
- **类别**: platform,configuration,permission
- **触发工具**: config.status, configure
- **阶段**: configuration

## 错误特征
```
config.status: error: could not setup config files machinery|Permission denied.*confXXXXXX|cannot create a temporary directory in .
```

**关键词**: TMPDIR,umask,mktemp,Permission denied,临时目录,config.status,HarmonyOS权限

## 根因分析
HarmonyOS上umask 077 + SGID导致mktemp创建的临时目录权限为drwx--S---，当前用户无法写入。configure脚本使用umask 077创建临时目录，且使用相对路径./confXXXXXX，在SGID环境下导致权限不足。

**影响范围**: 所有使用autotools的软件，特别是configure脚本中使用mktemp创建临时目录的场景。HarmonyOS环境下的SGID目录特别容易触发此问题。

## 推荐方案
- **方法**: patch-script
- **描述**: 在configure脚本中强制设置TMPDIR为可写目录，修改umask 077为umask 022，使用绝对路径$TMPDIR/confXXXXXX而非相对路径./confXXXXXX，确保临时目录可写。使用make -e确保环境变量传递给子进程。
- **命令**: `sed -i 's/^  tmp=.*umask 077.*mktemp.*&/: "${TMPDIR:=/tmp}"\n{\n  tmp=`(umask 022 \&amp;\&amp; mktemp -d "\$TMPDIR/confXXXXXX") 2>/dev/null` \&amp;/' configure`
- **自动修复**: false

## 验证
```bash
grep -n 'TMPDIR.*umask 022' configure \&amp;\&amp; echo "修复成功" || echo "未修复"
```
