# E420: Legacy C sources must include the dependency header that owns each API declaration

## 基本信息
- **严重度**: 2
- **类别**: compat, headers, autotools, cross-compile
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !6124

## 错误特征
```
wvSummary\.c.*incompatible integer to pointer conversion|gsf_doc_prop_get_val.*expression of type 'int'|gsf_doc_meta_data_new.*expression of type 'int'
```

## 根因分析
A legacy C translation unit calls APIs declared by a dependency-specific public header but includes only neighboring headers that used to expose those declarations transitively. With a newer dependency header layout and modern Clang, the undeclared calls retain the legacy implicit-int type and fail when their results initialize pointer values.

## 推荐方案
**方法**: include-api-owning-public-header

**说明**: Identify the installed public header that declares every failing dependency API and include that header directly in the translation unit before rebuilding with the same compiler and dependency graph.

**验证/命令**:
```
add #include <dependency/api-owner.h> to the translation unit and rebuild without diagnostic suppression
```
