# E528: Close the OHOS native Autotools environment before configure

## 基本信息
- **严重度**: 3
- **类别**: ohos, autotools, conan, permissions, native-toolchain
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !6620

## 错误特征
```
could not determine .* interface|configure: error: could not setup config files machinery|conf.*/subs1.awk: Permission denied|checking for .*ar.*link -lib|cannot create .*subs1.awk
```

## 根因分析
On OHOS shadow CI, the runner profile can provide clang through tools.build:compiler_executables while PATH still omits the full native toolchain directory. Autotools then fails archiver discovery and may fall through to unrelated host tools such as link -lib. After that is fixed, Autoconf config.status can create ./conf* subdirectories under the build folder with ownership/permission semantics that reject creating generated files such as subs1.awk.

## 推荐方案
**方法**: recipe-local-ohos-autotools-env-closure

**说明**: In generate(), derive the tool directory from tools.build:compiler_executables['c']; prepend it to PATH; define AR, NM, RANLIB, and STRIP to llvm-* tools when present. For OHOS, create a device-private TMPDIR such as /data/storage/el2/base/<pkg>-configure-tmp and use replace_in_file(strict=True) after apply_conandata_patches() to make the generated configure/config.status template create conf* below TMPDIR instead of the build folder.

**验证/命令**:
```
conan create archives/l/libunwind/1.6.2 --build=missing
```
