# E486: 引导构建中在宿主 ELF 首次执行前签名并保持最终编译器为原生 ELF

## 基本信息
- **严重度**: 1
- **类别**: ohos, autotools, toolchain, linking, conan
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !6387

## 错误特征
```
Permission denied.*(gen|cc1|xgcc|avr-gcc)|Operation not permitted.*(gen|cc1|xgcc)|missing [.]codesign.*(cc1|avr-gcc)|Exec format error.*build helper
```

## 根因分析
GCC 等引导构建会交错执行“由宿主编译器链接辅助程序”和“立即运行该程序”两个阶段。HarmonyOS 要求宿主 ELF 具有有效 .codesign，等到 make 完成或 package() 再批量签名已经太晚。编译器包装器还必须区分宿主 EXEC/DYN 与目标对象、汇编输出及 AVR ELF；若把最终 avr-gcc 替换为 shell 包装器，又会改变工具身份、相对路径和下游探测语义。

## 推荐方案
**方法**: link-interception-sign-before-first-exec

**说明**: 仅在 OHOS 宿主构建环境中以 CC/CXX 包装真实编译器。真实编译器成功返回后解析 -o 和编译阶段参数，用 readelf 只识别宿主 EXEC/DYN；对命中的输出先移除旧 .codesign，再签名到同目录临时文件，确认新签名段后原子替换并恢复执行位。通过 SHELL 显式解释位于 HMDFS 的包装脚本。阶段目标完成和 package() 后再扫描补签遗漏的宿主 ELF，但最终 avr-gcc、cc1 仍以签名后的原生 ELF 交付。test_package 必须直接运行 avr-gcc，确认版本和包内 libgcc，再链接并检查目标 AVR ELF。

**验证/命令**:
```
real compiler -> classify output with readelf -> remove stale .codesign -> sign temporary file -> verify .codesign -> replace before make executes the host tool
```
