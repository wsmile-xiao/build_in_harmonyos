# E107: GLib 静态库与 gettext 动态库链接冲突

> **结构化数据**: [graph/E107.kv](../graph/E107.kv)
> **严重度**: 🔴 blocking | **分类**: linking | **自动修复**: ❌ manual

---

## 错误特征

```
undefined reference to `g_libintl_bind_textdomain_codeset'
undefined reference to `g_libintl_*'
lld: error: undefined symbol: g_libintl_*
```

链接共享库时报错，找不到 `g_libintl_*` 系列符号。

## 根因

鸿蒙系统中：
- GLib 编译为**静态库**（libglib-2.0.a 等）
- gettext 只提供**动态库**（libintl.so.8）
- GLib 静态库依赖 libintl.a 中的 `g_libintl_*` 符号（GLib 对 gettext 的封装）
- 系统的 libintl.so 是标准 gettext，不包含这些符号

当链接依赖 GLib 的共享库时，符号无法解析。

## 解决方案

### 方法：创建中间动态库

从 libintl.a 提取 g_libintl_* 符号，创建独立的动态库：

```bash
# 1. 找到 libintl.a（通常在预编译包中）
LIBINTL_A=$(find ~/usr/local/lib -name "libintl.a" | head -1)

# 2. 创建中间动态库
clang -shared -o ~/usr/local/lib/libintl_glib.so \
    -Wl,--whole-archive $LIBINTL_A -Wl,--no-whole-archive

# 3. 验证符号
nm -D ~/usr/local/lib/libintl_glib.so | grep g_libintl

# 4. 链接时使用
clang -o mylib.so ... -lintl_glib
```

### 应用范围

所有依赖 GLib 静态库的共享库都需要链接 libintl_glib.so：
- libgudev-1.0.so
- libupower-glib.so
- 其他 GNOME 相关库

## 注意事项

1. **RPATH 配置**: 确保 libintl_glib.so 的 RPATH 正确
2. **打包分发**: 预编译包需要包含 libintl_glib.so
3. **依赖声明**: manifest.yaml 中记录此特殊依赖

## 案例

- **upower 0.99.20**: 编译 libupower-glib.so 时遇到此问题
- **libgudev 238**: 同样需要链接 libintl_glib.so
