# E223: secure tmp 需联合验证 owner、mode、MAC 与真实写入闭环

## 基本信息
- **严重度**: 3
- **类别**: platform, hmdfs, environment, security
- **作者**: GoliWie <GoliWie@noreply.gitcode.com>
- **来源 PR**: metrics_success_count:  1

## 错误特征
```
config\.status.*subs1\.awk.*Permission denied|mktemp -d.*conf|mode 2771|Read-only file system.*EROFS
```

## 根因分析
HMDFS 上目录存在、可创建或显示某个 mode 均不足以证明敏感临时数据满足 owner 隔离、权限位、MAC 域和后续写入语义；放宽 umask 或 chmod 777 会破坏 secure tmp 边界。

## 推荐方案
**方法**: private-cache-capability-validation

**说明**: 优先使用调用方注入或能力探测得到的 app-private cache；验证 owner、目录0700、文件0600、MAC域和真实写入闭环，失败则 fail-closed。

**验证/命令**:
```
在候选目录创建私有子目录和文件，检查 stat 与安全标签，完成读写删除，再定向 secure temp 并执行 config.status。
```
