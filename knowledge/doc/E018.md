## 错误特征
```
ln.*cannot create symbolic link.*Permission denied|
                         ln.*sf.*garbled|No such file or directory.*symlink|
                         symlink.*Permission denied
```

## 根因分析
鸿蒙 SELinux 策略限制用户进程在特定目录
                         创建和访问软链接, ln -sf 可能创建异常文件,
                         已有软链接可能无法被进程正确解析

## 推荐方案
**方法**: wrapper-script

**说明**: 用 shell wrapper 脚本替代软链接:
                         #!/bin/sh; exec /real/path "$@"

**验证/命令**:
```
cat > link << 'EOF'; chmod +x link
```
