# E228: HMDFS 上无扩展名 Libtool 测试 wrapper 无法直接启动

## 基本信息
- **严重度**: 2
- **类别**: hmdfs, testing, permissions, libtool
- **作者**: 1catmint1 <goblinrs@yeah.net>
- **来源 PR**: source_commit:

## 错误特征
```
Permission denied.*test/|LOG_COMPILER.*Permission denied|libtool.*wrapper.*cannot execute
```

## 根因分析
Automake/Libtool 为动态链接测试生成与测试 ELF 同名的无扩展名 shell wrapper，真实 ELF 位于相邻 .libs 目录。HMDFS 权限语义可能阻止 wrapper 直接执行，而它没有 .sh 后缀，普通脚本规则无法识别；同时静态或非 Libtool 测试本身是真实 ELF，不能统一交给 shell 解释。

## 推荐方案
**方法**: conditional-log-compiler-launcher

**说明**: 给 Automake LOG_COMPILER 提供 launcher；对首个测试参数计算同目录 .libs/<basename>，存在该真实 ELF 时用 HarmonyOS shell 启动外层 wrapper，否则直接 exec 原测试。launcher 自身也通过已知 shell 启动，不依赖执行位。

**验证/命令**:
```
candidate="${1%/*}/.libs/${1##*/}"; if test -f "$candidate"; then exec /system/bin/sh "$@"; else exec "$@"; fi
```
