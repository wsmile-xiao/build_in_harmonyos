# E365: Synchronize valid-abort tests with launcher termination semantics

## 基本信息

- **作者**: 2301_80739235 <2047361658@qq.com>

## 错误特征
```
valid PMI abort control returned 1 for valid-int-(max|min)
```

## 根因分析
After the production abort handler stopped treating disabled automatic cleanup as a successful return, the valid INT_MIN and INT_MAX probes still expected the launcher and ranks to survive, write canaries, finalize, and return zero. The stale oracle therefore rejected the required nonzero abort termination even though cleanup completed and no process residue remained.

## 推荐方案
**方法**: termination-bound-valid-abort-oracle

**说明**: Accept the expected nonzero launcher result only through the managed cleanup path; bind the three live role/rank/PID/PGID records and exact proxy topology, reject PMI parser errors, require exact armed evidence, forbid a delayed survival canary, prove zero residue, and run a fresh ordinary MPI smoke case.

**验证/命令**:
```
python validate_valid_abort_termination.py
```
