# E363: Legacy Bash test harness setup failures must not be reported as a passing upstream suite

## 基本信息
- **严重度**: 3
- **类别**: ohos, portability, shell, false-green, testing-infrastructure
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !5425

## 错误特征
```
cp: /tmp/.*Read-only file system|/bin/bash: bad interpreter|xargs: Unknown option 'I'|install: Permission denied|ASLTS.*PASS\s*:\s*$|iasl compiler not found.*exit_code=0
```

## 根因分析
Legacy upstream Bash harnesses can combine three independent portability assumptions: staging executable tools under hard-coded /tmp, executing transitive helpers through a fixed /bin/bash shebang, and using GNU-only utility flags such as xargs -I. If setup and phase errors use bare exit or are not returned to the top-level process, the harness can exit 0 with no test case executed and an empty PASS/FAIL/Tests summary.

## 推荐方案
**方法**: writable-temp-explicit-interpreter-fail-fast-positive-summary

**说明**: Honor caller-owned TMPDIR and verify it is writable; declare Bash as a reproducible tool dependency; invoke the top-level and transitive scripts through that Bash instead of a system shebang; use mkdir for pure directory creation instead of a policy-blocked install program; replace unsupported parallel dispatch with a portable selected-case loop; return every setup/compile/execute failure explicitly; and require a non-empty structured summary plus a generated artifact before declaring success.

**验证/命令**:
```
conan create archives/a/acpica-unix/20260408 --build=missing
```
