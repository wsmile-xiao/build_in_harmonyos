# E524: Autotools configure 反复报 C compiler cannot create executables / 依赖缺失：检查共享 SYS_PREFIX 注入污染与逐项 REQUIRED 依赖

## 基本信息
- **严重度**: 1
- **类别**: build-system, autotools, conan, dependency
- **作者**: openharmory-agent <agent@openharmony.local>
- **来源 PR**: !6055

## 错误特征
```
C compiler cannot create executables|checking whether the C compiler works\.\.\. no|configure: error: \*\*\* .* support not found|requires libjansson|requires SQLite3|uuid support not found|Asterisk requires
```

## 根因分析
两个叠加根因。(1) 依赖注入目标用了共享目录 SYS_PREFIX（如 /storage/Users/currentUser/usr/local，CI worker 与本地共享同一台机器文件系统）：CI 从制品仓下载的依赖包 revision 与本地不同（共享库版 vs 静态库版、.pc 布局不同），注入后污染共享目录 → clang 链接 conftest 时 -L/usr/local/lib 找到坏库 → C compiler cannot create executables；本地恰好有历史遗留正确库所以永远复现不了。(2) Asterisk 等 autotools 项目的 configure 逐项硬性 REQUIRED 依赖缺失即报错：libedit、uuid(e2fsprogs)、jansson(>=2.11)、sqlite3、libxml2(menuselect)、ncurses(tinfo)——本地共享目录有历史遗留所以之前能过，改私有 prefix 后真实暴露。

## 推荐方案
**方法**: private-prefix-injection

**说明**: generate() 依赖注入目标改为 build_folder 私有 prefix（os.path.join(self.build_folder, "prefix")），不碰共享 /usr/local；同时按 configure 报错逐项补齐 REQUIRED 依赖（libedit/libxml2/ncurses/uuid(e2fsprogs)/jansson/sqlite3），sqlite3 包无 .pc 时生成 shim，jansson 只发布共享库按 .so 校验。work 目录直接用 build_folder 子目录，禁用 os.access(X_OK) 探测（HMDFS chmod 被忽略、权限固定 660，X_OK 恒 False）。

**验证/命令**:
```
generate() 内 _ensure_dep_present(self._prefix(), ...) + configure 传 CPPFLAGS/LDFLAGS/PKG_CONFIG_PATH 指向私有 prefix
```
