# E484: OHOS patch --dry-run 真实创建文件，污染 .orig 基线目录

## 基本信息
- **严重度**: 2
- **类别**: platform, limitation, ohos
- **作者**: hhyxx1 <f24011422@st.sandau.edu.cn>
- **来源 PR**: !7105

## 错误特征
```
creating|patch --dry-run|--dry-run -p1|source/target file does not exist
```

## 根因分析
HarmonyOS PC 的 GNU patch 在 --dry-run 模式下仍会真实创建新文件（0 字节占位），
                        而非仅预览。refresh-patch 的 _dry_run() 在 .orig 目录执行 patch --dry-run，
                        导致新增源文件（如 core.go）被写成 0 字节占位文件；下次 refresh-patch
                        据此误判该文件"已存在"，生成 --- a/xxx 而非 --- /dev/null 的新文件补丁，
                        conan apply_conandata_patches (patch_ng) 报 source/target file does not exist。

## 推荐方案
**方法**: baseline-restore

**说明**: 每次 finish/refresh-patch 前，从原始 tarball 恢复干净的 .orig 基线目录，
                        删除其中的 0 字节占位文件，使新增文件被正确识别为 /dev/null 新文件

**验证/命令**:
```
rm -f ${ORIG_DIR}/${REL_NEW_FILE}; # 或重新解压 tarball 到 .orig
```
