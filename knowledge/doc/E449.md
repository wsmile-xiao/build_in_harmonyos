# E449: Publish GNU Objective-C runtime flags and run paths for GNUstep consumers

## 基本信息
- **严重度**: 3
- **类别**: ohos, conan, runtime, gnustep, objective-c
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !6806

## 错误特征
```
Foundation/Foundation.h.*not found|undefined reference.*objc|objc_msg_lookup|NSConstantString|cannot find -lobjc|symbol lookup error.*libgnustep-base
```

## 根因分析
A GNUstep Foundation consumer needs the same GNU
                        Objective-C runtime ABI and constant-string class as the
                        library package. Conan's C and CMake consumers do not
                        infer these flags automatically from the presence of
                        libobjc2. If the recipe only publishes the library name,
                        downstream Objective-C code can compile or link with the
                        wrong runtime, miss Foundation headers, or fail at target
                        execution because libobjc, libffi, curl, or
                        libgnustep-base are not on the runtime library path.

## 推荐方案
**方法**: objc-runtime-flags-in-package-info

**说明**: Publish GNUstep Base headers and libraries with
                        transitive libobjc2, libffi, and curl requirements. Add
                        -fobjc-runtime=gcc, -fblocks, and
                        -fconstant-string-class=NSConstantString to consumer
                        compile flags, add the runtime flags to executable and
                        shared link flags, and prepend the GNUstep Base and
                        dependency libdirs to buildenv_info and runenv_info.
                        Verify with an Objective-C test_package that imports
                        Foundation/Foundation.h, constructs Foundation objects,
                        links, signs/runs under shadow CI, and exits cleanly.

**验证/命令**:
```
conan create archives/g/gnustep-base/1.31.1 -pr:h=ohos-aarch64 -pr:b=ohos-aarch64 --build=missing
```
