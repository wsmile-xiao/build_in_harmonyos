# E361: Gate detached-descendant canaries on post-cleanup release

## 基本信息
- **严重度**: 2
- **类别**: cleanup, mpi, openharmony, process-control, timeout
- **作者**: 2301_80739235 <2047361658@qq.com>
- **来源 PR**: !5510

## 错误特征
```
managed MPI command exceeded [0-9]+ seconds: .*test_process_control.*detach|detached MPI descendant wrote delayed canary for detach
```

## 根因分析
A managed MPI launcher may either return while a detached descendant remains or stay live until the bounded harness timeout. The initial timeout acceptance still used a canary written four seconds after startup even though timeout cleanup cannot begin until 15 seconds, so the canary measured pre-cleanup lifetime rather than post-cleanup escape. Substring mode matching also allowed detach to match detach-kill.

## 推荐方案
**方法**: bound-timeout-plus-post-cleanup-token-gate

**说明**: Keep a finite timeout and parse its command list exactly. Make the child publish an armed token and wait; only after zero-residue cleanup and escape-PID absence may the host create-new the exact release token. Reject any canary before or after that gate, then run a fresh MPI smoke test.

**验证/命令**:
```
python validate_r65_detached_cleanup_gate.py --conanfile <test_package/conanfile.py> --process-source <test_process_control.c> --scratch <E-drive scratch>
```
