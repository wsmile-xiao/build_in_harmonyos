## 错误特征
```
undefined symbol: g_libintl_gettext|undefined symbol: g_libintl_bindtextdomain|ld\.lld: error: undefined symbol: g_libintl_
```

## 根因分析
meson 构建系统中，当使用静态库（如 glib 的 .a 文件）作为依赖时，如果这些静态库依赖其他库（如 libintl），meson 可能会错误地链接动态库版本（.so）而不是静态库版本（.a）。这导致静态库中引用的符号在运行时找不到，因为静态库期望链接到静态版本的依赖库。

## 推荐方案
**方法**: patch-build-file

**说明**: 修改 meson 生成的 build.ninja 文件，将所有动态库依赖（.so）替换为静态库版本（.a）。具体操作：sed -i 's|libintl\.so|libintl.a|g' build.ninja，然后重新编译。

**验证/命令**:
```
cd build && sed -i 's|libffi\.so|libffi.a|g' build.ninja && sed -i 's|libintl\.so|libintl.a|g' build.ninja && ninja
```
