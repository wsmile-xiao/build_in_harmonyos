# E123: patch-build-file

## 基本信息
- **严重度**: 2
- **类别**: linking|meson|static_library
- **触发工具**: meson|ninja
- **阶段**: linking

## 错误特征
```
undefined symbol: g_libintl_gettext|undefined symbol: g_libintl_bindtextdomain|ld\.lld: error: undefined symbol: g_libintl_
```

**关键词**: meson, static library, linking, libintl, glib, undefined symbol, g_libintl_

## 根因分析
meson 构建系统中，当使用静态库（如 glib 的 .a 文件）作为依赖时，如果这些静态库依赖其他库（如 libintl），meson 可能会错误地链接动态库版本（.so）而不是静态库版本（.a）。这导致静态库中引用的符号在运行时找不到，因为静态库期望链接到静态版本的依赖库。

**影响范围**: 使用 glib 静态库作为依赖的 meson 项目，以及其他使用静态链接但依赖库同时提供静态和动态版本的场景。

## 推荐方案
- **方法**: patch-build-file
- **描述**: 修改 meson 生成的 build.ninja 文件，将所有动态库依赖（.so）替换为静态库版本（.a）。具体操作：sed -i 's|libintl\.so|libintl.a|g' build.ninja，然后重新编译。
- **命令**: `cd build && sed -i 's|libffi\.so|libffi.a|g' build.ninja && sed -i 's|libintl\.so|libintl.a|g' build.ninja && ninja`
- **自动修复**: false

## 验证
```bash
grep 'libintl\.a' build/build.ninja && ninja -j1 && echo "链接成功"
```
