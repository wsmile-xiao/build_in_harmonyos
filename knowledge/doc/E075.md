# E075: C_INCLUDE_PATH 导致 pkg-config --cflags 返回空

> **类别**: configuration/environment/pkg-config | **严重度**: 🟡 | **触发**: configure/cmake/cc | **阶段**: configuration
> **来源**: environment.md §11

---

## 错误现象

configure 或 cmake 能检测到库存在，但编译时报头文件找不到：

```bash
$ pkg-config --libs openssl
-L/storage/Users/currentUser/usr/local/lib -lssl -lcrypto    # ✅ 正常

$ pkg-config --cflags openssl
                                                          # ❌ 空字符串！

$ clang -c test.c
fatal error: 'openssl/ssl.h': No such file or directory      # 编译失败
```

关键特征：
- `pkg-config --libs` 有输出，`--cflags` 为空
- `.pc` 文件中明确写了 `Cflags: -I${includedir}`
- 设置了 `C_INCLUDE_PATH` 环境变量

## 根因分析

pkg-config 的 `verify_package()` 函数执行"系统目录过滤"：

```
加载 .pc 文件 → 解析 Cflags: -I/path/to/include
                    ↓
        读取"系统路径"列表:
        ├── PKG_CONFIG_SYSTEM_INCLUDE_PATH（内置默认值 /usr/include）
        └── C_INCLUDE_PATH（GCC 环境变量）← ⚠️ 用户设置了
                    ↓
        遍历 -I 标志：如果路径匹配任一"系统路径" → 删除该标志
                    ↓
        返回空的 cflags 字符串
```

**这是一个配置陷阱**：用户设置 `C_INCLUDE_PATH` 的本意是**帮助**编译器找到头文件，结果反而导致 **pkg-config 故意删除**了这些路径。

**为什么 Linux 上没这个问题**：Linux 上通常不设置 `C_INCLUDE_PATH`（标准做法是用 pkg-config），所以这个过滤逻辑不会触发。

## 解决方案

### 方案 1（推荐）：移除 C_INCLUDE_PATH

从 `~/.zshrc` 中删除以下行：

```bash
# ❌ 删除这些
export C_INCLUDE_PATH=$HOME/usr/local/include
export CPLUS_INCLUDE_PATH=$HOME/usr/local/include
export LIBRARY_PATH=$HOME/usr/local/lib
```

确保只设置构建系统级别的变量：

```bash
# ✅ 保留这些
export PKG_CONFIG_PATH=$HOME/usr/local/lib/pkgconfig:$PKG_CONFIG_PATH
export CMAKE_PREFIX_PATH=$HOME/usr/local
export LDFLAGS="-L$HOME/usr/local/lib"
export CPPFLAGS="-I$HOME/usr/local/include"   # 注意：是 CPPFLAGS 不是 C_INCLUDE_PATH
```

> **CPPFLAGS vs C_INCLUDE_PATH**：`CPPFLAGS` 是构建系统（configure/cmake）使用的变量，会正确传递给编译器。`C_INCLUDE_PATH` 是编译器预处理器全局变量，会被 pkg-config 误判为系统路径。

### 方案 2（临时救急）：强制允许系统 cflags

```bash
export PKG_CONFIG_ALLOW_SYSTEM_CFLAGS=1
pkg-config --cflags openssl   # 现在有输出了
```

⚠️ 这只是临时 workaround，不建议写入 `.zshrc`，因为它掩盖了真正的配置问题。

## 排查流程

```
编译报 "xxx.h: No such file or directory"
    │
    ├─ Step 1: pkg-config --cflags <pkgname> 是否为空？
    │       有输出 → 不是 E075，可能是 E032/E033（宏未定义）或其他
    │       为空 ↓
    │
    ├─ Step 2: 检查 C_INCLUDE_PATH 是否设置
    │       echo $C_INCLUDE_PATH
    │       未设置 → 可能是 .pc 文件本身问题，检查 .pc 内容
    │       已设置 ↓
    │       → **确认是 E075**
    │
    └─ Step 3: pkg-config --debug --cflags <pkgname>
            查找 "Removing ... from cflags" 行确认根因
```

## 正确的环境变量分类

| 变量类型 | ✅ 安全 | ❌ 危险 | 说明 |
|----------|---------|---------|------|
| 构建系统级 | `CPPFLAGS`, `LDFLAGS`, `PKG_CONFIG_PATH`, `CMAKE_PREFIX_PATH` | — | 被 configure/cmake 正确消费 |
| 运行时级 | `LD_LIBRARY_PATH`, `PATH`, `TMPDIR` | — | 运行时动态链接器和 shell 使用 |
| **编译器全局** | — | **`C_INCLUDE_PATH`, `LIBRARY_PATH`, `CPATH`** | 被 pkg-config 误判为系统路径 |
