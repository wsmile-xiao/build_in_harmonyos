# E534: OHOS musl 缺失 GNU/BSD 扩展函数的 BusyBox 兼容层与配置规避

## 基本信息
- **严重度**: 2
- **类别**: portability, libc, musl, gnu-extensions
- **作者**: junshi_liu <liujsh2023@lzu.edu.cn>
- **来源 PR**: !6286

## 错误特征
```
undefined symbol: gethostid|undefined symbol: strverscmp|undefined symbol: sigisemptyset|call to undeclared function 'getusershell'|call to undeclared function 'gethostid'|implicit declaration.*getusershell|implicit declaration.*gethostid
```

## 根因分析
OHOS musl libc 基于 musl 标准实现，不提供 gethostid、strverscmp、sigisemptyset、getusershell 等 GNU/BSD 扩展函数。这些函数在 glibc 中属于标准扩展，但 musl 项目明确选择不实现非 POSIX 扩展。BusyBox 的某些 applet（hostid、sort -V、ls -v、hush shell、su）直接调用这些函数，编译时产生隐式声明警告/错误，链接时产生未定义符号错误。

## 推荐方案
**方法**: compat-patch-in-missing-syscalls

**说明**: 在 libbb/missing_syscalls.c 中添加 gethostid/strverscmp/sigisemptyset 的兼容实现，用 __attribute__((weak)) 弱符号（无需平台条件编译，链接时自动检测：glibc 强符号优先，musl 缺时弱定义生效）。getusershell 因逻辑较复杂（需扫描 /etc/shells），建议直接禁用 applet（CONFIG_SU=n）。实现原则：最小化、不改变调用语义、仅填补 libc 空缺。

**验证/命令**:
```
|
  diff --git a/libbb/missing_syscalls.c b/libbb/missing_syscalls.c
  --- a/libbb/missing_syscalls.c
  +++ b/libbb/missing_syscalls.c
  +__attribute__((weak)) long gethostid(void) { return 0; }
  +__attribute__((weak)) int strverscmp(const char *l0, const char *r0) { /* 标准 GNU 算法，长度比较优先，无溢出；详见 patch */ }
  +__attribute__((weak)) int sigisemptyset(const sigset_t *set) { for(i=1;i<_NSIG;i++) if(sigismember(set,i)) return 0; return 1; }
  (完整实现见 BusyBox 1.36.1 适配 patches/0001-ohos-compat-missing-libc-functions.patch)
```
