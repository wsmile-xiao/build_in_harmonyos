# E461: OHOS filesystem matrix rejects AF_UNIX file-socket bind; use abstract namespace

## 基本信息
- **严重度**: 2
- **类别**: ohos, testing, filesystem, networking
- **作者**: Awstme <awstme@qq.com>
- **来源 PR**: !7064

## 错误特征
```
Failed to bind socket /tmp/dbus-XXXX: Read-only file system; Operation not permitted on user FS bind; /dev/shm bind EACCES
```

## 根因分析
On HarmonyOS PC the writable filesystem (HMDFS under $HOME) refuses AF_UNIX bind with EPERM, /tmp is read-only erofs (EROFS), and /dev/shm is writable for regular files but bind() returns EACCES from the SELinux domain. Upstream tests hardcoding unix:tmpdir=/tmp therefore fail on two layers (path + capability).

## 推荐方案
**方法**: abstract-socket-first-with-tmpdir-fallback

**说明**: In test tooling prefer the Linux abstract socket namespace (unix:abstract=<unique name>, no filesystem involvement, verified bindable on OHOS) and fall back to unix:tmpdir=$TMPDIR (then /tmp) for portability. Never relax permissions or write to system dirs to fake success; record the capability matrix with the raw errno per path.
