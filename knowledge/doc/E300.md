# E300: Bridge Conan dependency paths into upstream custom CMake find modules

## 基本信息
- **严重度**: 3
- **类别**: cmake, conan
- **作者**: 2301_80739235
- **来源 PR**: source_commit:

## 错误特征
```
Could NOT find .* \(missing: .*_INCLUDE_DIR.*_LIBRARY.*\)|.*_INCLUDE_DIR-NOTFOUND|.*_LIBRARY-NOTFOUND
```

## 根因分析
An upstream Find module may ignore Conan-generated CMake targets and search only legacy include and library cache variables, so a published dependency remains undiscoverable during cross configuration.

## 推荐方案
**方法**: cmake-cache-path-bridge

**说明**: Resolve and validate the dependency header and library from self.dependencies, then pass the exact cache variables expected by the upstream Find module through CMakeToolchain.

**验证/命令**:
```
Set <DEP>_INCLUDE_DIR and <DEP>_LIBRARY from the verified Conan package paths before tc.generate().
```
