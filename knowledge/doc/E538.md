# E538: 统一 C++17/libc++ profile 后 ohpcd 发布依赖图选项不一致的解决与 pangomm 本地闭环修复链

## 基本信息
- **严重度**: 2
- **类别**: ohos, toolchain, conan, dependency-graph, meson-pkgconfig
- **作者**: junshi_liu <liujsh2023@lzu.edu.cn>

## 错误特征
```
Missing binary: harfbuzz|Options conflicts|No compatible configuration found|package 'pangocairo' has no Version|has no Description|gmmprocdir|glibmm_generate_extra_defs-2.68 not found|binary-sign-tool.*-a|pangomm.h.*not found|symbol not found
```

## 根因分析
>
  r11 时 ohpcd 发布的 harfbuzz/14.2.0.1 binary 仅基于 glib:shared=False（静态）
  构建，而 glibmm/cairomm/pango 发布 binary 基于 shared=True，pangomm 全图
  glib=shared=True 时 harfbuzz 计算包 ID 无发布 binary，源码构建超过 300s 前台时限。
  r12 中 ohpcd 发布修复版 harfbuzz/14.2.0.1#58fa487c（2026-08-23），binary
  1b5bfb 改为 requires glib/2.84.Z（动态，不锁 revision），全图解析成功。
  但 pangomm 自身闭环又暴露 meson/PkgConfigDeps/签名/运行时的多环节适配点。

## 推荐方案
**方法**: published-binary-wait-plus-meson-pkgconfig-fixes

**说明**: >
  发布侧：等待 ohpcd 发布与 shared glib 匹配的 harfbuzz binary（r12 已修复）。
  消费侧 recipe 需要四类修复：
  (1) alias-pc：PkgConfigDeps 只生成 pango.pc，需为 pangocairo/pangoft2 手写
      转发 .pc 且带 Name/Description/Version（pkg-config 0.29.2 校验）；
  (2) pc-var：PkgConfigDeps 不写 gmmprocdir，需补进 glibmm-2.68.pc；
  (3) link-args：meson find_library(glibmm_generate_extra_defs-2.68) 需
      -L glibmm libdir（经 conf tools.build:sharedlinkflags/exelinkflags 注入）；
  (4) sign：binary-sign-tool 正确语法 sign -selfSign 1 -inFile X -outFile Y，
      -a 非法；package_info 需声明 include/pangomm-2.48 与 lib/.../include。

**验证/命令**:
```
>
  conan create archives/p/pangomm/2.50.1 --profile:host=pangomm-cxx17 --build=missing
```
