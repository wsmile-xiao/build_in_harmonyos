# E513: Preserve joinable thread teardown when pthread cancellation is unavailable

## 基本信息
- **严重度**: 2
- **类别**: compat, libc, syscall, threading, lifecycle
- **作者**: asp1r1n1 <912802346@qq.com>
- **来源 PR**: !3482

## 错误特征
```
pthread_cancel.*undeclared|pthread_setcanceltype.*undeclared|undefined reference to pthread_cancel|undefined symbol: pthread_cancel
```

## 根因分析
E085 identifies missing pthread cancellation APIs, but a no-op stub or simply returning an error changes the lifecycle of a joinable worker: callers still wait in pthread_join() and cannot reclaim the thread. A fallback must preserve both targeted exit and join semantics.

## 推荐方案
**方法**: guarded-signal-thread-exit

**说明**: Keep the normal pthread-cancel path when available; otherwise install a narrowly scoped async-signal-safe thread-exit handler before creating the joinable worker, send a reserved signal with pthread_kill(), and join the worker. Ensure the application's signal-mask setup does not block that reserved signal.

**验证/命令**:
```
# project-specific: handler calls pthread_exit(0); fallback cancellation calls pthread_kill(thread, SIGUSR1); then pthread_join(thread, &status)
```
