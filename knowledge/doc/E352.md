# E352: Pure Lua 5.1 modules need interpreter-aware layout and target-side require validation

## 基本信息
- **严重度**: 2
- **类别**: hmdfs, lua, conan, packaging, target-validation
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !5253

## 错误特征
```
module '.*' not found|no file '.*/share/lua/5\.1/.*\.lua'|cannot open .*\.lua|attempt to call .* nil value
```

## 根因分析
Pure Lua modules are executable interpreter resources rather than opaque data files.
                        A generic data-only recipe can preserve files while still breaking the Lua contract:
                        versioned module roots may be absent from LUA_PATH, legacy top-level require names may
                        depend on upstream symlinks that HMDFS cannot follow, and host-only file checks do not
                        prove that the target Lua 5.1 interpreter can parse and execute the packaged modules.

## 推荐方案
**方法**: lua-module-dual-layout-target-require

**说明**: Declare all four OHOS profile settings and clear them only in package_id; validate an
                        exact non-empty module inventory; install real file copies under both the namespaced
                        and compatibility module paths; publish a versioned LUA_PATH through Conan buildenv/runenv;
                        then compile or obtain the target Lua interpreter and execute require plus behavior
                        assertions against the packaged files. Keep optional-dependency stubs in test_package
                        only and prove that they drive the real packaged module.

**验证/命令**:
```
conan create archives/a/acf-lib-lua5.1/0.11.1 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```
