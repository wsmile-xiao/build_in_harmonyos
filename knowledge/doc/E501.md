# E501: Makefile-only C libraries need direct Conan build and linker runtime env on OHOS runners

## 基本信息
- **严重度**: 2
- **类别**: toolchain, conan, runner
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !4635

## 错误特征
```
make: inaccessible or not found|cmake: inaccessible or not found|Error loading shared library libxml2.so.16|Error relocating .*lld: xml.* symbol not found
```

## 根因分析
Some OHOS PR runners do not expose make/cmake to Conan subprocesses, and OHOS SDK lld may require the SDK llvm/lib directory in LD_LIBRARY_PATH for libxml2 runtime symbols.

## 推荐方案
**方法**: direct-compile-source-list-and-wrap-link-env

**说明**: Mirror the upstream Makefile source list in the Conan recipe, compile with the profile compiler, archive with llvm-ar/llvm-ranlib, run the upstream smoke test from the build tree, and prepend OHOS SDK ohos/native/llvm/lib to LD_LIBRARY_PATH around link commands.

**验证/命令**:
```
use conan.tools.env.Environment().prepend_path("LD_LIBRARY_PATH", sdk_llvm_lib) with vars(self).apply() around clang link commands
```
