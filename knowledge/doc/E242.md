# E242: Bind compiler-specific Fortran module files to Conan package identity and consumer CMake gates

## 基本信息
- **严重度**: 2
- **类别**: linking, fortran
- **作者**: 2301_80739235
- **来源 PR**: source_commit:

## 错误特征
```
Cannot open module file|module file was created by a different version|Unexpected EOF in module file|requires LLVMFlang
```

## 根因分析
Fortran .mod files are compiler-specific binary interfaces, but a normal Conan library package ID and an imported CMake target do not automatically encode the compiler executable that produced them. A consumer can therefore resolve the archive while using an incompatible compiler ID or version, or use the Fortran target without explicitly accepting its compiler contract.

## 推荐方案
**方法**: compiler-identity-package-and-component-gate

**说明**: |
  Declare the exact Fortran compiler package as a tool requirement with
  package_id_mode=full_mode in both the producer and Fortran consumer. Export
  the Fortran archive and module files as a separate Conan component. Attach a
  CMake build module that requires an explicit Fortran component, verifies that
  the Fortran language is enabled, and checks the compiler ID and exact version
  before allowing the imported Fortran target to link. Keep the C-only
  component independent of this gate.

**验证/命令**:
```
|
  self.tool_requires("<fortran-tool>/<version>", package_id_mode="full_mode")
  # Package .mod files with the Fortran archive in a separate component.
  # Export a cmake_build_modules guard that checks COMPONENTS Fortran,
  # CMAKE_Fortran_COMPILER_LOADED, CMAKE_Fortran_COMPILER_ID, and
  # CMAKE_Fortran_COMPILER_VERSION before enabling the Fortran target.
```
