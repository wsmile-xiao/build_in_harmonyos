# E304: Prevent exhaustive FFTW planning from consuming short target test budgets

## 基本信息
- **严重度**: 3
- **类别**: dependency, runtime
- **作者**: 2301_80739235
- **来源 PR**: source_commit:

## 错误特征
```
Mdrun.*\(Timeout\)|FFTW_MEASURE|Using [0-9]+ MPI thread
```

## 根因分析
A project-level no-measure option can reach the primary FFT wrapper but miss a direct multidimensional planner, leaving that path on FFTW_MEASURE during every fresh process startup; constrained targets then spend minutes planning before a tiny transform or simulation makes progress.

## 推荐方案
**方法**: evidence-bound-fftw-estimate

**说明**: When target timing proves FFTW planning dominates startup, enable the conservative planning option and audit every direct FFT planner so the same policy reaches all FFTW_MEASURE selections while preserving transforms, tests, and result assertions.

**验证/命令**:
```
Set the project's supported no-measure CMake option to ON, verify the generated macro and every direct planner flag, then rerun the full suite rather than only timed-out tests.
```

## 关键词
FFTW_MEASURE, FFTW_ESTIMATE, GMX_DISABLE_FFTW_MEASURE, PME, CTest timeout, repeated process startup
