# E465: Route upstream dlopen/ctypes tests past the OHOS worker loader boundary with an embedded-Python launcher that links the library under test as its own NEEDED

## 基本信息
- **严重度**: 3
- **类别**: platform, ohos, autotools, testing, security
- **作者**: Awstme <awstme@qq.com>
- **来源 PR**: !6848

## 错误特征
```
AttributeError: do_dlsym failed: Symbol not found.*so=/data/service/hnp/bin/python3|FAIL: .*test_python\.py
```

## 根因分析
On workers where dlopen and LD_PRELOAD refuse user-directory shared objects (E2166), the only loader path that accepts them is the process-startup DT_NEEDED chain. A tiny embedded-Python launcher whose own NEEDED entry is the freshly self-signed library under test maps it into the process global symbol scope before the interpreter initializes, so the upstream ctypes binding resolves through its CDLL(None) fallback and the real test logic executes unchanged. The stock interpreter can never do this because no post-start mapping of the library is permitted there.

## 推荐方案
**方法**: embedded-python-launcher

**说明**: Compile launcher.c (Py_Initialize, Py_DecodeLocale-marshalled argv, script-dir sys.path insertion, PyRun_SimpleFileEx) with clang linking the freshly self-signed shared library by full path (NEEDED records the SONAME) plus HNP libpython (rpath to its directory; python3-config --embed fallback when no shared libpython exists); route the automake test through it with make check PYTHON=<launcher>.

**验证/命令**:
```
clang -Wno-deprecated-declarations launcher.c -I "$($PY -c import\ sysconfig\;print\(sysconfig.get_paths\(\)\[.include.\]\)") <PYROOT>/lib/libpython3.12.so <selfsigned>/<libtarget.so> -Wl,-rpath,<PYROOT>/lib -o launcher && make -j1 check PYTHON="$PWD/launcher"
```
