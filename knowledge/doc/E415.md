# E415: CI Mirror-fallback 原地改写 worktree conandata.yml 需在 CI 后恢复（与 L4 误扫关联）

## 基本信息
- **严重度**: 2
- **类别**: conan, recovery, side-effect
- **作者**: GoliWie <GoliWie@noreply.gitcode.com>
- **来源 PR**: !6184

## 错误特征
```
Source URLs rewritten with mirror fallback|\[Errno 2\] No such file or directory: 'curl'|gh-proxy
```

## 根因分析
ci/conan/build_and_test.sh（928-980 行）在 conan create 前把 conandata.yml 的官方 url 单值原地改写为含 gh-proxy 的镜像列表（备份 conandata.yml.orig），且不恢复；设备无 curl 时预下载 9 次全 [fail] [Errno 2] curl，随后依赖 conan 自带下载。改写残留污染 worktree；CI 后必须核验并恢复 conandata.yml 与 HEAD 逐字节一致（无 gh-proxy 残留）。

## 推荐方案
**方法**: verify-and-restore-conandata-after-ci

**说明**: CI 执行后必须把 conandata.yml 恢复为与 HEAD 逐字节一致（官方 URL、无 gh-proxy 残留），再核验 git status 空、diff 仅预期文件；CI 不改（改脚本是基础设施），只做执行期副作用管理与事后恢复。

**验证/命令**:
```
git -C <worktree> status --porcelain; sha256sum <conandata>; grep -e gh-proxy -e ghproxy <conandata>
```
