# E356: Validate fixed-target compilers without mixing target ABIs

## 基本信息
- **严重度**: 2
- **类别**: compiler, testing, abi, path-c, source-provenance
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>

## 错误特征
```
make: inaccessible or not found|Read-only file system|features.h:.*no expression|bits/alltypes.h:.*expected an expression|in eval_const_expr: no expression|in primary: expected an expression|in paste: invalid preprocessing token|cannot open file: No such file or directory
```

## 根因分析
chibicc/1.0.24.1 builds and runs as an OHOS/armv8 executable but unconditionally generates x86-64 code. Upstream tests link and execute the generated x86-64 programs, so the armv8 worker cannot provide executable evidence. Injecting OHOS/armv8 libc headers mixes target ABIs. A musl x86-64 environment is also insufficient for this fork because its self-hosted source assumes glibc header and linker layouts; native execution evidence therefore requires a matching glibc x86-64 userspace.

## 推荐方案
**方法**: two-plane-fixed-target-validation

**说明**: Keep the OHOS/armv8 package gate fail-closed at the source-owned compile boundary, then run the complete upstream stage1 and genuinely self-hosted stage2 suites in a matching glibc x86-64 environment. Require exact source inventories, per-case terminal states, both driver suites, all 13 stage2 self-hosted objects, and explicit pass and execution denominators. Preserve deterministic XFAIL, target-header blockers, compile failures, runtime failures, and missing dependency blockers as non-PASS outcomes.

**验证/命令**:
```
CHIBICC_SOURCE_DIR=<verified-source> CHIBICC_RESULTS_DIR=<results> CHIBICC_JOBS=4 bash test_package/test_native_x86_64.sh
```
