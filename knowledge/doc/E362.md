# E362: Materialize dependency-owned resources when the target filesystem forbids links

## 基本信息
- **严重度**: 2
- **类别**: hmdfs, conan, packaging, symlink, resource-layout
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !5414

## 错误特征
```
PermissionError.*os.symlink|Permission denied.*symlink|missing packaged resource.*link|dangling symbolic link
```

## 根因分析
An upstream resource package may install relative links to files owned by another runtime package. Archive extraction or package copy can omit dangling links, while explicit symlink creation can be rejected by the target filesystem. Blindly copying similarly named local files loses the ownership contract and can silently package stale or unrelated content.

## 推荐方案
**方法**: dependency-derived-resource-materialization

**说明**: Keep the upstream public filename, but derive the source path from the exact Conan dependency package_folder. Copy each dependency-owned target as a regular file during package(), fail if the source does not exist, and expose no machine-specific cache path. In test_package, require a regular non-link file and compare its complete bytes with the same resolved dependency source. Validate the full expected resource inventory separately.

**验证/命令**:
```
|
  dependency_root = self.dependencies["<dependency>"].package_folder
  # Map each upstream linked name to its dependency-owned source.
  # copy(..., keep_path=False) into the package public resource directory.
  # In test_package: test -f "$dst" && test ! -L "$dst" && cmp -s "$src" "$dst"
```
