# E218: link-only-clang-cpp-monolith

## 基本信息
- **严重度**: 2
- **类别**: llvm, linking, runtime
- **作者**: junshi_liu <liujsh2023@lzu.edu.cn>
- **来源 PR**: 2796

## 错误特征
```
CommandLine Error: Option '.*' registered more than once!|LLVM ERROR: inconsistency in registered CommandLine options|libLLVM-15.*libclang-cpp.*NEEDED|mc-relax-all
```

## 根因分析
CastXML 二进制同时 NEED libLLVM-15.so 和 libclang-cpp.so。
                        OHOS SDK LLVM 是 LLVM_ENABLE_SHARED_LIBS=ON 构建，libLLVM-15.so 和 libclang-cpp.so
                        各为独立 monolith，各自拥有完整的 LLVM CommandLine option 注册循环。
                        当 binary 同时 dlopen 两库时，mc-relax-all 等 option 被注册两次，
                        触发 LLVM ERROR: inconsistency in registered CommandLine options，
                        导致进程以 exit 134 崩溃，所有 3919 个 CTest 失败。

## 推荐方案
**方法**: link-only-clang-cpp-monolith

**说明**: 只链接 libclang-cpp.so（OHOS SDK 的 clang monolith 已包含全部 LLVM 符号），
                        移除对 libLLVM-15.so 的直接链接。具体步骤：
                        1. patch CastXML 的 src/CMakeLists.txt：移除/注释 llvm_config(castxml ...) 调用
                        2. patch castxml.cxx：移除 #include "llvm/Support/InitLLVM.h" 和
                           llvm::InitLLVM initLLVM(...) 实例化。OHOS 不需要 LLVM crash handler，
                           直接初始化 llvm::SmallVector(argv_in, argv_in + argc_in) 替代。
                        3. 保持 CLANG_LINK_CLANG_DYLIB=ON，确保 binary 通过 clang-cpp target 链接 libclang-cpp.so。
                        前提条件：libclang-cpp.so 必须是包含所有 LLVM 符号的 monolith。

**验证/命令**:
```
# patches/0007-ohos-llvm-remove-llvm-config.patch + patches/0008-ohos-llvm-remove-initllvm.patch
                        # 验证: readelf -d castxml | grep NEEDED (应只输出 libclang-cpp.so)
                        # castxml --version (exit 0); ctest --output-on-failure (应全通过)
```
