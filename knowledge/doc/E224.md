# E224: alternate signal stack 的拥有者线程注销与 backing memory 回收顺序

## 基本信息
- **严重度**: 3
- **类别**: syscall, threading, runtime, memory
- **作者**: GoliWie <GoliWie@noreply.gitcode.com>
- **来源 PR**: metrics_success_count:  2

## 错误特征
```
SIGSEGV\(SEGV_MAPERR\).*free|je_arena_dalloc_small|TaskData::~TaskData|free\(signalStack\)|sigaltstack.*SS_DISABLE
```

## 根因分析
线程注册 alternate signal stack 后，在拥有者线程生命周期结束前未完成注销，却由析构或 join 后路径释放 backing memory，形成注册资源与内存回收顺序冲突；具体平台表现可能是崩溃或悬空状态。

## 推荐方案
**方法**: owner-thread-altstack-lifecycle

**说明**: 当前 source event 在 OHOS 发现；实现应由 SA_ONSTACK 与 HAVE_SIGALTSTACK 能力探针门控，由拥有者线程在退出前注销 alternate stack，确认结果后再回收 backing memory；失败时不得无条件危险释放。

**验证/命令**:
```
在拥有者线程退出或 TLS 清理前调用 sigaltstack(SS_DISABLE)，记录结果，再执行后续回收；用原始多线程负载重复验证。
```
