# E491: Harden legacy Autotools packages for HMDFS and staged OHOS installs

## 基本信息
- **严重度**: 2
- **类别**: hmdfs, autotools, legacy-c, staged-install
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !5343

## 错误特征
```
Permission denied.*configure|cannot create.*subs1\.awk|multiple definition|install.*(/bin|/share)
```

## 根因分析
Legacy generated Autotools files can assume directly executable source scripts, private temporary directories that remain usable by child processes, common-symbol merging, and recursive install rules that honor the selected prefix without an explicit staging root. These assumptions fail independently on OHOS/HMDFS and with modern Clang defaults.

## 推荐方案
**方法**: patch-each-autotools-failure-layer-and-run-end-to-end

**说明**: Invoke a readable configure script through sh when direct execution is unreliable; create a per-build writable TMPDIR with compatible permissions; replace tentative definitions with extern declarations plus one definition; propagate DESTDIR through every recursive Makefile.in install rule; distinguish declared upstream tests from files actually present in the release archive; then validate a real generated artifact with another packaged command.

**验证/命令**:
```
sh configure <args> && make -j1 && make DESTDIR=<package-root> install
```
