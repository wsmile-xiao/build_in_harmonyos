## 错误特征
```
operation not permitted|Operation not permitted|Permission denied.*ELF|codesign|section already exists|cannot open.*elf
```

## 根因分析
鸿蒙系统的 ELF 可执行文件必须包含有效的 `.codesign` 签名段才能被内核加载执行。
                        patchelf（修改 RPATH）、llvm-strip（移除调试符号）、llvm-objcopy（修改段）
                        等工具修改 ELF 文件后会使签名失效。
                        binary-sign-tool 无法覆盖已有签名段（报 "section already exists"），
                        必须先移除旧签名再重新签名。签名后文件权限归零需重新 chmod +x。
                        四步流程顺序不可变，任何一步跳过都会导致运行失败。

## 推荐方案
**方法**: post-install-script

**说明**: 遵循四步 post-install 流程：移除签名 → 修改 ELF → 重新签名 → 恢复权限。顺序不可变。

**验证/命令**:
```
|
  # Step 1: 移除旧签名（必须先做！）
  llvm-objcopy --remove-section .codesign $TARGET_FILE

  # Step 2: 修改 ELF（patchelf/strip/objcopy 等）
  patchelf --set-rpath '$ORIGIN/../lib' $TARGET_FILE
  # 或: llvm-strip $TARGET_FILE
  # 或: llvm-objcopy --only-keep-debug ...

  # Step 3: 重新签名（必须！）
  binary-sign-tool sign -inFile $TARGET_FILE -outFile $TARGET_FILE -selfSign 1

  # Step 4: 恢复权限（签名后权限归零！）
  chmod a+x $TARGET_FILE
```
