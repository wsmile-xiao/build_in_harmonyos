# E077: ELF 签名失效导致 Operation not permitted

> **类别**: elf-signing/post-processing/packaging | **严重度**: 🔴 | **触发**: patchelf/strip/objcopy | **阶段**: post-install**
> **来源**: harmonyos-specifics.md §2 + Python 3.9.0 可移植打包经验

---

## 错误现象

```bash
$ ./myprogram
zsh: operation not permitted

$ ./python3.9 --version
zsh: operation not permitted

$ ls -la myprogram
-rw------- 1 user user 84K ...   # 注意：没有 x 权限！
```

关键特征：
- 文件刚经过 `patchelf`、`llvm-strip` 或 `llvm-objcopy` 处理
- `chmod +x` 无效（如果签名已失效，chmod 不能恢复执行能力）
- `llvm-readelf -S` 显示 `.codesign` 段存在但内容已过时

## 根因分析

### 鸿蒙 ELF 签名机制

每个可执行的 ELF 文件必须包含两个关键段：

| 段名 | 说明 | 大小 |
|------|------|------|
| `.note.ohos.ident` | 平台标识段 | 小 |
| `.codesign` | 签名数据段 | 4KB 对齐 |

**任何对 ELF 文件内容的修改都会使签名失效**：

```
原始 ELF (.codesign 有效)
    ↓ patchelf --set-rpath
ELF 内容变更 → .codesign 与内容不匹配
    ↓ 尝试执行
内核校验签名 → ❌ 不匹配 → Operation not permitted
```

### 为什么不能直接覆盖签名？

`binary-sign-tool sign` 在检测到已有 `.codesign` 段时报错：

```
binary-sign-tool: section already exists
```

必须先用 `llvm-objcopy --remove-section .codesign` 移除旧段。

### 四步流程及顺序约束

```
Step 1: llvm-objcopy --remove-section .codesign
    │   ← 必须第一步！否则 patchelf 报 "Operation not permitted"
    ▼
Step 2: patchelf / strip / objcopy （实际修改操作）
    │
    ▼
Step 3: binary-sign-tool sign ...
    │   ← 必须在修改后！否则签名与内容不匹配
    ▼
Step 4: chmod a+x
    │   ← 必须最后！签名后权限归零为 000
    ▼
✅ 可执行
```

| 顺序错误 | 后果 |
|---------|------|
| 不移除 .codesign 就 patchelf | `patchelf: open: Operation not permitted` |
| 不签名就运行 | `Operation not permitted`（内核拒绝） |
| 不 chmod +x | `Permission denied`（权限归零） |
| 先签名再 patchelf | 签名再次失效，且无法覆盖（回到起点） |

## 解决方案

### 方案 1：标准四步流程（单个文件）

```bash
TARGET=$HOME/usr/local/bin/myprogram

# 1. 移除旧签名
/data/service/hnp/bin/llvm-objcopy --remove-section .codesign "$TARGET"

# 2. 修改 RPATH
/data/service/hnp/bin/patchelf --set-rpath '$ORIGIN/../lib' "$TARGET"

# 3. 重新签名
/data/service/hnp/bin/binary-sign-tool sign \
    -inFile "$TARGET" -outFile "$TARGET" -selfSign 1

# 4. 恢复权限
chmod a+x "$TARGET"
```

### 方案 2：Strip + Debug 分离 + 签名（发布版本，五步）

```bash
TARGET=$HOME/usr/local/bin/myprogram
DEBUG_DIR=$HOME/usr/local/debug

# 1. 提取 debug info
llvm-objcopy --only-keep-debug "$TARGET" "$DEBUG_DIR/${TARGET##*/}.debug"

# 2. Strip 主文件
llvm-objcopy --strip-debug "$TARGET" "${TARGET}.tmp" && mv "${TARGET}.tmp" "$TARGET"

# 3. 添加 debuglink
llvm-objcopy --add-gnu-debuglink="$DEBUG_DIR/${TARGET##*/}.debug" "$TARGET"

# 4. 移除签名 + 重新签名
llvm-objcopy --remove-section .codesign "$TARGET"
binary-sign-tool sign -inFile "$TARGET" -outFile "$TARGET" -selfSign 1

# 5. 恢复权限
chmod a+x "$TARGET"
```

### 方案 3：批量处理脚本

```bash
#!/bin/sh
# batch-resign.sh — 批量 post-install 处理
PREFIX="${1:-$HOME/usr/local}"

find "$PREFIX/bin" -type f | while read f; do
    # 跳过非 ELF
    file "$f" | grep -q ELF || continue

    llvm-objcopy --remove-section .codesign "$f" 2>/dev/null
    patchelf --set-rpath '$ORIGIN/../lib' "$f" 2>/dev/null
    binary-sign-tool sign -inFile "$f" -outFile "$f" -selfSign 1 2>/dev/null
    chmod a+x "$f"

    echo "✅ $(basename "$f")"
done
```

## 验证

```bash
# 确认签名存在
llvm-readelf -S myprogram | grep -E "codesign|note.ohos"

# 确认 RPATH 已嵌入
llvm-readelf -d myprogram | grep -i rpath
# 期望: 0x000000000000001d (RUNPATH) Library runpath: [$ORIGIN/../lib]

# 确认可执行
./myprogram --version
```

## ⚠️ 禁止事项

| ❌ 不要做 | 原因 |
|-----------|------|
| 编译 ncurses 时使用 `--with-shared` | 共享库可能覆盖系统 libncursesw.so.6，导致 zsh 崩溃 |
| 反复 chmod +x 试图修复 "operation not permitted" | 问题不是权限而是签名，chmod 无法解决 |
| 先签名后 patchelf | 签名再次失效，进入死循环 |
| 删除 `.note.ohos.ident` 段 | 平台标识段不可删除，否则系统无法识别文件类型 |
