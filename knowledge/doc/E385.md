# E385: 为 Cargo 原生 CMake 子构建补全 OHOS SDK 缺失的 llvm-ranlib

## 基本信息
- **严重度**: 2
- **类别**: ohos, cmake, toolchain, rust, archive
- **作者**: wingsluo <wingsluo@noreply.gitcode.com>
- **来源 PR**: !5534

## 错误特征
```
native/llvm/bin/llvm-ranlib.*not found|Error running link command.*crypto|CMAKE_RANLIB.*native/llvm/bin/llvm-ranlib
```

## 根因分析
含原生 C/CMake 子构建的 Rust crate 会通过 build.rs 独立调用 OHOS SDK 的 CMake toolchain。该 toolchain 将 CMAKE_RANLIB 固定为 native/llvm/bin/llvm-ranlib，但当前 SDK 仅提供同目录 llvm-ar，缺少 llvm-ranlib。仅设置 Cargo 的 AR_<target> 或通用 RANLIB 不会覆盖子 CMake cache，导致静态归档索引阶段失败。前置架构配置错误也可能表现为 AES/BN 未定义符号，但该签名必须结合 OHOS_ARCH、CMAKE_SYSTEM_PROCESSOR 和 archive 对象清单单独诊断，不能归因于 ranlib 缺失。

## 推荐方案
**方法**: target-scoped-cmake-toolchain-overlay

**说明**: 保留官方 OHOS CMake toolchain 以获得正确目标架构、sysroot 和汇编源选择；在 Conan/Cargo 构建目录生成只执行 llvm-ar s 的 ranlib 包装器，再生成薄 CMake toolchain overlay，先 include 官方 ohos.toolchain.cmake，随后强制覆盖 CMAKE_RANLIB、CMAKE_C_COMPILER_RANLIB 和 CMAKE_ASM_COMPILER_RANLIB。通过 crate 提供的 target-specific CMAKE_TOOLCHAIN_FILE 环境变量注入，且只作用于目标 crate 子构建。

**验证/命令**:
```
printf '#!/bin/sh\nexec "%s" s "$@"\n' "$LLVM_AR" > "$BUILD_DIR/llvm-ranlib"; chmod +x "$BUILD_DIR/llvm-ranlib"; write overlay including "$OHOS_NDK_HOME/native/build/cmake/ohos.toolchain.cmake" and force CMAKE_*_RANLIB to wrapper; export AWS_LC_SYS_CMAKE_TOOLCHAIN_FILE_aarch64_unknown_linux_ohos="$BUILD_DIR/aws-lc-ohos-toolchain.cmake"; cargo build --release --locked
```
