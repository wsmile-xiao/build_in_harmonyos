## 错误特征
```
no events were recorded|Rprof_memory_summary|Error in Rprof_memory_summary
```

## 根因分析
R 默认使用 RPE_CPU 采样事件，通过 setitimer(ITIMER_PROF) 周期触发 SIGPROF 进行 CPU 性能采样。在 HarmonyOS 上，该定时器存在初始延迟异常：请求 0.02s 的 it_value 实际被内核置为约 1.4s，首个 SIGPROF 远晚于典型 profiling 工作负载的结束时刻，导致采样事件数为 0。属于平台运行时能力差异，不是测试本身或数值功能损坏。

## 推荐方案
**方法**: probe-detect-fallback

**说明**: 在 R_InitProfiling 中、signal(SIGPROF, doprof) 之后增加能力探测：以请求 interval 设置 ITIMER_PROF 后立即 getitimer 回读；若回读 it_value 大于请求值 10 倍（p_got > p_set * 10），判定定时器异常，将 R_Profiling_Event 改为 RPE_ELAPSED 走既有 ProfileThread（pthread_kill(SIGPROF)）路径；探测完成后清零定时器，不残留状态。补丁 0008。

**验证/命令**:
```
cd $R_HOME && patch -p1 < archives/r/r-base/4.5.1/patches/0008-rprof-memory-profiling-cpu-fallback.patch && make -j4 && make install DESTDIR=$TEST_PREFIX
```
