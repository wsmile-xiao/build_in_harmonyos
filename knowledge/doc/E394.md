# E394: LD_PRELOAD 初始化早于 main 时测试环境和夹具必须在 exec 前就绪

## 基本信息
- **严重度**: 2
- **类别**: ld-preload, runtime-init, test-fixture
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !4234

## 错误特征
```
PAM_WRAPPER_SERVICE_DIR.*not set|PAM_SERVICE_ERR|pam_start.*failed|run_pamtest.*failed|No such file or directory.*passdb
```

## 根因分析
动态加载器在进入消费者 main() 前加载 LD_PRELOAD 库并执行其初始化逻辑。若 preload 库在此阶段复制环境变量或打开配置路径，消费者随后在 main() 中 setenv、创建服务文件或生成数据库都已经太晚；库会继续使用启动时捕获的空值或不存在路径。

## 推荐方案
**方法**: parent-prepare-then-exec

**说明**: 由 Conan test()、CTest launcher 或父进程先创建完整配置目录和状态文件，再一次性设置绝对路径环境变量与 LD_PRELOAD 并 exec 子进程；消费者 main() 只执行功能断言，不承担 preload 初始化输入的准备工作。

**验证/命令**:
```
mkdir -p <service-dir> <runtime-dir> && write-fixtures && PAM_WRAPPER_SERVICE_DIR=<service-dir> PAM_WRAPPER_RUNTIME_DIR=<runtime-dir> LD_PRELOAD=<wrapper.so> <consumer-test>
```
