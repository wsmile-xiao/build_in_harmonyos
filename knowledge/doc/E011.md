## 错误特征
```
Permission denied.*conf.*\.tmp|
                         cannot create.*subs[0-9]*\.awk.*Permission denied|
                         cannot create.*subs[0-9]*\.sed.*Permission denied|
                         config\.status.*error.*creating.*tmp|
                         umask 077.*mktemp
```

## 根因分析
HMDFS 文件系统的 UID 映射机制导致 umask 077 创建的
                         临时目录无法被当前进程写入。autotools 的 configure 脚本
                         在生成 config.status 时，使用 `mktemp -d "./confXXXXXX"`
                         创建临时目录，并先执行 `umask 077` 设置权限。
                         在 HMDFS 上，目录所有者 UID 被映射为 20001006，
                         而进程实际 UID 为 20020083，导致 0700 权限的目录
                         对当前进程不可写。
                         此外 HMDFS 可能给目录设置 setgid 位（02700），
                         进一步加剧权限问题。

## 推荐方案
**方法**: edit-umask-in-configure

**说明**: 修改 configure 脚本中 `umask 077` 为 `umask 022`（或 000/007）。
                         方法 1（推荐）: `./configure --no-create` → 编辑 config.status
                         将 `umask 077` 改为 `umask 022` → 手动运行 `./config.status`。
                         方法 2: 直接 `sed -i 's/umask 077/umask 022/g' configure`
                         然后正常运行 `./configure`。
                         umask 022 允许同组用户写入，在无多用户场景下安全。

**验证/命令**:
```
sed -i 's/umask 077/umask 022/g' configure && ./configure --prefix=$DEFAULT_PREFIX
```
