# E011 — HMDFS 文件系统 umask 077 权限问题

## 错误特征

运行 `./configure` 时，config.status 在创建临时目录后写入文件失败：

```
config.status: creating config.h
./conf12345/subs1.awk: Permission denied
./conf12345/subs1.sed: Permission denied
config.status: error: could not create ./conf12345
```

或 configure 本身直接报错：

```
cannot create temp file for here-document: Permission denied
```

## 触发条件

- 构建系统: autotools（所有使用 autoconf 的项目）
- 阶段: configure / config.status
- 平台: HarmonyOS HMDFS 文件系统

## 根因分析

autotools 的 configure 脚本在创建临时文件/目录时使用 `umask 077` 保护临时数据。这在 ext4 等传统文件系统上正常工作，但在 HMDFS 上：

1. **UID 映射不匹配**: HMDFS 将文件所有者映射为 UID 20001006，而进程实际 UID 为 20020083
2. **umask 077 效果**: 创建的临时目录权限为 0700（仅 owner 可访问），但 owner 不是当前进程
3. **setgid 位**: HMDFS 可能给目录设置 setgid 位（02700），进一步限制写入

受影响的代码位置：
- `configure` 中的 `umask 077` + `mktemp -d "./confXXXXXX"`
- `config.status` 中同样的模式

## 解决方案

### 推荐方案：修改 configure 中的 umask

```bash
# 方法 1: 直接修改 configure（推荐）
sed -i 's/umask 077/umask 022/g' configure
./configure --prefix=$DEFAULT_PREFIX

# 方法 2: 分步操作
./configure --no-create --prefix=$DEFAULT_PREFIX
sed -i 's/umask 077/umask 022/g' config.status
./config.status
```

### 禁止做法

- ❌ 使用 `--build=xxx --host=xxx` 绕过 configure（会导致 AC_RUN_IFELSE 跳过，级联错误）
- ❌ 手动 chmod 临时目录（不可靠，每次 configure 都会重新创建）

## 验证

```bash
# 验证 configure 中是否还有 umask 077
grep "umask 077" configure

# 验证 config.h 生成正确
grep "HAVE_STDIO_H" config.h

# 验证完整编译流程
make -j$(nproc)
```
