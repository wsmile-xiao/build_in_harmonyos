# E011: HMDFS 文件系统 umask 077 权限问题

## 错误特征

运行 `./configure` 时，config.status 在创建临时目录后写入文件失败：

```
config.status: creating config.h
./conf12345/subs1.awk: Permission denied
./conf12345/subs1.sed: Permission denied
config.status: error: could not create ./conf12345
```

或 configure 本身直接报错：

```
cannot create temp file for here-document: Permission denied
```

## 触发条件

- 构建系统: autotools（所有使用 autoconf 的项目）
- 阶段: configure / config.status
- 平台: HarmonyOS HMDFS 文件系统

## 根因分析

autotools 的 configure 脚本在创建临时文件/目录时使用 `umask 077` 保护临时数据。这在 ext4 等传统文件系统上正常工作，但在 HMDFS 上：

1. **UID 映射不匹配**: HMDFS 将文件所有者映射为 UID 20001006，而进程实际 UID 为 20020083
2. **umask 077 效果**: 创建的临时目录权限为 0700（仅 owner 可访问），但 owner 不是当前进程
3. **setgid 位**: HMDFS 可能给目录设置 setgid 位（02700），进一步限制写入

受影响的代码位置：
- `configure` 中的 `umask 077` + `mktemp -d "./confXXXXXX"`
- `config.status` 中同样的模式

## 解决方案

### 推荐方案：修改 configure 中的 umask

```bash
# 方法 1: 直接修改 configure（推荐）
sed -i 's/umask 077/umask 022/g' configure
./configure --prefix=$DEFAULT_PREFIX

# 方法 2: 分步操作
./configure --no-create --prefix=$DEFAULT_PREFIX
sed -i 's/umask 077/umask 022/g' config.status
./config.status
```

### 禁止做法

- ❌ 使用 `--build=xxx --host=xxx` 绕过 configure（会导致 AC_RUN_IFELSE 跳过，级联错误）
- ❌ 手动 chmod 临时目录（不可靠，每次 configure 都会重新创建）

## 验证

```bash
# 验证 configure 中是否还有 umask 077
grep "umask 077" configure

# 验证 config.h 生成正确
grep "HAVE_STDIO_H" config.h

# 验证完整编译流程
make -j$(nproc)
```

## 极端方案：手动生成配置文件（Fallback 2）

> **适用场景**: 当 umask 修改方案（推荐方案 / Fallback 1）均无法解决时。
> 例如 HMDFS 的极端限制导致即使 umask 000 临时目录仍不可写，config.status 完全无法运行。

### 方案 A：手动从 config.h.in 创建 config.h

当 config.status 无法生成 config.h 时，可以手动从模板创建：

```bash
# Step 1: 先运行 configure --no-create 获取检测结果（写入 config.log）
./configure --no-create --prefix=$DEFAULT_PREFIX 2>&1 | tee config.log

# Step 2: 从 config.h.in 生成 config.h，将 #undef 改为 #define
# 注意：需要根据 config.log 中的检测结果判断哪些宏需要启用
sed 's/^#undef \(.*\)/#define \1 1/' config.h.in > config.h

# Step 3: 手动修正 config.h（可选但推荐）
# 查看 config.log 确认关键检测结果，移除不需要的 #define
# 例如有些检测需要特定值而非简单的 1：
#   #define SIZEOF_LONG 8          （不是简单的 1）
#   #define HAVE_STRUCT_STAT_ST_BLKSIZE 1
#   #define PACKAGE_VERSION "x.y.z"（字符串值）
```

**注意事项**：
- 此方案将所有 `#undef` 全部改为 `#define 1`，可能启用了一些实际不具备的功能
- 编译后运行 `make check` 验证功能正确性
- 关键宏（如 `SIZEOF_*`, `PACKAGE_VERSION`）需要手动修正为正确值

### 方案 B：从 Makefile.in 创建 Makefile（条件赋值）

```bash
# Step 1: 将 Makefile.in 中的硬赋值替换为条件赋值
# = 替换为 ?= 允许环境变量覆盖
sed 's/\([A-Z_]*\) = /\1 ?= /g' Makefile.in > Makefile

# Step 2: 设置关键变量后编译
make -j$(nproc) \
  CC=gcc \
  CFLAGS="-O2 -pipe" \
  PREFIX=$DEFAULT_PREFIX
```

### 方案 C：创建独立 Makefile.manual

当以上方案均不适用时，创建完全独立的 Makefile：

```makefile
# Makefile.manual — 完全脱离 autotools 的手动构建文件
# 使用方法: make -f Makefile.manual install

CC       ?= gcc
CFLAGS   ?= -O2 -pipe -Wall
LDFLAGS  ?=
PREFIX   ?= $(HOME)/usr/local
DESTDIR  ?=

SRCDIR   := .
OBJDIR   := build

# 自动发现 .c 文件并编译为 .o
SRCS     := $(shell find $(SRCDIR) -name '*.c' ! -path '*/test*' ! -path '*/example*')
OBJS     := $(patsubst $(SRCDIR)/%.c,$(OBJDIR)/%.o,$(SRCS))
TARGET   := $(PREFIX)/bin/$(shell basename $(CURDIR))

.PHONY: all install clean check

all: $(TARGET)

$(TARGET): $(OBJS)
	@mkdir -p $(@D)
	$(CC) $(CFLAGS) -o $@ $^ $(LDFLAGS)

$(OBJDIR)/%.o: $(SRCDIR)/%.c
	@mkdir -p $(@D)
	$(CC) $(CFLAGS) -c -o $@ $<

install: all
	@echo "Installed to $(TARGET)"

check:
	@echo "Skipping make check (manual Makefile, no test harness)"

clean:
	rm -rf $(OBJDIR)
```

```bash
# 使用方法
make -f Makefile.manual PREFIX=$DEFAULT_PREFIX
make -f Makefile.manual install PREFIX=$DEFAULT_PREFIX DESTDIR=$TEST_PREFIX
```

### 极端方案的适用判断

```
umask 修改后 configure 是否成功？
├─ 是 → 正常流程（推荐方案 / Fallback 1 已解决）
└─ 否 → config.status 是否能运行？
    ├─ 能 → 检查 config.h 是否正确生成
    └─ 否 → 使用极端方案
        ├─ 软件结构简单 → 方案 A（手动 config.h）
        ├─ 有 Makefile.in → 方案 B（条件赋值）
        └─ 结构复杂/多模块 → 方案 C（Makefile.manual）
```
