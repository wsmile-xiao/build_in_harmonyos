# E403: Conan test() 每次运行在 test_package 再生构建/测试残留，交付前必须清理且不入 commit

## 基本信息
- **严重度**: 2
- **类别**: conan, packaging, testing, delivery-hygiene
- **作者**: GoliWie <GoliWie@noreply.gitcode.com>
- **来源 PR**: !5084

## 错误特征
```
__pycache__|conanbuild\.sh|dirty.*source tree
```

## 根因分析
Conan 2.x 的 test()/conan create 在 test_package/ 目录生成 CMake/环境脚本与运行残留：mlton-consumer（测试 ELF 二进制）、__pycache__/、conanbuild.sh、conanrun.sh、conanbuildenv-release-armv8.sh、conanrunenv-release-armv8.sh、deactivate_conanbuild.sh、deactivate_conanrun.sh、deactivate_conanrunenv-*.sh、metadata/ 等。这些文件不属于配方输入，每次 CI/本地运行都会重新生成；若直接 commit/push 会把脏产物混入仓库（MLton Round 18 web-review 即以 REVISE B1/B2 检出）。交付前必须清理使 test_package 保持 pristine（仅配方输入），并以 KEEP-OK 清单 + RESIDUAL-CLEAN 校验留证。

## 推荐方案
**方法**: pre-delivery-test-package-residual-cleanup

**说明**: 交付/commit 前对 test_package 做残留清理：删除运行时生成的二进制（如 mlton-consumer）、__pycache__/、conanbuild.sh/conanrun.sh/conanbuildenv-*/conanrunenv-*/deactivate_* 脚本与 metadata/，仅保留配方输入（MANIFEST.yml、conanfile.py、测试源、测试脚本），并以 KEEP-OK 清单（5/5）+ 残留校验（10/10 RESIDUAL-CLEAN）留证；CI 之后再次清理并留证，保证提交态与产物态一致。

**验证/命令**:
```
rm -rf mlton-consumer __pycache__ conanbuild.sh conanrun.sh conanbuildenv-release-armv8.sh conanrunenv-release-armv8.sh deactivate_conanbuild.sh deactivate_conanrun.sh deactivate_conanrunenv-release-armv8.sh metadata；校验：ls 后仅剩配方输入，git status 确认 test_package 干净。
```
