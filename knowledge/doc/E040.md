# E040: MAN_OWNER 空指针解引用段错误

> **结构化数据**: [graph/E040.kv](../graph/E040.kv) | **原则**: [P-PATCH-001](../graph/principles.kv)
> **严重度**: 🔴 high | **分类**: security/runtime/null-pointer | **自动修复**: ❌ 手动编辑

---

## 错误特征

```
mandb
# (无输出，直接退出)
echo $?  # 139 = SIGSEGV
```

## 根因

man-db 源码中 `lib/security.c` 的 `get_man_owner()` 函数在 HarmonyOS 上找不到 `man` 系统用户时返回 NULL，但调用方直接解引用返回值 `man_owner->pw_uid` 而未做 NULL 检查，导致段错误。

**问题链**：
```
configure --with-owner=man (默认行为)
    ↓
config.h: #define MAN_OWNER "man"
    ↓
src/mandb.c: struct passwd *man_owner = get_man_owner();
             // 未检查 NULL
             chown(catpath, man_owner->pw_uid, man_owner->pw_gid);
             //                              ^^^^^^^^^^^^^ 段错误!
```

## 解决方案

**方案 1（推荐）：取消 config.h 中 MAN_OWNER 定义**

```bash
sed -i 's/^#define MAN_OWNER "man"/\/\* #undef MAN_OWNER \*\//' config.h
make clean && make
```

最彻底的方案，让整个权限管理代码路径不被编译。

**方案 2：补丁 security.c + 调用方加 NULL 检查**（需改多处）

## 验证命令

```bash
grep MAN_OWNER config.h  # 应看到: /* #undef MAN_OWNER */
mandb -C man_db.conf -c /path/to/man
echo $?  # 应为 0，而非 139
```

## 禁止模式

❌ `getpwnam()` 返回值未做 NULL 检查就直接解引用 `pw_uid`/`pw_gid`/`pw_name` → 鸿蒙上段错误

## 涉及软件

man-db 2.13.1 及所有假设 Linux 系统用户必然存在的软件。
