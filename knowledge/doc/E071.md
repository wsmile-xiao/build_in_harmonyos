# E071: automake 版本不匹配

> **来源**: build-systems.md §10.3 | **严重度**: 🟡 medium
> **触发工具**: configure / autoreconf | **阶段**: configuration

## 问题现象

```
configure.ac: error: requires automake >= 1.17, but 1.16.5 is installed
AUTOMAKE_VERSION mismatch: needed X.Y, have A.B
```

上游 tarball 要求的 automake 版本高于系统安装版本；或时间戳不一致触发 autotools 重生成。

## 根因

1. **版本不足**：configure.ac 中声明的 `AM_INIT_AUTOMAKE([1.17])` 高于系统安装版本
2. **时间戳问题**：autotools 检测到源码比生成的 Makefile.in 更新，尝试调用 autotools 重生成

## 影响范围

man-db 等使用较新 autotools 特性的软件。任何 configure.ac 声明高版本 automake 的项目。

## 推荐方案 (priority 1)

**将 autotools 工具设为 /bin/true 绕过调用**：

> ⚠️ **前提条件**：tarball 必须已包含正确生成的 `Makefile.in` 文件

```bash
ACLOCAL="/bin/true" AUTOHEADER="/bin/true" AUTOMAKE="/bin/true" \
  ./configure --prefix=$HOME/usr/local
make -j1
make install
```

**原理**：让 configure 认为这些工具已经执行过，直接使用已有的 Makefile.in。

## 回退方案 (priority 2)

**VPATH out-of-tree 构建**（同时解决时间戳触发重生成问题）：

```bash
# 源码目录保持只读
SRC_DIR="$HOME/man-db-src"
BUILD_DIR="$HOME/build-man-db"

mkdir -p "$BUILD_DIR"
cd "$BUILD_DIR"

ACLOCAL="/bin/true" AUTOHEADER="/bin/true" AUTOMAKE="/bin/true" \
  "$SRC_DIR"/configure --prefix=$HOME/usr/local
make -j1
make install
```

**优势**：
- 不触碰源码目录时间戳 → 避免触发 autotools 重生成
- 源码和构建产物分离 → 方便多配置构建和清理

⚠️ 注意：VPATH 下某些 make target 名称可能不同（如 `make mandb` vs `make src/mandb`），需检查实际 Makefile。

## 禁止事项

| 禁止模式 | 原因 | 后果 |
|---------|------|------|
| `apt-get install automake` | 鸿蒙非 Debian/Ubuntu | command not found |

## 验证命令

```bash
# 检查当前 automake 版本
automake --version | head -1

# 检查 configure.ac 要求的版本
grep -i "AM_INIT_AUTOMAKE\|prereq" configure.ac | head -3

# 确认 Makefile.in 存在且完整
ls -la Makefile.in */Makefile.in 2>/dev/null | wc -l
```
