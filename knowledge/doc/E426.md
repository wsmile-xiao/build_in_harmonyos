# E426: pico-sdk 的 OHOS 包装应优先构建 tools/pioasm host 工具，而不是顶层 RP 固件工程

## 基本信息
- **严重度**: 2
- **类别**: cmake, conan, embedded-sdk, host-tool
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !6613

## 错误特征
```
PIOASM_VERSION_STRING|PIOASM_GENERATE_PARSER|tools/pioasm|pico_sdk_init.cmake|bare-metal|RP2040|RP2350
```

## 根因分析
pico-sdk 顶层 CMake 面向 RP2040/RP2350 固件和裸机 toolchain；直接配置顶层工程会落入硬件平台、target board、外部 submodule 和固件测试逻辑。tools/pioasm 是独立 host-side CMake 子项目，包含已生成 lexer/parser 源码，适合 OHOS-native 构建与 smoke 验证。

## 推荐方案
**方法**: cmake-subproject-application-package

**说明**: Conan recipe 只 configure tools/pioasm，设置 PIOASM_VERSION_STRING=<version>，关闭 PIOASM_GENERATE_PARSER，打包 bin/pioasm 和 share/pico-sdk；test_package 用 pioasm --version 与 .pio->.h 生成校验代表可执行面。

**验证/命令**:
```
cmake.configure(build_script_folder=os.path.join(self.source_folder, "tools", "pioasm")); cmake.build(build_tool_args=["-j1"])
```
