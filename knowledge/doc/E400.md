# E400: Node.js CLI on HarmonyOS: JITless/WASM capability boundary and cross-UID package-cache consumer validation

## 错误特征
```
Check failed.*__errno_location|Signal 5|Executable not found.*bun|WebAssembly.*undefined|Permission denied.*bin/ai|exit 126
```

## 根因分析
On the tested HarmonyOS armv8 image, Node.js v24.13.0 exits
                        with Signal 5 and `Check failed: 12 == (*__errno_location())`
                        before ai-cli business JavaScript runs. Narrow V8 optimization
                        flags do not avoid the failure; `--jitless` does. The same
                        runtime mode makes `typeof WebAssembly` undefined, so a
                        prebuilt Node CLI containing OpenH264 WASM has a capability
                        trade-off rather than a lossless runtime workaround. Separately,
                        Shadow CI Conan package cache materializes the launcher with
                        a different UID and mode 0750, so direct execution by the SSH
                        test UID returns exit 126 even when the recipe requested 0755.

## 推荐方案
**方法**: capability-matrix-and-package-folder-consumer-test

**说明**: Keep Linux on normal JIT. On OHOS, fail closed for unsupported
                        architectures, use `--jitless` only as a target-specific
                        fallback after recording the normal-JIT failure, and explicitly
                        probe WebAssembly before claiming multimedia support. For
                        cache materialized launchers, execute the real package-folder
                        launcher through `/system/bin/sh` on OHOS, retain direct
                        execution on Linux, and pair the positive consumer test with
                        a destructive package-content negative test.

**验证/命令**:
```
bun test; node --version; node --jitless --version; node --jitless -e "console.log(typeof WebAssembly)"; /system/bin/sh test.sh
```
