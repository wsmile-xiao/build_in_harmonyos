# E277: 库自带 vendored 依赖且 registry 无配方时，在 build() 内编译子项目到 staging

## 基本信息
- **严重度**: 2
- **类别**: build-system, autotools, dependency
- **作者**: nebulamao <xmccln@outlook.com>
- **来源 PR**: 2310

## 错误特征
```
Required library .* not found|could not find .* \(the .* package\)|Package type is 'library', but no 'shared' option declared|undefined reference to .*(libmodbus|popt|apr|libssh|msgpack)
```

## 根因分析
三方库依赖一个未发布到 OHOS 制品仓（ohpcd）且仓库内无 Conan 配方的库；但上游源码包内已自带该依赖的源码（vendored）。无法用 self.requires() 拉取，也不能假设 CI worker 有系统库。

## 推荐方案
**方法**: build-vendored-to-staging

**说明**: 在 build() 里把 vendored 子项目单独 configure(autotools)/cmake 编译为静态库，install 到 build_folder 下的 staging 目录，主库通过 -I/-L 指向 staging 编译链接；PKG_CONFIG_PATH 指向 staging/lib/pkgconfig 让主库 pkg_check_modules 找到。

**验证/命令**:
```
# 伪代码（autotools 子项目）：
                        prefix=$(realpath $BUILD_FOLDER/staging_<dep>)
                        self.run("./configure --prefix=$prefix --disable-shared --enable-static --build=<triplet>", cwd=<dep_src>)
                        self.run("make install", cwd=<dep_src>)
                        # 主库引用：
                        tc.extra_cflags.append("-I$prefix/include")
                        tc.extra_ldflags.append("-L$prefix/lib")
```
