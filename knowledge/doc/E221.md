# E221: 同时提供 CLI 与公开库时应建模完整 Conan library 契约

## 基本信息
- **严重度**: 3
- **类别**: cmake, linking, conan, packaging, api
- **作者**: GoliWie <GoliWie@noreply.gitcode.com>
- **来源 PR**: metrics_success_count:  1

## 错误特征
```
undefined symbol:.*|set\([^)]*_LIBS_RELEASE\s*\)|CMakeDeps.*target.*libs.*empty|non-existent.*include
```

## 根因分析
配方同时安装 CLI 和公开库却按 application 模型声明；生成依赖元数据可能不传播公开库，或默认 include/system library 元数据与安装物不一致，导致 target 缺库、缺系统依赖或引用不存在目录。

## 推荐方案
**方法**: model-cli-library-public-contract

**说明**: 若开发库是公开契约，将包建模为 library，声明 shared 选项，按实际顺序填写 libs/system_libs；无公共头时 includedirs 为空，同时保留 bindirs 暴露 CLI。

**验证/命令**:
```
检查安装的库、头和 bin；配置 package_type/options/cpp_info；用 CMakeDeps imported target 执行真实消费者。
```
