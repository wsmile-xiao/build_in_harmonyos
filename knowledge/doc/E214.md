# E214: Shell 脚本交互式 read 阻塞非交互式执行

## 基本信息
- **严重度**: 2
- **类别**: shell
- **作者**: goblinrs <goblinrs@yeah.net>
- **来源 PR**: source_commit:

## 错误特征
```
read -r void|Press ENTER to continue|Security check failed|hangs indefinitely|timeout kills
```

## 根因分析
Shell 脚本工具（如安全审计工具 lynis）在初始化阶段有交互式安全检查，使用 `read -r var` 等待用户按 ENTER 确认。在非交互环境（conan test_package、CI、L2 smoke test）中，stdin 没有输入，`read` 会永久阻塞，直到被超时机制杀死。常见于安全审计工具（lynis, rkhunter, chkrootkit 等）有交互式安全确认提示。

## 推荐方案
**方法**: non-blocking-read

**说明**: 三种方案（任选其一，推荐组合方案1+2）：1. 非阻塞 read: `read -r var < /dev/null 2>/dev/null || true`；2. 早期参数处理: `for arg in "$@"; do case "$arg" in --version|-V) echo "$VERSION"; exit 0;; esac; done`；3. 终端检测: `[ -t 0 ] && read -r var || true`

**验证/命令**:
```
sed -i 's/read -r void/read -r void < \/dev\/null 2>\/dev\/null || true/' script.sh
```
