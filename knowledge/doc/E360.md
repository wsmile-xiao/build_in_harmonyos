# E360: CMake static-only 构建必须保持安装导出的逻辑包身份稳定

## 基本信息
- **严重度**: 3
- **类别**: cmake, static-library, consumer, install-export
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !5427

## 错误特征
```
include could not find requested file:.*[A-Za-z0-9_]+Targets\.cmake
```

## 根因分析
构建脚本把同时参与目标命名与 install(EXPORT)/Config.cmake 生成的可变库名在 static-only 分支改成带 -static 后缀，而 Config 模板仍以不可变 PROJECT_NAME 引用 Targets，导致包目录、Config、Targets 与 include 路径发生身份漂移。

## 推荐方案
**方法**: separate-logical-package-identity-from-artifact-variant

**说明**: 先按项目变量图手工修改 CMake 源码：保持 PROJECT_NAME 或独立 PACKAGE_NAME 作为不可变的安装包身份；仅在真实 target 名、ALIAS 和 OUTPUT_NAME 上表达 static/shared 变体，并让 Config、Targets、安装目录和 include 根目录统一使用稳定包名。修改完成后执行 rec_command 验证安装结果。

**验证/命令**:
```
cmake -S . -B build -DBUILD_SHARED_LIBS=OFF -DBUILD_STATIC_LIBS=ON -DCMAKE_INSTALL_PREFIX="$PREFIX" && cmake --build build && cmake --install build && cmake -S consumer -B consumer-build -DCMAKE_PREFIX_PATH="$PREFIX" && cmake --build consumer-build
```

## 关键词
mutable logical package name, @PROJECT_NAME@Targets.cmake, install export namespace drift, variant-suffixed package config, static-only export identity
