# E468: PkgConfigDeps writes .pc files but does not extend PKG_CONFIG_PATH, so upstream PKG_CHECK_MODULES probes miss Conan metadata

## 基本信息
- **严重度**: 2
- **类别**: toolchain, conan, pkg-config
- **作者**: Awstme <awstme@qq.com>
- **来源 PR**: !7080

## 错误特征
```
Package [a-z0-9.-]+ was not found in the pkg-config search path|No package .[a-z0-9.-]+. found|configure: error: Package requirements
```

## 根因分析
Conan 的 PkgConfigDeps 只在 generators 目录写出与上游探测名对齐的 .pc 文件，不会把该目录加入 PKG_CONFIG_PATH；AutotoolsToolchain 也不一定包含它。于是上游 configure 的 PKG_CHECK_MODULES 只能看到系统路径，找不到 Conan 生成的元数据，报 was not found in the pkg-config search path。X.Org 类库还会额外需要 xorg-macros.pc（由 util-macros 提供），缺失时 macros_datadir 为空、man/DOCUSER 替换退化却不报错，属于静默降级。

## 推荐方案
**方法**: append-generators-folder-to-pkg-config-path

**说明**: 在 generate() 中显式 self.buildenv_info.append_path('PKG_CONFIG_PATH', self.generators_folder)，并把需要 .m4/.pc 的构建工具（如 util-macros）声明为 tool_requires，让其 package_info 暴露的 PKG_CONFIG_PATH/ACLOCAL_PATH 经 VirtualBuildEnv 生效。

**验证/命令**:
```
self.buildenv_info.append_path('PKG_CONFIG_PATH', self.generators_folder)
```
