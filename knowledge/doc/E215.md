# E215: LuaRocks 3.13.0 targeting Lua 5.5 needs Path B test-dependency handling

## 基本信息
- **严重度**: 2
- **类别**: lua, packaging, testing, relocatable
- **作者**: m0_46382645
- **来源 PR**: https://gitcode.com/OpenHarmonyPCDeveloper/build_in_harmonyos/pull/3886

## 错误特征
```
luacov 0.15.0-1|lua >= 5.1, < 5.5|os.tmpname()|unable to generate a unique filename|luarocks command not found
```

## 根因分析
LuaRocks 3.13.0 supports --lua-version=5.5, but its upstream Busted test harness depends on luacov 0.15.0-1, whose rockspec declares lua >= 5.1, < 5.5. This makes the upstream test dependency incompatible with a lua/5.5.0 target, so Path A cannot be claimed even when the packaged commands build and run.

## 推荐方案
**方法**: path-b-with-consumer-validation

**说明**: Use Path B, record upstream inventory and luacov dependency-range failure, keep test_package separate from upstream tests, execute packaged luarocks commands by absolute path, and cover positive smoke plus deterministic fault injection.

**验证/命令**:
```
python test_package/test_luarocks55.py <package>/bin/luarocks <package>/bin/luarocks-admin
```
