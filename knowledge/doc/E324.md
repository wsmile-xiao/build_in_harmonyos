# E324: 监控型程序在 OHOS 上应把单项指标失败降级为部分数据

## 基本信息
- **严重度**: 2
- **类别**: portability, runtime, system-monitoring
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !7151

## 错误特征
```
collect_cpu_usage.*return -1|collect_memory.*return -1|sysinfo.*return -1|getloadavg.*return -1|fatal.*metrics
```

## 根因分析
这类系统监控程序往往把 CPU、内存、hostname、kernel、
                        loadavg、根分区信息视为同一条成功路径；但在 OHOS 上，
                        个别 /proc、sysinfo、getloadavg 或磁盘探测可能失败。
                        若任一探针直接返回错误，就会把可用的其余指标一起丢掉。

## 推荐方案
**方法**: best-effort-metric-aggregation

**说明**: 将每个指标探针拆成独立的失败边界，初始化结果为 0 或空值；
                        单项失败只跳过对应字段，不要把局部失败升级成整体 fatal。

**验证/命令**:
```
在聚合函数中把 collect_* 改为 void 或返回局部状态；主路径只在
                        真正无法启动时才报错。
```
