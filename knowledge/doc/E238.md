# E238: 嵌入式 Clang 头路径发现必须保留目标 sysroot

## 基本信息
- **严重度**: 3
- **类别**: headers, compiler, clang
- **作者**: 2301_80739235 <2047361658@qq.com>
- **来源 PR**: source_commit:

## 错误特征
```
fatal error: 'features.h' file not found|CLING_CXX_INCL.*c[+][+].*missing sysroot|Signal 11.*features.h
```

## 根因分析
嵌入式 Clang 前端从 clang++ -E -v 输出提取 C++ 头目录时只保留路径名含 ++ 的目录，或把运行时相邻 clang 的任意非空结果视为完整；前者丢弃目标架构与通用 sysroot，后者会让不完整的运行时结果遮蔽配置期完整 fallback，最终使 libc++ 间接包含的 features.h 等 libc 头不可见。

## 推荐方案
**方法**: preserve-and-merge-target-sysroot-includes

**说明**: 在 OHOS/HarmonyOS 路径发现中保留与当前目标 sysroot 匹配的架构 include 和通用 usr/include；通过 CMake 双系统名路由把项目私有特性宏定义到真正编译运行时发现源码的 target；若相邻编译器结果非空但缺少任一级 sysroot，则按稳定顺序补合并配置期已验证目录并去重。Clang resource headers 必须继续使用当前嵌入式前端自身版本，不能混入旧 SDK resource 目录。

**验证/命令**:
```
Compare the adjacent compiler search list with configured CLING_CXX_INCL, merge missing target-sysroot directories, then trace the final include order with cling -v.
```
