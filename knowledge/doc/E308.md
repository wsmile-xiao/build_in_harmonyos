# E308: Conan test_package 模板后缀不被 CI L0c 识别

## 基本信息
- **严重度**: 3
- **类别**: conan, testing
- **作者**: 1catmint1
- **来源 PR**: source_commit:

## 错误特征
```
\[fail\] L0c: No test source files in test_package/|no_test_sources|TEST_SOURCES.*empty
```

## 根因分析
CI L0c 在 conan create 前只用 find 搜索 test_package 两层内以 .c/.cpp/.cc/.cxx/.sh/.py 结尾且不是 conanfile.py 的文件；真实模板若命名为 .c.in、.cpp.in 或 .tmpl，即使随后会生成并编译消费者，也会被判定为没有测试源。

## 推荐方案
**方法**: accepted-test-source-suffix

**说明**: 让至少一个被 test_package 实际 exports/读取/编译或执行的实质测试源保留 L0c 接受的最终后缀，并同步更新 exports_sources、MANIFEST 与测试文档；随后用相同 find 规则和 fresh conan create 双重验证。

**验证/命令**:
```
mv test_package/header_smoke.c.in test_package/header_smoke.c
```
