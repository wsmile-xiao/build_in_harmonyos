# E064: conftest 无法执行导致配置检测失败

> **结构化数据**: [graph/E064.kv](../graph/E064.kv) | **原则**: [P-AUTOTOOLS-001](../graph/principles.kv)
> **严重度**: 🔴 high | **分类**: autotools/configuration/security | **自动修复**: ❌ 手动

---

## 错误特征

```
configure: error: cannot run C compiled programs.
If you meant to cross compile, use '--host'.
See 'config.log' for more details.

config.log: ./conftest: inaccessible or not found
configure:5796: $? = 127
```

## 根因

autotools 的 configure 通过**编译并运行小测试程序**来检测平台能力。在鸿蒙上：

1. configure 编译出 `conftest` 二进制
2. 尝试执行 `./conftest`
3. **首次执行非系统二进制需要安全确认弹窗（E054）**
4. 弹窗超时未点 → 进程被杀 → configure 认为程序无法运行
5. **得出错误结论："此平台不能运行编译出的程序"→ 误判为交叉编译**

### 关键区别

| 场景 | conftest 结果 | configure 行为 |
|------|--------------|---------------|
| 正常（点了弹窗） | exit 0 + 输出 | 正确检测平台能力 |
| 弹窗超时 | exit 127 / Permission denied | **误判为 cross compile** |
| 真正交叉编译 | 不能执行（架构不同） | 正确判断 |

### 如何区分真交叉编译 vs 弹窗超时

```bash
grep "cannot run\|inaccessible\|conftest.*exit" config.log

# 弹窗超时的特征:
#   ./conftest: inaccessible or not found   ← 权限问题
#   $? = 127                               ← 找不到/不能执行

# 真交叉编译的特征:
#   file format not recognized             ← 架构完全不匹配
#   Exec format error                       ← 同上
```

## 影响

当 configure 误判为交叉编译后：

```
cross_compiling=yes
    → AC_RUN_IFELSE 全部跳过
    → 大量检测使用硬编码默认值
    → gnulib 模块选择错误 (E061)
    → 函数可用性检测跳过
    → 符号未声明 (E062)
    → -Werror 级联失败 (E063)
    → 最终编译错误
```

## 解决方案

**方案 1（首选）：手动触发弹窗后再跑 configure**

```bash
./configure --prefix=$PREFIX &
# 快速点击所有弹窗
# 等 configure 完成; 如果超时被杀, 重新跑(此时弹窗已确认过)
./configure --prefix=$PREFIX
```

**方案 2：预填充 `ac_cv_*` 缓存变量**

```bash
cat > config.cache <<'EOF'
ac_cv_c_bigendian=no
ac_cv_func_mmap_fixed_mapped=yes
ac_cv_func_strerror_r_char_p=no
EOF
./configure --prefix=$PREFIX --cache-file=config.cache
```

**方案 3（禁止）**：加 `--host=` 参数 → ❌ 违反 R1 参数最少化原则

## 禁止模式

❌ 在非真交叉编译场景下用 `--host=` 绕过 → 级联错误链

## 涉及范围

**所有 autotools 项目**。这是鸿蒙编译中最常见的**根因性问题**。
