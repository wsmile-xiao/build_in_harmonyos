## 错误特征
```
search.*!=.*failed|ftell.*big.*value|fopen.*wb.*failed|fpos_t.*struct|file.*position.*tracking
```

## 根因分析
在 HarmonyOS musl libc 上，fpos_t 是 struct { off_t __pos; mbstate_t __state; }，
                        而 calc 的 f_tell/f_seek_set 宏按整数类型处理 fpos_t（FILEPOS 类型），
                        导致 fgetpos/fsetpos 返回的 struct 数据被解释为巨大整数，
                        造成 ftell 返回乱码（例：7170310590227061835506233901086），
                        文件位置跟踪（search、fseek 等）全部失效。
                        文件内容读写（fgetline、fgets、fputs）不受影响。

## 推荐方案
**方法**: source-patch

**说明**: 将 FILEPOS 类型从 fpos_t 改为 off_t（64 位整数），
                        f_tell/f_seek_set 宏从 fgetpos/fsetpos 改为 ftello/fseeko。
                        涉及两个补丁：
                        1) have_fgetsetpos.c: typedef off_t FILEPOS（替代 typedef fpos_t FILEPOS）
                        2) file.h: 使用 ftello/fseeko 替代 fgetpos/fsetpos
                        补丁位置：archives/c/calc/2.15.1.0/patches/

**验证/命令**:
```
patch -p1 < patches/0001-have-fgetsetpos-use-off_t-instead-of-fpos_t.patch
                        patch -p1 < patches/0002-file-h-use-ftello-fseeko-over-fgetpos-fsetpos.patch
```
