# E069: automake 鸡生蛋问题

> **来源**: build-systems.md §10.1 | **严重度**: 🟡 medium
> **触发工具**: make | **阶段**: compilation

## 问题现象

编译 automake 自身（或依赖 automake 重生成的项目）时：

- config.status 执行后 Makefile 中存在未替换变量：`@am_AUTOCONF@`、`@am_AUTOMAKE@`
- make check 触发重新生成，导致失败或无限循环
- 报错信息含 `unresolved` / `timestamp` / `regenerate`

## 根因

make 过程需要调用尚未构建好的 automake 来重新生成 Makefile.in 文件，形成循环依赖。

## 影响范围

automake 自身及其依赖链中需要 re-autoconf 的项目。

## 推荐方案 (priority 1)

**使用 gen-all.pl + sed 手动修补**：

```bash
# 1. 用 automake 自带的脚本预生成所有模板文件
perl gen-all.pl

# 2. 手动 sed 修补残留的未替换变量
sed -i 's/@am_AUTOCONF@/autoconf/g' Makefile
sed -i 's/@am_AUTOMAKE@/automake/g' Makefile

# 3. 继续编译
make -j$(nproc)
```

## 回退方案 (priority 2)

**绕过 autotools 调用**（仅当 tarball 已包含正确生成的 Makefile.in）：

```bash
ACLOCAL="/bin/true" AUTOHEADER="/bin/true" AUTOMAKE="/bin/true" \
  ./configure --prefix=$HOME/usr/local
make -j1
```

> ⚠️ 此方案要求 tarball 中已包含正确的 `Makefile.in` 文件。如果 `Makefile.in` 本身就有问题，此方案无效。

## 禁止事项

| 禁止模式 | 原因 | 后果 |
|---------|------|------|
| `aclocal --force` 强制重生成 | 再次触发循环依赖 | 无限循环或同样的未替换变量错误 |

## 验证命令

```bash
# 检查是否还有未替换变量
grep -n '@am_' Makefile 2>/dev/null | head -5
# 无输出 = 已修复
```

## 关联原则

- **P-PATCH-001**: 修改生成文件必须保存为 .patch
- **P-AUTOTOOLS-001**: 禁止 --build/--host 绕过系统检测
