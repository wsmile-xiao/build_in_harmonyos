# E237: HarmonyOS PC ACPI 接口缺失，acpid 类守护进程不可运行

## 基本信息
- **严重度**: 2
- **类别**: platform, runtime, api
- **作者**: junshi_liu <liujsh2023@lzu.edu.cn>
- **来源 PR**: !3959

## 错误特征
```
/proc/acpi: No such file or directory|
                        /sys/bus/acpi: No such file or directory|
                        /sys/firmware/acpi: No such file or directory|
                        no NETLINK_GENERIC in /proc/net|
                        HongMeng Kernel
```

## 根因分析
HarmonyOS PC 内核（HongMeng Kernel 1.12.0 aarch64）不提供 Linux 标准 ACPI
                        用户态接口：/proc/acpi、/sys/bus/acpi、/sys/firmware/acpi 均不存在，
                        /proc/net 中无 NETLINK_GENERIC 协议族。acpid 是纯事件源守护进程，编译期
                        只依赖 libc 与标准头文件（configure/make 全通过），但运行期依赖上述接口
                        接收电源键/合盖/电池/热事件，无接口则无事件源可读，守护进程实际不可运行。

## 推荐方案
**方法**: compile-verify-with-runtime-degradation

**说明**: 编译验证 + 运行期降级/shim 三选一，按目标场景取舍：
                        1. 仅编译验证（积分赛适配基线）：acpid 作为纯可执行包发布，configure/make/
                           conan create/conan-verify 全通过，运行依赖在 notes 中声明 ACPI 缺失。
                        2. 运行期事件源探测降级：patch event.c 让 acpid 启动时探测 /proc/acpi、
                           /sys/bus/acpi、netlink 三种事件源，全部缺失则打印明确诊断日志并退出
                           （而非静默挂起），便于集成方感知平台差异。
                        3. 平台 shim：若 HarmonyOS 有替代电源事件接口（如 hdf/udev 事件），写适配
                           层把平台事件翻译为 acpid 事件格式；当前 probe 阶段未发现该接口，需人工
                           确认后另行评估。
                        probe 阶段结论：采用方案 1（仅编译验证），不虚构可运行结论。

**验证/命令**:
```
# 最小复现（HarmonyOS PC 上执行）:
                        #   ls /proc/acpi/ 2>&1 || echo "MISSING: /proc/acpi"
                        #   ls /sys/bus/acpi/ 2>&1 || echo "MISSING: /sys/bus/acpi"
                        #   ls /sys/firmware/acpi/ 2>&1 || echo "MISSING: /sys/firmware/acpi"
                        #   grep -r NETLINK_GENERIC /proc/net/ 2>/dev/null || echo "no netlink acpi"
                        #   uname -r   # HongMeng Kernel 1.12.0
```
