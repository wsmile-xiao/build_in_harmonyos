# E095: 自定义 configure 脚本不尊重 CXX 环境变量

> **结构化数据**: [graph/E095.kv](../graph/E095.kv)
> **严重度**: 🟡 medium | **分类**: toolchain|custom-configure | **自动修复**: ✅ set-env-var

---

## 错误特征

configure 阶段：
```
checking for c++... no
c++: not found
which: no c++ in (PATH)
```

或构建阶段：
```
./configure: line 123: c++: not found
```

## 根因

部分软件使用自定义 configure 脚本（非 autoconf/automake 生成），脚本中硬编码了
C++ 编译器名称（如 `c++`、`g++`），而非读取 `$CXX` 环境变量。

在 OpenHarmony 上，系统没有 `c++` 命令（仅有 `clang++`），导致 configure 阶段
找不到 C++ 编译器而失败。

这与 autoconf 生成的标准 configure 脚本不同——标准脚本会检查 `$CXX`、`$CC` 等环境变量。

## 影响范围

使用非标准 configure 脚本的软件。已知受影响：
- **lzip** — 压缩工具（自定义 configure 脚本）
- **nasm** — 汇编器（类似问题）

## 解决方案

### 方案 1（推荐）：显式传入 CXX=clang++

```bash
./configure --prefix=$DEFAULT_PREFIX CXX=clang++
```

部分自定义脚本支持在命令行传入编译器变量，但不会自动从环境变量读取。
显式传入参数是最可靠的方式。

如果脚本也使用 CC 变量，一并传入：
```bash
./configure --prefix=$DEFAULT_PREFIX CC=clang CXX=clang++
```

### 方案 2：修改 configure 脚本

如果方案 1 无效（脚本完全忽略命令行参数），直接修改脚本：

```bash
sed -i 's/c++/clang++/g' configure
```

修改后需 `track-edit add` 记录。

## 验证

```bash
# 检查系统是否有 c++ 命令
which c++ 2>&1    # 预期: not found
which clang++     # 预期: /path/to/clang++

# 检查 configure 中硬编码的编译器
grep -n "c++\|CXX\|g++" configure | head -10

# configure 成功后确认编译器
grep "CXX\|c++\|clang++" config.log 2>/dev/null | head -5
```

## ⛔ 禁止

- **不要**创建 `c++` → `clang++` 软链接或 alias 来绕过，这会污染构建环境且可能影响其他软件的编译器检测。
