# E476: OHOS 小对象默认分配未满足 foonathan/memory 的最大对齐契约

## 基本信息
- **严重度**: 2
- **类别**: platform, portability, libc, musl, memory
- **作者**: Awstme <awstme@qq.com>
- **来源 PR**: !7099

## 错误特征
```
REQUIRE\(detail::is_aligned.*\)|heap_allocator.*is_aligned|malloc_allocator.*is_aligned|new_allocator.*is_aligned|alignment.*16
```

## 根因分析
OpenHarmony 的 musl 系运行时对小尺寸 malloc 和 operator new 返回的地址可能只有 8 字节对齐，而 foonathan/memory 的默认、malloc 和 new 分配器在 hosted 实现中要求 detail::max_alignment（本机为 16 字节）；size 为 0 时还必须按至少 1 字节请求对齐分配。

## 推荐方案
**方法**: source-code-patch

**说明**: 在 POSIX hosted 路径（标准 __unix__ 守卫）以 posix_memalign(detail::max_alignment, size ? size : 1) 分配，并以 std::free 释放；Windows 路径保留原有行为。

**验证/命令**:
```
grep -R -n -E 'malloc\(|operator new|is_aligned' include src test && ctest --test-dir build --output-on-failure
```
