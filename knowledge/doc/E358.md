# E358: 旧 Rust Unix 依赖锁图在 OHOS target_env 下的确定性迁移

## 基本信息
- **严重度**: 2
- **类别**: rust, cargo-ohos-lock-compatibility
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !5485

## 错误特征
```
unresolved import.*libc|mismatched types.*nix|target_env.*ohos|could not compile.*libc
```

## 根因分析
旧 Cargo.lock 固定的 libc/nix/ctrlc 版本早于 OHOS target_env 支持，并与现代 Rust 1.97 的目标 ABI/cfg 组合不兼容；仅设置 linker 无法修复依赖源码和锁图。

## 推荐方案
**方法**: semver-bounded-deterministic-lock-migration

**说明**: 先定位引入旧 nix/libc 的直接依赖，在上游 Cargo.toml 允许的 semver 范围内升级最小根依赖，让 Cargo 重解确定性传递锁图；把 Cargo.lock 差异作为可审计补丁导出，并保持 --locked 构建、上游测试和消费者负测。

**验证/命令**:
```
cargo update -p ctrlc --precise 3.5.2 && cargo build --release --locked && cargo test --workspace --release --locked --tests
```
