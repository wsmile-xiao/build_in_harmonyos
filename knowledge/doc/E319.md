# E319: Python noarch 包在 OHOS 受限网络下 import 时自动下载资源导致阻塞/失败；纯 Python 包需 pip wheel --no-deps + site-packages 布局打包

## 基本信息
- **严重度**: 2
- **类别**: network, python, packaging
- **作者**: Fish_bone233 <Fish_bone233@noreply.gitcode.com>
- **来源 PR**: 4638

## 错误特征
```
LookupError:.*corpus|Initial downloading of word corpus|nltk.download|ModuleNotFoundError: No module named '.*'|connection timed out|Failed to establish a new connection|unable to generate a unique filename|ssl.SSLCertVerificationError
```

## 根因分析
(1) 上游 Python 包（如 bacook17/acronym 2.0.0）在模块顶层调用 nltk.corpus.words/brown/gutenberg.ensure_loaded()，语料缺失时自动 nltk.download() 联网下载——OHOS 构建/worker 容器网络受限时 import 挂起或失败，阻塞所有仅 import 包的使用方；(2) 纯 Python noarch 包（py3-none-any.whl）无编译产物，Conan 打包必须用 pip wheel --no-deps 构建 wheel，再以 site-packages 布局（lib/pythonX.Y/site-packages）放入 package，并通过 runenv/buildenv PYTHONPATH 暴露，console_scripts 放 bin/。

## 推荐方案
**方法**: lazy-resource-loading-and-pip-wheel-noarch-package

**说明**: 1) 移除模块顶层的 ensure_loaded()/download() 调用，改为显式惰性 helper（如 ensure_corpus(corpus)），仅在真正执行功能（find_acronyms/main）时调用，语料缺失抛清晰 RuntimeError 提示 nltk.download()；import 模块绝不触网；2) 纯 Python 包 Conan 配方：settings 仅 ("os","arch")，build() 用 python3 -m pip install --break-system-packages --no-deps --prefix=staging 安装，package() 定位 staging 下 lib/pythonX.Y/site-packages 复制到 package 同构目录，bin/ 复制 console_scripts；3) package_info() 中 runenv_info/buildenv_info append PYTHONPATH 指向 package 的 site-packages，bindirs=["bin"]；4) test_package 用 unittest 补全路径 B 测试，find_acronyms 用 FakeCorpus（实现 words()/ensure_loaded()）避免真实语料下载。

**验证/命令**:
```
conan create archives/a/acronym/2.0.0 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing --user=ohpcd --channel=stable
```
