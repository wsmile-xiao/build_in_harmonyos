# E354: Run Redis upstream Tcl suites against signed OHOS binaries

## 基本信息
- **严重度**: 2
- **类别**: hmdfs, ohos, linking, filesystem, security
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !5315

## 错误特征
```
Permission denied.*runtest|Redis test.*failed|REDIS_TEST_TMPDIR|tclsh8\.6.*not found|SIGSTOP.*not.*suspend|pause_process.*accounting
```

## 根因分析
Redis upstream integration tests execute source-tree target binaries and Tcl launchers. On OHOS the binaries must be signed before testing, HarmonyFS can block direct script execution, test state needs user-cache storage, and SIGSTOP can be acknowledged without suspending the process.

## 推荐方案
**方法**: sign-targets-run-all-suites-account-capabilities

**说明**: Declare Tcl as a separate build-only tool, sign all source-tree target commands before testing, invoke launchers through sh, redirect state to user-cache storage, run all four official entry points, and count only named SIGSTOP-dependent tests as skips with a fail-closed helper guard.

**验证/命令**:
```
llvm-objcopy --remove-section .codesign src/redis-*; binary-sign-tool sign ...; REDIS_TEST_TMPDIR=/data/storage/el2/base/cache/redis-test-$$ make -j1 test test-modules test-sentinel test-cluster
```
