# E037: shebang 兼容性（/usr/bin/env 缺失 + 可移植性）

> **结构化数据**: [graph/E037.kv](../graph/E037.kv) | **原则**: 无
> **严重度**: 🟡 medium | **分类**: filesystem/compat/shell/portability | **自动修复**: ✅ batch-sed

---

## 错误特征

```
/usr/bin/env: bad interpreter: No such file or directory
```

## 根因

双重问题合并：
1. **鸿蒙缺少 `/usr/bin/env`**：`#!/usr/bin/env sh` 格式的 shebang 无法执行
2. **硬编码路径不可移植**：构建脚本将解释器绝对路径写入 shebang（如 `#!/data/service/hnp/bin/perl`），换机即失效

## 解决方案

```bash
# 策略：先检测 /usr/bin/env 是否存在，存在则优先可移植格式，不存在则降级为直接 shebang

# 批量修复已安装的脚本（针对无 /usr/bin/env 的平台）
if [ ! -e /usr/bin/env ]; then
  find $PREFIX -type f -exec sed -i 's|#!/usr/bin/env \([^ ]*\)|#!/\1|g' {} +
fi

# 单个文件修复示例
sed -i 's|#!/usr/bin/env sh|#!/bin/sh|' file
sed -i 's|#!/usr/bin/env bash|#!/bin/bash|' file
sed -i 's|#!/data/service/hnp/bin/perl|#!/usr/bin/env perl|' file  # 反向：硬编码→可移植
```

**决策树**：

| 目标平台有 `/usr/bin/env`？ | 推荐shebang | 说明 |
|---------------------------|------------|------|
| ✅ 有 | `#!/usr/bin/env xxx` | 可移植，跨发行版兼容 |
| ❌ 无（鸿蒙） | `#!/bin/sh` 或 `#!/bin/bash` | 直接指定解释器路径 |

## 禁止模式

❌ 构建生成的脚本中使用硬编码平台特定路径作为 shebang → 换机即废
❌ 在已知无 `/usr/bin/env` 的目标平台新写脚本用该格式 → 执行失败

## 涉及软件

libtool 2.4.7、automake 1.16.5（gen-all.pl 生成的脚本）、通用。
