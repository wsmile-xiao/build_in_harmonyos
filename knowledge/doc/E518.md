# E518: CI git-clone 步骤失败——Worker 上 /data/service/hnp/bin/git 缺 libz.so (RUNPATH 硬编码构建机路径 /code/deps_install/lib, musl ldso 不解析)

## 基本信息
- **严重度**: 3
- **类别**: ohos, toolchain, environment
- **作者**: yanjiaxin <yanjiaxin@noreply.gitcode.com>
- **来源 PR**: !6547

## 错误特征
```
Error loading shared library libz\.so.*needed by /data/service/hnp/bin/git|Error loading shared library libz\.so.*git.*exit code 127|git-clone.*exit code 127|libz\.so.*Permission denied
```

## 根因分析
buildbot worker 使用 /data/service/hnp/bin/git (git 2.45.2) 执行 git-clone,
           该二进制 NEEDED libz.so, 但其 RUNPATH 硬编码为 /code/deps_install/lib
           (构建 git 的机器路径, worker 上不存在)。musl ldso 不解析 $ORIGIN,
           只能靠系统默认加载路径。健康 worker 的 /usr/lib/libz.so.1 存在,
           故障 worker 缺失 → git 启动失败 exit 127, 构建在 git-clone 步骤即失败。
           该步骤发生在 checkout-pr / conan 配方可见之前, 配方代码无法干预。

## 推荐方案
**方法**: worker-env-fix-zlib

**说明**: CI 维护者修复 worker 环境: 安装 zlib (libz.so.1) 到系统默认库路径 /usr/lib, 使 git 可加载; 该 worker 上所有 PR 恢复正常

**验证/命令**:
```
将 libz.so.1 安装到 /usr/lib (或从 cmd-pkgs 拉 zlib 包), 然后 /data/service/hnp/bin/git --version 验证
```
