# E543: Autotools 老项目交叉编译（AC_TRY_RUN + flex/bison + test_package）

## 基本信息
- **严重度**: 2
- **类别**: autotools, cross-compilation, toolchain, build-system
- **作者**: songzhenyan
- **来源 commit**: c9c59e3ba84c

## 错误特征
```
cannot run test program while cross compiling
checking for format to printf and scanf a guint64
cannot run C compiled programs
AM_PROG_LEX / AC_PROG_YACC (flex/bison 缺失)
```

## 根因分析
1. configure.in 的 AC_TRY_RUN 探测（libIDL: guint64 printf/scanf 格式测试）在
   交叉编译时无法运行测试程序；2008 版 autoconf 生成的 configure 在
   cross_compiling=yes 分支直接 abort，没有默认值/缓存分支。
2. configure.in 硬性要求 flex + yacc 重新生成 lexer.c/parser.c；CI（OHOS
   构建机）无系统 flex/bison，需 tool_requires 注入。
3. 上游无 make check 目标（tstidl 为 noinst_PROGRAMS），构建验证需由
   test_package 实质调用库 API（IDL_parse_filename 等）完成。

## 推荐方案
**方法**: patch-configure-cross-branch

直接补丁 configure 脚本的交叉编译分支（不改 configure.in，避免构建时依赖
autoconf 重新生成）：

```sh
# for format in ll q I64 循环的 cross_compiling=yes 分支（原文 abort）改为：
if test "$cross_compiling" = yes; then
    libIDL_cv_long_long_format="ll"
    break
else
    # ...原有 AC_TRY_RUN 探测...
fi
```

musl/glibc 的 guint64 格式标准为 %lld（"ll"），可安全默认。

## 回退方案
**方法**: tool-requires-flex-bison

```python
def build_requirements(self):
    if self.settings_build.os == "OHOS":
        self.tool_requires("flex/2.6.4")
        self.tool_requires("bison/3.8.2")
```

macOS 开发机用系统 flex/bison；本机 OHOS 模拟（build=OHOS 但实际 macOS）
通过 `user.build:flex_bison_native` conf 走宿主工具。
