# E087 — HMDFS 上文件无执行权限，脚本无法直接运行

## 错误特征

```
./gpg-error-config-test.sh: Permission denied
make[2]: *** [Makefile:1234] Error 126
```

或：
```
./test-script.sh: /bin/sh: bad interpreter: Permission denied
```

## 触发条件

- 构建系统: autotools / any
- 阶段: installation / testing
- 平台: HarmonyOS HMDFS 文件系统

## 根因分析

HMDFS 文件系统的 UID 映射机制导致 `chmod +x` 操作不生效。新生成的 `.sh` 文件权限为 0600（无执行位），而 Makefile 中通常使用 `./script.sh` 直接执行。

验证：
```bash
# HMDFS 上 chmod 不生效
touch test.sh && chmod +x test.sh && ls -la test.sh
# -rw------- (仍然是 0600，没有 +x)
```

## 解决方案

### 推荐方案：用 `sh` 前缀执行脚本

```bash
# 修改 Makefile 中所有直接执行 .sh 的地方
sed -i 's|\./\([^ ]*\.sh\)|sh ./\1|g' Makefile
```

### 回退方案：用 install 命令替代 cp

```bash
# 在 Makefile 的 install 规则中
sed -i 's|cp \(.*\.sh\)|install -c -m 755 \1|g' Makefile
```

## 验证

```bash
# 验证修改生效
grep '\.sh' Makefile | head -5
make install
```

- 根因: E011（HMDFS umask 077 权限问题的姊妹问题，同为 HMDFS 文件系统限制）
