# E252: Asset-gated libraries need substantive pre-asset consumer tests

## 基本信息
- **严重度**: 2
- **类别**: packaging, testing, api
- **作者**: 1catmint1
- **来源 PR**: source_commit:

## 错误特征
```
version-only smoke passes while context API is unusable|test requires redistributing unavailable runtime assets|missing-asset path is unverified
```

## 根因分析
Libraries that require user-supplied ROMs, firmware, models, or licensed data for their full workload still expose meaningful installed-package contracts before those assets are loaded. Testing only a version function proves linkage but misses allocation, inventory, configuration, cleanup, and explicit missing-asset behavior. Bundling invented or redistributable-looking substitutes would test a different contract and can violate provenance or licensing boundaries.

## 推荐方案
**方法**: substantive-pre-asset-lifecycle-flow

**说明**: Keep the lawful asset boundary explicit. In one installed-package consumer, call real public inventory and capability queries, create and release the primary context, exercise reversible configuration, and require the documented missing-asset result without changing the context to an open or active state. Run the process under the generated package environment. Count the process as one logical flow; its internal semantic checks are assertions, not extra tests.

**验证/命令**:
```
<consumer> && verify exactly one successful process exit
```
