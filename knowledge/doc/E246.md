# E246: HarmonyOS seccomp 拦截 Linux 私有 syscall（adjtimex 等），进程因 SIGSYS 终止

## 基本信息
- **严重度**: 2
- **类别**: compat, kernel, syscall, security
- **作者**: junshi_liu <liujsh2023@lzu.edu.cn>
- **来源 PR**: !3958

## 错误特征
```
SIGSYS|si_code.*SYS_SECCOMP|si_syscall|Signal 31|exit 159|
                        adjtimex.*SIGSYS|syscall 171|seccomp blocked
```

## 根因分析
HarmonyOS 沙箱/安全策略(seccomp 过滤器)直接拦截部分 Linux
                        私有 syscall(如 adjtimex, aarch64 编号 171)。
                        与 E051"未实现 syscall"不同: 被拦截调用通过 seccomp 返回
                        SIGSYS, si_code=1(=SYS_SECCOMP), siginfo_t.si_syscall
                        携带 syscall 号, 进程默认因 SIGSYS 终止(core dump, exit 159)。

## 推荐方案
**方法**: graceful-degradation

**说明**: 无应用层恢复手段(seccomp 策略不可被应用层修改)。
                        适配策略: 检测 SIGSYS(可捕获时)后降级/跳过受限功能,
                        或仅保留不触发受限 syscall 的功能子集。
                        对 CLI 工具: smoke test 使用不触发受限 syscall 的路径
                        (如 --version), 核心功能在鸿蒙上标记为不可用

**验证/命令**:
```
# 信号处理中读取 si_syscall 判断:
                        #   struct sigaction sa; sa.sa_sigaction = on_sigsys;
                        #   sa.sa_flags = SA_SIGINFO; sigaction(SIGSYS, &sa, NULL);
                        #   void on_sigsys(int sig, siginfo_t *si, void *uc) {
                        #       printf("si_signo=%d si_code=%d syscall=%d\n",
                        #              si->si_signo, si->si_code, si->si_syscall);
                        #   }
```
