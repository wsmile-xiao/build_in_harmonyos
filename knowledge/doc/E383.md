# E383: OHOS shared library missing SONAME due to absent Platform/HarmonyOS.cmake module

## 基本信息
- **严重度**: 2
- **类别**: platform, detection, cmake, linking, shared-library
- **作者**: bellaaa_ <bellaaa_@noreply.gitcode.com>
- **来源 PR**: !5618

## 错误特征
```
readelf -d.*lib.*\.so.*no SONAME|SONAME.*not found|soname_gate_failed|CMAKE_SHARED_LIBRARY_SONAME.*empty
```

## 根因分析
CMake 4.x ships no Platform/HarmonyOS.cmake module. The Linux platform module (Platform/Linux.cmake) sets CMAKE_SHARED_LIBRARY_SONAME_C_FLAG=-Wl,-soname,, but without a HarmonyOS equivalent this variable is empty. The link template CMAKE_C_CREATE_SHARED_LIBRARY contains <SONAME_FLAG><TARGET_SONAME>; when SONAME_FLAG is empty the soname is not passed to the linker and the resulting .so has no SONAME field in its ELF dynamic section (readelf -d shows no SONAME). The project's SET_TARGET_PROPERTIES(... SOVERSION ...) has no effect on the binary.

## 推荐方案
**方法**: conan-recipe-soname-flag

**说明**: In conanfile.py generate(), set tc.cache_variables['CMAKE_SHARED_LIBRARY_SONAME_C_FLAG']='-Wl,-soname,' and tc.cache_variables['CMAKE_SHARED_LIBRARY_SONAME_CXX_FLAG']='-Wl,-soname,' so CMake passes -Wl,-soname,<TARGET_SONAME> to the linker. The project's SOVERSION property then resolves TARGET_SONAME to libfoo.so.<major>.

**验证/命令**:
```
tc.cache_variables['CMAKE_SHARED_LIBRARY_SONAME_C_FLAG'] = '-Wl,-soname,'; tc.cache_variables['CMAKE_SHARED_LIBRARY_SONAME_CXX_FLAG'] = '-Wl,-soname,'
```
