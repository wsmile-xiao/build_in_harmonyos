# E270: CLOCK_SGI_CYCLE may be declared but unsupported at runtime

## 基本信息
- **严重度**: 2
- **类别**: platform, compat
- **作者**: 2301_80739235 <2047361658@qq.com>
- **来源 PR**: 1994

## 错误特征
```
clock_gettime\(CLOCK_SGI_CYCLE.*EINVAL|bench -s.*timeout|measure_execution_time.*start_over
```

## 根因分析
Some libc headers expose CLOCK_SGI_CYCLE even though
                        the kernel rejects clock_gettime(CLOCK_SGI_CYCLE, ...)
                        with EINVAL. FFTW 3.3.10 selects this clock when the
                        macro is defined and does not check the return code.
                        Invalid timing samples can repeatedly restart planner
                        measurement and prevent default FFTW_MEASURE planning
                        from terminating.

## 推荐方案
**方法**: source-patch

**说明**: Check clock_gettime(CLOCK_SGI_CYCLE, ...) at runtime and
                        fall back to CLOCK_MONOTONIC only when it fails. Preserve
                        the upstream clock on platforms where it is supported and
                        leave the upstream test arguments unchanged.

**验证/命令**:
```
Patch kernel/cycle.h to check the clock_gettime return value.
```
