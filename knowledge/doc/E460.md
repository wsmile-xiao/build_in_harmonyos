# E460: Pin gnulib and bootstrap tools when Conan builds an Autotools source snapshot

## 基本信息
- **严重度**: 2
- **类别**: portability, build-system, autotools, conan
- **作者**: 2301_79503900 <3308319887@qq.com>
- **来源 PR**: !6602

## 错误特征
```
configure: No such file or directory|bootstrap.*failed|aclocal.*not found|automake.*not found|libtoolize.*not found|gnulib.*not found|po/Makefile\.in
```

## 根因分析
A Git tag can intentionally omit generated Autotools files and expect a matching gnulib tree plus a complete bootstrap toolchain. Treating the tag as a release archive, using an unrelated gnulib revision, or relying on undeclared host tools makes configure generation and the later recursive build non-reproducible.

## 推荐方案
**方法**: pinned-gnulib-bootstrap-toolchain

**说明**: Treat the source tag and gnulib revision as one build input. Declare missing bootstrap tools as Conan tool requirements, pass an absolute gnulib path to bootstrap, make NLS/po generation consistent with the recipe, and build generated library outputs before dependent source targets.

**验证/命令**:
```
conan create . -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```
