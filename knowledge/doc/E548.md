# E548: 静态 glib 双副本 GType 不互通导致跨库 GFile* 的 G_IS_FILE 断言失败：test_package 应避免跨库传递 GObject，改用纯 struct API

## 基本信息
- **严重度**: 2
- **类别**: testing, limitation, linking
- **来源事件**: libcolord 1.4.8 HarmonyOS 适配
- **提升日期**: 2026-10-01

## 错误特征
```
G_IS_FILE.*assert|G_TYPE_CHECK_INSTANCE_TYPE.*failed|cd_icc_load_file.*failed|cd_it8_load_from_file.*failed
```

## 根因分析
glib2 为静态库时，被测库（如 libcolordprivate.so，内嵌 6166 个 glib 局部符号）与测试二进制各链一份静态 glib，GType 类/实例类型注册表不互通；测试侧创建的 GFile*（测试二进制 glib 的 GType 表）传入库内（另一份 glib 的 GType 表）时 G_IS_FILE 跨类型系统检查失败。属构建环境限制（原生 Linux glib 为动态库共享 GType，无此问题），非库代码缺陷。test_package 应只用纯 struct API（如 CdColorRGB/CdIcc）做实质验证，避免跨库传 GObject。

## 推荐方案
**方法**: avoid-cross-library-gobject-in-tests

静态 glib 下涉及跨库 GFile/GObject 的上游测试必然失败（环境限制，非适配缺陷，报告中如实回填原因）；test_package 改用不跨库传 GObject 的纯 struct API 做实质验证

## 实施记录（libcolord 1.4.8）
详见 archives/l/libcolord/1.4.8/notes.md 与 reports/test-report.md。

## 验证
```bash
llvm-nm -g build/lib/colord/libcolordprivate.so 2>/dev/null | grep -c -E 'g_file_|g_type_' ; ./build/tests/colord-test-private 2>&1 | grep -c 'G_IS_FILE'
```
