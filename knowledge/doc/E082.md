# E082: gnulib configure conftest 需要二次运行

> **结构化数据**: [graph/E082.kv](../graph/E082.kv) | **原则**: [P-AUTOTOOLS-001](../graph/principles.kv)
> **严重度**: 🔴 blocking | **分类**: autotools|gnulib | **自动修复**: ✅ configure-rerun

---

## 错误特征

```
checking for stdbool.h... no
checking for stdlib.h... no
checking for stdint.h... no
checking for bool, true, false... no
sed: can't read conftest.c: No such file or directory
configure: error: C compiler cannot create executables
```

随后编译时出现：
```
error: unknown type name 'bool'
error: 'true' undeclared
```

## 根因

这是 **E064（安全弹窗导致 conftest 失败）在 gnulib 项目中的特异性表现**。

gnulib 项目的 configure 使用大量 `AC_RUN_IFELSE` 运行时检测（比普通 autotools 项目密度高得多）。
首次运行时，编译出的 conftest 程序触发 HarmonyOS 安全弹窗：

```
./conftest → 安全确认弹窗 → 超时被杀 → configure 误判为"检测失败"
```

导致 `config.h` 中缺少关键定义：
- `HAVE_STDBOOL_H` 未定义 → gnulib 生成错误的 `stdbool.h` 替换
- `HAVE_STDLIB_H` 未定义 → gnulib 生成错误的 `stdlib.h` 替换
- 级联影响数十个检测

**第二次运行**时弹窗已被接受，conftest 正常执行，检测结果正确。

## 与 E064 的区别

| 维度 | E064（通用） | E082（gnulib 特有） |
|------|-------------|-------------------|
| 触发场景 | 所有 autotools 项目 | gnulib 项目（AC_RUN_IFELSE 密集） |
| 错误特征 | "cannot run C compiled programs" | 大量标准头文件检测为 no |
| 修复方案 | 手动触发弹窗后 configure | configure 两次（第一次接受弹窗） |
| 影响 | 可能成功但 config.h 不准 | 编译必失败（bool 等基础类型未定义） |

## 解决方案

### 推荐方案：configure 二次运行

```bash
# 第一次：触发弹窗（可能检测结果不准）
./configure --prefix=$TEST_PREFIX

# 清理
make distclean 2>/dev/null || true

# 第二次：弹窗已接受，检测结果正确
./configure --prefix=$TEST_PREFIX
```

### 回退方案：config.cache 预填充

适用于反复编译同一软件：

```bash
# 从成功的 config.log 提取 cache
grep -oE 'ac_cv_[a-z_]+=yes' config.log > config.cache
./configure --prefix=$TEST_PREFIX --cache-file=config.cache
```

## 禁止做法

- ❌ 使用 `--build=` 或 `--host=` 参数绕过检测
- 后果：gnulib 基于错误平台假设选择替换模块 → `unknown type name 'bool'` → Werror 级联失败

## 影响范围

所有使用 gnulib 的 autotools 项目：
libpipeline, coreutils, sed, grep, diffutils, gzip, tar, wget, man-db 等
