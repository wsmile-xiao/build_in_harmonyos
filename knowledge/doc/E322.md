# E322: header-only CMake INTERFACE 库的 Conan 配方模式（关闭上游默认 tests/examples + 消费上游 CONFIG target）

## 基本信息
- **严重度**: 2
- **类别**: headers, cmake, conan, packaging
- **作者**: junshi_liu <liujsh2023@lzu.edu.cn>
- **来源 PR**: !7225

## 错误特征
```
TF_BUILD_TESTS|TF_BUILD_EXAMPLES|conan create.*builds tests|find_package\(Taskflow|package_type.*header-library
```

## 根因分析
header-only 库（add_library(X INTERFACE)）在上游 CMake 自带完整 install/export（XConfig.cmake + X::X target）时，若 conanfile.py 直接 conan create，上游默认 ON 的 TF_BUILD_TESTS/TF_BUILD_EXAMPLES 会把 26+ unittests/examples 连带构建，引入 3rd-party 测试依赖并大幅拖慢配包装插；同时配方若不声明 package_type=header-library + self.info.clear()，会错误生成与编译器相关的 package_id 并产出空 .so 链接目标。

## 推荐方案
**方法**: header-only-cmake-interface-recipe

**说明**: 配方声明 package_type="header-library"，package_id() 里 self.info.clear()（header-only 与编译器/arch 无关）；generate() 用 CMakeToolchain 显式关闭上游默认构建选项（TF_BUILD_TESTS=OFF / TF_BUILD_EXAMPLES=OFF / TF_BUILD_BENCHMARKS=OFF / TF_BUILD_PROFILER=OFF / TF_BUILD_CUDA=OFF / TF_BUILD_SYCL=OFF）；build()/package() 走上游 CMake install（自动装 include + XConfig.cmake）；package_info() 设置 cmake_file_name/cmake_target_name 以便 find_package(CONFIG)；test_package 用 find_package(Taskflow CONFIG REQUIRED) + 链接 Taskflow::Taskflow + 真实调用 API（非空壳）。

**验证/命令**:
```
python3 scripts/ohc-run.py conan create archives/c/cpp-taskflow/3.8.0 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```
