# E074: make -j 并行构建失败（FIFO 禁止）

> **类别**: selinux/build-system/filesystem | **严重度**: 🟡 | **触发**: make | **阶段**: compilation
> **来源**: environment.md §5.2

---

## 错误现象

```
make -j2
# 无输出，进程卡住不退出
```

或：

```
make[1]: cannot make pipe: Permission denied
make[1]: *** [all] Error 1
```

关键特征：
- `make -j1` 正常完成
- `make -j2` 及以上卡住或立即报错
- 无明显错误信息时表现为"编译挂起"

## 根因分析

GNU make 的 jobserver 并行机制工作原理：

```
make (parent)
  │
  ├─ 创建 FIFO (命名管道) 用于令牌传递
  │   └─ fork() N 个子 make 进程
  │       └─ 子进程通过 FIFO 读写令牌，控制并发数
```

鸿蒙 **SELinux 策略禁止用户进程创建 FIFO**，导致：
1. `mkfifo()` 系统调用返回 `EACCES`
2. make jobserver 初始化失败
3. 行为取决于 make 版本：**卡住**（旧版等待 FIFO）或 **报错退出**（新版检测到失败）

**与 E009 的区别**：

| 维度 | E009 | E074 |
|------|------|------|
| 触发操作 | 执行 SDK 工具（如 `clang`） | `make -j` 并行构建 |
| SELinux 机制 | 域转换限制 (`hishell_hap → adhoc_bin`) | FIFO 创建权限 |
| 绕过方式 | `cmd \| cat` 管道语法 | 强制 `-j1` 单线程 |

两者同属 SELinux 限制，但拦截的 syscall 不同。

## 解决方案

### 方案 1（推荐）：强制单线程

```bash
make -j1
```

最简单可靠，对所有项目通用。

### 方案 2：禁用 jobserver

通过环境变量关闭 jobserver 机制（保留子 make 的并行能力）：

```bash
export MAKEFLAGS="-j1"
make   # 或 ./configure && make
```

> ⚠️ 注意：此方案仅影响顶层 make，嵌套的子 make 可能仍尝试创建 FIFO。

### 方案 3：configure 阶段禁用

部分 autotools 项目支持在 configure 时指定：

```bash
./configure --prefix=$HOME/usr/local
# 编辑生成的 Makefile：将 $(MAKE) -j 改为 $(MAKE) -j1
sed -i 's/\$(MAKE) -j/\$(MAKE) -j1/g' Makefile
```

## 影响范围

所有使用 GNU make 并行构建的场景：
- **直接编译**：`make -j$(nproc)` 或 `make -j4`
- **间接触发**：某些 configure 脚本内部调用 `make -j`
- **测试阶段**：`make check` 或 `make test` 内部可能使用 jobserver

## 验证修复

```bash
# 确认是 FIFO 问题
mkfifo /tmp/test_fifo 2>&1
# 输出: mkfifo: cannot create fifo '/tmp/test_fifo': Permission denied

# 清理
rm -f /tmp/test_fifo

# 用 -j1 验证编译正常
make -j1 && echo "✅ 编译成功"
```
