# E084: manual-java-native-build

## 错误特征
```
TEMPLATE version mismatch|
                         harmonyos-aarch64 not found in JAR|
                         ant.*not found|mvn.*not found
```

## 根因分析
Java 库（如 JNA）的鸿蒙适配需要同时编译 Java 层和 Native JNI 层，
                        但鸿蒙环境通常缺少 ant/maven 等构建工具。
                        需要手动构建：javac 编译 Java + 生成 JNI 头文件，
                        clang 编译 native .c 并静态链接 libffi，
                        最后 jar 打包。
                        JNA 的 Version.java 使用 TEMPLATE 占位符需替换为实际版本号。
                        JNA 在鸿蒙识别为 harmonyos-aarch64（不是 linux-aarch64），
                        JAR 需包含对应路径。

## 推荐方案
**方法**: manual-java-native-build

**说明**: 手动构建 JNI 库：(1) 替换版本号占位符；(2) javac 编译 Java 源码并生成 JNI 头文件；
                        (3) clang 编译 native .c，静态链接 libffi.a；
                        (4) jar 打包含 harmonyos-aarch64 平台 native library；(5) 签名 ELF。

**验证/命令**:
```
|
  # 1. 修改版本号: Version.java 中 VERSION = "5.19.0", VERSION_NATIVE = "5.19.0"
  # 2. 编译 Java 源码 + 生成 JNI 头文件
  javac -d build/classes -h build/jni-headers \
    -sourcepath src $(find src/com/sun/jna -name "*.java")
  # 3. 编译 Native 层（静态链接 libffi）
  clang -O2 -fPIC -D_REENTRANT -DHAVE_PROTECTION -DNO_JAWT \
    -DJNA_JNI_VERSION='"5.19.0"' -DCHECKSUM='"0"' \
    -I$JAVA_HOME/include -I$JAVA_HOME/include/linux \
    -I$FFI_HOME/include -Ibuild/jni-headers -Inative/ \
    -c native/dispatch.c -o build/dispatch.o
  clang -O2 -fPIC ... -c native/callback.c -o build/callback.o
  clang -shared -o build/libjnidispatch.so \
    build/dispatch.o build/callback.o $FFI_HOME/lib/libffi.a
  # 4. 打包 JAR（含平台 native library）
  mkdir -p build/classes/com/sun/jna/harmonyos-aarch64/
  cp build/libjnidispatch.so build/classes/com/sun/jna/harmonyos-aarch64/
  cd build/classes && jar cf dist/jna.jar com/sun/jna/
  # 5. 签名
  python3 $SKILL_ROOT/scripts/ohc-run.py sign-elf build/libjnidispatch.so
```
