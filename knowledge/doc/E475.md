# E475: Reinitialize Conan source trees before ordered patch replay

## 基本信息
- **严重度**: 2
- **类别**: conan, source-cache-replay
- **作者**: 2301_80739235 <2047361658@qq.com>
- **来源 PR**: !7109

## 错误特征
```
a later conan create re-applies a patch to a source cache left in a postimage state and reports hunk mismatch
```

## 根因分析
Conan retries can invoke source() against the same recipe cache directory after an earlier run applied patches and failed later; reapplying the ordered patch set then sees postimage bytes instead of the official preimage. Strict patch_ng also requires exact hunk offsets and explicit blank-line records.

## 推荐方案
**方法**: fresh-source-and-exact-hunks

**说明**: Bind every patch to the exact official preimage, use standard blank-line context, and use a new recipe revision or explicit source reset so a retry cannot treat a previous postimage as its preimage; do not rely on patch_ng.apply()'s boolean to detect replay.

**验证/命令**:
```
patch_ng.fromfile(patch).apply(strip=0, root=clean_source_root, fuzz=False); compare postimage SHA256; invoke a second call and assert the postimage hash is unchanged; patch --dry-run --forward -p1; git diff --check
```

## 关键词
conan source cache, patch_ng hunk mismatch, repeated create, stale postimage, explicit blank hunk record
