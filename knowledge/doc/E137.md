## 根因分析
Perl 5.42.0 on OpenHarmony is configured with -fstack-protector-strong in both ccflags (correct, compiler flag) and ldflags/lddlflags (incorrect, these are passed directly to ld.lld which does not recognize compiler flags). When ExtUtils::CBuilder::have_compiler() tries to compile and link a test program, ld.lld rejects -fstack-protector-strong as an unknown argument, causing compiler detection to fail. Module::Build::XSUtil then exits with "This distribution requires a C compiler". Additionally, system libraries (libc, libunwind) and musl C library headers are not in ld.lld's default search paths.

## 推荐方案
**方法**: source-patch

**说明**: Override the cbuilder() method in the Module::Build subclass to create ExtUtils::CBuilder with a modified Config hash copy: (1) Remove -fstack-protector-strong from ldflags and lddlflags via regex. (2) Add -L/system/lib64 -L$HOME/usr/local/lib -lunwind -lc to lddlflags for library search paths. (3) Add -I$HOME/usr/local/include to ccflags for musl headers. (4) Clear the _have_c_compiler cache property after SUPER::new() to force re-evaluation with fixed config. Key insight: ExtUtils::CBuilder reads config values from the hash directly (not through Module::Build::Config->get()), so a plain hash must be passed, not a Module::Build::Config object.

**验证/命令**:
```
Override cbuilder() to pass config hash with -fstack-protector-strong removed and -L/-I paths added; clear _have_c_compiler cache after SUPER::new()
```
