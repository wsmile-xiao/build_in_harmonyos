# E083: BiSheng JDK System.load 签名校验

## 严重度: 🔴 3 (高 — 所有 JNI 应用受影响)

## 触发场景

使用 `System.load()` 或 `System.loadLibrary()` 加载自签名的 JNI 库时失败。

## 现象

```
Exception in thread "main" java.lang.UnsatisfiedLinkError: 
  /path/to/libfoo.so: Permission denied
```

但 C 程序用 `dlopen()` 加载同一个 `.so` 完全正常。

## 根因

BiSheng JDK 的 `NativeLibraries.load()` native 方法在内部调用 `dlopen` 前会校验 ELF 的 `.codesign` 段签名是否与 JVM 自身匹配。

| 对比 | JVM 内部 dlopen | C 程序 dlopen |
|------|----------------|--------------|
| 签名校验 | ✅ 校验 .codesign 段 | ❌ 不校验 |
| 系统 JDK + 系统 .so | ✅ 匹配 | N/A |
| 系统 JDK + 自签名 .so | ❌ Permission denied | ✅ 正常 |
| 自签名 JDK + 自签名 .so | ✅ 匹配 | ✅ 正常 |

## 修复方案

### 1. 拷贝 JDK 至可写路径

```bash
cp -a /data/service/hnp/bishengjdk17* $HOME/usr/local/bishengjdk17
```

### 2. 批量签名 JDK 所有 ELF 文件

```bash
python3 $SKILL_ROOT/scripts/ohc-run.py sign-elf --batch $HOME/usr/local/bishengjdk17
# 典型输出：批量签名: 65 个 ELF，65 成功，0 失败
```

### 3. 签名 JNI 库

```bash
python3 $SKILL_ROOT/scripts/ohc-run.py sign-elf libfoo.so
```

### 4. 使用签名后的 JDK 运行

```bash
$HOME/usr/local/bishengjdk17/bin/java -cp app.jar Main
```

## 验证

```java
public class TestLoad {
    public static void main(String[] args) {
        System.load("/path/to/libfoo.so");
        System.out.println("SUCCESS!");
    }
}
```

## 影响范围

所有使用 JNI 的 Java 应用：JNA、JNR、JFFI、lwjgl、Py4J 等。
