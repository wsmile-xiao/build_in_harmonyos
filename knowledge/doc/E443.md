# E443: Build a task-local interpreter and data-path closure for Autotools bootstrap tools on OHOS

## 基本信息
- **严重度**: 3
- **类别**: ohos, autotools, conan, permissions, relocatable
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !6480

## 错误特征
```
(aclocal|automake|libtoolize|glib-genmarshal|glib-mkenums).*Permission denied|gettext source directory .* doesn.t exist|//share/libtool(-conan)?/build-aux|cannot execute.*(aclocal|automake|glib-genmarshal|glib-mkenums)
```

## 根因分析
An OHOS build task can read scripts from a Conan tool package but HMFS cross-UID policy rejects direct shebang execution. Calling the scripts through Perl, Python, or sh bypasses that executable-file boundary, but Gettext and Libtool scripts can still contain installation-time prefix and data-directory paths that are invalid after Conan package relocation. A working bootstrap therefore needs both an executable interpreter bridge and task-local relocation of the scripts' data paths.

## 推荐方案
**方法**: task-local-native-interpreter-and-relocation-closure

**说明**: Copy only the required scripts below the current build folder; patch copied Gettext and Libtool prefix/data paths to their resolved Conan package folders; expose readable shell text when upstream reads a tool with sed; otherwise place a small native launcher at the literal command name that execs a fixed system interpreter with the copied script and required data-directory arguments. Put the task-local tool directories first in PATH and set supported variables such as ACLOCAL, AUTOMAKE, GETTEXTIZE, LIBTOOLIZE, gettext_datadir, ACLOCAL_PATH, and PKG_CONFIG_PATH.

**验证/命令**:
```
CI_PACKAGES="archives/a/avahi-glib/0.9_rc5" zsh ci/conan/build_and_test.sh
```
