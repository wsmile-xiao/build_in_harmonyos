# E457: Static-only dependency absorbed into shared library creates duplicate runtime (crash on vtable dispatch)

## 基本信息
- **严重度**: 2
- **类别**: linking, conan, shared-library
- **作者**: Awstme <awstme@qq.com>
- **来源 PR**: !7064

## 错误特征
```
PC=0 SIGSEGV in final unref/dispose while ASan stays silent; shared consumer links .so that embeds static-only dependency
```

## 根因分析
When a dependency package ships only static archives (e.g. OHOS glib/2.88.0), linking a shared consumer embeds a private copy of the dependency runtime into the .so. The executable additionally links the same static archives, producing two independent registry/GType/state copies. Refcount-only operations happen to work (field arithmetic), but final teardown dispatches through the wrong copy class/vtable and calls a NULL pointer.

## 推荐方案
**方法**: build-consumer-static-or-verify-dependency-shared

**说明**: Default the consumer recipe to shared=False and refuse shared on platforms where the dependency package has no shared objects (raise ConanException with the missing paths, avahi-glib guard pattern). Validate with a minimal repro linked once against .a and once against .so: crash only in the .so variant proves the double-copy mechanism.
