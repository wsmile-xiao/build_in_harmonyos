# E389: Reconcile downstream references after a provider repair keeps the canonical version

## 基本信息
- **严重度**: 2
- **类别**: conan, dependency, publication, validation, versioning
- **作者**: 2301_80739235 <2047361658@qq.com>
- **来源 PR**: !5706

## 错误特征
```
Unable to find '.*\.[0-9]+' in remotes|downstream.*temporary version|canonical package.*downstream reference|dependency version mismatch
```

## 根因分析
A provider repair can replace a broken recipe while retaining the canonical upstream package version and removing a temporary suffixed version. Downstream recipes that were prepared against the temporary reference remain syntactically valid but can never resolve from the official remote, so their release pipeline fails before compilation even though the repaired provider is published.

## 推荐方案
**方法**: canonical-reference-reconciliation

**说明**: Treat the provider repository and formal binary retrieval as the authority. Replace the obsolete downstream reference in recipe and metadata together, add fail-closed graph checks for the exact canonical version and binary presence, and rerun the complete downstream graph, upstream suite, consumer tests, and current-snapshot target validation.

**验证/命令**:
```
conan install --requires=<provider>/<canonical-version> -pr:a=<ohos-profile> -r=ohpcd --build=never
```
