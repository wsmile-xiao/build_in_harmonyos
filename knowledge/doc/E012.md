# E012: 找不到 llvm-ar

> **结构化数据**: [graph/E012.kv](../graph/E012.kv) | **原则**: P-TOOLCHAIN-001
> **严重度**: 🔴 blocking | **分类**: toolchain | **自动修复**: ✅ set-env-var

---

## 错误特征

```
ar: command not found
ar: invalid option -- 'T'
RANLIB: command not found
```

## 根因

使用 GNU `ar` 而非 LLVM `ar`。鸿蒙 SDK 只提供 LLVM 工具链，没有 binutils（GNU ar/RANLIB/NM/STRIP）。

autotools 构建系统默认查找 `ar` 命令，找到的是 toybox 或不兼容版本。

## 验证命令

```bash
which ar          # 可能指向 /usr/bin/ar (toybox)
which llvm-ar     # 应该在 $OHOS_SDK/native/llvm/bin/
ar --version      # GNU ar 或 toybox (错误)
llvm-ar --version # LLVM ar (正确)
```

## 解决方案

设置环境变量指向 LLVM 工具链：

```bash
export AR=llvm-ar
export RANLIB=llvm-ranlib
export NM=llvm-nm
export STRIP=llvm-strip
```

**适用场景**：所有 autotools 项目、任何需要 `ar`/`RANLIB`/`NM` 的构建。

## 涉及软件

所有 C/C++ 库的编译（静态库归档阶段）。
