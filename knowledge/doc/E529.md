# E529: Give OHOS CMake test_package recipes their own tool PATH

## 基本信息
- **严重度**: 3
- **类别**: ohos, cmake, conan, packaging, testing
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !6620

## 错误特征
```
/system/bin/sh: cmake: inaccessible or not found|CMake.configure.*Error 127|test package.*cmake
```

## 根因分析
Conan executes test_package as a separate recipe context. Build environment scripts generated by the package recipe do not automatically repair PATH for CMake.configure() inside the test package. On OHOS shadow CI, cmake and make can live in the same native toolchain directory as clang, so a package can build successfully while its consumer test fails with cmake inaccessible or not found.

## 推荐方案
**方法**: test-package-local-tool-path

**说明**: Add a generate() method to the test_package recipe. For OHOS, derive the tool directory from tools.build:compiler_executables['c'], fall back to /data/service/hnp/bin when present, prepend that directory to PATH with Environment(), and save the script before calling CMake.configure().

**验证/命令**:
```
conan create archives/l/libunwind/1.6.2 --build=missing
```
