# E089: aclocal @am_AUTOM4TE@ 未替换导致 PKG_INSTALLDIR 缺失

## 现象

从 GitHub tarball 或 git 仓库编译 autotools 项目时，运行 `autoreconf --install` 或 `aclocal` 报错：

```
sh: @am_AUTOM4TE@: inaccessible or not found
aclocal: error: @am_AUTOM4TE@ failed with exit status 127
```

后续 `automake` 报错：

```
Makefile.am: error: 'pkgconfig_DATA' is used but 'pkgconfigdir' is undefined
```

## 根因

OHOS 预装的 aclocal 脚本中，`@am_AUTOM4TE@` 是 autoconf 的模板变量，应在安装时被替换为 autom4te 的实际路径。由于平台安装问题，该变量未被替换，导致 aclocal 尝试执行字面字符串作为命令。

在 HMDFS 上，找不到的命令返回 "inaccessible or not found" 而非标准的 "command not found"。

## 影响范围

- aclocal 无法正常生成 aclocal.m4
- PKG_INSTALLDIR 等来自 pkg.m4 的宏不会被包含
- configure 脚本中缺少 pkgconfigdir 定义
- **仅影响**从 git/GitHub tarball 编译（无预生成 aclocal.m4）；release tarball 通常不受影响

## 解决方案

### 方案 1（推荐）：手动替换 PKG_INSTALLDIR

在 `configure.ac` 中：
```autoconf
# 删除: PKG_INSTALLDIR
# 替换为:
AC_SUBST([pkgconfigdir], [\${libdir}/pkgconfig])
```

在 `Makefile.am` 中确保有：
```makefile
pkgconfigdir = $(libdir)/pkgconfig
pkgconfig_DATA = xxx.pc
```

### 方案 2：手动补充 aclocal.m4

跳过 aclocal，手动追加宏定义：

```bash
cat >> aclocal.m4 << 'EOF'
AC_DEFUN([PKG_INSTALLDIR], [AC_SUBST([pkgconfigdir], [${libdir}/pkgconfig])])dnl
EOF
```

## 验证

```bash
# 确认 aclocal 有问题
grep "@am_AUTOM4TE@" $(which aclocal)

# 确认 pkgconfigdir 已正确设置
grep "pkgconfigdir" configure.ac Makefile.am
```
