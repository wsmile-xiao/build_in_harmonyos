# E386: Capability-tested shell and selective Automake dispatcher on noexec source trees

## 基本信息
- **严重度**: 2
- **类别**: hmdfs, autotools, conan, testing, noexec
- **作者**: 2301_80739235 <2047361658@qq.com>
- **来源 PR**: !5661

## 错误特征
```
getcwd.*diagnostic|working directory.*invalid|Permission denied.*RunTest|LOG_COMPILER.*RunGrepTest|configure.*noexec
```

## 根因分析
A HarmonyOS/HMDFS source or build tree can reject direct
                        execution of generated configure helpers and suffixless
                        shell test drivers. A shell binary may still return zero
                        while emitting a getcwd diagnostic, so executable-bit or
                        return-code checks alone do not prove that it can preserve
                        the requested working directory. Automake test lists can
                        mix shell drivers with real ELF tests; routing every test
                        through a shell would change the test semantics. Conan
                        self.run may also source conanbuild after the recipe has
                        selected a shell, silently replacing the tested path.

## 推荐方案
**方法**: capability-tested-shell-and-selective-dispatch

**说明**: Probe each candidate shell from the real build directory
                        and accept it only when `pwd` returns zero with empty
                        output and diagnostics. Reassert the resulting shell in
                        an explicit environment script after Conan's conanbuild
                        environment is sourced. Set CONFIG_SHELL and SHELL for
                        Autoconf, and use LOG_COMPILER only for known suffixless
                        shell drivers; direct ELF tests must continue to exec
                        directly.

**验证/命令**:
```
make -j1 check LOG_COMPILER='<tested-shell> -c <dispatcher>'
```
