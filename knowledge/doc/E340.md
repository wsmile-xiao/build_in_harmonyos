# E340: conan package() 用 glob 递归定位 cargo 产物，绕过 basic_layout 路径不确定性

## 基本信息
- **严重度**: 2
- **类别**: conan, packaging, cargo, layout
- **作者**: 2401_87095818 <zhaowenxiang06@outlook.com>
- **来源 PR**: !4753

## 错误特征
```
aiken binary not found|binary not found.*build.*source|FileNotFoundError.*target/release
```

## 根因分析
conanfile.py 使用 basic_layout(self) 时，build_folder 与
            source_folder 的具体路径取决于 conan 的 layout 解析，
            不同 conan 版本/profile 组合下路径可能不同。cargo build
            产物在 <build>/target/release/<bin>，但 build_folder 的
            确切位置在 conan 2.x 不同 layout 模式下有差异，
            导致 package() 中硬编码的路径（如 self.build_folder）可能
            找不到产物。

## 推荐方案
**方法**: glob-recursive-locate-cargo-artifact

**说明**: 在 conanfile.py package() 中，不硬编码 build_folder 路径，
                 而是用 glob.glob(recursive=True) 在 build_folder 和
                 source_folder 下递归查找 target/release/<bin>，
                 鲁棒定位 cargo 产物。

**验证/命令**:
```
|
  import glob, os
  found = []
  for root in (self.build_folder, self.source_folder):
      found.extend(glob.glob(os.path.join(root, "**", "target", "release", "<bin>"), recursive=True))
  assert found, "<bin> binary not found under build/source folders"
  src_dir = os.path.dirname(found[0])
  copy(self, "<bin>", src_dir, os.path.join(self.package_folder, "bin"))
```
