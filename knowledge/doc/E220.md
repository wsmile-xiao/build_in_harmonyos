## 根因分析
OHOS true-device storage and runtime can diverge from
                         POSIX/Linux assumptions in several independent ways:
                         hardlink/symlink creation may be denied, metadata-only
                         touch on generated executables may fail, -w or
                         POSIX::access(W_OK) may not match actual create/unlink
                         ability, and Configure may detect headers/symbols for
                         runtime features that later fail with SIGSYS/EINVAL.

## 推荐方案
**方法**: composite-ohos-toolchain-adaptation

**说明**: Treat repeated build failures as a connected platform
                         pattern instead of isolated patches: replace upstream
                         link shortcuts with a copy-link wrapper that preserves
                         relative-source semantics; remove timestamp-only touch
                         steps on generated executables; replace unreliable
                         permission predicates with actual create/unlink probes;
                         and disable runtime features when true-device execution
                         proves configure probes are false positives.

**验证/命令**:
```
Set TMPDIR/TMPPREFIX to a build-local writable path;
                         pass Configure through an explicit shell; set lns/LNS
                         to an OHOS copy-link wrapper; patch writeability checks
                         to probe create/unlink; disable misdetected runtime
                         features such as IPC/SysV or HAS_PRCTL_SET_NAME when
                         true-device tests prove SIGSYS/EINVAL failures.
```
