# E541: zlib on OHOS should stay static-only but use PIC objects for DSO consumers

## 基本信息
- **严重度**: 2
- **类别**: ohos, system-same-name-static-pic
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !6617

## 错误特征
```
R_AARCH64_ADR_PREL_PG_HI21|z_errmsg|libz.so|libz.a|non-PIC|shared library
```

## 根因分析
HarmonyOS provides a system libz.so, so publishing another shared libz.so from Conan can collide with system loader paths. However, a plain static libz.a built without -fPIC cannot be linked into shared libraries or Python extension modules on AArch64.

## 推荐方案
**方法**: static-only-pic-archive

**说明**: Build zlib with upstream configure in static mode, keep the package artifact as lib/libz.a, and force CFLAGS to include -fPIC. This avoids publishing a competing libz.so while still allowing downstream shared objects to absorb zlib objects safely.

**验证/命令**:
```
CONFIG_SHELL=/data/service/hnp/bin/bash CC=/data/service/hnp/bin/clang CFLAGS="-O3 -fPIC" /data/service/hnp/bin/bash ./configure --static --prefix=/ && make -j1 && make check
```
