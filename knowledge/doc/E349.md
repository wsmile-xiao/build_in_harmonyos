# E349: pinned-bootstrap-source-and-signed-stage-wrapper

## 错误特征
```
vlang/vc|make v|binary-sign-tool|read-only /tmp|Boehm GC|CMakeToolchain.extra_ldflags
```

## 根因分析
自举编译器类软件常把 bootstrap 源、阶段产物执行、源码根定位
                        和运行时临时目录耦合在一起。V 0.5.2 的默认 Makefile 会在
                        构建阶段拉取 vlang/vc，并立即执行 stage1/stage2/final
                        编译器；HarmonyOS PC 上构建阶段不能依赖联网拉取，生成的
                        ELF 需要签名后才能继续执行，默认 /tmp 可能只读，且默认
                        Boehm GC 在目标上可能报告无效数据根范围。Conan 2 的
                        CMakeToolchain 还区分可执行链接标志和通用链接标志。

## 推荐方案
**方法**: pinned-bootstrap-source-and-signed-stage-wrapper

**说明**: 在 source() 中下载并校验主源码与 bootstrap 源，避免 build()
                        阶段 clone/pull；只运行本地 bootstrap 目标；每个需要立即
                        exec 的 OHOS 阶段产物用 binary-sign-tool 签名并恢复执行位；
                        build/package/test 均设置 recipe-owned TMPDIR/TMP/TEMP；
                        包装 bin/v 让真实编译器在 share/v 下找到 cmd/vlib/thirdparty，
                        并在 OHOS 普通编译调用中追加 -gc none。

**验证/命令**:
```
get(v source) && get(vc source) && make -f Makefile -j1 v VCFILE=v.c OHOS_SIGN_TOOL=binary-sign-tool TMPDIR=$build/tmp
```
