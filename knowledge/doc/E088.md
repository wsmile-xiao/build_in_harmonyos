# E088: HarmonyOS musl namespace 忽略 RUNPATH/LD_LIBRARY_PATH

## 错误特征

Python 扩展模块或第三方共享库加载失败：

```
ImportError: libxxx.so.1: cannot open shared object file: No such file or directory
```

即使已设置 `LD_LIBRARY_PATH` 或使用 `patchelf` 设置了 `RPATH`/`RUNPATH`，仍然无法找到依赖库。`ldd` 显示 `not found`，但库文件实际存在于指定路径。

## 触发条件

- 构建系统: 任何产生共享库的项目
- 阶段: runtime / installation
- 平台: HarmonyOS（musl 动态链接器）

## 根因分析

HarmonyOS 的 musl 动态链接器使用 **namespace 隔离机制**（`ld-musl-namespace`），这是鸿蒙特有的安全设计。该机制会：

1. **忽略二进制自身的 RUNPATH**: ELF 文件中通过 `patchelf --set-rpath` 设置的 `$ORIGIN/../lib` 等 RUNPATH 条目不被 musl 动态链接器识别
2. **忽略环境变量 LD_LIBRARY_PATH**: 设置 `export LD_LIBRARY_PATH=...` 对 musl 动态链接器无效
3. **每个 namespace 有独立的搜索路径**: 不同 namespace（如应用 namespace 和系统 namespace）的库搜索路径互不可见

这意味着传统的 Linux 共享库查找机制（RPATH → LD_LIBRARY_PATH → ldconfig）在 HarmonyOS 上部分失效。

## 解决方案

### 推荐方案：复制依赖库到 lib-dynload/ 目录

Python 扩展模块的标准加载路径 `lib-dynload/` 是 musl namespace 中少数被信任的搜索路径之一。将缺失的 `.so` 文件直接复制到该目录：

```bash
# 查找缺失的共享库
find $DEFAULT_PREFIX -name "libxxx.so*" -type f

# 复制到 Python 的 lib-dynload 目录
PYTHON_DYNLOAD=$(python3 -c "import sysconfig; print(sysconfig.get_path('platlib'))")/lib-dynload
mkdir -p "$PYTHON_DYNLOAD"
cp $DEFAULT_PREFIX/lib/libxxx.so.* "$PYTHON_DYNLOAD/"
```

### 回退方案：在预编译包 install.sh 中自动收集

对于预编译包分发场景，在 `install.sh` 中添加依赖库收集步骤：

```bash
# install.sh 中自动收集 Python 扩展模块的依赖库
PYTHON_DYNLOAD=$DEFAULT_PREFIX/lib/python3.$PY_MINOR/lib-dynload
mkdir -p "$PYTHON_DYNLOAD"
for so in $(find $DEFAULT_PREFIX/lib -maxdepth 1 -name "*.so.*" -type f); do
    cp "$so" "$PYTHON_DYNLOAD/"
done
```

### 禁止做法

- ❌ 依赖 LD_LIBRARY_PATH（musl namespace 会忽略）
- ❌ 仅设置 RPATH/RUNPATH 期望自动解析（namespace 机制下不生效）
- ❌ 修改系统 namespace 配置（需要 root 权限，不可移植）

## 验证

```bash
# 验证库文件已复制到 lib-dynload
ls $DEFAULT_PREFIX/lib/python3.*/lib-dynload/libxxx.so*

# 验证 Python 可以正常导入
python3 -c "import xxx; print(xxx.__version__)"

# 验证依赖链完整
python3 -c "import ctypes.util; print(ctypes.util.find_library('xxx'))"
```
