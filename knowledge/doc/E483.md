# E483: Conan get() 无法从无扩展名下载 URL 推断压缩格式，报 BadZipFile

## 基本信息
- **严重度**: 2
- **类别**: conan, packaging, codeload, source-download, url-extension
- **作者**: bellaaa_ <bellaaa_@noreply.gitcode.com>
- **来源 PR**: !5678

## 错误特征
```
BadZipFile.*File is not a zip file|NotADirectoryError.*zip|conan.*get.*BadZipFile|failed.*uncompress.*zip|Uncompressing.*to.*\.\.\..*error
```

## 根因分析
Conan tools.files.get() 通过 URL 末段文件名推断压缩格式。当下载 URL 末段是 tag/commit 名而非带扩展名的文件名（典型: GitHub codeload 形如 https://codeload.github.com/owner/repo/tar.gz/refs/tags/2.2.0，末段是 "2.2.0"），Conan 把文件存为 "2.2.0" 并默认按 zip 解压，导致 BadZipFile: File is not a zip file。conandata.yml 中虽声明了正确 URL，但 get() 不读 conandata 的 tar_format 字段做格式提示。

## 推荐方案
**方法**: explicit-filename-in-get

**说明**: 在 source() 的 get() 调用中显式传 filename="软件名-版本.tar.gz"，使 Conan 通过扩展名正确识别压缩格式。get(self, **self.conan_data["sources"], strip_root=True, filename="emojify-2.2.0.tar.gz")。conandata.yml 的 URL 无需修改，仍保留 codeload URL（绕过 github.com 阻断）。

**验证/命令**:
```
sed -i 's/get(self, \*\*self.conan_data\["sources"\], strip_root=True)/get(self, **self.conan_data["sources"], strip_root=True, filename="<name>-<ver>.tar.gz")/' archives/<letter>/<name>/<ver>/conanfile.py
```
