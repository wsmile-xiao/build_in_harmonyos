# E219: CI buildenv 下勿将非 HNP python 作为 conan create 硬门禁

## 基本信息
- **严重度**: 2
- **类别**: platform, limitation, ohos, toolchain, python
- **作者**: yanjiaxin <yanjiaxin@noreply.gitcode.com>
- **来源 PR**: 3855

## 错误特征
```
OHOS: no non-sandbox python3 found|inaccessible or not found|/data/app/bin/python3
```

## 根因分析
|
  ci/conan/profiles/ohos-aarch64 的 [buildenv] 将 /data/service/hnp/bin 置于 PATH 首位。
  conan create 内使用 HNP python 做 pip 是预期行为。HNP 进程因 hmmac(E212) 无法
  dlopen 用户路径 .so；同时 /data/app/bin/python3 在 create 沙箱中常 inaccessible。
  将「必须找到非 HNP python」写成 required=True 会导致 CI 在签名/测试前失败，
  而早期无该门禁时 pip+package 本可成功（仅 test 阶段遇 E077/E212）。

## 推荐方案
**方法**: e212-verify-elf-fallback

**说明**: pip 可用任意 python（含 HNP）；E077 签名 + 可选 ctypes preload；live import/CLI 失败且命中 E212 时 ELF 静态校验通过即可，对齐 nanobind

**验证/命令**:
```
|
  # build: python3 -m pip ...（buildenv HNP OK）
  # sign: llvm-objcopy --remove-section .codesign; binary-sign-tool sign -selfSign 1
  # test: try CLI; on Permission denied → llvm-readelf -d rpds*.so
```
