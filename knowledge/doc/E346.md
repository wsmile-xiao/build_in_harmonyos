# E346: OHOS hmmac 沙盒拒绝 make 默认 SHELL=/bin/sh（/bin/sh: Permission denied → Error 127；配置阶段 try-compile 与编译阶段均受影响，改用 Ninja generator 解决）

## 基本信息
- **严重度**: 3
- **类别**: ohos, make, environment, shell, ninja
- **作者**: MakeBlackSheepGreat <yzj876762330@163.com>
- **来源 PR**: !5297

## 错误特征
```
/bin/sh: Permission denied|Error 127|make.*Error 127|make.*Permission denied|SHELL.*/bin/sh|Check for working C compiler.*broken|checking for working C compiler.*broken
```

## 根因分析
CMake 生成的 Makefile 硬编码 SHELL = /bin/sh（第 48 行附近），make 子进程执行每条编译规则时调用 /bin/sh 启动 shell；OHOS OpenDesk 沙盒的 hmmac 策略拒绝执行 /bin/sh（报 /bin/sh: Permission denied），导致所有编译目标静默失败并返回 Error 127/Error 1，日志中 clang 编译器命令零输出。该问题同时影响两个阶段：(1) 编译阶段 make 执行 .o 编译规则；(2) CMake 配置阶段（cmake -B）的 try_compile（如 Check for working C compiler）内部也调用 make + /bin/sh → try-compile 失败 → "Check for working C compiler ... broken" → 干净构建在配置阶段即中止。这是 make 默认 shell 被沙盒拒绝的问题，不是 clang 前端初始化失败，也不是 LD_LIBRARY_PATH 问题。补充：hmmac 还拒绝 symlink() 系统调用（ln -s / cmake -E create_symlink / cmake_symlink_library 均 Permission denied），共享库版本化 symlink 规则需改写为 cp 复制

## 推荐方案
**方法**: cmake-generator-ninja

**说明**: 推荐首选改用 Ninja generator（主编验证 + 实测通过）：cmake -B 配置命令追加 -G Ninja -DCMAKE_MAKE_PROGRAM=/data/service/hnp/bin/ninja。Ninja 直接 exec 编译器，不经 /bin/sh，配置阶段 try-compile 与编译阶段均通过。配套：(1) 共享库版本化 symlink 规则在 Ninja 下位于 build-ohos/CMakeFiles/rules.ninja（rule CMAKE_SYMLINK_LIBRARY），需改写 command 为 cp 循环（for f in $out; do cp -f $in $$f; done）规避 hmmac 拒绝 symlink()；(2) cmake --build 不可再追加 -- SHELL=...（Ninja 会把 SHELL=... 当作 target 报 unknown target）。R33 合规：ninja 路径为显式探测常量

**验证/命令**:
```
# 配置阶段（关键）:\n  self.run('{cm} -B "{bd}" -S "{src}" -G Ninja -DCMAKE_MAKE_PROGRAM=/data/service/hnp/bin/ninja {defs}')\n  # 编译阶段: ninja 直接 exec 编译器，无需 SHELL 覆盖\n  self.run('{cm} --build "{bd}" -j{nj}')  # ⚠️ 勿加 -- SHELL=...（Ninja 报 unknown target）\n  # symlink 补丁（hmmac 拒绝 symlink()）: 改写 CMakeFiles/rules.ninja 中\n  #   rule CMAKE_SYMLINK_LIBRARY 的 command 为\n  #   for f in $out; do cp -f $in $$f; done
```
