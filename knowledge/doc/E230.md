# E230: 源码分发型传输库不能只验证编译宏矩阵

## 错误特征
```
compile matrix passed but runtime transport failed|runtime smoke failed at|loopback transport workflow failed
```

## 根因分析
源码分发型传输实现会按命名空间、角色和传输宏编入不同消费者。逐组合编译只能证明声明与条件编译闭合，函数取址或 sizeof 检查不会执行 bind、listen、connect、accept、read、write 和 close，因此目标系统的套接字策略、地址解析和运行时语义仍可能全部失效。

## 推荐方案
**方法**: compile-matrix-plus-loopback-runtime

**说明**: 保留输入唯一的编译/链接宏矩阵，并按声明与实现相同的条件守卫引用全部目标平台公开入口，但只做函数取址或类型检查的组合必须标为不计数构建预检；再为每种实际支持的传输增加目标机本地回环事务：创建监听端、连接客户端、接收连接、以有界等待检查可读状态、执行标量与向量双向传输、检查地址和本地性，并验证断开与清理所有权合同。平台不支持的传输只能在到达目标操作、精确匹配 errno，并证明描述符和端点终态正确后记录能力限制；若失败操作已经关闭描述符，只释放剩余连接结构，不得再次关闭。其他失败必须保持失败；不得连接外部主机。

**验证/命令**:
```
conan create <recipe> -pr:h=<target-profile> -pr:b=<target-profile> --build=missing
```
