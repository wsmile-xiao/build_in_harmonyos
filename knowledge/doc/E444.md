# E444: HarmonyOS 原生 GLib/GObject 消费方不要假设 ELF .init_array 构造器已完成类型系统初始化

## 基本信息
- **严重度**: 3
- **类别**: ohos, constructors, glib, gobject, runtime-init
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !6619

## 错误特征
```
GObject.*type system.*not initialized|G_IS_OBJECT.*failed|g_object_new.*failed|first GObject use.*HarmonyOS|constructor.*init_array.*not run|g_type_ensure_initialized
```

## 根因分析
GLib/GObject 通常依赖库构造器在进程启动或动态库装载时自动运行 gobject_init()。
                        HarmonyOS 原生 Conan 测试环境中，首次使用 GObject 类型系统前不能总是假设 ELF
                        .init_array 构造器已经按上游预期执行。若消费方直接进入 g_object_new()、
                        G_IS_OBJECT()、GType 查询或 GIO 对象构造，可能暴露类型系统未初始化风险。
                        glib 2.88.0 适配通过新增显式、幂等、线程安全的
                        g_type_ensure_initialized() 入口，在首次 GObject/GIO 使用前兜底调用。

## 推荐方案
**方法**: explicit-idempotent-gobject-init-entry

**说明**: 在 GLib/GObject 适配补丁中提供公开入口 g_type_ensure_initialized()，
                        通过 g_once_init_enter()/g_once_init_leave() 保证幂等和线程安全；
                        若构造器已运行则不重复初始化，若 HarmonyOS 上构造器未先运行则显式执行
                        gobject_init()。消费方 test_package 在首次 GObject/GIO 使用前调用该入口两次，
                        同时覆盖重复调用不会破坏状态的场景。

**验证/命令**:
```
|
  g_type_ensure_initialized();
  g_type_ensure_initialized();
  GObject *o = g_object_new(G_TYPE_OBJECT, NULL);
  g_assert(G_IS_OBJECT(o));
```
