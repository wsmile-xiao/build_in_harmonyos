# E041: automake 版本不匹配触发重生成

> **结构化数据**: [graph/E041.kv](../graph/E041.kv) | **原则**: 无
> **严重度**: 🟡 medium | **分类**: autotools/compat/build-system | **自动修复**: ✅ set-env-var

---

## 错误特征

```
configure.ac: error: requires automake >= 1.17, but automake 1.16.5 is installed
Makefile.am: error: AM_INIT_AUTOMAKE called but too old
```

或更隐蔽的情况：configure 成功但 make 过程中 autotools 检测到源码时间戳比生成的 Makefile.in 更新，触发重新生成。

## 根因

上游 tarball 的 `configure` 脚本是用较新版本的 automake 生成的，但 configure.ac 中声明的 automake 版本要求更高。VPATH 构建中如果源码目录时间戳被 touch 更新，autotools 会尝试重生成。

## 解决方案

```bash
# 方案 1（推荐）：绕过 autotools 重生成工具
ACLOCAL="/bin/true" AUTOHEADER="/bin/true" AUTOMAKE="/bin/true" \
  ./configure --prefix=$HOME/usr/local
make -j1

# 方案 2（推荐，避免时间戳问题）：VPATH 构建
mkdir -p $HOME/src-only    # 原始源码（只读）
mkdir -p $HOME/build-dir   # 构建目录
cd $HOME/build-dir
ACLOCAL="/bin/true" AUTOHEADER="/bin/true" AUTOMAKE="/bin/true" \
  ../src-only/configure --prefix=$HOME/usr/local
make -j1
```

## 禁止模式

❌ 在已包含正确生成的 Makefile.in 的 tarball 上运行 `autoreconf` 或手动 `touch` 源码文件 → 触发重生成 → 版本不匹配错误

## 涉及软件

man-db 2.13.1 及其他使用 autotools 的项目。
