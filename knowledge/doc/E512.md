# E512: 纯 Python 包 build() 自检 import 运行时 Python 包，宿主环境预装而 CI 干净环境缺失导致本地通过、远程 CI 失败

## 基本信息
- **严重度**: 2
- **类别**: python, dependency, ci-env
- **作者**: xioaxin <3990149441@qq.com>
- **来源 PR**: !5985

## 错误特征
```
ModuleNotFoundError: No module named .unidecode.|ModuleNotFoundError: No module named .*
```

## 根因分析
纯 Python 包（无 C 扩展）的 build()/test_package 自检会 import 包内子模块，若子模块顶层 import 第三方运行时 Python 包（如 venc3.datastore -> unidecode），宿主开发环境预装该包时本地 conan create 通过，而 CI worker 为干净环境缺少该包，导致 conan-build-test 阶段 ModuleNotFoundError

## 推荐方案
**方法**: add-deps

**说明**: 在 conanfile.py build() 与 test_package test() 的 pip install 中显式安装运行时 Python 包依赖（unidecode/pyyaml 等，社区源 pypi.cnb.cool 有 cp312-ohos_aarch64 预编译 wheel，先 pip download 验证可得性）；或在自检中跳过依赖外部包的子模块

**验证/命令**:
```
pip download unidecode pyyaml --no-deps -d ./dl && conan create ...
```
