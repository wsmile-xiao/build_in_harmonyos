# E292: 大型 C++ 数据处理库上游测试在 OHOS 上需要分层迁移和环境补齐

## 基本信息
- **严重度**: 3
- **类别**: testing
- **作者**: goblinrs <goblinrs@yeah.net>
- **来源 PR**: !3033

## 错误特征
```
gtest_captured_stream|PARQUET_TEST_DATA|ARROW_TEST_DATA|discover_tz_dir|Cannot locate timezone|std::ranges::equal|Error loading shared library .*release.*so|duplicate libarrow_gtest|SIGTRAP 133|jobserver mkfifo|posix_fadvise failed|OpenAppendStream|Boost.Context.*x86_64|make_x86_64_sysv_elf_gas|DST|Broken_Hill|std::bad_alloc|OutOfMemory|ResizeOOM|Signal 11|symlink.*Permission denied|hardlink.*Operation not permitted|OpenSSL::SSL|OpenSSL::Crypto
```

## 根因分析
大型 C++ 数据处理库的上游测试同时依赖 CTest/GTest、官方测试数据、timezone 数据、动态库加载路径、C++20 标准库能力、平台文件系统语义和重依赖 FetchContent 源码包; OHOS Conan 真机环境缺少这些 Linux 开发机默认条件, 且当前测试文件系统可能拒绝 symlink/hardlink, 导致无法直接声明完整上游测试通过

## 推荐方案
**方法**: layered-ctest-migration

**说明**: 先按 CTest target inventory 区分可执行 C++ 子集、需额外环境子集和不可执行子集; 对可执行子集补齐 TEST_TMPDIR/TMPDIR、ARROW_TEST_DATA、PARQUET_TEST_DATA、TZDIR、单一动态库目录和 basename NEEDED 等环境; timezone 用例需记录 tzdb 来源和版本, 不应未验证就把系统 zoneinfo 作为默认回退; compute-on 或 Boost.Context 场景需显式设置 CMAKE_SYSTEM_PROCESSOR/BOOST_CONTEXT_ARCHITECTURE; Flight/gRPC 等重依赖探针需先检查 FetchContent 源码包是否含 symlink/hardlink, 必要时使用 no-links 预解包并通过 FETCHCONTENT_SOURCE_DIR_* 注入; 若继续缺少 OpenSSL/BoringSSL 等依赖, 应记录为依赖闭环缺口而不是目标测试失败; 必要时给 GTest/date 等测试或运行时基础设施增加通用环境变量入口; 对可归纳为通用防御语义的平台差异采用 POSIX 兼容修复, 其余差异独立报告说明

**验证/命令**:
```
export TMPDIR=$PWD/tmp ARROW_TEST_DATA=$ROOT/testing/data PARQUET_TEST_DATA=$ROOT/cpp/submodules/parquet-testing/data TZDIR=$HOME/.local/lib/python3.12/site-packages/tzdata/zoneinfo; cmake -DCMAKE_SYSTEM_PROCESSOR=aarch64 -DBOOST_CONTEXT_ARCHITECTURE=arm64 -DBOOST_CONTEXT_ABI=aapcs; ctest -j1 --output-on-failure
```
