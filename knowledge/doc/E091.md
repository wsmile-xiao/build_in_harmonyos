# E091: OHOS linux/socket.h 重定义 sockaddr_storage

## 基本信息
- **严重度**: 2 (medium)
- **类别**: platform_headers
- **触发工具**: clang
- **阶段**: compilation
- **首次发现**: glib 2.88.0 编译 (2026-04-21)

## 错误签名

```
error: redefinition of 'sockaddr_storage'
/path/linux/socket.h:23:8: error: redefinition
/path/sys/socket.h:377:8: note: previous definition is here
```

## 根因分析

OHOS 内核头文件 `linux/socket.h` 定义了 `struct sockaddr_storage`，与 musl libc 的
`sys/socket.h` 中的定义冲突。当代码同时包含 `<sys/socket.h>`（通过系统头文件链）
和 `<linux/netlink.h>`（间接包含 `<linux/socket.h>`）时，产生重定义错误。

这是 OHOS 内核头文件与 musl libc 的不一致——musl 已定义了 sockaddr_storage，
但内核头文件又重复定义了同名结构体。

## 受影响范围

所有包含 `<linux/netlink.h>` 的软件。已知:
- glib (gnetworkmonitornetlink.c)
- systemd
- 其他使用 netlink socket 的网络监控工具

## 解决方案

### 方案 1（推荐）：宏重命名冲突符号

在包含 `<linux/netlink.h>` 的源文件中，用 `__OHOS__` 守卫：

```c
#ifdef HAVE_LINUX_NETLINK_H
#ifdef __OHOS__
#define sockaddr_storage __linux_sockaddr_storage
#endif
#include <linux/netlink.h>
#include <linux/rtnetlink.h>
#ifdef __OHOS__
#undef sockaddr_storage
#endif
#endif
```

修改后需 `track-edit add` 记录。

### 方案 2：禁用 netlink 功能

如果不需要 netlink 网络监控：
```bash
# glib 示例
meson setup builddir --prefix=$DEFAULT_PREFIX -Dnetwork_libnl=disabled
```

## 验证

```bash
# 编译包含 linux/netlink.h 的文件不报错即为通过
echo '#include <sys/socket.h>
#ifdef __OHOS__
#define sockaddr_storage __linux_sockaddr_storage
#endif
#include <linux/netlink.h>
#ifdef __OHOS__
#undef sockaddr_storage
#endif' | clang -xc -c - -o /dev/null
```

## 补充：`_UAPI_LINUX_SOCKET_H` 宏守卫方案

当源码直接包含 `<linux/socket.h>`（而非通过 `<linux/netlink.h>` 间接引入）时，
可以在包含前定义 `_UAPI_LINUX_SOCKET_H` 宏，阻止内核头文件重复定义已由
`sys/socket.h` 提供的结构体：

```c
#include <sys/socket.h>
#ifdef __OHOS__
#define _UAPI_LINUX_SOCKET_H
#endif
#include <linux/socket.h>
```

验证命令：
```bash
echo '#include <sys/socket.h>\n#include <linux/socket.h>' | clang -c -xc -
```

### 受影响软件

- **libusb** — USB 设备访问库，源码中直接包含 `<linux/socket.h>`
- **usbutils** — Linux USB 工具集（lsusb 等），依赖 libusb
