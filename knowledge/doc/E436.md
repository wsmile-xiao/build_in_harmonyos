# E436: Lua module porting: generic-for loop variables are mutable in 5.2 but read-only in 5.4+/5.5

## 基本信息
- **严重度**: 2
- **类别**: portability, lua, language-version
- **作者**: yanjiaxin <yanjiaxin@noreply.gitcode.com>
- **来源 PR**: !6301

## 错误特征
```
attempt to assign to const variable|generic-for control variable|mutable loop value
```

## 根因分析
Lua 5.2 allows mutating a generic-for loop control variable (for l in string.gmatch(...) do l = ... end). Lua 5.4+ makes generic-for control variables read-only, so the same module fails to load on 5.4/5.5 with 'attempt to assign to const variable'. acf-lib format.lua reuses the loop value l as a working variable in update_ini_file/parse_ini_file/set_ini_section, so acf-lib-lua5.5 needs 0001-lua55-mutable-loop-values.patch while acf-lib-lua5.2/0.11.1 runs unmodified.

## 推荐方案
**方法**: assess-lua-version-first

**说明**: Before porting a pure-Lua module collection to a new Lua version, parse-check every module with luac -p of the target interpreter and run the module functions that mutate generic-for loop variables. Apply the mutable-loop-values patch only for Lua 5.4+; Lua 5.2 needs no patch.

**验证/命令**:
```
for f in *.lua; do luac -p $f; done && lua -e 'local m=loadfile("format.lua")(); assert(m.update_ini_file("#c\n[a]\nb=c\n","a","b","v2"))'
```
