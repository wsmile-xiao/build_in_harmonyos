# E245: OHOS libc 未导出 vhangup（声明缺失+符号缺失），但内核 syscall 存在

## 基本信息
- **严重度**: 3
- **类别**: platform, limitation, api
- **作者**: junshi_liu <liujsh2023@lzu.edu.cn>
- **来源 PR**: source_commit:

## 错误特征
```
call to undeclared function 'vhangup'|
                        ld.lld: error: undefined symbol: vhangup|
                        undefined symbol: vhangup
```

## 根因分析
OHOS SDK ohos-sdk_26.0.0.18（clang 15.0.4，aarch64-unknown-linux-ohos）上，
                        vhangup(2) 出现三层问题：
                        1) 声明缺失：sysroot 头文件（unistd.h / sys/vt.h / sys/*.h）均无 vhangup 声明，
                           编译产生 implicit-function-declaration 警告；
                        2) libc 符号缺失：libc.so（nm -D 核验）未导出 vhangup 符号，链接报
                           ld.lld: error: undefined symbol: vhangup；
                        3) 内核 syscall 仍存在：aarch64 bits/syscall.h 定义 __NR_vhangup=58 / SYS_vhangup=58，
                           即内核能力存在但 libc 未封装，可通过 syscall(SYS_vhangup) 直调。
                        agetty.c 在 F_HANGUP 路径（--hangup 选项）调用 vhangup()，触发上述问题。

## 推荐方案
**方法**: ohos-syscall-shim

**说明**: 仅 OHOS 条件下使用 AArch64 SYS_vhangup syscall 封装（shim），不伪造 libc API：
                          int vhangup(void) { return (int)syscall(SYS_vhangup); }
                        实现位于 archives/a/agetty/2.42.2/src/ohos-utmpx-shim.c（连同 utmpx no-op 降级一起，
                        utmpx 部分归 E121 已覆盖，非本条目新贡献）。非 OHOS 平台不启用 shim，保持上游语义。

**验证/命令**:
```
# 诊断流程：
                        # 1) 最小复现：编译调用 vhangup() 的最小 C 程序，观察声明警告与链接失败；
                        # 2) 核验 syscall 编号：grep SYS_vhangup $SYSROOT/.../bits/syscall.h
                        # 3) 核验 libc 导出：nm -D $SYSROOT/.../libc.so | grep vhangup
                        # 4) 仅当"无声明 + 无导出 + 内核 syscall 存在"时，才在 OHOS 条件启用 syscall shim。
```
