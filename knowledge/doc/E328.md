# E328: monorepo 包的 PR 说明应把包内 smoke-test 与 repo 级测试簇分开列出

## 基本信息
- **严重度**: 2
- **类别**: testing, evidence-boundary, review
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !7151

## 错误特征
```
underreported.*upstream.*tests|test-related files.*23|PR.*smoke-test|review.*scope
```

## 根因分析
单包 Conan 适配只拥有自己的可执行入口，但上游 monorepo 还包含控制面、
                        前端和基础设施测试簇。若 PR 只写“执行了一个 smoke-test”，审查会把
                        其余测试簇视为少报；若把仓库级脚本硬并入包内通过率，又会误导后续
                        维护者。

## 推荐方案
**方法**: separated-test-clusters

**说明**: PR 正文里保留完整上游分母，再单列包内实际执行的 smoke-test 与新增的
                        test_package；对 control-plane/tests、tests、web/dashboard/tests、
                        infrastructure scripts 逐条说明依赖边界，避免把 monorepo 其他测试误算成
                        当前 Conan 包通过率。

**验证/命令**:
```
在 notes.md 和 PR body 中分别列出 23 个上游 test-related 文件、1 个包内
                        smoke-test、1 个 test_package，并对未运行项写明 FastAPI / DB / Qt /
                        Node / infra 边界。
```
