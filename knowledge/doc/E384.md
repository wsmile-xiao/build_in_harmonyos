# E384: configure-documented-env-override

## 基本信息
- **严重度**: 2
- **类别**: build-system, configure, dependency, pkg-config, security
- **作者**: 2401_87095818 <zhaowenxiang06@outlook.com>
- **来源 PR**: !5581

## 错误特征
```
Library option -lcrypto cannot be used|
                    OpenSSL Crypto development libraries are not installed properly in required location|
                    Library option -lssl cannot be used|
                    OpenSSL development libraries are not installed properly in required location
```

## 根因分析
自写（非 autoconf 生成）的 configure 脚本用
                    `${CC} ${OSCFLAGS} ${OSLIBS} -lcrypto` 这类裸命令探测第三方库，
                    只拼接脚本内部的 OSCFLAGS/OSLIBS，**不读** conan 的
                    LDFLAGS/CPPFLAGS 环境变量；同时它用 pkg-config 按上游模块名
                    （libcrypto/libssl）查询，而 conan 的 PkgConfigDeps 只按配方
                    pkg_config_name（或包名，如 openssl.pc）生成 .pc，两路探测
                    在 conan 缓存环境下都失败 → configure 中止。

## 推荐方案
**方法**: configure-documented-env-override

**说明**: 使用 configure 脚本自身文档化的覆盖变量（coturn 为
                    SSL_CFLAGS/SSL_LIBS；libp11 用 OPENSSL_CFLAGS/OPENSSL_LIBS），
                    在 conanfile build() 的 Environment 中指向依赖包路径，configure
                    命中 "Private SSL Library option" 分支直接采用并写入生成的 Makefile，
                    无需改依赖配方，也不用补转发型 .pc。

**验证/命令**:
```
|
  openssl = self.dependencies["openssl"].package_folder
  build_env.define("SSL_CFLAGS", f"-I{os.path.join(openssl, 'include')}")
  build_env.define("SSL_LIBS", f"-L{os.path.join(openssl, 'lib')} -lcrypto -lssl")
```
