# E480: X11 客户端库的头文件级依赖在同轨可用时直接用 transitive_headers 消费，不必写桩 .pc 或 vendor 头

## 基本信息
- **严重度**: 3
- **类别**: ohos, autotools, conan, pkg-config, transitive-headers
- **作者**: zhangbowl-JW <406099677@qq.com>
- **来源 PR**: !6703

## 错误特征
```
Package '.*', required by 'virtual:world', not found|Xfixes.h: No such file or directory|header dependency.*transitive_headers
```

## 根因分析
X11 扩展客户端库的依赖可二分：链接依赖（NEEDED 含对应 .so）与
                        头文件级依赖（仅编译期 include 消费类型/宏）。Xcomposite.h 第 49 行
                        include <X11/extensions/Xfixes.h>，但 libXcomposite.so.1 只链接
                        -lX11，NEEDED 无 libXfixes.so。configure 的 PKG_CHECK_MODULES(XFIXES, xfixes)
                        只为拿 -I 头文件路径。当 libxfixes/6.1.0 已在 cmd-pkgs 同轨发布
                        （pkg_config_name=xfixes、含 xfixes.pc）且与 libx11/6.4.0 兼容时，
                        仅需 requires("libxfixes/6.1.0", transitive_headers=True)，由 Conan
                        透传 include 目录，无需求桩或 vendor。跨轨（libxfixes/6.0.2 pin 在
                        Track A/libx11/1.8.13）时才会同图双 libx11 版本冲突，才需 E338 方案。

## 推荐方案
**方法**: same-track-transitive-headers

**说明**: 头文件级依赖在同轨可用时，requirements 写 transitive_headers=True，
                        generate() 设 {DEP}_CFLAGS 供 configure 找头、{DEP}_LIBS="" 不加链接 flag；
                        package_info.requires 只列链接级依赖；不写桩 .pc、不 vendor 头、不打 patch。

**验证/命令**:
```
CI_PACKAGES="archives/l/libxcomposite/0.4.6" zsh ci/conan/build_and_test.sh
```
