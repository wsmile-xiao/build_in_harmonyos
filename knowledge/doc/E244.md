# E244: Capture handle operation errors before closing resources

## 基本信息
- **严重度**: 2
- **类别**: runtime, testing, api
- **作者**: 1catmint1
- **来源 PR**: source_commit:

## 错误特征
```
operation returned failure but reported error is zero|last operation error lost after close|error reporting dereferences a closed handle
```

## 根因分析
Some C libraries report open and close failures through an out-parameter but store errors from operations on an already-open resource inside the live handle. Reusing the open out-parameter for operation failures reports a stale success value. Closing first can overwrite the out-parameter and free the handle, making later error access invalid.

## 推荐方案
**方法**: operation-fault-injection-with-pre-close-error-snapshot

**说明**: Give open, operation, and close errors separate variables. After an operation returns failure, read or snapshot the documented handle error before closing. Use deterministic fault fixtures in separate consumer processes and verify that the open error remains success while the operation error is nonzero.

