# E257: header-only 无 CMake 库配方的 conan-verify G1 要求显式 build()（no-op 即可）

## 基本信息
- **严重度**: 2
- **类别**: headers, conan, completeness, recipe
- **作者**: junshi_liu <liujsh2023@lzu.edu.cn>
- **来源 PR**: !7243

## 错误特征
```
G1: FAIL|conanfile.py 缺少: build() 方法|G1 失败，请先生成完整配方
```

## 根因分析
>
  conan-verify 的 G1 配方完整性门禁把 build() 方法列为 conanfile.py 必填项，
  是结构检查而非编译检查。header-only 无 CMake/meson/autotools 构建系统的
  C++ 库按直觉省略 build()，导致 G1 FAIL 并阻止后续 G0-G5/L2/L4/L5 继续。
  只需提供 no-op build() 即满足结构完整性，与 E241/E255/E281 的数据/资源型包
  （settings=None、无 C++ 编译）不同：header-only C++ 库保留 settings 与
  package_type='header-library'，仅在配方中补显式 build()。

## 推荐方案
**方法**: no-op-build-for-header-only

**说明**: >
  header-only 无构建系统库在 conanfile.py 提供 no-op build()（pass），
  package() 用 conan.tools.files.copy 复制头文件；保留 settings 与
  package_type='header-library'。有 CMake 项目的库照常写真实 build()。

**验证/命令**:
```
>
  def build(self): pass  # no-op for header-only / no build system
```
