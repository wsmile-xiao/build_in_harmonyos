# E448: Close the GNUstep Make environment for GNUstep libraries on OHOS

## 基本信息
- **严重度**: 3
- **类别**: ohos, autotools, environment, gnustep, tool-requires
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !6806

## 错误特征
```
GNUSTEP_MAKEFILES.*not found|GNUSTEP_SYSTEM_ROOT|GNUSTEP_CONFIG_FILE|/bin/sh.*not found|Permission denied|GNUstep Makefiles
```

## 根因分析
GNUstep libraries are not plain Autotools packages. The
                        configure script and GNUmakefile both need a coherent
                        GNUstep Make domain before they can detect, build, and
                        install libraries. On OHOS, scripts may also need an
                        executable shell path that exists on the worker, and the
                        produced libraries must be staged in the GNUstep SYSTEM
                        layout rather than a conventional prefix-only libdir.

## 推荐方案
**方法**: conan-gnustep-make-domain-closure

**说明**: Resolve the gnustep-make package folder from the Conan
                        build dependency, prepend its bin directory to PATH, set
                        GNUSTEP_MAKEFILES to share/GNUstep/Makefiles, bind
                        GNUSTEP_SYSTEM_ROOT and GNUSTEP_CONFIG_FILE to the
                        current package folder, pass
                        GNUSTEP_INSTALLATION_DOMAIN=SYSTEM during configure and
                        make, and expose dependency library directories through
                        the build and run environments. Prepare configure and
                        GNUstep Make scripts with an OHOS-available shell before
                        invoking them.

**验证/命令**:
```
with gnustep_environment.vars(self).apply(): configure; make -j1 GNUSTEP_INSTALLATION_DOMAIN=SYSTEM GNUSTEP_SYSTEM_ROOT=<package_folder>
```
