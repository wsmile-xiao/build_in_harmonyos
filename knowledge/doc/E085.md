# E085 — musl pthread_cancel 缺失导致线程检测失败

## 错误特征

编译或链接时报错：
```
posix-lock.c: undefined reference to 'pthread_cancel'
```

或 configure 阶段线程检测失败，运行时报错：
```
gpgrt: pthread detection failed, falling back to no-threading
```

## 触发条件

- 构建系统: autotools
- 阶段: compilation / linking
- 平台: OpenHarmony（musl libc）

## 根因分析

musl libc 不实现 `pthread_cancel()`。部分 GNU 软件（如 libgpg-error 的 gpgrt）使用 `#pragma weak pthread_cancel` 做 weak symbol 检测来判断 pthread 是否可用。在 musl 上：

1. `pthread_cancel` 不存在于 libc 中
2. `#pragma weak` 机制在某些链接配置下不能正确降级
3. 导致检测逻辑误判为"无 pthread 支持"，或直接链接失败

## 解决方案

### 推荐方案：定义 PTHREAD_IN_USE_DETECTION_HARD

```bash
# 在 configure 之后、make 之前
echo '#define PTHREAD_IN_USE_DETECTION_HARD 1' >> config.h
make -j$(nproc)
```

这会将检测方式从 weak symbol 切换到 `pthread_create` 运行时检测，musl 完整支持。

### 禁止做法

- ❌ 静态链接 `-lpthread -static`（musl 上会引入不兼容符号）

## 验证

```bash
# 验证宏已定义
grep PTHREAD_IN_USE_DETECTION_HARD config.h

# 验证库功能
gpg-error --version
```
