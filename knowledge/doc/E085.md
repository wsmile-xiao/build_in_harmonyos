## 错误特征
```
undefined reference to pthread_cancel|
                         undefined symbol: pthread_cancel|
                         undefined symbol: pthread_testcancel|
                         pthread_cancel.*weak|
                         PTHREAD_IN_USE_DETECTION|
                         posix-lock\.c.*pthread_cancel|
                         lock.*pthread.*fail
```

## 根因分析
musl libc（OpenHarmony 使用）不实现 POSIX 线程取消 API，
                         包括 pthread_cancel()、pthread_testcancel()、
                         pthread_setcancelstate()、pthread_setcanceltype()。
                         部分 GNU 软件（如 libgpg-error）使用
                         `#pragma weak pthread_cancel` 来运行时检测
                         pthread 是否可用。但在 musl 上，链接器
                         找不到 pthread_cancel 的 weak symbol，
                         导致检测逻辑失败或链接错误。
                         另一类场景是软件直接调用 pthread_cancel 等函数，
                         链接阶段出现 ld.lld: undefined symbol 错误。

## 推荐方案
**方法**: define-pthread-detection-hard

**说明**: 在 config.h 中定义 PTHREAD_IN_USE_DETECTION_HARD=1，
                         将线程检测从 weak symbol 方式切换到 pthread_create 运行时检测

**验证/命令**:
```
echo '#define PTHREAD_IN_USE_DETECTION_HARD 1' >> config.h
```
