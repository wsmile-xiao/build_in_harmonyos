# E345: Validate a packaged loadable module through an ABI-matched private host

## 基本信息
- **严重度**: 2
- **类别**: conan, packaging, dynamic-module, runtime-validation
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !5121

## 错误特征
```
module(load|path).*(not found|failed)|dlopen.*(failed|undefined symbol)|cannot open shared object file|test.*passed.*without package artifacts
```

## 根因分析
A loadable module may expose no standalone headers, executable, or stable entry point that a conventional consumer test can call. Checking only that the shared object exists does not prove that the package contains a compatible loader, resolves runtime dependencies, registers the module, or accepts its configuration. Upstream integration tests may also need same-source backends that are outside the package contract, while a merely writable HarmonyOS path may reject FIFOs required by a daemon harness.

## 推荐方案
**方法**: abi-matched-private-host-validation

**说明**: Build the module and the smallest supported host in one build graph; retain the host and required configuration data as private package artifacts; generate a minimal runtime configuration from resolved package paths; execute the host's validation-only mode; and pair the positive check with a destructive missing-artifact check. Run applicable upstream coverage separately: build its smallest same-source fixtures only for the test phase, select isolated temporary storage by probing every required operation such as file I/O and FIFO creation, execute and count real target entries, and remove fixture artifacts before packaging. Keep the private host out of public bindirs.

**验证/命令**:
```
|
  # Generic pattern:
  <package-private-host> <validation-only-options> <generated-minimal-config>
  # OpenLDAP rwm example:
  <package>/libexec/slapd -Tt -f <build>/slapd-rwm.conf
  mkfifo <isolated-test-root>/.fifo-probe
  tests/run -b ldif <selected-rwm-test>
```
