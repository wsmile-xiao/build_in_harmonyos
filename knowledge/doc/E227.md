# E227: Distinguish unified patch context prefixes from source trailing whitespace

## 基本信息
- **严重度**: 2
- **类别**: patch
- **作者**: 2301_80739235 <2047361658@qq.com>
- **来源 PR**: source_commit:

## 错误特征
```
trailing whitespace\.|new blank line at EOF\.|raw patch line == ' '
```

## 根因分析
A canonical unified diff prefixes every unchanged context line with one space; when the unchanged source line is empty, the patch file therefore contains a raw single-space line that an outer repository git diff --check can classify as blank-at-eol even though the patched source has no trailing whitespace.

## 推荐方案
**方法**: split-source-and-patch-whitespace-validation

**说明**: Run git diff --check on non-patch changes and validate patch files with both Git and GNU patch parsers at zero fuzz.

**验证/命令**:
```
git diff <base>...HEAD --check -- . ':(exclude,glob)**/*.patch'; git apply --check <patches>; patch --dry-run --fuzz=0 -p1 -d <source> -i <patch>
```

## 关键词
