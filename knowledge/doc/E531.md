# E531: OHOS musl libc 缺少 glibc 风格 qsort_r — 以本地 shim 委托 qsort 修复

## 基本信息
- **严重度**: 2
- **类别**: compat, portability, libc, musl, autotools
- **作者**: junshi_liu <liujsh2023@lzu.edu.cn>
- **来源 PR**: !6804

## 错误特征
```
undefined reference.*qsort_r|qsort_r.*not found|ld.lld.*undefined.*qsort_r
```

## 根因分析
authselect 的 src/lib/util/dir.c 使用 glibc 风格 qsort_r (GNU 签名 qsort_r(void*,size_t,size_t,int(*)(const void*,const void*,void*),void*), compar 回调接收用户上下文 arg)；OHOS 使用 musl libc，不导出 GNU 签名 qsort_r (musl 导出的 BSD 签名参数顺序不同, thunk 在 compar 前且未作为公共符号导出)；链接时 --no-allow-shlib-undefined 检测到未定义符号 qsort_r 而失败。

## 推荐方案
**方法**: local-glibc-compat-shim

**说明**: 在受影响源文件中以 #ifndef __GLIBC__ 条件编译添加本地 GNU 签名 qsort_r shim，通过静态全局变量保存比较器与上下文，委托标准 qsort 实现；调用方无需修改代码；仅安全用于单线程 CLI 场景。

**验证/命令**:
```
见 patches/0001-qsort-r-compat.patch
```
