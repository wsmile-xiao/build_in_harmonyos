# E396: Bind Conan graph identity to install package materialization

## 基本信息
- **严重度**: 2
- **类别**: conan, evidence, package-identity, schema
- **作者**: 2301_80739235 <2047361658@qq.com>
- **来源 PR**: !5812

## 错误特征
```
package_folder.*null|package_folder.*missing|graph info.*package_folder
```

## 根因分析
Conan graph info resolves and serializes package identity but does not materialize a package for consumption, so a node may have complete RREV, PID, PREV, binary state, and remote attribution while package_folder is null. The successful install result for the same exact identity is the authoritative producer of the materialized package folder. Package inventory path fields are a separate schema and cannot substitute for package_folder.

## 推荐方案
**方法**: cross-bind-graph-identity-and-install-folder

**说明**: Use graph JSON for dependency topology, options, invalid/missing state, binary state, and remote attribution. Use install JSON for the materialized package_folder only after the exact node identity matches across both documents. Bind raw files, command RCs, isolated-home identity, and the derived result with SHA-256.

**验证/命令**:
```
conan graph info <recipe> --build=never --format=json && conan install <recipe> --build=never --format=json
```
