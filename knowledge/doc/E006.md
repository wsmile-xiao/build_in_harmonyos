# E006: OpenSSL BAD_SIGNATURE

> **结构化数据**: [graph/E006.kv](../graph/E006.kv) | **原则**: 无（本条目自身约束）
> **严重度**: 🔴 blocking | **分类**: ssl/asm | **自动修复**: ❌ 需重编 OpenSSL

---

## 错误特征

```
ssl.SSLError: [SSL: BAD_SIGNATURE] bad signature
RSA_verify_PKCS1_PSS_mgf1:last octet invalid
tls_process_cert_verify:bad signature
```

**触发场景**：pip install、wget https、curl https 等所有 TLS 连接。

## 根因

OpenSSL 的 ARM64 汇编优化代码在 RSA-PSS 签名验证时存在 bug。这不是配置问题，而是汇编指令层面的缺陷。

**问题链**：

```
OpenSSL 启用 ARM64 汇编优化 (BN_ASM_MONT, SHA1_ASM)
    ↓
RSA-PSS 签名验证使用汇编路径
    ↓
aarch64 上该汇编实现有 last octet invalid bug
    ↓
所有 TLS 证书验证失败 → BAD_SIGNATURE
```

## 验证命令

```bash
# 测试 OpenSSL 连接（应看到错误）
openssl s_client -connect pypi.org:443 </dev/null
# 输出: RSA_verify_PKCS1_PSS_mgf1:last octet invalid

# 检查编译配置（确认启用了 ASM）
openssl version -f
# 输出: OPENSSL_BN_ASM_MONT SHA1_ASM ... (表示有问题)
```

## 解决方案

使用 `no-asm` 重新编译 OpenSSL，禁用所有汇编优化：

```bash
./Configure --prefix=$HOME/usr/local --openssldir=$HOME/usr/local/ssl no-asm
make clean && make && make install
```

**性能影响**：纯 C 实现比汇编慢约 10-20%，但稳定性大幅提升。

**⚠️ 禁止事项**：不要在鸿蒙 aarch64 上启用 OpenSSL 汇编优化。

## 涉及软件

OpenSSL（所有版本）、Python（通过 ssl 模块间接依赖）、pip、wget、curl。
