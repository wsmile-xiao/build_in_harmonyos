# E387: LLVM 15.0.4 lit 测试框架在 OHOS 的适配入口与最小子集实测方法

## 基本信息
- **严重度**: 2
- **类别**: ohos, toolchain, llvm, cross-compile, lit
- **作者**: junshi_liu <liujsh2023@lzu.edu.cn>
- **来源 PR**: !5637

## 错误特征
```
llvm_lit_ohos_adaptation|lit_site_config_missing|lit_psutil_missing
```

## 根因分析
上游 llvm/test/lit.cfg.py 依赖 CMake 生成的 lit.site.cfg.py 提供大量 config 属性
  （llvm_tools_dir/llvm_obj_root/host_triple/targets_to_build/have_libxml2 等）；在 Conan 包/临时
  worktree 环境无 CMake 生成物时加载即 AttributeError；psutil 缺失使 lit --timeout 不可用（仅警告）

## 推荐方案
**方法**: 1) 自包含替换式 lit.cfg.py：复制上游 llvm/test/lit.cfg.py 并在顶部注入全部 site 属性
  （llvm_src_root/llvm_obj_root/llvm_tools_dir/llvm_lib_dir/llvm_shlib_dir/host_triple/target_triple/
  targets_to_build=字符串/llvm_use_sanitizer/build_mode/enable_llvm_dylib/llvm_dylib_version/host_arch/
  host_os/host_cc/host_ldflags/llvm_enable_assertions/inliner_model/raevict_model/lit_tools_dir/
  use_lit_shell/use_default_substitutions/python_executable/go/gold/ld/ld64/ptxas/ocamlfind/ocaml_flags/
  osx_sysroot/build_examples/build_shared_libs/enable_threads/expensive_checks/has_plugins/have_curl/
  have_libxar/have_libxml/have_libxml2/have_llvm_driver/have_ocamlopt/have_opt_viewer_modules/have_tf_aot/
  have_tf_api/libcxx_used/link_llvm_dylib/linked_bye_extension/llvm_locstats_used）+ import lit.llvm +
  lit.llvm.initialize(lit_config, config)；2) 入口脚本 run_lit_subsel.sh 生成 llvm-lit-wrapper.py
  （config_map 把源码 llvm/test 映射到 lit.site.cfg.py）；3) 最小 smoke 用例 test_lit/add.ll
  （RUN: llc -mtriple=aarch64-unknown-linux-ohos | FileCheck %s）；4) 子集选择：按文件名排序取
  CodeGen/AArch64 前 50 + InstSimplify 前 15，禁止跑全量（约 7.3 万文件不现实）

**说明**: |
  LLVM 15.0.4 在 OHOS 上运行 lit 最小子集需自包含替换式配置（上游 lit.cfg.py + 注入全部 site 属性 +
  lit.llvm.initialize），否则加载即报 AttributeError（use_lit_shell/host_triple/ld64_executable/
  have_libxml2 等逐个缺失）。实测：AArch64 子集 49 用例 46 Passed + 3 Unsupported（缺 cortex-a53 fix /
  O0-O3 pipeline feature 非失败）+ InstSimplify 15 用例全 Passed（61/64，1.19s+0.61s，exit 0）。
  lit 框架自测 4/4 通过。psutil 缺失仅使 --timeout 不可用（警告非错误）。包内 bin 工具
  （llc/FileCheck/count/not/clang-15 等）需签名（.codesign 段）方可执行。
  与 DRAFT-intel-oneapi-dpcpp-ohos-sycl-lit（SYCL 层）范围不同，证据独立不重叠。

**验证/命令**:
```
python3 <SRC>/llvm/utils/lit/lit.py --no-progress-bar <SUITE>/CodeGen/AArch64
```
