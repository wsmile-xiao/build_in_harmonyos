# E521: libtoolize hardcoded SED path breaks aux-dir resolution (ltmain.sh placed in parent dir)

## 基本信息
- **严重度**: 2
- **类别**: build-system, autotools
- **作者**: mkz--mkz <ak74A3WKxU__vozN.mkz--mkz@noreply.gitcode.com>
- **来源 PR**: !5330

## 错误特征
```
required file \x27\./ltmain\.sh\x27 not found|libtoolize: putting auxiliary files in \x27\.\./\.\.\x27|usr/local/bin/sed: No such file
```

## 根因分析
Installed libtoolize/automake hardcode /storage/Users/currentUser/usr/local/bin/sed which does not exist on the minimal OHOS image.  When SED is unset, libtoolize's extract-trace / aux-dir heuristic fails and it walks UP the tree, placing auxiliary files (ltmain.sh) into a parent directory; automake then aborts with "required file ./ltmain.sh not found".

## 推荐方案
**方法**: export-env-tools

**说明**: Set SED/AUTOCONF/AUTOHEADER/AUTOM4TE to the real tool paths (command -v) before autoreconf -fi so libtoolize resolves the aux dir to "." and copies ltmain.sh into the source root.  conanfile.py implements this in _prepare_autotools_env().

**验证/命令**:
```
export SED=$(command -v sed) AUTOCONF=$(command -v autoconf) AUTOHEADER=$(command -v autoheader) AUTOM4TE=$(command -v autom4te); autoreconf -fi
```
