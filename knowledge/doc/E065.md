# E065: gnulib 头文件包含顺序导致符号未声明

> **结构化数据**: [graph/E065.kv](../graph/E065.kv) | **原则**: 无
> **严重度**: 🟡 medium | **分类**: gnulib/headers/compilation | **自动修复**: ✅ set-env-var

---

## 错误特征

```
sed/compile.c:988:7: error: use of undeclared identifier 'xzalloc'
sed/compile.c:1299:62: unexpected type name 'size_t': expected expression
sed/compile.c:1321:67: expected expression
```

## 根因

gnulib 提供的头文件之间有依赖顺序要求：
- `xzalloc()` 定义在 `lib/xalloc.h`
- `size_t` 需要 `<stddef.h>` 或 `<sys/types.h>`
- 如果 `.c` 文件的 `#include` 顺序不符合预期，或 gnulib 替换头文件未正确覆盖系统头文件 → 符号未声明

这通常是 **E064（conftest 失败）** 的二级后果：gnulib 的 `config.h` 包含了错误的 `#define` 配置。

## 解决方案

```bash
# 方案 1：确保 CPPFLAGS 包含必要路径
export CPPFLAGS="-I$BUILD_SRC_DIR/lib -I$BUILD_SRC_DIR"

# 方案 2：在受影响的 .c 文件显式包含所需头文件
// compile.c 顶部添加:
#include <stddef.h>
#include "xalloc.h"

# 方案 3：清理后重新 configure（解决 E064 后顺带解决）
make distclean && ./configure --prefix=$PREFIX
```

## 诊断流程

```
遇到 "undeclared identifier" 错误
    │
    ├─ 符号来自系统头文件(size_t, FILE*, etc) → 缺少 #include → 补上
    ├─ 符号来自 gnulib 替代模块(xzalloc, xmemdup, etc) → gnulib 头文件顺序问题 → 检查 CPPFLAGS
    └─ 符号来自项目自身 → 正常编译错误 → 修复源码
```

## 涉及软件

sed 4.9、以及其他深度依赖 gnulib 的 GNU 软件。
