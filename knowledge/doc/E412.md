# E412: Make optional acceleration backends explicit in self-contained static packages

## 基本信息
- **严重度**: 2
- **类别**: configure, linking, dependencies, reproducibility
- **作者**: goblinrs <goblinrs@yeah.net>
- **来源 PR**: !5938

## 错误特征
```
OpenSSL library not found|cannot find -lcrypto|undefined reference to (EVP_|MD5_|SHA)|optional OpenSSL backend auto-detected
```

## 根因分析
Configure scripts can auto-detect an optional acceleration library from the build worker even when it is absent from the Conan dependency graph. The resulting static package then varies by worker or exposes undeclared link requirements. Disabling the backend is valid only when upstream provides complete internal implementations and the backend changes performance rather than functionality.

## 推荐方案
**方法**: explicit-optional-backend-policy

**说明**: Decide the optional backend policy in the recipe instead of accepting host autodetection. For a dependency-free static package whose upstream internal implementation retains every public feature, disable an acceleration-only backend and document the boundary. If the backend supplies required functionality, declare it as a Conan requirement and enable it explicitly.

**验证/命令**:
```
./configure --disable-openssl --enable-static --disable-lib-shared && make -j1 test test-lib
```
