# E418: Mandatory PowerShell empty-string parameters can bypass the intended mock oracle

## 基本信息
- **严重度**: 2
- **类别**: testing, mock-oracle, powershell
- **作者**: 2301_80739235 <2047361658@qq.com>
- **来源 PR**: !6320

## 错误特征
```
Cannot bind argument.*empty string|OWNERSHIP_CLOSED=PASS rc=42|unrelated exception
```

## 根因分析
A PowerShell helper with a mandatory string parameter rejects an explicitly empty value during parameter binding unless it declares AllowEmptyString. When an empty value is the valid positive state, the helper can fail before the production branch runs. If a catch block accepts any exception as the expected negative, an ownership-drift mock can therefore report PASS without exercising the injected native failure or the real downstream diagnostic.

## 推荐方案
**方法**: explicit-empty-state-and-exact-error-oracle

**说明**: Keep required identity and diagnostic parameters mandatory. Add AllowEmptyString only to parameters for which empty is a documented valid state. Create zero-byte fixtures with File.WriteAllText or an equivalent byte-preserving API, then require the exact downstream error in both the PowerShell harness and the independent consumer.

**验证/命令**:
```
File.WriteAllText($path, [string]::Empty); require "phase returned nonzero: OWNERSHIP_CLOSED=PASS rc=42"
```
