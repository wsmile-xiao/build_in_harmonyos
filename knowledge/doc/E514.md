# E514: libtoolize aux-dir heuristic picks .. / ../.. because of a stray install.sh in a parent dir (ltmain.sh lands in the wrong directory)

## 基本信息
- **严重度**: 2
- **类别**: build-system, autotools, libtoolize
- **作者**: mkz--mkz <ak74A3WKxU__vozN.mkz--mkz@noreply.gitcode.com>
- **来源 PR**: !5329

## 错误特征
```
libtoolize: putting auxiliary files in '\.\.'\|\.\./\.\.|required file '\./ltmain\.sh' not found|automake failed with exit status 1
```

## 根因分析
libtoolize's aux-dir heuristic scans '.', '..', '../..' for install-sh/install.sh; on the OHOS build host $HOME/tmp/install.sh exists (from a previous package install), so libtoolize chooses '../..' (= $HOME/tmp) as the aux dir and copies ltmain.sh there. automake then fails with 'required file ./ltmain.sh not found'.

## 推荐方案
**方法**: ensure-install-sh-in-source-root

**说明**: Ensure install-sh (or install.sh) exists in the source root before running autoreconf so libtoolize picks '.' as the aux dir; the conan recipe writes a placeholder install-sh in build() before autoreconf -fi.

**验证/命令**:
```
test -f install-sh || printf '#!/bin/sh\n' > install-sh; autoreconf -fi
```
