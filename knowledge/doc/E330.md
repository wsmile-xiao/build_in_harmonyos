# E330: Disable CMake versioned shared-library symlinks on OHOS paths

## 基本信息
- **严重度**: 2
- **类别**: ohos, cmake, linking, filesystem, shared-library
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !4598

## 错误特征
```
failed to create symbolic link .*\.so\.[0-9]+|cmake_symlink_library: System Error: Permission denied|DT_NEEDED.*\.conan2
```

## 根因分析
CMake's Unix shared-library rules can create versioned .so names and symlinks. OHOS/HMDFS-backed build paths can reject symlink creation even when the compiled shared object is valid. Disabling SONAME entirely avoids symlink creation but can make downstream DT_NEEDED entries record an absolute Conan cache path.

## 推荐方案
**方法**: no-versioned-soname-keep-soname-flag

**说明**: Set CMAKE_PLATFORM_NO_VERSIONED_SONAME=ON while keeping CMAKE_SHARED_LIBRARY_SONAME_C_FLAG=-Wl,-soname, so CMake emits an unversioned real .so with a relocatable ELF SONAME and does not create versioned symlinks.

**验证/命令**:
```
-DCMAKE_PLATFORM_NO_VERSIONED_SONAME=ON -DCMAKE_SHARED_LIBRARY_SONAME_C_FLAG=-Wl,-soname,
```
