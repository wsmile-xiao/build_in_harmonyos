# E446: Keep filesystem tests active while exempting unsupported OHOS link-creation paths

## 基本信息
- **严重度**: 2
- **类别**: hmdfs, portability, testing, filesystem
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !6611

## 错误特征
```
Assertion failed: !zix_create_symlink|ZIX_STATUS_BAD_PERMS|hard.?link.*BAD_PERMS|symlink.*NOT_SUPPORTED
```

## 根因分析
Some OHOS/HMDFS-backed test directories reject hardlink or symlink creation even though ordinary file, directory, and path canonicalization operations work. Upstream filesystem tests may assert POSIX link creation success and abort before the remaining coverage runs.

## 推荐方案
**方法**: capability-scoped-filesystem-test-exemption

**说明**: Patch only the link-creation assertion. Accept documented platform statuses such as BAD_PERMS or NOT_SUPPORTED, and skip only the symlink-specific branch when creating the symlink is denied. Keep the rest of the filesystem test program enabled.

**验证/命令**:
```
assert(!st || st == ZIX_STATUS_NOT_SUPPORTED || st == ZIX_STATUS_BAD_PERMS)
```
