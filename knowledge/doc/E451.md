# E451: 消费 clang/LLVM 包时用 CMakeDeps 导致自带 ClangConfig 被遮蔽，clang 组件目标找不到

## 基本信息
- **严重度**: 2
- **类别**: build-system, cmake, conan
- **作者**: hazel_xyx <1707119571@qq.com>
- **来源 PR**: !6633

## 错误特征
```
Target "ccls" links to target "clangIndex" but the target was not found|No rule to make target.*clangIndex|clangIndex.*not found|find_package\(Clang\).*target.*not found|CLANG_LINK_CLANG_DYLIB.*not defined
```

## 根因分析
CMake 工程（如 ccls）需要 find_package(Clang REQUIRED) 解析到 clang 包自带的
                        LLVM ClangConfig.cmake（定义 clangIndex/clangFormat/clangTooling 等组件目标，
                        并设置 CLANG_LINK_CLANG_DYLIB=ON -> 链接 clang-cpp、LLVM_LINK_LLVM_DYLIB=ON ->
                        链接 LLVM 聚合库）。但 conanfile 若同时生成 CMakeDeps，CMakeToolchain 生成的
                        toolchain 会把 CMakeDeps 输出目录 PREPEND 到 CMAKE_PREFIX_PATH，CMakeDeps 生成的
                        ClangConfig.cmake（只定义 clang::clang 聚合目标、无组件目标、无 *_DYLIB 变量）
                        会遮蔽包内自带的 LLVM ClangConfig.cmake，导致链接 clangIndex/... 报 target 不存在。
                        clang 包自身是 cmake_find_mode=config（包内含 lib/cmake/clang + lib/cmake/llvm）。
                        另注意 rapidjson 包自带 config 只设 RapidJSON_INCLUDE_DIR（无 S），下游 CMakeLists
                        若读 RapidJSON_INCLUDE_DIRS 变量会拿到空值导致 rapidjson 头找不到。

## 推荐方案
**方法**: cmake-only-cmake-toolchain     # 只用 CMakeToolchain，不用 CMakeDeps

**说明**: conanfile generate() 只生成 CMakeToolchain，显式把依赖包目录写入
                        CMAKE_PREFIX_PATH，find_package(Clang)/find_package(RapidJSON) 即命中
                        包内自带的 LLVM/RapidJSON config；CMakeLists 需要的 *_INCLUDE_DIRS 变量显式补齐

**验证/命令**:
```
tc = CMakeToolchain(self); tc.variables["CMAKE_PREFIX_PATH"] = ";".join(
                        [self.dependencies["clang"].package_folder,
                         self.dependencies["rapidjson"].package_folder]);
                        tc.variables["RapidJSON_INCLUDE_DIRS"] =
                        os.path.join(rapidjson_pkg, "include"); tc.generate()
```
