# E408: Register optional AppConfig variables before guarding their values

## 基本信息
- **严重度**: 2
- **类别**: configure, perl, runtime, consumer-test
- **作者**: 2301_80739235 <2047361658@qq.com>
- **来源 PR**: !6075

## 错误特征
```
.*no such variable|AppConfig.*undefined|lc.*uninitialized
```

## 根因分析
AppConfig validates accessor names against variables registered before parsing. Calling an unregistered optional accessor emits a no-such-variable diagnostic before a caller-side defined-value guard can run. Registration and value normalization are separate contracts: define the optional variable first, then guard an omitted or undefined value before string operations such as lc.

## 推荐方案
**方法**: register-then-normalize-optional-appconfig-value

**说明**: Add the optional variable to the AppConfig definition with the intended inherited or empty default before read or parse. Keep a separate defined-value guard before lowercase, comparison, interpolation, or other string operations. Verify omitted and explicit-value paths through the packaged runtime, while proving unrelated unknown accessors still produce diagnostics.

```
rec_auto_fix:           false
```
