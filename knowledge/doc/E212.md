# E212: hmmac 安全标签阻止从用户路径 dlopen .so 文件

## 基本信息
- **严重度**: 2
- **类别**: platform, limitation, ohos, toolchain, security
- **作者**: ZACH_123 <ZACH_123@noreply.gitcode.com>
- **来源 PR**: source_commit:

## 错误特征
```
Error loading shared library.*\.so.*Permission denied|Can't load.*\.so.*Permission denied|dlopen.*Permission denied
```

## 根因分析
OpenHarmony 的 hmmac (Harmony MAC) 安全模块根据文件所在路径分配安全标签。/data/service/hnp/ 下的文件获得 hnp_file 标签（通过 hmmac=inherit_parent），而用户可写路径（/storage/Users 为 hmdfs 标签，/data/storage/el2/base 为 hishell_hap_data_file 标签）获得不同标签。Perl/Python 进程运行在 hnp_file 安全上下文中，hmmac 策略仅允许加载 hnp_file 标签的 .so 文件。用户无权写入 /data/service/hnp/（属主 installs:installs），导致编译产物无法被 dlopen 加载。注：perl-dbd-pg 3.18.0 (2026-06-10) 已记录此问题，当时称为 "SELinux HMDFS 限制"，本次通过 ls -Z 安全标签分析确认根因更精确地为 hmmac 安全标签。

## 推荐方案
**方法**: install-to-hnp-path

**说明**: 通过 hnp 包管理器或 cmd-pkgs 将 .so 安装到 /data/service/hnp/ 路径，获得 hnp_file 安全标签

**验证/命令**:
```
# 需通过系统包管理器安装，非用户可自行操作
```
