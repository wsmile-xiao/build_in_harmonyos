# E535: CGNS 4.5.2 上游 CTest 在 OHOS 启用与真实通过率核验（24 项: 23 通过 + 1 skip + 0 失败）

## 基本信息
- **严重度**: 2
- **类别**: platform, ohos, build-system, cmake, testing
- **作者**: junshi_liu <liujsh2023@lzu.edu.cn>
- **来源 PR**: !6809

## 错误特征
```
CGNS_ENABLE_TESTS=OFF|100% tests passed, 0 tests failed out of 24|
                         Test #.*test_back_comp.*Skipped|The Fortran compiler identification is unknown|
                         HDF5.*not found|MPI.*not found
```

## 根因分析
>
    路径 A（基础适配）常以"上游测试需 HDF5/MPI，不可用"为由直接将上游测试写成 0/N，
    未实际启用上游 CTest 核验真实通过率。实测证明该假设对 CGNS 4.5.2 不成立：
    上游 C 测试（24 个 CTest 入口）不依赖 HDF5 链接即可完整构建执行；当
    CGNS_ENABLE_TESTS=ON 且 HDF5=OFF 时，C 测试仅链接 cgns + m。启用后真实结果：
    24 个注册项中 23 个执行并通过、1 个 test_back_comp 由上游 SKIP_TESTS 机制
    （SKIP_RETURN_CODE 125）跳过硬编码在每条 case 的预期输出，0 个失败，
    执行通过率 23/23（100%），不得写成 24/24 或 0/24。OHOS 平台能力缺口
    （无 Fortran 编译器 flang/gfortran、无 MPI）导致 10 个 Fortran CTest 与
    8 个并行示例 N/A，属独立边界，不应与 C 测试结果混算。

## 推荐方案
**方法**: enable-upstream-ctest

**说明**: conanfile.py 的 generate() 设置 CGNS_ENABLE_TESTS=ON（HDF5=OFF），
                        build() 中执行 cmake.test()，让 conan create 真实运行上游 24 项
                        CTest；结果按"执行通过数 = 注册数 - skip 数"口径上报

**验证/命令**:
```
|
    def generate(self):
        tc = CMakeToolchain(self)
        tc.variables["CGNS_ENABLE_HDF5"] = False
        tc.variables["CGNS_ENABLE_TESTS"] = True
        tc.generate()
    def build(self):
        cmake.configure(); cmake.build()
        cmake.test()   # conan create 时真实执行上游 CTest
```
