# E526: Conan 2.x apply_conandata_patches 默认 strip=0，pre-CI/本地校验必须镜像该语义而非 -p1

## 基本信息
- **严重度**: 3
- **类别**: conan, patch, patch-ng
- **作者**: GoliWie <GoliWie@noreply.gitcode.com>
- **来源 PR**: !5084

## 错误特征
```
patch: can't find file|Apply failed
```

## 根因分析
Conan 2.x 的 apply_conandata_patches 读取 conandata.yml 的 patches 条目，经 patch_ng 库应用补丁，默认 strip=0：patch_ng 会自动剥离 git format-patch 风格 diff 头里的 a/ 与 b/ 前缀，无需 -p1 强剥。若 pre-CI/本地/评审校验用系统 patch 命令按 -p1 语义 dry-run，与 Conan 实际应用语义不一致：要么对 "--- a/xxx" 头多剥一层误判目标文件缺失（假失败），要么在 strip 层级上未覆盖真实应用路径（假通过），使 patch 校验结论失真。MLton 0001/0002/0003 补丁均为 git format-patch 格式（diff --git a/... b/...、--- a/... +++ b/...），应用与校验必须同一语义。

## 推荐方案
**方法**: mirror-strip-0-patch-semantics-in-pre-ci

**说明**: pre-CI/本地校验与 apply_conandata_patches 使用同一 patch 语义：以 strip=0 + patch_ng 对 a/b 前缀的自动剥离为准，不用 -p1 强剥；最稳妥是直接在干净源码树调用 apply_conandata_patches 验证（应用后 diff 确认目标行已改），再对应用结果做 hash 比对，保证校验即应用。

**验证/命令**:
```
校验脚本在干净源码树执行 apply_conandata_patches 后核对 hash/差异；若需 dry-run，按 strip=0 语义（patch_ng 自动剥 a/b 前缀）模拟，禁止 patch -p1 直接 dry-run git 格式补丁。
```
