# E507: Probe optional pthread cancellation state before enabling Boost sleep calls

## 基本信息
- **严重度**: 3
- **类别**: cmake, boost, capability-detection, pthread
- **作者**: 2301_80739235 <2047361658@qq.com>
- **来源 PR**: !5392

## 错误特征
```
sp_thread_sleep.*pthread_setcancelstate|pthread_setcancelstate.*undeclared
```

## 根因分析
POSIX thread support does not guarantee the optional pthread cancellation-state API, while bundled Boost can infer its call path from BOOST_HAS_PTHREADS alone.

## 推荐方案
**方法**: link-aware-symbol-capability-selection

**说明**: Probe pthread_setcancelstate with Threads::Threads and apply BOOST_SP_THREAD_SLEEP_NO_PTHREAD_SETCANCELSTATE only to the target that embeds the Boost sleep implementation when the symbol is unavailable.

**验证/命令**:
```
Use CheckCXXSymbolExists with CMAKE_REQUIRED_LIBRARIES=Threads::Threads, restore the probe state, and gate only the cancellation-state calls while retaining nanosleep.
```

pthread_setcancelstate, CheckCXXSymbolExists, Threads::Threads, BOOST_SP_THREAD_SLEEP_NO_PTHREAD_SETCANCELSTATE, KWStyle
