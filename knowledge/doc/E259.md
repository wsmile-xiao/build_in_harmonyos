# E259: Conan Release 的 -DNDEBUG 让 assert(含副作用的表达式) 整体不求值，触发上游 latent bug

## 基本信息
- **严重度**: 2
- **类别**: build-system, conan, testing
- **作者**: GoliWie <GoliWie@noreply.gitcode.com>
- **来源 PR**: source_commit:          e81b42ab7c26c1e6207f7b4099d5739ff7c2a6bf

## 错误特征
```
assertion.*self != NULL.*failed|assertion.*[a-z_]+ != NULL.*failed|Critical.*assertion.*failed|FAIL:.*[0-9]+ out of [0-9]+ tests failed
```

## 根因分析
上游代码用 assert(EXPR) 包裹了一个有副作用的表达式（如 assert(g_module_symbol(h, "sym", (gpointer*)&p)))），本意是"断言成功的同时完成取符号赋值"。但 Conan 的 AutotoolsToolchain 在 build_type=Release 时注入 -DNDEBUG，C/C++ 标准下 assert(EXPR) 展开为 ((void)0)，EXPR 根本不求值——于是赋值/调用从未发生，p 保持未初始化，后续逻辑静默走错分支或读到垃圾值。这类 bug 在上游裸 make check（无 NDEBUG）下永远不会触发，故属 latent bug；只有 Conan Release 或其它显式 -DNDEBUG 构建才会暴露。调试特征：测试大面积失败（数百个）、但编译/链接全过、失败模式集中在某个初始化路径返回 NULL 或空，且 set_configure / hook 注册类调用"看似没执行"。

## 推荐方案
**方法**: hoist-side-effect-out-of-assert

**说明**: 把 assert(含副作用的表达式) 拆成两步：先把表达式求值存入局部变量，再 assert 该变量的结果。这样 NDEBUG 下断言虽被去除，但副作用（赋值/调用）仍执行。修改落在测试夹具或上游源码的对应行，用最小 source patch 实现，不改变测试 oracle、不跳过测试、不预置答案。

**验证/命令**:
```
gboolean ok = g_module_symbol(h, "set_configure", (gpointer*)&sc); assert(ok);
```
