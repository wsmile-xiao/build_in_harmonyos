# E163: source-patch

## 基本信息
- **严重度**: 2
- **类别**: platform_headers|linker
- **触发工具**: clang|ld.lld
- **阶段**: compilation|linking

## 错误特征
```
duplicate symbol: __packed|ld.lld: error: duplicate symbol: __packed
```

**关键词**: __packed,duplicate symbol,binder.h,userfaultfd.h,OpenHarmony header

## 根因分析
OHOS 内核头文件 linux/android/binder.h 和 linux/userfaultfd.h 将 __packed 定义为全局变量（"struct binder_handle_cookie { ... } __packed;"），而非 Linux 标准的宏定义（"#define __packed __attribute__((packed))"）。当多个源文件包含这些头文件时，每个编译单元都会生成一个名为 __packed 的全局符号，导致链接时重复符号错误。

**影响范围**: 所有包含 linux/android/binder.h 或 linux/userfaultfd.h 的 C/C++ 软件。已知：stress-ng, 其他使用 binder/userfaultfd 接口的系统工具。

## 推荐方案
- **方法**: source-patch
- **描述**: 在 #include 前将 __packed 重定义为宏，include 后取消定义，使用 #ifdef __OHOS__ 守卫。
- **命令**: `|`
- **自动修复**: false

## 验证
```bash
nm <object-file> | grep "__packed" 或 echo '#include <linux/android/binder.h>' | clang -xc -c - 2>&1
```
