# E329: control-plane 纯逻辑测试的 ServiceAction 定义顺序问题可用 recipe patch 修复

## 基本信息
- **严重度**: 2
- **类别**: testing, import-order, review
- **作者**: wxjshr <wxjshr@noreply.gitcode.com>
- **来源 PR**: !7151

## 错误特征
```
NameError: name 'ServiceAction' is not defined|test_models.py|models.py
```

## 根因分析
`src/ostra_control_plane/models.py` 在定义 `ServiceStatus.allowed_actions`
                        时引用了 `ServiceAction`，但 `ServiceAction = Literal[...]` 放在
                        `ServiceStatus` 之后。Python 3.12 导入模块时会立刻求值类型注解，
                        因而 `pytest tests/test_models.py` 在收集阶段直接报 `NameError`。

## 推荐方案
**方法**: reorder-service-action

**说明**: 将 `ServiceAction = Literal[...]` 提前到 `ServiceStatus` 之前，或把
                        `allowed_actions` 的注解改为字符串前向引用，再重跑 `test_models.py`
                        与 `test_config.py`。

**验证/命令**:
```
先修正 `models.py` 定义顺序，再执行 `PYTHONPATH=src python -m pytest
                        tests/test_models.py tests/test_config.py -q` 复核纯逻辑子集。
```
