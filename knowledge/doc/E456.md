# E456: Windows-to-OHOS Qt5 cross builds must separate target Qt from native host moc/rcc/uic

## 基本信息
- **严重度**: 2
- **类别**: cmake, cross-compile, host-tools, qt5
- **作者**: 2301_79503900 <3308319887@qq.com>
- **来源 PR**: !6994

## 错误特征
```
Automatic MOC.*moc|Exec format error.*moc|cannot execute.*moc|AArch64.*moc
```

## 根因分析
CMake AUTOGEN executes moc, rcc, and uic on the build host, but a target Qt package for OHOS contains AArch64 tools that Windows cannot execute. Treating the target Qt prefix as both the target runtime and the host-tool prefix therefore fails before target compilation.

## 推荐方案
**方法**: separate-target-qt-and-native-host-tools

**说明**: Keep the OHOS Qt package in the target dependency graph, provide a native Qt host-tools directory containing moc.exe, rcc.exe, and uic.exe, and inject CMAKE_AUTOMOC_EXECUTABLE, CMAKE_AUTORCC_EXECUTABLE, and CMAKE_AUTOUIC_EXECUTABLE through the Conan CMake toolchain.

**验证/命令**:
```
conan create archives/a/attica-kf5/5.116.0 -pr:h=ci/conan/profiles/ohos-aarch64 -c user.attica-kf5:qt_host_tools_dir="$QT_HOST_TOOLS_DIR"
```
