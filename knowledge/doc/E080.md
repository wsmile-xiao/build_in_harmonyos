# E080: venv 创建失败（lib64→lib 符号链接被 HMDFS 拒绝）

> **类别**: python/hmdfs/filesystem/runtime-linking | **严重度**: 🟡 | **触发**: python/venv | **阶段**: runtime**
> **来源**: python-extensions.md §3.5 + Python 3.9.0 补丁 0011

---

## 错误现象

```bash
$ python3 -m venv myproject
Error: [Errno 13] Permission denied: 'lib' -> '/path/to/myproject/lib64'
```

关键特征：
- 仅在 **64 位系统** 上触发（32 位不会创建 lib64 链接）
- 错误码固定为 `Errno 13` (Permission denied)
- `python -m venv` 和 `venv.EnvBuilder().create()` 都会触发
- 影响 pip install --user、tox、nox、poetry 等所有依赖 venv 的工具

## 根因分析

### Python venv 的 lib64 symlink 逻辑

Python 3.9+ 的 `Lib/venv/__init__.py` 第 ~137 行：

```python
if ((sys.maxsize > 2**32) and (os.name == 'posix') and
    (sys.platform != 'darwin')):
    link_path = os.path.join(env_dir, 'lib64')
    if not os.path.exists(link_path):
        os.symlink('lib', link_path)   # ← 💥 HMDFS 不支持！
```

**问题链**：

```
python -m venv myproject
    │
    └─ ensure_directories()
        ├─ sys.maxsize > 2**32 → ✅ 64 位
        ├─ os.name == 'posix' → ✅
        └─ sys.platform != 'darwin' → ✅
            └── os.symlink('lib', 'lib64')
                └── HMDFS: Operation not permitted 💥
                    └── OSError 未捕获 → venv 创建中断
```

### 为什么 symlinks=False 不管用？

```bash
python3 -m venv --symlinks false myproject
# ❌ 仍然失败！
```

`symlinks=False` 只控制 `bin/` 下脚本的处理方式，**不影响** `lib64 -> lib` 的创建。后者在 `ensure_directories()` 中无条件执行。

## 解决方案

### 方案 1（推荐）：源码补丁 — try/except + makedirs

```diff
--- a/Lib/venv/__init__.py
+++ b/Lib/venv/__init__.py
@@ -137,7 +137,12 @@ class EnvBuilder:
             if ((sys.maxsize > 2**32) and (os.name == 'posix') and
                 (sys.platform != 'darwin')):
                 link_path = os.path.join(env_dir, 'lib64')
                 if not os.path.exists(link_path):
-                    os.symlink('lib', link_path)
+                    try:
+                        os.symlink('lib', link_path)
+                    except OSError:
+                        # HarmonyOS: HMDFS does not support symlinks.
+                        os.makedirs(link_path, exist_ok=True)
```

**为什么 makedirs 安全**：`sysconfig.get_path('purelib')` 始终返回 `lib/pythonX.Y/site-packages`，`lib64/` 永远不会被 pip 或 import 遍历。

### 方案 2：运行时 workaround

```python
import os, venv
env_dir = '/path/to/venv'
os.makedirs(os.path.join(env_dir, 'lib64'), exist_ok=True)

_orig = os.symlink
def _safe_symlink(src, dst, *a, **kw):
    try: _orig(src, dst, *a, **kw)
    except OSError:
        if not os.path.exists(dst):
            os.makedirs(dst, exist_ok=True)
os.symlink = _safe_symlink

try:
    venv.EnvBuilder(with_pip=True, symlinks=False).create(env_dir)
finally:
    os.symlink = _orig
```

## 验证修复

```bash
python3 -m venv /tmp/test_venv && echo "✅ venv 创建成功"
ls -la /tmp/test_venv/lib64
# 期望: directory (非 symlink)
/tmp/test_venv/bin/pip install six && echo "✅ pip 正常"
```
