# E1008 — `make install` 前置重查 build 目标：build 变量须重传到 package()

## 错误特征
conan package() 阶段 `make install` 失败（而非 build()）：
```
make -C src/pmcpp ... pmcpp.static
/usr/bin/ld: cannot find -lpthread   # 或 undefined symbol: pthread_cancel
make: *** [GNUmakefile:NN: pmcpp.static] Error 2
```
关键信号：**install 阶段**出现"本应在 build 期就跳过"的目标（`.static` 等）被重建。

## 触发条件
- 构建系统: 多级 make，`install` 目标以 build 目标为前置（PCP：`install :: default_pcp install_pcp`）
- 场景: conan 配方 build() 与 package() 两次独立 `self.run`，命令行 make 变量不跨调用持久
- 典型: build() 用 `CROSS_COMPILING=yes` 跳过 `.static`，package() 未重传 → 变量回退默认 → `.static` 被重建

## 根因分析
`install :: default_pcp install_pcp` 的 make 语义：
1. 先构建前置 `default_pcp` —— 它会**重新评估**每个子目录的 default 目标依赖。
2. `CROSS_COMPILING` 不是持久状态，而是 builddefs 每次 make 运行时按命令行/环境重新求值。
3. package() 的 `make install` 没带 `CROSS_COMPILING=yes` → builddefs 求值 `CROSS_COMPILING=no` → `STATICTARGETS` 恢复非空 → `pmcpp.static` 等从未构建的静态目标被当作待构建 → 静态链接失败（OHOS 静态 libpthread.a 缺 pthread_cancel）。

**泛化**：只要 build/install 目标共享前置依赖图，build 期变量（交叉编译标志、工具覆盖、LD_LIBRARY_PATH）必须一致重传到 install 调用，否则"已构建 up-to-date"是假象。

## 解决方案

### 推荐方案
把 build() 的 make 变量覆盖抽成共享方法，package() 复用（防漂移）：
```python
def _make_override_vars(self):
    return (
        f'CROSS_COMPILING=yes PCP_CONF="{pcp_conf}" PCP_SORT_PROG=/usr/bin/sort '
        "'PMIECONF=...' 'PMGENMAP=...' 'PMCPP=...' 'NEWHELP=...'"
    )
# build():   self.run(f'cd "{src}" && make -j1 {self._make_override_vars()}')
# package(): self.run(f'cd "{src}" && make -j1 install {self._make_override_vars()}')
```
实例：`archives/p/pcp/7.1.5/conanfile.py` 的 `_make_override_vars()`。

### 禁止做法
- ❌ package() 裸 `make install`（丢 build 变量，触发 .static 重建）
- ❌ `touch` .static 文件掩盖（只用于定位根因，不可提交）
- ❌ 在 package() 重复粘贴一份变量（与 build() 漂移，改一处漏一处）

## 验证
```bash
grep -n "^install" GNUmakefile   # 确认 install 前置含 default_pcp/build 目标
grep -rn "CROSS_COMPILING\|STATICTARGETS" src/include/builddefs
# 修好后：make install 不再重建 .static，package() 通过
```
