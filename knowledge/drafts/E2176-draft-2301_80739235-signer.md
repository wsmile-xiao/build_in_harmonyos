# 生成式数据包的源输入绑定与安装输出闭包

## 问题现象

规则、目录数据库或 XML 目录包可以在 Meson/Conan 中成功结束，但安装结果
仍可能缺少一个生成域、保留空文件、丢失最后一组记录、包含未转义的 XML，或
遗漏旧路径兼容别名。仅检查进程退出码、安装目录存在或总文件数，会把这些
错误当成成功。Windows 主机交叉到 POSIX 目标时，还可能在 Meson 配置阶段看到
`prefix value 'F:/' must be an absolute path`。

## 根因

生成器常以相对数据域名运行在独立 build 目录，空 glob 不一定报错；分组输出
若只在下一键到来时刷新，会在 EOF 丢失最后一组；字符串拼接 XML 属性会遗漏
转义；构建系统声明的域和安装规则也可能没有一一覆盖。Conan 的 Meson helper
在 Windows 上从主机根目录推导默认 prefix，得到盘符路径，而目标 Meson 按
POSIX 语法解释该值。

## 修复步骤

1. 从脚本位置或显式源根解析输入，冻结每个数据域的非空文件清单、关键文件和
   官方归档 SHA-256；空清单立即失败。
2. 覆盖构建系统声明的每个生成域，在 EOF 刷新分组，按目标格式序列化并转义
   字段。
3. 保留 Conan 生成的 Meson machine file，但在 Windows 到 POSIX 目标的 setup
   命令中显式传 `--prefix=/`；仍使用 Conan 的 build/install 生命周期。
4. 在 package 阶段逐域比较安装文件数，解析全部生成 XML/模式文件，检查兼容
   alias 的解析闭包，并将 pkg-config prefix 设为 `${pcfiledir}/../..`。
5. 在 test_package 中读取真实 `package_folder`，同时运行语义解析和 metadata
   检查。上游测试分母与消费者断言数分开记录，主机结果不能替代 OHOS W3。

## 本次验证

`xkeyboard-config/2.48` 的官方归档为 953316 字节，SHA-256 为
`b77041324f0109f77161ee43743fe04baa485866af8460d31e476ad3f7648fd5`。源树包含
`compat=22`、`geometry=30`、`keycodes=21`、`symbols=198` 个普通文件，其中
`meson.build` 是构建描述文件并被安装规则排除，所以 `symbols` 源计数 198 对应
安装闭包 197；`types` 下的 `custom` 目录也由安装规则排除，所以源计数 13 对应
安装闭包 12；另有 8 个符号链接。清单分别记录源计数和安装下限，由消费者校验
安装闭包，避免把有意排除的构建输入误报成缺失。Meson 在 `--prefix=/` 下生成
的 X11 兼容链接目标是目标根绝对路径 `/share/xkeyboard-config-2`；Windows
Conan 暂存目录中它可能无法按主机路径解析，消费者应核对链接目标字节，对相对
链接才要求解析到包内版本化根。
安装测试还解析 `base.xml`、`base.extras.xml`、`evdev.xml`、`evdev.extras.xml`，
验证 `share/X11/xkb` 与 `xkeyboard-config.pc` 两个兼容别名，以及无盘符的
relocatable pkg-config 字段。

## 适用范围与安全边界

该模式适用于生成式资源包、规则/目录数据库和 schema/catalog 安装包，尤其是
Meson 自定义目标与 Conan consumer 组合。计数一致不替代 schema、键字段和语义
断言；外部依赖仍须单独通过 `--build=never` 发布门禁。不得修改官方源或旧证据
来补写 PASS，不得用主机生成成功代替目标 W3；源 hash、输入清单、目标包路径、
测试分母和当前候选身份必须来自同一 run。
