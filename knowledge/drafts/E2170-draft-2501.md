# E2170 draft: Complete a published Guile header closure for downstream Conan consumers

Status: draft. Contributor: `2501_91199785`. Source: `libctl/4.5.1`, task #8151, HarmonyOS PC arm64, 2026-09-25.

## Failure and deduplication

The published `guile/2.2.7.1` OHOS package has its `include/guile/2.2/libguile/*` headers but omits the public `include/guile/2.2/libguile.h`. `libctl`'s configure probes `<libguile.h>` to enable its modern Guile API branch. Without that header it selects the old `<guile/gh.h>` branch, which is also absent, and `clang` stops on `fatal error: 'guile/gh.h' file not found` (diagnostic log SHA-256 `77d15854b47684fb6561f3731097ee8a39e4a027366eb20bd822d32674819a55`). This is not evidence that Guile itself is absent: its binary and internal headers were resolved and downloaded.

The version-matched upstream Guile 2.2.7 `libguile.h` is 4,083 bytes with SHA-256 `baffa7e9d97488eac7b773ce2858c65d1a127491ae01f9d4ad145937d0bedd82`. It includes `<gmp.h>` and internal headers that include `<gc/gc.h>`. Once the overlay reached the recipe source and package, `libctl` compiled, `test-prism` passed, and Conan created the package; the installed-package consumer then failed on `fatal error: 'gmp.h' file not found` because the public header's dependency include paths were not transitive (diagnostic log SHA-256 `f27cbc4f96ab5f7bab26b03a4974a1f1087024f03caded1f36f3b812f464061a`).

The graph index has no Guile-specific missing-umbrella-header or Conan `transitive_headers` entry. E158 is a missing-header symptom in fbida/pkg-config, not a published Guile export omission or downstream Conan trait. E011/E052/E060/E112/E129 and related entries already cover HMDFS `config.status` temporary-directory permissions; those are separate failures observed in this adaptation and are not claimed as this draft's new knowledge.

## Reusable method and safety boundary

1. Inspect the exact dependency package and distinguish missing public umbrella header from missing internals or missing binary. Confirm a version-matched upstream header's source and SHA-256; do not synthesize declarations or borrow a different Guile version.
2. Export the header with Conan `exports_sources`, copy it from `export_sources_folder` into `source_folder`, and make it visible to configure via task-local `CPPFLAGS`. Install it in the consuming package's public include directory so installed-package consumers see the same header.
3. Set `transitive_headers=True` for Guile and every direct dependency whose headers that public entry point exposes (here GMP and GC). Set `transitive_libs=True` for Guile when the consumer calls Guile's API directly.
4. Rebuild from a fresh Conan cache and test an installed-package consumer through the generated CMake target. A successful library compilation alone cannot prove the downstream header closure.

This is a bounded workaround for a published Guile package missing one version-matched public file; it does not modify that shared dependency. If its internal headers are not compatible with the verified public file, repair and republish Guile instead. The recipe still depends on Guile and does not use `--without-guile`.
