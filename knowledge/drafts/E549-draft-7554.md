# E549 — m4 生成型 Makefile 修改必须同补 m4 模板与再生产物并钉时间戳

> Status: DRAFT | 实例: cbflib 0.9.7(HarmonyOS PC 构建 OHOS AArch64)
> severity 🟠 2 | category: build-system, patch-pipeline

## 错误特征

```text
make: *** No rule to make target 'ifneq', needed by 'all'.  Stop.
# 或(CI 无 m4 时)
make: m4: command not found
```

## 触发条件

- 上游用 m4 从 `m4/Makefile.m4` 生成 `Makefile`,且生成规则
  `Makefile: m4/Makefile.m4` 留在文件内(CBFlib 风格);
- 补丁只修改 `Makefile`(生成物)而 m4 模板同步更新导致 m4 源更新 →
  GNU make 启动时自动调用 m4 再生 Makefile,补丁被回滚;或 CI 无 m4 时中断。

## 根因

GNU make 会自动重建「过期的 makefile 本体」:只要存在重建规则且某先决
文件比 makefile 新就触发。

## 修复(已验证)

1. 同一补丁同时改 m4 模板与再生产物:
   `m4 -P -Dcbf_system=default m4/Makefile.m4 > Makefile`,
   与原始 tarball diff 仅含预期 hunk(可再生确定性核对);
2. `build()` 内 `os.utime` 把 `m4/Makefile.m4` 与 `Makefile` 钉到同一
   历史时间戳(1600000000),切断自动再生(boolstuff autotools
   `_pin_autotools_timestamps` 先例的 m4 变体)。

cbflib 0.9.7 干净 conan create 全绿,CI 无 m4 依赖。

## 相关

- causes: 补丁回滚或构建中断
- caused_by: make 自动重建过期 makefile
