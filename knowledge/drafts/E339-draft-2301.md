# E339 - Probe IPC constructors before isolating blocking authentication tests

> Contributor: 2301_80739235 | Status: DRAFT | Created: 2026-08-30

## Scope

Use this pattern when an IPC test exercises Unix-domain address forms or an
authenticated stream on a restricted kernel, sandbox, or embedded runtime.
It applies to any event-driven test where a worker can wait for a peer during
construction or handshake. It does not replace tests for a mandatory IPC
feature, and it does not classify unknown errors as environmental.

## Symptom

A low-level socket probe succeeds, but a GDBus test later waits for a worker or
authentication handshake until the CI harness timeout. Different address
spellings can fail at constructor time even when `socket()` and `bind()` work.

## Root cause

The low-level operation and the library constructor do not have the same
runtime contract. Constructor pathname setup, authentication policy, and
worker scheduling add failure points. A worker-bearing probe can reproduce the
deadlock it is supposed to classify, and an unbounded vector lets one missing
capability consume the complete suite timeout.

## Recommended solution

1. Probe each address form through the library constructor with worker threads
   disabled. Cache only an explicitly classified capability failure.
2. Keep unexpected constructor errors as failures; do not infer support from a
   successful bind or from the current user identity.
3. Execute the full blocking vector inside an exec'ed test subprocess with a
   finite monotonic timeout. Convert only an unavailable capability or a
   timeout of that optional handshake into a reason-bound skip.
4. Keep the normal assertions and all unrelated transport vectors registered,
   so a supported runtime still exercises the complete contract.

## Evidence and verification

GLib 2.88.3 CI #34598 reached 353 successful tests but timed out at 480 seconds
in `gdbus-peer`, `gdbus-server-auth`, and `gdbus-connection-flush`. The r930
successor replaced the worker-bearing constructor probes, added bounded
subprocess guards around the authentication vectors, and moved flush
connection setup into the guarded child. In an isolated Linux replay, the
patched binaries completed peer 12/12, server-auth 10/10, and flush 2/2 with
exit code 0.

## Forbidden shortcuts

- Do not treat a successful `bind()` or a privileged UID as proof that the
  library constructor and authentication handshake are usable.
- Do not wrap the entire test suite in one broad skip or increase the global
  timeout.
- Do not convert an unclassified constructor error or child failure into a
  capability skip.

## Safety boundary

The probe and timeout only classify the directly exercised optional IPC
capability. They do not change production IPC behavior, and they do not prove
that another address form, transport, or target device has the same support.
