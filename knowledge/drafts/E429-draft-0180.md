# E429 — 旧 Maven pom 硬编码 source/target 1.5，JDK 17 拒绝编译

- **条目主题**：JVM（Maven）三方库在 OHOS 平台（BiSheng JDK 17）构建时，因上游 pom 把
  `maven-compiler-plugin` 的 `<source>/<target>` 硬编码为 `1.5` 而编译失败；命令行 `-D` 无法覆盖，
  必须改构建文件。
- **状态**：草稿（待知识库主编审核，拟提升编号 E###）
- **来源事件**：`weupnp/0.1.4` OHOS 适配（2026-10-01）

## 适用场景

Maven 项目在 JDK 17 环境下执行 `mvn clean package` 时失败：

```
[INFO] --- maven-compiler-plugin:3.1:compile (default-compile) @ weupnp ---
[ERROR] COMPILATION ERROR :
[ERROR] Source option 5 is no longer supported. Use 7 or later.
[ERROR] Target option 5 is no longer supported. Use 7 or later.
```

上游 pom 形如：

```xml
<plugin>
    <groupId>org.apache.maven.plugins</groupId>
    <artifactId>maven-compiler-plugin</artifactId>
    <configuration>
        <source>1.5</source>     <!-- 硬编码 -->
        <target>1.5</target>     <!-- 硬编码 -->
    </configuration>
    <version>3.1</version>
</plugin>
```

## 根因

1. `maven-compiler-plugin` 3.x 的默认 `source/target` 是 `1.5`；老 pom（2016 年以前）通常既不写属性
   也不改默认值，于是编译级别停在 1.5。
2. **JDK 17 的 javac 已删除 source/target < 7 的支持**（JDK 20 起连 7 也被移除），因此直接报
   `Source option 5 is no longer supported`。
3. 关键陷阱：`<source>/<target>` 写在插件的 `<configuration>` 里属于**显式配置**，优先级高于
   `${maven.compiler.source}` 属性默认值，所以 `-Dmaven.compiler.source=8` **不会生效**；
   `maven-compiler-plugin:3.1` 也不支持 `release` 参数。

## 诊断步骤

```bash
# 1. 复现首错
sh <maven>/bin/mvn clean package -B            # → [ERROR] Source option 5 is no longer supported

# 2. 确认是硬编码而非属性
grep -A8 maven-compiler-plugin pom.xml | grep -E '<source>|<target>'   # → <source>1.5</source> ...
```

## 推荐方案（priority 1）

改**构建文件本身**，用补丁把编译级别提到 8（≥7 即可）：

```bash
# 探索阶段直接改源码树，再由补丁管线固化
# pom.xml: <source>1.5</source> → <source>8</source>，<target>1.5</target> → <target>8</target>
python3 scripts/ohc-run.py refresh-patch --auto <软件名> <版本>
sh <maven>/bin/mvn clean package -B -DskipTests=false
```

实测结果（weupnp 0.1.4）：补丁后 `EXIT_CODE=0`，45s，产出 `target/weupnp-0.1.4.jar`。

## 回退方案（priority 2）

仅当 Maven 本身完全无法获取时，才用 `javac + jar` 直接编译（只对零第三方依赖的 JVM 库等价），
并在 notes.md 中记录偏离；不要默认走这条路，因为会丢掉上游构建系统产出的 OSGi/资源打包语义。

## 禁止策略

**禁止**把 `-Dmaven.compiler.source=…` / `-Dmaven.compiler.target=…` / `maven.compiler.release`
当作修复手段：

- 显式 `<configuration>` 优先于属性默认值，覆盖无效；
- `maven-compiler-plugin:3.1` 没有 `release` 参数；
- 实测（weupnp 0.1.4）该方向 EXIT_CODE=1、耗时 4s、报错原文**完全不变**，
  等于白跑一轮并产生"已修复"的假结论。

## 平台相关性

OHOS worker 只提供 BiSheng JDK 17（`~/bishengjdk17`，`java.vendor=bisheng`），
没有 JDK 8；因此这不是"换 JDK 就好"的问题，而是必须在构建文件层面修正编译级别。

## 验证命令

```bash
sh <maven>/bin/mvn clean package -B     # 期望 [INFO] BUILD SUCCESS，且产物为 major=52（Java 8）字节码
```
