# E580: C++17 严格模式下 gnu 扩展宏 linux 未定义导致老代码平台分支失效

## 错误特征

- `unknown type name '__u32'` / `'__u16'` / `'__u8'`
- `use of undeclared identifier 'KDMKTONE'` / `'fd_set'`
- `'linux/kd.h' file not found`（实际头存在但包含分支被跳过）
- 本地 gnu 方言编译通过、conan 干净构建（`-std=c++17`）失败的反差

## 触发条件

1. 老 C/C++ 源码使用 `#if defined(linux)` 判断 Linux 平台（zhcon 0.2.6 有 11 文件 23 处）
2. 编译器为 clang，conan profile `compiler.cppstd=17`（或显式 `-std=c++17`）启用严格 ISO 模式
3. `linux`（无下划线）是 gnu 扩展预定义宏，仅在默认 gnu 方言下定义；严格 ISO 模式下不定义

## 根因

`#if defined(linux)` 分支在严格 ISO C++ 模式下整体失效 → 包含 `<linux/kd.h>`、`<asm/types.h>` 等内核头的代码被跳过 → 后续代码引用 `__u32/__u16/__u8/KDMKTONE/fd_set` 等类型与宏全部未声明，产生大量编译错误。

## 解决方案

将 `#if defined(linux)` 统一替换为 `#if defined(linux) || defined(__linux__)`：

```bash
grep -rln "defined(linux)" src/ | while read f; do
  sed -i 's/#if defined(linux)/#if defined(linux) || defined(__linux__)/g' "$f"
done
```

`__linux__` 是标准预定义宏，在严格 ISO 模式与 gnu 方言下均定义，对 Linux/OHOS 成立，不影响其他平台。

## 验证证据

- zhcon 0.2.6 修复后：`clang++ -std=c++17 -stdlib=libc++ ... -c src/main.cpp` 0 错误
- 全量 make 回归 0 错误（MAKE_EXIT=0）
- conan-verify G2 `conan create` 干净构建通过（G1-G5 全 PASS）

## 适用边界

- 适用：所有以 `defined(linux)`/`defined(unix)` 等 gnu 扩展宏判断平台的老 C/C++ 项目
- 不适用：已使用 `__linux__` 的项目；非严格模式（默认 gnu++17）下不触发
- 同类宏：`unix` 在严格模式同样未定义，需同样处理

## 关联条目

- similar_to: E102（musl 未实现 Linux API，`__linux__` 条件需排除 OHOS）、E130（OHOS SDK libc++ 头特殊）、E147（musl 未实现 CPU 亲和 API）
- 区别：E580 聚焦**编译期平台宏失效**（`defined(linux)` 未定义），E102/E147 聚焦**运行时 API 缺失**（宏成立但 API 不存在）
