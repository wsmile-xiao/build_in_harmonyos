# E14723 draft: upstream clock-helper commands belong to the test build context

An Autotools package may compile cleanly while an upstream time-dependent test cannot execute because its script calls an external clock-control utility. This is a test dependency, not necessarily a production library dependency. Inspect the actual script before declaring the complete upstream test inventory.

In OATH 2.6.14, `liboath/tests/tst_usersfile.sh` sets `FAKETIME=datefudge`, obtains a fixed UTC timestamp through that command, and emits `Faketime or datefudge missing` when the command is absent. The OHOS Conan recipe declares `datefudge/1.27` in `build_requirements()`, preserving the original test behavior. The fresh target `conan create` completed all nine `liboath/tests` and two `oathtool/tests` registered cases: 11/11 PASS, zero failures. The consumer independently passed its RFC 6238 TOTP assertion flow (1/1 case, four assertions). Raw evidence: `submission-evidence/oath/conan-create.log`, SHA-256 `02ad14082093583ab3c565fa2b147ca98294274f058098065c8e2e093bf8a10d`.

Reusable decision: inspect upstream test scripts for subprocess commands and classify each as build-context tool, target runtime dependency, or optional input; require the exact published tool in the appropriate Conan context; then execute the unchanged test suite and count terminal cases from its own harness. If the tool is unavailable, stop and report the unverified suite. Do not turn the missing-tool branch into a passing skip, inject a fake result, or reduce the upstream denominator. This knowledge applies to clock virtualization and other external test-only commands; it does not imply that every package should depend on datefudge.
