# E565 — ECM ecm_set_disabled_deprecation_versions 遮蔽 KF6 弃用 API

## 错误特征

```
src/main.cpp:98:48: error: unknown type name 'KLocalizedContext'
```

## 现象与误导性

报错形态是 `unknown type name`，看起来像"这个类不存在"——实际上类存在（在仓 ki18n
头文件里有完整声明），只是被 ECM 的弃用宏机制在预处理期移除了。

## 根因（平台/构建机制因果链）

1. KDE 应用顶层 CMakeLists 常见 `ecm_set_disabled_deprecation_versions(Qt 6.5.0 KF 6.12.0)`
2. ECMDeprecationSettings 把 "KF 6.12" 传播为各框架的 `KF_DISABLE_DEPRECATED_BEFORE_AND_AT`
3. 框架头（如 `ki18n_export.h`）内：未显式定义 `KI18N_DISABLE_DEPRECATED_BEFORE_AND_AT` 时
   继承组值 6.12 → `KI18N_ENABLE_DEPRECATED_SINCE(6, 8)` 为假
4. KF 6.8 弃用的类（`KLocalizedContext` → `KLocalizedQmlContext` 改名）整体声明被
   `#if` 包裹消失 → `unknown type name`

OHOS 特有前提：制品仓 ki18n 全版本未构建 `src/i18n-qml`（KF6::I18nQml /
KLocalizedQmlContext / KLocalization::setupLocalizedContext 都不在仓），应用只能用
在仓 ki18n 提供的前代 `KLocalizedContext`（同 i18n()/xi18n() QML context object
机制，上游仅改名弃用），于是必然撞上这层遮蔽。

## 修复方案

CMake target 级编译定义，把弃用下限显式归零（命令行宏优先于 _export.h 头内默认值）：

```cmake
target_compile_definitions(alligator PRIVATE KI18N_DISABLE_DEPRECATED_BEFORE_AND_AT=0)
```

C++ 侧等价替换：

```cpp
#include <KLocalizedContext>   // was: <KLocalizedQmlContext>
engine.rootContext()->setContextObject(new KLocalizedContext(&engine));
// was: KLocalization::setupLocalizedContext(&engine);
```

同时从 `target_link_libraries` 移除 `KF6::I18nQml`（KLocalizedContext 由 KF6::I18n 提供）。

## 红线

- 不要试图在应用源文件里 `#define KI18N_DISABLE_DEPRECATED_BEFORE_AND_AT 0` 再 include
  （顺序敏感、易与全局定义打架）——用 CMake 编译定义最稳
- `KI18N_NO_DEPRECATED`（若被全局定义）会无条件隐藏，归零宏无效，需一并 undef
- 换用 `KLocalizedQmlContext` 需要 ki18n 配方先补构建 i18n-qml 组件（仓级依赖，勿在
  应用内硬扛）
