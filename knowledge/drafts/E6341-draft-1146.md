# E6341 — OHOS Meson 测试需用直接 DT_NEEDED 避开间接 SONAME 搜索失效

## 问题现象

目标 worker 启动 Meson 上游测试时，日志中的 `LD_LIBRARY_PATH` 已明确包含所有 Conan 依赖目录，也包含报错库所在目录，但测试仍以 RC 127 报 `Error loading shared library <indirect-soname>`，随后出现该库导出符号的 `symbol not found`。

## 根因

编译、链接和环境日志只能证明依赖目录被声明，不能证明目标 loader 会解析到间接 SONAME。平台 CI 进一步证明，即使 Meson 的 verbose launch 明确经过任务私有 wrapper，wrapper 在最后边界恢复绝对 `LD_PRELOAD`，loader 仍可能拒绝 `librest` 后面的间接 `libjson-glib`。Meson 虽把传递依赖放在测试 ELF 的链接命令中，但默认 `--as-needed` 会删除测试代码未直接引用的库，最终测试 ELF 没有对应的 `DT_NEEDED`，仍依赖目标 loader 的间接搜索。应只对已证实缺失的运行时根使用局部 `--no-as-needed`，随后立即恢复 `--as-needed`，让测试 ELF 直接声明这些根。

现有 E502 已经证明 OHOS CI worker 对用户目录共享库存在“`LD_PRELOAD` 拒绝、exec-time `DT_NEEDED` 可用”的平台边界，本条目不重复声明该结论。这里的新增知识是：Meson 的默认 `--as-needed` 会让测试 ELF 丢失原本已经出现在链接行上的传递库；需要用局部链接状态恢复直接 `DT_NEEDED`，并在 Windows-hosted OHOS clang 包装器下把 POSIX 库路径保持为独立 driver 参数。该状态不能放进 toolchain 的全局 `c_link_args`，因为 Meson native configure 会把它用于签名前的编译器可运行性探针；必须在 compiler detection 完成后、项目目标声明前注入 project link arguments。平台进一步证明，即使直接 `DT_NEEDED` 和搜索路径均已出现，从制品仓复制到任务目录的旧签名身份仍可能被 native worker 拒绝；关键根必须在每个最终 loader 可见位置重新自签，且签名必须是文件的最后一次变更。

## 修复步骤

1. 枚举 Conan host dependency graph 的真实 `package_folder` 与 `cpp_info.libdirs`。
2. 在构建目录创建任务私有的 runtime stage；只复制已验证的普通 `.so`/`.so.*` 文件。
3. 若目标 basename 已存在，仅允许源和目标字节完全一致；不一致立即 fail closed，禁止覆盖。
4. Meson 完成构建后，将同一闭包再复制到其实际 prepend 的 `builddir/rest`；保持相同的冲突与字节一致性检查，确保第一 loader 项包含全部间接 SONAME。
5. 若平台日志已证明 Meson wrapper 被执行，但错误仍是同一间接 SONAME，则停止继续叠加环境变量或 preload。确认链接行已有该库但测试 ELF 动态段没有对应 `DT_NEEDED`。
6. 在 `project()` 完成 compiler detection 后、任何 target 声明前注入 Meson project link arguments：`-Wl,--no-as-needed`、`<verified-root-1>`、`<verified-root-2>`、`-Wl,--as-needed`。库路径必须作为独立 clang driver 参数，不能嵌入逗号分隔的 `-Wl` 参数。禁止写入 `MesonToolchain.c_link_args`，否则 native worker 的未签名 compiler-runnability probe 也会加载这些库并使 configure 失败。
7. 仅在 native OHOS executor 上，对 task-private runtime stage 中的已观察根移除旧 `.codesign` 后自签；Meson 将闭包复制到首个 loader 目录后，对该目录中的同名根再次自签。禁止修改 Conan 共享缓存；每次自签后用 `llvm-readelf -S` 验证 `.codesign`，且之后不得再复制或编辑该文件。
8. fresh 构建后逐个回读完整测试 ELF 清单，要求每个 ELF 都直接包含这些 `DT_NEEDED`；不得只检查 `librest` 本身。随后原样运行完整上游测试，不改测试 argv、清单或分母。
9. 再由同一候选的目标事务验证包消费者；最后仍要求平台 CI 对完整上游清单达到 `N/N PASS`。

## 验证

librest/0.10.2 的平台 CI #60540 在完整多目录 `LD_LIBRARY_PATH` 中仍找不到 `libjson-glib-1.0.so.0`；CI #60579 又反证了“第一目录物化即可”。CI #60589 证明父进程 preload 没有进入 child launch；其后的 #60598 明确打印 `Target-test wrapper`，10 个 verbose launch 也都经过该 wrapper，但仍然 0/10 RC 127。r095 的 `readelf -d` 证明测试 ELF 没有直接需要 `libjson-glib` 或 `libintl`；r096 又证明绝对路径不能嵌入 `-Wl`。r097 把独立参数写入 `MesonToolchain.c_link_args` 后，本地交叉构建和 10/10 动态段审计通过，但平台 #60606 在 native configure 的 compiler-runnability probe 阶段失败，证明 toolchain 全局参数的作用域过早。r098 改为 project target 作用域后，本地 10/10 ELF 均有直接根；平台 #60610 也进入完整测试并在 verbose launch 中同时显示直接根和完整 `LD_LIBRARY_PATH`，却仍 0/10 拒绝复制的 `libjson-glib`，从而把剩余边界缩小到 task-private copy 的最终签名身份。最终方案在每个最终位置重签关键根；r099 fresh `conan create` 返回 RC 0，package consumer 构建通过，10/10 测试 ELF 仍各有两个直接根、单一 `DT_RPATH` 且无 `DT_RUNPATH`。native 自签分支仍须由同 HEAD W3 和平台 exact-head CI 验证。

## 适用范围与安全边界

仅当缺失 SONAME 已被证明存在、文件为兼容目标 ELF、stage 路径进入测试进程，并且 loader 在 wrapper 已执行后仍失败于同一间接查找时，才允许把该根强制为测试 ELF 的直接 `DT_NEEDED`。若文件缺失、架构错误、权限不可读或提供者冲突，应修复真实提供者；若测试 ELF 已有直接 `DT_NEEDED`，则应继续诊断 loader/文件身份，不能重复加链接参数。自签只允许作用于任务私有副本并限定已观察根，绝不能修改 Conan cache 或系统目录；签名后任何字节变更都会使证据失效。`--no-as-needed` 必须局部闭合，禁止对整个图永久关闭；不得把本地动态段或单一消费者 PASS 当作平台完整上游测试 PASS。候选变化后必须创建新的 W3 successor，旧事务不能拼接。
