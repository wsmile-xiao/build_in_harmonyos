# E351 — find_project_dir 误指 skill 安装目录，归档写错位置

## 错误特征

在 `build_in_harmonyos` 仓库工作区执行 `ohc-run.py init-build` 后：

```
ℹ️ 初始化档案: portablegl 0.100.0
  ℹ️   路径: /storage/Users/currentUser/.opendesk/apps/skills/resources/openharmony-compile-agent/archives/p/portablegl/0.100.0
```

归档骨架与 `.build-context-<name>-<ver>` 被写到 **skill 安装目录**而非当前仓库；
仓库内 `archives/<字母>/<包名>/` 缺失，后续 conan-init/finish 在仓库里找不到归档。

## 触发条件

- 工具: ohc-run.py 任意子命令（init-build / conan-init / conan-verify / finish /
  graph / result …），它们内部调用 `ohc.utils.find_project_dir()`
- 环境: 未设置 `OHC_PROJECT_DIR`，且当前目录不是 skill 安装目录

## 根因分析

`find_project_dir()` 搜索序：

1. `OHC_PROJECT_DIR` 环境变量（**要求该目录下存在 SKILL.md 才接受**）
2. 从脚本位置向上找 SKILL.md → skill 安装目录
   （`/storage/.../openharmony-compile-agent`）自带 SKILL.md，**优先命中**
3. ATOMCODE_HOME / `~/.atomcode/skills/`
4. `~/.opendesk` 平台回退

当贡献者在自己的 build_in_harmonyos 仓库工作区（该仓库根也有 SKILL.md）执行命令而
未设置环境变量时，第 2 步先命中 skill 安装目录——归档/上下文写进 skill 数据目录，
污染 skill 自带的 archives 镜像。

## 解决方案

### 推荐方案（export-project-dir）

```bash
export OHC_PROJECT_DIR=/storage/Users/currentUser/runner001/build_in_harmonyos
# 子命令同时带 --project-dir 双保险（init-build/conan-init/conan-verify/finish/graph 均支持）
python3 $SKILL_ROOT/scripts/ohc-run.py init-build <name> <ver> --project-dir $OHC_PROJECT_DIR ...
```

若已误建：删除 skill 目录下的 `archives/<字母>/<包名>/` 误建内容与误生成的
`.build-context-*`，然后带 `--project-dir` 重跑。

### 验证

```bash
echo $OHC_PROJECT_DIR
ls $OHC_PROJECT_DIR/archives/<字母>/<包名>/<版本>/manifest.yaml   # 归档在仓库内
```

### 禁止做法

- ❌ 在 skill 安装目录的 archives/ 里继续干活（那是 skill 数据镜像，非协作仓库，
  不进 PR，工作会丢失）
- ❌ 误删 skill 目录下的其他既有归档（历史数据镜像）——只清理本次误建的包目录
