# E2183 — 传递依赖 visible=False 时其 include 不进 cpp_info 聚合(缺 X11/X.h 型)

## 错误特征
`fatal error: 'X11/X.h' file not found`,但报错头所在包(xorgproto)确实在依赖图里;
conan graph 警告 `required both with visible=True and visible=False`。

## 触发条件
- 构建系统: 裸 Makefile 手工聚合依赖 include 路径(非 CMakeDeps 等生成器消费者)
- 阶段: make(编译期)
- 前提: 纯头文件包(如 xorgproto)被传递依赖且图内 visible=False

## 根因分析
xorgproto 等纯头包被 libx11/libsm/libice 等传递引用且 visible=False 时,其 include
路径不出现在下游可枚举的 cpp_info 聚合里。CMakeDeps 消费者无感,但裸 Makefile
手工聚合依赖路径的包直接缺头。

## 解决方案

### 推荐方案
requirements() 显式 `self.requires("xorgproto/<ver>", force=True)` 把纯头包拉为直接
依赖,其 include 目录进入手工聚合。识别信号: graph 的 visible=True/False 冲突 WARN
且报错头文件位于传递依赖包内。

### 禁止做法
- ❌ 向 CMDLINE_CPPFLAGS 硬编码 ~/.conan2 包路径(不可复现,违反 R49)

## 实证
chiark-utils/8.0.1:xbatmon-simple 链接前 X11/X.h 缺失,force=True 后构建通过
(conan-create.log 中 xorgproto include 进入 CMDLINE_CPPFLAGS)。
