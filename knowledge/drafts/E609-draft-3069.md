# E609 — meson subproject 上游 wrap 不可达时预置本地源码 + wrap_mode=nodownload

## 错误特征
```
subprojects/libglib-testing/libglib-testing/meson.build:22:20:
ERROR: static_library got unknown keyword arguments "soversion" ... "version"
(或) 拉取 wrap-git 时: Could not resolve 'gitlab.gnome.org' / 503
```

## 触发条件
- 构建系统: meson（subprojects 测试/构建依赖）
- 阶段: configuration（meson setup 拉取/解析 subproject）
- 测试依赖为 wrap-git 子项目（如 libglib-testing → gitlab.gnome.org），上游 git 服务在 OHOS/CI 不可达；或子项目旧版 meson.build 含新版 meson 已拒绝的参数

## 根因分析
meson 测试依赖常用 wrap-git（url + revision）按需拉取。两类故障：
1. 上游 git 服务不可达（gitlab.gnome.org 503 / DNS 失败），wrap 拉取失败；
2. 即使拉取成功，旧版子项目（如 libglib-testing 0.1.0）meson.build 用 `static_library(..., version:, soversion:)`——新版 meson（1.12）允许 library() 但 static_library 不再接受 version/soversion 参数；docs 子目录还需 gtkdoc-scan（未安装）。
两类都导致干净构建（conan create）失败，而本地手工修好 work 目录无法固化。

## 解决方案

### 推荐方案
1. 把修复后的子项目源码目录放进 conan 包：`exports_sources = "patches/*", "subprojects/*"`，conan export/create 自动复制进 source 目录（无需手动 copytree，export_sources_folder 与 source_folder 同路径）；
2. `MesonToolchain` 设 `project_options["wrap_mode"] = "nodownload"`——meson 检测到 `subprojects/<name>/` 已存在就直接用本地，不再走 wrap 拉取；
3. 子项目 meson.build 做新 meson 兼容修复：static_library 分支去掉 version/soversion（library 分支保留）、docs 子目录以 `if not meson.is_subproject()` 条件化（subproject 场景不生成 gtkdoc）。

### 禁止做法
- ❌ 依赖 wrap 在线拉取（CI 上 gitlab.gnome.org 不可达，构建必失败）
- ❌ 在 source() 里从 export_sources_folder copytree 到 source_folder（同路径会报 "same file" 错误，conan 已自动复制）

## 验证
```bash
# 修复前（干净 conan create）
conan create archives/l/libmalcontent/0.10.2 ...
# ERROR: static_library got unknown keyword arguments "soversion"
# 修复后
conan create ... --build=missing
# meson 配置通过、subproject libglib-testing: YES、测试执行
```

## 适用与不适用边界
- 适用：meson wrap-git 测试依赖在 OHOS/CI 不可达、或子项目与新 meson 不兼容的项目（libmalcontent 0.10.2 + libglib-testing 0.1.0 先例）
- 需要随包分发第三方源码时注意许可证（libglib-testing LGPL/COPYING 随包保留）
- 不适用：wrap 源可达且子项目与新 meson 兼容时（无需预置，默认 wrap 拉取即可）
