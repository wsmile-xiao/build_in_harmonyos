# E544 — 真机 conan 裸 ohos-aarch64 profile 缺 os.version：包本体 create 成功，test_package 计算 package_id 报 Invalid ID

## 错误特征

```text
libtut/0.0.20070706: Package 'da39a3ee...' created        ← 包本体成功
libtut/0.0.20070706 (test package): Test package build: build/clang-15-armv8-...
ERROR: libtut/0.0.20070706 (test package): Invalid ID: Invalid:
'settings.os.version' value not defined
```

- **关键判别**：`conan create` 的**包本体阶段全绿**（源码下载、打包、
  revision 生成全部正常），只在建/测 test_package 时爆 Invalid ID。
- 触发点在 test_package 的 package_id 计算：其 conanfile 声明了
  `settings = os, compiler, build_type, arch`，而 host profile 的
  `os=OHOS` 缺 `os.version` 子设置。

## 触发条件

- 构建系统: conan（真机直连验证场景）
- 阶段: testing（test_package 依赖图 package_id 计算）
- 环境: 设备上的裸 `ohos-aarch64` profile——只有 [settings] 六行
  （arch/build_type/compiler*/os），无 os.version，无 [conf]

```ini
# 裸 ohos-aarch64（缺 os.version → 触发）
[settings]
arch=armv8
build_type=Release
compiler=clang
compiler.cppstd=gnu14
compiler.libcxx=libstdc++11
compiler.version=15
os=OHOS
```

## 根因分析

Conan 2 对声明了 `settings.os` 的消费者配方计算 package_id 时，会
下钻 settings.yml 中该 OS 的子设置树；OHOS 在 settings.yml 里带
`version` 子设置，profile 未提供取值 → package_id 解析失败。包本体
不受影响的原因：header-library 配方 `package_id.clear()`（或库配方
settings 面更窄），不触发同样的下钻路径。

## 解决方案

### 推荐方案

真机验证一律用 `ohos-aarch64-fixed` profile（设备上已预置）：

```bash
$HOME/.local/bin/conan create . \
  --profile:build=default --profile:host=ohos-aarch64-fixed
```

fixed 版三处补全，缺一不可：

```ini
[settings]
...（同上）
os.version=6.0                     # ← 修 Invalid ID

[conf]
tools.build:compiler_executables={"c": "/data/service/hnp/bin/clang",
                                  "cpp": "/data/service/hnp/bin/clang++"}
tools.build:cflags=["-Wno-int-conversion", ...]
tools.cmake:cmake_program=/data/service/hnp/bin/cmake   # ← 真实工具链
```

### 禁止做法

- ❌ 为消错往 test_package 的 settings 里删 "os"（削弱跨平台语义，
  CI 侧同样要算 id）
- ❌ 动全局 settings.yml 给 OHOS 填默认 version（改基础设施，影响面
  不可控）
- ❌ 看到 Invalid ID 误判为配方写错去反复改 conanfile（错误在 profile
  环境，一行没改配方、换 profile 即过——libtut 实测）

## 验证

