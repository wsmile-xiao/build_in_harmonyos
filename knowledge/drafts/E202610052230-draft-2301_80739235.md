# 构建工具 stdout 混入 Conan 图 JSON 时的独立报告通道

配对草稿 E202610052230，draft: true；这是独立的结构化输出通道问题，不是补充草稿，不申报既有 E301、E077、E489 的基础机制。

## 触发特征与根因

CLI 使用 `--format=json`，配方中的签名或其他原生子工具也向 stdout 打印文本。即使命令 RC 0，捕获的 stdout 仍可能不是一个 JSON 对象；`json.loads` 因 `Extra data` 失败。这里的故障层是控制器数据通道，不是产品编译或测试失败。

## 可复用修复

1. 检查被执行版本的 CLI 是否支持 `--out-file`，不要猜测接口。
2. 冻结前将机器报告绑定到任务唯一的新文件；stdout/stderr 原字节保全，不将签名输出过滤掉。
3. 先核验 RC，再分别解析报告 schema、完整节点及 RREV/PID/PREV；核对当前源码、产物哈希与实际测试清单/分母。任何一项失败都不能宣称事务 PASS。
4. 已消费的失败事务仅终态收敛、精确清理和归档；控制器修复只能进入全新事务，不能裁剪旧 stdout 或重写回执追认 PASS。

## 真实证据

证据根 F:\HarmonyPC\pr-review-closure-20261004-r1：formal r003 的实际 Conan RC 0，24 个上游函数、1 个消费者、1 项鸿蒙专项执行通过；控制器解析混流 stdout 报 Extra data，最终 FAIL 保留。r004 独立图接口已修正，但官方源码下载超时导致 RC 1，FAIL 保留。r005 将同一官方 SHA-256 原归档冻结传输到任务私有 Conan 下载缓存，执行新的完整 native Conan create，将图输出到独立文件；24/24、1/1、1/1、图解析、产物绑定及完整 WAL/receipt 校验通过，唯一 launch=1，进程清零，release/postrelease PASS。

r005 最终 snapshot SHA-256：`9957b1697e5df579dfec53e0a115e574396a94ebc8ae7a7393060591537e4b93`。仓内 reports/native-conan-r005-verified-binding.json 与 raw-log-evidence-index.json 保存关联和原始日志 bytes/SHA-256；原始日志不进入 PR。真实目标 PASS 不等于 finish、平台 CI、AI Review 或提审完成。

## 查重与边界

四域查重已覆盖 knowledge/graph、drafts、doc、operations。E373 解决 Conan 生成环境未被裸 subprocess 继承，E396 解决图节点与已物化 package_folder 的身份关联；本条解决成功执行时子工具输出污染结构化数据通道，触发、根因和修复不同。E301 的 CMake.test/ctest 参数路由、E077 的签名后恢复权限、E489 的构建树加载闭包签名仅作为复用知识，不重复申报。

不适用于 CLI 不支持独立报告文件而强行传参；这种情况只能在冻结前可靠隔离子工具输出。禁止用正则从第一处左花括号截取、不检验返回码、忽略解析异常，或把新的数据解析器追认到已消费旧事务。
