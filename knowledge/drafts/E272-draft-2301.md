# E272 - Explicit Memory Budget after Target CMake Procfs Failure

## Symptom

A target build succeeds and CTest reports every generated test passing, but
the generated inventory contains one fewer test than an exact host baseline.
CMake also prints `Problem parsing /proc/meminfo`. In ITK 5.4.6 the missing
entry was `itkImageFillBufferTest4.1`, guarded by
`ITK_COMPUTER_MEMORY_SIZE GREATER 4`.

The same contract can fail earlier in same-machine OHOS CI: Conan reports the
target runnable, but no external task controller exported
`ITK_COMPUTER_MEMORY_SIZE`, so a recipe that made the override mandatory stops
before configure even though local `/proc/meminfo` is available.

## Root Cause

The target exposed a valid, readable `MemTotal` field and had ample memory,
but the selected CMake build could not parse the target procfs format for
`cmake_host_system_information(TOTAL_PHYSICAL_MEMORY)`. The derived cache
value therefore did not satisfy the upstream test gate. This is a capability
discovery failure, not proof that the target lacks memory.

The CI failure has a separate control-plane cause: a task-local evidence
variable was treated as a universal package input. An ordinary runnable
`conan create` has no controller to inject it.

## Recommended Fix

Keep the exact expected CTest inventory. Parse exactly one read-only
`MemTotal: <decimal> kB` field through a frozen task-local helper, reject
missing, duplicate, malformed, zero, too-small, wrong-unit, and implausibly
large values, and derive the same 80% GiB test budget used by the project.
Convert KiB to MiB before multiplying by 80: some target shells use 32-bit
integer arithmetic, and multiplying a 31 GiB KiB count first overflows.
Pass that budget through a strictly validated recipe input and require its
exact CMake cache binding before accepting the test result. Keep an explicit
override as the highest-priority path for sealed device runs. For runnable
OHOS builds with no override, parse the same exact local `/proc/meminfo` field
inside the recipe; fail closed on any read, cardinality, syntax, unit, range,
or derived-budget error. Non-runnable cross builds must not inspect host
`/proc/meminfo`.

## Validation

The local directed matrix passed 24/24 cases. A 31 GiB sample produced the
upstream-equivalent 24 GiB test budget; a direct 31 GiB recipe input reached
the generated CMake cache; all malformed and out-of-range cases failed before
Conan/CMake. The production target runner also requires the exact missing test
name and the complete 618-test verifier. Target recovery is **Needs
verification** until the create-new successor completes one genuine W3.

The first target implementation multiplied `32680776 * 80` before division.
The device shell overflowed that intermediate value and produced `-16`, so r31
failed before Conan with a clean release. The corrected order divides to MiB
first and keeps every supported intermediate value within signed 32-bit range.

After CI build `#26077` failed on the absent controller variable, a create-new
recipe fallback matrix passed 30/30. It covered explicit-override precedence,
the observed 32680776 KiB sample, minimum/maximum bounds, malformed and
duplicate fields, unreadable input, non-runnable isolation, and fail-closed
error propagation. Replacement CI and a new exact-snapshot W3 are **Needs
verification**.

## Deduplication

Exact searches across `knowledge/graph`, `knowledge/drafts`,
`knowledge/doc`, and `knowledge/operations` found no existing entry covering
CMake procfs memory-discovery failure plus a fail-closed explicit test-budget
binding.

## Safety Boundary

Do not lower the expected inventory to the smaller generated count, disable
tests, trust an unvalidated environment value, read host procfs for a
non-runnable cross build, or add a source-level OHOS/HarmonyOS macro. Bind the
measured capability and retain the upstream memory safety margin.
