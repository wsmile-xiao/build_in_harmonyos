# 草稿知识条目：PR 测试统计与 ledger 不一致（高估）被分析端核出并纠正（DRAFT-zlog-1.2.18-test-statistics-ledger-consistency）

## 问题（Problem）

PR 正文的测试统计表与执行端自己提交的逐入口 ledger 互相矛盾：正文按"带参数重跑后的乐观数字"填写（如通过率 25/26、单元 17、集成 5），而所附 `upstream_tests.log` 的 ledger 是首轮无参数运行结果（16 通过/10 失败/1 超时）；5 个压力入口本轮确实运行过但全部失败（rc=1）却在「适配后测试用例统计」表中被整体省略；合计口径在自身账目下不自洽。分析端以 `result_contract.prohibited_markers: inflated_test_statistics` 机器核出，判定 `quality_rework_required`。

## 根因（Root Cause）

正文统计未以单一事实源（逐入口运行 ledger）为准，而按汇总印象填写：
1. 带参数入口首轮无参数运行失败，正文直接采用"带官方参数后通过"的数字，但 ledger 仍是首轮结果，正文与证据互相矛盾；
2. "实际运行过但失败"的条目（压力入口 rc=1）被省略以回避低通过率；
3. 通过率用「路径覆盖」「可观察行为由某文件内联覆盖」等替代表述替代实测 N/N′；
4. 合计没有按同口径去重（17+5+5+1=28 vs 写 23），「与上游对比 +1」不自洽。

## 方案（Approach）

- PR 正文三张测试表与所附逐入口 ledger 逐行一致；仅统计本轮**实际执行**的入口（含压力入口），按 单元/集成/其他 分行列出来源，合计为去重和；
- 「与上游对比」只能写 `不变` / `+N` / `-N`；鸿蒙特有测试行写「新增」且不得为 `0`；
- 通过率写实测 `N/N′`（分子分母口径与该表一致）；未运行与不可运行单列，不计入分子/分母；
- 带参数入口一律以官方/CMake 参数运行，把结果如实记入 ledger 与正文（同一次重跑，ldger 与正文同源）；
- 失败项给出技术原因、归属（上游缺陷/平台限制/依赖缺失/基础设施）与最小复现证据（如 `zlog-chk-conf` 输出）。

## 验证（Verification）

- 逐入口重跑生成新 ledger（真实命令、cwd、退出码、绝对路径、sha256），正文三张表与 ledger 逐行对照一致；
- 以 `prohibited_markers: inflated_test_statistics` 校验：正文任何统计数字与 ledger 不一致即不合格；
- 分析端只读复核：ledger 行数与分类、正文三个表、通过率 N/N′ 三者一致。

## 适用边界（Applicability）

- 所有需在 PR 正文填报上游/适配后测试统计的适配任务；R51「PR 如实回填实测 N/N′/通过率（禁占位符）」；
- 带参数入口必须在正文与 ledger 中一致标注运行参数；无自然终止条件的入口按 SKILL 受控完成规则记录，不得改写为自然 exit 0 也不得计入通过。

## 反例与限制（Counter-examples / Limits）

- 首轮无参数运行结果与带参数重跑结果必须任选其一作为统一口径，并在 ledger 中如实体现；不得正文用一套、ledger 用另一套；
- 压力/性能入口即使"运行了且无异常"，只要退出码非 0 仍是失败，不得因"是压力测试"而省略或改写；
- 该草稿不覆盖基线噪声、共享框架或控制器/客户端故障类知识（此类问题不得创建草稿）。
