# E240 — autotools ext 扩展模块在 OHOS 上 DSO 链接缺核心库（EXT_LIBGAUCHE）

## 错误特征
`make -C ext` 构建 Gauche 扩展模块时：
```
ld.lld: error: unable to find library -lgdbm
*** ERROR: failed to link .../util--match.so dynamically: Error relocating ...
Scm_CurrentOutputPort: symbol not found
```
以及 `gosh -e '(use dbm.gdbm)'` 报 `cannot find "dbm/gdbm"`。

## 触发条件
- 构建系统: autotools（Gauche 的 ext/Makefile.ext）
- 阶段: linking / runtime
- 平台: OHOS aarch64（HMDFS）

## 根因分析
上游 `ext/Makefile.ext` 中：
- `MODLINK = $(CCLD) $(CFLAGS) $(LDFLAGS)`
- `EXT_LIBGAUCHE = -L"$(top_builddir)/src"` **只给 -L 不给 -l**，DSO 内含未定义 `Scm_*` 符号，dlopen 重定位失败
- `CFLAGS`/`LDFLAGS` 在 Makefile 内已定义（`-fPIC -O2 -O3 ...`、`... -shared -o`），**环境变量不覆盖**，必须 make 命令行传参
- precomp 阶段运行 `gosh` 需要 `LD_LIBRARY_PATH`（libgauche）与 `GAUCHE_LOAD_PATH`（libsrc/ + ext/ 各模块目录，解析 `(include ...)`）
- 部分模块（charconv）链接需要系统 `libiconv`，需在 `XLDFLAGS` 中追加 `-L` 路径
- 打包时 build lib 下生成的 `.sci`（如 `gauche/uvector.sci`）与仅存于 `libsrc/` 的 `.scm`（如 `srfi/13.scm`）必须一并打包

## 解决方案

### 推荐方案
在 conanfile.py build() 中为 ext 构建注入（make 命令行传参，非环境变量）：
```python
ext_env.define("LD_LIBRARY_PATH", src_build)
ext_env.define("GAUCHE_LOAD_PATH", ":".join([lib, libsrc] + ext_module_dirs))
self.run(
    f'make -C "{ext_build}" all -k -j1 '
    f'EXT_LIBGAUCHE="-L{src_build} -lgauche-0.98" '
    f'XCFLAGS="-O0 -DGC_NO_PTHREAD_CANCEL" '
    f'XLDFLAGS="-L{iconv_dir} -L{gdbm_lib}"',
    env=..., ignore_errors=True)
```
- 用 `XCFLAGS`/`XLDFLAGS` 追加（保留 Makefile 的 `-shared -o`），不要整值覆盖 `CFLAGS`/`LDFLAGS`
- 大生成文件（uvector.c ~7.5MB）用 `-O0` 加速编译（18s vs 4min+）
- package() 额外打包 build lib 的 `*.sci` 与 `libsrc/` 的 `*.scm`，DSO 放 arch 目录，`package_info()` 设 `GAUCHE_DYNLOAD_PATH`

### 禁止做法
- ❌ 用 `os.environ`/`Environment.define("CFLAGS", ...)` 覆盖 Makefile 已定义的变量（会被忽略或丢失 `-shared -o`）
- ❌ 只打包 `lib/` 的 .scm（漏 `libsrc/` 与 build lib 的 `.sci`，导致 `(use srfi.13)`/`(use gauche.uvector)` 找不到）
