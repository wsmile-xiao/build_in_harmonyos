# DRAFT-libsvgtiny-0.1.8-netsurf-nsshared-standalone-makefile-gperf-fallback

> Contributor: 2301_76770579 | Status: Draft | Updated: 2026-09-10
> Source: libsvgtiny 0.1.8 HarmonyOS PC 适配（NetSurf NSSHARED → standalone Makefile + gperf 预生成 fallback）

## 现象

NetSurf 家族库（libsvgtiny/libdom/libwapcaplet/libhubbub/libparserutils…）
的顶层 Makefile 只有两行有效内容：

```make
NSSHARED ?= $(PREFIX)/share/netsurf-buildsystem
include $(NSSHARED)/makefiles/Makefile.tools
```

在没有任何 netsurf-buildsystem 的平台（HarmonyOS PC 构建 worker 即如此）
上直接 `make` 报 `Makefile.tools: No such file or directory`，构建系统
整体缺失，连编译规则都没有。

## 根因

NetSurf 把全部编译/安装/测试规则收敛进独立包 netsurf-buildsystem
（NSSHARED），组件库自身 Makefile 只做变量声明。分发 tarball 不含
NSSHARED 实体 → 凡不装 netsurf-buildsystem 的环境，上游构建系统等于零。

此外 libsvgtiny 还有第二个 host 工具依赖：`src/autogenerated_colors.c`
由 `gperf src/colors.gperf` 在构建时生成（147 色查找表），worker 无 gperf
时同样卡住。

## 解决方案

1. **standalone Makefile 补丁**替换 NSSHARED include：从上游 Makefile 摘出
   真实源文件清单（svgtiny.c / svgtiny_gradient.c / svgtiny_list.c；
   autogenerated_colors.c 被 svgtiny.c `#include`，不进 SRC），
   WARNFLAGS 原样保留但 `-Werror` 改 `-Wno-error`（clang 15 警告集与
   GCC 不同，上游 -Werror 会假失败）；依赖 CFLAGS/LIBS 做成
   `DOM_CFLAGS ?=` / `DEP_LIBS ?=` 变量由 conanfile 从各依赖 cpp_info
   注入，替代 pkg-config 探测（worker 无 .pc 闭包）。
2. **gperf 生成物预生成提交（单一代码路径）**：把
   `autogenerated_colors.c` 作为补丁提交——功能等价的手写实现（同一
   147 个 CSS 色条目、与 colors.gperf 逐条核对值的线性查找；不必是
   gperf 的逐字节输出）。Makefile **不保留** gperf 再生成规则：生成件
   是唯一事实源，`make clean` 不删它，文件缺失时 make 直接
   "No rule to make target" 快速失败。曾试过"提交件 + command -v
   gperf 条件再生成"双路径，被审出两个实问题而废弃：clean 删掉提交件
   后无 gperf 环境无法重建；双路径产物不一致（手写≠gperf 输出）导致
   不可复现。单路径同时消除这两个风险。
3. **.pc 用 sed 就地展开**：libsvgtiny.pc.in 里的 PREFIX/LIBDIR/
   INCLUDEDIR/VERSION 占位符 install 时 sed 替换，并把 Requires/Libs
   补齐 libdom+libwapcaplet 闭包，不引入 configure。

## 禁止策略

- 不得为"装不上 netsurf-buildsystem"去 vendor 整个 buildsystem 仓库——
  组件真实编译规则只有几十行，standalone Makefile 更薄更可控。
- 不得把 `-Werror` 原样带过到 clang 15——警告集差异会假失败。
- 不得把 autogenerated_colors.c 加进 SRC 编译——它被 svgtiny.c
  `#include`，重复编译会符号冲突；它只需作为 svgtiny.o 的依赖存在。
- 不得假定 worker 有 gperf——预生成件直接提交为唯一代码路径；不要留
  "有 gperf 就再生成"的条件规则（双路径产物漂移 + clean 删文件后无法
  重建）。
- 不得让 `make clean` 删除提交进源码树的生成件。

## 验证

- `conan create`（OHOS aarch64 worker）全绿；
- 上游 test/runtest.sh 语义保留并加强：vendored decode_svg harness 对
  test/data/*.svg 12 个功能性用例**逐文件注册为 CTest 用例**（decode_*，
  CI 直接可见 12/12；仅编译不注册等于死代码，曾被 AI 检视判 P2）。
  注意上游 decode_svg 解析失败也只打印 stderr 后 return 0，单靠退出码
  会让解析失败空转通过——用 CTest `FAIL_REGULAR_EXPRESSION` 匹配
  "svgtiny_parse failed" 等错误输出兜底（vendored 源码保持零改动）。
  但严格判据立刻暴露语义例外：test/data/afl-expat-crash.svg 是 AFL
  发现的 expat 崩溃 PoC，其回归目的就是"graceful 解析失败、不崩溃"，
  该文件须豁免严格判据——vendored 语料里可能混有"预期失败"的 PoC
  输入，收紧判据前先逐个确认语义；2612 个 ns-afl-svg 为 AFL fuzz
  变异语料（判据仅"不崩溃"），不作为功能性回归 vendored，rule2 须
  写明此减少原因。

## 适用范围

- 全部 NetSurf NSSHARED 家族组件库（libdom/libwapcaplet/libhubbub/
  libparserutils/libcss/libnsgif/libnsbmp…）在无 netsurf-buildsystem
  平台的适配；
- 任何"构建期用 host 代码生成器（gperf/flex/bison/re2c）生成单一 .c"
  且 worker 不保证该工具的库：预生成提交 + 条件再生成是通用 fallback。
