# E549 — can_run() 导入路径陷阱

## 一句话

Conan 2.x（含 OHOS 适配版 2.29.1）中 `can_run()` 定义在 `conan.tools.build` 包内；写成 `from conan.tools.can_run import can_run` 会在 recipe 加载阶段抛 `ModuleNotFoundError`。

## 真实事件

- **软件**: primer3 2.6.1（OpenHarmonyPCDeveloper/build_in_harmonyos，分支 feat/primer3-2.6.1）
- **时间**: 2026-09-04
- **现象**: `conan create` 在 test_package recipe 加载阶段崩溃：
  `ModuleNotFoundError: No module named 'conan.tools.can_run'`
- **修复**: 导入改为 `from conan.tools.build import can_run`，`conan create` EXIT=0。

## 诊断

`can_run()` 是 `conan.tools.build` 包内的函数（与 `check_min_cppstd` 等同包），不存在独立的 `conan.tools.can_run` 模块。报错文本只提 `conan.tools.can_run`，容易被误判为"conan 版本缺组件"，导致无谓的版本升降级排查。

## 影响范围

所有 test_package（或主配方）需要用 `can_run()` 判断"宿主能否运行目标二进制"的场景。OHOS arm64 交叉编译尤其高频：交叉时 `can_run()` 为 False 应跳过 `self.run`；本机同架构自测时为 True 才执行（primer3 的 boulder IO 断言即此模式）。

## 修复

```python
# ❌ 错误
from conan.tools.can_run import can_run   # ModuleNotFoundError

# ✅ 正确
from conan.tools.build import can_run
...
def test(self):
    if can_run(self):
        self.run(...)
```

## 验证命令

```bash
python3 -c "from conan.tools.build import can_run; print('OK', can_run)"
python3 -c "import conan.tools.can_run"   # 应报 No module named 'conan.tools.can_run'
```
