# CMake 库的显式动态/静态构建开关映射

## 场景

部分 CMake 库不把动态/静态选择声明成 `option()`，而是在顶层文件中直接读取
`DISABLE_DYNAMIC`、`DISABLE_STATIC` 等缓存变量。另一些库没有注册 CTest 用例，
仅执行默认测试命令不能证明安装的头文件和库被消费者使用。

## 根因

Conan 的 `shared`/`fPIC` 选项与上游项目专用缓存变量不是自动同义词。若不显式
绑定，构建可能同时生成两种库、生成错误的链接目标，或在没有 CTest 测试时把空
测试结果误当成功。

## 修复步骤

1. 从上游 CMakeLists 读取实际动态/静态条件，并在 `CMakeToolchain` 中把
   `shared` 映射到这些缓存变量。
2. 静态且需要被下游共享库吸收时，显式设置 `CMAKE_POSITION_INDEPENDENT_CODE`。
3. 用 `CMakeDeps` 生成包目标，在 test_package 中链接安装目标并调用真实公共 API；
   没有上游 CTest 时，把空清单写入 MANIFEST，而不是伪造测试数量。

## 验证方式

检查配置缓存和安装产物只包含所选模式，运行 CMake consumer；交叉构建环境不能运
行目标时，至少要求消费者完成真实编译/链接，并把目标机运行列为后续门禁。

## 适用范围与安全边界

适用于 CMake 项目将构建模式隐藏在自定义缓存变量中、且上游测试入口为空或不完整
的 C/C++ 库。若上游已有独立且完整的 CTest 分母，应执行并记录全量 CTest；不能用
消费者测试替代上游测试。不得把系统同名库能编译通过当作包内容验证，消费者必须
通过 Conan 生成的目标和包内头/库闭包完成链接。
