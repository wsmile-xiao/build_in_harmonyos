# E646 — COIN-OR 家族下游包 configure 报依赖不可得：已发布依赖包 .pc 固化 prefix=/ 且 Libs 内嵌构建机绝对路径，须改子包 configure 的 flags 模式注入

## 错误特征

COIN-OR 家族下游包（Cbc 等 `.coin-or/Dependencies` 形态项目）在 OHOS 上
configure 阶段失败，典型报错（Cbc 2.10.13 子包 configure 实测文案）：

```text
configure: error: One or more required packages CoinUtils, Osi, and Cgl are not available.
configure: error: "Required package Clp unavailable."
checking for COINDEPEND... no
Package coinutils was not found in the pkg-config database.
```

姊妹形态（另一处隐蔽坑，链接期才爆）：

```text
grep: //lib/libClp.la: No such file or directory
libtool: link: `//lib/libClp.la' is not a valid libtool archive
make[2]: *** [Makefile:848: libCbc.la] Error 1
```

## 触发条件

- 项目：COIN-OR 家族下游（依赖 CoinUtils/Osi/Clp/Cgl，用 BuildTools 的
  `AC_COIN_CHECK_PACKAGE` 做 pkg-config 探测）
- 环境：依赖已经以 conan 包发布（autotools 构建时 `--prefix=/`，`make install
  DESTDIR=<包目录>` 打包）
- 阶段：configuration（第一形态）/ linking（第二形态）

## 根因分析

1. 依赖包 autotools 配置 `--prefix=/`，其 `make install` 生成的
   `lib/pkgconfig/*.pc` 把 `prefix=/`、`libdir=${prefix}/lib`（即 `/lib`）固化；
   且 `Libs:` 行在构建时被展开成**构建机的绝对缓存路径**（另一台机器上不存在）。
2. 下游子包 configure 的 `AC_COIN_CHECK_PACKAGE(CoinDepend,[cgl osi coinutils])`
   走 pkg-config：即使把包目录塞进 `PKG_CONFIG_PATH`，解析出的仍是 `/lib` 与
   陈旧绝对路径——configure 阶段找不到（第一形态），或假通过后在链接期炸。
3. 第二形态：conan 依赖包 `lib/` 内还带着 libtool `.la` 文件，其 `libdir='//'`。
   下游链接串里写 `-l<name>` 时，libtool 会去读 `<pkg>/lib/lib<name>.la`，按其
   `libdir='//'` 解析出 `//lib/libX.la`，直接 `not a valid libtool archive`。

## 解决方案

### 推荐方案（build-config，coinor-cbc 2.10.13 实测通过）

直接驱动子包 configure（顶层 configure 仅做子包编排），以 **flags 模式**显式
注入依赖——configure 脚本中 `--with-<pkg>-lib / --with-<pkg>-incdir /
--with-<pkg>-datadir` 分支直接置 `coin_has_*=yes` 并跳过 pkg-config：

```bash
./configure --prefix=/ \
  --enable-static --disable-shared --disable-dependency-tracking \
  --with-coindepend-incdir=<合并头 staging> \
  --with-coindepend-lib='<cgl>/lib/libCgl.a <osi>/lib/libOsi.a <coinutils>/lib/libCoinUtils.a <zlib>/lib/libz.a -lm' \
  --with-clp-incdir=<合并头 staging> \
  --with-clp-lib='<clp>/lib/libOsiClp.a <clp>/lib/libClpSolver.a <clp>/lib/libClp.a <同前闭包>' \
  --with-ositests-lib='<osi>/lib/libOsiCommonTests.a <同前闭包>' \
  --with-sample-datadir=<Data-Sample> \
  --with-miplib3-datadir=<Data-miplib3>
```

要点：

- **闭包用直接 `.a` 路径**而非 `-L/-l`（规避第二形态的 .la 解析；与上游自家
  cgl.pc 的写法一致）；
- **incdir 只收单目录**而依赖头分居各包 `include/coin` → 先合并到单一 staging
  再注入；
- 闭包顺序「依赖方在前、被依赖方在后」重复展开（同上游 cgl.pc）；
- 测试数据以 `--with-<pkg>-datadir` 注入激活 `make test` 的数据面（Sample →
  `-dirSample`；miplib3 → `-dirMiplib3 -unitTest`）。

### 回退方案（source-bundle）

用 get.dependencies.sh 思路把 CoinUtils/Osi/Clp/Cgl 源码拉成子包目录做 in-tree
递归构建。代价：全链重编、HMDFS 上要逐子包做 config.status/.lo 修复。

## 禁止

- **不要**把 conan 包目录塞进 `PKG_CONFIG_PATH` 来喂 `AC_COIN_CHECK_PACKAGE`
  （解析到 `/lib` 与陈旧路径，产生更隐蔽的失败）。
- **不要**在 `--with-<pkg>-lib` 里写 `-l<name>` 形式（触发 .la 解析，见第二形态）。

## 复现/验证命令（设备可直接执行）

```bash
# 判定依赖包 .pc 是否为不可用形态（prefix=/ 固化 + 绝对路径内嵌）
grep -n "libdir=\|^Libs:" <依赖包目录>/lib/pkgconfig/coinutils.pc
# 期望修复后证据：configure 输出 checking for COINDEPEND... yes / CLP... yes
```

## 与既有条目的关系

- `DRAFT-ohos-la-libdir-hardcode`：同一 .la `libdir='//'` 固化问题的**通用形态**，
  解法是复制改写 .la 到 staging；本条目是其 **COIN-OR 家族特化**——直接绕开 .la/
  pkg-config 整条链，用子包 configure 的 flags 模式 + 直连 .a 闭包，两者互补。
- `DRAFT-libtool-la-cross-package-and-private-header-deps`：.la 跨包复用的链接期
  形态记录；本条目的第二形态与之同症状。
- `E524`：依赖注入共享 prefix 的污染面（本条目的 forbid_1 与之呼应）。
