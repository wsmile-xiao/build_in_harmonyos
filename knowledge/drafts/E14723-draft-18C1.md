# Draft E14723 — KDE DocTools 的上游测试受 DocBook 数据发现条件控制

## 错误特征

配置日志显示 DocBook 组件缺失，随后执行 CTest 时没有注册测试：

```text
Could NOT find DocBookXML4 (missing: DocBookXML4_DTD_DIR) (Required is at least version "4.5")
Could NOT find DocBookXSL (missing: DocBookXSL_DIR)
No tests were found!!!
```

## 触发条件

- 构建系统：CMake + CTest
- 阶段：配置 / 测试
- 适用范围：上游测试用 `DocBookXML4_FOUND` 和 `DocBookXSL_FOUND` 控制注册的 KDE DocTools 项目
- HarmonyOS 设备环境：HarmonyOS PC 6.0，aarch64，Clang 15.0.4

## 根因分析

KDocTools 5.116.0 的 `meinproc_template` 和 `kdoctools_install` 注册在 DocBook XML 4.5 DTD 与 DocBook XSL 均被 CMake 找到的条件分支内。首次配置缺少这两项数据时，CTest 清单中根本没有这两个测试项。后来安装数据但不重新运行 CMake，也不会更新已生成的测试清单。

本次开始时，设备测试环境没有发现系统级 DocBook 数据。把官方 DocBook XML 4.5 DTD 和 DocBook XSL 1.79.2 安装到设备用户级测试前缀，并重新配置后，两个原本未注册的上游测试项都在 HarmonyOS 真机上运行通过。该验证说明这是测试数据发现/配置顺序问题，不是 HarmonyOS 上转换程序无法运行。

## 解决方案

### 推荐方案

1. 在可写的设备用户级测试前缀准备官方 DocBook XML 4.5 DTD 和 DocBook XSL 数据。
2. 确认 CMake 和设备上的 XML 工具能发现这些数据。KDocTools 运行时还需要正确的数据目录/catalog 环境。
3. 用 `BUILD_TESTING=ON` 重新配置既有构建目录。
4. 用 `ctest -N` 核对注册结果，再分别运行 `meinproc_template` 与 `kdoctools_install`。
5. 上游测试数按 CTest 注册的测试项计数：`kdoctools_install` 内部对子消费者的配置、构建、安装和文件检查仍是一个上游测试项。

把这些测试数据装进设备的用户级验证前缀即可完成该验证；本次没有把 DTD/XSL 数据打进 Conan 包，也没有把它们添加为 Conan 配方依赖。

### 禁止做法

- ❌ 不要把 `No tests were found` 当作上游测试通过，也不要以构建目录最初的测试列表作为补装数据后的最终测试清单。
- ❌ 不要把一个 CTest 项内部的多项文件检查拆算成多条上游测试用例。
- ❌ 不要只补装数据却忘记重新运行 CMake。

## 验证

```bash
cmake -S <source> -B <build> -DBUILD_TESTING=ON
ctest --test-dir <build> -N
# 安装官方 DocBook XML 4.5 DTD 与 DocBook XSL 1.79.2，并确保配置/运行时可发现后：
cmake -S <source> -B <build> -DBUILD_TESTING=ON
ctest --test-dir <build> --output-on-failure -R meinproc_template
ctest --test-dir <build> --output-on-failure -R kdoctools_install
```

实测结果：两个上游测试项均在 HarmonyOS PC aarch64 上通过（2/2）；其中 `kdoctools_install` 仍只计为一个测试项，尽管它会构建消费者并检查多个安装产物。
