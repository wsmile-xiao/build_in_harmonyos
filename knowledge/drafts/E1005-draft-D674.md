# E1005 — HarmonyOS PC /proc 数据源部分暴露：监控工具须按维度优雅降级

## 错误特征
- 运行期读取 /proc 数据源失败：
  - `open("/proc/diskstats")` → `Permission denied` (EACCES)
  - `/proc/pressure/cpu`、`/proc/pressure/io` → `No such file or directory` 或 EACCES
  - `/proc/cmdline` → EACCES
- 监控工具（PCP PMDA、topline、sysstat 等）启动即死或功能缺失

## 触发条件
- 平台: HarmonyOS PC (OHOS, aarch64)
- 阶段: runtime（编译无关；PCP 本身编译可通过，运行期数据源受限）
- 典型工具: PCP linux/linux_proc PMDA、iostat/sar、dstat、nmon、topline、htop

## 根因分析
HarmonyOS PC 的 procfs 是**选择性暴露**的。pcp 7.1.5 任务机实测（2026-10-09，普通用户）：

| 文件 | 可读性 |
|------|--------|
| /proc/stat | ✅ 可读 |
| /proc/meminfo | ✅ 可读 |
| /proc/net/dev | ✅ 可读 |
| /proc/loadavg | ✅ 可读 |
| /proc/pressure/memory | ✅ 可读 |
| /proc/self/status | ✅ 可读 |
| /proc/diskstats | ❌ root-only（EACCES；符号链接 → /sys/block/diskstats，见 DRAFT-11233） |
| /proc/pressure/cpu | ❌ 受限/缺失 |
| /proc/pressure/io | ❌ 受限/缺失 |
| /proc/cmdline | ❌ 受限/缺失 |

两个关键推论：
1. **PSI 不是全有/全无**：pressure/memory 可读而 cpu/io 不可读——代码不能假设三者同生共死，必须逐文件探测。
2. **diskstats 在 CI/conan 包环境永远不可读**（无 sudo，E031 的 sudo-run 方案在 CI 不可用）。

监控工具若对某数据源硬依赖且打不开即 `die()`，在 OHOS 上整个进程无法启动。

## 解决方案

### 推荐方案
按维度优雅降级（degrade-gracefully）：
- `fopen` 失败 → 该指标源标记 **unavailable**（PMDA 语义），绝不 `die()`。
- **PCP 天然安全**：linux/linux_proc PMDA 对缺失文件的设计就是指标 unavailable（pcp 7.1.5 适配验证：无需为 /proc 数据源打补丁）。
- die() 型工具需补丁降级（实例：E429/DRAFT-11233 topline `init_disks()` 失败改告警 + `do_disks()` 短路）。
- 探测方式：逐文件 `head -c 1 /proc/$f`，不要假设 /proc 家族整体可读。

### 禁止做法
- ❌ 假设 /proc/diskstats 在 CI/普通用户环境可读
- ❌ 对 PSI 三件套做整体存在性判断
- ❌ 用 sudo 方案绕过（CI 无 sudo，E031）
- ❌ 静默删除受限于 /proc 的核心功能（应上报 env_unsupported）

## 验证
```bash
for f in stat meminfo net/dev diskstats loadavg \
         pressure/cpu pressure/memory pressure/io cmdline; do
  head -c 1 /proc/$f >/dev/null 2>&1 \
    && echo "/proc/$f 可读" || echo "/proc/$f 受限"
done
```
预期（OHOS PC 普通用户）：stat/meminfo/net/dev/loadavg/pressure/memory 可读；diskstats/pressure/cpu/pressure/io/cmdline 受限。
