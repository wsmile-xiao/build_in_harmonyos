# Makefile 静态库配方的工具链与系统链接闭包

## 问题现象

手写 Makefile 的 Conan 配方在主机上可以构建，但在 Windows host 或 OHOS
armv8 worker 上会回退到错误的 `cc`/`c++`/`ar`，或者消费者找不到头文件和
`dlopen` 所需系统库。OHOS worker 还可能让 libc++ `__config` 报
`features.h file not found`；将一个通用 sysroot 的 `usr/include` 以前置
`-isystem` 注入后，又会让 libc++ `cstddef` 误选 musl `stddef.h`，报
`no member named 'nullptr_t' in the global namespace`；消费者的 CMake 编译器
探针还可能因通用 sysroot 缺少 `Scrt1.o`、`crti.o`、`crtn.o`、`libm` 或 `libc`
而链接失败。上游 `install-static` 只安装归档，静态包若直接依赖该目标还会
漏掉 include 目录。

## 根因

Makefile 的默认工具来自执行环境 PATH，Conan 的 host profile 与 build
profile 并不会自动覆盖这些变量。`BUILD=static` 使用 `ar` 生成
`lib/libsass.a`，但上游安装目标不包含 headers；而插件 API 需要 `m` 与
`dl` 系统链接闭包。部分 worker 的通用 sysroot 不含 libc++ 期望的
`features.h`，真实 C 头位于编译器同级 SDK 的 native sysroot；若把该目录
以前置 `-isystem` 注入，标准头搜索顺序会被改变并隐藏 libc++ 自带的
`nullptr_t` 定义；同一错误路径也会让消费者的 `CMAKE_SYSROOT` 指向不完整
目录，导致启动对象和 libc 链接缺失。仅检查归档存在不能证明消费者可用。

## 修复步骤

1. 从 `tools.build:compiler_executables` 读取 C、C++ 和归档工具，并把
   `tools.build:sysroot`、C/C++ flags 作为同一 Makefile 调用的变量传入。
2. OHOS 默认固定 `BUILD=static`，在 `package()` 复制静态归档和递归头文件，
   在 `package_info()` 声明库名、CMake/pkg-config 名称及目标系统库。
3. OHOS 下先验证显式 sysroot 的 `usr/include/features.h`；若通用路径缺失，
   从编译器目录探测同级版本化 SDK 的 `ohos/native/sysroot`，选择含
    `features.h` 的目录作为 `--sysroot`。不要把该目录以前置 `-isystem`，以免
   `cstddef` 误选 musl `stddef.h` 并丢失 `nullptr_t`；test_package 的
   CMakeToolchain 也必须使用同一完整 sysroot，确保编译器探针能找到启动对象
   和 libc。
4. 把上游实际可运行的测试入口纳入构建；LibSass 归档内的两个 `test/Makefile`
   二进制必须分别构建并执行。消费者测试必须调用 `sass_make_data_context`、
   `sass_compile_data_context` 并检查生成 CSS，而不是只读取文件。

## 本次验证

本任务固定官方 `libsass` 3.6.6 tag 的 SHA-256，并以 `make -C test test` 盘点
两个上游测试。平台 CI 首次在 `/data/service/hnp/bin/clang++` 与通用
`/data/service/sysroot` 组合上复现 `features.h` 缺失；修复后按编译器同级
`ohos-sdk.org/*/ohos/native/sysroot` 选择真实 sysroot；消费者曾在通用 sysroot
上复现启动对象/系统库缺失，修复后本地 OHOS 交叉构建、消费者和目标设备均通过。
目标验证还需确认当前 profile 的绝对编译器、sysroot、
`libm`/`libdl` 链接和消费者输出；任一工具或二进制身份漂移都使结果失效。

## 适用范围与安全边界

该模式适用于使用手写 Makefile、静态归档和真实 C/C++ 消费者的跨平台 Conan
配方。它不适用于 header-only 包，也不能替代 OHOS 共享库签名、真机执行和
平台 CI。未执行的上游测试不能计为 PASS，缺少依赖 binary 时不得用
`--build=missing` 掩盖 W0 闭包问题；sysroot 选择必须以头文件存在性和最终
编译器参数为证据，不能仅凭目录名或平台默认路径猜测。
