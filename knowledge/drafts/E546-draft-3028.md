# E546-draft-3028 — shebang 适配后上游自举测试的「整片假失败」

> 状态：草稿（contributor 3028）｜ 触发事件：clitest 0.5.0 适配
> 关联：E165（鸿蒙无 `/bin`，`sh` 在 `/system/bin/sh`）——本条是打完那个补丁之后
> 紧接着会踩到的验证陷阱

## 现象

按 E165 把脚本 shebang 改写成鸿蒙路径：

```diff
-#!/bin/sh
+#!/system/bin/sh
```

然后在适配机（x86 容器）上复跑上游测试套件，通过数断崖：

```
补丁前:  OK: 286 of 286 tests passed
补丁后:  FAIL: 262 of 286 tests failed
```

**这是假象**。上游套件是自举的——`test.md` 里的用例以 `./clitest ...` 形式调用被测
脚本，靠内核解析 shebang。适配机没有 `/system/bin/sh`，于是每个调用点都拿到
ENOENT，测试框架只报「输出不匹配」，并不会告诉你 "bad interpreter"。

危险之处在于失败长得很像真实回归，于是很容易走上两条错路：

1. 回退 shebang 补丁 → 交付一个在设备上根本无法直接执行的工具
   （而软件级 `commands.json` 声明的正是直接执行 `bin/<tool>`）；
2. 改上游测试用例「让它过」 → 在 PR 里提交一堆无谓的上游改动，掩盖一个并不存在的缺陷。

## 判定：三条命令区分真假

```bash
./<tool> --version        # 假失败场景：No such file or directory
sh ./<tool> --version     # 正常输出  → 脚本本身没坏，失败来自 shebang 路径
head -1 <tool>            # 确认 shebang 指向 /system/bin/sh
ls -l /system/bin/sh      # 构建机上通常不存在
```

显式解释器能跑通，就说明失败面在「构建机缺目标平台解释器」，与被测工具无关。

## 修法

### 推荐：给适配机建立解释器映射，复跑上游套件

```bash
mkdir -p /system/bin && ln -sf /bin/dash /system/bin/sh
./<tool> <upstream-test-entry>
```

这属于**构建机准备**（与 `/data/service/hnp/bin/clang` 软链同类），
**绝不写进配方，也不进补丁**。clitest 实测：映射建立后，打补丁的脚本经 shebang
直接执行，上游 286 用例恢复 286/286，与补丁前逐一致——补丁无功能回归的结论由此坐实。

### 配套：测试侧一律显式解释器调用

test_package 不要依赖 shebang：

```python
self.run(f'sh "{test_sh}" "{pkg_bin}"')
```

shebang 本身用独立断言覆盖，并且**前提不成立时打印 SKIP 而不是当作通过**：

```sh
head1=$(head -1 "$CLITEST")
[ "$head1" = "#!/system/bin/sh" ] && ok "shebang 正确" || no "shebang 正确" "$head1"

if [ -x /system/bin/sh ]; then
    "$CLITEST" --version >/dev/null && ok "经 shebang 直接执行可用"
else
    sk "经 shebang 直接执行" "/system/bin/sh 不在本机"
fi
```

这样同一份 test_package 在适配机（SKIP）与 CI 设备（实跑）上都诚实。

## 不要把上游自举套件塞进 `build()`

在 `conanfile.py` 的 `build()` 里跑上游套件，测到的是**构建机**的 shebang 支持，
以及 GNU coreutils 与鸿蒙 toybox 的行为差异（clitest 的套件里还有依赖 `perl` 的
用例），与适配质量无关。正确做法：

- 上游套件在适配阶段完整实跑并留下逐条记录（R51 第二步）；
- 平台相关行为由 test_package 在 CI 设备上复验；
- `test_package/MANIFEST.yml` 里如实写明 `upstream_test_in_build: false` 及其原因。

## 适用范围

所有脚本类包（shell / perl / python 单文件或多脚本工具），只要同时满足：
① 打了 shebang 路径改写补丁；② 上游测试以 `./<tool>` 自举调用。
仓库内 `lynis`、`powerlevel10k`、`cronic` 等属同一形态。
