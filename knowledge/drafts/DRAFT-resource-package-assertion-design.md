# 资源包自检设计：主断言是「声明 ↔ 内容一致性」，不是文件数

**来源**：`pop-icon 3.5.1` / `wm-icons 0.4.0` / `iso-flags-svg 1.0.4` 适配
**日期**：2026-09-20 ｜ **状态**：DRAFT

> 本条是把原先按包拆开的 3 条草稿（pop-icon / wm-icons / iso-flags-svg）**合并成一条**：
> 它们描述的是同一类问题（资源包的自检该断言什么），拆成 3 条属于同族重复。

## 为什么"文件数一致"不够

这类包的消费方式是**按声明取资源**：

| 包 | 声明在哪 | 取资源的方式 |
|---|---|---|
| pop-icon | `index.theme` 的 `Directories=` | XDG 图标查找按目录声明找图 |
| wm-icons | `icons/names.lst`（84 个语义名） | 窗口管理器按语义名（`window-close`…）取图 |
| iso-flags-svg | csv/json 索引（248 个 alpha-2 代码） | 按两位国家代码取旗帜 |

**资源在磁盘上但没被声明覆盖 = 系统里取不到**，而"目录里有 N 个文件""文件非空"这类断言对此
完全不敏感。

## 三种实测损坏模式

1. **pop-icon 3.5.1**：图标文件都在，但 `index.theme` 的 `Directories=` 没列出某个叶子目录 →
   那个尺寸/类别的图标在系统里**不可见**（实测 `Directories=` 154 项、8497 个 SVG、
   140 个 `.cur`、8 个 `.ani`、148 个无扩展名 X11 光标）。
2. **wm-icons 0.4.0**：31 个集合各实现语义名清单的一部分，**少一个标准名**就是那一类图标
   在整个系统里没有实现（实测 `names.lst` 84 个标准名、31 个集合、文件总数 2069，
   其中 `16x16-kde` 单集合完整实现全部 84 个名字）。
3. **iso-flags-svg 1.0.4**：索引与两套资源目录必须**双向**一致 —— 索引里每个代码都要有图，
   每张图都要能被索引找到；且两套目录各带**不同的富余条目**（非国家的组织旗帜等），
   与上游逐字一致才对。简单"由索引生成目录清单"会把富余条目删掉。
   （实测 csv 248 行、json 249 键 = csv + `EU`、两套目录 262/253 个 `.svg`。）

## 断言设计（主 / 辅）

**主断言 —— 声明 ↔ 内容一致性：**

```python
# 1) 声明 → 内容：声明的每一项都要能找到（无死链）
# 2) 内容 → 声明：所有真正含资源的叶子目录/语义名都要被声明覆盖，
#    只允许上游已知例外（pop-icon 的 512x512/places、cursors）显式白名单
# 3) 清单 ↔ 实现矩阵：所有实现集的并集覆盖全部标准名，且至少一个"完整集"实现全部名字
# 4) 双向索引核对，富余条目与上游逐字一致
```

**辅断言 —— 本体格式与体量基线：**

```python
# 逐文件校验：PNG 魔数 / /* XPM */ 头 / SVG 根元素为 svg / CUR 的 00 00 02 00 / ANI 的 RIFF…ACON
# 体量基线：各目录文件数与上游逐个一致（发现"上游 tarball 被裁剪"）
```

辅断言只能证明"文件没坏"，证明不了"能被取到" —— 所以它是辅，不是主。

## 与已有条目的边界

- `E255`（resource data package / icon theme / font package…）、`E281`（语音资源叶子包）、
  `E305`（字体资源：hash/metadata/glyph 抽样）、`E241`（清单型数据）、`E536`（固件资源）
  覆盖的是**"资源包怎么交付与校验"**这一类；
- 本条只补其中**一个具体判据**：**主断言必须是"声明↔内容一致性"（覆盖率/双向核对），
  而不是文件数或本体格式**，并给出三种损坏模式与"已知例外白名单"的写法。
