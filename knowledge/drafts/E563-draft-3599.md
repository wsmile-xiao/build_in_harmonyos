# E563 — OHOS clang15 不支持别名模板 CTAD：上游用例须显式写出模板实参

## 错误特征

```
unittests/test_iterators.cpp:180:18: fatal error: alias template 'IndexRange' requires
template arguments; argument deduction only allowed for class templates
  tf::IndexRange r(0, 10, 2);  // deduction guide -> IndexRange<int>
                 ^
taskflow/utility/iterator.hpp:971:1: note: template is declared here
using IndexRange = IndexRanges<T, 1>;
```

## 触发条件

- 构建系统: cmake（OHOS profile，clang 15.0.4，`-std=c++20`）
- 阶段: 编译期
- 写法: 别名模板指向类模板时使用 CTAD（`Alias obj(args...);` 不带模板实参）

## 根因分析

C++20 的 P1814R0「别名模板的类模板实参推导」clang 至今未实现（LLVM issue
106839；clang 15/16/17 行为一致），GCC 12+ 与 MSVC 已实现。因此同一份源码在
上游的 GCC/MSVC/AppleClang CI 上全绿，在 OHOS 的 clang 15 上直接编译失败——
这是**上游源码的可移植性缺口**，不是 OHOS 库能力缺失，也不能靠标准库或链接选项绕开。

最小复现（与 taskflow 无关，纯语言特性）：

```cpp
template <class T> struct A { A(T,T,T){} };
template <class T> using B = A<T>;
int main(){ B b(1,2,3); }   // clang: alias template 'B' requires template arguments
```

taskflow 4.1.0 命中点：

- `unittests/test_iterators.cpp` 的 `TEST_CASE("IndexRange1D.CTAD")`；
- `unittests/test_for_each.cpp` 两处 `tf::IndexRange range(beg, end, -s);` /
  `tf::IndexRange range(0, 0, 0);`。

库头文件本体没有使用该写法（只有 `taskflow/utility/iterator.hpp` 的 Doxygen 注释示例）；
别名本身 `using IndexRange = IndexRanges<T, 1>;` 推导结果唯一，显式写出实参无歧义。

## 解决方案

### 推荐方案

调用点显式写出模板实参：

```cpp
-  tf::IndexRange r(0, 10, 2);            // deduction guide -> IndexRange<int>
+  tf::IndexRange<int> r(0, 10, 2);
```

- 语义完全等价（别名固定 `IndexRanges<T,1>`，推导结果就是 `<int>`）；
- 用例数、断言数、断言内容不变，`static_assert(std::is_same_v<decltype(r),
  tf::IndexRange<int>>)` 依然成立；
- 只改测试/示例源，不改库行为，不使用平台宏（无 `__OHOS__` 条件编译）。

taskflow 实测：3 处改写后 34/34 测试可执行编译通过，`ctest` 2909/2909 通过。

### 禁止做法

- ❌ 删除或 `#if 0` 掉相关 TEST_CASE —— 直接改变分母，提审必判返工。
- ❌ 用宏或 `-fms-extensions` 之类开关“骗过”推导 —— 破坏类型身份，掩盖真实缺口。
- ❌ 把库的别名模板改成真实类模板来让 CTAD 工作 —— 会改变公开类型身份与重载解析，
  除非逐处核对 `static_assert`/concept，否则风险高于改调用点。

## 验证

```bash
printf 'template <class T> struct A { A(T,T,T){} };\ntemplate <class T> using B = A<T>;\nint main(){ B b(1,2,3); }\n' > /tmp/alias-ctad.cpp
clang++ -std=c++20 -c /tmp/alias-ctad.cpp    # 期望报 alias template 'B' requires template arguments
grep -rn 'IndexRange[^<]' unittests/         # 改写后不再有别名 CTAD 构造点
```

## 预扫描口径说明

`prescan_pattern` 命中的是**别名模板定义点**（`using X = Y<...>;`），只是线索而非结论：
真正的风险点是该别名随后被以 CTAD 形式构造（`X obj(args);` 不带模板实参），正则无法可靠识别
这种跨行语义，需人工或编译器核对。本模式的主要自动化入口是 `error_signature`——clang 的报错原文
（`alias template '...' requires template arguments; argument deduction only allowed for class templates`）
可直接由构建日志匹配命中，无需依赖预扫描。
