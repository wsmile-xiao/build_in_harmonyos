# E2026100504 — 具有设备副作用的工具应按原始源码身份隔离配置数据面

## 现象与触发特征

消费者只调用 `--help`，或者在测试里重复实现一个配置解析器，不能证明产品的功能数据流。正常入口却可能抓取输入、创建虚拟设备或启动系统守护进程，不能为了“功能测试”影响目标用户与其他任务。

## 根因

命令行程序可能没有可单独链接的公共库，但真正的配置解析函数与有副作用的 main 处于同一源文件。帮助输出、测试自身的解析函数和真实产品解析是三个不同的执行对象。

## 修复步骤

1. 阅读官方调用链，确认可独立调用的解析函数不会打开设备、发出 ioctl 或启动子进程。不能证明时不采用本方法。
2. 原样携带哈希绑定的官方实现；消费者编译时仅重命名 main 后包含它，不调用该 main，不复制或重写解析逻辑。
3. 生成合法配置文件，让真实函数实际读取、解析、构造对象；通过真实依赖 API 查询名称、身份字段和事件能力，与独立写出的预期比较，最后释放对象。
4. 同时运行已安装产品的受控帮助/非法参数入口，声明其覆盖边界。平台专项另用独立中文配置和 HMDFS 私有路径，核验文件与父目录的真实投影属主、输入哈希及清理。
