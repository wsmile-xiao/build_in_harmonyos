# E543（草稿）— Conan target profile 不能替代实际 target runner

**类别**：Conan / 测试 / 交叉编译 / OHOS
**来源**：lcab 1.0b12，PR !11486

## 错误特征

在 Linux/x86_64 runner 上把同一 OHOS/armv8 profile 同时传给 Conan 的 host 与 build：

```text
can_run(self) == true
Exec format error
Could not open '/lib/ld-musl-aarch64.so.1'
```

`can_run()` 依赖 Conan settings 判断；它不知道当前 CPU 实际是 x86_64。因此 settings 相同不等于生成的 AArch64 ELF 能由构建机执行。

## 触发条件

- 构建系统：任意使用 Conan 2 `test_package` 的命令行工具或消费者测试。
- 目标：OHOS / armv8（AArch64）。
- runner：Linux/x86_64，且传入相同的 OHOS/armv8 host、build profile。
- `test()` 直接启动已安装的 target 二进制。

## 根因分析

Conan 看到 host/build settings 相同，`can_run()` 返回 true；但本地 clang 产生的是 AArch64 musl ELF，而 x86_64 内核无法启动它。若 `test()` 仅据 `can_run()` 运行，失败表现为 `Exec format error` 或因没有 target musl loader 而失败。

另一种错误修复是无条件跳过 `test()`。这会让功能测试没有运行证据；在本项目的 L1e 破坏性反向测试中，若跳过前也没有读取安装产物，移走包的 `bin/` 后测试仍会成功，进而被识别为空壳测试。

## 推荐方案

1. **优先**在 AArch64 OHOS runner 运行 `test_package`。
2. x86 runner 上配置 `qemu-aarch64` 和包含 `lib/ld-musl-aarch64.so.1` 的 `QEMU_LD_PREFIX`，通过 QEMU 运行安装后的真实二进制。
3. 若当前 CI 不能提供 QEMU：
   - 在非 AArch64 分支返回前，先断言 `self.dependencies["<package>"].package_folder/bin/<tool>` 存在；
   - 将该跳过明确记为**未在本 runner 执行功能测试**；
   - 另以 QEMU 或 AArch64 runner 运行同一功能脚本，并记录场景与断言数。

示意：

```python
binary = os.path.join(self.dependencies["<package>"].package_folder, "bin", "<tool>")
if not os.path.isfile(binary):
    raise RuntimeError("package binary is missing")

if platform.machine().lower() not in ("aarch64", "arm64"):
    # 仅在没有可用 QEMU 时使用；真实功能测试必须另行取证。
    return
self.run("<tool> <functional-args>", env="conanrun")
```

更佳方案是在前述分支调用 QEMU，而不是返回。

## 禁止做法

- 仅以 `can_run(self)` 的结果推断 CPU/ABI 兼容。
- 无条件跳过 target 功能测试后仍申报其为通过。
- 在跳过前不触及 `self.dependencies` 的安装产物，导致 L1e 无法识别空壳测试。

## 验证

```bash
# AArch64 目标 runner：直接执行 consumer test
conan create archives/l/lcab/1.0b12 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64

# x86 runner：配置 OHOS musl fakeroot 后通过 QEMU 执行安装工具
QEMU_LD_PREFIX=<ohos-fakeroot> \
qemu-aarch64 -L "$QEMU_LD_PREFIX" <package_folder>/bin/lcab -h
```

lcab 1.0b12 的独立 QEMU 功能测试覆盖帮助/版本、单文件 CAB、多文件 CAB、递归目录和缺失输入处理，共 **5 个场景、13 个断言**通过；W3 的 L1e 反向测试也确认测试依赖安装后的 `bin/lcab`。
