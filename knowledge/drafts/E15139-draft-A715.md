# E15139 — PRE_TEST 不会延迟独立的 POST_BUILD 程序

## 适配场景和根因

同一 CMake 工程可同时包含 GoogleTest 兼容的测试发现和独立 add_custom_command(TARGET ... POST_BUILD COMMAND ...)。
CMAKE_GTEST_DISCOVER_TESTS_DISCOVERY_MODE=PRE_TEST 只改变 gtest_discover_tests 的发现时机，不会让任意构建期程序停止执行。因此仅在 CTest 前补运行库路径、签名或执行能力，对更早的 POST_BUILD 阶段无效。

## 可复用决策步骤

1. 分别盘点测试发现入口和独立构建期命令，不能从 PRE_TEST 推导“构建期不执行 ELF”。
2. 原生构建中，POST_BUILD 若依赖当前构建产物，应在 cmake.build() 周围提供计算得出的构建树运行库路径。VirtualRunEnv 不自动包含尚未打包的本项目库。
3. 构建期执行仍受平台许可和签名规则限制，不能关闭签名。构建完成后对测试 ELF 使用平台工具签名，保留可执行模式。
4. 再延迟发现，保存真实清单，要求非空、无重复、无禁用，完整执行。数量变化必须检查配置和清单，不能写死旧版本计数。

Environment 只包围任务构建或测试，不修改全局环境，不把缓存路径写入安装产物。

## 查重与实质增量

E332 已记录上游 standalone runner，restclient-cpp 草稿已提到 PRE_TEST。它们不区分测试发现与独立 POST_BUILD 程序的执行要求。本条新增阶段边界、构建树提供者必须先于构建执行的顺序和完整动态发现验证；不只是重复 standalone 开关或版本升级。

## 适用和安全边界

适用于原生 CMake 混合延迟测试发现与构建期执行的项目。交叉编译需要上游宿主工具拆分或真实可用 emulator，不能用 host/build profile 相同伪装目标可执行。无独立构建期命令的项目无需加该层环境。正式编号由主编审核分配。
