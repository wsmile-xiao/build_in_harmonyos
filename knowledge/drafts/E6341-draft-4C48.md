# E6341 — HMDFS 上生成式 Autotools 的稳定构建方法

> 状态：draft，仅作为路径 B / B 类知识库扩展候选材料提交评审。

## 错误特征

典型失败点包括：

```text
config.status: error: could not setup config files machinery
./confXXXX/subs1.awk: Permission denied
Read-only file system: /tmp/...
Permission denied: ./configure
mkfifo: Permission denied
```

这类错误往往发生在 configure 或 make 的早期，源码还没有开始大规模编译。
同一配方在普通 Linux ext4 上可能完全正常，放到 HarmonyOS PC 的 HMDFS
Conan cache 后才出现。

## 触发条件

- 构建系统：Autoconf/Automake。
- 构建位置：Conan cache、源码目录或 build 目录位于 HMDFS。
- 源码形态：发布包自带 `configure`、`Makefile.in`、`aclocal.m4` 等生成文件，
  但 `configure.ac` 或 `Makefile.am` 又会触发自动重生成。
- 设备差异：`/tmp` 只读、脚本直接 exec 受限、0700 临时目录权限投影不同、
  make jobserver FIFO 不稳定。

## 根因分析

这里有四个容易混在一起的变量：

1. **执行入口**：HMDFS 上的脚本或缓存 ELF 可能不能直接 `execve`，但用
   `/data/service/hnp/bin/bash` 解释执行可行。
2. **临时目录**：Autoconf 会使用 `TMPDIR` 和内部 `mktemp`。设备的 `/tmp`
   可能是只读 erofs，不能当作默认临时目录。
3. **临时目录权限**：生成的 configure 可能使用 `umask 077` 创建 0700 目录，
   HMDFS 的 owner/group 映射会让后续 `subs1.awk` 无法访问。
4. **生成文件重建**：如果 `configure.ac` 比 `configure` 更新，make 会尝试
   调用 Autoconf/Automake；而缓存里的这些脚本可能不可直接执行，或者生成结果
   因 host 工具版本漂移而不稳定。

因此仅设置 `TMPDIR` 或仅把 `./configure` 改成 `sh configure` 都可能不够。

## 推荐解决方案

对于源码归档已经包含完整生成文件的老项目，优先采用“使用已生成文件、禁止
重新生成”的闭环：

1. 在 Conan `build()` 中创建 build-local `tmp`，将 `TMPDIR`、`TMP` 和
   `TEMP` 指向它。
2. 设置 `CONFIG_SHELL` 和 `SHELL` 为设备上的 native bash，并用
   `sh <configure>` 或 native shell 显式调用 configure。
3. 只对构建目录内的 configure 副本把 `umask 077` 调整为 `umask 022`；
   不把临时设备权限 workaround 扩散为公共基础设施改动。
4. 将 `configure.ac`/`Makefile.am` 的时间戳置于 `configure`/`Makefile.in`
   之前，或用 `ACLOCAL=:`、`AUTOMAKE=:`、`AUTOCONF=:`、
   `AUTOHEADER=:`、`AUTOM4TE=:` 阻止构建期重生成。
5. 对旧小型构建树使用 `make -j1`，避免 HMDFS 上的 jobserver FIFO 限制。
6. 安装阶段同样透传 shell 和 generator 禁用变量，确保 `make install` 不会
   重新触发生成。

ext2fuse 的最终配方采用了这套方法，并在 OHOS armv8 Shadow CI 中完成
configure、编译、安装和消费者测试。

## 何时不能使用本方案

如果源码包没有可信的 `configure`/`Makefile.in`，或者补丁改变了必须重新生成
的 Automake 规则，就不能简单禁用 autoreconf。此时应将构建树放在可执行且可写
的 native/tmpfs 路径，使用目标环境工具链重新生成，并把生成结果纳入可审计的
补丁或源码流程。

## 禁止做法

- ❌ 在目标设备上无条件运行 `autoreconf --install --verbose`，忽略源码包已经
  自带生成文件的事实。
- ❌ 把 `TMPDIR` 继续指向 `/tmp`，然后把只读错误误判为依赖缺失。
- ❌ 只把 `umask 077` 改为更宽权限，却不验证目录真实可写和脚本可访问。
- ❌ 依赖并行 make 作为默认验证，导致 jobserver/FIFO 错误掩盖真实编译结果。
- ❌ 把 HMDFS workaround 写入公共 `scripts/` 或 `ci/` 目录来解决单库问题。

## 验证

```bash
mkdir -p "$BUILD_DIR/tmp"
TMPDIR="$BUILD_DIR/tmp" CONFIG_SHELL=/data/service/hnp/bin/bash \
  sh "$SOURCE_DIR/configure" \
  --build=aarch64-unknown-linux-ohos \
  --host=aarch64-unknown-linux-ohos
make -j1
make install DESTDIR="$PACKAGE_DIR"
```

验证还应检查生成器没有被意外调用，并确认安装树中只有目标包文件。ext2fuse
本轮经历两次补丁阶段失败后，最终 run 在设备全局锁等待为 0 秒的情况下完成，
runner 返回码 `0`。

## 适用范围和边界

本条适用于在 HarmonyOS PC/HMDFS 上构建老式 Autotools C/C++ 项目。它不替代
源码缺失、工具链缺失或真正的权限授权问题诊断；如果最终失败位于 `/dev/fuse`
等设备能力，应转入运行时能力条目。

## 与相似条目的区别

E011、E114 和 E129 主要描述 HMDFS 上 0700 临时目录或 `umask 077` 的单点
权限现象；E223 强调敏感临时目录的 owner、mode、MAC 和真实写入闭环。本条
在这些基础经验之上，抽象出老 Autotools 包在 OHOS worker 中的组合式构建
策略：生成文件生命周期、native shell、build-local TMPDIR、umask、生成器
禁用和 jobserver 并行度必须一起设计。它不替代已有的临时目录条目，而是用于
判断何时应采用“使用可信 shipped generated files”的完整配方模式。
