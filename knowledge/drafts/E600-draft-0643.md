# E600 — OpenLDAP 2.6 头文件隐藏旧版 LDAP API

## 错误特征
```
ldap2dns.c:802:14: error: call to undeclared function 'ldap_init'
ldap2dns.c:802:12: error: incompatible integer to pointer conversion assigning to 'LDAP *' from 'int'
```
以及 `ldap_simple_bind_s` / `ldap_search_s` / `ldap_search_st` 等同报
"call to undeclared function"。旧源码（2000 年代初）还可能伴随
`unknown type name 'time_t'`。

## 触发条件
- 构建系统: makefile / autotools
- 阶段: compilation
- 环境: OpenLDAP 2.6+（含 conan openldap/2.6.7），musl / OHOS sysroot

## 根因分析
OpenLDAP 2.6 把旧版 API 的声明放在 `#if LDAP_DEPRECATED` 守卫内；默认未定义
`LDAP_DEPRECATED` 时 `#if LDAP_DEPRECATED` 求值为 0，声明被整体隐藏。但符号
仍在 `libldap.so` 中导出（可用 `nm -D libldap.so` 验证），因此只需在编译期
恢复声明即可，无需改库。

另：`time_t` 未定义是因为源码漏 `#include <time.h>`——旧代码在 glibc 下靠
头文件传递包含侥幸通过，musl/OHOS sysroot 不包含，必须显式补头文件。

## 解决方案

### 推荐方案
1. CFLAGS 增加 `-DLDAP_DEPRECATED=1`，恢复旧版 LDAP API 声明：
   ```bash
   make INC="-I$P/include -DLDAP_DEPRECATED=1"
   ```
2. 对 `time_t` 报错，在源文件补 `#include <time.h>`。

### 禁止做法
- ❌ 误以为需要换新 API 而大改源码（符号已在库中，声明宏即可解决）
- ❌ 用 `-Wno-implicit-function-declaration` 掩盖（会得到隐式 int 返回的畸形 ABI）

## 验证
```bash
nm -D /path/to/libldap.so | grep -E 'T ldap_init|T ldap_simple_bind_s'
grep -n "LDAP_DEPRECATED" /path/to/include/ldap.h   # 确认声明被宏守卫
```
