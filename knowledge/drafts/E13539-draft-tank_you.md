# E13539 — 分块 EXIF 扫描的标记状态与流错误状态

## 问题现象

metacam 1.2 原版在鸿蒙 PC AArch64 上可以编译，读取 TIFF 正常；当 JPEG 的
EXIF 标记位于第二个 1024 字节缓冲区时，程序仍返回 0，却输出
`No EXIF/TIFF data found`，没有预期的 `Canon` 字段。只测编译、帮助信息
或退出码会漏报。

## 根因

扫描器在进入循环前把 `found_exif` 错设为 `true`，首块未命中也提前结束。
另一独立问题是短文件的末次 `istream::read` 同时设置 `eofbit` 和
`failbit`，旧代码只清除 `eofbit`，导致后续 `seekg` 无法访问 TIFF 结构。

## 修复和验证

1. 初始状态设为“未找到”，仅在匹配完整标记后置为“找到”，保留跨缓冲区匹配。
2. 在可恢复的 EOF 扫描结束后、随机访问前清除流状态；真实 I/O 错误仍应独立处理。
3. 使用已安装的 Conan 包中的可执行程序，分别测试短 TIFF、延后 EXIF、
   短 JPEG 和缓冲区边界拆分的 EXIF，检查字段内容与退出码。
4. 原版在延后 EXIF 用例失败；修复后，真机 `conan create` 和
   `test_package` 返回 0，1 个消费者场景中的 11 项断言通过。

## 适用边界

该经验适用于固定大小读取、搜索标记后再 `seekg` 的旧 C++ 解析器。它不证明
JPEG 规范完整性、所有厂家私有字段或所有 I/O 错误路径。上游没有自动测试时，
上游通过率应写“不适用（0/0）”，不能由新增消费者测试倒推出 100%。
