# E14723 — 包内 XML 配置、启用模板与应用缓存分别绑定

## 触发特征

组件已经编译/链接成功，但运行时报告 `Cannot load default config file`；目标系统缺少构建系统默认的 /etc 配置或 /usr/share 资源。配置还引用启用模板链接，且运行时需要可写缓存。此模式不限于某个字体库，也适用于依靠外部 XML/include 与缓存的图形和媒体组件。

## 根因

生产者 ABI、只读配置树与消费者可写状态是三个不同契约。库链接通过不证明配置存在。直接固定系统配置路径不适用于移动安装根；启用链接指向全局模板目录也会失效。将缓存位置设为 Conan package_folder 则混淆只读共享资源与应用状态。

## 修复步骤

1. 使用安装后的实际 XML；校验根节点和唯一相对 include，不遇到任何路径就无条件替换，也不丢弃上游别名/匹配规则。
2. 对启用目录逐个校验链接名称及对应包内普通模板文件。整组校验成功后，仅实体化已启用配置，不能启用所有 conf.avail 中相互排斥的规则。
3. 按目标真实资源位置设置目录；不要在测试中修改系统字体、全局 /etc 或其他任务资源。
4. 从消费时的当前 package_folder 导出配置文件/目录。包根迁移后必须重新绑定；不要把构建机路径或历史安装根固化为运行时路径。
5. 保持 XDG 相对缓存策略，由应用或测试提供自己可写的 XDG_CACHE_HOME。不得由生产者将其设为共享包目录。
6. 消费者使用显式配置加载入口并启用错误检查；分别测试实际配置加载、资源枚举、匹配结果可打开，以及缺失/非法 XML 拒绝。
