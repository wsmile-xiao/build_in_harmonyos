# autoconf 2.13 生成的 configure 把命令行 `VAR=value` 判为 host 三元组并拒绝——老 autotools 包传旗标必须改走环境变量通道

- 条目 id：`DRAFT-SNTOP-143-AUTOCONF213-REJECTS-CMDLINE-VAR-ARGS`
- 来源：sntop 1.4.3 适配 HarmonyOS PC（鸿蒙 B 机一手真机探针）
- 引用方式：**按文件名引用**，不要按 E 编号引用（drafts 里 E 编号存在复用）。

---

## 一、错误特征

一手出处：`archives/s/sntop/1.4.3/reports/p1-arm-cmdline.log`（该文件第 4、6、7 行；
第 5 行夹着一行与本机制无关的 `job-working-directory: error retrieving current
directory` 噪声，是探针在已删除的 cwd 里起 shell 造成的，**不是**故障链的一部分）。
三行原文：

```
configure: warning: CC=/data/service/hnp/bin/clang: invalid host type
configure: warning: CFLAGS=-DM12_CMD_MARKER: invalid host type
configure: error: can only configure for one host and one target at a time
```

伴随现象（比签名更能定性）：

- 退出码 `rc=1`；
- **没有产出 `Makefile`**（也没有可用的 `config.status` 替换结果）——所以症状不是
  "旗标没生效"，而是"配置阶段直接不干了"；
- 报错措辞与"未知选项"（`unrecognized option`）完全不同，因此极易被误读成
  "交叉编译参数写错了"或"host triple 拼错"，进而去改 `--host=` 的值——方向就偏了。

## 二、触发条件

**主判据（先看这个）**：`configure` 头部写的是 2.13 世代的措辞。实拍第 1-6 行
（`archives/s/sntop/1.4.3/reports/knowledge-candidate-ledger.md` 第 20-30 行）：

```
#! /bin/sh

# Guess values for system-dependent variables and create Makefiles.
# Generated automatically using autoconf version 2.13
# Copyright (C) 1992, 93, 94, 95, 96 Free Software Foundation, Inc.
```

- `# Generated automatically using autoconf version 2.13` ⇒ 命中本条。
- 现代措辞 `# Generated by GNU Autoconf 2.69`（≥2.5x/2.6x）⇒ **不命中**，那里
  命令行 `VAR=value` 与环境变量两条通道都可用。

**次判据（排除手写脚本）**：`--prefix` 一类目录选项由 autoconf 标准的
`for ac_option … case` 块处理，脚本里**不存在** `case "$optarg" in CXX=*)` 形态的
自解析分支 ⇒ 它是 autoconf 生成物、不是手写自解析 configure。

**触发动作**：把 `VAR=value` 作为**位置参数**送给这个世代的 `configure`。在 conan 2
配方里最常见的引入方式就是 `tc.configure_args.append("LDFLAGS=…")` /
`"LIBS=-ldl"` 这类仓内惯用写法（对照同族先例 `archives/a/alpine/2.26/conanfile.py`）。
一条 `VAR=value` 只会留下一行 `invalid host type` 警告；**两条**才会触发
`can only configure for one host and one target at a time` 的 error 退出。

## 三、根因分析

autoconf 2.13 生成的 `configure` 的参数循环只有两类认知：

1. 以 `-` 开头的选项走 `--prefix` / `--with-*` 等标准分支；
2. 不以 `-` 开头的位置参数**一律**当作 host / target / build 三元组候选去做
   `cpu-vendor-os` 形态的拆分与识别。

它**没有**"命令行 `VAR=value` 覆盖同名变量"这条现代路径。于是 `CC=…`、`CFLAGS=…`
被当成两个三元组去解析：识别失败 ⇒ 各打一条 `invalid host type` 警告；而这两个
位置参数分别被登记进了 host 与 target 两个槽位 ⇒ 随后的自洽性检查发现
"host 和 target 同时被指定"，直接 `configure: error` 终止。

同名变量的**环境变量**通道在这个世代是完好的：脚本按 `${CC-…}` 这类标准取法读环境，
所以 `env CC=… CFLAGS=… ./configure` 会正常采纳。

⇒ 本条的根因不是"鸿蒙 / 工具链 / musl 的行为差异"，而是**该世代 autoconf 的
参数协议本身**。它只在把新世代写法照搬到老生成物上时暴露。

## 四、解决方案

**执行顺序是这套解法的一部分，不要颠倒**：

1. **先读 `configure` 头部判 autoconf 与否、判世代**（第二节主判据）。
2. **再做两臂 A/B 探针定通道**（第五节命令），用实测退出码而非版本号猜测决定
   `VAR=value` 走命令行还是走环境变量。
3. **2.13 世代 ⇒ 旗标全部改走环境变量通道**：在 conan 2 的 `generate()` 里用
   `Environment()` define `CC` / `CPPFLAGS` / `LDFLAGS` / `LIBS`（编译器路径取自
   `tools.build:compiler_executables`，R33），`tc.configure_args` 里**只留目录类选项**。
4. **如果环境变量臂生效、旗标却仍然进不了编译命令** ⇒ 那是**另一条机制**：
   上游 `Makefile.in` 重写了 `CFLAGS` 且不引用 `@CFLAGS@`/`@LDFLAGS@` 占位符，
   configure 探到的值只活在 `config.status` 的替换表里。此时的解法是借上游编译规则
   里已存在的钩子（如 `$(CC) -I$(INCLUDE) …` 用 `make INCLUDE=<dep>/include` 注入），
   或者补占位符补丁——**不要用本条去解释那个症状**，两条机制的签名、根因、解法都不同。

**命令行臂 ⇒ 应复现故障**


stdout/stderr 即第一节那三行。

**签名自测口径**：`.kv` 里 `error_signature` 各分支之间是 **OR（任一命中即命中）**，
不要求各分支在同一条物理行内同时出现。单看第一支（`invalid host type`）**不具区分度**
——本条未实测其它 autoconf 世代是否也报同一措辞，因此判适用性时以"configure 头部
版本行"为主判据、签名为辅判据。自测用真件回放：

```sh
python3 - <<'PY'
import re,io
sig=r"configure: warning: [A-Za-z_]+=[^:]+: invalid host type|configure: error: can only configure for one host and one target at a time"
t=io.open("archives/s/sntop/1.4.3/reports/p1-arm-cmdline.log",encoding="utf-8",errors="replace").read()
print("hits=",len(re.findall(sig,t)))
PY
```

实拍 `hits=3`（第一支 2 次、第二支 1 次）。

## 六、禁止做法

- ⛔ **把它当成池内 M12 同一个配方照抄**。
  `DRAFT-PKG-VER-custom-configure-only-cli-args-no-env.{kv,md}` 讲的是
  "**只认命令行 `var=value`、忽略环境变量**"（手写自解析脚本），其 `.kv:27-28`
  自述"**不适用**于 autoconf 生成的 configure：那类脚本按标准读取同名环境变量"，
  `.kv:30` 的判据是"autoconf 产物含 `# Generated by GNU Autoconf`、手写产物没有"。
  本条是**同一失效面（非标准参数协议的 configure）的相反方向**：
  命令行被拒、环境变量有效。两条各管一头，用 `similar_to` 互相指认。
- ⛔ **给上游 `configure` 打补丁"修"老 autoconf**。这类包上游往往**不发布**
  `configure.ac`（sntop 即如此），改了既无法 `autoreconf` 再生、又要在每次升版重对位，
  净亏。换通道是零补丁的。
- ⛔ **靠关测试 / `--disable-*` / 缩减分母凑绿**。本条只解决"旗标从哪进去"，
  与功能验收无关。
- ⛔ **在确认是 autoconf 产物之后还去试命令行 `VAR=value`**。判据没读之前就试，
  会把 `invalid host type` 误报成"工具链不接受这个编译器"，进而怀疑 profile。
- ⛔ 把 `--build/--host/--target` 也一起改成环境变量——目录/三元组类选项仍走命令行，
  被拒的是**不带 `-` 前缀的 `VAR=value` 位置参数**。
