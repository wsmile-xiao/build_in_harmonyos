# E639 — spdlog 包把 `include/spdlog` 列为 include 路径，使 `<fmt/ranges.h>` 命中 spdlog 自带 shim，真 fmt 头被 `#pragma once` 吞掉，`fmt::join` 未声明

- **来源**: j4-dmenu 3.2 HarmonyOS PC 适配（`conan create` 编译期）
- **状态**: draft（待审，勿自行 promote）
- **关联**: 与「fmt 跨大版本 API 变更」是**同征兆不同根因**——本例 fmt 头根本没被解析过；与 E216（CMakeDeps 传递依赖链）同属"依赖暴露面接线"邻域

## 1. 现象

编译 `src/main.cc` 时，明明是标准 fmt 用法却报符号缺失：

```text
error: no member named 'join' in namespace 'fmt'
    error: no matching function for call to 'join'
```

`fmt::join` 是 fmt 的稳定 API，且工程用的 fmt 版本本身**支持**它。
此时最容易被引向"版本漂移"的误诊：上游钉 fmt 10.2.0、实际用 fmt 12.2.0，
于是把报错归因于跨版本 API 变化——**方向错了**。

## 2. 根因

路径遮蔽（header shadowing），两个条件叠加即触发：

1. **spdlog 把自己的 include 根暴露过深**：ohpcd 的 spdlog 制品
   `cpp_info.includedirs` 同时包含 `include` 和 `include/spdlog`，
   于是编译命令里出现

   ```text
   -isystem <spdlog包目录>/include/spdlog
   ```

2. **spdlog 自带同名 fmt 转发 shim**：spdlog 为摆脱外部 fmt 依赖，
   在 `include/spdlog/fmt/` 下放置了一套与 fmt 头同构的 shim
   （如 `spdlog/fmt/ranges.h`）。

两者相遇后，`#include <fmt/ranges.h>` 在搜索 `<spdlog包目录>/include/spdlog`
时**先命中** spdlog 的 shim。该 shim 自身带 `#pragma once` 且不转发到真正的
fmt 头——于是"包含过了"这个判定成立，真正的 `fmt/ranges.h` **从未被解析**，
`fmt::join` 等仅由真 fmt 头声明的符号全部缺失。

所以这不是 fmt 版本问题，也不是代码问题：**真 fmt 头一次都没进来过**。

## 3. 修法（收窄依赖的 include 面）

在配方 `generate()` 中把 spdlog 的 `includedirs` 覆盖为仅 `include/`：

```python
def generate(self):
    spdlog_cpp_info = self.dependencies["spdlog"].cpp_info
    spdlog_cpp_info.includedirs = [
        os.path.join(self.dependencies["spdlog"].package_folder, "include")
    ]
    ...
```

要点：

- 保留 `include/` 后 spdlog 自身的头（`<spdlog/spdlog.h>`）依旧可用，
  只是去掉了 `include/spdlog` 这层多余的搜索根；
- 去掉后 `<fmt/...>` 一律解析到 fmt 包，遮蔽消失；
- 改动**零源码补丁**，只在配方里接线。

### 禁止做法

- ❌ 用宏把 spdlog 切到 bundled-fmt 分支（`SPDLOG_FMT_EXTERNAL=0` /
  `SPDLOG_USE_STD_FORMAT`）——工程本身仍需要真 fmt 头，切分支解决不了
  `<fmt/ranges.h>` 被遮蔽，还会引入 spdlog 与 fmt 两套 fmt 定义共存的 ODR 风险；
- ❌ 顺着"版本漂移"的误诊去降级 fmt 到上游钉定的版本——根因是路径遮蔽，
  降版本可能恰好让 shim 分支不再被走到而"看起来好了"，掩盖真实接线缺陷。

## 4. 验证证据（j4-dmenu 3.2 实测）

覆盖 `includedirs` 后同一份配方编译通过并全绿：

```text
100% tests passed, 0 tests failed out of 79
Total Test time (real) =   1.00 sec
```

- `fmt::join` 报错消失，上游 79 个用例中 **73 个执行并通过、0 失败**
  （6 个因本机 `/tmp` 只读被上游 `SKIP()` 守卫跳过）；
- 未改任何上游源码，fmt 仍为制品仓版本 12.2.0（**没有**回退到 10.2.0）。

## 5. 适用面与边界

- **适用**: 同时使用 spdlog 与 `#include <fmt/...>` 的 C++ 工程，且 spdlog
  制品的 `includedirs` 含 `include/spdlog` 这一层；纯编译期问题，与动静态链接无关。
- **不适用**: spdlog 制品只暴露 `include/`（无多余根）时不触发；
  工程不直接用 fmt 头（仅经 spdlog 间接使用）时也不受影响。
- **识别方法**: 编译命令中 `-isystem .../spdlog/include/spdlog` 有命中即可疑，
  再 `grep -n 'pragma once' <spdlog包>/include/spdlog/fmt/ranges.h` 确认 shim
  自包含（不含指向外部 fmt 的 include）即坐实。三件套：报错符号属真 fmt +
  include 路径含 `spdlog/include/spdlog` + shim 带自包含守卫。
- **一般化**: 任何依赖把"会与第三方同名头目录重名"的目录塞进 include 根，
  都会命中同族遮蔽；收窄 `includedirs` 是通用修法。
