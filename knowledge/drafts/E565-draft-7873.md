# E565 — release tarball 子模块为空时，先判定测试入口是否真引用子模块（草稿）

- **来源**：simde 0.8.4-rc3 OHOS 适配（`archives/s/simde/0.8.4-rc3`）
- **日期**：2026-09-10
- **对照证据**：同一上游项目的 `archives/s/simde/0.8.2`（旧归档按 E150 补了 munit 子模块并只抽样 7 组）
- **关联**：`caused_by: E150`；`similar_to: E363`（假绿型测试基础设施问题）

## 现象

从 GitHub/Gitee 官方 release tarball 取源码时，`test/<framework>/` 之类的子模块目录
**存在但为空**（tarball 只带 `.gitmodules`）。第一反应是"测试框架缺失 → 套件跑不了"，
于是按知识条目 E150 的推荐方案 manual-download 子模块源码补进去，并把上游测试降级为
抽样运行。

## 根因

"子模块目录为空"只是**文件系统事实**，不是**依赖事实**。构建系统的测试注册可能给
每个入口注入 standalone/bare 宏，使入口编译时根本不 include 子模块头；子模块只被
另一条**未被本任务使用**的入口（聚合 runner）引用。此时：

1. 补子模块是不必要的（浪费且引入仓库外源码）；
2. 更严重的是**把可全量运行的套件错报成抽样通过**——测试面被自己缩小，
   而上游测试计数是审方必查项。

## simde 的同项目 A/B 实证

| 项目 | 归档记录 | 上游 | 实测 |
|---|---|---|---|
| simde | `0.8.2`（先例） | v0.8.2 | 归档记为"meson 测试依赖 munit 子模块，官方 tarball 不含，已从 munit master 补充后编译运行"，仅**抽样 7 组** |
| simde | `0.8.4-rc3`（本任务） | v0.8.4-rc3 | **未补任何子模块**，全量 `meson test` **2014/2014 注册入口通过**（TAP 断言 32710 ok / 0 not ok） |

注册级核对结果（v0.8.2 与 v0.8.4-rc3 均成立）：

- `test/meson.build` → `subdir('common')`/`('x86')`/`('arm')`/`('wasm')`/`('mips')`；
  每个真实注册文件（`test/common`、`test/x86`、`test/x86/avx512`、`test/arm/neon`、
  `test/arm/sve`、`test/wasm/simd128`、`test/wasm/relaxed-simd`、`test/mips/msa`）
  的 `executable()` 均传入 `extra_flags`，而 `extra_flags` **恒含** `-DSIMDE_TEST_BARE`；
- `test/test.h` 是**测试入口侧**唯一 `#include "munit/munit.h"` 的位置，且该 include 只在
  **非** `SIMDE_TEST_BARE` 分支内（v0.8.4-rc3：`L1195 #if defined(SIMDE_TEST_BARE)` /
  `L1200 #else` / `L1206 #include "munit/munit.h"`；第 1192–1194 行注释原文：
  "The bare version basically assumes you just want to run a single test suite.
  It doesn't use munit, or any other dependencies"）。另有 **12 个 `run-tests*.h`**
  （`test/x86`、`test/arm/neon`、`test/arm/sve`、`test/wasm/simd128`、
  `test/wasm/relaxed-simd`、`test/mips/msa`、`test/x86/avx512` 各 1–2 个）以
  `"../../munit/munit.h"` / `"../munit/munit.h"` 相对路径 include 同一头，
  但它们只被同目录的 `run-tests.c` 层级引用，属于下面的"聚合 runner"形态；
- munit 的**引用面全部落在"非 bare / 聚合 runner"形态上**，具体为：
  **11 个 `run-tests.c`**（`test/` 及各 ISA 子目录）+ 其 `run-tests*.h` 包含头 +
  **8 个 `test-*-footer.h`**；后者以 `#if defined(SIMDE_TEST_BARE)` 分叉——
  **bare 分支**直接生成打印 TAP 的 `main()`，**`#else` 分支**才生成 `MunitSuite`；
- `v0.8.4-rc3` 已**没有** `test/CMakeLists.txt`（根 `CMakeLists.txt` 只有
  `add_subdirectory(test/cmake-packaging)`），即该聚合 runner 在本版本**没有任何
  构建系统会去编译它**；`v0.8.2` 则仍有 `test/CMakeLists.txt`（故 0.8.2 的 CMake
  测试路径确实存在，但其 meson 路径与 rc3 同构，同样不引用 munit）。

结论：子模块对 meson 测试路径**不可达**；E150 的处置在本项目的 meson 路径上属误用。

## 推荐方案

**先做注册级依赖判定，再决定是否补子模块**：

```sh
# 1) 每个注册文件用了哪些宏、注册了几个入口
for f in $(find <src>/test -name meson.build); do
  printf "%-34s bare=%s exe=%s\n" "$f" "$(grep -c 'TEST_BARE' "$f")" "$(grep -c 'executable(' "$f")"
done

# 2) 子模块头到底出现在哪些分支（bare 分支内 = 不可达）
grep -n -B3 -A3 'munit/munit.h' <src>/test/test.h

# 3) 子模块是否被消费方注册路径引用
grep -rn 'submodule_header_name' <src>/test/ | grep -v '^.*test\.h:.*BARE'
```

判据：**全部注册路径都注入 bare 宏、且子模块头只出现在非 bare 分支** → 子模块对
测试路径不可达 → 不补子模块，直接全量运行套件。

### 回退方案（确认确有引用时才用）

若某个注册入口确实引用子模块头，或聚合 runner 是唯一测试入口，则按 E150 拉取子模块
源码到**任务私有副本**继续；子模块只能用于测试期，不得进入 `conandata.yml` 的
`sources`/`sha256` 校验链或制品内容。

### 禁止做法

- ❌ 未做注册级判定就 manual-download 子模块，并把上游套件降级为抽样；
- ❌ 把子模块写入包 `sources`/`sha256`（破坏源码锚定与制品可复现性）。

## 验证

```bash
# meson 注册入口数与 bare 宏覆盖率（simde 0.8.4-rc3 实测）
meson setup build -Dtests=true
meson test -C build --list | wc -l          # -> 2014
ninja -C build                              # -> 4532/4532 目标，RC=0
meson test -C build --print-errorlogs --num-processes 2
# -> Ok: 2014   Fail: 0   （TAP: 32710 ok / 0 not ok；全程未补 test/munit/）
```
