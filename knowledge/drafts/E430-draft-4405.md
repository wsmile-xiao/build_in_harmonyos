# E430 — staged install 两类陷阱：安装目标 rc 失真 + 私有权限检查与文件系统权限归一化冲突

> 类型：知识库草稿（draft） ｜ 类别：`installation, platform`（hmdfs / autotools）
> 来源：dcc-extras 2.3.169（OHOS/HarmonyOS PC；上游 DCC 以 `/var/dcc` 为安装终点，含 0600 私有文件）

---

## 1. 使用说明（怎么用这条知识）

适用者：给"以**系统目录**为安装终点"的上游工程（服务/守护进程/邮件过滤类）做 Conan 打包，出现
`make install` 结果与预期不符（要么"显示成功实则失败"，要么"某步骤恒定失败"）的场景。

**两步排查流程**

**第 1 步：先验 rc 真实性（顶层 make install 的 rc 可能是假的）**
```bash
# 反例形态：顶层 rc=0，但日志里有子目录失败
$ make install > install.log 2>&1; echo $?
0
$ grep -nE 'make\[[0-9]+\]: \*\*\* \[.*\].*Error' install.log
make[1]: *** [Makefile:31: install] Error 69      # ← 真实失败被 for 循环掩盖
```
判定：若顶层 `install` 目标是用 **shell `for D in $(SUBDIR); do (cd $D; make install); done`**
递归子目录（autotools/GNU make 常见写法），则**只有最后一个子目录的退出码决定顶层 rc**。
→ 正确做法：改**逐目录安装**，让失败显性化：
```bash
for d in <各组件目录>; do make -C "$d" install || echo "FAILED: $d"; done
```
⚠️ 不要用 `make install SUBDIR="…"` 覆盖变量：命令行变量会经 MAKEFLAGS 透传给子 make，
而子 make 可能自带 `SUBDIR` 递归 → 递归无限展开（实测 10 分钟不返回）。

**第 2 步：若真实失败发生在"生成状态文件/密钥文件"的步骤，先做文件系统权限探针**
```bash
$ python3 - <<'PY'
import os
for d in ("<目标文件系统>", "/dev/shm"):
    p = os.path.join(d, "perm-probe.bin")
    try:
        fd = os.open(p, os.O_CREAT|os.O_EXCL|os.O_RDWR, 0o600); os.close(fd)
        print(d, "created:", oct(os.stat(p).st_mode & 0o777)); os.remove(p)
    except Exception as e:
        print(d, "ERR", e)
PY
/storage/.../tmp: created: 0o660 after-chmod(600)=0o660     # HMDFS：0660，chmod 无效
/dev/shm:         created: 0o600                            # 保留 0600
```
判定：程序若对输出文件做"必须私有"检查（典型：`st_mode & (S_IRGRP|S_IWGRP|S_IWOTH|S_IXOTH) != 0 → 拒绝`），
在**权限被归一化**的文件系统（HMDFS/tmpfs，典型 `0660` 且 `chmod` 无效）上**必然失败**——
这是文件系统特性，不是源码缺陷，**不要**用打补丁的方式绕过安全检查。

**结论与打包策略（正解）**
1. 逐目录 `make -C <dir> install` 安装，跳过"生成主机专属密钥/状态"的那一步；
2. 包内只交付**可重定位产物**（bin/libexec/cgi-bin/include/lib/share/man…）+ 上游**静态配置原型**；
3. 把生成密钥/状态的动作写进**部署说明**（在支持 0600 的真实文件系统上执行上游自带脚本完成）；
4. 主机专属密钥（含随机 secret 的 map/ids 等）**不应**进入可重定位包（既不可复现，也有泄密风险）。

## 2. 适用范围

| 维度 | 覆盖范围 |
|---|---|
| 上游形态 | autotools / GNU make；顶层 `install` 目标用 shell `for` 循环递归子目录 |
| 上游行为 | 安装期会生成/校验**状态或密钥文件**，并对其做权限（0600/0700）检查 |
| 目标文件系统 | 权限被归一化的共享文件系统：**HMDFS / tmpfs**（实测文件 mode 恒为 `0660`，`chmod` 无效）；`/dev/shm` 等保留 0600 |
| 打包目标 | 需要"可重定位 + 可复现"的包（Conan 包、系统包 staged install） |
| 反向（不适用） | 上游 install 用 `$(MAKE) -C` 且 `&&` 串联（rc 真实）；或程序无私有权限检查；或安装在普通 ext4/f2fs 上 |

## 3. 输入 / 输出定义

**输入**
- `install_log`：`make install` 的完整 stdout+stderr
- `top_rc`：顶层退出码（**不可单独采信**）
- `install_makefile`：顶层 `install` 目标的 recipe（判断是否 shell for 递归）
- `failing_step`：日志中首个 `Error <n>` 所属子目录 + 该子目录 recipe
- `fs_probe`：目标文件系统的 0600 探针结果（created-mode / after-chmod）

**输出**
- `HONEST_RC`：是否"rc 失真"（`for` 循环掩盖）＋ 真实失败子目录
- `FAIL_KIND`：`permission_check_vs_normalized_fs` ｜ `host_specific_secret_generation` ｜ `other`
- `install_strategy`：`per_dir_install`（逐目录）＋ 跳过的组件清单 + 跳过理由
- `package_whitelist`：进入包的产物路径集合（不含主机专属密钥）
- `deploy_notes`：部署期需自行执行的命令（如上游 `fix-map` 类脚本）与所需文件系统前提

**失败判据**：把 `FAIL_KIND=permission_check_vs_normalized_fs` 当作源码缺陷去打补丁（放宽/删除安全检查）
= **错误输出**；把顶层 `rc=0` 当作安装成功 = **错误输出**。

## 4. 示例（dcc-extras 2.3.169 实录）

**第 1 步：rc 失真**
```bash
$ make install > 05_make_install.log 2>&1; echo $?
0                                     # 顶层“成功”
$ grep -nE 'Error [0-9]+' 05_make_install.log
65:make[1]: *** [Makefile:31: install] Error 69    # homedir 子目录真实失败
```

**真实失败定位（`sh -x` 逐行 trace，取自 homedir/fix-map）**
```
+ ../cdcc/cdcc -qh$HD file=$HD/map 'new map $HD/map; load -; info'
open($HD/map): File exists
 ?                                                    # cdcc 退出 69 → set -e 中止 fix-map
```

**第 2 步：权限探针 → 判定为文件系统特性**
```
/storage/Users/currentUser/tmp : created-mode=0o660  after-chmod(600)=0o660
/dev/shm                       : created-mode=0o600
```
根因链：DCC 打开 map 时 `HAVE_PRIVATE_FILES` 检查要求 **0600**（`clntlib/lock_open.c:141`
`st_mode & (S_IRGRP|S_IWGRP|S_IWOTH|S_IXOTH)`）→ HMDFS 强制 `0660` → 检查失败 → `cdcc` 退出 69
→ `fix-map` 因 `set -e` 中止 → homedir 的 install 失败（被 for 循环掩盖）。

**正解（已落地为配方实现）**
```python
# 逐目录安装（15 个组件全部 rc=0）；homedir 只交付静态原型，不跑主机专属密钥生成
for sub in ("dcclib","clntlib","srvrlib","dns-helper","thrlib","cdcc","ck2ip",
            "dbclean","dccd","dblist","dccifd","dccproc","dccsight","misc","cgi-bin"):
    self.run(f'make -C "{sub}" install', cwd=self.source_folder)
```
```bash
$ for d in <15 组件>; do make -C $d install; echo "rc[$d]=$?"; done
rc[dcclib]=0 … rc[cgi-bin]=0        # 全部 0，失败不再被掩盖
```
包内容：`bin/`(cdcc,dccproc,dccif-test)、`libexec/`(dccd,dccifd,…,fix-map)、`cgi-bin/`、`include/`+`lib/`、
`res/dcc/`(静态原型)；**不含** map/ids（主机专属密钥）。部署说明：在支持 0600 的文件系统上执行
`libexec/fix-map -n '' -c bin/cdcc -h /var/dcc -i /var/dcc/ids -m /var/dcc/map -t /var/dcc/map.txt`。

## 5. 关联与协作

- 与 **E046（chmod 不生效 / HMDFS 权限）**、**E524（依赖注入勿用共享前缀）** 同族：均属"文件系统/沙箱语义
  与上游假设不符"，处置原则一致——**先实测、再判定，不绕过安全语义**。
- 预扫描可提前预警：检索上游 `Makefile*` 顶层 `install:` 是否含 `for D in $(SUBDIR)`，以及源码是否含
  `S_IRGRP|S_IWGRP|S_IWOTH|st_mode & …` 形态的私有性检查与 `O_EXCL` 建文件。
- 正式入库前建议：若知识库已有"HMDFS 权限"条目，本条可作为其**安装期分支**并入；否则独立成条。
