# E577 — CMake project() 声明 Fortran 语言时即便禁用 Fortran 特性仍强制查找 Fortran 编译器

## 错误特征

```
CMake Error at CMakeLists.txt:2 (project):
  No CMAKE_Fortran_COMPILER could be found.

  Tell CMake where to find the compiler by setting either the environment
  variable "FC" or the CMake cache entry CMAKE_Fortran_COMPILER to the full
  path to the compiler, or to the compiler name if it is in the PATH.
```

即使构建命令已显式传递 `-DFORTRAN_LIB=OFF`（关闭 Fortran 库构建的 option），configure 阶段仍在 `project()` 处直接失败。

## 触发条件

- 构建系统: CMake
- 阶段: configuration（`project()` 处，早于任何 option 生效）
- CMakeLists.txt 顶层声明：`project(<name> C Fortran)` 或 `project(<name> CXX Fortran)` 等含 `Fortran` 语言
- 平台: OHOS / HarmonyOS PC（无 gfortran/flang/ifort），或其他缺少 Fortran 工具链的平台
- 典型场景: 混合语言项目（C 核心库 + 可选 Fortran 组件），Fortran 组件可通过 option 关闭

## 根因分析

CMake 的 `project(<name> C Fortran)` 在 configure 阶段**无条件**要求每个声明的语言都有可用的编译器。语言探测发生在 `project()` 内部，早于后续 `option(FORTRAN_LIB "..." OFF)` 的求值——option 只控制"是否编译 Fortran 源码"，**无法阻止** CMake 先完成编译器探测。因此在无 Fortran 编译器的平台上，任何 `project()` 含 Fortran 的 CMake 项目都会在配置开始即失败，与业务逻辑中的 feature 开关无关。

注意区分两个独立问题（易混淆）：
1. **cmake_minimum_required < 3.5 在 CMake 4.x 报兼容性错误** → E103（bump-cmake-minimum-version）/ E187（add-cmake-flag `-DCMAKE_POLICY_VERSION_MINIMUM=3.5`），与本条目无关
2. **project() 含 Fortran 语言声明 → 强制探测 Fortran 编译器** → 本条 E577

## 解决方案

### 推荐方案：从 project() 语言列表移除 Fortran

适用于 Fortran 部分为可裁剪特性、核心功能在 C 库的场景（libccp4 正例：`ccp4c` C 核心库是下游 libpdb-redo 唯一依赖，`ccp4f` Fortran 库可整体裁剪）：

```bash
# CMakeLists.txt
# 修改前: project(libccp4 C Fortran)
# 修改后: project(libccp4 C)

# 同时以 option 关闭 Fortran 库构建（配方生成器中设置）
cmake .. -DFORTRAN_LIB=OFF
```

conanfile.py 中的对应做法：

```python
def generate(self):
    tc = CMakeToolchain(self)
    tc.variables["FORTRAN_LIB"] = "OFF"
    tc.generate()
```

### 禁止做法

- ❌ 用假编译器占位（`-DCMAKE_Fortran_COMPILER=/bin/true` 等）：绕过探测后，任何 `.f`/`.f90` 源码编译或链接必然失败，产生更难排查的错误
- ❌ 用 `-DCMAKE_POLICY_VERSION_MINIMUM=3.5` 解决本问题：该参数只解决 `cmake_minimum_required` 版本兼容（E103/E187），不涉及 Fortran 编译器探测

## 验证

```bash
# 修改后 configure 应通过（无 Fortran 编译器平台上）
cmake .. -DFORTRAN_LIB=OFF   # 不再报 No CMAKE_Fortran_COMPILER

# 产物完整性验证：C 核心库完整产出，Fortran 库不存在
ls lib/libccp4c.so          # ✅ C 库
ls lib/libccp4f.so          # ✅ 不存在（可选 Fortran 库已裁剪）
```

## 适用与不适用边界

**适用**：混合语言 CMake 项目，Fortran 组件为可选特性、可通过 option 关闭，且核心功能位于 C/C++ 部分，下游不依赖 Fortran API。

**不适用**：
- 项目主体为 Fortran（无实质 C 核心可保留）→ 走 E109（交叉编译或等待预编译包）
- Fortran 库是下游硬依赖 → 需提供 Fortran 工具链（如 tool_requires flang），参考 E242
- 修改 project() 语言列表会破坏下游 find_package 期望的组件/目标结构时，需评估裁剪影响面

## 验证证据

libccp4 8.0.0（2026-09-15，OHOS PC aarch64）：
- 修改前：`conan create` configure 报 `No CMAKE_Fortran_COMPILER could be found`，尽管 `-DFORTRAN_LIB=OFF` 已注入
- 修改后（补丁 `0001-CMakeLists.txt.patch`：`project(libccp4 C Fortran)` → `project(libccp4 C)`）：configure/make 全部通过，产出 `libccp4c.so`；`conan-verify` G0-G4 全部门禁 PASS；test_package 14 项断言全过
- 下游核查：libpdb-redo 的 `find_package(CCP4 REQUIRED ccp4c clipper-core ...)` 仅需 ccp4c，源码无任何 ccp4f 引用
