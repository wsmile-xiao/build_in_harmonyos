# E6418 — 老式 C 代码用 CLK_TCK 换算 times() 滴答：OHOS musl 无此宏，改 sysconf(_SC_CLK_TCK)

## 错误特征

```
cpubench.c:93:59: error: use of undeclared identifier 'CLK_TCK'
    dlt=((double )times(&tmsb)-(double )clticks)/(double )CLK_TCK;
membench.c:83:57: error: use of undeclared identifier 'CLK_TCK'
```

gcc 的写法：`error: 'CLK_TCK' undeclared (first use in this function)`。

## 触发条件
- 构建系统：任意（手写 Makefile / configure 最常见，典型是 1990s 基准与计时工具）
- 阶段：compile
- 源码特征：`times(&tms)` 的返回值或 `tms_utime` 除以 `CLK_TCK` 换算秒数

## 根因分析

`CLK_TCK` 是 POSIX.1-1988 时代的"每秒时钟滴答数"宏，POSIX.1-2001 已删除，改由
`sysconf(_SC_CLK_TCK)` 运行时查询。

- OHOS NDK sysroot（musl 系）只在 `<unistd.h>` 定义 `_SC_CLK_TCK`（值 2），
  `<time.h>`、`<sys/times.h>`、`<limits.h>` 均无 `CLK_TCK`。
- 现代 glibc 在默认特性宏下同样不定义它（本机 `gcc` 默认与 `-std=c89` 都报 undeclared）。
  所以这是老 C 代码移植问题，不是 OHOS 独有问题；但适配老软件时它经常和
  `sys_errlist`、K&R 隐式声明一起出现。

**不能用 `CLOCKS_PER_SEC` 顶替。** 它是 `clock()` 的单位（XSI 规定为 1000000），
`times()` 的单位是内核 USER_HZ（Linux/OHOS 为 100）。用错会让换算出的秒数小 10^4 倍，
`while (load(i) < 0.4) i *= 2;` 这类校准循环会失真甚至不收敛。

## 解决方案

### 推荐方案

在 `.work` 源码中把每个使用点替换为 `sysconf(_SC_CLK_TCK)`（需要 `<unistd.h>`，老代码一般已经包含），
然后用 `refresh-patch --auto` 生成补丁：

```bash
grep -rn 'CLK_TCK' .
sed -i 's/(double )CLK_TCK/(double )sysconf(_SC_CLK_TCK)/' cpubench.c membench.c
```

这是可移植的 POSIX 写法，不需要 `__OHOS__` 平台宏（符合 R8 / PF5）。

### 备选方案

使用点很多时，在公共头里加特性探测式兼容定义（这不是平台宏）：

```c
#ifndef CLK_TCK
#define CLK_TCK sysconf(_SC_CLK_TCK)
#endif
```

### 禁止做法
- ❌ `-DCLK_TCK=CLOCKS_PER_SEC`：单位错误，计时结果差 10^4 倍
- ❌ `-DCLK_TCK=100`：硬编码 USER_HZ，不可移植

## 验证

```bash
grep -rn 'CLK_TCK' <src>          # 补丁后应无残留
printf '#include <unistd.h>\nlong t(void){return sysconf(_SC_CLK_TCK);}\n' \
  | /data/service/hnp/bin/clang -x c -c - -o /dev/null
```

ubench 0.32 实测：补丁后 `ubench -cs` / `-ms` 回报的校准时长为 `0.40s`（目标 0.4s），
test_package 把 0.1–2.0s 作为断言区间，任何量级错误的滴答率都会被拦下。
