# EA 家族头文件在 OHOS aarch64 的平台检测缺口（E3000 草稿）

> 状态：草稿（DRAFT，待人工审核）｜来源：eabase 0699a15（electronicarts/EABase）OHOS aarch64 适配（2026-09-11）｜similar_to: E094, E187

## 问题

在 OHOS（HarmonyOS PC）aarch64 交叉编译 EA 家族头文件库时，上游 `eaplatform.h` /
`eastdarg.h` 的平台检测分支存在 4 处缺口，导致上游测试 3 处失败：

1. **端序宏缺失**：`eaplatform.h` Linux 分支的 `__aarch64__` 分支只定义
   `EA_PROCESSOR_ARM64` 与 `EA_PLATFORM_DESCRIPTION`，漏定义
   `EA_SYSTEM_LITTLE_ENDIAN` → 上游 `EA_SYSTEM_ENDIAN` 测试走入 `#else` 报错。
2. **va_list 引用语义**：`eastdarg.h` 的 `va_list_reference` 判定条件只覆盖
   Microsoft / 32-bit / Apple-ARM64 / Android-ARM64，缺 Linux+ARM64。OHOS aarch64
   的 `va_list` 是 32 字节结构体（非数组），按值传递不推进 → 上游 EAStdarg
   引用测试读回第一个参数。
3. **malloc 对齐常量**：`EA_PLATFORM_MIN_MALLOC_ALIGNMENT` 默认
   `PTR_SIZE*2=16`，但 OHOS aarch64 malloc 实测最小 8 字节对齐 → 上游
   EAAlignment 测试偶发失败。
4. **测试框架符号**：EAThread 测试框架在 OHOS sysroot（musl）缺失
   `pthread_setaffinity_np` / `pthread_getaffinity_np` / `pthread_setcancelstate`
   → 测试套件编译失败。

## 根因

EA 家族头文件的分支枚举按"已知平台"白名单展开，未包含 aarch64 Linux-family
（`__linux__` + `__aarch64__` 组合，含 OHOS）。`va_list_reference` 的判定
依赖"va_list 是数组还是结构体"的 ABI 事实，aarch64 AAPCS 下 va_list 是结构体，
必须引用传递。

## 方案

三个头文件补丁（见 eabase 0699a15 `patches/`）：

```c
// eaplatform.h — aarch64 Linux 分支
#elif defined(__aarch64__) || defined(__AARCH64)
    #define EA_PROCESSOR_ARM64 1
    #define EA_SYSTEM_LITTLE_ENDIAN 1
    #define EA_PLATFORM_DESCRIPTION "Linux on ARM64"
```

```c
// eaplatform.h — EA_PLATFORM_MIN_MALLOC_ALIGNMENT
// aarch64 Linux-family（含 OHOS）malloc 实测最小 8 字节对齐
#elif defined(EA_PLATFORM_LINUX) && defined(EA_PROCESSOR_ARM64)
    // aarch64 Linux-family (incl. OHOS) malloc returns at least 8-byte alignment (probed locally).
    #define EA_PLATFORM_MIN_MALLOC_ALIGNMENT 8
```

```c
// eastdarg.h — va_list_reference 判定追加 Linux+ARM64
... || (defined(EA_PLATFORM_LINUX) && defined(EA_PROCESSOR_ARM64))
```

EAThread 测试框架：以 `EA_PLATFORM_LINUX && EA_PROCESSOR_ARM64` 组合判定跳过
affinity / cancel-state 调用（aarch64 通用判定，与 Android 分支同思路，CPU
亲和性非正确性依赖；测试框架文件不进入交付物）。

## 验证

- 上游测试 15/15 通过（EABaseTest 11 函数 + C 入口 4 函数，RETURNCODE=0）
- 鸿蒙专项测试 15 断言全部 PASS（端序/va_list 引用/malloc 对齐/类型宏）
- conan create（-pr:h ohos-aarch64）通过，test_package 1/1 通过

## 适用边界

- 适用：EA 家族（EABase/EASTL/EAStdC/EAThread/EATest/EAMain）在 OHOS aarch64
  的适配；任何以 `EA_PLATFORM_LINUX` 分支编译 aarch64 的 EA 家族库
- 反例：非 EA 家族库不涉及；x86/x64 端序与 va_list 语义正常不需要此补丁；
  POSIX 风格条件（EA_PLATFORM_LINUX && EA_PROCESSOR_ARM64）仅对 aarch64
  Linux-family 生效，其余平台回退原逻辑

## 查重与差异

- E187（cmake_minimum_required <3.5 / CMAKE_POLICY_VERSION_MINIMUM）：本任务的
  CMake 4.x policy 问题与其**完全同源**，E187 已覆盖 → CMake policy 部分
  `reuse_existing`（E187），不新建。
- E094（pthread_attr_setaffinity_np，musl 缺 GNU 扩展）：仅覆盖
  `pthread_attr_setaffinity_np`（前缀不同的 attr 版符号）；本任务新增
  `pthread_setaffinity_np` / `pthread_getaffinity_np` / `pthread_setcancelstate`
  三个符号的 OHOS 缺失与"跳过不影响正确性"验证 → 部分覆盖，新增差异。
- EA 家族平台检测（端序 / va_list 引用 / malloc 对齐）：index.tsv、doc/、
  graph/、drafts/ 四范围均零命中 → 完全新增，可跨 EA 家族库复用。
- 结论：`new_draft`（E3000 草稿），CMake policy 部分复用 E187。
