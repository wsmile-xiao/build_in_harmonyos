# E2157 - Mandatory PowerShell empty-string parameters can bypass the intended mock oracle

> Contributor: 2301_80739235 | Status: DRAFT | Created: 2026-08-20

## Why this is a reusable pattern

PowerShell parameter binding occurs before a validation helper reaches its
production branch. An explicitly empty value can be valid fixture data, but a
mandatory string rejects it unless `AllowEmptyString` is declared. This creates
a distinct false-green risk when a negative test catches any exception.

## Symptom

An ownership-drift negative reports PASS, but the intended injected native
failure was never reached. The helper failed while binding an empty argument:

```text
Cannot bind argument to parameter 'ExpectedError' because it is an empty string.
```

## Root cause

The fixture used an empty value to model zero-byte output or no expected error.
PowerShell rejected the value before the mock returned its configured native
return code. A broad catch then treated the binding exception as the expected
negative, so the matrix did not prove the production ownership gate.

## Recommended solution

1. Keep required identity, path, hash, and diagnostic parameters mandatory.
2. Add `[AllowEmptyString()]` only where empty is an explicit valid state.
3. Write intentional zero-byte output with `File.WriteAllText($path, [string]::Empty)` or an equivalent byte-preserving API.
4. Require the exact downstream diagnostic in both the PowerShell harness and the independent Python consumer:

   `phase returned nonzero: OWNERSHIP_CLOSED=PASS rc=42`

5. Reject unrelated exceptions instead of accepting any catch path.

## Forbidden shortcuts

- Do not remove mandatory binding from parameters whose omission is invalid.
- Do not use `AllowEmptyString` for required identity, path, hash, or diagnostic values.
- Do not treat a parameter-binding exception as proof that the production branch rejected ownership drift.

## Verification

The librasterlite2 1.1.0-beta1 local W4 successor preserved the failed
predecessor, used a fresh production matrix, and closed the ownership-drift
negative with zero-byte output, injected native `rc=42`, and exact diagnostic
matching in both consumers. The fresh production matrix passed `28/28`, the
directed matrix passed `49/49`, and SSH, remote mutation, device, and launch
counts remained zero.
