# E2179 — meson 配置期 compile-and-run 探针 127（host 共享依赖不在 LD_LIBRARY_PATH）

## 错误特征

`meson setup` 配置阶段出现成对的“误导性”日志：

```
Checking if "LOG4CPLUS_INITIALIZER_H" with dependency log4cplus runs: NO (127)
Checking if "Get Log4cplus version" with dependency log4cplus runs: NO (127)
...
meson.build:824:24: ERROR: Unknown variable "log4cplus".
```

meson-log.txt 里可以看到真实原因：

```
Error loading shared library liblog4cplus.so.9: (needed by .../meson-private/tmpXXXX/output.exe)
```

## 触发条件

- 构建系统：meson
- 阶段：configure（`dependency(...)` 的 compile-and-run 特性探针）
- 依赖形态：Conan 提供的 **shared** 库（例：`log4cplus/2.2.0.1` `shared=True`）
- 工具链：`MesonToolchain` + `PkgConfigDeps` 生成 machine file / `.pc`，
  但配置期进程的 `LD_LIBRARY_PATH` 不含依赖的 `libdir`

## 根因分析

meson 的 `dependency()` 默认做“编译并运行”探测。探针可执行文件在**配置期被真实执行**
（native build，宿主与目标同架构），而 Conan 的 host 依赖库只由 build 阶段的 env script
注入运行时路径；配置期（`conan install` 之后、`meson setup` 之时）其 `libdir` 既不在
构建目录 RPATH 内，也不在 `LD_LIBRARY_PATH`，动态加载失败 → 进程退出码 127。
meson 将“运行失败”判定为特性不可用，把依赖标记为 not found，于是后续
`get_variable()` 读取该依赖变量时报 `Unknown variable`，掩盖了真实原因。

## 解决方案

### 推荐方案（priority 1，approach=inject-runtime-libdirs）

在 `conanfile.generate()` 中把所有 host 依赖的 `cpp_info.libdirs` 追加进
`LD_LIBRARY_PATH`，并保存为 env script（聚合进 `conanbuild.sh`，build 阶段自动 source）：

```python
from conan.tools.env import Environment

env = Environment()
for dep in self.dependencies.values():
    for libdir in dep.cpp_info.libdirs:
        env.append_path("LD_LIBRARY_PATH", libdir)
env.vars(self).save_script("conanbuildenv-<pkg>-runtime")
```

实测（kea-hook-perfmon 3.0.3）：注入后 `HAVE_GENERIC_TLS_METHOD`、
`LOG4CPLUS_INITIALIZER_H`、`Get Log4cplus version` 探针全部 YES，
`meson setup` exit_code=0（242 个构建目标）。

### 回退方案（priority 2，approach=disable-probe）

仅对**可选**特性使用：用显式项目选项关闭触发运行探针的 feature
（如 `-Dmysql=disabled -Dpostgresql=disabled -Dnetconf=disabled`）。
强制特性不可用此法。

### 禁止做法

- ❌ 用 `--build=missing`、跳过配置探针或伪造 meson-log 掩盖依赖缺口
  （违反 R36：依赖必须先发布再构建下游；会产生假绿构建）

## 验证

```bash
# 失败形态
grep -n -B3 -A3 'runs: NO (127)' <builddir>/meson-logs/meson-log.txt

# 修复后
grep -n -E 'LOG4CPLUS_INITIALIZER_H|Get Log4cplus version' <builddir>/meson-logs/meson-log.txt   # 期望 YES
```
