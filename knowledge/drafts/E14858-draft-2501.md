# CMake 上游测试分母须同时核对构建目标和 CTest 注册

## 场景与根因

有些 CMake 工程同时用选项控制测试构建和 CTest 注册。库目标尚未 `add_library` 时执行 `set_property(TARGET ...)` 会在配置期失败；即使配置修好，某个测试变体可能已编译却未 `add_test`，`ctest` 的 100% 只覆盖已注册的子集。不能把绿色摘要直接当作上游全量测试证明。

## 可复用修复

先在源码中盘点测试源、构建目标与 `add_test`，再用 `ctest -N` 与实际生成的测试可执行文件做双向核对。把目标属性移到目标创建之后，启用并注册缺失的变体。涉及网络的测试仍保留原断言，只把固定端口与无界等待改为每次运行的动态端口和有界等待。涉及 Unix socket 的测试需要实际支持 pathname bind 的短私有目录，不能只验证 TMPDIR 可写。

Conan 的 `self.run(..., env=["conanbuild", "conanrun"])` 会先激活环境脚本，外部设定或继承的 TMPDIR 不是最终有效值的保证。在 OHOS 应用私有 native files 存储下创建每次唯一目录，并把 `TMPDIR=<quoted-private-dir>` 放到最终 CTest 命令前缀；使用 `TemporaryDirectory` 对整次完整 CTest 调用作异常安全清理。保留 4/4 的测试分母和原有 Unix/TCP 断言，不用其他三项成功掩盖一个网络用例失败。

不要减少测试分母来取得 100%，也不要仅增加消费者测试代替遗漏的上游用例。网络断言的有效性需由测试实际退出码确认。

## 本次证据与边界

liblo 0.32 的 `cmake/CMakeLists.txt` 补丁修复目标属性时序，并补齐 C++ exception 变体注册。CI #80115 环境中的 `TMPDIR=/data/storage/el2/base/cache` 仍在 `testlo` Unix socket bind 时报 `Operation not permitted`，其他三个 CTest 成功，不能将最后打印的“liblo test PASSED”当作 authoritative exit status。修复后的鸿蒙 PC 真机事务 `liblo-w3-20261010T103000Z` 完整执行 CTest 4/4、安装包消费者 1/1，12 个事务回执含释放后的检查。原始 `conan-create.log` SHA-256 为 `56f891d5db81336e327b3bf329c7379ca0545d3fd60ba2c71b6e6b69cf64c9a6`。

适用于 CMake/CTest 多变体测试；若上游本来没有 CTest，则应按其实际测试框架盘点，不应强行套用 `ctest -N`。与已有的固定端口/网络测试经验相近，原增量是“构建目标与注册清单不等价”的分母核验；本轮增量是激活后的运行环境、目录 socket capability、完整套件退出状态和异常清理必须同时验证。native files 正例不证明其他沙箱、cache 路径或全部 AF_UNIX 功能可用。
