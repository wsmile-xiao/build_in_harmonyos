# E2152 - Remove dangling package aliases with explicit symlink detection

## Symptom

A package recipe removes an obsolete metadata file, then attempts to remove an alias with code guarded only by `Path.is_file()`. The alias remains as a dangling symbolic link and is recorded in `conanmanifest.txt`, even though the real target no longer exists.

Consumers can then find a path that looks like a supported helper or metadata file but cannot be opened. A simple regular-file inventory misses the residue because it follows the broken link.

## Root cause

`Path.is_file()` follows symbolic links. Once the target has been removed, it returns `False` for the dangling link, so cleanup code such as this silently skips it:

```python
if alias.is_file():
    alias.unlink()
```

The directory entry still exists. Package integrity needs a no-follow existence decision for expected aliases, not only a target-file decision.

## Fix

Keep an explicit allowlist of paths that must be absent and unlink each path when it is either a regular file or a symbolic link:

```python
for path in prohibited_aliases:
    if path.is_file() or path.is_symlink():
        path.unlink()
```

Do not replace this with broad recursive deletion. If a prohibited path changes into a directory or another unexpected type, fail closed so upstream layout drift remains visible.

## Validation

Use both positive and negative checks:

1. Create a real metadata file and an alias symlink.
2. Delete the real target first, reproducing a dangling alias.
3. Run the package finalizer and require the alias path to be absent without following it.
4. Inspect the generated package manifest and require no record for the prohibited aliases.
5. In `test_package`, reject both regular-file and symlink forms of each alias.

For `libpng/1.6.58.2`, the directed local regression recreated the two dangling aliases from the published `1.6.58.1` package and proved their removal. The current recipe successor still requires a fresh exact-tree target W3; older target output is retained only as historical evidence.

## Scope and boundaries

This pattern applies to Python/Conan package normalization where real metadata targets and compatibility aliases are removed in sequence. It does not authorize deleting unknown directories, following arbitrary links, or changing upstream source contents.

The issue is independent of target platform conditionals; the cleanup remains portable Python package logic.
