# E322 — legacy C code fails at link with duplicate symbols under -fno-common

## 错误特征
```
ld.lld: error: duplicate symbol: Res_bit
>>> defined at mpc_decoder.c
>>>            mpc_decoder.c.obj:(Res_bit) in archive ../libmpcdec/libmpcdec_static.a
>>> defined at requant.c
>>>            requant.c.obj:(.rodata+0x0) in archive ../libmpcdec/libmpcdec_static.a
clang-15: error: linker command failed with exit code 1
```
同一静态库内多个 .obj 定义同名全局符号；编译全部成功，仅在最终链接（或链接引用该库的工具）时失败。

## 触发条件
- 构建系统: cmake / autotools / 任意（与构建系统无关，纯语言层问题）
- 阶段: linking（所有 .c 编译通过之后）
- 编译器: GCC >= 10 或 clang >= 11（含 OHOS clang 15）——两者都已把 `-fno-common` 设为默认

## 根因分析
2015 年前的 C 代码常把共享查找表写成多个翻译单元中的"试探性定义"（tentative definition，如 `int tbl[N];` 无 extern，不加初始化）。老 GCC 默认 `-fcommon`，链接器会把同名 tentative definition 合并为一个符号。现代 GCC/clang 默认 `-fno-common`，每个 TU 都产出真实符号 → `ld.lld duplicate symbol`。
实测案例（musepack r475）：`Res_bit`/`__Cc`/`__Dc` 同时定义于 mpc_decoder.c 与 requant.c，链接 mpcgain 时炸出 3 个 duplicate symbol。

## 解决方案

### 推荐方案（append-fcommon-flags）
以最小侵入方式追加 `-fcommon`，且必须用**追加式**写法避免覆盖工具链注入的 flags（R33）：
- CMake：`set(CMAKE_C_FLAGS "${CMAKE_C_FLAGS} -O2 ... -fcommon")`（不要写 `set(CMAKE_C_FLAGS "-O2 -fcommon")`）
- autotools：把 `-fcommon` 追加进 CFLAGS
适用前提：重复定义只发生在同一"合并组"内（tentative definition 语义）。若同名符号跨**不同归档**被有意重复定义，`-fcommon` 也救不了，需走 fallback。

### 禁止做法
- ❌ `-Wl,--allow-multiple-definition`：静默任选一个定义，掩盖真实 ABI 错误，可能运行期用错表/布局。
- ❌ 覆盖式 `set(CMAKE_C_FLAGS "-fcommon ...")`：丢掉 Conan toolchain 注入的 flags（R33）。

### 备选方案（extern-declaration-refactor）
编译器拒绝 `-fcommon` 时才用：保留一个定义 TU，其余改 `extern` 声明；补丁经 `refresh-patch --auto` 重新生成。对三方快照尽量选 `-fcommon` 保持补丁最小。

## 验证
```bash
cd build && make 2>&1 | grep "duplicate symbol"   # 修复后应为空
nm libmpcdec.a | grep " [BbDCd] Res_bit"           # 修复前可见多个 .o 定义同名符号
```
