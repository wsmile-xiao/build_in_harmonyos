# E14725 draft: isolate configured outputs shipped inside an Autotools snapshot

Some source snapshots ship both authoritative Autotools inputs and generated results from a previous configure. A fresh target build must not silently consume the old `config.status`, Makefiles, `config.h` or stamp. This differs from the existing KyTea draft about an old `config.h` leaking into a VPATH compile: here the multi-file configured state must be handled before regeneration.

The PhyML 3.3.20250515 release contains seven exact outputs: `Makefile`, `config.h`, `config.log`, `config.status`, `doc/Makefile`, `src/Makefile`, `stamp-h1`. The Conan recipe requires each to be an ordinary file in its disposable source copy, removes exactly that set, preserves `configure.ac` and build templates, then runs `autoreconf --force --install`, target configure, build and package. It also preserves Conan C/LDFLAGS and binds `config.guess` to a compiler-proven OHOS tuple. Target W3 `w3-phyml-20261004T074245Z` passed; the installed executable inferred a Newick tree from a four-taxon nucleotide alignment (consumer 1/1). Raw Conan log SHA-256: `3bea39a8f9d4d0641a2cf56215c1f95bea404768e1b1cc160e9184dc18fb27f6`.

Reusable procedure: classify release files as source inputs or generated configured outputs, require an exact file inventory, remove only generated outputs from an isolated Conan copy before Autotools regeneration, and verify the actual target compiler and installed consumer. Do not delete unknown paths, follow symlinks, mutate the user's source checkout, or count a successful `autoreconf` as an upstream test pass. This release registers no upstream tests, so 0/0 is not applicable.

## 2026-10-10 verification increment: regeneration has a tool-script closure

CI80109 demonstrated a new boundary of this cleanup procedure: deleting stale
configured outputs correctly requires regeneration, but having autoreconf on
the developer device does not declare aclocal/automake on the release worker.
Skipping regeneration is not a repair when authoritative configure.ac is
transformed to preserve Conan CFLAGS/LDFLAGS.

The repair declares Autoconf 2.72, Automake 1.18, Perl 5.42.2 and m4 1.4.19,
all checked with `conan download --only-recipe` and compatible OHOS binary
identities. A declared script package can still retain a producer shebang or
baked-in module/data prefix. Task-local wrappers invoke its inspected raw
Automake scripts through the actual build-host Perl, with package-relative
macro/libdir arguments and pure-Perl module directories. Resolve the host Perl
before activation and reject the Conan cache Perl on OHOS; this also prevents
the previously observed cached Cwd XS module permission failure. This is an
interpreter/module closure requirement, not a hardcoded developer tool path.

The new frozen transaction `phyml-ci9-w3-20261010T101200Z` performed real
regeneration, native configure, full build/package, `make check` (no registered
tests) and the four-taxon Newick consumer 1/1. Its unique launch and 12 receipts
including release/postrelease passed, and exact tool RREV/PID/PREV matched the
frozen graph. Raw log SHA-256:
`bc3ebe332859f331dee957f17fa7454e73d5d2d7f53b690d1af08d34149a7a69`.

This extension applies where snapshot cleanup requires real Autotools
regeneration, a compatible build-host Perl exists and the declared package has
the inspected raw entry points. It does not authorize installing into shared
user paths, replacing missing tools with `/bin/true`, mixing Perl XS ABIs,
deleting unknown outputs, or using this native device result as a CI PASS.
