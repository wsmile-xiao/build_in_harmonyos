# E327 — 旧 Rust Unix 依赖锁图在 OHOS target_env 下的确定性迁移

## 错误特征

```text
could not compile libc
unresolved import ... libc
mismatched types ... nix
target_env="ohos"
```

## 触发条件

- 构建系统：Cargo
- 阶段：Rust compilation
- 目标：HarmonyOS/OHOS，现代原生 Rust 工具链
- 项目特征：`Cargo.lock` 固定早于 OHOS 支持的 `libc`/`nix` Unix 依赖图

## 根因分析

旧项目的锁文件可能固定在 OHOS `target_env` 出现之前的 Unix portability crate。现代 OHOS Rust 编译器会进入新的目标 cfg/ABI 组合，但旧 `libc` 和 `nix` 没有对应定义或仍假定旧类型。只设置 clang linker、只更新最底层 `libc`，或者绕过 `--locked` 都不能得到可审计且内部一致的依赖图。

alass 2.0.0 的直接根依赖是 `ctrlc 3.1.3`，它锁定 `nix 0.14.1` 和 `libc 0.2.62`。旧 libc 产生 662 个编译错误；单独替换 libc 后，旧 nix 仍有 45 个 ABI/type 错误。

## 解决方案

### 推荐方案

1. 用 `cargo tree`/锁文件定位引入旧 Unix 图的最小直接依赖。
2. 检查上游 `Cargo.toml` 的 semver 范围，选择范围内支持 OHOS 的版本。
3. 精确更新该直接根，让 Cargo 生成一致的传递锁图。
4. 将完整 `Cargo.lock` delta 导出为源码补丁并审计版本、来源和 checksum。
5. 应用补丁后始终以 `--locked` 构建和测试。
6. 同时运行上游测试、消费者测试和破坏性负测。

alass 的已验证命令：

```bash
cargo update -p ctrlc --precise 3.5.2
cargo build --release --locked --package alass-cli
cargo test --workspace --release --locked --tests
```

### 禁止做法

- 不删除 `--locked`，否则 CI 解析结果不可复现。
- 不运行无版本边界的全量 `cargo update` 后直接提交。
- 不直接修改共享设备的 `.cargo/registry/src`。
- 不把仅能通过 Linux target 的结果写成 OHOS 通过。
- 不只更新 `libc` 而忽略拥有 API/feature 契约的上层 `nix`/根依赖。

## 验证

```bash
cargo build --release --locked --package alass-cli
cargo test --workspace --release --locked --tests
```

验证必须同时证明锁图差异受控、目标为 OHOS、上游测试没有删减，并由打包消费者检查实际产物。
