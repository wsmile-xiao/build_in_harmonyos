# USB HDC GUI test closure must separate render, window, and graphics capabilities

## Problem pattern

On a signed HarmonyOS PC HAP, a browser-backed GUI can render real controls and the native test runner can exit with RC 0, while individual upstream cases still observe an art-size mismatch, unstable paint-client geometry, unavailable key state, inactive top-level windows, or a graphics-context SIGSEGV. A test case can even report `success=true` with zero assertions when a capability patch returns unconditionally. HDC shell runs as `uid=2000(shell)` while the app owns a different storage domain: app-view paths may be denied even when exact physical-path result readback is permitted.

## Root cause

Broadway supplies a browser surface, not a native window manager. Rendering alone does not prove activation, key-state, or off-screen graphics support. Geometry must be diagnosed separately: outer-frame sizing and a logical child DC size do not prove that the parent client area has been allocated. In fresh USB r28, the size probe accepted 260x300 but wxPaintDC clipping still observed 258x261 and 17 assertions failed. Correct parent client allocation retained and passed these assertions in r30/r33. The Drawing crash occurred while resolving the reference directory, with a non-null renderer, not during graphics-context creation. Explicitly setting the upstream reference-root environment parameter avoided that fallback; the archive then proved to lack the portable basic-case reference PNG. These fixture failures are not evidence that rendering should be skipped. An unconditional return hides missing coverage behind the framework's success flag. Console-only and GUI/drawing inventories differ; successful HDC transport also does not cross the app storage UID boundary.

## Reusable resolution

1. Keep the recipe and source free of vendor-specific conditional compilation. Correct fixture allocation first: use parent client sizing, a bounded parent paint wait, and minimum client-size assertions before child creation. Keep every original clipping comparison and tolerance. Probe precise capabilities only after fixture correctness; emit one reason-bound `WX_EXPECTED_SKIP:id=...;path=...;reason=...` only on the unsupported branch. Never put an unconditional skip before the original assertions.
2. Build and sign the complete test bundle, transfer it once over the authorized USB HDC serial, and launch it once. Run Base, GUI, and Drawing as separate selectors and record the exact Catch denominators and child-exit status.
3. Bind the signed app identity and exact storage view before retrieving results. If physical-path readback is permitted, receive complete files and verify remote/local bytes and SHA-256. If denied, expose bounded `upstream.log`, `child-exit.log`, and `result.xml` through the signed app UI. Do not infer shared UID or merge evidence from different execution domains merely because a path is readable.
4. Separate console and GUI/drawing marker allow-lists and reject undeclared, malformed, or duplicate markers. For every suite, record case count, assertion count, skip count, child exit, and exact result identity. A framework `N/N` with zero assertions is not a functional pass. Keep the original failure and each successor's marker as immutable evidence.
5. Diagnose missing reference resources independently of renderer availability. Bind the upstream fixture-root parameter to the signed child sandbox; do not rely on executable-path discovery in a loadable Native child. If the official source omits a golden file but independently defines an exact portable image (e.g. an opaque white rectangle), assert that specification's dimensions, pixels and transparency. Never copy target output into a golden file, enable reference-generation mode, or widen tolerances to achieve PASS. Keep normal reference comparison for other cases and when an upstream golden file exists.

6. Respect the selected native art provider's size hint rather than another provider's fixed-size assumptions. Construct help events with an explicit origin when global key-state discovery is unavailable; test clone origin/position/id without claiming that unavailable capability was implemented. Verify top-level Raise/activation and Hide/inactivation separately from rendering.
7. Derive each marker's owner from its actual XML TestCase ancestor. Section aggregates are not complete per-case assertion counts: assertions outside Sections may be omitted from that summary. Use root OverallResults for whole-run assertion totals; unavailable per-case counts remain unknown. A source-proven unconditional return is a real coverage defect, but zero direct Section counts alone do not prove it.
