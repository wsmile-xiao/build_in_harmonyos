# E577: QBS 生态项目适配 OHOS — 上游仅 QBS 构建时改写 CMakeLists.txt

## 错误特征
- CI/本地环境执行 `qbs` 相关命令报 `qbs: command not found`
- 上游仓库仅有 `*.qbs`（Qt Build Suite）构建文件，无 CMakeLists.txt/Makefile/configure
- 直接 `cmake` 报 `Project file ... .qbs not found` / 无任何 CMake 入口
- 改写后 AUTOMOC 报 `moc ... symbol not found`（需 libc++_shared.so 运行时路径）
- conan create 报补丁应用失败 `source/target file does not exist:`（补丁头不是 /dev/null）

## 触发条件
适配 HarmonyOS PC 的第三方库上游构建系统为 QBS 时（典型的 Qt5/Qt 生态项目）。本条目源自 dewalls 1.0.0：上游仅提供 `dewalls.qbs`（DynamicLibrary dewalls + CppApplication dewalls-test，Depends Qt core），CI 能力矩阵无 QBS 工具链，必须改写为 CMake 才能走 conan 流水线。

## 根因
OHOS 适配 CI 的能力矩阵只提供 gcc/clang/make/cmake/ninja/bash，QBS（Qt Build Suite）不在其列，离线环境下 qbs 不可用。上游 QBS 项目直接编译必然失败。改写为 CMakeLists.txt 是唯一可复现路径，但需要等价还原 QBS 声明的构建目标，并叠加 OHOS 平台特有坑：

1. **新文件补丁头**：`refresh-patch --auto` 对新文件生成补丁时，若 orig 目录残留 0 字节同名文件（patch --dry-run 副作用，见 E484/E547），补丁头会退化为 `--- a/CMakeLists.txt` 而非 `--- /dev/null`，conan `patch_ng`（默认 strip=0）无法应用。修复：清理 orig 污染后重新生成，且 conandata.yml patches 声明 `strip: 1`。
2. **Qt5 消费路径**：qt/5.15.19 配方自带 Qt5Config.cmake 且 `cmake_find_mode=none`，CMakeDeps 不生成 qt-config 代理文件。若库配方把 qt 声明为可见依赖，下游 `find_package(dewalls)` 会把 `find_dependency(qt)` 写进生成物，消费端 CMake 报找不到 qt-config。修复：qt 用 `visible=False`（构建期私有依赖），消费者自理 Qt5——generate() 注入 CMAKE_PREFIX_PATH 指向 qt package_folder、test_package 显式 requires qt 并对 qt 声明 `cmake_find_mode=none`。
3. **AUTOMOC 运行时库**：qt 包自带 bin/moc 是 OHOS 可执行程序，但运行时需要 libc++_shared.so；moc 在 CMake AUTOMOC 阶段崩于 `__cxa_pure_virtual symbol not found`。修复：generate()/build() 把 OHOS SDK llvm/lib 与 `llvm/lib/aarch64-linux-ohos` 子目录 prepend 到 LD_LIBRARY_PATH。
4. **SONAME**：OHOS 无 Platform/HarmonyOS.cmake，CMake 不注入 `-Wl,-soname,`，`add_library(SHARED)` 产物缺 DT_SONAME（W3 L5 门禁拦截）。修复：CMakeLists 中 `project(... VERSION ...)` + `set_target_properties(VERSION/SOVERSION)`，conanfile generate() 显式设 `CMAKE_SHARED_LIBRARY_SONAME_CXX_FLAG=-Wl,-soname,`（与 E383 同法）。

## 解决方案
1. 按 `dewalls.qbs` 目标全集手写 CMakeLists.txt：`file(GLOB DEWALLS_SOURCES src/*.cpp)`、`CMAKE_AUTOMOC/AUTORCC ON`、`find_package(Qt5 REQUIRED COMPONENTS Core)`、`add_library(dewalls SHARED)`、测试目标 `add_executable(dewalls-test test/*.cpp qrc)` + `enable_testing()/add_test`。
2. 生成新文件补丁走 `/dev/null` 头（清理 orig 0 字节污染后 `refresh-patch --auto`，conandata 声明 `strip: 1`）。
3. Conan 配方（见 affected_scope 描述）：qt `visible=False`、generate() 注入 qt 的 CMAKE_PREFIX_PATH、test_package 显式 requires qt + 对 qt 声明 cmake_find_mode=none；build() 中 ctest 运行时把 build 目录与 qt lib 加入 LD_LIBRARY_PATH。
4. moc 运行时：SDK llvm lib 目录注入 LD_LIBRARY_PATH（generate + build 双保险）。

## 验证证据
- dewalls 1.0.0（上游仅 dewalls.qbs）改写 CMake 后：`conan-verify` G0-G4 全 PASS，`finish` W3 本地 CI Pass rate 100%（L0/L1/L5 PASS）。
- ctest（构建期上游测试）：`All tests passed (2729 assertions in 8 test cases)`，8 个 TEST_CASE 全绿。
- test_package（消费者视角）：链接 libdewalls 并调用 WallsSurveyParser 公共 API 解析 .srv 数据行成功（4 项自研断言）。
- 补丁应用：`patch_ng.fromfile(...).apply(strip=1)` 成功生成 CMakeLists.txt。

## 适用 / 不适用边界
- **适用**：上游构建系统为 QBS/qmake 的 Qt 生态库、CI 无 QBS 工具链、需要 conan+CMake 承载的全部场景；同样适用"上游无标准构建文件、需自行补 CMakeLists"的库。
- **不适用**：上游已有完整 CMakeLists.txt 的 CMake 项目（走模式 A 即可）；Windows→OHOS 交叉编译需 Qt host-tool 分离的（见 E456，本条目仅覆盖同架构 OHOS 构建）。
- 与 E383（SONAME 缺失）同根因部分，本条目聚焦"QBS 改写 + Qt5 消费路径"组合，E383 单独覆盖 SONAME flag 机制。
