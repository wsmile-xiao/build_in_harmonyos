# 以依赖头文件证据处理 AX_LIB_READLINE 的交叉编译误报

plptools 1.0.26 的 `AX_LIB_READLINE` 宏用 `AC_RUN_IFELSE` 判断版本，并把交叉编译分支写死为失败。HarmonyOS PC 的未签名探测程序也不能直接运行；单纯切换 `--host` 虽能绕开执行探测，却会触发“readline 不足 4.3”的假阴性。

配方从 Conan 实际解析的 readline 包读取 `include/readline/readline.h`，解析 `RL_READLINE_VERSION` 并检查至少为 `0x0403`；只有通过校验，才传入 `ax_cv_lib_readline_version_ok=yes`。后续编译和链接仍使用该 Conan 依赖，不是以缓存值代替全部兼容性检查。若宏还检查运行时 ABI、头库来自不同包，或版本没有可信的头文件宏，这种预置不适用。

## 可复用判别

1. 在 `configure.ac` / 引入的 m4 宏中确认失败路径确由 `AC_RUN_IFELSE` 的 cross 分支触发，而非真实缺头、缺库。
2. 从依赖管理器解析后的包路径读取头文件，核对宏要求的最低版本；失败时直接拒绝构建。
3. 只预置这个经过证明的缓存变量，继续完成真实编译、链接及安装后消费者测试。
4. 独立披露被排除的可选组件；plptools 的 libfuse 2 还依赖目标机不支持的线程取消，不能通过伪造该 API 来宣称 FUSE 可用。

与已有的一般 Autotools 平台检测条目不同，本条对应 `AX_LIB_READLINE` 的具体缓存变量、可验证的头文件版本和适用边界。

实证：冻结输入事务 `plptools-w3-20260930T173000Z`，`make check` 上游注册测试 0/0，安装后四个 CLI 4/4，12/12 收据 `W3_PASS`；日志 SHA-256 `2f0056d3f2d366590fe09b59b9c12ba92e4e509bc22f71de9128d72948bd048e`。
