# E340 - Legacy Autotools Desktop Metadata Without intltool

> Contributor: codex | Status: DRAFT | Created: 2026-08-29

## Problem

Some older Autotools desktop applications ship a generated `configure` script
that unconditionally requires `intltool`, even when the selected standalone
build only installs a small number of `.desktop` files.  On an OHOS worker the
configuration can stop with:

```text
The intltool scripts were not found. Please install intltool.
```

If configuration is bypassed, the generated data Makefile can later fail with
`intltool-merge: not found`.

The exact runtime failure still needs verification on the clean W3 worker for
`activity-log-manager/0.9.7`; the source-level probe and Makefile dependency
are directly present in the release tarball.

## Scope

This applies to legacy Autotools releases with generated `configure` and
`Makefile.in` files where the product can accept untranslated desktop metadata
and only needs standard keys such as `Name`, `Exec`, and `Type`.

It does not apply when translated desktop entries are a product requirement or
when intltool performs nontrivial XML, policy, or schema transformations.

## Inputs

- A release archive with generated `configure` and `Makefile.in` files.
- One or more `.desktop.in` files using underscore-prefixed metadata keys.
- A standalone package decision that accepts untranslated desktop metadata.

## Outputs

- A configure/build that does not require a system-wide intltool installation.
- Installed `.desktop` files with standard `Name`, `Exec`, and `Type` keys.
- A retained `make check` result from a real `desktop-file-validate` tool.

## Root cause

`IT_PROG_INTLTOOL` expands to mandatory checks for `intltool-update`,
`intltool-merge`, and `intltool-extract`.  The `.desktop` rule generated by
intltool also invokes `intltool-merge` to convert underscore-prefixed
translation keys.  OHOS does not guarantee that the legacy Perl tool is
installed on the worker.

## Recommended fix

Keep the workaround inside the Conan recipe and its package patches:

1. Remove `IT_PROG_INTLTOOL` from `configure.ac` so a future regeneration does
   not restore the unconditional dependency.
2. Create build-folder-only probe scripts for the three names.  The update
   probe must report a real compatible version; the merge and extract probes
   must never be packaged or used as the data transformation.
3. Replace the data Makefile desktop rule with a deterministic rule that
   converts `_Name=...` to `Name=...` and similarly handles other underscore
   prefixed desktop keys.
4. Keep `make check` enabled.  It must still use a real
   `desktop-file-validate` implementation on the worker; the probe shims are
   not validation tools.

If translations are required, use the fallback: publish or declare a real
intltool build requirement and preserve the upstream merge rule.

## Executable example

```bash
conan create archives/a/activity-log-manager/0.9.7 \
  --profile:host=ci/conan/profiles/ohos-aarch64 \
  --profile:build=ci/conan/profiles/ohos-aarch64 --build=missing
```

For a direct source check, apply the recipe patches to a fresh archive, put the
build-folder probe scripts first on `PATH`, run `./configure --disable-nls`,
then run `make -j1` and `make check`.  Confirm the generated desktop file
contains the expected standard keys and that no probe script is packaged.

## Forbidden shortcuts

- Do not replace `make check` with `true` or omit the test target.
- Do not claim that the probe shims provide translations.
- Do not install a developer's private intltool path or modify shared CI PATH.
- Do not mark W3 passed until a clean worker has run configure, make, make
  check, and the consumer test.

## Verification

Apply all patches to a fresh release archive, configure with the local probe
tools on PATH, build with `-j1`, and inspect the generated desktop file.  Then
run the upstream `make check` target with `desktop-file-validate` available and
run the Conan consumer test.  Record the worker log and target architecture;
the knowledge entry remains a draft until those checks pass on the target
worker.  A package that only reaches configure or uses a fake validator must
not be reported as verified.

## Safety boundary

The fallback desktop rule deliberately drops translation merging.  It is safe
only for a standalone package where untranslated English metadata is accepted.
Packages requiring localized desktop metadata must use a real intltool
implementation instead.
