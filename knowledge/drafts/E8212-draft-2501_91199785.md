# Autotools 自举时统一宿主 Perl，隔离 Conan 缓存中的 XS 模块

## 现象与根因

OHOS CI 的 `autoreconf` 在读取 `Cwd.pm` 时尝试加载 Conan 用户缓存里的 `auto/Cwd/Cwd.so`，动态加载器返回 `Permission denied`，失败发生在项目配置或编译之前。仅把 `PERL` 设为 Conan Perl 不够：已选中的 `autoreconf` 脚本可以由系统 shebang 启动，而 `conanbuild` 的 `PERL5LIB` 仍把 Conan Perl 的核心/XS 目录暴露给它。

这种日志证明 `.so` 已找到但未能加载；CI 构建 #63612 尚未提供可将拒绝精确归因于单一 MAC 规则的标签证据。E212 描述用户目录 `dlopen` 的一般边界，E729 草稿处理两套 Perl 的 ABI 和工具重定位；本条补充的是 **当 CI 不允许加载 Conan 缓存的 XS 时，自举阶段可完全避开该 XS 闭包**。

## 修复步骤

1. 在进入 `conanbuild` 环境前选取宿主 Perl，并确认它不是 Conan Perl 包内的解释器；先运行 `perl -MCwd` 验证宿主自身的核心模块。
2. 从 `tool_requires` 取得 Autoconf、Automake 包路径。显式调用该 Autoconf 包的 `bin/autoreconf`，避免 PATH 落到另一套 HNP 工具。
3. 仅在本次 `autoreconf` 命令中设置 `PERL=<宿主解释器>`，并把 `PERL5LIB` 限定为 `<automake>/share/automake-1.18:<autoconf>/share/autoconf`，不混入 Conan Perl 的 `lib/perl5` 或架构专属 XS 目录。
4. `ACLOCAL`/`AUTOMAKE` 包装脚本用同一宿主 Perl 运行包内 `.aclocal-real` / `.automake-real`，保留包所需的 `--automake-acdir`、`--system-acdir`、`--libdir` 重定位参数。
5. 验证 `autoreconf`、完整 `conan create`、全部上游测试及安装包消费者；不要只凭 `perl -MCwd` 成功宣布库适配通过。

## 验证与边界

libgenome 的 CI #63612 在 `/storage/Users/currentUser/.cache/conan2/.../Cwd.so` 失败；旧真机环境的缓存位于 `/data/storage/el2/base/files/...`，原先本地通过并不能证明 CI 路径可用。新配方在真机事务 `libgenome-w3-20260928T081735Z` 中显式记录宿主 `PERL`、纯模块 `PERL5LIB` 和包内 `autoreconf`，`conan create` 返回 0，上游测试 1/1、消费者 1/1；12 个回执完整，单次启动，日志 SHA-256 为 `9e19a02a683676dd9cec8b1dc83a93d36c87cdfd66a2ae665288d630c154bb06`。**CI Worker 上的修复有效性仍须新构建确认**。

此法只适用于宿主 Perl 自身可正常加载核心模块、Autotools 所需附加模块是纯 Perl 的自举链。若构建确实要运行 Conan Perl 专属 XS，不能简单删去其 `PERL5LIB`；应单独定位该扩展的运行路径、ABI 和平台权限。不要 `chmod 777` Conan 缓存里的 `.so`，不要修改共享包，也不要跳过测试掩盖失败。
