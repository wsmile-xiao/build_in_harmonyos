# E348 — 上游 GLib 单测在 OHOS test_package 中 vendored 实跑：GLib::GLib 链接 + G_TEST_SRCDIR 注入

## 错误特征

上游库测试用 GLib 测试框架（`g_test_init`/`g_assert`/`g_test_run`）+ TAP 驱动，
`check_PROGRAMS` 被 `if ENABLE_UNIT_TESTS if HAVE_GLIB` 门控。直接在 OHOS 上
`make check` 不可行（无 GLib/TAP 工具链）。若只写"0/N 未执行"会被评审按 rule4 判
**少报**。libXpm 3.5.17 上游 5 个测试（XpmCreate/XpmMisc/XpmRead/XpmWrite/rgb），
把 4 个 display-independent 测试**未修改 vendored** 进 test_package，由 CI 实跑得到
真实通过率 4/4；`rgb` 因需 configure 生成的内部头（release tarball 不含）判 N/A。

## 触发条件

- 上游测试依赖 GLib 测试框架 + TAP（`test/Makefile.am` 的 `check_PROGRAMS` 在
  `ENABLE_UNIT_TESTS`/`HAVE_GLIB` 条件下）。
- GLib 已在同轨鸿蒙化发布（glib/2.88.0，default shared=False 静态构建，package_info
  提供 `GLib::GLib` 目标）。
- 测试依赖数据文件（pixmaps 等），经 `G_TEST_SRCDIR`/`G_TEST_DIST` 定位。

## 根因分析

- GLib 测试的 `g_test` 默认在 CWD 找测试数据；`G_TEST_SRCDIR` 需显式指向源数据目录、
  `G_TEST_BUILDDIR` 指向构建产物目录。不注入则运行时找不到 pixmaps 挂掉。
- test_package 默认 CMake 构建，需 `find_package(GLib CONFIG)` 拿到 `GLib::GLib`
  目标，与上游测试源码一起链接进 consumer 可执行文件。
- 上游测试常 include configure 生成的内部头（如 xpm.h/unixio.h/file.h），release
  tarball 不含 → 该用例无法在 test_package 重构，须如实判 N/A 并说明根因。

## 解决方案

1. 上游测试源码**未修改** vendored 到 `test_package/upstream/test/`（.c + 辅助头
   `TestAllFiles.h`/`CompareXpmImage.h` + pixmaps 数据 + 最小 `config.h` 等价宏）。
2. CMake: `find_package(GLib CONFIG REQUIRED)`（或 pkg-config），
   `target_link_libraries(... GLib::GLib <pkg>::<pkg>)`。
3. 运行期注入 `G_TEST_SRCDIR=<test_package>/upstream/test`、
   `G_TEST_BUILDDIR=<build>/test` 环境变量，逐用例执行。
4. 对缺 configure 生成内部头、无法在 test_package 重构的用例（如 rgb），如实写
   N/A + 根因。
5. 把真实通过率回填 PR body"上游测试用例通过率"（rule4 修复），而非"0/N 未执行"。

验证：CI worker（OHOS aarch64）上 vendored 测试全部 exit 0，输出含 g_test 汇总
（OK: 若干 assertions / PASS）。

## 禁止策略

- 不写"0/N 未执行"作为过渡（army16/Septest 按 rule4 判 FAIL）。
- 不省略 `G_TEST_SRCDIR`/`G_TEST_BUILDDIR`（测试数据找不到会挂）。
- 不改上游测试源码让"通过"。
- 不把不可实跑（缺内部头/需配置生成）的用例谎报为通过。
