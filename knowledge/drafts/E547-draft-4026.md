# E547 — OHOS getpwuid 失败平台上工具身份 fallback 分叉导致上游测试比较断言失配与登录类测试不可行

## 错误特征
```
ssh-keygen 公钥 comment: 100@localhost（uid 派生值）
dropbearkey -y 输出 comment: @localhost
AssertionError: assert 'ssh-rsa AAAA… @localhost' == 'ssh-rsa AAAA…100@localhost'
dbclient: Warning: failed to identify current user. Trying anyway.
服务端: Login attempt for nonexistent user from 127.0.0.1
asyncssh: PermissionDenied
```

## 触发条件
- 构建系统: 任意（与构建系统无关；出现在上游测试/运行阶段）
- 阶段: testing（上游测试套件）、runtime（依赖用户身份的登录/比较逻辑）
- 平台: OHOS 设备——当前 uid（应用 uid，如 20020084）无 /etc/passwd 条目；
  passwd 全部条目 pw_dir 为空、shell 为 /bin/false；进程非 root

## 根因分析
OHOS 不用 /etc/passwd 管理普通用户，getpwuid/getpwnam 对当前 uid 返回 NULL。
不同工具在此失败路径上各自 fallback 且互不一致：ssh-keygen 用 uid 派生值拼
`100@localhost` 作公钥 comment，dropbearkey 的 fallback（src/dropbearkey.c:411）
取空用户名拼 `@localhost`。上游测试若比较含身份串的整行（如公钥 comment，
上游注释自认 "since it currently matches" 属附带比较），两个 fallback 的差值
即成为断言失败。另一面：非 root 网络服务端（dropbear svr-auth.c checkusername）
仅允许 `pw_uid == 服务器 euid` 的用户登录，而 passwd 中不存在任何
pw_uid==当前 uid 的条目，使认证类集成测试在本机平台性不可行——且普通权限
无法修复（不可写 /etc/passwd）。

与 E338 的区别：E338 是 getpwuid NULL 后对 NULL 拼接导致的**崩溃**（SIGSEGV）；
本条目是**不崩溃的静默失配**（测试比较断言失败）与**登录基础设施缺失**
（认证类测试整组无法执行），失败面完全不同。

## 解决方案

### 推荐方案
1. 按"环境限制"归类此类失败，逐工具实测 fallback 证据（对同一输入分别运行
   两端工具并留原始输出），测试计数如实分列（PASS/FAIL/SKIP/NOT_RUN），
   不用 PASS 掩盖。
2. 功能等价性用**替代验证**证明：密钥格式转换用往返逐字节比较
   （dropbear→openssh→dropbear 后 cmp）；网络服务用传输层握手验证
   （连接建立、版本协商、KEX 完成即证协议栈可用，认证拒绝为预期行为）。
3. 测试环境需要身份/密钥时，在 `HOME=$TASK_DIR/test-home` 沙箱内预置，
   绝不写真实 `~/.ssh`（见 feedback/2026-09-06-dropbear-2025.88.md 事故）。

### 禁止做法
- ❌ 修改上游测试断言来绕开 comment 比较（断言属上游契约）
- ❌ 伪造 /etc/passwd 条目或要求 root 改系统文件
- ❌ 把环境限制类 FAIL 写成 PASS 或 "skip"

## 验证
```bash
# 1) 确认 getpwuid 失败（当前 uid 无条目）
python3 -c "import pwd,os; pwd.getpwuid(os.getuid())"   # 预期 KeyError
# 2) 确认两个工具 fallback 分叉（同一密钥两种 comment）
ssh-keygen -f k1 -t ed25519 -N '' && cat k1.pub          # <uid派生值>@host
dropbearconvert openssh dropbear k1 k2 && dropbearkey -f k2 -y   # @host
# 3) 确认服务端登录检查（非 root dropbear 仅同 uid 可登录）
grep -n -A6 "running as nonroot" src/svr-auth.c
```
