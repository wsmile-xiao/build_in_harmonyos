# E2146 - Identity-bound acquisition and coherent publication for signed execution trees

## Symptom

A target runner copies unsigned ELF inputs to `signed-exec.pending`, signs the
copies, and publishes `signed-exec`. Failure cleanup appears correct in ordinary
tests, but a path created between the initial absence check and a later create
or publish can be deleted even though it belongs to another transaction.

Using `mv -n pending final` does not close this race when `final` is an existing
directory. GNU `mv` treats it as a target directory and moves the owned pending
tree to `final/pending`. The foreign directory survives, but its contents have
been modified and the owned tree is no longer reachable at the expected source
path.

## Root Cause

There are four separate contract defects:

1. A single transaction-active flag authorizes cleanup of several paths but
   does not prove which objects the current invocation created.
2. `mv -n` disables replacement but retains target-directory semantics. It is
   not a no-replace directory publication primitive unless `-T` is also used.
3. Creating an object, reading its inode, and setting its owner flag as separate
   interruptible commands leaves a window where cleanup has no proven authority
   or can capture a replacement as if it were invocation-owned.
4. Clearing signed-root and evidence ownership independently leaves a signal
   window where a committed root can survive while its evidence is removed.

An absence check before creation or publication cannot make either operation
atomic.

## Fix

1. Track pending directory, final directory, transition temp, and final evidence
   with separate ownership flags and `device:inode` identities.
2. Hold the pending directory and transition file on dedicated descriptors.
   Derive the expected inode from the held object, compare the live path to it,
   and only then publish ownership.
3. During each create/identity/owner handoff, defer HUP/INT/TERM into one record.
   Replay it after ownership is visible so EXIT cleanup has exact authority.
4. Publish with `mv -nT`, then require the source to be absent and the
   destination identity to equal the source identity before transferring the
   cleanup flag.
5. Establish destination ownership before releasing source ownership. On
   EXIT/HUP/INT/TERM, remove a path only when both its flag and current
   identity match. Preserve and report every identity mismatch.
6. Replace independent final flag clears with one commit state. Before commit,
   root and evidence are both cleanup-owned; after commit, both are preserved.

When the target `mv` lacks `-T`, freeze a task-local helper that performs
`renameat2(..., RENAME_NOREPLACE)` and apply the same identity checks.

## Validation

The production-equivalent matrix must include:

- pending replacement before `mkdir`;
- transition-temp replacement before exclusive creation;
- final-root replacement before publish;
- evidence replacement before publish;
- TERM after a foreign final root appears.
- pending and transition stat failure after a held object exists;
- pending and transition replacement between held identity and path identity;
- pending and transition TERM deferred until owner publication;
- TERM immediately before and immediately after the single commit assignment.

Each race must prove the foreign marker remains after production cleanup. The
test harness then removes only its own injected object and proves the canonical
transaction inventory returns to the pre-case hash and member count. Ordinary
signer, section, source-drift, and TERM failures must still produce no residue.

For pkgconf 3.0.5, target generation was byte-identical `21/21`; signing checks
passed static `29/29`, recipe `8/8`, and runner `23/23`. Acquisition TERM and
pre-commit TERM returned 143 with zero residue; post-commit TERM preserved the
complete root/evidence pair. The same frozen snapshot later completed one
authorized endpoint-215 W3: five ELF files were signed, 26/26 target assertions
passed, controller/runner launch counts were 1/1 with runner RC 0, and release
proved root process 0, two clean scans, and absent lock/lease.

## Safety Boundaries

- Never clean by package prefix, process name, or path name alone.
- Never delete an identity-mismatched destination to make a failed transaction
  look clean.
- A host matrix proves the shell contract, not target filesystem or signal
  behavior.
- Windows/MSYS cannot prove the production `/proc/<owner-pid>/fd/N` contract;
  preserve that target contract and report it NOT_RUN locally.
- E077 covers the ELF re-signing order. E261 covers preserving the old output
  after an exchange when the installed target is replaced concurrently. This
  entry covers the earlier shell-directory acquisition/publication windows,
  deferred signals, and one commit state for the signed root/evidence pair.
