# E6341 — 现代 cpp 塌缩多行宏调用内的制表符，使 X11 imake 生成语法错误的 Makefile

## 错误特征

三类症状并发出现，且都不指向真正的补丁点：

```
# 1) 顶层 Makefile 解析失败（配方行丢了 tab）
Makefile:302: *** missing separator.  Stop.

# 2) 对齐的宏定义被当成配方行，变量消失
#    （生成物里 "   PRIVCONFIGDIR = $(TOP)/config" 变成了 "\tPRIVCONFIGDIR = ..."）

# 3) 子目录 imake 因此拿不到 -I<TOP>/config
<stdin>:3:10: fatal error: 'Imake.tmpl' file not found
#include IMAKE_TEMPLATE
         ^~~~~~~~~~~~~~
imake: Exit code 1.  Stop.
make[1]: *** [Makefile:382: subdirMakefiles] Error 2

# 4) 被注释掉的配方行被 cpp 当成指令
./Imakefile:27:3: error: invalid preprocessing directive
```

## 触发条件

- 构建系统: X11 imake（Project.tmpl / Imake.rules / @@ 软换行体系）
- 阶段: configuration（`imake` 生成 Makefile、`make Makefiles` 生成子目录 Makefile）
- 工具链: 现代 clang / gcc 的 cpp（OHOS 上是 clang 15.0.4 的 clang-cpp）

## 根因分析

`Imake.rules` 里每条规则用 `@@` 作软换行标记，imake 的 `ReadLine()` 在 `@@` 处切分，
再由 `CleanCppOutput()` / `KludgeOutputLine()` 还原成 Makefile 的每一行。

1991 年的 cpp 在展开多行宏调用时**保留**续行行首的制表符，所以还原出来的配方行
天然带 tab。现代 cpp 按 C 标准把宏调用内部的换行与连续空白**合并成一个空格**，
imake 拿到的配方行只剩一个前导空格，make 于是报 `missing separator`。

imake 自带修正逻辑 `KludgeOutputLine()`（需要 `FIXUP_CPP_WHITESPACE`；
`imakemdep.h` 只在 `sun / SYSV / SVR4 / hcx` 下自动定义它，OHOS 不在其列），
但它判定 target 行的依据是「行内是否出现冒号」，判据太宽，两头都错：

1. 配方行本身不含冒号时（例如 `$(MAKE) $(MFLAGS) Makefile`）不会被补 tab；
2. 含冒号的对齐宏定义（`   PRIVCONFIGDIR = $(TOP)/config`）被认成 target 行，
   前导空格被剥掉一个、随后又被换成 tab，**变量从此消失**；子目录 imake 因此
   丢掉 `-I$(NEWTOP)$(PRIVCONFIGDIR)`，报 `Imake.tmpl file not found`。

另有一处同族问题：顶层 `Imakefile` 与 `appsrc/dconvert/signa/Imakefile` 里
注释掉的配方行写作 `\t#...`，现代 cpp 把它当指令，报 `invalid preprocessing
directive`。imake 自己的 `CleanCppInput()` 只处理**第 0 列**的 `#`。

## 解决方案

### 推荐方案

编译 imake 时：

1. 定义 `-DFIXUP_CPP_WHITESPACE`；
2. 把 `KludgeOutputLine()` 的 target 判据从「行内有冒号」改成「**首个空白分隔的
   词**里含冒号」，并把缩进行分成两类——单个前导空格且在规则内的是配方行（还原
   成 tab），形如 `NAME = / NAME := / NAME += / NAME ?=` 的是宏定义（回到第 0 列）；
3. `CPP_PROGRAM` 指向读 stdin 的 `clang-cpp`，并给它加 `-P`：`-P` 既去掉行号标记，
   也去掉 clang 为保持源码行号而插入的空行——那些空行会重置 imake 的 `InRule`
   状态，让紧随其后的配方行又被漏掉；
4. 把注释掉的配方行改写成 `XCOMM ...`（`XCOMM` 即 `#`），让它活着穿过 cpp。

```sh
"${CC}" -std=gnu89 -w -DFIXUP_CPP_WHITESPACE -o "${BIN}/imake" \
    -I"${IMAKE_SRC}/config" -I"${IMAKE_SRC}/include" \
    -DCPP_PROGRAM="\"${BIN}/cpp\"" "${IMAKE_SRC}/config/imake.c"

# ${BIN}/cpp:
#   #! /bin/sh
#   exec clang-cpp -P "$@"
```

### 回退方案

不改 imake 源码，改用一个在宏展开中保留制表符的传统 cpp（老 gcc 的
`cpp -traditional`）作为 `CPP_PROGRAM`；OHOS 上没有 gcc，需要自行引入。

### 禁止做法

- ❌ 对 imake 生成的 Makefile 做 sed/post-process 补 tab：imake 每轮都会重新生成
  Makefile，子目录 Makefile 还要由 `make Makefiles` 二次生成，补丁覆盖不到，
  首次 make 可能通过、随后任何 Makefile 目标都会重新生成坏文件。
- ❌ 用 `core.ignorecase` 或版本控制手段掩盖生成物差异：根因不在这里。

## 验证

```sh
# 直接把 Imakefile 交给 cpp，观察 @@ 展开后配方行的前导字符
printf '#define IMAKE_TEMPLATE\t"<abs>/config/Imake.tmpl"\n#define INCLUDE_IMAKEFILE\t<Imakefile>\n#include IMAKE_TEMPLATE\n' > in.txt
clang-cpp -P -I. -I<abs>/config - < in.txt | grep -n 'all::' | cat -A
# 期望：@case 那一行的前导字符是单个空格（说明 cpp 确实塌缩了），
#       因此必须由 imake 侧还原成 tab

# 生成的 Makefile 里对齐的宏定义必须原样保留
imake -I./config <defines>
grep -n 'PRIVCONFIGDIR = ' Makefile
# 期望：'   PRIVCONFIGDIR = $(TOP)/config'，前面是空格而不是 ^I

# 子目录必须能生成
make IMAKE_DEFINES="..." Makefiles
# 期望：不再出现 'Imake.tmpl' file not found，且 find . -name Makefile | wc -l 为 67
```

## 与既有条目的差异

既有条目中没有覆盖「cpp 作为通用宏处理器时现代实现改变了空白语义」这一类。
最接近的是 E219（CI buildenv 下 python 路径问题），其错误特征落在
`inaccessible or not found`，与本条的 `Imake.tmpl file not found` 不重叠。

反证命令（在应用本补丁**之前**的树上执行，实测输出如下）：

```sh
$ cd <pristine>/appsrc/dconvert/signa && imake -I../../config -DTOPDIR=../.. 2>&1 | tail -3
./Imakefile:27:3: error: invalid preprocessing directive
./Imakefile:32:3: error: invalid preprocessing directive
imake: Exit code 1.  Stop.

$ grep -n 'PRIVCONFIGDIR = ' <pristine>/Makefile
177:	  PRIVCONFIGDIR = $(TOP)/config        # 变量还在（顶层 imake 未用修正逻辑时反而正常）

$ grep -rl "'Imake.tmpl' file not found" <logs>/makefiles.log
makefiles.log: cd appsrc; imake -I../ ... → fatal error: 'Imake.tmpl' file not found
# 根因：-I$(NEWTOP)$(PRIVCONFIGDIR) 展开成 -I../（PRIVCONFIGDIR 为空）
```

即：打开 `FIXUP_CPP_WHITESPACE` 但未修判据时，变量被吞掉→子目录 imake 失败；
不打开该宏时配方行丢 tab→`missing separator`。两者互为反证，说明必须同时满足
「启用修正」和「判据正确」。
