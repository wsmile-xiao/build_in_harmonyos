# E2164 - Re-sign task-private OHOS shared-library copies

## Symptom

An OpenHarmony package consumer has a complete private shared-library closure,
ordinary materialized SONAME aliases, a valid `DT_RPATH`, an explicit
`LD_LIBRARY_PATH`, owner-executable modes, and exactly one `.codesign` section
per copied library. The consumer itself starts, but the loader still reports
missing libraries such as `libfoo.so.1`, followed by unresolved symbols and
exit 127.

## Root Cause

A unique `.codesign` section proves structural presence, not that the current
target accepts the copied artifact. A provider package can be correctly signed
in its Conan cache while a byte-identical copy or materialized alias under a
task-private runtime root is rejected. Treating `existing == 1` as a successful
fast path skips the only operation that establishes a current target signature
for that private copy.

This differs from E077: no `patchelf`, strip, or content mutation is required
to trigger the boundary. It also differs from E2146, which covers ownership and
atomic publication of the signing transaction rather than whether a provider
signature may be reused after materialization.

## Fix

Keep the Conan package cache immutable. For every private shared ELF copy:

1. Reject duplicate `.codesign` sections and pre-existing sibling temporaries.
2. Copy the private ELF to a sibling unsigned temporary.
3. Remove one old `.codesign` from that temporary with the target
   `llvm-objcopy`.
4. Require the stripped temporary to contain zero `.codesign` sections.
5. Sign it to a second sibling temporary with the current target
   `binary-sign-tool`.
6. Require exactly one new `.codesign`, restore owner execute, and atomically
   replace only the task-private copy.
7. On every failure, preserve the original copy and remove only the two
   invocation-owned temporaries.

Apply the same rule to the versioned library and every regular SONAME alias in
the private closure. Keep signer diagnostics off machine-readable stdout; route
them to stderr when the enclosing command emits JSON.

## Validation

For `libxft/2.3.9`, W3 r17 preserved one provider `.codesign` per private copy
and failed with loader RC 127 for `libXft.so.2` and `libfontconfig.so.1`.
The forced re-sign successor executed both consumers successfully with 79 and
16 assertions. The final repaired-candidate r26 transaction passed:

- upstream tests: `0/0` because the upstream Meson project defines no tests;
- package consumers: `2/2`;
- shared/static variant executions: `4/4`;
- consumer assertions: `95`;
- exact endpoint: `10.62.148.108:2222`;
- launch count: `1`;
- postrelease clean scans: `2/2`.

The directed signing matrix also passed unsigned signing, an existing-section
fast path outside private staging, forced re-signing, missing-section failure,
owner execute, original preservation, and zero temporary residue.

## Safety Boundaries

- Never strip or re-sign the shared Conan dependency cache.
- Section count, mode, RPATH, and loader path are separate contracts; none alone
  proves target loadability.
- Do not convert a target loader failure into a skip or reduce the consumer
  denominator.
- A host mock validates control flow only; require one fresh same-snapshot W3
  for the target loader result.
- Preserve consumed failures and create a new immutable W3 successor after any
  recipe, signer, runner, or collector change.
