## 问题

LLVM 15.0.4 上游使用 lit + llvm-lit + check-llvm/check-clang 作为测试入口。在 OHOS（pc3 真机原生）上运行 lit 最小子集时，上游 `llvm/test/lit.cfg.py` 依赖 CMake 生成的 `lit.site.cfg.py` 提供大量 config 属性；在 Conan 包/临时 worktree 环境无 CMake 生成物时加载即报 `AttributeError`（`use_lit_shell` → `host_triple` → `ld64_executable` → `have_libxml2` 逐个缺失）。`psutil` 缺失使 lit `--timeout` 不可用（仅警告，不影响用例执行）。

## 方案

1. **自包含替换式 `lit.cfg.py`**：复制上游 `llvm/test/lit.cfg.py`，在顶部注入全部 site 属性：
   `llvm_src_root` / `llvm_obj_root` / `llvm_tools_dir` / `llvm_lib_dir` / `llvm_shlib_dir` / `llvm_shlib_ext` /
   `llvm_plugin_ext` / `llvm_exe_ext` / `llvm_host_triple` / `host_triple` / `target_triple` / `targets` /
   `targets_to_build`（字符串 `AArch64`）/ `llvm_use_sanitizer` / `llvm_build_mode` / `enable_llvm_dylib` /
   `llvm_dylib_version` / `llvm_libs_dir` / `host_arch` / `host_os` / `host_cc` / `host_ldflags` /
   `llvm_enable_assertions` / `llvm_inliner_model_autogenerated` / `llvm_raevict_model_autogenerated` /
   `lit_tools_dir` / `use_lit_shell` / `use_default_substitutions` / `python_executable` / `go_executable` /
   `gold_executable` / `ld` / `ld64_executable` / `ptxas_executable` / `ocamlfind_executable` / `ocaml_flags` /
   `osx_sysroot` / `build_examples` / `build_shared_libs` / `enable_threads` / `expensive_checks` /
   `has_plugins` / `have_curl` / `have_libxar` / `have_libxml` / `have_libxml2` / `have_llvm_driver` /
   `have_ocamlopt` / `have_opt_viewer_modules` / `have_tf_aot` / `have_tf_api` / `libcxx_used` /
   `link_llvm_dylib` / `linked_bye_extension` / `llvm_locstats_used`；随后
   `import lit.llvm; lit.llvm.initialize(lit_config, config)` 再加载上游配置。
2. **入口脚本 `run_lit_subsel.sh`**：生成 `llvm-lit-wrapper.py`，用 `config_map` 把源码 `llvm/test` 映射到 `lit.site.cfg.py`。
3. **最小 smoke 用例 `test_lit/add.ll`**：`// RUN: llc -mtriple=aarch64-unknown-linux-ohos %s -o - | FileCheck %s`。
4. **子集选择**：按文件名排序取 `CodeGen/AArch64` 前 50 + `Transforms/InstSimplify` 前 15；禁止跑全量（约 7.3 万文件不现实）。

## 实测结果（pc3 真机原生，OHOS profile，clang 15，libcxx=libstdc++，gnu14，Release，shared=False，R8 静态方案）

| 子集 | 用例数 | Passed | Unsupported | Failed | 耗时 |
|------|--------|--------|-------------|--------|------|
| lit 框架自测 | 4 | 4 | 0 | 0 | 4.39s |
| CodeGen/AArch64 | 49 | 46 | 3 | 0 | 1.19s |
| Transforms/InstSimplify | 15 | 15 | 0 | 0 | 0.61s |
| **合计** | **68** | **65** | **3** | **0** | — |

- 3 个 Unsupported：`aarch64-fix-cortex-a53-835769.ll`（缺 cortex-a53 fix feature）、`O3-pipeline.ll`/`O0-pipeline.ll`（缺 O0/O3 pipeline feature），非失败。
- lit 工具链（llc/FileCheck/count/not/clang-15 等）在包内齐全且已签名（含 `.codesign` 段）。
- 运行时依赖闭环：`llc` NEEDED `libc++_shared.so`，设备存在（`/system/lib64/` + `/lib64/`，1289544 字节），静态消费方无需修改。

## 知识库查重

- `DRAFT-intel-oneapi-dpcpp-ohos-sycl-lit`：intel-oneapi-dpcpp 库 SYCL 层 lit 适配（category llvm|sycl|lit|toolchain|ohos|cross-compilation）。
- 本草稿：LLVM 15.0.4 本体 lit 框架，专注 AArch64 CodeGen + InstSimplify 等 LLVM 核心 IR/后端测试。
- 范围对比：不同库、不同测试层级、不共享代码/脚本 → 证据独立，不构成重复申报。

## 复现命令

```bash
# 1. lit 框架自测
python3 $SRC/llvm/utils/lit/lit.py $SRC/llvm/utils/lit/tests/

# 2. AArch64 CodeGen 子集（49 用例）
python3 $SRC/llvm/utils/lit/lit.py --no-progress-bar <SUITE>/CodeGen/AArch64

# 3. InstSimplify 子集（15 用例）
python3 $SRC/llvm/utils/lit/lit.py --no-progress-bar <SUITE>/Transforms/InstSimplify
```
