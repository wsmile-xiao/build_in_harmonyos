# E2163 - Release native error outputs and check coordinate ranges

## Symptom

A platform adapter returned immediately when a pasteboard call reported a
nonzero status, even though the call could also return a non-null owned object.
The same adapter rounded external `double` pointer offsets into signed 32-bit
values and added signed origins or deltas without a wider intermediate.

## Root Cause

Status, ownership, and representability are separate API contracts. Failure
does not imply a null output. A finite-looking coordinate path can still see
NaN, infinity, an out-of-range rounded value, or signed overflow during
addition.

## Fix

Release every non-null owned output on all returns, preferably through a scoped
owner when several returns follow. Reject non-finite coordinates, bound the
rounded offset against `INT32_MIN - origin` and `INT32_MAX - origin`, add in
`int64_t`, and narrow only after the final range check. Apply the same wide-add
rule to relative deltas and preserve the output parameter on failure.

## Validation

The `synergy-core/1.20.4` successor replayed 43/43 patches into 48/48
postimages. Its portable state executable compiled with strict warnings and
passed 8/8 tests, including half-unit rounding, NaN, infinity, both signed
limits, valid edge values, and both overflow directions. Production-source
assertions confirmed the destructor precedes the pasteboard failure return and
both coordinate helpers are used for both axes.

## Safety Boundaries

- Do not silently clamp unless the product contract explicitly requires it.
- Verify the exact destructor and ownership rule for each native API.
- Directed host tests do not replace complete current-snapshot target tests.
- Do not add platform-name conditional macros to upstream source or patches.
