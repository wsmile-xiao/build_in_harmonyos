# E696 — OHOS(musl) 的 `getopt()` 不做 GNU 置换：选项放在文件名之后会被当成输入文件

> 草稿编号 E696（`knowledge_id.py --claim --task potool-0.19` 取号并回查未占用）；
> 来源：potool 0.19 HarmonyOS PC 适配（任务卡 9677，2026-09-24）。
> 配套 `.kv`：`knowledge/drafts/E696-draft-9677.kv`。

## 错误特征

上游测试链在第三组用例（`poedit`）处断裂，报错看起来像「文件名写错」，实为 libc 语义差异：

```text
+ ../potool "3/work.po" -fnth
** (process:26913): CRITICAL **: Can't open input file: -fnth
Running 'potool "3/work.po" -fnth > .../work.po' failed with code 1
make: *** [Makefile:58: check] Error 1
```

`make check` 在此之前 7 条用例全过（选项前置形态 + 无选项形态），止步于**唯一选项后置**的调用点。

## 触发条件

1. 程序用 ISO C `getopt()`（**不是** `getopt_long`）解析参数，并用 `argv[optind]` / `argv[optind+1]` 区分单文件/双文件模式；
2. 调用方把选项写在文件名**之后**（`prog "$FILE" -fnth`）；
3. 运行在 musl libc 上（OHOS 唯一 libc）。glibc 上因 GNU 置换而一切正常，因此**上游与 Debian 打包测试都不会暴露**。

## 根因分析

| 面 | glibc（上游/Debian） | musl（OHOS） |
|---|---|---|
| `getopt()` 语义 | `POSIXLY_CORRECT` 未设时自动把选项重排到位置参数前（GNU 置换） | 严格 POSIX：遇到首个非选项参数即返回 `-1`，`optind` 停在该处 |
| `prog file -fnth` | 解析出 `opt=f optarg=nth`，`optind` 指向 `file` | `optind` 仍=1，`-fnth` 沦为位置参数 |
| 后果 | 正常 | 上游 `potool.c:748` 的双文件分支取 `argv[optind+1]` = `-fnth` → 当输入文件打开失败 |

一手编译探针（与 `potool.c` 同 optstring `"f:n:scph"`、同 clang 15 编译）——设备实测：

```text
$ ./gpprobe in.po -fnth          # 选项后置
optind=1 argc=3
positional[1]=in.po
positional[2]=-fnth              ← 选项被当位置参数

$ ./gpprobe -fnth in.po          # 选项前置（对照）
opt=f optarg=nth
optind=2 argc=3
positional[2]=in.po

$ readelf -d gpprobe | grep NEEDED && strings gpprobe | grep musl
 NEEDED  libc.so
 /lib/ld-musl-aarch64.so.1
```

## 影响范围

- 本例：`scripts/poedit` 4 处调用（`$potool "$POFILE" -fnth` / `-fnt` / `-ft -fno` / `-ft -fo`）→ `make check` 3/10 条失败；
- **同源第 2 个面（交付物，make check 不覆盖）**：`scripts/postats` 3 处 `potool $a -ft -s` / `potool $a -s` / `potool $a -ff -s` → 真跑必失败，且上游用 `[ $? -eq 0 ] || { echo "Error: …"; continue; }` **吞错**，整脚本仍 **rc=0**（假绿面）。实测：
  ```text
  $ postats tests/1/in.po
  Error: "potool /…/tests/1/in.po -ft -s" failed     # 修复前；rc=0（被吞）
  ```
  修复（选项前置）后：
  ```text
  tests/1/in.po            -     5/  1/9     ( 55%)  -4
  x(100%)x                 -     5/  1/9     (55%)  -4     # rc=0，0 条 Error
  ```
- 同族：任何「脚本包装 C 工具、且习惯把选项写在文件尾」的上游测试（与 glibc 系发行版上全绿形成反差）；
- 不受影响：选项前置调用、纯位置参数调用（本包上游测试中 7/10 条即此类）。

## 推荐方案（rec_approach=reorder-argv-options-first）

改**调用方脚本**，把选项搬到文件名之前，并同步改写同一行的错误提示串；**不动被调程序的 getopt 解析器**（改脚本面最小、不改上游 C 语义）：

```diff
-	$potool "$POFILE" -fnth > "$TMPFILE" || { echo "Running '$potool \"$POFILE\" -fnth ...' failed ..."; exit 1; }
+	$potool -fnth "$POFILE" > "$TMPFILE" || { echo "Running '$potool -fnth \"$POFILE\" ...' failed ..."; exit 1; }
```

落地补丁：`archives/p/potool/0.19/patches/0003-scripts-poedit.patch`（4 处调用 + 4 处提示串）。
修复后 `make check` 由 7/10 → **10/10（rc=0）**，`conan create` 全链 rc=0。

## 禁止策略

- **不要**设 `POSIXLY_CORRECT`：它只会关掉 glibc 侧置换，让设备/CI 与上游分叉，且无法让 musl 恢复置换；
- **不要**改写上游 `getopt` 解析器（改 `potool.c` 的 `optarg` 处理等）：超出适配面、与上游难对齐，审计判 P1；
- 若调用方不可改：只能按「环境限制 + 原始证据」如实申报 NOT_RUN/FAIL，**不得记 PASS**。

## 环境事实（同批实测，供排查时并读）

`make check` 在 OHOS 上要跑满 10 条还叠加了三个环境缺口（**不是**本条目的根因，但常与之同时出现，逐层实测归因见 `$TASK_DIR/w0/W0-gates.md` 关④）：

1. `scripts/*` 的 `#!/bin/bash`、`change-po-charset` 的 `#!/usr/bin/perl`（设备与 CI 均无该绝对路径）→ `env` 形式 shebang；
2. 全机无 `locale` 命令 → 环境 shim 提供 `locale charmap` → `UTF-8`（返回 `C.UTF-8` 会被 `iconv` 判 `conversion unsupported`）；
3. `mktemp -d -t` 需可写 `TMPDIR`（`/tmp` 只读）。
