# E2147 - Unified keyed inventory for platform-conditioned Meson fixtures

## Symptom

A Meson test run reports every top-level suite as `OK`, but the suite stdout
contains nested `SKIP:` terminals. The report still claims the complete
official fixture count as passed because it checks only the top-level JSONL
`result` field.

Adding a second complete run does not fix the count by itself. Both runs list
the same official fixture files, so summing their totals repeats most cases.

## Root Cause

The upstream fixture runner returns success for source-declared
`SkipPlatforms`. Meson therefore proves only that the suite runner accepted its
own mixture of `PASS` and `SKIP`; it does not prove that every fixture passed.

The stable identity is the official `(suite, fixture)` key, not an environment
summary. A second defect can appear before testing when registered tests depend
on `build_by_default: false` executables: a hand-written compile list may omit
the commands that the fixture runner later invokes.

## Fix

1. Enumerate `t/*/*.test` and require the exact official key count.
2. Parse every suite stdout and require one unique `PASS`, `SKIP`, or `FAIL`
   terminal for each `(suite, fixture)` key.
3. Parse each fixture's `SkipPlatforms` field and reject any raw terminal that
   does not match the source declaration for that run.
4. Build one unified map over the same key set. Select exactly one real `PASS`
   for every key; never relabel a `SKIP` or add repeated run totals.
5. Require the final map to satisfy `passed=inventory`, `skipped=failed=0`.
6. For top-level expected failures, bind the exact result kind, return code,
   stdout marker, and stderr marker.
7. Derive compile selectors by joining every `intro-tests.json` dependency ID
   to one `intro-targets.json` record and compile the unique `name:type`
   projection at a bounded job count before `meson test --no-rebuild`.

## Validation

The pkgconf 3.0.5 source contains 425 unique fixture keys. Two complete raw
logs exposed exactly the same key set, and the unified selector bound one real
PASS to each key. The result was 425/425 fixtures plus 15 API tests, one OOM
test, 141 parser inputs, three solver inputs, and one exact expected-failure
negative: 586/586 with zero skipped or failed official entries.

Meson introspection joined 23/23 dependency IDs to 23 unique `name:executable`
selectors, including all four command executables used by fixture suites. A
19-case production-recipe matrix passed both exact raw shapes and rejected:

- unexpected `PASS`, `SKIP`, or `FAIL` terminals;
- missing or duplicate fixture terminals;
- duplicate top-level names;
- expected-failure return-code and marker drift;
- missing, duplicate, incomplete, colliding, or malformed target projections.

## Safety Boundaries

- Do not reduce the official inventory to only one platform's passed subset.
- Do not claim a skip as a pass and do not sum repeated complete-run totals.
- Every selected PASS must use the same official source and candidate snapshot.
- Local upstream closure does not authorize W3, device access, push, PR, CI,
  submission, or artifact upload.
