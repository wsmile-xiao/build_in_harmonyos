# E337 - Reproducible Autotools bootstrap for a source snapshot with gnulib

> Contributor: 2301_79503900 | Status: DRAFT | Created: 2026-08-27
> Knowledge draft path: `knowledge/drafts/E337-draft-2301.md`

## Scope

Use this pattern when an Autotools project is obtained from a Git tag or
development snapshot rather than a generated release archive. The source tree
may omit `configure`, `aclocal.m4`, `Makefile.in`, or generated gnulib files and
expect its `bootstrap` script to assemble them from a matching gnulib tree.

This draft is about making that bootstrap reproducible inside a Conan recipe.
It does not replace E007 for HarmonyOS triplet recognition, E011/E223 for
HMDFS temporary-directory behavior, or E058 for the general symptom of missing
generated Autotools files.

## Problem

The source tag can look versioned and complete while the first build fails
before compilation:

```text
configure: No such file or directory
bootstrap: failed
aclocal: command not found
automake: command not found
gnulib: not found
```

For recode 3.7.15, the official tag is a Git tree without the generated
Autotools output. Its bootstrap process also needs a matching gnulib snapshot.
The target build image did not provide the complete Automake/Libtool/gettext/m4
bootstrap set, so an implicit host-tool dependency would not be reproducible in
CI.

## Diagnosis

Before changing the recipe, inspect the source tree and bootstrap metadata:

```sh
test ! -f configure
test -f configure.ac
test -f bootstrap
test -f bootstrap.conf
grep -n 'gnulib\|autopoint\|automake\|libtool' bootstrap bootstrap.conf
```

If generated files are absent and bootstrap references gnulib, the source tag
and gnulib revision are a coupled input. A successful local bootstrap using a
different globally installed gnulib is not evidence that CI can reproduce the
same generated sources.

## Recommended solution

1. Put the official source tag URL, the exact gnulib commit archive URL, and
   both SHA-256 values in `conandata.yml`.
2. Declare every bootstrap tool missing from the target image as a Conan
   `tool_requires` entry. For recode this includes Automake, Libtool, gettext,
   and m4; the recipe explicitly selects the available Autoconf-family tools.
3. Set the bootstrap environment to the pinned gnulib directory. Do not let
   the script discover an arbitrary system copy.
4. Make feature switches consistent. If NLS is disabled, use the bootstrap
   option that skips po generation and remove unconditional `po/Makefile.in`
   generation from the project metadata. Keep the library and CLI targets
   enabled.
5. Run the normal Conan Autotools configure after bootstrap. For recode, build
   `lib` before `src/recode` because the latter consumes generated headers and
   the generated `libgnu.la` output.
6. Install and test the package through Conan. The consumer must call a real
   public API; configure-only or empty executables do not validate the package.

The minimal shape is:

```python
def source(self):
    get(self, **self.conan_data["sources"], strip_root=True)
    get(self, **self.conan_data["gnulib"], strip_root=True,
        destination=os.path.join(self.source_folder, "gnulib"))

def build(self):
    self.run("./bootstrap --skip-po --copy", cwd=self.source_folder,
             env="conanbuild")
    Autotools(self).configure()
    Autotools(self).make(args=["-C", "lib", "all", "-j1"])
    Autotools(self).make(args=["-C", "src", "recode", "-j1"])
```

The actual recipe must also pass the explicit tool paths and handle the
target's platform probes; the snippet is an ordering example, not a universal
copy-paste recipe.

## Verification

Use separate evidence for each stage:

```sh
python -m py_compile archives/r/recode/3.7.15/conanfile.py \
    archives/r/recode/3.7.15/test_package/conanfile.py
conan create archives/r/recode/3.7.15 \
    -pr:h=ci/conan/profiles/ohos-aarch64 \
    -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```

For recode 3.7.15, the formal Conan build and consumer test completed on a
HarmonyOS PC AArch64 target. The unmodified upstream modules and harness then
executed 496/496 tests on the target through the final packaged CLI; the former
`t70_inferenz.py/test_1` failure also passed after the explicit `libiconv/1.17`
runtime dependency was added. The exact log and artifact hashes are recorded
in the version notes and device report.

## Boundaries and prohibited shortcuts

- Do not call a Git snapshot a self-contained release archive when generated
  files are absent.
- Do not use an unpinned or unrelated gnulib tree, or silently depend on tools
  installed outside Conan.
- Do not hand-write `configure` or commit generated output merely to hide a
  bootstrap failure; use an approved checksummed generated-file archive only
  when the worker cannot bootstrap.
- Do not treat `--disable-nls` as sufficient if the generated make graph still
  enters `po`.
- Do not build dependent source targets before generated library headers and
  archives exist.
- Conan create, consumer linkage, target execution, CI, and publication are
  separate claims.
