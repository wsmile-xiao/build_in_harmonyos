# E2167: Separate auxiliary observers from native consumer terminal results

> Status: DRAFT | Contributor: 2301 | Date: 2026-08-28

## Symptom

A target validation run can execute the native core, invalid-input, audio, and
video consumers while an optional screenshot or management acknowledgement is
missing. A validator that treats that observer as another consumer, or accepts
stage fields without the authoritative terminal receipt, can change the
reported four-consumer result.

## Root Cause

Screenshots and management acknowledgements are observation or transaction
control contracts. They do not exercise the product's native audio or video
paths. Combining their state with the consumer denominator makes observer
timeouts look like consumer failures and allows unbound local output to look
like a completed run.

## Fix

Define the consumer set and denominator before execution. Emit each consumer
stage only after the production operation completes, record optional observers
as `NOT_REQUIRED` or `NOT_RUN`, and accept the final count only from a terminal
receipt bound to the same run identity and input snapshot.

## Validation

The SDL2 host contract executed the four ordered consumer stages and returned a
terminal receipt with `consumers=4`, `snapshot=NOT_REQUIRED`, and no observer
calls. The validator rejected a result assembled from observer timeout text or
from historical upstream evidence.

## Scope and Safety Boundary

This rule applies to API-level UI hosts, multimedia or graphics adapters, and
target runners that combine native capability checks with optional screenshots
or external management channels. It does not prove target-device rendering or
audio output, and it does not authorize replacing an incomplete target run with
host evidence or historical upstream results.
