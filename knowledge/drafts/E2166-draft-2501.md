# E2166 draft: GNU glob flags can fail after `glob()` detection

Status: draft. Contributor: 2501_91199785. Source: libcvd commit
`30e8cfc1697048c7d8fb48e0b7853a4e2b4b9867` on HarmonyOS PC arm64.

## Symptom and cause

The project correctly detected `glob()` but compiling
`cvd_src/globlist.cxx` failed because `GLOB_BRACE` was not declared. A
function-level CMake check does not establish availability of GNU extension
flags in `<glob.h>`. The existing knowledge comparison already records that
`GLOB_BRACE` is absent from musl; this draft adds the tested build-system
remedy, rather than restating that platform fact.

## Reusable procedure

1. Identify whether the upstream source has a supported branch that calls
   `glob(pattern, 0, ...)` or otherwise avoids extension flags.
2. If it exists, enable that branch through the build configuration. For
   libcvd, set `CVD_INTERNAL_GLOB_IS_BAD=ON`; its configured
   `config_internal.h` selects the zero-flags path without a source patch.
3. Build on the actual target and run the full enabled upstream suite plus
   an independent package consumer. Do not treat configure success as proof.

The zero-flags path does not provide brace or tilde expansion. Libraries
whose public API promises those extensions need separate behavioral tests
and a different remedy; this draft does not claim semantic equivalence.

## Evidence

- Before: `GLOB_BRACE` undeclared at `cvd_src/globlist.cxx:26` on the target.
- After: the package built as `libcvd.so` with JPEG, PNG and TIFF enabled.
- Target execution: CTest `5/5` passed; Conan `test_package` linked and ran.
- The adapted package changed CMake configuration only, not upstream tests
  or source files.
