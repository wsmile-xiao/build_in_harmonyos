# E566 — KF6 QML 绑定模块不在仓时的应用侧等价替代链

## 错误特征

```
qrc:/qt/qml/org/kde/kirigamiaddons/formcard/AboutPage.qml:12:1:
    module "org.kde.coreaddons" is not installed
qrc:/qt/qml/org/kde/alligator/Main.qml:41:9: Type FormCard.AboutPage unavailable
```
以及配置期：
```
CMake Error: ... Could NOT find KF6I18nQml
```

## 根因

制品仓 KF6 框架包普遍未构建 QML 绑定层：

| 缺失物 | 上游位置 | 影响 |
|---|---|---|
| `KF6::I18nQml` target（KLocalizedQmlContext、KLocalization::setupLocalizedContext） | ki18n `src/i18n-qml/` | KDE QML 应用 main.cpp 标配链接项 |
| `org.kde.coreaddons` QML 模块（AboutData/KTextToHTML 单例） | kcoreaddons `src/qml/`（配方 `KCOREADDONS_USE_QML=OFF`） | Main.qml import org.kde.coreaddons |

**双重陷阱**：应用自身的 import 会失败之外，kirigami-addons 的 `FormCard.AboutPage.qml`
自身也无条件 `import org.kde.coreaddons`（其 qmldir `depends org.kde.coreaddons`）——
应用只要引用 FormCard.AboutPage 就触发 QML 编译期失败，即使应用自己不 import。

## 修复方案（两步等价替代）

1. **C++ i18n 上下文**：用在仓 ki18n 的前代 `KLocalizedContext`（配 E565 弃用宏解除），
   从 target_link_libraries 移除 KF6::I18nQml
2. **QML About 页**：绕开 FormCard.AboutPage，改用 kirigami 自带 `Kirigami.AboutPage`
   （无 coreaddons 依赖）+ 官方支持的 JSON `aboutData`（与 KAboutData 同 shape）
3. **附带**：QQuickStyle 从 org.kde.desktop 回退 "Basic"（qqc2-desktop-style 也不在仓），
   保留 QT_QUICK_CONTROLS_STYLE 环境变量覆盖能力

## 红线

- `depends` 声明（qmldir）与显式 `import` 的失败语义不同：depends 缺失不报错，import
  缺失才是硬失败——定位时看真实 import 的模块
- 修复必须落在 patch（进 PR 归档），不要在 conanfile 里 replace 源码（PF5 拦 replace 注入）
- 根治是框架配方侧补建 QML 组件（kcoreaddons KCOREADDONS_USE_QML=ON / ki18n i18n-qml），
  应用侧替代是过渡方案
