# E8983 — 发行包含完整解析器时，强制工具探测不等于真实生成依赖

## 通用触发条件与根因

稳定 C/C++ 发行归档已经包含 lexer/parser 的生成 C 文件及匹配头文件，
但 `configure.ac` 在 `AC_PROG_LEX` / `AC_PROG_YACC` 后仍无条件要求
某个生成器名称，错误签名为 `could not find required installation of FLEX`
或 `could not find required installation of BISON`。

不能仅因源码包存在 `configure` 就认为构建无生成器依赖，也不能把这个
报错当作生成 C 缺失的证据。必须分开检查归档内容、生成规则和生产链接清单。
这里阻塞的是 configure 的硬性工具名称探测，不是文件时间戳触发再生成。

## 可复用处置与边界

1. 绑定官方稳定发行归档、版本与 SHA-256，不混用 GitHub 标签快照或其他版本输出。
2. 核对每一份 grammar 对应的 lexer/parser C 与头文件成对存在，核对全部生产
   翻译单元、链接依赖、实际使用的配置宏以及安装清单。
3. 若确实无需改 grammar，可直接编译同一归档的完整生成物，补齐构建配置与
   安装契约；不替换解析算法、不减少生产源，也不调用不存在的生成器。
4. 保留所有注册上游测试。新增安装后测试须分别声明，覆盖解析、生产算法、
   输出和坏输入，不能伪装为上游测试或据此证明没有盘点过的上游分母。
5. 生成物缺失、grammar 已修改、头文件不配对、生成器版本具有 ABI 差异时，
   本方法不适用；生成器是实际依赖，必须先完成 W0，而不是加空壳或忽略失败。
