# E2168: Reinitialize Conan source trees before ordered patch replay

> Status: DRAFT | Contributor: 2301 | Date: 2026-08-29

## Symptom

The first CI run applies an ordered patch set, fails later in the build or test
phase, and a retry with the same recipe revision fails in `source()` with
`hunk ... doesn't match source file`. The retry is using a shared Conan home
whose source directory already contains the previous patch postimage.

## Root Cause

Conan can invoke `source()` again against the same recipe-cache directory after
an incomplete run. If extraction does not restore the official preimage, the
next `apply_conandata_patches()` call re-applies a patch to already transformed
bytes. Strict `patch_ng` additionally requires hunk offsets that include every
structural line and an explicit representation for blank records. A local GNU
patch replay that tolerates offset or whitespace differences is not evidence
for the Conan call path.

## Fix

1. Preserve the failed cache and identify the exact official source preimage.
2. Reproduce the patch from that preimage, recalculating hunk offsets after all
   preceding patches.
3. Keep blank lines as standard unified-diff context. If an explicit blank
   replacement is unavoidable, verify the exact parser behavior rather than
   assuming an application return code is a replay detector.
4. Use a new recipe revision or an explicit source-tree reset so each retry
   starts from the official preimage rather than a partial postimage.
5. Replay the complete ordered patch set with `patch_ng 1.19.1`,
   `strip=0,fuzz=False`, and compare the final postimage hashes.

## Validation

For SDL2 2.32.10, the corrected 0016 patch applied with `patch_ng 1.19.1`
under `strip=0,fuzz=False` and produced the expected `SDL_egl.c` SHA-256
`9ad67c7e765d2950a54f5ff63c7078edae88c0be9e62595568d6a2c2cd0628dd`.
GNU `patch --dry-run --forward -p1` and the outer `git diff --check` both
passed. A second `patch_ng.apply()` call returned success but left the
postimage hash unchanged, so the boolean return value is not a sufficient
replay detector; the fail-closed control is a fresh source root or recipe
revision before every ordered replay. The CI failure that motivated this
entry was observed at 0016 replay in build #34279 after an earlier build
reused the same source-cache identity.

## Scope and Safety Boundary

This knowledge applies to Conan recipes whose ordered patches are replayed in
reusable CI or local caches. It does not authorize reverse-patching a failed
tree, accepting fuzzed output, deleting another task's cache, or treating a
patch replay pass as a build, upstream-test, device, or publication pass.
