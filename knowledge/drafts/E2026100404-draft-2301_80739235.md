# 补充至 PR #5346：HMDFS 文件服务归属投影不能替代进程身份或实际访问验证

## 适配场景与通用触发特征

在共享或服务投影文件系统中，私有消费者成功写入文件，但
`stat().st_uid != getuid()` 触发失败。不要从不相等直接推断无权限，也不要
从属主或 chmod 推断可读、可执行；存储身份与进程身份属于不同校验域。

## 既有知识与本次增量

本草稿补充原 PR #5346 的 E488。原条目覆盖 Python 扩展 dlopen 因服务属主与
受限权限失败，并区分可读本地环境与不可读 CI 环境。本次提供反例与判定边界：
由当前进程新建的 HMDFS 文件也显示文件服务属主，但实际写入、完整读回与
签名共享库消费者均可成功；不应把进程/文件 UID 相等提升为通用准入条件。
既有 libgit2 owner-validation 草稿讨论库内安全检查，本草稿不关闭它或
`safe.directory`，而是建立测试身份域及实际访问验证合同。

## 根因与可复用修复步骤

1. 保留进程 UID、boot_id、PID/start 和唯一 launch 的独立身份校验。
2. 只操作冻结的任务私有根，读回父目录的文件系统属主；独占创建新 fixture，
   不覆盖同名文件，不硬编码 `file_manager` 数值。
3. 比较新文件与私有父目录的存储身份，并验证写入长度、逐字节读回、
   实际被测功能与清理。动态代码另须 native 自签及真实 loader 成功。
4. 已消费的失败 run 保留 FAIL。代码或测试改变后创建完全重绑定的 successor，
   不把旧日志拼接成 PASS。

## 无效尝试与安全边界

`st_uid == getuid()` 的假设在 r001/r002 导致假失败。简单删除所有归属检查、
硬编码20001006、对系统目录chmod或忽略读回都不正确。只在已证明的投影
文件系统内使用此决策；不处理无权读取的文件，不更改系统用户或其他任务。
原生测试不等于正式平台 CI/AI Review/提审通过。
