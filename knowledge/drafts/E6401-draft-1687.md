# E6401 — 旧式 C 测试程序用 `char` 承接 `getopt()` 返回值 → OHOS aarch64 上 EOF 哨兵截断失效，测试程序直接退出

> 草稿（draft，待主编审核转正为 `E6401.kv`/`doc/E6401.md`）
> 贡献者：GaoPengqiang <GaoPengqiang@noreply.gitcode.com> ｜ Agent：1687 ｜ 日期：2026-09-26

## 使用说明

适用场景：**上游确实提供了测试程序（`EXTRA_PROGRAMS`/`check_PROGRAMS`/独立 test 二进制），但一键运行后一条用例都没跑、只打印了 usage 然后非 0 退出**。

三步使用：

1. **识别**：构建日志里出现 `Failed with: Invalid parameter`（该程序的用法说明紧跟其后打印），且**看不到任何 `... ok` 用例行**。
2. **自检**（确认是否为本模式，30 秒）：
   ```bash
   grep -n -E '^[[:space:]]*char[[:space:]]+[A-Za-z_][A-Za-z0-9_]*[[:space:]]*;' <test-src>.c   # 是否用 char 接 getopt 返回值
   grep -n 'getopt' <test-src>.c                                                              # 同文件是否在用 getopt
   <test-binary> -h ; echo "rc=$?"                                                            # 正常应打印用法并 rc=0
   ```
   两条 grep 同时命中 → 按本条目处理。
3. **修复**：把该局部变量改为 `int`（以 `patches/` 固化），重新构建并重跑。**不要**改测试输入、断言或判定标准。

## 适用范围

- **适用**：C 语言、旧式 `getopt()`（单字符选项解析）驱动的测试程序；尤其 autotools 工程里由 `EXTRA_PROGRAMS`/`check_PROGRAMS` 声明、在 `build()`/CI 中手工 `make <target>` 后执行的 test harness。平台侧：OHOS aarch64（本条目实测平台），以及任何 `char` 的有效宽度/符号性使 `EOF` 哨兵无法往返还原的 ABI/编译选项组合。
- **不适用**：
  - 测试程序打印了 `... ok` 用例行而只是个别用例失败（那是真实测试失败，不是本模式）；
  - 使用 `getopt_long()` 且返回类型本就是 `int` 的现代写法；
  - 因缺少 fixture（口令库、服务端、端口）而失败——那属于环境/依赖问题。
- **边界**：本条目**只解释"整轮用例 0 执行"**这一现象；修复后仍可能有真实用例失败，需另行分析。

## 错误特征

```
Usage:
 testsuite [-g name] [-s seed] [-r tests] -a -M
    g -- gssapi service name to use (default: host)
    ...
Failed with: Invalid parameter
```

关键点：usage 说明**紧跟** `Failed with: Invalid parameter`，且整个运行过程里**没有任何** `... ok` / `... skipped` 用例行。这与"测试真跑但失败"的输出形态完全不同。

## 触发条件

| 维度 | 值 |
|---|---|
| 语言/工程 | C；autotools（`utils/Makefile.am` 的 `EXTRA_PROGRAMS`）或任何手工构建的测试二进制 |
| 触发代码 | `char c; while ((c = getopt(argc, argv, "…")) != EOF) { … default: usage(); fatal("Invalid parameter"); }` |
| 阶段 | testing（`build()` 内 `make testsuite` + 执行） |
| 平台 | OHOS aarch64（实测必现）；其它平台可能偶然正常 → 上游 CI 发现不了 |

## 输入输出定义

- **输入**：① 构建日志（含测试程序 stdout/stderr 与退出码）；② 测试程序源码（用于确认 `char` + `getopt` 组合）；③ 平台/编译器（`os`/`arch`/`compiler`）。
- **输出**：
  - **判定**（三态）：`命中本模式` / `非本模式（附排除依据）` / `证据不足`；
  - **修复物**：一个只改局部变量类型的补丁（`patches/000N-*.patch`），可选同款 sed 命令；
  - **复核**：修复后重新运行测试程序的**逐用例统计**（总数/通过/失败/跳过），以及"是否仍为 0 执行"的对照。
- **不产出**：任何对测试断言/输入/通过标准的改动。

## 根因分析

`getopt()` 规定返回 `int`：返回选项字符，或 `-1`（`EOF`）表示选项解析结束。旧式代码常写成 `char c;` 承接返回值，随后用 `c != EOF` 判结束。

在 OHOS aarch64 上，这个 `int → char` 赋值把 `-1` 截断/转换后，**不再与 `EOF` 比较相等**（平台 `char` 的符号性/有效宽度使哨兵无法往返还原），于是：

1. 选项解析循环**永不因 EOF 终止**；
2. `getopt()` 在参数耗尽后返回 `-1`（或 `'?'`），被转成某个不在选项表里的字符 → 落入 `switch` 的 `default:`；
3. `default:` 打印 `usage()`，然后 `fatal("Invalid parameter")` 退出。

结果：**测试程序存在、命令 rc≠0、但一条用例都没执行**。若只看"有没有测试文件"就会误判为"上游无测试"，进而把整轮统计报成 0 执行或伪造通过。

> 上游为什么没发现：该代码在 `char` 为有符号且宽度足够的平台上恰好能工作，缺陷只在特定 ABI/平台暴露。

## 解决方案

### 推荐方案（priority 1）

- **方案**：`char` → `int`，只改局部变量类型；以 `patches/` 固化。
- **命令**：
  ```bash
  sed -i 's/^\([[:space:]]*\)char c;/\1int c;/' utils/testsuite.c
  ```
  建议写成补丁文件（`patches/000N-testsuite-use-int-for-getopt.patch`）以便审计与复现。
- **验证**：修复后测试程序进入正常用例流程，输出逐阶段 `... ok`，退出码 0。

### 回退方案（priority 2）

- 若审阅口径**禁止**改动上游测试源：**不得伪造通过**。应如实申报该 harness 未运行（0 执行、未覆盖哪些阶段），并以消费者侧测试（`test_package`）覆盖被测包功能，在 PR 的"上游测试用例修改说明/验证结果"中写明差异。

### 禁止策略

| # | 禁止 | 原因 | 后果 |
|---|---|---|---|
| 1 | 继续用 `char` 承接 `getopt()` 返回值 | OHOS aarch64 上必现整轮用例不执行 | 上游测试统计失真（0 执行却宣称已覆盖），R51 判 P1 |
| 2 | 把 `Failed with: Invalid parameter` 当作"测试通过" | 这是参数解析崩溃，不是通过 | 伪造测试结论，P0 |

## 示例

被测实例：`cyrus-sasl` 上游 2.1.28 的 `utils/testsuite.c`（`EXTRA_PROGRAMS` 中的 `testsuite`）。

**修复前**

```console
$ make testsuite && LD_LIBRARY_PATH=lib/.libs SASL_PATH=plugins/.libs utils/.libs/testsuite -a
Usage:
 testsuite [-g name] [-s seed] [-r tests] -a -M
    ...
Failed with: Invalid parameter        ← 用例数 0
```

**补丁**

```diff
--- a/utils/testsuite.c
+++ b/utils/testsuite.c
@@ -2939,7 +2939,7 @@
 int main(int argc, char **argv)
 {
-    char c;
+    int c;
     int random_tests = -1;
     int do_all = 0;
     int skip_do_correct = 0;
     unsigned int seed = (unsigned int) time(NULL);
```

**修复后**（同一命令，逐阶段用例正常）

```console
$ utils/.libs/testsuite -a -s 1
Checking plaintext passwords... ok
Random number functions... ok
Testing base64 functions... ok
Testing auxprop functions... ok
Tests of sasl_{server|client}_init()... ok
Testing sasl_listmech()... ok
Testing serverstart...ok
...（机制协商 8 组 + All corruption tests... ok + Proxy Policy + security layer）
All tests seemed to go ok (i.e. we didn't crash)
```
