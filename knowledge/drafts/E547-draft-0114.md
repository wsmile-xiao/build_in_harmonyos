# E547（草稿）：OHOS 无 libudev——udev 设备枚举依赖的 stub-libudev 适配模式

> 来源：libfido2 1.15.0 适配（feat/libfido2-1.15.0，calbee21，2026-09-04）
> 状态：草稿（DRAFT，待人工审核 promote）

## 适用场景

上游为 Linux 编写、通过 libudev 枚举设备的外设类库移植到 OHOS/HarmonyOS PC：
- libfido2（FIDO2 认证器，`src/hid_linux.c` 用 udev_enumerate 扫 hidraw）
- hidapi（hidraw 后端）
- pcsc-lite / acsccid（智能卡读卡器）
- 任何 `pkg_search_module(UDEV libudev REQUIRED)` 的 CMake 项目

## 错误特征

```
fatal error: 'libudev.h' file not found
Could NOT find UDEV (missing: UDEV_LIBRARY UDEV_INCLUDE_DIR)
pkg_search_module(UDEV libudev REQUIRED) → FATAL
undefined reference to `udev_new`
```

## 根因

OHOS 不提供 libudev（无 systemd/udev）。**协议栈/加密/CLI（纯计算逻辑）与
设备发现（平台强相关）是两个独立关注点**：前者可完整移植+上游测试验证，
后者必须平台化（HID-DDK 或 /dev/hidraw 直连）。

## 推荐方案：static-inline stub-libudev.h

参考实现：`archives/l/libfido2/1.15.0/patches/`（0001 + 0004）

1. 新增 `src/stub-udev/libudev.h`：为上游用到的**每个** udev API 提供
   static-inline stub——`udev_new()` 返回 NULL、枚举函数返回 -1/NULL、
   `udev_list_entry_get_next` 返回 NULL（foreach 宏自然终止）
2. CMakeLists 加 HarmonyOS 分支：`set(NFC_LINUX OFF)` + include stub 目录
   + 跳过 `pkg_search_module(UDEV ...)`
3. `BUILD_TESTS=ON` 跑上游纯逻辑 regress（libfido2 7/7）验证协议栈完整
4. **R40 强制**：notes.md 显式记录设备发现降级并标注需人工确认

## 关键红线

- ❌ `#define udev_new() return 0`——指针 API 返回 0 非 NULL → 调用方解引用崩溃
- ❌ `#ifdef __OHOS__ return 0; #endif` 空壳（R8）
- ✅ 每个 stub 保持失败语义（NULL / -1），foreach 宏因 get_next=NULL 自然退出
- ❌ 不推荐 stub-udev.c 独立 .a + target_sources 注入（hidapi pr-547 五轮修复
  未收敛后整体回滚的教训）——头文件 inline 方案零构建系统干预
