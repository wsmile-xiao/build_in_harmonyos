# 补充至 PR #9499（E571）：测试框架环境修复后须隔离选择器并核对注册与运行身份

## 适配场景与精确根因

跨平台测试在临时目录修复后仍可能少跑甚至零跑。继承的选择环境改变
真实运行清单，而测试进程 RC0 或一个百分比不绑定原始注册分母。
外层一个测试程序也不能替代框架内部用例数。

既有 E571（已合并 libtsm PR #9499）已证明 Check 首选 TEMP，不需要
私有重建。该机理不是本条新增贡献。本轮先沿用它修复真实失败，再增加
一个独立的覆盖闭包：环境选择隔离、原源注册清单和目标运行 XML 身份相等。

## 可跨软件复用的修复步骤

1. 确认框架的临时目录取值逻辑，将最高优先变量绑定任务私有路径。
   不用“设置过 TMPDIR”推断所有框架都会遵从。
2. 清除继承的用例/标签选择器及 fork 覆盖值，保留框架原本的默认隔离。
   只显式设置该次结构化输出路径；不修改原测试源或框架二进制。
3. 盘点真实注册 ID，而不是凭测试源个数或外层入口猜分母。要求 XML
   执行 ID 和原注册 ID 双向相等、唯一数相等、全部成功，且 RC 和精确
   整行摘要均匹配。未执行、未知、重复、过滤或缺结果均 fail closed。
4. 分别记录入口数、框架用例数、消费者和平台专项，不混用分母。
   API 名为 skip 的协议功能用例可以执行成功，不能直接判为框架跳过。

## 适用、不适用与安全边界

适用于注册型、存在选择环境及结构化输出的第三方框架。对动态注册应
使用框架官方运行时清单，不强套此例的简单源码正则。无法控制子环境
或无法确认真实分母时，保留 UNKNOWN/FAIL，不降低隔离或删除用例。
不得由 XML fixture 的宿主控制声称目标框架 PASS，不应修改共享工具、
重建已可用 provider 或把原生结果当平台 CI/提审成功。

证据根：F:/HarmonyPC/pr-review-closure-20261004-r1；W3 r002 的冻结
validator、snapshot-009.json；subunit-upstream-directed-controls-r001.json。
本 PR 为 #13626；知识补充对象为 #9499，二者不混淆。

## 补充：动态子案例与多组件报告主表

原框架加载清单不必等于实际结果数。协议执行包装器可能把控制权交给
原Shell或子协议，并透传多个独立案例。真实check-local加载526个入口，
其中三个包装器产生12个子案例；逐项核对后运行分母为526-3+12=535，
每个ID恰好start→success→stop，没有失败或跳过。原stdout SHA-256为
8ec8a20fc3a7954a0a321a27f524c646f4023f1d3423408d70489dece2d7470a。

可复用步骤：保留原加载清单与原运行事件；识别被子协议替代的包装器，
按框架实际传递的唯一结果ID及生命周期判定，不重复累计包装器。
多语言组件的完整覆盖须同步到报告主表、验证结果与附录，不能主表只填
一个组件而把其他已执行入口藏在补充段。C6与Python/Shell535分别保留
各自完整原始事务；541只是非重复覆盖清单合计，不拼接事务阶段，不生成
虚假的单次541项W3回执，也不能由这个覆盖合计声称平台CI通过。
