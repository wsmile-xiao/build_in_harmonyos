# E430 — 从未被编译过的 header-only 上游库：clang 解析期急切检查非依赖构造，include 即编译失败（GCC 不暴露）

## 错误特征

```text
In file included from test.cpp:1:
<pkg>/include/tnt_sparse_matrix_csr.h:97:3: error: no matching constructor for initialization of 'Array1D<int>'
                rowptr_(M, r), colind_(nz, c), dim1_(M), dim2_(N) {}
```

- **关键判别**：报错**没有** `note: in instantiation of ... requested here`
  注记 → 解析期错误，不是实例化期——即使 main 为空、即使没人用这个类。
- 变体：链接期 `ld.lld: error: undefined symbol: TNT::Stopwatch::running()`
  （编译过、一调用就 undefined）。

## 触发条件

- 构建系统: 任意（header-only 库，问题在头文件本身）
- 阶段: 消费者编译 / 链接
- 库形态: 上游无测试、发行版仅安装头文件从不编译的老库
  （实例：NIST TNT 1.2.6，Debian libtnt-dev 数十年 arch-all 只拷贝头文件）

## 根因分析

两类上游潜伏缺陷，只在 clang + 真实编译消费时暴露：

1. **解析期急切检查**：类模板成员定义中，**非依赖类型**成员的构造
   （如 `Array1D<int> rowptr_` 从 `(M, const int*)` 初始化）被 clang 在
   模板定义解析时立即检查；GCC 延迟到实例化，故 GCC 时代从未暴露。
   上游重载只有 `Array1D(int, T*)`（丢 const）与 `(int, const T&)`
   （类型不符）→ include 即报 no matching constructor。
2. **悬空声明**：声明未定义的成员（`Stopwatch::running()`、
   `Sparse_Matrix_CompRow` 的 copy ctor/operator=）编译通过，链接期
   undefined symbol。

## 解决方案

### 推荐方案

适配 header-only 老库先跑两级探针，再决定补丁或规避：

```bash
# ① 编译探针：暴露解析期错误（含空 main）
printf '#include <tnt.h>\nint main(){return 0;}\n' | \
  clang++ -x c++ -std=c++17 -stdlib=libc++ -I<pkg>/include -fsyntax-only -

# ② 链接探针：逐组件实例化并链接（暴露悬空声明）
clang++ -std=c++17 -stdlib=libc++ -I<pkg>/include probe.cpp -o probe && ./probe
```

- 解析期错误 → 打最小补丁（改签名匹配既有重载；libtnt 0001 补丁
  仅去 3 个参数的 const）；
- 悬空声明 → 不打补丁（无实现可改），test_package 规避该调用，
  notes.md/MANIFEST.yml 显式声明消费者不可用。

### 禁止做法

- ❌ 看到编译错误先怀疑自己 test_package 写错而反复盲改（先跑空 main
  探针分辨上游/自身）
- ❌ 为悬空声明手工补"合理实现"（数值库无测试保护，发明实现=引入
  未验证代码）
