# 随包 autoconf 2.13 configure 的三个专有坑（命令行 VAR=value、--datarootdir、字面 CXX=g++）

> Draft: E717
> Stem: `E717-opt-3.19-autoconf213-bundled-configure` — pairs with the same-stem `.kv`

## 基本信息

- **ID**: E717
- **严重度**: 2
- **类别**: build-system-autotools
- **触发工具**: conan|configure|make
- **阶段**: configure|build

## 错误特征

```
invalid host type|can only configure for one host|invalid option; use --help|Generated automatically using autoconf version 2\.13
```

2004 时代项目（如 OPT 3.19）随包 `configure` 是 autoconf 2.13 生成，与现代
autoconf（2.69/2.71/2.73）行为不同，三条实测差异：

1. **命令行 `CFLAGS=...` / `CXXFLAGS=...` 赋值不被识别**——2.13 的参数解析只认
   `--*` 与 BUILD/HOST/TARGET 位置参数，`VAR=value` 会被当 host type：
   `configure: warning: CFLAGS=-O3: invalid host type` →
   `configure: error: can only configure for one host and one target at a time`，**rc=1**。
   现代 autoconf 都能吃 `./configure CFLAGS=...`，照抄必炸。
2. **`--datarootdir=` 是 invalid option**（2.60 才引入）。Conan `AutotoolsToolchain`
   默认注入 `--datarootdir=${prefix}/...`，对 2.13 直接 `invalid option` 硬失败 →
   不能用 `Autotools.configure()`，configure 调用必须由配方自持。
3. **`configure.in` 末尾的字面 `CXX=g++` + `AC_SUBST(CXX)`** 把 `CXX = g++` 固化进
   全部生成的 Makefile；configure 期传 `CXX=clang++` 只能让 `AC_PROG_CXX` 探测通过，
   **覆盖不了 AC_SUBST 的结果**，make 时仍报 `g++: No such file or directory`。

同类包判据：`head -5 configure` 出现 `autoconf version 2.13`；这类包通常没有
`AC_CANONICAL_HOST`（连 `config.sub`/`config.guess` 都没有），反而**不需要**
config.sub/guess 陈旧族补丁。

## 解决方案

**主方案**: env-prefix-plus-make-line-double-pin-never-autoreconf

配方口径（OPT 3.19 落地形态）：

- **绝不 autoreconf**（任务卡口径 + 2005 时代工具链再生必炸，config.sub/guess 族先例同源）；
- 标志走**环境前缀**注入 configure：`umask 022 && CC=… CXX=… CFLAGS='…' CXXFLAGS='…' ./configure --prefix=/`，
  并在 make 行**再钉一次**（`autotools.make(args=["-j1", "CXX=…", "CFLAGS=…", "CXXFLAGS=…"])`）；
- `CXX=clang++` 必须在 **make 行**覆盖（configure 期只解决探测）；
- configure 后清点 `AC_OUTPUT` 产物（rc=0 假绿双阶段核对，先例 #9）。

## 验证

```sh
# 复现：命令行 CFLAGS 赋值 → invalid host type（rc=1）
sh -c 'd="$HOME/tmp/opt-3.19/w0"; rm -rf "$d/repro-e717"; mkdir -p "$d/repro-e717/b" "$d/repro-e717/home"; \
  tar -xzf "$d/dl/c1.tar.gz" -C "$d/repro-e717"; cd "$d/repro-e717/b"; \
  HOME="$d/repro-e717/home" CC=/data/service/hnp/bin/clang ../opt-3.19.orig/configure --prefix=/ \
  "CFLAGS=-O3 -pipe -DNDEBUG"; echo "rc=$?"'
# 预期：configure: warning: CFLAGS=…: invalid host type；rc=1
# 正解证据（环境注入已把值烤进 Makefile）：
sh -c 'grep -n "^CFLAGS = " "$HOME/tmp/opt-3.19/w0/probe3/b/src/Makefile"'
```

## 关联条目

- config.sub/config.guess 陈旧族（先例 #1）：同为老 autotools 问题，但触发面是
  **host 判别**；本条覆盖「参数/变量注入语义」差异，两者互补。
- 先例 #7（CC/CXX 显式化）：本条是它的加强形态——显式还不够，必须在 **make 行**覆盖。
