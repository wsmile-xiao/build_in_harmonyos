# E338 - Gate portability-sensitive tests with production capability probes

> Contributor: 2301_80739235 | Status: DRAFT | Created: 2026-08-28

## Scope

Use this pattern when a test exercises optional filesystem, local IPC,
permission, or asynchronous notification semantics on a sandboxed or embedded
target. It applies across libraries and test frameworks when the API exists but
the target may not provide its full runtime contract.

It does not apply to a mandatory product requirement, an unknown error, or a
general test-suite failure. Those must remain failures until their cause is
understood.

## Symptom

The test suite builds successfully, but a small set of tests abort with
`EPERM`, report a mode mismatch after `chmod()`, or consume the harness timeout
while waiting for a callback or child process. A descriptor-only socket probe or
an euid/privilege check may report support even though the operation used by the
test is denied.

## Root cause

Availability of a function such as `socket()`, `chmod()`, or an event source is
not equivalent to the semantic capability that the test asserts. Restricted
filesystems may reject `bind()` or silently project permissions, and a missing
notification backend can leave an unbounded main-context loop waiting forever.
This turns an environmental limitation into a false product regression and
delays the whole CI job.

## Recommended solution

1. Implement a small probe that performs the exact operation under test, such as
   binding a temporary Unix socket or setting and querying a temporary file mode.
2. Cache the probe result for the test process and classify only documented
   capability errors (`EACCES`, `EPERM`, `EROFS`, `ENOSYS`, `ENOTSUP`, or
   `EOPNOTSUPP`, as appropriate for that operation).
3. Run the normal assertions when the probe succeeds. When it fails with a
   classified capability error, skip only the dependent contract and preserve
   unrelated tests.
4. Replace callback, trap, and child waits with a finite monotonic deadline.
   Timeout is a precise skip only when the missing progress is the optional
   capability being probed; unknown errors remain failures.
5. Keep the probe and the skip decision in the production test path so the
   target behavior, not a host-only assumption, controls the result.

## Evidence and verification

GLib 2.88.3 CI build #33027 (`ci_revision=8b135a7b0a28d36b2b3be09dcc2f89ca318c292b`)
reported nine capability-related aborts and three 480-second timeouts. The
successor candidate adds operation-level probes for Unix socket bind and exact
POSIX mode preservation, bounded waits for settings notifications and D-Bus
traps, and restores the upstream static assertion-symbol check. The new patch
is `archives/g/glib/2.88.3/patches/0020-target-runtime-capability-fixes.patch`
with SHA-256 `6e79396ee597f8702f8ff6d87cad58c0c66a465e85e92eb665c4e7dc03a82195`.
Final acceptance still requires the platform CI to complete with `results=0`.

## Forbidden shortcuts

- Do not treat `socket()` success, root/euid, or a broad filesystem label as
  proof that `bind()`, permission projection, or notifications work.
- Do not skip an entire binary or ignore every errno; keep the affected test
  contract and unexpected errors visible.
- Do not increase the global harness timeout to hide a missing progress event.
- Do not convert an unknown or product error into a skip.

## Safety boundary

This pattern changes test classification only for a capability that is directly
measured by the probe. It does not weaken the library implementation, alter
runtime behavior, or replace target validation. A passing probe proves only the
specific operation it performs; other semantics still require their own tests.
