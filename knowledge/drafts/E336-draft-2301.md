# E336 - 目标 ABI 条件 SKIP 的透明上游测试计数

> 贡献者：2301_80739235 | 状态：DRAFT | 创建日期：2026-08-21

## 适用范围

适用于清单固定、但部分注册测试会因目标 ABI 或公共 API 的表达能力而按上游
设计跳过的跨平台测试套件。该模式不限于 libXt 或 GLib TAP；CTest、JUnit、
DejaGnu 等入口只要同时存在“注册清单”和“条件不适用”语义，都应保持相同的
计数边界。

## 问题现象

同一份上游清单包含 PASS 与条件 SKIP。若结果解析器只匹配 `ok` 前缀，
`ok ... # SKIP` 会被误记为 PASS；若只把可运行项作为分母，又会把注册测试从
报告中消失。两种做法都可能伪造 `N/N（100%）`。

libXt 1.3.1 的四个 overflow 测试正是这种情况。其公开分配 API 使用 32 位
`unsigned` 大小，而 AArch64 的 `size_t` 是 64 位；调用方不能通过该 API 构造
上游测试要求的 64 位溢出参数，因此上游源码明确执行：

```text
g_test_skip("overflow not possible in this config")
```

## 根因

注册数、执行终态数、通过数、跳过数、失败数和 nonfailed 数是不同事实。
条件 SKIP 表示该注册项已被测试框架判定为对当前能力集合不适用，并不表示其
断言已经通过；但它仍属于上游清单，不能从分母删除。

## 推荐方案

1. 从上游构建脚本和注册源码冻结完整清单及稳定 ID。
2. 对每个允许的条件 SKIP 冻结测试路径和精确原因，并对清单做哈希绑定。
3. 只有 ID、路径、原因三者同时匹配时才接受 SKIP；额外 SKIP、原因漂移或
   预期 SKIP 变成 PASS 都应失败关闭。
4. 分别报告 `passed`、`skipped`、`failed`、`total` 和 `nonfailed`，并验证
   `passed + skipped = total`、`failed = 0`。
5. shared/static 重复执行属于构建变体，不增加独立测试分母；内部断言数也不
   叠加到测试用例数。

## 验证

libXt 1.3.1 真机 W3 绑定最终 staged candidate，结果为：

- 上游固定清单 20 项：16 PASS、4 个精确 expected SKIP、0 FAIL、20 nonfailed；
- 两个安装包 consumer：2/2 PASS，并在 shared/static 两种 Conan create 中执行；
- 独立总分母保持 22：18 PASS、4 SKIP；
- `assertion_metadata_total=20` 仅是断言元数据，不进入测试分母；
- W3 `summary.txt` SHA-256：
  `8ce929598bf257a2ca46e7680c9243e840f8fdacd33639bf227e3f2b15a82fc0`。

## 禁止做法

- 不得把四个 `# SKIP` 记为 PASS。
- 不得把上游分母从 20 缩为 16。
- 不得用恒真断言替换 SKIP，或通过宏改变目标 ABI 来制造可运行条件。
- 不得用两个 consumer 替代上游 overflow 注册项。
- 本计数合同不能绕过官方 Pre-PR 合同；若工具尚不接受透明 SKIP，应如实记录
  工具合同冲突并修复工具，而不是伪造测试结果。

## 与现有条目的边界

- E228 解决 HMDFS 上 Libtool wrapper 的条件启动，不定义测试结果计数。
- E331 草稿解决 Conan/Libtool 传递 `.la` shadow closure，不定义 ABI 条件 SKIP。
- 当前 `origin/main` 的四个规定查重范围没有等价的透明计数条目。
