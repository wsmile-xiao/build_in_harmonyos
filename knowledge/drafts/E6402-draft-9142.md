# E6402 草稿：OHOS SDK 缺少可选 llvm-strip 导致旧 Makefile CLI 构建失败

## 真实错误链

本地交叉编译时，上游 `Makefile` 链接出 aarch64 `pilercr`，随后硬编码宿主 `strip` 导致：

```text
strip: Unable to recognise the format of the input file `pilercr'
make: *** [Makefile:25: pilercr] Error 1
```

首次修复在 Makefile 中改用 `$(STRIP)` 并从 Conan 配置的编译器真实路径找 `llvm-strip`，本地 W3 完全通过。但 PR #13010 CI 使用另一套 OHOS SDK，编译器可用却没有相邻的 `llvm-strip`，强制检测导致 L1 在调用 `make` 前失败：

```text
ERROR: pilercr/1.06: Invalid configuration: OHOS target llvm-strip missing: /data/service/hnp/ohos-sdk.org/ohos-sdk_26.0.0.18/ohos/native/llvm/bin/llvm-strip
L1_RESULT=fail: conan create failed
L2_RESULT=skip: not run
```

`gitcode_pr.py diagnose` 误把日志中的 `timeout 14400 secs` 当作网络超时，但实际报错是本地构建与 CI SDK 的工具内容不同。该路径的 compiler symlink 存在不等于同目录有剥离器。

## 修复原则

编译产物剥离调试符号不是程序可运行的必要步骤；用一行 Makefile 补丁将 `strip pilercr` 改为 `$(STRIP) pilercr`，Conan 的 OHOS 配方显式传 `STRIP=:`（shell no-op）。保留静态目标编译和真实消费者运行验证，不回退宿主 strip，也不要求 CI 安装机器上没有的工具。Linux 原生构建仍可用宿主 `strip`。如果后续发布确有剥离硬需求，须提供独立可执行的目标 llvm-strip 并在 CI 真机复验。

与既有 `DRAFT-yosys-0.66-makefile-install-host-strip-cross-elf` 查重：其处理的是宿主 strip 读取目标 ELF 失败；本草稿新增点是**即使显式定位目标 strip，本地/CI NDK 内容差异仍会使“必须剥离”的方案在 CI L1 失败；安全可复现地跳过可选剥离**。

## 验证

```bash
CONAN_HOME=/data/harmony-compact/.conan2-ohos conan create archives/p/pilercr/1.06 \
  -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
# 查看构建行 STRIP=:，本地 test_package 经 qemu 调包内 CLI 后生成报告，
# 用报告生成发现头文件，编译并运行消费者，应打印 OHOS pilercr consumer PASS，exit 0。
# 远端 CI 状态必须重新触发后独立确认，不能把本地证据冒充远程已通过。
```
