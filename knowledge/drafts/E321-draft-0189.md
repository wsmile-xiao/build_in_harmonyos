# E321 — 单头文件库的实现重复与 Conan 消费者验证

## 错误特征
多翻译单元同时包含 `str.h` 完整实现时，链接器可能报告 `duplicate symbol`、`multiple definition` 或 `undefined reference`；若配方把单头文件误当二进制库，消费者测试无法证明真实 API 可用。

## 触发条件
- 构建系统：CMake/Conan 消费者
- 阶段：linking/testing

## 根因分析
`str.h` 的实现默认随头文件展开，只有定义 `STR_API_ONLY` 才只保留声明。单头文件库没有待链接的 `.a/.so`，其配方应声明 `header-library` 并安装头文件和许可证；测试必须调用实际 API。

## 解决方案

### 推荐方案
Conan 配方使用 `package_type=header-library`，`package_info()` 暴露空库列表；test_package 用 `CMakeDeps` 链接接口目标并调用格式化和 JSON API。多翻译单元场景仅让一个文件包含完整头文件，其余文件定义 `STR_API_ONLY`。

### 禁止做法
- ❌ 创建空库或只打印字符串的 test_package 来掩盖头文件未安装/目标名错误。
- ❌ 在每个翻译单元包含完整实现，或把上游 `footprint.c` 等辅助程序冒充默认单元测试。

## 验证
```bash
CC=clang make clean run    # 上游 188 个断言通过
conan create archives/s/str/1.0.0 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 -s:h os.version=6.0 -s:b os.version=6.0 --build=missing
```
