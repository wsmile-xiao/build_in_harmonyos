# 补充至 PR #2991：混合语言严格告警测试矩阵中的任务私有临时流后端

## 场景与已有知识

E272 / PR #2991 已证明 OHOS 上原 `tmpfile()` 可能忽略 TMPDIR，测试层可用
mkstemp/unlink/fdopen 的私有临时流保持 stdio 语义。本条不是再次申报该基础方案。
实质增量是将后端注入混合 C89/C99/C11 和 C++98 至 C++20 的严格告警矩阵时，
必须保留每个 TU 的语言合同，同时区分重复测试场景与框架自身 skip 行为。

## 问题现象与根因

utest 原生 r005 完整日志定位 `test/type_printers.inc:19`：`tmpfile()` 返回 NULL，
两项打印器测试失败，使 13 个真实 CTest 场景均失败。即使 runner 设置任务 TMPDIR，
仍不能以“目录可写”推断 libc tmpfile 会使用它。

r006 使用测试专用后端后，原上游 `-Weverything -Werror` 拒绝 C++ 中的 C 风格
malloc 转换及 OHOS `NULL=0L`，错误为 `old-style-cast` 和
`zero-as-null-pointer-constant`。这是兼容后端本身的语言缺陷，不能降低告警来掩盖。

## 可复用修复步骤

1. 先通过完整失败日志定位临时流的真实失败点，而非只看套件总 RC。
2. 只在测试编译中注入私有兼容后端，保留生产头、原测试源和所有断言。
3. C++11+ 使用 nullptr；C++98 保留该标准支持的 NULL；malloc 在 C++ 中用
   static_cast，在 C 中使用 C 转换。维持上游逐 TU 标准和严格告警。
4. 后端只接受任务私有 `/storage/Users/` 子树的 TMPDIR；独占创建文件，
   fdopen 为 w+b，立即 unlink，所有失败分支关闭描述符/流，不触碰系统临时目录。
5. 原生签名真正的探测 ELF 和测试 ELF，再运行上游原有 sanitizer、排序场景。
6. 以注册清单和 JUnit 核对场景身份，不把重复内部用例相加充数。

## 安全与适用边界

2026-10-04 后续 r008 在相同完整上游矩阵中重新验证 13/13、消费者2/2、
鸿蒙1/1、release/postrelease PASS。包装器在父 TMPDIR/TMPPREFIX 缺失时
显式接受 Conan build_folder，并将独占临时目录传入编译/签名/运行子环境；
这不改变 tmpfile 兼容后端的语言合同，也不回退系统 /tmp。
本轮配置 SHA-256：88303ea005f491e4a91958fee1748de5bfeb675591e2e460a4cd9ea63d8db6b8。
原 r007 证据独立保留，平台 CI/Review 仍不能由该结果推断通过。

只适用于已证明存在测试临时流障碍且上游需要 stdio 写/seek/read/close 语义的混合语言套件。
不改系统 libc、生产头或系统工具，不用全局 LD_PRELOAD，不弱化测试或告警。
后端不支持把无名流重新发布为文件；有该需求的套件需单独验证其原合同。
任何代码行为变化都要新候选和新的独立 W3；已消费事务不得再次 launch。
