# E543 — C++98 时代测试套件故意从析构函数抛异常：C++11 起析构隐式 noexcept，默认标准下 libc++abi 运行期 terminate（非库缺陷）

## 错误特征

```text
exceptions at test setup time: ......libc++abi: terminating due to uncaught
  exception of type std::runtime_error: ex in destructor
SELFTEST_RC=134
Signal 6 (core dumped)
```

- **关键判别**：套件前半部分正常逐组通过（ok 点号逐组打印），到某个
  特定测试组**中途**戛然而止 abort，不是编译错误、不是断言失败。
- 编译期先兆（clang，开着 -Wall 就能看到）：

```text
warning: '~dummy' has a non-throwing exception specification but can
still throw [-Wexceptions]
    throw runtime_error("ex in destructor");
    ^
note: destructor has a implicit non-throwing exception specification
```

## 触发条件

- 构建系统: 任意（问题在被编译的测试代码语义，与构建系统无关）
- 阶段: testing / runtime（编译链接全过，运行套件时崩）
- 库形态: C++98 时代的框架/套件，其测试**有意**验证"析构函数抛异常"
  这一当年合法的语义（实例：TUT (libtut) 0.0.20070706 selftest 的
  teardown_ex 组——warn 结果类型正是为该场景设计）
- 工具链: 以 C++11 及以后标准编译（clang 15 默认 gnu17 + libc++abi）

## 根因分析

C++11 [class.dtor] 将析构函数的隐式异常规范从"可抛任何异常"改为
**隐式 noexcept**；C++98 时代合法的 `~T(){ throw ...; }` 在 C++11+
下离开析构函数即调用 `std::terminate`。libc++abi 的表现为
`terminating due to uncaught exception` + Signal 6。

三个要点：

1. **不是库缺陷**：交付的库头文件在现代标准下正常（消费者代码不会
   故意从析构抛异常）；只有"故意测析构抛异常语义"的老测试套件受影响。
2. **不是回归**：上游 2007 年用 g++ 默认 C++98 跑该套件时
   `throw` 离开析构是合法行为，框架捕获后记为 warn——语义被标准
   变更改掉，代码一行没变。
3. **编译期可见**：clang -Wexceptions 警告精确指向测试本地的抛出
   析构（区别于库头文件内部），可作预判信号。

## 解决方案

### 推荐方案

以时代匹配的标准重编译上游套件（不改动任何测试代码）：

```bash
# 设备 OHOS clang 15，源码根为 include 根（<tut/tut.hpp> 角括号形式）
for f in selftest/*.cpp; do \
  /data/service/hnp/bin/clang++ -std=gnu++98 -ftemplate-depth-100 \
  -I"$src" -Wall -O2 -c "$f" -o "${f%.cpp}".o; done && \
  clang++ *.o -o selftest && ./selftest
# libtut 实测：tests summary: ok:63 / THIS VERSION OF TUT IS CORRECT / RC=0
```

- 交付物（配方 package() 的头文件）**不需要也不应该**限定标准；
  test_package 在目标默认标准（gnu17）下验证现代消费者路径，
  上游套件用 gnu++98 验证历史语义——两条证据互补，PR 里分开陈述。
- 区分口径：适配后统计表只计 test_package（现代标准），上游套件
  通过率单列（-std=gnu++98 复现上游语义）。

### 禁止做法

- ❌ 给上游测试的析构打 `noexcept(false)` 补丁"修复"（改动上游测试
  语义，违反最小干预；套件本该用时代标准跑）
- ❌ 因套件 abort 判定库在 OHOS 不可用/降低兼容性评级（库本体在
  gnu17 下 test_package 全绿是直接反证）
- ❌ 把 -std=gnu++98 加进配方让消费者也被拉回老标准（惩罚所有
  现代消费者）
