# E2179: Bind CMake optional backends before OHOS cross testing

## Symptom

A CMake C++ library can look like a one-dependency target while its default
configuration enables optional Qt, iconv, or helper-server components. A cross
build may then fail on an unpublished dependency or produce test binaries that
cannot run on the host. A consumer can also fail if the installed CMake target
name is not preserved.

## Root cause

Upstream CMake defaults describe the broadest desktop build, not the smallest
OHOS closure. Cross compilation changes the meaning of test execution: CTest
can compile target tests successfully but cannot execute AArch64 binaries on a
Windows host. A generic Conan OHOS profile can also set only the compiler path,
leaving CMake with an unknown system name or no target triple/sysroot; the
linker then falls back to the Windows toolchain. These are independent concerns
and must not be collapsed into a single build result.

## Fix

1. Read the upstream CMake options and map each optional backend to the target
   feature actually required by the package.
2. Bind `BUILD_SHARED_LIBS`, optional backend switches, and test compilation in
   `CMakeToolchain`; keep only the platform `Threads` edge when the core API
   does not require a Conan dependency.
3. Compile the upstream CTest targets during cross build but execute them only
   on a matching host or through the target-device validation contract.
4. Use `CMakeDeps` in `test_package` and link the installed public target to
   catch package-config and include/lib layout errors.
5. Bind the Conan OHOS system name, target triple, and sysroot in both recipe
   and consumer. For an offline W3, pass a task-local source archive through a
   dedicated environment override while keeping the official URL and SHA-256
   in `conandata.yml`; Conan must still verify the archive hash.

## Evidence and verification

For log4cplus 2.2.0.1, the official archive is bound to SHA-256
`374175c22fabe752eb1c20138e732b69ae191e641f92d32c9432985cd860a2df`. Its
CMake project declares `Threads` as the required core dependency and exposes
Qt4, Qt5, iconv, and logging-server options. The recipe disables those optional
paths, compiles upstream tests, and keeps the `log4cplus::log4cplus` consumer
target explicit. The final Conan OHOS profile bound `CMAKE_SYSTEM_NAME=OHOS`,
`aarch64-linux-ohos`, and the SDK sysroot; the local source override avoided
GitHub retry loops while preserving the official archive hash.

## Applicability and safety boundaries

Use this pattern for small CMake libraries with optional GUI, codec, or helper
backends and cross-compiled test binaries. It does not waive W0 binary-closure
checks, target signing, target runtime validation, or postrelease cleanup.
Do not mark a skipped cross CTest run as a test PASS, and do not disable a
backend unless source inspection proves it is outside the required closure.
