# DRAFT - 单模块 Python 引导依赖的直接打包与等价性验证

> Contributor: xuguowei | Status: VERIFIED DRAFT | Updated: 2026-08-20
> Source: six 1.17.0, contrib task #4151, PR #6045

## 知识类型与边界

本条目是路径 B 知识库扩展草稿，不预占正式 E 编号。它只新增到
`knowledge/drafts/`，不修改正式知识图谱、索引或基础设施；是否提升及最终分类由
知识库维护者和赛事评审决定。

本条目不是“所有纯 Python 包都可以直接复制源码”的建议。它描述一个更窄的引导依赖
场景：上游安装清单经审计后确认只有一个顶层 Python 模块，运行时不需要构建后端生成的
文件或分发元数据，而该模块又可能位于 Python 打包工具链的底层依赖位置。此时可用一个
可验证的直接安装过程替代不必要的 pip/setuptools 执行。

## 问题模型

six 1.17.0 的官方 `setup.py` 明确声明 `py_modules=["six"]`，并注释说明 six 是
setuptools 的依赖，使用 setuptools 会形成循环依赖。若为了安装这个单模块再次启动
pip/setuptools，
会给底层依赖适配引入额外的构建后端和引导依赖。另一方面，简单执行
`copy("*.py")` 也不充分，因为一般 Python 项目可能包含：

- `package_data`、资源文件或生成源码；
- `console_scripts` 等入口点；
- namespace package 或多个包/模块；
- C/C++/Rust 扩展；
- 运行时通过 `importlib.metadata` 读取的分发元数据。

直接安装只有在这些条件逐项排除后才与上游安装载荷等价。判断依据必须来自上游元数据和
源码清单，不能只因为项目“看起来很小”或第一次 `import` 成功。

## 推荐方法

### 1. 审计上游安装清单

确认上游声明的可导入载荷恰好是一个 `py_modules` 模块，并记录模块文件、许可证和版本
来源。明确检查没有扩展模块、package data、入口点、namespace package、生成步骤和运行
时分发元数据需求。任一条件不满足，就回到 wheel/构建后端方案。

### 2. 把直接复制实现为可审计的安装步骤

将明确命名的模块文件复制到 Conan 包的 `lib/python/site-packages`，不要使用宽泛的源码
通配符。许可证单独安装。通过 `runenv_info` 导出包内 Python 搜索路径；配方不调用 pip、
setuptools 或 distutils，也不在构建过程中解析网络依赖。

six 配方还在打包前完成两项快速检查：

1. 使用 Python `compile()` 编译 `six.py`，排除损坏或语法错误；
2. 核对源码中的 `__version__ = "1.17.0"`，防止源文件与配方版本错配。

这些检查只负责输入完整性，不能替代功能测试。

### 3. 建立等价性证据链

验证至少包含四层：

1. 对 SHA256 固定的上游 sdist 运行未修改的完整测试套件；
2. 消费者从 Conan `VirtualRunEnv` 导入模块并执行代表性公共 API；
3. 断言 `module.__file__` 精确落在 Conan 包目录，排除环境预装模块；
4. 移走包内 `lib/` 后重跑消费者，要求测试失败，形成 L1e 反向证据。

只有“正向 API 通过 + 路径归属正确 + 反向破坏失败”同时成立，才能说明消费者使用的是
直接安装的包内模块。

## 与现有知识的差异

- E319 已覆盖一般 Python noarch 包的 wheel/site-packages/PYTHONPATH 适配，并重点处理
  import 阶段的资源下载。本草稿不重复该方案，而是定义何时可以在底层引导依赖中跳过
  wheel 构建，以及跳过后必须怎样证明安装载荷等价。
- E298 已覆盖 `VirtualRunEnv`、显式消费者执行和一般 L1e 思路。本草稿把这些验证手段用于
  一个更具体的风险：单模块直接安装可能遗漏构建后端产物或误用环境预装模块。
- 本草稿的新信息是“直接安装的准入审计 + 明确禁止条件 + 多层等价性证据链”，不是单独
  宣称 site-packages、PYTHONPATH 或 L1e 本身为新知识。

## 禁止做法

- 不要把直接复制扩展成纯 Python 项目的默认打包策略。
- 不要使用 `*.py` 通配符代替上游安装清单审计。
- 不要在存在 package data、入口点、扩展、生成文件或元数据需求时跳过 wheel 语义。
- 不要只断言版本号或固定打印 PASS。
- 不要依赖设备预装模块；必须检查 `__file__` 并执行 L1e 反向验证。
