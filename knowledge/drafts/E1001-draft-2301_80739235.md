# E1001 — C API target probes must honor handle lifecycle

## 问题概述

本轮 `db-c/5.3.28` 的 HarmonyOS 专测在 `db_create` 后直接调用 `DB->put`，
运行时返回 `BDB1565 DB->put: method not permitted before handle's open method`。
同一个 Conan 包的普通消费者使用完整的 open、put、get、close 流程并通过，说明
问题出在专测遗漏状态转换，而不是链接或包内容缺失。

## 根因

`db_create` 只创建并返回句柄，不代表 Berkeley DB 句柄已经绑定数据库类型和存储
路径。CRUD 方法只有在显式 `open` 成功后才允许调用。目标专测为了保持最小化而
省略了 `open`，因此编译可以通过，运行时却在第一条写操作上失败。

## 修复与验证

1. 在目标专测中增加任务临时 BTree 路径，并调用 `DB->open`，使用
   `DB_CREATE | DB_TRUNCATE` 和受控权限。
2. 保持 `db_create -> open -> put -> close` 的状态顺序；无论 `open` 或 `put`
   失败，都关闭句柄并删除临时数据库文件。
3. 用冻结包的头文件和共享库重新编译专测。修复前复现了 BDB1565；修复后输出
   `HARMONY_TEST_PASS=1/1`，并确认退出后临时文件清理。
4. 同一 WSL Conan 流程还完成了 CMake 消费者构建并输出 `db-c consumer PASS`。

## 适用范围与安全边界

适用于所有工厂函数返回“已创建但未初始化”句柄的 C/C++ 库，包括数据库、连接、
编解码器和设备 API。目标 probe 应覆盖库文档定义的最小生命周期，而不是只验证
符号可链接；每个临时路径必须位于任务私有目录并在所有退出路径清理。不能把主机
消费者的通过结果替代目标机运行，也不能通过删除专测、忽略非零 RC 或静态打印
`HARMONY_TEST_PASS` 来制造目标验证证据。
