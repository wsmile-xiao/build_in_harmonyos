# E202610060400 — 标量命令中的字面引号破坏数值输出与缓存失效

## 错误特征
脚本语法与首次缓存生成均成功，但更新输入 mtime 后仍返回旧缓存；真实目标出现 arithmetic syntax error。触发特征是把命令及参数保存在标量变量中，变量内部包含用于“装饰”参数的引号，随后将工具输出用于数值比较。

## 触发条件
- 阶段：Shell 运行时、缓存刷新或增量构建判断。
- 环境：Bash 调用真实 stat/expr/xargs 管线；已在 HarmonyOS aarch64 Toybox 上复现，不将结论扩大为所有工具版本都产生相同输出。

## 根因分析
Shell 不会把参数展开产生的引号重新作为语法解析。例如将 `stat -c '%Y'` 整体存入标量再展开时，stat 获得的格式包含字面单引号。不能依赖后续管线偶然剥掉引号。OHOS 实测输出为 `'2000000010'`，Bash 整数比较失败，缓存没有失效。文件存在、`bash -n` 成功及首次补全均不能证明缓存刷新正常。

## 解决方案

### 推荐方案
1. 在实际目标记录工具身份、原始输出、RC 与比较失败，不先替换 stat、框架或产品。
2. 单 token 格式改为 `stat -c %Y`；BSD 分支同理改为 `/usr/bin/stat -f %m`。复杂参数改用真实 argv 数组，不能二次 eval。
3. 在任务私有根完成首次缓存生成、同输入缓存复用、确定性 mtime 更新后重生成三段式验证，同时检查实际输出内容。
4. 补全资产还需走固定 commit/hash 的官方动态加载器验证安装名，不只手动 source；可以固定外部业务命令输出，但不能桩化被测产品、缓存逻辑或框架。
5. 用实际 Conan 缓存流验证导出补丁、官方源码、打包后的资产和消费者；测试所需加载器在实际执行的 build 阶段获取并校验 SHA-256，不能假设 test_package source 钩子已运行。

本条没有可安全跨项目机械套用的单行修复命令，KV 的可选 `rec_command` 留空；应按以上步骤绑定实际工具和三段式缓存结果，不能把模板提示当成可执行命令。

### 禁止做法
- 不用 eval 或替换真实框架掩盖引号问题。
- 不把宿主模拟、重复配置或断言拆分为更多目标用例。
- 不把 Conan 成功当成平台 CI、AI Review 或提审通过。
