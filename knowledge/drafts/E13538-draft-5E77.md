# E13538 — OHOS libcxx-ohos (LLVM 15.0.4) 缺失 std::ranges 算法（ccache 4.14 实证）

## 错误特征
```
src/ccache/argprocessing.cpp:198:23: error: no member named 'all_of' in namespace 'std::ranges'
  return std::ranges::all_of(...)
src/ccache/config.cpp:87:23: error: no member named 'any_of' in namespace 'std::ranges'
unittest/test_util_tokenizer.cpp: error: no member named 'equal' in namespace 'std::ranges'
```

## 触发条件
- 构建系统: cmake（project(ccache LANGUAGES C CXX)，CMAKE_CXX_STANDARD 20）
- 阶段: build（clang++ 编译 C++20 源）
- 工具链: OHOS SDK LLVM 15.0.4（libcxx-ohos 头目录 include/libcxx-ohos/include/c++/v1）

## 根因分析
libcxx-ohos（OHOS SDK LLVM 15.0.4 自带 libc++）在 `__config` 中定义
`_LIBCPP_HAS_NO_INCOMPLETE_RANGES`（`#if !defined(_LIBCPP_ENABLE_EXPERIMENTAL) && !defined(_LIBCPP_BUILDING_LIBRARY)`），
因此 `std::ranges::all_of / any_of / equal` 等 ranges 算法完全不可用。
ccache 4.14 按 C++20 编写并使用这些算法，直接编译报错。

## 解决方案

### 推荐方案
将 `std::ranges::X(...)` 替换为迭代器版 `std::X(begin, end, ...)`：
- `std::ranges::all_of(tokenizer, pred)` → `std::all_of(tokens.begin(), tokens.end(), pred)`
- `std::ranges::any_of(safe_dirs, pred)` → `std::any_of(begin, end, pred)`
- `std::ranges::equal(a, b)` → `std::equal(a.begin(), a.end(), b.begin(), b.end())`
另外：产物用 `-ffile-prefix-map=<src>=.` 剥离构建机绝对路径（鸿蒙专项 T2 检查）。

### 禁止做法
- ❌ 在 conandata 中注入 gh-proxy 等非官方源（PF7）
- ❌ 用 `-D_LIBCPP_ENABLE_EXPERIMENTAL` 绕过（libc++15 ranges 仍不完整）

## 验证
```bash
cmake --build build -j8 && build/ccache --version
# 4 处 std::ranges 错误消失；strings ccache | grep '/storage/Users' 为空
```
