# Official release owner is a per-version source identity

The previous FAAD2 2.11.2 archive records `knik0/faad2` as its source URL. The new 2.11.4 official release and tag are published under `FreewareAdvancedAudio/faad2`. Reusing the previous URL with only its version changed would leave this version's authoritative source location unverified; a historical archive is evidence for that old version, not a rule for future tags.

For a newer version, inspect the current maintainer release, pin the official tag archive URL and SHA-256 in `conandata.yml`, then bind the same bytes to target validation. Here the 2.11.4 archive SHA-256 is `ee479ccbae4a8387ab696e6f21a481bd83fe3881471cafa81b4ae59d7d3aed43`. The target `conan create` used the byte-identical, transaction-frozen archive while the checked-in URL stayed official. Its log SHA-256 is `d14ee70aab244d0e28427eea0ae4349b1a5d049a83ea3d59b9c341873c9950c3`; the independent consumer passed 1/1. Upstream CMake registers no test, so that consumer is not misreported as an upstream case.

This applies to repository transfers, renamed maintainers and moved release hosting. It does not claim old URLs necessarily fail or redirect; the required decision is to verify the current release identity and bytes for each version. A local `file://` source override is only a W3 transport of the same hashed official archive, never a replacement for the PR's official `conandata.yml` URL. Existing knowledge about tag versus release asset contents is adjacent, but does not cover owner drift across versions.
