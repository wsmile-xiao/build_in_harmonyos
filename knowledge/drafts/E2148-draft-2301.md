# E2148 - Exact directory-member contracts for readback tar archives

## Symptom

A target transaction completed its only launch and emitted a PASS terminal.
Sealed release and postrelease also passed, but the host then raised:

```text
terminal readback tar closure invalid
```

The tar transferred with RC 0, zero stderr, and matching byte count and SHA-256.
Its validator accepted every regular file but rejected the expected archive-root
directory record because that name ended in `/`.

## Root Cause

Archiving a directory by name includes the root directory and its subdirectory
records. They are structural members, not file payloads. A blanket regular-file
check or a pathname expression that requires a final non-slash component
conflicts with the producer contract even when the archive is canonical,
unique, in scope, and contains no links or special files.

## Fix

1. Define exact sets for directory members and regular files separately.
2. Require every name to be relative, canonical, unique, and below one exact
   run root. Reject traversal, backslashes, absolute names, and repeated paths.
3. Accept only the whitelisted directories and regular files. Reject symlinks,
   hardlinks, devices, FIFOs, and unknown types.
4. Check payload size and SHA-256 only for regular files, then validate every
   row in the evidence manifest against the archived bytes.
5. Bind the terminal, run log, release, postrelease, and host transport records
   to the same run, HEAD, tree, and one-launch identity.
6. Preserve the consumed host failure. If remote release already passed, use
   only the original owner-bound ledger release and a create-new local
   reconciliation result; never launch or release the device a second time.

## Validation

Pkgconf 3.0.5 r36 produced a 1,427,968-byte tar with SHA-256
`83856bf764a71f75d59755b3c88047337a0b66b6c5fb27e829f33fcb64bbc7fb`.
The corrected validator accepted 48/48 unique members: 12 exact directories,
36 exact regular files, and 13/13 evidence hashes. A 7/7 matrix accepted the
real archive and rejected an extra directory, symlink, extra file, duplicate
terminal, missing terminal, and payload-hash drift.

The bound terminal proves controller/runner launch counts 1/1, runner RC 0,
five signed ELF inputs, and 26/26 target assertions. Release proves root process
0, two clean scans, lock 0, and lease 0; postrelease passed. No second SSH
session or launch occurred.

## Safety Boundaries

- A valid tar structure alone cannot prove W3 PASS; require the exact terminal
  and release identities from the same immutable run.
- Do not delete directory records from historical evidence or rewrite a pinned
  failure result.
- If launch count, terminal, transport ownership, release, or any member hash is
  uncertain, retain the allocation and fail closed.
- This pattern does not authorize device access, upload, push, PR, CI, or
  submission.
