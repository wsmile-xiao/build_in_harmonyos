# E607 — 上游 CMake 平台分支只判 Linux/Darwin/Windows，HarmonyOS 下漏编 POSIX 源文件

> 草稿（draft）。来源任务：osqp/1.0.0 适配（HarmonyOS PC aarch64），Agent 3464，2026-09-08。

## 错误特征

```
ld.lld: error: undefined symbol: osqp_start_interrupt_listener
>>> referenced by osqp_api.c
>>>               osqp_api.c.obj:(osqp_solve) in archive ../out/libosqpstatic.a
ld.lld: error: undefined symbol: osqp_is_interrupted
ld.lld: error: undefined symbol: osqp_end_interrupt_listener
clang-15: error: linker command failed with exit code 1
```

配置期还有一行线索：`-- We are on a HarmonyOS system`，且没有任何编译错误——
**源文件被平台分支静默剔除**，只在链接期暴露。

## 触发条件

- 构建系统: CMake
- 阶段: linking（根因在 configure 的源文件挑选）
- 前置: 上游用 `CMAKE_SYSTEM_NAME` 字符串精确匹配推导 `IS_LINUX/IS_MAC/IS_WINDOWS`，
  再用这些布尔量决定编译哪个平台实现文件；功能开关默认 ON 且公共代码无条件引用其符号

osqp 1.0.0 实例：

```cmake
# CMakeLists.txt:27-33
if(${CMAKE_SYSTEM_NAME} STREQUAL "Linux")     set(IS_LINUX ON)
elseif(${CMAKE_SYSTEM_NAME} STREQUAL "Darwin")set(IS_MAC ON)
elseif(${CMAKE_SYSTEM_NAME} STREQUAL "Windows")set(IS_WINDOWS ON)
endif()
# src/CMakeLists.txt:61-67
if(OSQP_ENABLE_INTERRUPT AND NOT OSQP_CUSTOM_INTERRUPT)
  if(IS_WINDOWS)      ... interrupt_windows.c
  elseif(IS_MAC OR IS_LINUX)  ... interrupt_unix.c     # ← HarmonyOS 两条都不成立
  endif()                                             # ← 什么都没编，但符号仍被引用
endif()
```

## 根因分析

OHOS 上 `CMAKE_SYSTEM_NAME=HarmonyOS`（OHOS 适配版 conan 的映射结果），
三个 `IS_*` 全为 OFF。上游的"未知平台"在源文件挑选处表现为**什么都不加**（而不是报错），
于是 `osqp_api.c` 里对中断三函数的调用失去实现 → 链接期 3 个 undefined symbol。
HarmonyOS/OHOS 具备 POSIX `signal()` 语义，`interrupt_unix.c` 本来就是正确实现。

## 解决方案

### 推荐方案：在该平台分支显式追加 HarmonyOS 与 OHOS 两种系统名

```cmake
  elseif(IS_MAC OR IS_LINUX OR CMAKE_SYSTEM_NAME STREQUAL "HarmonyOS"
                             OR CMAKE_SYSTEM_NAME STREQUAL "OHOS")
    target_sources(OSQPLIB PRIVATE "${CMAKE_CURRENT_SOURCE_DIR}/interrupt_unix.c")
  endif()
```

- 两种名字都写：`CMAKE_SYSTEM_NAME` 在本 SDK/conan 下是 `HarmonyOS`，
  而部分交叉工具链/conan 版本会给出 `OHOS`，一处覆盖两种取值；
- 改动落在**构建系统文件**（CMakeLists.txt）而非 C 源文件，符合 R8/PF5
  （补丁新增行禁止出现 `__OHOS__` 平台宏）；
- 同型先例（仓内已合并）：ableton-link 3.1.2、aws-c-io 0.27.5、arpon 3.0-ng 的
  `CMAKE_SYSTEM_NAME` 平台分支补丁。

### 备选方案：把 HarmonyOS 归入 IS_LINUX

在顶层平台探测处加一个 `elseif(CMAKE_SYSTEM_NAME STREQUAL "HarmonyOS") set(IS_LINUX ON)`，
一处覆盖全部下游分支。**代价**：连带启用所有 Linux 专属链接/编译项——osqp 会同时加上
`-lrt -ldl`（`CMakeLists.txt:293-295`），需先确认目标 sysroot 具备这些库。
本次仅缺一个源文件分支，故选推荐方案（改动面 +2/-1）。

### 禁止做法

- ❌ `-DOSQP_ENABLE_INTERRUPT=OFF` 绕过（阉割上游默认功能，掩盖适配缺陷）；
- ❌ 在 `interrupt_unix.c` 里加 `#ifdef __OHOS__` 兜底（R8/PF5 禁止补丁引入平台宏）；
- ❌ 只写 `OHOS` 不写 `HarmonyOS`（换 conan 版本即复发）。

## 验证

```bash
cmake -S . -B build -DOSQP_BUILD_UNITTESTS=ON && cmake --build build -j2   # exit 0
nm -a build/out/libosqpstatic.a | grep osqp_start_interrupt_listener        # 存在且为 T
ctest --test-dir build --output-on-failure                                  # 3/3 Passed
```

实测（osqp 1.0.0）：基线 exit 2（3 个 undefined symbol）→ 打补丁后 exit 0，
ctest 3/3、104 用例 / 1255 断言全通过。
