# 关闭可选 TLS 后仍须保留非 TLS 协议的必需散列闭包

## 问题现象与触发特征

网络库提供可选 TLS 开关；TLS 关闭时普通 HTTP 和编译通过，但未加密协议的握手仍调用散列函数并在运行时退出。此错误不能用“TLS 本来就未启用”解释，因为被测功能并不依赖加密传输。

## 根因

构建开关把传输加密后端与协议必需原语耦合。接口存在并不代表 TLS=OFF 时拥有实现。需从实际调用图判定独立能力，而不是从可选依赖列表推导零依赖。

## 可复用修复步骤

1. 保存原失败日志和配置，定位真实协议测试调用的必需原语。
2. 使用已发布目标平台提供者的公开 API；把精确产品依赖、头文件、静态链接闭包绑定到配方，而非只靠测试包或宿主系统库。
3. 原 TLS 实现存在时仍使用它；缺席时只补充协议散列，不暗中开启 TLS，不加入常量摘要或空壳实现。
4. 保留原握手测试，增加独立标准向量；继续执行配置内的完整上游套件，分别记录入口、内部用例、断言数。

## 真实验证

PR #14507 的 onion/0.8，TLS=OFF：r008 的原始 WebSocket 测试因没有 SHA1 实现退出，整体 FAIL。修复使用 OpenSSL 3.5.8.1 的公开 SHA1：精确 RREV `0825772c02c4be90c6add143a1fadadc`，OHOS PID `4b977264131a1c74e82bd6bb51b63cc9aadc4cfa`，PREV `773b7a4d178a42435ebf441e26dbd416`。这些标识来自隔离 `--build=never` 的真实制品仓解析。

独立 r012 保留原 WebSocket 两项测试并新增 `abc` 标准向量；完整运行19个注册入口、两份原录制请求各LF/CRLF四种运行、原资产工具场景，总89/89，无失败或跳过。消费者1/1、独立鸿蒙签名库/HMDFS中文文件HTTP测试1/1、前后输入和二进制哈希、release/postrelease均通过。本机验证记录绑定配置 SHA-256 `2065c55b45de238cf1655e9c7aee05c2441406b5499538f2416b8b687fb5eed1`。

17个补丁由官方 `refresh-patch --auto` 生成。用Conan真实补丁入口重放后，289个源文件与成功原生事务输入逐字节一致，无换行差异。这证明源码表示等价，不把后续配方执行、平台CI或提审冒充已完成。

## 适用范围与安全边界

后续当前候选 r016 独立重验上述89/89、消费者1/1、鸿蒙1/1以及release/postrelease全部通过。配置SHA-256 `d312d09be16480423ddd809a2851609b8df854a4b5ae5824edf86bb76864f25e`，终态快照SHA-256 `b0f22fd4b61246ed5add632bbda25f3a5f71bb3a33f9035b2f04a73f3d27894e`；修复嵌套工具解析与私有动态库搜索不改变原协议用例及标准向量。r012和r016是各自完整的独立事务，不跨运行拼接。

适用于加密传输可选但协议散列不可选的库和组件。不是所有 TLS=OFF 项目都需要新增密码库；没有真实调用与失败证据时不套用。SHA1在这里仅实现既定协议握手，不能推广为新安全设计、口令散列或证书验证算法。补充散列不等于支持TLS；发布二进制存在不等于当前候选目标测试或平台CI通过。
