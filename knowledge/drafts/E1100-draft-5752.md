# E1100 草稿：纯 CLI 工具产出参与 OHOS 消费者编译与实跑

## 错误面与新意

机器检视的 `规则 12: 鸿蒙特有测试 N=0 < 1` 往往发生于只有 CLI 而无库的包：检查可执行文件存在、ELF 架构、符号或运行 `--version` 不验证真实消费者行为。已有 E544 解决 x86 上 OHOS 动态 loader 缺失；E999 解决手搓 Makefile 被误认成 autotools；E392 解决原始 Makefile 在 Conan 的构建细节；`DRAFT-no-upstream-tests-drive-real-interface` 解决无上游自动测试时如何驱动真实接口。本草稿**仅**补充此前条目未给出的可复用消费者构建路径：**让包内 CLI 真实输出成为消费者编译输入，随后实际执行消费者**，不重复上述错误诊断。

## 可复现证据：sickle

`sickle` 只有 `bin/sickle`，上游 `test/` 中三个 FASTQ 仅是输入数据，无注册的测试，`make check` 退出 2。`test_package/conanfile.py` 声明 `self.requires(self.tested_reference_str)`；`build()` 在 x86 交叉编译机上依次：

1. 把两条 FASTQ 读段制成 gzip，`qemu-aarch64 <Conan 包>/bin/sickle se -t sanger -q 20 -l 1 -f input.fastq.gz -o trimmed.fastq`；可观察到 2 条输入、1 条保留、1 条丢弃，验证 zlib 联动及质量过滤。
2. **从工具生成的 `trimmed.fastq` 字节**写入 `generated_fastq.h`，目标 OHOS clang 用该头文件编译 `consumer.c` 为静态 aarch64 程序。
3. `test()` 真正执行 `qemu-aarch64 consumer`，消费者比对完整 FASTQ 记录字节，输出 `OHOS consumer: gzip FASTQ processed; 1 good read kept, 1 poor read removed`。

本地 `python3 scripts/ohc-run.py conan-verify sickle 1.33-git20150314.f3d6ae3` 退出码 0；`archives/s/sickle/1.33-git20150314.f3d6ae3/reports/conan-create.log` 行 95–110 含三段运行输出；测试为 1/1，qemu 实跑。远端 CI 尚未运行，不冒称其已通过。

## 推荐方案

CLI 包先经 Conan 打包和依赖解析；在 `test_package.build()` 用**包内**目标 CLI 产生真实业务数据，生成一个供目标消费者编译使用的头文件（或源码），在 `test_package.test()` 真运行目标消费者并验具体输出。x86 上静态重链或直接静态交付，使用 qemu；若环境无法运行必须明确 skip 而不能算通过。避免将 `file`、`nm`、`sha256sum` 等完整性检查计入 rule12。
