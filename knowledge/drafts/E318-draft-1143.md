# E318 — Desktop-specific wrapper commands need an explicit context provider

> Contributor: 1143 | Status: DRAFT | Created: 2026-08-12

## Error signature

```text
Requirement plasma-activities-cli missing
xdpyinfo: not found
kdialog: not found
```

## Trigger

A shell or command-line wrapper is moved from KDE/X11 Linux to OpenHarmony or
another desktop. It reads an application context directly from desktop-specific
commands before performing its actual work.

## Root cause

The program has coupled two separate concerns:

1. resolving a stable desktop/workspace identity;
2. selecting application data or behavior using that identity.

OpenHarmony does not implement KDE Activities, and a command-name shim cannot
create the missing service semantics. Display geometry and GUI message helpers
are separate optional capabilities and should not block context resolution.

## Recommended solution

Introduce a provider boundary:

- retain automatic KDE discovery when a compatible CLI is present;
- accept an explicit stable ID and display name from the OpenHarmony launcher,
  system parameter bridge, or product workspace manager;
- validate that both values are present and non-empty, and restrict IDs used in
  paths to a documented safe character set and maximum length;
- use deterministic non-GUI defaults for optional display/dialog helpers;
- add a probe that prints the resolved provider and key without launching the
  wrapped GUI program.

For activity-aware-firefox the contract is
`--activity-id` + `--activity-name` (or the corresponding environment
variables), and `--probe-context` provides the test seam.

## Forbidden shortcuts

- Do not ship a fake `plasma-activities-cli` that returns a constant value.
- Do not generate a random activity ID per launch.
- Do not treat packaging a script as proof that its context behavior works.

These shortcuts either mix user profiles or create false-positive tests.

## Verification

```bash
bash test_activity_context.sh /path/to/packaged/activityfirefox
```

The test must invoke the packaged script and verify provider selection, identity
preservation, deterministic key sanitization, rejection of partial/unsafe
contexts, profile creation and reuse, selected profile paths, and wrapped
application arguments.
