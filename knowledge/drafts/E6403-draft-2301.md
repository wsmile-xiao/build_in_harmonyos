# E6403 - WrapDB auxiliary patch URLs need deterministic mirror projection

## Symptom

The CI wrapper reports mirror fallback, while `conan create` still fails in
`source()` when downloading a Meson WrapDB patch. The endpoint
`/v2/gtest_1.14.0-1/get_patch` redirects to a GitHub release asset that the
worker cannot reach. The source archive and all dependency downloads can pass,
so the failure appears late in source acquisition rather than as a general
network outage.

## Root Cause

The wrapper's pre-download transformation is temporary: it rewrites URLs that
it can see in `conandata.yml`, prefetches them, and restores the official file
before invoking Conan. A recipe-level `download()` call receives the restored
WrapDB URL and follows its redirect directly. The redirect contains a stable
release identifier, but the recipe has no bounded candidate for that derived
asset. Treating HTTP success or a non-empty response as sufficient would also
admit HTML and truncated archives.

## Fix

1. Keep the official WrapDB endpoint, filename, and expected SHA-256 in
   `conandata.yml`.
2. Recognize only the exact `/v2/<release>/get_patch` shape and derive
   `mesonbuild/wrapdb/releases/download/<release>/<release>_patch.zip`.
3. Try the derived asset through the approved `ghproxy.net` mirror with
   Conan's ordinary `download(..., sha256=...)` API, then try the official
   endpoint. Delete only a regular partial destination after an exception.
4. Aggregate candidate errors and raise a terminal Conan error when no
   candidate passes the same digest contract.

## Validation

For DOSBox Staging `0.82.2-r1`, Buildbot `48963` completed checkout, quality
checks, dependency resolution, and package downloads, then failed because the
WrapDB redirect timed out. A bounded host probe fetched the derived release
asset as exactly `2440` bytes with SHA-256
`2e693c7d3f9370a7aa6dac802bada0874d3198ad4cfdf75647b818f691182b50`, matching
the frozen metadata. Python syntax validation passed for the production recipe;
the next CI run must prove the worker can acquire the patch and finish its
build and tests.

## Applicability and Safety Boundary

This pattern applies to redirecting auxiliary inputs whose upstream endpoint
contains a deterministic release identity. It does not authorize arbitrary
URL rewriting, artifact-repository uploads, or replacing canonical provenance.
Every candidate remains subject to the original byte and SHA-256 contract, and
successful source acquisition does not establish build, target, review, or CI
completion.
