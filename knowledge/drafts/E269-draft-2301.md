# E269 - Isolated Conan Source Probe Directory

## Symptom

`conan source <absolute recipe path>` reports that `source()` is running in the
recipe directory and extracts the upstream archive beside `conanfile.py`.
Conan 2.29.1 also rejects `conan source --output-folder` before recipe code
runs.

## Root Cause

For this command, the absolute recipe path selects the recipe but does not
relocate `self.source_folder`. The command's current source output remains the
recipe directory.

## Recommended Fix

Create a new isolated case directory, copy only `conanfile.py` and
`conandata.yml` into its `recipe` child, set a case-local Conan home, and run
`conan source .` from that copy. Verify positive extraction and fail-closed
archive negatives there, then compare the real worktree status.

## Validation

The unsafe probe was preserved with CLI RC2 and subsequent worktree extraction
evidence. Exact tar top-level members were removed from only the ITK recipe
root. A fresh isolated-copy matrix passed local source, missing archive, bad
SHA, and CMake local-source cases without changing the worktree.

## Safety Boundary

Do not use broad `git clean` after contamination when the recipe directory
contains pre-existing untracked task outputs. Derive an exact archive-member
allowlist, verify every resolved path remains under the task recipe root, and
remove only paths proven to come from the failed probe.
