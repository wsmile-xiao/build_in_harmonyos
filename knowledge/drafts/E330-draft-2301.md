# E330 - Capability-tested shell and selective Automake dispatch on noexec source trees

> Contributor: 2301_80739235 | Status: DRAFT | Created: 2026-08-18

## Why this is a reusable pattern

E228 covers a Libtool wrapper with a sibling `.libs` ELF. PCRE2 exposes a
different but related failure: the upstream `RunTest` and `RunGrepTest` entries
are suffixless shell drivers, while `pcre2posix_test` and `pcre2_jit_test` are
real ELF programs. A generic suffix rule cannot identify the shell drivers, and
an unconditional shell launcher would corrupt the ELF entries. The pattern is
therefore useful for any Automake project whose noexec source/build tree mixes
extensionless shell tests and direct binaries.

## Symptom

On a restricted HarmonyOS/HMDFS path, configure or `make -j1 check` can fail
before the tested code runs. A candidate shell may start successfully but emit a
`getcwd` diagnostic, which makes Autoconf reject the build directory. After that
is fixed, direct execution of the two suffixless shell drivers can still return
`Permission denied` while the compiled ELF tests must remain direct executions.

## Root cause

Three contracts are independent:

1. Shell executability does not prove working-directory capability. The probe
   must run `pwd` from the actual Conan build directory and require return code
   zero with empty stdout and stderr.
2. Autoconf may re-exec through `CONFIG_SHELL`, and Conan `self.run()` sources
   `conanbuild` by default. A shell selected before that step can be replaced
   unless an explicit package environment is sourced after `conanbuild`.
3. Automake's `LOG_COMPILER` applies to a mixed test list. Only the known shell
   drivers may be interpreted by the tested shell; direct ELF tests must be
   passed to `exec` unchanged.

## Recommended solution

1. Build an ordered candidate list from the profile-provided `CONFIG_SHELL`,
   the compiler-tool directory, the target shell and `PATH`.
2. For every candidate, run `pwd` with `cwd` set to the exact Conan build
   directory. Accept only a real executable whose return code is zero and whose
   stdout and stderr are both empty. Fail closed when no candidate meets this
   contract.
3. Save `CONFIG_SHELL` and `SHELL` in a task-local environment script and
   source it after `conanbuild` for configure, build, check and install.
4. Generate a `LOG_COMPILER` dispatcher that recognizes only the project's
   suffixless shell-driver names (`RunTest` and `RunGrepTest` in this case) and
   starts those through the tested shell. All other entries are executed
   directly.

This preserves the upstream test inventory and does not modify the upstream
test sources.

## Forbidden shortcuts

- Do not route the whole test list through `/system/bin/sh`.
- Do not treat `chmod +x` as proof that a HMDFS path is executable.
- Do not accept a `pwd` probe that emits diagnostics.
- Do not rely only on `os.environ` for profile buildenv values inside a Conan
  recipe.
- Do not skip a failing shell driver or count the two ELF tests twice.
