# E2175 — 固定 CMake 可选后端后再核对上游测试分母

## 现象

同一 CMake 项目在不同主机上自动发现 PNG、Iconv 或线程库后，CTest 清单数量会变化；只按源码静态列表填写测试数会漏掉条件测试。

## 根因

上游 `CMakeLists.txt` 用 `WITH_TOOLS`、`WITHOUT_PNG`、`WITH_TESTS` 以及 `find_package(Iconv/Threads)` 条件创建目标。宿主机依赖差异会改变构建目标和 CTest 分母，导致结果不可复核。

## 修复步骤

1. 在 Conan `CMakeToolchain` 中显式冻结可选开关，例如关闭 PNG 工具、开启上游测试。
2. 在已配置的构建目录运行 `ctest -N`，把实际生成的目标作为唯一上游清单。
3. 使用同一构建目录执行 `ctest --output-on-failure`，记录完整 `N/N`；目标平台若缺少可选依赖，必须记录条件变化而不能伪造分母。

## 验证方式

qrencode 4.1.1 使用 `WITH_TOOLS=OFF`、`WITHOUT_PNG=ON`、`WITH_TESTS=ON` 配置，并将 CTest 清单与执行结果绑定到同一构建树；消费者测试另行调用真实 `QRcode_encodeString` API 并验证矩阵尺寸、数据和释放流程。

## 适用范围与边界

适用于通过 `find_package` 或 option 条件增加测试/工具目标的 CMake 库。它不授权关闭核心库测试，也不能用固定静态清单替代目标平台配置后的 `ctest -N`；可选依赖缺失时应保留真实的条件测试证据。
