# E431 — make 默认 /bin/sh 下 which 探测失效导致 pkg-config 探测噪声

> Draft: E431-draft-7643（kamailio-memcached 6.0.6 适配产出）

## 错误特征

用上游 Makefile 构建模块时出现（注意：构建**仍然成功**，属噪声/不可靠信号）：

```text
$ make -C src modules modules=modules/memcached
make[1]: --libs: No such file or directory
make[1]: --libs: No such file or directory
```

不带 `SHELL=` 时有 1~2 条；显式传 `SHELL=<bash 绝对路径>` 后为 0 条（实测）。

## 触发条件

- 平台: OHOS / HarmonyOS PC
- 构建系统: GNU make（默认 shell `/bin/sh`，toybox）
- 上游写法: `BUILDER = $(shell which pkg-config)`（kamailio `src/modules/memcached/Makefile`）

## 根因分析

该 Makefile 用 `which pkg-config` 探测 pkg-config 是否存在：

```make
ifeq ($(CROSS_COMPILE),)
	BUILDER = $(shell which pkg-config)
endif
ifneq ($(BUILDER),)
	DEFS += $(shell $(BUILDER) --cflags libmemcached)
	LIBS += $(shell $(BUILDER) --libs libmemcached)
else
	DEFS += -I$(LOCALBASE)/include -I$(SYSBASE)/include
	LIBS += -L$(LOCALBASE)/lib -L$(SYSBASE)/lib -lmemcached
endif
```

`BUILDER` 是**递归变量**，每次展开都会重跑 `which pkg-config`。在 OHOS 上
GNU make 的默认 shell 环境下该探测不稳定：某次展开返回空 → `$(shell --libs libmemcached)`
把 `--libs` 当命令执行 → 报 `--libs: No such file or directory`。

风险在于：探测结果与 `else` 分支的取舍**不可确定**，链接参数来源在
"pkg-config 的 .pc" 与 "LOCALBASE/SYSBASE 裸路径" 之间摇摆——后者既不带
`system_libs`（见 E429），也依赖机器上恰好存在 `-lmemcached`。

## 解决方案

### 推荐方案

驱动 make 时显式指定 shell（无需改源码）：

```bash
make -C src cfg                                        SHELL=/data/service/hnp/bin/bash
make -C src modules modules=modules/memcached -j1      SHELL=/data/service/hnp/bin/bash
```

并同时用 `PKG_CONFIG_PATH` 指向 `PkgConfigDeps` 生成的 `.pc` 目录，使探测结果确定化：

```python
shell = os.environ.get("CONFIG_SHELL") or "/data/service/hnp/bin/bash"
if not os.path.isfile(shell):
    shell = "/bin/sh"
self.run("make -C src modules modules=modules/memcached -j1 SHELL=%s" % shell)
```

### 禁止做法

- ❌ 在源码树上 sed 改 `which pkg-config`（应通过构建参数适配，R6/R8）
- ❌ 无视该噪声、把"链接成功"当"链接正确"（真正的后果是 E429 的静默缺陷）

## 验证

```bash
# 噪声计数：期望 0
make -C src modules modules=modules/memcached -n SHELL=/data/service/hnp/bin/bash 2>&1 | grep -c "No such"
# 链接参数来源：makecfg.lst 中的 -I 应指向 PKG_CONFIG_PATH 的 .pc 前缀
grep -o -- "-I[^ ]*libmemcached[^ ]*" src/modules/memcached/makecfg.lst
```
