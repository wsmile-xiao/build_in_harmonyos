# E768 — Conan CMakeDeps 同 cmake_file_name 撞名：属主包独占聚合，后者组件静默丢弃

## 错误特征

双包依赖模式（包 A `requires` 包 B，两包都声明 `cmake_file_name="Boost"`）下，消费者侧 CMake 报：

```
CMake Error at CMakeLists.txt:5 (target_link_libraries):
  Target "xxx" links to:

    Boost::yyy

  but the target was not found.  Possible reasons include:

    * There is a typo in the target name.
    * A find_package call is missing for an IMPORTED target.
```

或 `find_package(Boost REQUIRED CONFIG COMPONENTS yyy)` 时组件未被声明。生成的 `BoostConfig.cmake` / `BoostTargets.cmake` 里只出现一个包的组件（`list(APPEND <owner-pkg>_COMPONENT_NAMES ...)` 只有属主包的组件清单），另一个包的组件完全消失，且 conan 无任何警告。

## 根因（conan 2.29.1 实测）

CMakeDeps 生成器对同名 `cmake_file_name` 的多个包**不聚合**，而是**独占**：
- 同名 Config 文件只由一个"属主包"生成内容，属主按包名字母序（实测
  `boost1.84-context` 赢过 `boost1.84-fiber`，与 requires 顺序无关）；
- 输家包的组件目标被静默丢弃；
- 被测包（test_package 的 tested_reference）的组件同样不进聚合文件，
  `conandeps_legacy.cmake` 只留全限定全局目标（如 `probe-deps::probe-deps`），
  组件级目标（`Boost::probe`）不存在。

这与 conan 官方文档"同名 cmake_file_name 组件聚合进同一 Config"的描述不符。

## 解法（依赖模式组件目标全保留）

1. 被依赖包保留 `cmake_file_name="Boost"`；
2. 依赖方包改**独立** `cmake_file_name`（包名风格，`boost1.84-log` 先例同款）；
3. 组件 `cmake_target_name` 用全限定名；对上游组件的 `requires` 用跨包全限定名；
4. test_package 用独立 `find_package(<独立名>)` + 全限定目标链接。

```python
def package_info(self):
    self.cpp_info.set_property("cmake_file_name", "boost1.84-fiber")
    self.cpp_info.components["boost_fiber"].libs = ["boost_fiber"]
    self.cpp_info.components["boost_fiber"].requires = [
        "boost1.84-context::boost_context"]   # 跨包全限定
    self.cpp_info.components["boost_fiber"].set_property(
        "cmake_target_name", "boost1.84-fiber::boost_fiber")
```

```cmake
find_package(boost1.84-fiber REQUIRED CONFIG)
target_link_libraries(x PRIVATE boost1.84-fiber::boost_fiber)
```

跨包传递的库（libboost_context.a）在链接期正确解析（实测编译链接运行全过）。

## 降级方案

必须保持 `Boost::xxx` 短名生态兼容时，放弃 conan requires 依赖模式，回自包含路线（包内自带依赖库源一起编译，如 boost1.84-coroutine 自带 context 源），代价是包体重复、无法复用已发布依赖包。

## 红线

- 禁止靠 requires 顺序"抢属主"——实测与顺序无关，字母序决定；
- 独立 cmake_file_name 后，消费者文档必须同步写清楚 find_package 名（不再是 Boost）。

## 实证

- 探针复现：双包（cmake_file_name=Boost 撞名）conan create → 组件目标消失；独立名 + 全限定 requires → 编译链接运行全绿；
- verify_builds: #45444（boost1.84-fiber PR #9758，CI 绿）；
- 参照先例：boost1.84-log（独立 cmake_file_name 手法）、boost1.84-coroutine（自包含路线对照组）。
