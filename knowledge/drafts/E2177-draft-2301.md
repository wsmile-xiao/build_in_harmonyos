# E2177: Device signing is a target capability, not a local section check

## Symptom

An AArch64 OHOS consumer links and has execute permission, but the target
returns `Permission denied` and `RC=126`. Adding a `.codesign` section with a
host-side structural tool does not change that result.

## Root cause

OpenHarmony validates ELF execution with the endpoint's real
`binary-sign-tool`, and filesystem/ownership rules apply to the copied target
file. A local stand-in can prove only ELF structure. It cannot prove that the
device trusts the signature or accepts the task-private copy.

## Fix

1. Build the target ELF and record its source, input, byte count, and SHA-256.
2. Transfer unsigned executable and shared-library inputs to a unique task root
   and independently read back bytes and hashes.
3. On the device, remove any stale `.codesign` section from each private copy,
   sign with the endpoint's real signer, and verify exactly one `.codesign`
   section with the endpoint readelf.
4. Restore owner execute permission (`0755` for executable ELF files), launch
   once with an explicit private library path, and record the real marker/RC.
5. If execution returns `RC=126`, freeze that run as failed, release only its
   own root, and create a successor with a new run ID. Do not retry launch or
   combine it with local mock-sign evidence.

## Evidence

For Allegro 4.4.3.1, r1 failed under HMDfs storage, r2 failed with an
unsigned ELF on executable HMFS, and r3 failed with a host structural
signature. r4 used `/storage/Users/currentUser/usr/local/bin/binary-sign-tool`
and `llvm-objcopy`; both files had one `.codesign` section and owner execute,
then the target emitted `allegro_core_contract PASS` with `RC=0`. The r4
process was clean and its private root passed release/postrelease checks.

## Applicability and safety boundaries

This applies to any OpenHarmony PC W3 flow that executes newly transferred
ELF files, including shared-library dependencies. It does not make a local
signature tool a substitute for the endpoint signer, does not authorize
shared-cache mutation, and does not permit a second launch after a consumed
transaction. Compile/link success and a `.codesign` section count remain
separate from target runtime acceptance.
