# E2182: Preserve cross-DSO exception identity on non-glibc Linux-like targets

## Symptom

An OHOS shared-library build compiles and links its tests, but a test that
throws an exported exception reports a failed catch or aborts. The failure is
visible in tests such as `test_global_control` and `test_tbb_header`, while
ordinary API tests continue to pass.

## Root cause

The target is Linux-like but does not use glibc. With hidden default symbol
visibility, the exception class can have a different RTTI identity in the
shared library and the executable. A `catch` for the public exception then
does not match, and the test reaches its aborting assertion path. This is an
ABI/visibility capability difference, not a compile or link failure.

## Fix

1. Confirm that the failing path throws the exported exception across the
   shared-library boundary and that the ordinary build uses hidden visibility.
2. Add default visibility only around the affected public exception type under
   the narrow non-glibc Linux-like capability condition.
3. Keep all unrelated symbols hidden and preserve the complete test suite.
4. Replay the patch with the release patch-ng settings and run the affected
   throw/catch tests plus the remaining target CTest inventory.

## Validation

Buildbot #41540 bound to PR #8474 and revision
`86d839949a99972094c6f0cde46510f041e41689` built the library successfully but
failed `test_global_control` and `test_tbb_header`. The successor patch adds
default visibility for `unsafe_wait` only when `__linux__ && !__GLIBC__` and
passes strict patch-ng replay on the official oneTBB 2023.1.0 source tree.

## Applicability and safety boundaries

This pattern applies to exported C++ exception types crossing a shared-library
boundary on targets where the standard Linux/glibc ABI assumptions do not
hold. It does not justify exporting every library symbol, suppressing a failed
catch, or removing ABI tests. A target that provides the normal glibc ABI must
retain the upstream visibility behavior unless an independent failure proves
otherwise.
