# mdocml 1.14.6 — 手写 configure 的三个环境缺口（configure.local 单点修复）

> 草稿号 **E697**（`knowledge_id.py --claim --task mdocml-1.14.6` 取号，回查未占用）
> 状态：draft ｜ 触发工具：`configure` / `make` ｜ 阶段：configuration + testing
> 关键签名：`FATAL: no endian conversion functions found`、`cc: inaccessible or not found`、
> `cannot create hard link`、`locale: inaccessible or not found`、`utf8:diff`

## 一句话

上游是**手写 sh configure**（非 autotools）时，OHOS 上「探测全红 + 硬链接失败 + utf8 测试
成批失败」三个现象是**同一类环境默认值落空**，全部由 `configure.local` 一行一个变量修复，
**零源码补丁**；错误措辞（`compilation failed` / `FATAL`）极易把人引向"改源码"的误修路径。

## 现象（mandoc / mdocml 1.14.6 实测）

1. `sh ./configure` → 每条探测都 `tested *: no (compilation failed)`，
   `config.log` 里逐条 `cc: inaccessible or not found`，
   最终 `FATAL: no endian conversion functions found` + `FATAL: nanosleep: no`，
   **不生成 `Makefile.local`**。
2. `make` → `ln: cannot create hard link from 'mandoc' to 'man': Operation not permitted`
   → `make: *** [Makefile:522: man] Error 1`。
3. `make regress` → `NUMBER OF FAILED TESTS: 19 (of 1427 tests run.)`，
   19 项**全部**是 `utf8:diff`；`config.h` 里 `#define HAVE_WCHAR 0`，
   configure 日志 `locale: inaccessible or not found` + `tested wchar: no (no UTF8_LOCALE)`。
4. `make install` → `make: install: No such file or directory`（**Error 127**，设备无 `install` 命令）。

## 根因

上游构建入口是手写的 `sh configure`（`head` 可见非 `generated by GNU Autoconf`，源树无
`aclocal.m4` / `configure.ac` / `config.guess` / `config.sub`），其行为靠 `. ./configure.local`
读用户变量。三个默认值在 OHOS/CI worker 全部落空：

| # | 上游默认 | 落空原因 | 后果 |
|---|---|---|---|
| 1 | `CC="cc"` | 设备 PATH 有 `clang` **无 `cc`** | 全部 `runtest` 探测失败 → `FATAL` 硬失败 |
| 2 | `LN="ln -f"` | **HMDFS 不支持硬链接**（`device-facts` §一.21） | `make` 建别名失败 → Error 1 |
| 3 | `UTF8_LOCALE` 靠 `locale -a` 探测 | 设备**无 `locale` 命令** | `HAVE_WCHAR=0` → `-T utf8` 输出与期望不一致 → 19 个 `utf8:diff` |

三者都是**环境问题，不是代码缺陷**；同族还有设备**无 `install` 命令**（`make install` 必 Error 127）。

## 修法（`configure.local` 单点注入，零源码补丁）

```sh
CC="<profile tools.build:compiler_executables.c>"   # R33：conf 整取 dict 再索引，不读 shell 环境变量
AR="<profile ar>"                                    # llvm-ar 绝对路径
LN="cp -f"                                           # HMDFS 硬链接替代（值必须加引号）
STATIC=" "                                           # 官方 configure.local.example 置空写法
UTF8_LOCALE="en_US.UTF-8"                            # 手工指定，绕开缺失的 locale 命令
CFLAGS="-O3 -pipe -DNDEBUG -I<conan zlib>/include"   # R33 钉死 + 依赖头显式注入
LDFLAGS="-L<conan zlib>/lib"                         # 依赖库显式注入（不依赖 SDK sysroot 隐式可见）
```

配方在 `build()` 内写 `configure.local` 再 `sh ./configure` → 自动生成 `config.h` + `Makefile.local`。

### 两个必须先实测的前置

1. **先证明值可用，再手工指定**：`UTF8_LOCALE` 要先跑
   `setlocale(LC_CTYPE,"en_US.UTF-8")` 探针 —— 返回非 NULL、`wcwidth(L' ')=1`、
   `sizeof(wchar_t)=4` 才敢指定。否则会把「locale 真不可用」误判成「探测脚本坏了」。
2. **含空格的值必须整体加双引号**：`. ./configure.local` 是 shell 赋值语义，
   裸 `LN=cp -f` 被解析成「前缀赋值 + 执行 `-f`」→ configure **立即 rc=127**，
   错误信息只有 `-f: not found` 一行，极难反查（本任务实测踩过一次）。

## 验收（不能只看"编过了"）

| 判据 | 修前 | 修后 |
|---|---|---|
| `grep -c FATAL config.log` | 2 | **0** |
| `Makefile.local` 生成 | 无 | 有，且 `CC`/`AR`/`LN`/`CFLAGS`/`LDFLAGS`/`STATIC` 全部落地 |
| `config.h` 的 `HAVE_WCHAR` | `0` | **`1`** |
| `make` | `Error 1`（硬链接） | **rc=0**（mandoc/man/demandoc/soelim/libmandoc.a 全产出） |
| `make regress` | `1427 run / 19 failed` | **`1427 run / 0 failed`**（约 89 秒） |
| `make install` | `Error 127`（无 `install` 命令） | 不走 install，`package()` 直接收纳产物 |

**核心**：上游测试从 `19 failed` 变成 `0 failed` 才是缺口修复的正面证据 —— 这比
「跳过/剔除 utf8 测试」高一档（后者属 §3.5 不认可的凑绿）。

## 复现命令

```sh
# 1) 定性：确认是手写 configure 而非 autotools
head -5 configure | grep -q "GNU Autoconf" && echo "autotools" || echo "handwritten"
ls aclocal.m4 configure.ac config.guess config.sub 2>/dev/null

# 2) 写 configure.local（含引号）后：
sh ./configure 2>&1 | grep -E 'FATAL|selected'
grep -c FATAL config.log                      # 期望 0
grep -E '^(CC|AR|LN|CFLAGS|LDFLAGS|STATIC)[[:space:]]*=' Makefile.local
grep -E 'HAVE_WCHAR|UTF8_LOCALE' config.h     # 期望 HAVE_WCHAR 1

# 3) 构建 + 上游测试
make -j1 && make regress 2>&1 | grep -E 'tests run|NUMBER OF FAILED'
```
