# E340 — X11 客户端库头文件级依赖在同轨可用时用 transitive_headers 消费，而非桩 .pc + vendor

## 错误特征

libXcomposite 0.4.6 的 `Xcomposite.h` 第 49 行 `#include <X11/extensions/Xfixes.h>`，
但库本身只链接 `-lX11`。`configure.ac` 同时声明
`PKG_CHECK_MODULES(XCOMPOSITE, [compositeproto >= 0.4 xproto >= 7.0.22 x11])`
与 `PKG_CHECK_MODULES(XFIXES, xfixes)`。直接照搬跨轨 libXi 的"桩 .pc + vendor 头"
方案（E338）是过度工程：本轨道上 libxfixes/6.1.0 已随 `xfixes.pc` 发布，
错误做法是仍去 vendor 一份 Xfixes.h 并写桩 .pc，造成维护负担与符号分叉风险。

## 触发条件

- 构建系统: Autotools，X11 家族扩展库（Xcomposite / Xdamage / Xinerama /
  Xrandr / Xcursor 等）。
- 依赖的 pkg-config 模块（如 `xfixes`）**已在 cmd-pkgs 同轨**发布
  （`libxfixes/6.1.0`，`pkg_config_name=xfixes`），且对上游其余依赖
  （libx11/6.4.0、libxext/6.4.0、xorgproto/2025.1）兼容。
- 依赖是**编译期/头文件级**：`Xcomposite.h` 拉取 `Xfixes.h` 的
  `PointerBarrier`/region 类型，产物 libXcomposite.so.1 的 NEEDED 中
  没有 libXfixes.so。

## 根因分析

- X11 客户端库的依赖可二分：**链接依赖**（libXcomposite.so 的 NEEDED 里有
  libX11.so）与**头文件级依赖**（仅编译期 `#include` 消费类型/宏，链接期不产生
  NEEDED）。
- `PKG_CHECK_MODULES(XFIXES, xfixes)` 只为了让 configure 拿到 `-I` 头文件路径，
  语义上等同 E338 注释里的 "CFLAGS only"。
- 当该头文件级依赖的 Conan 包在同轨可用时，`transitive_headers=True` 已把
  include 目录透传给消费者，无需再伪造任何 pkg-config 数据。
- 跨轨才需要 E338 的桩方案：libxfixes/6.0.2 被 pin 在 Track A（libx11/1.8.13），
  拉入本图会形成同图双 libx11 版本冲突。

## 解决方案

### 推荐方案：同轨头文件级依赖直接 transitive_headers

1. `requirements`: `self.requires("libxfixes/6.1.0", transitive_headers=True)`
   及其余链接依赖（libx11/6.4.0、libxext/6.4.0、xorgproto/2025.1）。
2. `generate()`: 设 `XFIXES_CFLAGS`（供 configure 找头文件）、
   `XFIXES_LIBS=""`、`XCOMPOSITE_CFLAGS`、`XCOMPOSITE_LIBS=self._module_libs("-lX11")`。
3. 不用写任何桩 .pc、不 vendor 头文件、不打 patch。
4. `package_info`: `libs=["Composite"]`，`requires` 只列**链接级**依赖
   （libx11/libxext/libxfixes/xorgproto 中实际产生 NEEDED 的），
   `pkg_config_name="xcomposite"`，`cmake_target_name="libxcomposite::libxcomposite"`。

`readelf -d libXcomposite.so.1 | grep NEEDED` 口径验证：仅 libX11.so.6，无 libXfixes.so。

### 分类判定表

| 依赖性质 | 同轨（cmd-pkgs）| 跨轨（Track A）|
|---|---|---|
| 链接级 | 普通 `requires` + `package_info.requires` | 需整图回归 Track A 或拆分 |
| 头文件级 | `transitive_headers=True`，不写链接 flags | 桩 .pc + vendor 头（E338）|

## 禁止策略

- 同轨可用时不写桩 .pc / 不 vendor 头文件（过度工程，产生维护负担）。
- 不把头文件级依赖写进 `package_info.requires`（会让消费者链接到错误的库）。
- 不因头文件级依赖而要求改 libxfixes 自身配方。
