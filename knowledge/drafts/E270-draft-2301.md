# E270 - Complete Offline Upstream Test Input Closure

## Symptom

A clean upstream test build can still attempt network access or fail on missing
inputs after the main source archive is frozen. ITK 5.4.6 exposed three such
boundaries: a direct clang-format download during configuration, a host
libiconv requirement in vendored GDCM, and content-addressed test baselines
resolved by CMake ExternalData near the end of the build.

A clean Conan CI worker exposed a fourth boundary: the recipe correctly bound a
task-local object store during development, but the store was not part of the
recipe export. CMake therefore reached an existing `.cid` pointer and failed
with `Object CID=... not found` while URL templates were intentionally empty.

A later CI run exposed a fifth boundary before checkout completed. GitCode's
worker reconstructed the PR from a text diff, reported `missing binary patch
data` for the newly added CID objects, and never reached the recipe. The Git
objects were valid; the PR patch transport omitted their binary payloads.
Formal entry E256 already covers this transport symptom for disposable build
artifacts and recommends removing them. It is a near match, not an equivalent
solution here, because these CID baselines are required by the preserved
upstream test inventory and must be transported rather than deleted.

## Root Cause

The complete test graph includes auxiliary tools, compiler support libraries,
ExternalProject sources, and baseline data that are not part of the main
release archive. A no-download switch does not automatically govern every
legacy direct download path.

## Recommended Fix

Keep `BUILD_TESTING` and the real test modules enabled. Disable only the
developer clang-format target, bind KWStyle to its checksum-frozen local
source, provide a compiler-compatible host libiconv, and create a manifest for
the complete ExternalData object store. Bind the hash-store root itself: for
ITK's CID layout this is `.../test-data/Objects`, whose direct child is
`CID/<digest>`; `.../test-data` is only the manifest parent. Require empty
URL templates and use a rejecting proxy to make any omitted input fail closed.
On filesystems that reject symbolic links, set `ExternalData_NO_SYMLINKS=ON`
so CMake uses its built-in atomic copy path instead of changing the data
layout or restoring network fallback.

For Conan, export the manifest and complete object store through
`export_sources()`. Runnable builds should default to
`self.source_folder/test-data/Objects`, while an explicit environment override
may take precedence only after the same manifest, path, size, hash, duplicate,
extra-file, and link checks pass. Non-runnable cross builds must not bind host
test data.

When CI applies a text-only PR patch, store each binary object in the source
tree as canonical 76-column Base64 text. During `export_sources()`, require the
exact encoded file set, reject links and non-canonical encoding, decode into
the isolated Conan export-sources directory, and verify every decoded path,
byte count, and SHA-256 against the unchanged manifest. Export only the
manifest and original decoded objects; the build and CMake paths must never
consume the encoded representation directly.

## Validation

The clean ITK build completed `2209/2209` Ninja edges from the local KWStyle
source and a 14-object frozen CID store. CTest discovered 618 entries, all 618
ran and passed, and disabled/failed/skipped counts were zero. The run used no
device and no network fallback.

A fresh Conan 2.29.1 export produced recipe revision
`272725e9dca1c58a5f9fcdb304dcd52f`. Its export-sources tree contained 15/15
files: the manifest plus all 14 CID objects, totaling 992270 object bytes, with
every relative path, byte count, and SHA-256 equal to the candidate, and zero
encoded files. The text-transport matrix passed 6/6 and the exported runtime
matrix passed 8/8. Earlier directed store and generate matrices passed 12/12
and 8/8, including linked roots,
nested links, missing/tampered/extra/duplicate objects, explicit-override
precedence, empty-override fallback, non-runnable explicit-override isolation,
and wrong-root rejection. A production
CMake readback reused the completed probe without rerun and passed 2/2: the
exact object resolved, while the manifest-parent root remained a code-1
negative with no URL fallback.

An OHOS W3 negative proved the path boundary: the requested CID was present
and hash-bound under `Objects/CID`, but passing the parent directory failed
with `Object CID=... not found` and no URL templates. Production must pass
the `Objects` directory; retain a parent-root negative so this cannot regress.
The next device run found the object but failed while creating the temporary
symbolic link on HMDFS. CMake's supported `ExternalData_NO_SYMLINKS` switch
selects the copy branch and preserves the same CID and hash verification.

## Safety Boundary

Do not disable the upstream suite, delete tests with missing baselines, copy an
unbounded cache, commit an unverified binary-to-text conversion, or mix support
libraries from a different compiler ABI. Bind each auxiliary input by path,
bytes, and SHA-256 before the clean run. A local round-trip does not prove the
CI transport until a replacement checkout reaches the recipe; that final
Buildbot confirmation remains required.
