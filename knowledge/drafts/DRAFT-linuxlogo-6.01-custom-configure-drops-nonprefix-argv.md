# DRAFT-linuxlogo-6.01（草稿）: 手写 configure 只认 `--prefix`，非 `--prefix` 的 argv 被静默丢弃、部分环境变量反而存活 ⇒ 工具链只能经 **make 命令行**传入

## 基本信息
- **严重度**: 2
- **类别**: build-system, cross-compile, configure-script, toolchain
- **阶段**: configuration
- **作者**: 主理-34
- **来源包**: linuxlogo 6.01（B 机真机实测）
- **来源 PR / commit**: (待主窗回填)

## 错误特征
```
make: O2: No such file or directory
make: [Makefile:75: parse_logos] Error 127 (ignored)
make: *** [Makefile:81: load_logos.h] Error 127
# 而 ./configure 的退出码是 0，只打印过一行：
C compiler not found!
# 生成物里：
CC=
CFLAGS=-O2
```
关键指纹：上游 `configure` 是**手写脚本**（头部没有 `# Generated by GNU Autoconf`），
`while` 循环里用 `case "${1%=*}"` 做**只列了 `--help`/`--prefix` 的白名单**，
未匹配到的 token 直接 `shift` 丢弃；随后自己 `which gcc`/`which cc` 重算 `CC`、
再按 `if [ $CC = gcc ]` **无条件重写 `CFLAGS`**，最后 `echo` 成 `Makefile.default`。

## 根因分析（linuxlogo 6.01 的 configure 实际行号）
```sh
while [ $# -gt 0 ]                        # 17
   case "${1%=*}" in                      # 19  ⇒ CC=clang 匹配到的是 "CC"
      --prefix) PREFIX="${1#*=}";;        # 21  ⇒ 白名单里只有 --help/--prefix
   esac
   shift                                  # 23  ⇒ 其余 token 静默丢弃
done
which gcc ; GCC_MISSING=$?                # 44-45
if [ $GCC_MISSING -eq 1 ]; then
   which cc ; CC_MISSING=$?               # 48-49
   if [ $CC_MISSING -eq 1 ]; then
      echo "C compiler not found!"        # 51  ⇒ 只提示，不赋值、不退出
   else CC=cc; fi
else CC=gcc; fi
if [ $CC = gcc ]; then CFLAGS="-Wall -O2"; else CFLAGS="-O2"; fi   # 63-67 无条件重写
echo "CC=$CC" > Makefile.default          # 92
echo "CFLAGS=$CFLAGS" >> Makefile.default # 97
```

三件事叠加造成"配置成功、构建炸在别处"：

1. **命令行 `var=value` 无效**：`${1%=*}` 把 `CC=clang` 削成 `CC` 去匹配白名单，没有任何分支 ⇒ 丢弃。
2. **环境变量只在"探测落空"分支里侥幸存活**：脚本从不用 `${CC:-...}` 读 env，
   但 `which cc` 也失败时那条分支**根本不给 CC 赋值**，于是环境里的 `CC` 原样活到生成物里；
   `CFLAGS` 却没有这种侥幸（第 63-67 行必重写）。⇒ "手写 configure 到底认哪种形态"**不可跨包类推**。
3. **静默失败**：探测失败既不退出也不置非零码，`CC=`（空）被烧进 `Makefile.default`；
   `make` 阶段 `$(CC)` 展开为空 ⇒ 命令行首词变成 `-O2`，报出与编译器毫无关系的
   `make: O2: No such file or directory`，而该 recipe 带 `-` 前缀被 `Error 127 (ignored)` 吞掉，
   直到下一条不带 `-` 的 recipe 才致命失败 ⇒ 第一条真实错误离根因两层远。

宿主装有 gcc/cc 的机器上更危险——第 56 行会把**宿主编译器**烧进生成物，配置"成功"、
产出宿主架构对象，错误延迟到链接、运行或 CI 产物校验才暴露。

## 推荐方案
**方法**: `make-inline-variables-plus-generated-file-audit`（优先级 1，配方侧，不改上游）

```python
compilers = self.conf.get("tools.build:compiler_executables", default={}, check_type=dict)
cc = compilers.get("c") or "clang"
ar = compilers.get("ar") or "llvm-ar"
# configure 只用来生成 Makefile.default（它只认 --prefix）
self.run("sh ./configure --prefix={0}".format(self.package_folder), cwd=self.source_folder)
# 工具链与功能开关一律走 make 行内变量（优先级高于 Makefile 内 include 的赋值，
# 且经 MAKEFLAGS 自动下发给 libsysinfo 子 make）
self.run("make CC={0} AR={1} OS=Linux USE_I18N=0 TRANSLATIONS= -j1".format(cc, ar),
         cwd=self.source_folder)
```

**验证/命令**（同一份源码三臂对照，本包实测于 B 机 2026-09-25，每臂跑完
`grep -E '^(CC|CFLAGS)=' Makefile.default`）:
```
① sh ./configure --prefix=P
     ⇒ CC=（空） / CFLAGS=-O2                 rc=0
② sh ./configure --prefix=P CC=clang CFLAGS=-DMARKER9911
     ⇒ CC=（空） / CFLAGS=-O2                 与 ① 逐字相同 ⇒ 命令行形态被丢弃
③ CC=<abs>/clang CFLAGS=-DMARKER9911 sh ./configure --prefix=P
     ⇒ CC=<abs>/clang / CFLAGS=-O2            CC 环境变量意外存活、CFLAGS 仍被重置
```
②③ 合起来否证了"照 lzip 家族那样把 CC 当 configure 参数传"这条解法在本包可用，也否证了
"手写 configure 一律忽略环境变量"这句话；③ 的存活是 not-found 分支不赋值的副作用，
**不能当作可依赖的传参通道**（换一台装有 gcc 的机器就会走别的答案）。

采用 make 行内变量形态后本包实测：`conan-verify` 报告 `**Verdict**: PASS`（G1/G2/G3/G4 全 PASS，
`VERIFY_RC=0`）；`build()` 内 4 项上游用例（test1/test2/memory_print/memory_method）全部真实执行并通过；
W3 本地 CI 模拟 `L0_RESULT=pass`、`L1_RESULT=pass`、`Pass rate: 100.0% (1/1)`、`.ci-result.json` `exit_code: 0`。

## 适用边界 / 反例 / 解除条件
- **不适用** autoconf 生成的 configure（读同名环境变量是标准行为；判据看头部生成注释）。
- **不适用** 会对白名单外参数**致命退出 `Unknown option`** 的手写 configure ⇒ 那是 E2167 的覆盖面，
  解法是 `AutotoolsToolchain.update_configure_args({"--oldincludedir": None})` 剪参数。
- **反例（同族不同协议）** lzip 1.24.1（池草稿 M12）：命令行 `CXX=…` 生效、环境变量被忽略 ⇒
  与本案正好相反，两条不能互相替代；碰到"手写 configure"必须**自己跑三臂对照**再决定传参面。
- **兜底（优先级 2）**：若 make recipe 里硬编码了编译器名（行内变量压不住），才在 configure 之后、
  make 之前 `sed` 改写**生成**的 `Makefile.default` 的 `CC=`/`CFLAGS=` 行；与 R6 取向冲突，
  须在 notes/正文逐项说明改了哪几行、为何无源码级把手。
- **解除条件**：上游改用 autotools/meson/CMake，或脚本改为读 env 且不再重写 flags。
