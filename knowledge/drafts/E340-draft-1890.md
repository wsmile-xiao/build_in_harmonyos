# E340 — CNB 制品仓把"依赖未发布"报成基础设施故障（system acceleration policy not enabled）

## 错误特征

CI `conan-build-test` 步骤的 L0 门禁失败，日志形如：

```
[step] L0i: Checking dependency availability in registry (R36)...
        [retry] registry probe 1/3 failed for libparserutils/0.2.5 (transient?), retrying...
        [retry] registry probe 2/3 failed for libparserutils/0.2.5 (transient?), retrying...
        [error] registry unreachable for: libparserutils/0.2.5
        conan stderr: Connecting to remote 'ohpcd' anonymously ERROR: error:system acceleration policy not enabled. [Remote: ohpcd]
[fail] L0i: Registry unreachable (infra error, not R36 violation): libparserutils/0.2.5
```

真实含义：**依赖包未发布到制品仓**，而非 worker 网络/认证故障。

## 触发条件

- 构建系统: Conan（CI 走 `ci/conan/build_and_test.sh` 的 L0i 依赖发布检查）
- 阶段: configuration（构建前的制品仓依赖探测）

## 根因分析

1. 制品仓是 CNB(cnb.cool)。对**不存在的包**执行 `conan download ... -r=ohpcd --only-recipe`
   时，CNB 返回 `error:system acceleration policy not enabled`（HTTP 404 / route not matched），
   **不是**标准 Conan 的 "not found/404" 文本。
2. `build_and_test.sh` L0i 的分类逻辑只把
   `unable to find|does not exist|not found|404` 识别为"依赖未发布"（R36），
   其余报错一律归为 `registry_unreachable`（基础设施故障）。
3. 于是真实根因被掩盖：R36 要求**依赖必须先发布到制品仓**（合并依赖 PR 后由发布流水线上传）。
4. 本地通过的原因：本地 conan cache 已有该依赖配方/二进制，`conan create` 直接从 cache 解析，
   不触发制品仓探测——"本地通过、PR CI 失败"是 cache 造成的假象。

## 解决方案

### 推荐方案

按 R36 先把依赖发布到制品仓，再重跑本 PR 的 CI：

```bash
# 1) 确认依赖是否真的未发布
conan list "libparserutils/*" -r=ohpcd          # 空输出 = 未发布
conan download "libparserutils/0.2.5" -r=ohpcd --only-recipe  # 与 L0i 相同的探测

# 2) 依赖发布后（或确认已发布），重新触发 PR CI
python3 scripts/gitcode_pr.py trigger-ci --repo OpenHarmonyPCDeveloper/build_in_harmonyos --number 6869
```

### 禁止做法

- ❌ 把 "system acceleration policy not enabled" 当成 worker 网络故障，盲目 /rebuild
  或"修 worker 网络"——包不存在时永远不会通过。
- ❌ 用本地 cache 有配方当作"制品仓已发布"的证据——CI 是干净环境，必须走制品仓探测。

## 验证

```bash
conan list "libparserutils/*" -r=ohpcd && conan download "libparserutils/0.2.5" -r=ohpcd --only-recipe
```

依赖发布后本地跑 `CI_PACKAGES="archives/l/libhubbub/0.3.8" zsh ci/conan/build_and_test.sh` 全绿，
PR 重跑 CI 后 L0i 通过。
