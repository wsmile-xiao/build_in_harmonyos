# E2149 - Hash-bound authority HTTP fallback for Conan workers without curl or SSL

## Symptom

An OpenHarmony PC CI worker reaches the Conan source phase but fails before
extraction or compilation:

```text
[Errno 2] No such file or directory: 'curl'
Can't connect to HTTPS URL because the SSL module is not available.
```

The shared pre-download layer can also truncate a hyphenated archive filename,
so its best-effort URL is not a reliable substitute for the recipe consumer.

## Root Cause

The worker has neither a usable `curl` command nor Python SSL support. Conan's
normal HTTPS downloader therefore cannot consume an otherwise valid official
source URL. Independently, a CI URL-extraction expression that excludes `-`
can stop at the first hyphen in an archive filename. The latter is shared
infrastructure behavior and must not be hidden by editing CI from a software
PR.

## Fix

When an authoritative distribution service exposes byte-identical release
content directly over HTTP:

1. Keep the official HTTPS URL first in `sources.url`.
2. Add the authority HTTP URL second.
3. Keep one SHA-256 independently verified against the official release.
4. Prove that the HTTP endpoint returns a direct response rather than an HTTPS
   redirect, and bind its exact byte length and stream hash.
5. In a fresh isolated Conan home, force only the first HTTPS URL to fail.
6. Require Conan to print `Trying another mirror`, return RC0, validate the
   checksum, and extract the expected source layout from the second URL.

For pkgconf 3.0.5, the official archive and Alpine authority mirror were both
426972 bytes with SHA-256
`3acd3a8a3cce65a8d620321855d92fb602e026cbe8e13ee36bdec58483b59ace`.
The isolated `conan source` fallback completed RC0 and extracted 770 files.

## Validation

- Buildbot build `#26293`, buildid `29120`, recorded both exact worker errors
  before source extraction.
- The authority HTTP endpoint returned direct HTTP 200 without an HTTPS
  redirect.
- The fallback bytes matched the official release length and SHA-256.
- A real isolated Conan source transaction forced the first URL to fail,
  selected the second mirror, verified the hash, and extracted the full tree.
- Replacement exact-current-HEAD CI remains the final integration gate.

## Safety Boundaries

- Never replace or demote the official HTTPS URL.
- Never use an arbitrary HTTP mirror, personal fork, rolling branch, or unknown
  CDN. The mirror must be an authority for the distribution and byte-identical
  to the official release.
- Never disable TLS verification, checksum verification, or source hashing.
- If no qualifying HTTP authority exists, report a worker infrastructure
  blocker instead of vendoring source bytes or weakening integrity checks.
- This source fallback does not prove compilation, tests, target execution,
  Review, CI, submission, merge, or publication.
