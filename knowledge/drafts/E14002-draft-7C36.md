# E14002 — 依赖的 ncurses 是 opaque API，`WINDOW` 内部字段编译失败

## 错误特征

```
linpac.cc:237:38: error: member access into incomplete type 'WINDOW' (aka '_win_st')
    setIConfig("mon_end_line", stdscr->_maxy);
                               ^
<ncurses>/include/ncurses.h:456:16: note: forward declaration of '_win_st'
typedef struct _win_st WINDOW;
```

## 触发条件

- 构建系统: 任意（本例 autotools）
- 阶段: 编译
- 链接的是**制品仓/Conan 提供的 ncurses**，且源码直接访问 `WINDOW` 内部字段
  （`_maxx` / `_maxy` / `_clear` / `_begy` …）

## 根因分析

Conan ncurses 包按 `--enable-opaque-curses` 构建，头文件里写死：

```c
#define NCURSES_OPAQUE       1
...
#if !NCURSES_OPAQUE
struct _win_st { ... };
#endif
```

因此 `WINDOW` 只是 `struct _win_st` 的 typedef，内部字段不可见。宿主发行版的
ncurses 通常**不是** opaque，所以同一份源码在本地手工编译能过、在 conan 构建里
报错——容易被误判为“工具链差异”。这是“依赖包的编译选项改变了头文件契约”的一类
问题，任何 TUI 程序都可能踩到。

## 解决方案

### 推荐方案：换用公共 API（语义等价）

| 内部字段 | 公共 API |
|----------|----------|
| `win->_maxx` | `getmaxx(win)` |
| `win->_maxy` | `getmaxy(win)` |
| `win->_clear = TRUE` | `clearok(win, TRUE)` |

```c
-  maxx = stdscr->_maxx;
-  maxy = stdscr->_maxy;
+  maxx = getmaxx(stdscr);
+  maxy = getmaxy(stdscr);
...
-   main_window->_clear = TRUE;
+   clearok(main_window, TRUE);
```

这三个接口自 ncurses 起就存在且稳定，改动极小、行为不变，也不引入平台宏。

### 回退方案

重新构建一份 `--disable-opaque-curses` 的 ncurses 作为依赖（成本高：需重编并重新
发布依赖，可能影响到其它消费者），仅在完全无法修改上游源码时使用。

### 禁止做法

- ❌ `#define NCURSES_OPAQUE 0` 强行打开内部结构：只是骗过头文件，与已编译的库
  在结构布局约定上不一致，属未定义行为。

## 验证

```bash
# 确认依赖头文件是 opaque 的
grep -n "NCURSES_OPAQUE" <ncurses_pkg>/include/curses.h   # → #define NCURSES_OPAQUE 1
# 确认源码里不再出现内部字段访问
grep -rn -- "->_\|->_max\|stdscr->_" src/ ; echo "expect no match outside comments"
```
