# E431 — gmp 包未导出 include 目录，nettle 公开头里的 `<gmp.h>` 找不到

## 错误特征

```
fatal error: 'gmp.h' file not found
#include <gmp.h>
         ^~~~~~~
```

报错位置通常**不是** gmp 自己的源码，而是 `nettle/*.h`（nettle 的公开头会
`#include <gmp.h>`）或任何 include `gnutls/gnutls.h` 的编译单元。同一工程里
`libnettle.a` 已存在、`find_package` 也没报错——只有编译命令缺了 `-I<gmp 包>/include`。

## 触发条件

- 构建系统: CMake + Conan（CMakeDeps）、或任何用 `cpp_info` 注入 include 的流程
- 阶段: compilation
- 前提: 依赖图里出现 `gmp`（经 `gnutls`/`nettle` 传递或显式 requires）
- 关键证据: 生成的 `generators/gmp-release-<arch>-data.cmake` 中 `set(gmp_INCLUDE_DIRS_RELEASE )` 为空
- 实测版本: `gmp/6.3.0.1`（已发布制品，含 revision）；同族 `gmp/6.3.0` 有默认 includedirs 生效的二进制

## 根因分析

制品仓中 `gmp/6.3.0.1` 的 Conan 元数据没有声明 include 目录，CMakeDeps 因而生成空的
include 变量，imported target 上也不挂 include 用法要求。而 nettle 的公开头把 `<gmp.h>`
作为**公开 API 的一部分**暴露出来（bignum 类型），所以只要编译任何包含 nettle 头的文件，
就必须让 gmp 的头目录出现在编译命令里。包内其实已经装了 `<pkg_prefix>/include/gmp.h`，
只是没有通过 `cpp_info` 暴露。

## 解决方案

### 推荐方案

在配方里从依赖包的真实 prefix 取 include 目录并注入构建（不硬编码路径）：

```python
def generate(self):
    tc = CMakeToolchain(self)
    gmp_inc = os.path.join(self.dependencies["gmp"].package_folder, "include")
    if os.path.isfile(os.path.join(gmp_inc, "gmp.h")):
        tc.variables["GMP_INCLUDE_DIR"] = gmp_inc   # 补丁把它 append 到 Nettle 目标
    tc.generate()
```

Makefile/autotools 工程等价做法：`CPPFLAGS += -I<dep_package_folder>/include`。

若配方自身在编 gmp，则应直接修 `cpp_info.includedirs`（更彻底），本条目针对
「gmp 已是制品仓里已发布的既有包、本次适配不便回改」的情形。

### 禁止做法

- ❌ 改上游 `nettle/*.h` 删掉 `#include <gmp.h>`（污染公开头、破坏 ABI 语义）
- ❌ 把 gmp.h 拷进系统 `/usr/include`（R49/R26：污染共享环境，CI 干净环境不可复现）
- ❌ 用宿主或系统同名库顶替（R26）

## 验证

```bash
# 1. 确认 gmp 的 include 目录确实没被导出
grep -n 'gmp_INCLUDE_DIRS' <build_folder>/generators/gmp-*-data.cmake

# 2. 确认包头存在，只是没暴露
ls "$(conan cache path gmp/6.3.0.1)/include/gmp.h"

# 3. 注入后重编
python3 scripts/ohc-run.py conan-verify <包> <版本>
```
