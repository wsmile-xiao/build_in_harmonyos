# rule12「鸿蒙特有测试」必须是完整端到端消费者用例

**条目**: `DRAFT-genht-1.1.3-rule12-needs-e2e-consumer-case`
**来源**: genht 1.1.3 · PR #12248 首轮审查被 REQUEST_CHANGES
**状态**: DRAFT

## 现象

PR 已 CI PASSED、P0/P1=0、其余 12 条规则全 PASS，但 pc-pr-review 仍判 **FAIL**：

```
| rule12 | 鸿蒙特有测试 | ❌ FAIL | 规则 12: 鸿蒙特有测试行只有断言（N=1），
  不算完整消费者用例——至少要有一个完整消费者用例（真正跑通功能/流程的端到端用例），纯断言不行 |
```

即：test_package 里 43 项 API 断言全过，仍不满足 rule12。

## 口径

- 「鸿蒙特有测试」行**不能为 0**；
- 且**不能只有断言**：至少 1 个**完整消费者用例** —— 端到端跑通功能/流程；
- 申报按**用例数**，说明按四段式写：**构造输入 → 真实执行 → 产出结果 → 校验内容**。

## 落地做法（可直接复用）

1. **新增独立可执行**（如 `test_consumer.c`），不要往断言文件里继续堆断言：

| 阶段 | 要求 |
|------|------|
| 构造输入 | 内嵌固定真实语料/数据，禁止随机，保证可复现 |
| 真实执行 | 把被测库当引擎跑完整条流程：多张表/多类型实例、真实增删改、放大负载触发扩容/退化路径、幂等与边界动作 |
| 产出结果 | 确定性输出；**显式排序**，不要依赖哈希/容器迭代序 |
| 校验内容 | 与**参考输出**逐字节比对 + 语义不变量复核 |

2. **参考输出必须独立来源**：由另一套实现按同一输入预算得出（如用 python 按同一语料算一遍）。
   用程序自输出回填 golden = 自证，等于没有校验，属欺骗类风险。
3. CMakeLists 增加该可执行；`test()` 里依次 `self.run(<bin>, env="conanrun")`，确保 CI 真跑到。
4. 文档同步：pr-body 统计表 + 补全说明 + 验证结果通过率、`MANIFEST.yml` 的
   `test_package_tests`/`assertion_count`、`test-report.md` 详情节，五处口径一致。
5. 自检：`conan create` 日志里两个可执行都被 `RUN:`；确定性用连跑 3 次比对末行验证。

## genht 实证

- `test_consumer.c`：13 行访问日志语料 → htsi×2（累计字节/命中）+ htss（最新状态）
  + htsi/htpp 两级 user 索引 + htip 注册表 + siphash24 指纹 → 下线资源（含幂等二次删除）
  + 2000 条负载扩容后按下标删一半 → 确定性报告 → 与独立预算的参考输出逐字节比对。
- 结果：**47 项检查 0 失败**，连跑 3 次输出一致；申报「鸿蒙特有测试 2 个用例」，rule12 通过。
- 附带教训：指针键（`htpp` + `ptrhash/ptrkeyeq`）**不能按内容匹配**，同一名字的不同 token
  指针会被当成不同键 → 需「内容键驻留表 + 指针键对象索引」两级结构，这也是真实工程写法。
