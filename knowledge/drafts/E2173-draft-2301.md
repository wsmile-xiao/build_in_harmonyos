# E2173: Rebind identity consumers created after the main freeze pass

## Symptom

A generated device bundle passes its outer manifest and controller checks, but
the target receiver exits during extraction or launch. The final helper has the
current byte count, SHA-256, and protocol schema while a receiver or validator
still requires predecessor values. The receiver can fail with an empty RC1,
making the mismatch look like a transport or extraction error.

## Root cause

The freeze pipeline rebound the helper and consumers that existed at that
point, then copied another consumer from a predecessor template. That late copy
reintroduced old identity constants after the apparent main rebind completed.
The executable closure is a generation-order graph, not just the root helper
and controller.

## Fix

1. Enumerate every helper identity consumer, including receiver, launcher,
   validator, fixtures, and files copied late in generation.
2. Bind the current helper byte count, SHA-256, and schema in each consumer's
   owning render block.
3. Require the current tuple exactly once and explicitly reject the predecessor
   tuple in production-path validation.
4. Generate a new input and freeze, then verify it from an independent
   extraction. Never patch the completed predecessor archive.
5. Use a new run ID and remote root for target validation; do not replay a
   transfer or prepare phase from a failed transaction.

## Validation

GLib r870 showed the first form: the payload helper emitted the current receipt
schema while a root helper still emitted the predecessor schema. r872 corrected
that boundary but its receiver still required the predecessor 4770-byte helper
and old SHA-256. The bundle actually contained the current 4769-byte helper,
SHA-256
`0b7fe1b8da48c20ed7dd4e0e5b188a2a07990ba19713b4b8048e05c27bb13d9b`.

The create-new r873 generator moved receiver helper binding into the owning
render tuple. Its direct positive and predecessor negative passed, the freeze
and controller closure validated, and one exact OpenHarmony/AArch64 transaction
completed with 363/363 upstream tests, 1/1 state test, 1/1 consumer program,
12 receipts, two clean scans, and POSTRELEASE_PASS. The host result SHA-256 is
`3191f78de05253a334137b641f922cba9de66ca1fec3eefc1bfdc5c8290aa37b`.

## Applicability and safety boundaries

Use this for any multi-stage generator where helper producers and consumers are
created at different times. It does not permit accepting multiple schemas,
hashes, or byte counts; editing consumed evidence; replaying committed phases;
or claiming target success from local generation tests. The final target run
must execute the exact regenerated closure.
