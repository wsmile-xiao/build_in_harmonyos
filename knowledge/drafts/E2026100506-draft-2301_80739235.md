# 补充 PR #7775：串行参数不能替代调度器临时路径与构建环境恢复

## 现象与根因

正常上游编译及 `--version` 通过，但安装版执行真实项目时先 ENOENT、再在恢复环境后 EPERM。这不是一个统一的“鸿蒙不支持 FIFO”结论。第一层是 build() 直接修改 Python 进程的 HOME/TMPDIR/PATH 等键，finally 删除工作根后未还原；第二层是调度驱动即使 `-j1` 仍初始化默认 FIFO jobserver，TMPDIR 在 HMDFS 不支持的命名管道区域。帮助入口没有执行这条初始化链。

## 通用修复步骤

1. 保存构建方法实际修改的精确环境键及原始缺失状态；正常、异常出口均在 finally 恢复。不要删改不属于本配方的键，也不保留已删路径。
2. 用官方源码确认真实驱动的 jobserver 默认策略和 tmp-dir 查找顺序；GNU make 的 `-j1` 结论不能移植成所有调度器的行为。
3. 保持真实输入/输出在 HMDFS，驱动 cwd 与 FIFO 临时目录放在本次独占的应用私有 cache；保留原始默认 FIFO，而不是用关闭调度器或测试侧复制代替产品功能。
4. 旧失败事务真实归档、清理后创建全新 run，完整执行上游入口和真实安装消费者，验证原始文件/复制结果的全字节 SHA-256、平台投影属主及双目录清理。

## 真实证据与反例

build2 r007 的官方上游85/85与版本消费者通过，但独立 HMDFS 项目 ENOENT；恢复九个环境键的实际方法检查正常/异常2/2后，r008仍在真实项目报 `ios_base::failure`/Operation not permitted，整体真实 FAIL。这证明只修环境恢复不足以证明完整消费者功能。

r009 candidate tree `2382a2fc782542629d2d7049e89f25f95386c9c3` 保持相同已安装二进制和默认 jobserver，仅给真实项目明确的同运行 app-private cache TMPDIR/TMP/TEMP/TEMPDIR。单次真实 Conan create RC0，官方85/85、安装消费者1/1、独立鸿蒙1/1；完整 WAL/receipt、release/postrelease和自有进程0通过。同软件 reports/r009-* 保留原始日志、配置和结果。旧 FAIL 未改写、未拼接。尚不声称平台 CI 或提审通过。

## 查重增量、适用与不适用边界

本条补充 PR #7775；E074/E525 讲 GNU make 的串行规避，本轮给出其在不同调度器上的明确反例，且不关闭 FIFO；megahit 条目改为普通文件等价流，本条不修改产品 IPC 策略，分离的是数据与临时 IPC 所在文件系统。环境恢复与调度器路径是两个独立原因，不能靠单个 help 或单个成功阶段合并推断。适用于允许使用任务独占 app-private cache 的原生任务；不能替代设备权限、未知文件系统支持性或必须在 HMDFS 建 FIFO 的产品需求验证。
