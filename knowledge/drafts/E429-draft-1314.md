# E429 — OHOS musl libc 无 shadow 口令 API（`shadow.h` 无 `getspnam`）

> 草稿（draft: true），来源：`polkit/124.1` 适配（PR 待建）。请主编审核后提升为正式条目。

## 错误特征

编译期（clang 15 / aarch64-linux-ohos，隐式声明被当作错误）：

```
src/polkitagent/polkitagenthelper-shadow.c:123:19: error: incompatible integer to
  pointer conversion initializing 'struct spwd *' with an expression of type 'int'
      [-Werror,-Wint-conversion]
        struct spwd *spwd = getspnam (user);
                            ^~~~~~~~
1 error generated.
```

或链接期（未开 `-Werror` 时）：

```
ld.lld: error: undefined symbol: getspnam
>>> referenced by polkitagenthelper-shadow.o:(...)
>>> did you mean: getpwnam
```

对照事实（同一 OHOS sysroot，可自行复核）：`getpwnam` / `getpwuid` / `getpwent` 在 `libc.so`
中**存在**，`getspnam` / `getspent` / `sgetspent` / `getspnam_r` **均不存在**；`shadow.h`
不声明这些函数。因此报错不是"链接参数问题"，是**能力缺失**。

## 触发条件

- 构建系统：任意（autotools / meson / cmake 均会命中，因为卡点在编译/链接而非构建系统）
- 阶段：compilation（隐式声明 → 类型转换错）/ linking（undefined symbol）
- 触发代码形态：源码直接调用 `getspnam()` 等 shadow 数据库 API，且**未做能力探测**；
  常见于需要"二次认证 / 提权校验"的组件（polkit agent helper、sudo 系、账户管理、cups 认证后端）

## 根因分析

shadow 口令数据库 API（`getspnam`/`getspent`/`sgetspent`）是 **glibc 扩展**，不属于
POSIX。OHOS 的 libc 基于 **musl**，musl 不实现 /etc/shadow 读取接口（musl 只提供
passwd/group 的 `getpwnam`/`getpwent`/`getgrnam` 等），因此：

1. 头文件无声明 → C 代码隐式声明 → clang 15 默认按错误处理（`-Wint-conversion`）；
2. 无实现 → 即便强转也会在链接期 `undefined symbol: getspnam`；
3. 该缺口**无法用依赖包补齐**：musl 的 `shadow.h` 与符号属于 libc 本体，OHOS 侧没有
   可 `requires` 的 shadow 库；GLIBC 私有的 `/etc/shadow` 语义在 OHOS 上也不存在。

同族现象（本次一并遇到）：musl 同样缺 `fgetgrent()` / `fgetpwent()`，上游测试用的
`subprojects/mocklibc` 需在本地补实现（见 `polkit/124.1/patches/mocklibc-ohos-fgetgrent-fgetpwent.patch`）。

## 影响范围

**判定口径**：源码含 `getspnam`/`getspent`/`sgetspent`/`shadow.h`（或对应符号探测为必需）的
组件，在 OHOS 上**不可能**获得完整功能，只能裁剪或桩化。

- 已实证：`polkit`（agent helper `polkitagenthelper-shadow.c`，musl 路线下必须排除该 helper）
- 预期同类：提权/认证代理（sudo 系、polkit agent 消费方）、账户与影子口令管理工具、
  打印/域认证后端（cups 的 PAM/shadow 后端）、任何硬依赖 `/etc/shadow` 的后端服务

**不适用**：只需要 passwd/group（`getpwnam`/`getpwuid`/`getgrouplist`）的库——这些 musl 有。

## 解决方案

### 推荐方案（优先）：用上游自带的"可选组件"开关裁剪，而不是加平台宏

先做能力探测，确认缺失后**关掉依赖该 API 的可选组件**，让包交付"能用的那部分"，
并把缺口写进 notes/README 与包元数据（下游据此决定运行期行为）：

```bash
# 1) 能力探测（CMake 例：探测成功才启用 shadow 路线）
#    check_symbol_exists(getspnam  shadow.h  HAVE_GETSPNAM)
# 2) meson 例：project 里用 cc.has_function('getspnam', prefix: '#include <shadow.h>')
#    → 缺失时不上 subdir('privhelper')（或把该 executable 包进 if not libs-only）
# 3) 配方侧：不引入任何平台宏，只使用上游已存在的开关（本例即 polkit 的 -Dlibs-only=true）
conan create archives/p/polkit/124.1 -pr:h=ci/conan/profiles/ohos-aarch64 \
    -pr:b=ci/conan/profiles/ohos-aarch64
```

参考实现：`archives/p/polkit/124.1/patches/polkitagent-libs-only.patch`（只用上游
`libs-only` 选项把特权 helper 排除，补丁内**不含** `__OHOS__` 之类平台宏，符合 R8/PF5）。

### 回退方案：显式桩（stub）实现，且行为必须"明确失败"而非静默成功

当组件**不可裁剪**（必须存在该符号才能构建/被 dlopen）时，提供一个只让编译链接通过、
运行期显式失败的桩，并保持日志可见：

```c
/* 能力缺失桩：不要假装成功——返回 NULL 并置 ENOSYS */
#if !defined(HAVE_GETSPNAM)
struct spwd *getspnam(const char *name) { (void)name; errno = ENOSYS; return NULL; }
#endif
```

配 `#error`/运行期告警，确保下游能观测到"该功能在 OHOS 上不可用"。

### 禁止做法

- ❌ 用 `#ifdef __OHOS__` 包一层**空壳 stub** 只为消除编译错误（R6/R8：守卫里必须有
  实质逻辑；空壳 stub 属本文明确禁止项，且 PF5 会在提交前拦截补丁中的平台宏）
- ❌ 把桩写成"返回成功"，让鉴权路径静默通过（安全语义错，比编译失败更危险）
- ❌ 谎报能力：README/manifest 声称"支持 shadow 认证"却只交付桩
- ❌ 为绕过而 `-Wno-int-conversion` / `-Wno-implicit-function-declaration` 把错误压掉——
  链接期仍会 `undefined symbol`，只是把失败推迟

## 验证

```bash
# A. 确认能力缺失（探测应与结论一致）
echo '#include <shadow.h>
int main(void){ return getspnam("root") != 0; }' > /tmp/probe.c   # 本机 /tmp 只读时用 $HOME/tmp
$OHOS_CC --sysroot=$SYSROOT -c $HOME/tmp/probe.c -o $HOME/tmp/probe.o   # 期望：隐式声明/未知类型报错
$OHOS_NM -D $SYSROOT/usr/lib/libc.so | grep -c '^.*getspnam'            # 期望：0（对照 getpwnam 非 0）

# B. 确认裁剪后包可用（polkit/124.1 实例）
conan create archives/p/polkit/124.1 -pr:h=ci/conan/profiles/ohos-aarch64 \
    -pr:b=ci/conan/profiles/ohos-aarch64
nm -D <pkg>/lib/libpolkit-agent-1.so | grep getspnam   # 期望：无输出（helper 未打包）
ls <pkg>/bin/polkit-agent-helper-1 2>/dev/null          # 期望：不存在（明确不交付）
```
