# E6402 - OHOS toybox mktemp templates must end with XXXXXX

## Symptom

An installed-package consumer creates a unique configuration with
`mktemp "$TMPDIR/name.XXXXXX.conf"`. Desktop GNU implementations accept the
literal suffix, but OpenHarmony toybox returns `mktemp: need XXXXXX: Not
supported` before the application is invoked. Build, packaging, and preceding
consumer checks may therefore pass while the target flow fails.

## Root Cause

The target toybox parser requires the six `X` placeholders to be the final
characters of the template. A host shell test exercises different utility
semantics and cannot establish target compatibility. The failure is a target
tool-capability mismatch, not evidence that the packaged application or its
temporary directory is intrinsically broken.

## Fix

Use a template ending exactly in `XXXXXX`, for example
`mktemp "$TMPDIR/name.XXXXXX"`; treat the returned path as opaque and do not
append an extension or derive a name from `$$`. Keep the directory task-owned,
install an EXIT trap that removes the returned file, and include a target
positive check for uniqueness and zero residual files. A negative fixture for
the suffix form prevents regression of the target-specific contract.

## Validation

DOSBox Staging `0.82.2-r1` r174 completed source, build, upstream `24/24`, and
export-pkg, then failed at the dynamic-core consumer with the exact toybox
message. The consumed r174 transaction was released without retry. The local
production wrapper was changed to suffix-free templates; two generated paths
were unique, the complete consumer flow returned `4/4 PASS`, omission of the
dynrec guest sentinel still failed closed, and two post-release scans found no
temporary files. Because the packaged script changes, a fresh target successor
is required.

## Applicability and Safety Boundary

This rule applies to shell consumers and task-owned wrappers on OpenHarmony
toybox images. It does not establish identical behavior on another image, nor
does it prove audio/video delivery, application functionality, or W3 success.
Do not copy a host mktemp binary, write outside the task root, use predictable
names, or treat a host-only shell test as target evidence.
