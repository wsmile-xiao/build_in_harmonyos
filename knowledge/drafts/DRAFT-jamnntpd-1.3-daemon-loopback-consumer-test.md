# DRAFT：无 root/无 GUI 环境下 TCP 守护进程应用的 loopback 消费者测试设计

> Contributor: hw-6（jamnntpd 1.3 适配） | Status: Draft | Updated: 2026-09-24
> Source: 平台任务 7572（分支 feat/jamnntpd-1.3，PR 编号创建后回填）
> 对应图谱草稿: knowledge/drafts/DRAFT-jamnntpd-1.3-daemon-loopback-consumer-test.kv

## 背景

jamnntpd 1.3 是 FidoNet JAM 消息库的 NNTP 服务器（守护进程 + 伴生 CLI
makechs）。CI 门禁要求 test_package 真实执行被测二进制并断言行为（R34），
而 L0d 会把"test() 无 self.run()"直接判为 stub。在 OHOS 设备/CI worker 上，
**无 root、无 GUI、默认端口不可用、默认配置路径（/etc/）不存在** 是守护进程
类应用消费者测试的四个结构性障碍——本条目给出一套与具体协议无关、可跨包
复用的破解模式。

## 症状（可复现）

按直觉写消费者测试会依次撞上：

```
[fail] L0d: test() method has no self.run() call — likely a stub
bind: Permission denied            # 119 是特权端口
jamnntpd exited early              # 缺 groups/xlat 配置项时服务启动即退出
```

第三条最阴险：守护进程静默退出后客户端只看到连接被拒，若无日志兜底，
排错方向会被带向"网络/防火墙"而不是"配置前置条件"。

## 根因

1. 特权端口（NNTP 119 / HTTP 80）无 root 不能绑；
2. jamnntpd 每条连接前有三级前置检查（allow → groups ≥1 条 → xlat 含 ≥1 条
   post 映射），任一不满足直接 503 断开——但**配置里声明的消息库路径
   （jampath）不需要真实存在**，可以造假；
3. 门禁不接受"只 --version"式冒烟（对守护进程也确实不算行为测试）。

## 方案（五步骨架，可跨库复用）

1. **端口**：`socket.bind(("127.0.0.1", 0))` 向内核要一个临时空闲端口，
   记下后立即 close，把该端口传给被测进程（`-port <P>`）。绝不假设默认端口可绑。
2. **配置注入**：在临时目录生成最小可用配置——允许列表一行 `*`；组文件一条
   合法记录但指向不存在的消息库；字符集表文件 `chsdir` 指向包内资源
   （`<package>/res/xlat`）+ 一条 read + 一条 post 映射。利用"声明的路径
   不必存在、但条目必须存在"这类协议语义差异，绕开真实数据依赖。
3. **启动 + 可诊断等待**：`Popen` 守护进程（stdout/stderr 归拢到日志文件），
   15s 死线轮询问候横幅；**每轮先 `poll()`，发现提前退出就把服务日志尾部
   400 字塞进断言消息**——失败时第一眼看到真因。
4. **应答码断言**：自写 20 行级协议客户端（`socket` + `makefile("rb")`
   逐行读），断言：欢迎横幅（200）+ 未知命令（500）+ 不存在的组（411）+
   POST 就绪（340）+ QUIT（205）。**每条命令独立建连**，避免会话状态耦合导致
   一条失败连环失败。断言用应答码前缀而非全文，容忍版本横幅差异。
5. **清理**：`finally` 中 terminate → `wait(timeout)` → kill 三段式，
   不留孤儿进程（守护进程类测试最容易污染后续用例）。

伴生 CLI（makechs）另做生成物断言：真实运行生成 .chs，断言退出码、
"; Generated by makechs" 签名、两侧字符集名、以及映射行内容
（`0x41 0x62` → 行尾 `\tb`），四者齐全才算消费了生成物语义。

conanfile 侧用 `self.run(f'"{python3}" "{script}" "{pkg}"', env="conanrun")`
满足 L0d；脚本放 test_package/test_script.py 随 recipe 一起 export。

## 真实验证

- jamnntpd 1.3@ohpcd/stable 设备 `conan create` 全绿（CREATE_RC=0）：
  `jamnntpd loopback NNTP consumer tests passed: greeting 200 + 500 + 411 + 340 + 205`
  `makechs generated-table consumer test passed`
- conan-verify G0–G4/L2/L4/L5 全 PASS；本地 CI 模拟 L0d 转绿。
- 内存实测（memcap-run --probe + 有界轮询）：守护进程峰值 RSS ≈4MB，
  makechs ≈4MB → 消费者测试预算 64MB，无整机风险。

## 适用范围与反例

- **适用**：一切"本机可非特权启动、监听 TCP、讲应答码协议"的应用包
  （NNTP/IRC/HTTP/SMTP/Memcached 系）。前提：进程支持端口与配置路径的
  命令行注入（jamnntpd 的 -port/-allow/-groups/-xlat 即典型）。
- **不适用/反例**：①必须 systemd/launchd 托管或依赖 GUI 会话的服务——
  改用其离线 CLI 面做生成物断言并如实标注；②需要真实后端数据才能过前置
  检查的协议栈——若造不出合法最小配置，按 fallback 只测伴生 CLI，
  不得虚构端到端测试；③多线程每连接模型下并发压测不在本模式范围内
  （本模式每条命令独立短连接，刻意串行）。
- 与 E230（库传输层编译矩阵+loopback）不同签名：那是**库**的编译期探测，
  本条是**守护进程应用**的运行时行为断言；与 E357（探测性 allowlist）无关。
