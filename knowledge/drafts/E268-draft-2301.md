# E268 - Offline ExternalProject Source without Test Reduction

## Symptom

The main source is checksum-frozen and CMake configuration succeeds, but the
build stops at a test-tool `ExternalProject` Git clone. Disabling the tool
would remove existing upstream tests and invalidate the complete test count.

## Root Cause

`BUILD_TESTING` activates an auxiliary tool whose source is fetched during the
build rather than recipe source acquisition. A target with no GitHub access
therefore fails before compiling the main project.

## Recommended Fix

Fetch the auxiliary tool's fixed revision in the recipe `source()` phase with
the same local-archive override and SHA-256 policy as the main source. Patch
the upstream ExternalProject narrowly so a supplied source directory uses
`DOWNLOAD_COMMAND ""`; enable the project's no-download gate and reject a
missing directory.

## Validation

ITK 5.4.6 bound KWStyle commit
`6971e89ec4c763601edf1d0ea0d6f71d42fbca5d` and rejected missing and
hash-mismatched archives. CMake generated `method=source_dir`, an empty
download command, and rejected a missing local directory. The complete
618-test inventory remains enabled.

## Safety Boundary

Do not disable `BUILD_TESTING` or the upstream test tool to avoid a download.
Do not accept an unfrozen directory, fallback network clone, or auxiliary
revision different from the upstream pinned revision.
