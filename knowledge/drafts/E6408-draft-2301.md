# E6408 - Validate OHOS target tool paths with POSIX semantics

## Symptom

A fresh Windows-hosted OHOS Conan graph resolves all published dependencies,
but `conan install --build=never` fails after downloading them:

```text
Invalid configuration: OHOS Meson builds require an absolute C compiler path
```

The profile already contains `/data/service/hnp/bin/clang`. A second failure
can report that the derived `llvm-ar` is absent even though that file is meant
to exist only on the target device.

## Root Cause

`os.path` uses the Python host's path implementation. On Windows,
`os.path.isabs('/data/...')` does not prove a fully qualified Windows path,
although `/data/...` is a valid absolute OHOS path. Host-side
`os.path.isfile()` and `os.access()` also cannot establish the state of the
target filesystem.

Conan `generate()` only needs to serialize the target tool path into Meson's
cross file. The tool must exist and be executable when `build()` runs on the
target, not when a Windows W0 materializes dependencies.

## Fix

Use a single resolver for the target compiler and archiver:

1. Read `tools.build:compiler_executables` as a dictionary.
2. Validate compiler and optional archiver with `posixpath.isabs`.
3. Derive the default archiver with `posixpath.dirname` and
   `posixpath.join`.
4. During `generate()`, emit that exact target path into the Meson toolchain.
5. At the beginning of `build()`, call the same resolver, then require
   `os.path.isfile()` and executable access before invoking Meson.

This preserves fail-closed target execution while allowing dependency-only
resolution on a different host OS.

## Validation

For DOSBox Staging 0.82.2-r1 with libpng 1.6.58.2:

- fresh `graph info --build=never`: 17/17 nodes, zero invalid and missing;
- fresh `install --build=never`: RC0, 14 packages downloaded and materialized;
- relative compiler production profile: RC6 with the compiler-path error;
- relative explicit archiver production profile: RC6 with the archiver-path
  error;
- graph/install RREV, package ID, PREV, and remote identities: zero drift.

## Safety Boundaries

- Generation success does not prove the compiler or archiver exists on OHOS.
- Do not remove the build-time target file and executable checks.
- Do not rewrite target paths to Windows syntax or accept relative paths.
- This pattern closes W0 and generator semantics only; r67 separately proved
  target compilation, upstream 24/24 and the installed-package flow 1/1. It
  does not substitute for platform Review, CI, or submission.
