# E6405 - Conan dependency metadata must bind header and linker contracts together

## Symptom

Meson reports `SDL2_net` as found and all translation units compile after the
header path is made visible, but the final executable link fails with
`undefined symbol: SDLNet_*`. The generated linker command contains SDL2 and
other providers but no `libSDL2_net` or equivalent provider library.

## Root Cause

Dependency discovery, header reachability, and link closure are independent
metadata contracts. A package can expose a version and include directory while
its generated pkg-config module has an empty or incorrectly named `Libs` field.
The consumer then reaches the implementation declarations but cannot resolve
the provider symbols. Correcting only the nested header path therefore moves
the failure from compilation to final linking; changing the feature option
would conceal a broken published dependency.

## Fix

1. Bind the exact dependency package revision and inspect its package-local
   header and library files before changing metadata.
2. Set the pkg-config module name to the spelling expected by the production
   Meson dependency (`SDL2_net` here).
3. When the package folder proves both `SDL_net.h` and `libSDL2_net.so` or
   `libSDL2_net.a`, normalize the generated module to expose exactly one
   `-lSDL2_net` flag and the verified include directory.
4. Reject missing files, duplicate library flags, malformed metadata, or
   arbitrary system fallbacks; keep the feature enabled.

## Validation

Buildbot `49504` completed source acquisition, all seven portability patches,
Meson configuration, and compilation. The linker then reported every
`SDLNet_*` symbol undefined, while the command line contained no SDL2_net
library. The successor keeps the header-layout fallback and adds a
task-scoped `generate()` repair for the `SDL2_net.pc` module. A complete CI
build must confirm that the provider library appears in the final link and
that the 24-entry upstream suite completes.

## Applicability and Safety Boundary

This pattern applies to Conan packages whose metadata exposes headers or
versions but omits the provider library from generated pkg-config/CMake link
properties. It does not authorize arbitrary `-l` injection, copying foreign
libraries, changing dependency versions, or disabling a required backend.
Every repaired flag must resolve to a verified file in the exact package
folder, and source acquisition, compilation, tests, target validation, Review,
and CI remain separate gates.
