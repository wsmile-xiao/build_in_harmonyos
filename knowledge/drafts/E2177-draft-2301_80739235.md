# E2177: OHOS CI workers need a source-bound fallback for host-only generators

## Context

Cross-compiled Conan recipes often build a small host executable to generate
documentation, schemas, tables, or other files consumed by the target package.
An OHOS worker can have the target clang and sysroot without having a native
build-machine compiler.

## Symptom

The target objects and ELF link succeed, but Conan fails before packaging with
`a build-machine C compiler is required for man generation` or a similar host
compiler error.

## Root cause

The target compiler and the build-machine compiler are different toolchains.
Using the target compiler for a host helper creates an OHOS executable that the
worker cannot run. Treating gcc/cc as unconditionally available therefore makes
the recipe fail on workers that intentionally provide only target tools.

## Fix

1. Probe for a real build-machine compiler independently of the target compiler
   settings.
2. Keep host generation when that compiler exists.
3. When it does not, consume checked-in outputs generated from the matching
   upstream inputs, and fail closed if any required output is absent.
4. Export and copy those outputs into the source/build boundary so Conan
   remains self-contained; never use the target compiler as a host fallback.

## Validation

CI #39446 for scdoc 1.11.3 compiled all target objects with the OHOS clang but
failed at `_build_host_generator()` because no `gcc` or `cc` was present. The
successor change adds source-bound `man/scdoc.1` and `man/scdoc.5` outputs,
selects them only when the host compiler is unavailable, and retains dynamic
generation on hosts that have a native compiler. The local Conan create and a
subsequent platform CI run must verify both target compilation and packaged man
page presence.

## Reusable decision rule

For every cross-build host-only generator, classify the compiler by execution
architecture, not by its name. If the host toolchain is absent, use a verified
source-bound output or a truly host-runnable generator; do not substitute target
tools and do not silently omit required generated files.

## Safety boundary

This fallback is limited to deterministic generated data whose upstream inputs
and output hashes are reviewed with the recipe. It does not permit copying a
target executable into a host step, modifying the upstream test suite, or
skipping target validation and package-content checks.
