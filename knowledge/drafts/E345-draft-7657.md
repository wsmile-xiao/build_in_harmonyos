# E345 — 上游无条件 FetchContent 在离线 header-only 打包中的门控修复

> 草稿状态：DRAFT（E345-draft-7657，作者 junshi_liu，来源 earcut 3.2.3 R01）

## 错误特征

```
CMake Error at .../FetchContent.cmake:1906 (message):
  CMake step for earcut_js failed: 1
CMake Error at .../ExternalProject/shared_internal_commands.cmake:744 (message):
  git version 1.6.5 or later required for --recursive flag with 'git submodule ...': GIT_VERSION_STRING=''
```

或更一般的：

```
Performing download step ... failed | FetchContent_MakeAvailable ... GIT_VERSION_STRING='' |
configure-time download blocks an offline package build
```

## 触发条件

- 构建系统: CMake（上游 CMakeLists.txt **顶层无条件** `FetchContent_Declare` + `FetchContent_MakeAvailable`，
  拉取测试 fixtures/依赖如 earcut.js、picojson、googletest，未挂在 `EARCUT_BUILD_TESTS` 等选项 if 块内）
- 阶段: configure（conan create / conan-verify G2 / finish W3 的 cmake configure）
- 环境: GitHub 直连不可达 / 离线 / 限速 CI worker；或 OHOS aarch64 交叉/原生受限网络

## 根因分析

上游把测试 fixtures 的拉取写在 CMakeLists.txt 顶层，不挂在任何构建选项下。配方
`generate()` 即使显式 `EARCUT_BUILD_TESTS=OFF / BENCH=OFF / VIZ=OFF`，configure 阶段
依然执行 FetchContent 的 Git 克隆 → 无网络时 ExternalProject 下载步骤失败，整个
configure 终止。对 header-only（INTERFACE target）库，库本身无需编译，但 fixtures
拉取是**无条件**的，所以纯 header 打包也被网络阻塞。这与 E342（BUILD_TESTING=ON 才
触发 googletest 下载）不同：本模式即使所有选项 OFF 仍触发，仅设选项无法解决。

## 解决方案

### 推荐方案（guard-unconditional-fetchcontent-then-bind-locally）

1. 对上游 `CMakeLists.txt` 打补丁（如 `patches/0001-guard-fixtures-fetchcontent.patch`）：
   把 fixtures 相关的 `FetchContent_Declare/MakeAvailable` 和 `add_library(fixtures ...)`
   整体包进
   ```cmake
   if (EARCUT_BUILD_TESTS OR EARCUT_BUILD_BENCH OR EARCUT_BUILD_VIZ)
       ... FetchContent_Declare(earcut_js ...) / FetchContent_MakeAvailable(earcut_js)
       ... FetchContent_Declare(picojson ...)  / FetchContent_MakeAvailable(picojson)
       ... add_library(fixtures OBJECT ...)
   endif()
   ```
2. 配方 `generate()` 保持 `EARCUT_BUILD_TESTS/BENCH/VIZ = OFF`（header-only 打包离线可过），
   并遵守 R32：`if self.settings.os in ("Linux", "OHOS")` → `CMAKE_SYSTEM_NAME=Linux` /
   `CMAKE_SYSTEM_PROCESSOR=aarch64`。
3. 需要跑上游全量测试时，用 `-DFETCHCONTENT_SOURCE_DIR_*` 把各依赖源指向本地已校验副本
   （官方 tag 经镜像拉取并核对 SHA-256），离线可复现测试。

### 禁止做法

- ❌ 直接删除 FetchContent 块（连测试 fixtures 一起删掉，破坏上游测试入口与台账可复现性）
- ❌ 仅设 BUILD_TESTS=OFF 就认为解决（本模式是无条件 FetchContent，configure 依旧联网）
- ❌ 把本地/上游 CTest 结果写成目标侧结果（host 与 target 口径必须分开报告）
- ❌ 空壳 test_package（R34：test 必须真实调用被测包 API）

## 验证

```bash
# 1) 无网络打包：补丁后 conan create 不触发任何下载
conan create archives/e/earcut/3.2.3 -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing

# 2) 上游测试离线复现（本地绑定）
cmake -DEARCUT_BUILD_TESTS=ON -DEARCUT_BUILD_BENCH=OFF -DEARCUT_BUILD_VIZ=OFF \
  -DFETCHCONTENT_SOURCE_DIR_EARCUT_JS=<本地 earcut.js v3.2.3> \
  -DFETCHCONTENT_SOURCE_DIR_PICOJSON=<本地 picojson v1.3.0> \
  -DFETCHCONTENT_SOURCE_DIR_GOOGLETEST=<本地 googletest v1.15.2> && ninja tests && ./tests
# earcut 3.2.3 实测：69/69 PASSED（10 TEST + 59 fixture 参数）
```
