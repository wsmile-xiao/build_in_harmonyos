# E550 — Conan 配方经 conandata 子模块 tarball + 镜像回退拉取缺失的 git 子模块

## 错误特征

```
CMake Error at logr/CMakeLists.txt:18 (include):
  include could not find requested file:
    .../cmake-scripts/extract_version.cmake
```

上游项目的 `.gitmodules` 声明了构建期依赖的子模块（如 cmake-scripts），
但 GitHub/Gitee 的 **tag tarball**（`/archive/refs/tags/vX.Y.Z.tar.gz`）
只包含 `.gitmodules` 与空的子模块目录，不含子模块内容。CMake 在
configure 阶段 `include(.../cmake-scripts/*.cmake)` 时直接失败。

## 触发条件

- 构建系统: cmake（同样适用于任何构建期读取子模块脚本/源码的项目）
- 阶段: configure（source() 下载完毕后、build() 前）
- 前置: 上游 tag tarball 不含子模块内容（.gitmodules 存在、子模块目录为空）

## 根因分析

GitHub/Gitee 的自动 tarball 不做 recursive submodule 展开。子模块目录
以空目录形式保留，内容需要从子模块自身的仓库（固定 commit）单独获取。
E150 记录过同类现象（Mbed-TLS framework），但那是一条"手动 git clone"
的通用方案；本条目给出 Conan 配方内的自包含方案（含 sha256 校验与
镜像回退），适合 CI 干净环境。

## 解决方案

### 推荐方案（conandata-submodule-tarball-get）

1. `conandata.yml` 的 sources 之外增加 `submodules.<name>` 条目：
   ```yaml
   submodules:
     cmake-scripts:
       url:
         - "https://github.com/<owner>/<sub>/archive/<commit>.tar.gz"   # 官方优先
         - "https://gh-proxy.com/https://github.com/<owner>/<sub>/archive/<commit>.tar.gz"  # 镜像回退
       sha256: "<submodule tarball sha256>"
   ```
   子模块 commit 从 `.gitmodules` 对应仓库的 tag 树查询（GitHub API：
   `/repos/<owner>/<repo>/git/trees/<tag>` 下 submodule 条目 sha）。
2. `conanfile.py` 的 `source()` 中拉取并展开到子模块目录：
   ```python
   def source(self):
       get(self, **self.conan_data["sources"], strip_root=True)
       sub = self.conan_data["submodules"]["cmake-scripts"]
       get(self, url=sub["url"], sha256=sub["sha256"],
           strip_root=True, destination="cmake-scripts")
   ```
3. 跑 `conan create` 验证 configure 阶段能读到子模块脚本。

### 禁止做法

- ❌ 不拉取子模块就直接 configure（必然报 include/文件缺失）。
- ❌ 用 `write_file`/叙述性伪命令绕过（CI 需要真实可复现的下载）。
- ❌ 只有构建期确实不使用该子模块时才可保留空目录（参见 E425 的
  空占位方案，仅适用构建期不需要子模块场景）。

## 验证

```bash
conan create . -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 --build=missing
```

logr 0.8.0 实测：configure 阶段 `cmake-scripts/`（extract_version /
lib_install / common_options 等脚本）全部可读，上游 27 个 gtest 用例
27/27 通过。
