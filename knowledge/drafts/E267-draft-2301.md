# E267 - Empty Library Cache after Target Link-Capability Proof

## Symptom

CMake finds `floor`, `pow`, and `sqrt`, but a later
`find_library(... m)` leaves `NIFTI_SYSTEM_MATH_LIB-NOTFOUND`. Generation
then rejects the poisoned link interface of `ITKniftiio`.

## Root Cause

The upstream build assumes every non-Windows target exposes a separately
discoverable `libm`. Some targets provide the required math symbols without
an additional library file, so discovery fails even though the link
capability exists.

## Recommended Fix

Preserve the original failure, then prove the required functions compile and
link on the exact target without an extra library. Bind only the affected
cache variable to the empty string in the recipe or toolchain. Prefer this
narrow configuration binding to a platform-named upstream source patch.

## Validation

ITK 5.4.6 first failed with `NIFTI_SYSTEM_MATH_LIB` set to `NOTFOUND`.
After the target-bound empty cache value, NIFTI configured and linked through
the final package; later complete target builds and the installed-package
consumer returned RC 0.

## Safety Boundary

An empty value is not a portable default. Re-probe each target toolchain, and
do not clear unrelated library variables or hide unresolved math symbols.
