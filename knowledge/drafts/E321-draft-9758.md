# E321 — 旧式 C inline 定义与生成文件依赖导致现代构建失败

## 错误特征
旧版 C 项目在现代 clang 上可能编译成功但在链接阶段报
`undefined symbol: Credit`、`HostIp2CharIp` 或 `FindIp`。同一类快照若使用
`make -j2`，还可能在编译 `conf.l.o` 时报告 `conf.tab.h: No such file`。

## 触发条件
- 构建系统: Autotools / 手写 Makefile.in
- 阶段: linking；并行生成阶段

## 根因分析
2009 年代源码把需要跨编译单元使用的函数定义为 plain `inline`。现代 clang
默认采用 C99/C23 的 inline 规则时，不再自动提供 GNU89 语义下的外部定义，
所以调用方留下未解析符号。与此同时，快照的 `Makefile.in` 只声明
`conf.l.o` 依赖 `conf.l.c`，没有声明它依赖由 `conf.y` 生成的 `conf.tab.h`，
并行构建会暴露生成顺序竞态。

## 解决方案

### 推荐方案
在 Conan 的 `AutotoolsToolchain` 中加入 `-fgnu89-inline`，保持上游源码的
链接契约；对这个未声明生成依赖的快照使用 `make -j1`。若维护上游源码，
长期方案是把 plain inline 改为普通函数或显式 `extern inline`，并补齐
`conf.l.o: conf.tab.h` 依赖。

### 禁止做法
- ❌ 仅通过关闭链接错误、添加未定义符号 stub 或直接启用并行 make 绕过问题。

## 验证
```bash
make -j1
./bandwidthd --help
./bandwidthd -l
```
