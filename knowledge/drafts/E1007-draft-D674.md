# E1007 — autotools install-sh 无条件调用 id：OHOS 无 id/chown 命令 → Error 127

## 错误特征
make install 阶段（OHOS aarch64）：
```
./install-sh[176]: id: inaccessible or not found
./install-sh[198]: test: 0: unexpected operator/operand
./install-sh[391]: chown: inaccessible or not found
make: *** [GNUmakefile:64: install_pcp] Error 127
```
- `id`、`chown` 均 "inaccessible or not found"
- install-sh 退出码 **127**（command not found），传导为 make `Error 127`

## 触发条件
- 平台: HarmonyOS PC（无 `id`、`chown` 命令——/system/bin、/usr/bin、/bin、/data/service/hnp/bin 均无）
- 构建系统: autotools（或其 install-sh）
- 阶段: installation（make install）

## 根因分析
autotools install-sh 的 root 判定链：
```sh
ID=id
OWNER=`$ID -u 2>/dev/null`      # OHOS: id 不存在 → 空
GROUP=`$ID -g 2>/dev/null`      # OHOS: id 不存在 → 空
...
REAL_UID=$OWNER                 # 空！
test $REAL_UID -ne 0 && CHOWN=true   # `test -ne 0` 语法错 exit 2 → CHOWN 仍为 _chown
# 安装时:
$CHOWN $OWNER $GROUP "$file"    # → chown not found (127) → install-sh 退出 127
```
`_chown` 内部虽有 `[ $REAL_UID != '0' ]` 容错，但 REAL_UID 为空时该测试本身语法错，容错失效。

**无害噪声**：同期 `id | sed` 派生 OWNER/GROUP 的报错（`install-sh[176]: id: not found`）可忽略——getopts 解析 `-o/-g` 后会覆盖 OWNER/GROUP。

## 解决方案

### 推荐方案
install-sh 打补丁，REAL_UID=$OWNER 后加一行：
```sh
[ -n "$REAL_UID" ] || REAL_UID=1
```
id 不可用时假定非 root → `test 1 -ne 0` 为真 → `CHOWN=true`（no-op）→ chown 永不被调用 → 文件保持自然所有权。

这正是 OHOS hmdfs 想要的：hmdfs 新文件继承父目录 owner（组 file_manager 需可写），`chown root:root` 既不可行（无 chown）也无必要。

实例：`archives/p/pcp/7.1.5/patches/0002-install-sh.patch`

### 禁止做法
- ❌ 往 PATH 安装 id/chown shim（配方复杂度上升、行为偏离上游）
- ❌ 用 `-j` 并行掩盖 install 失败
- ❌ 直接删 install-sh 的 chown 逻辑（偏离上游，应走最小 fallback）

## 验证
```bash
command -v id || echo "no id"          # 预期: no id
command -v chown || echo "no chown"    # 预期: no chown
# 打补丁后 make install 不再出现 Error 127
```
