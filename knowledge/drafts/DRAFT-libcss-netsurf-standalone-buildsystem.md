# E6403：NetSurf 自有构建系统 standalone 化

## 错误特征

适配 NetSurf 系库时三连堵：

```
make: *** No rule to make target 'build/Makefile.tools'  (include $(NSSHARED)/makefiles/Makefile.tools 失败)
git clone git.netsurf-browser.org/netsurf-buildsystem → 404（官方域名失效）
make test → testrunner.pl: not found / perl 不可用
```

## 根因

NetSurf 组件库（libcss/libwapcaplet/libparserutils/libdom/nsgenbind 等）共享 `netsurf-buildsystem` 仓库的 Makefile.tools——构建规则、clang 分支定义（`-D_ALIGNED=...`）、代码生成入口、测试驱动（perl 的 testrunner.pl）全在里面。该仓库无 conan 包且官方域名 404，**整条 NSSHARED 依赖链在 OHOS 平台不可得**。

## 解法（standalone Makefile 五步，代码级见 .kv）

1. 顶层 Makefile 重写（内联 Makefile.tools 所需逻辑：组件表/对象收集/lib 目标/pkg-config 生成）
2. `Makefile.clang` 注入 `-D_ALIGNED=__attribute__((aligned)) -DSTMTEXPR=1`（musl clang 不带这些宏，Debian/GitHub 镜像确证的分支定义）
3. 依赖解析走 conan PkgConfigDeps（PKG_CONFIG_PATH→generators）
4. 代码生成零步骤：tarball 自带 autogenerated_*.c（119 个）与 select 侧 autogenerated_*.h——**不要试图跑 gen_parser**
5. 测试改造：testrunner.pl 不可用→test/ 的 8 个数据驱动二进制改 conan test_package 直接执行，2759 用例按二进制分解申报

## 降级方案

Makefile.tools 逻辑过深无法内联：Debian 源码包提取 netsurf-buildsystem 子集随 PR 分发，或 GitHub 镜像单独建包。

## 红线

- 不要 git clone 官方域名（404）；用 Debian 源码包/GitHub 镜像核对 Makefile.clang 注入项
- `-D_ALIGNED` 漏注入会在 184 个手写 .c 里随机炸编译（宏缺失错乱）

## 实证

- PR #12105 libcss 0.9.2（第三例，2759 用例分解申报）
- 先例：libwapcaplet 0.4.3 / libparserutils 0.2.5（main 已合入，同款补丁）
