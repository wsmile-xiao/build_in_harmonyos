# E6441 草稿：test_package 切分 `tested_reference_str` 取版本，W3/CI 形态下带 `#revision%timestamp` 而失败

## 错误特征
`conan-verify`（G2）通过，紧接着 `finish` 的 W3 却报：

```
ERROR: shml/1.1.0 (test package): Error in test() method, line 89
	raise ConanException(f"unexpected shml -v output: {reported!r}")
	ConanException: unexpected shml -v output: 'shml version 1.1.0'
[fail] shml/1.1.0 — conan create failed
```

报出的 `reported` 与期望看起来一模一样——因为被比较的期望值是脏的：`shml version 1.1.0#<recipe-revision>%<timestamp>`。

## 触发条件
- 构建系统: 任意 Conan test_package
- 阶段: testing（`test()` / `build()` 里自己解析 `self.tested_reference_str`）
- 前提: 用 `ref.split("/", 1)[1].split("@")[0]` 之类字符串切分取版本

## 根因分析
两道本地门禁的 `conan create` 形态不同，`tested_reference_str` 因而不同：

| 门禁 | 命令形态 | `tested_reference_str` |
|------|----------|------------------------|
| `conan-verify` (G2) | `--user=ohpcd --channel=stable` | `shml/1.1.0@ohpcd/stable` |
| W3 `build_and_test.sh` / CI | 不带 user/channel | `shml/1.1.0#<recipe-revision>%<timestamp>`（例 `shml/1.1.0#c64f229a68c0ef1a356bc467219d1d75%1790670804.0011215`） |

（Conan 2.29.1；W3 日志行：`tested reference: shml/1.1.0#<recipe-revision>%<timestamp> (version 1.1.0)`，revision 与时间戳每次不同。）旧切分在第一种形态得 `1.1.0`，第二种得 `1.1.0#<recipe-revision>%<timestamp>`。conan-verify 先跑且通过，缺陷要到 W3 才暴露。

## 解决方案

### 推荐方案
不要切字符串，从依赖对象取：

```python
dep = self.dependencies[self.tested_reference_str]
version = str(dep.ref.version)      # 名字: dep.ref.name
self.output.info(f"tested reference: {self.tested_reference_str} (version {version})")
```

### 备选
只能处理字符串时，一次性排除三种后缀：`re.match(r"[^/]+/([^@#%]+)", ref).group(1)`。

### 禁止做法
- ❌ 只处理 `@user/channel` 一种后缀（`split("@")`）。
- ❌ 只在带 `--user/--channel` 的 conan-verify 里验证就认为 test_package 没问题；两种形态都要本地各跑一次。

## 验证
```bash
python3 -c 'r="shml/1.1.0#c64f229a68c0ef1a356bc467219d1d75%1790670804.0011215"; print(repr(r.split("/",1)[1].split("@")[0]))'
# → '1.1.0#c64f229a68c0ef1a356bc467219d1d75%1790670804.0011215'（旧写法错误）
conan create <dir> -pr:h=<profile> -pr:b=<profile> --user=ohpcd --channel=stable   # conan-verify 形态
conan create <dir> -pr:h=<profile> -pr:b=<profile>                                  # W3/CI 形态
```

## 关联条目
- 未发现覆盖 `tested_reference_str` 后缀差异的条目；现有 test_package 里只取名字的 `split("/")[0]` 用法不受影响，`archives/y/yt/4.4.2/test_package/conanfile.py` 已用 `.ref.version`。
- 框架侧建议（见 SKILL_FEEDBACK）：让 `conan-verify` 的 G2 与 W3 使用同一种 `conan create` 形态，避免两道门禁对同一配方给出不同结论。
