# E8288 — Qt JSON 日期测试须显式区分本地时区输入与序列化格式

## 错误特征
QtTest 的 JSON 字符串精确比较失败：时间相差一个本地时区偏移，或者相同 UTC 时刻分别表示为 `...00Z` 与 `...00.000Z`。这两种差异必须分开诊断，不能直接归因于平台错误。

## 触发条件
- 构建系统不限；执行包含 QDateTime、QVariant 或 QJsonDocument 的 QtTest。
- 输入 fixture 使用没有时区的日期文本，或者旧测试假定不同 JSON 序列化入口的日期格式相同。

## 根因分析
`QDateTime::fromString` 解析不含时区的格式时产生本地时间。本应代表 UTC 的 fixture 如果没有显式声明 UTC，生产代码调用 `toUTC()` 后得到不同的时间值。这不是更改机器 TZ 可以可靠解决的接口问题。

另外，Qt5 的 QVariant→JSON 日期转换可输出带毫秒的 UTC ISO 字符串；显式 `toString(Qt::ISODate)` 的结果不一定有相同的毫秒表示。即使两者代表相同时刻，也不能互换它们的格式契约。

## 解决方案

### 推荐方案
1. 从失败断言追到真实的输入解析和生产序列化 API，先确认接口需要 UTC 还是本地时间。
2. 对本来就是 UTC 的无时区 fixture，解析后显式 `setTimeSpec(Qt::UTC)`。此处是声明 fixture 语义，不是把任意本地业务时间强制改成 UTC。
3. 按实际序列化入口分别检查带毫秒和不带毫秒的精确输出；保留时间值、时区后缀和 JSON 内容断言。
4. 保留全部测试方法及其注册入口，完整执行，并核对命名结果与退出码。

### 禁止做法
- 不通过修改全机 TZ、跳过失败用例、移除时区后缀或只比较日期前缀来获得 PASS。
- 不为迁就旧 fixture 更改生产日期转换规则。
- 不把 QtTest 的初始化/清理函数计入上游逻辑测试分母；命名空间前缀必须正确解析，不能忽略未识别结果。

## 关联条目
