# E6400 — 内核 crypto API 用户态接口（AF_ALG/NETLINK_CRYPTO）在鸿蒙非特权域被 SELinux 全面封锁

## 错误特征
```
libkcapi - Error: AF_ALG: bind failed (errno: -13)
socket(NETLINK_CRYPTO): Permission denied
/proc/crypto: No such file or directory
```
（errno -13 = EPERM；全部用例失败于同一处，编译链接均正常）

## 触发条件
- 构建系统: 任意（libkcapi 实例为 autotools）
- 阶段: 运行期（make check / 上游测试套件执行）
- 平台: HarmonyOS PC（HongMeng Kernel 1.12.0），非特权 SELinux 域
  （实测 `u:r:hishell_hap:s0`，即 agent/CI shell 所在域）

## 根因分析
内核 crypto API 有两条用户态接口：AF_ALG socket（bind 选择算法后端）与
NETLINK_CRYPTO netlink 家族。实测（2026-09-16，hishell_hap 域）：
1. `socket(AF_ALG, SOCK_SEQPACKET, 0)` **成功**（协议族已注册），
   但 `bind()` 到 hash/skcipher/rng/aead 任意类型均 EPERM；
2. `socket(AF_NETLINK, SOCK_RAW, NETLINK_CRYPTO)` 直接 EPERM；
3. `/proc/crypto` 不存在（/proc/net 其余项可读，属针对性隐藏）；
4. 设备无 su/setenforce，系统分区 policy 只读，环境内无提权通道。

结论：是 SELinux 策略对非特权域的全面封锁，不是内核 crypto 子系统
缺失。环境内无法修复（策略需系统侧放行）。

## 解决方案

### 推荐方案
compile-verify-with-runtime-degradation（E237 同型）：
1. conan create 编译验证 + test_package 纯用户态 API 冒烟测试（不触碰
   AF_ALG 的部分 100% 通过）；
2. 上游测试**实际执行**并如实记录通过率与失败根因（禁止谎报或跳过）；
3. 鉴别试验定性：在更高权限域（如 hishell，需设备侧配合）复跑 bind
   探针，成功则确认为策略单点问题；
4. 走路径 B 申报平台能力缺口；集成方改用 OHOS Crypto Framework 或
   用户态算法库（OpenSSL/BoringSSL）。

### 禁止做法
- ❌ 伪造上游测试通过率或跳过测试谎报"平台限制"（测试必须实跑）；
- ❌ 反复调参重试 bind/提权（R41 外部阻塞，环境内不可解，3 次即止损）;
- ❌ 在配方里塞 dummy 后端假装功能可用。

## 验证
```bash
# 鉴别探针（编译时注意 E091 sockaddr_storage 守卫）
cat /proc/self/attr/current          # 确认 SELinux 域
ls /proc/crypto                      # 不存在
./algtest2                           # AF_ALG bind: EPERM（全类型）
./nlprobe                            # socket(NETLINK_CRYPTO): Permission denied
```
