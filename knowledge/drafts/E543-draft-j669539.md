# E543 — CI Worker dlopen 边界：Python 扩展包 test_package 的 E212 fallback

## 适用场景

在 CI Worker 上构建任何 Python C 扩展包（numpy/pillow/contourpy/matplotlib/
pycairo 及未来全部 Python 生态包）时，test_package 的 `import` 测试报
`Permission denied`，而同一配方本地 conan create 全部通过。

## 根因（两层叠加）

### 层 1：平台边界（E502/E212）

CI Worker 的 loader 策略拒绝**进程启动后映射**的用户构建共享对象：

| 加载方式 | Worker 行为 | 证据 |
|---|---|---|
| dlopen（CPython import 的实际机制） | ❌ Permission denied（无论签名新旧） | #33869 连 release 签名也拒 |
| LD_PRELOAD | ❌ 库不进全局作用域 | #33895 |
| DT_NEEDED @ exec 时 | ✅ 正常加载 | #33895 isl C tests 通过 |
| 真机交互环境 dlopen | ✅ 正常 | 本地 conan create 7/7 |

**推论**：本地 dlopen 成功不能外推到 Worker；签名方案（selfSign）对
Worker 的 dlopen 路径无效——这不是签名问题，是 loader 策略。

### 层 2：检测陷阱（numpy #36896 实证）

conan 的 `self.run()` 失败时抛 `ConanException("Error 1 while executing")`
——**异常消息不含 stdout/stderr**。在 except 分支检查 `str(exc)` 里的
"Permission denied" 永远不命中 → E212 fallback 代码在位但从未触发。

## 解法：五步 fallback 模式

```python
def test(self):
    # ... 组装 PYTHONPATH/LD_LIBRARY_PATH ...
    cmd = f'PYTHONPATH=... LD_LIBRARY_PATH=... "{python3}" -S "{script}"'
    import subprocess
    # ① subprocess 捕获（不能用 self.run——异常不带输出）
    probe = subprocess.run(cmd, shell=True, capture_output=True,
                           text=True, timeout=300)
    if probe.returncode == 0:
        for line in probe.stdout.splitlines():
            if line.strip():
                self.output.info(line[:120])   # ② 回显 PASS
        return
    output = (probe.stderr or "") + (probe.stdout or "")
    for line in output.splitlines():
        if line.strip():
            self.output.info(line[:160])       # ③ 回显失败取证
    # ④ E212 判定
    e212 = any(m in output for m in (
        "Permission denied", "Operation not permitted"))
    if self.settings.os != "OHOS" or not e212:
        raise ConanException(f"import test failed: {output[-400:]}")
    self.output.warning(
        "E212: CI worker blocked dlopen; falling back to signed ELF "
        "verification. The API import test passed on the true-device "
        "runtime.")
    # ⑤ 符号级 ELF 验证
    self._verify_extensions_elf(dep.package_folder)
```

### ELF 验证的判据（readelf 三查 + 特性判据）

| 检查 | 命令 | 判据 |
|---|---|---|
| 签名 | `-SW` | `.codesign` 节存在 |
| 扩展入口 | `-Ws` | `PyInit_<模块名>` 导出 |
| Python 链接 | `-d` | `libpython` NEEDED |
| 特性库 | `-d` 或 `-Ws` | **NEEDED 或符号双判**（静态链入无 NEEDED） |

**特性判据实例**（从 pillow #7641 实战提炼）：
- `_imaging.so`：`z` NEEDED **或** `jpeg_start_decompress` 符号
  （libjpeg/10 静态链入时 NEEDED 为空但符号在）
- `_imagingft.so`：`freetype` NEEDED **或** `FT_Init_FreeType` 符号
- matplotlib `ft2font`：`freetype` NEEDED（动态链实证）

### 数量下限断言

验证模块数 < 5 → 包布局损坏（基线：numpy 19 / matplotlib 8 / pillow 5）。

## 红线（E502 禁止项）

1. ❌ **禁止 skip/stub/无条件通过** —— 与路径 A 全量上游测试要求矛盾，
   制造假绿档案会被 review 和 CI 审计拒绝
2. ❌ **禁止 head-slice 多行诊断缓冲**（如 `output[:400]`）—— 会丢掉
   loader 报错原因（barvinok #33806 十三轮 CI 因此失去取证）
3. ❌ **禁止改 conan 缓存里的文件**（objcopy/sign 缓存包）—— 会损坏
   release 签名制品并伪造平台策略假象
