# E569 — 老 CMakeLists 的 FIND_PATH/FIND_LIBRARY 写死 /usr 路径，交叉编译找不到依赖

## 错误特征
```
CMake Error: Could NOT find XML2 (missing: XML2_INCLUDE_DIR XML2_LIBRARY)
```
上游脚本形如：
```cmake
FIND_PATH(XML2_INCLUDE_DIR libxml/xmlreader.h /usr/local/include/libxml2 /usr/include/libxml2)
FIND_LIBRARY(XML2_LIBRARY NAMES xml2 libxml2 PATHS /usr/local/lib /usr/lib)
```
交叉编译时这些绝对路径下当然没有目标平台的库，于是变量取到 NOTFOUND。

## 触发条件
- 构建系统: cmake（2005~2012 年手写依赖查找的工程）
- 阶段: configure
- 依赖: libxml2 / zlib / curl 等由 conan 提供、且上游未用 find_package(CONFIG) 的库

## 根因分析
`FIND_PATH` / `FIND_LIBRARY` 的查找顺序是「同名 cache 变量 → 显式 PATHS → 系统默认路径」。
关键在于：**只要同名 cache 变量已经有值，命令直接采用、不再查找**。因此不需要改上游脚本，
在配方 `generate()` 阶段把变量预置成 conan 依赖里的真实路径即可（`cpp_info` 的
includedirs / libdirs / libs）。这比重写 CMakeLists 侵入性小、也更容易被 review。

## 解决方案

### 推荐方案
在 conanfile 的 `generate()` 里按依赖注入同名 cache 变量（版本无关的写法）：
```python
def generate(self):
    tc = CMakeToolchain(self)
    deps = self.dependencies
    tc.cache_variables["XML2_INCLUDE_DIR"] = deps["libxml2"].cpp_info.includedirs[0]
    tc.cache_variables["XML2_LIBRARY"]     = deps["libxml2"].cpp_info.libs[0]
    tc.cache_variables["ZLIB_INCLUDE_DIR"] = deps["zlib"].cpp_info.includedirs[0]
    tc.cache_variables["ZLIB_LIBRARY"]     = deps["zlib"].cpp_info.libs[0]
    tc.generate()
```
静态依赖要显式指向 `.a`（R26：系统同名库不得动态链接），例如 zlib 指向 `libz.a`；
共享依赖（本平台 libxml2 只有 shared 制品）则由 conanrun 提供运行时库。

### 禁止做法
- ❌ 把 conan 依赖目录伪装成系统路径（`-DCMAKE_INSTALL_PREFIX=/usr`、软链到 /usr/lib）。
- ❌ 直接大改上游 CMakeLists 的查找逻辑（侵入大、review 成本高；仅在无法用变量短路时才考虑）。

## 验证
```bash
grep -E 'XML2_(INCLUDE_DIR|LIBRARY)' build/CMakeCache.txt   # 应指向 conan 缓存路径，非 NOTFOUND
readelf -d bin/<tool> | grep NEEDED                          # 静态依赖不应出现在 NEEDED 里
```
