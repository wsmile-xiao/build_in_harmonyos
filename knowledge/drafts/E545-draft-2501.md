# E545 草稿：CTest 嵌套 CppUnit 的输出格式和双层分母闭包

## 场景与现象

Conan 配方把 CppUnit 测试程序注册进 CTest。conan create 返回 0、CTest 2/2、消费者全部通过，验证器却报 upstream_not_122_of_122。

1. CMake.test(cli_args=['--verbose']) 实际执行 cmake --build ... --target test --verbose。参数合法，不报错，但只展开构建命令，CTest 成功项的内部输出仍隐藏。
2. 改用 CMake.ctest 后实际输出为 `1: OK (114)` 与 `2: OK (8)`。旧验证器只认 OK (N tests)，造成假失败。

## 根因和可复用方案

CTest 注册项是程序入口，CppUnit 注册项是内部逻辑用例，两层分母不同；摘要取决于输出器。本次保留的 tests/cppunit/test_runner.cc 使用 CompilerOutputter，不能套用其他输出器格式。

通用步骤：

1. 从构建注册和 CPPUNIT_TEST 双向盘点：记录程序数、各程序的 Suite::case 集合及源文件身份。
2. 核对真实命令路由，使用 cmake.ctest(cli_args=['--verbose','--output-on-failure']) 展开成功项输出。
3. 逐组校验唯一 Suite::case : OK 集合等于源注册集合，不仅比较总数。
4. 按真实语法绑定 OK (N)，独立核对 CTest 程序层全通过、退出码及零失败/跳过。
5. 消费者独立统计，不能补进上游分母。

## 查重后的实质增量

E301 已覆盖 CMake.test 参数路由，例子是非法 --output-on-failure 在测试前报错。本条不重复申报该修复，而增加合法 --verbose 被构建层静默消费的假绿边界、CompilerOutputter 实际摘要语法、逐组注册到运行名称的双层分母闭包。既有 CppUnit 草稿处理依赖发现、可选禁用和 TIOCSTI，未覆盖这条证据判定链。

## 适用范围与安全边界

适用于其他由 CTest 封装的 CppUnit 套件；数字必须从各自实际注册表派生，不限于 scrm 或 114/8。

不得修改断言、减少采样、改变种子、删除用例或缩小分母。不得只凭 CTest 2/2 推断内部 122/122，也不得用静态注册代替目标运行。其他输出器、参数化测试或动态注册须重新绑定清单和语法。本次失败事务未改写为 PASS；验证器修复使用新事务。
