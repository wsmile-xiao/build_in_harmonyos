# E544 — setuptools 构建的 Python C 扩展包：CI Worker 四重适配链（pillow 16 轮实证）

## 适用场景

setuptools / setup.py / pyproject 构建的 Python C 扩展包（区别于 meson
构建的 numpy），在 CI Worker 上 test_package 或 build 阶段连环失败。
pillow 10.4.0（PR #7641）16 轮 CI 攻坚全记录。

## 四层故障链（逐层暴露，修复顺序固定）

### 层 1：二进制传输（最隐蔽，极易误诊）

```
症状：CI 报 "diff 无法应用——与 main 分支存在冲突"
真相：GitCode PR diff 无法携带仓库内二进制文件
      （error: missing binary patch data for '...ttf'）
误诊陷阱：rebase 无效！base 没问题，是 diff 里二进制段损坏
对策：仓库零二进制——字体/图片等测试资源改用 /system/fonts/ 等
      系统路径，或运行时生成
```

### 层 2：构建工具（setup.py 第一行即挂）

```
症状：ModuleNotFoundError: No module named 'setuptools'
根因：CI Worker 的裸 HNP python 无 setuptools
对策：build() 探测 import setuptools → 失败则 pip install --no-deps
      --target <build>/_pybootstrap setuptools wheel（清华源）
      + PYTHONPATH 前缀注入
```

### 层 3：链接器（两个坑连锁）

```
坑 A：xmlFree symbol not found（SDK lld 缺 libxml2.so.16）
坑 B：覆盖 LDSHARED 换 bfd 时，丢掉 setup.py 默认的 libpython 链接
      → .so 无 libpython NEEDED 条目 → E212 验证失败
对策（缺一不可）：
  LDSHARED="clang -fuse-ld=bfd -shared -L<python_lib_dir> -lpython3.12"
```

### 层 4：签名（bfd 不自动签名）

```
症状：E212 fallback 的 ELF 验证报 Missing .codesign section
对策：package() 从 wheel zip 解包后，对全部 *.so 执行
      binary-sign-tool sign -selfSign（幂等）
```

## 与 E543（numpy/meson）的互补关系

| 维度 | E543（numpy） | E544（pillow） |
|---|---|---|
| 构建系统 | meson（vendored） | setuptools/wheel |
| 换链接器方式 | meson native file 的 `ld=` | `LDSHARED` 环境变量 |
| libpython 链接 | native file `c_link_args` | LDSHARED 内联参数 |
| 签名时机 | package()（meson install 后） | package()（wheel 解包后） |
| 特有坑 | E212 检测（self.run 无输出） | 二进制 diff 损坏（层 1） |

两条合计覆盖 Python 生态两大主流构建体系的 CI 适配全路径。

## 红线

1. ❌ 见"diff 冲突"就盲目 rebase——先查 diff 里有没有二进制文件
2. ❌ 覆盖 LDSHARED 不补 libpython——坑 B 必然在第 4 层暴露
3. ❌ E212 验证只查 NEEDED 不查符号——静态链入的库无 NEEDED 但有符号
