# 保留代码生成器的数据契约，替换不兼容的 XS parser

## 现象与根因

Perl 可运行且模块路径正确，XML::Parser 的 Expat.so 仍因
`PL_markstack_ptr: symbol not found` 加载失败。文件权限调整无法产生缺失的
解释器 ABI。先确认不是模块路径、签名或下载错误，再考虑此方案。

## 可复用决策与修复

确认原代码生成器是否只消费 parser 数据结构。若是，抽取该结构契约而不是
重写其生成逻辑。XML::Parser Tree 采用有序 tag/body 交替，body 首项是属性，
字符节点为 0/text；必须保持相邻字符合并、CDATA、DTD 默认属性和原节点顺序。
用可用的标准库 parser 输出 JSON，原解释器通过核心 JSON 模块恢复原结构。
必须限定发行包内所需 DTD，拒绝其他实体、符号链接逃逸和网络 fallback。

在生成器依赖树已明确且无其他 XS 行为时使用；需要插件扩展或不同实体语义的
生成器不能直接套用。若有正式发布且 ABI 匹配的 parser，应先验证该组合。

## 验证与边界

从同一原始源码完整执行原校验器、原生成器和全部模块构建，核对产物身份，
并对安装产物执行真实功能消费者。构建文件数不是注册测试数。
SWH 的真机 r9 验证原 bozo 1/1（覆盖 100 XML）、96 模块、109 descriptors、
消费者 6/6。日志 SHA256
e9b3f1e3eac39441d7c47f293b20507607ce0d4be145165513dcc5acdf487843。
XML bridge 位于 archives/s/swh/0.4.17/xml_tree.py；原 Perl 生成器保持生成职责。

本知识新增 parser 数据契约保持与受限实体边界，不是泛化的 Perl 路径修复、
chmod 建议、FFT 规划知识或删减测试。r3 的 XS 失败保留为失败；r9 成功不反向
升级它，也不代表比赛 worker CI 或发布已通过。
