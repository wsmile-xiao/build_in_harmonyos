# E2159 - Conan shared-package consumers need explicit transitive runtime libdirs

> Contributor: 2301_80739235 | Status: DRAFT | Created: 2026-08-22

## Why this is a reusable pattern

Conan link metadata and Conan runtime-environment metadata are separate
contracts. A shared library can link against a transitive dependency during
the producer build while a direct `test_package` consumer still cannot load
that dependency at runtime.

## Symptom

The real OHOS target completed the full upstream suite, but the package
consumer failed after linking:

```text
Error loading shared library libminizip.so.1
Error 127 while executing
```

The R107 transaction preserved `71/71` upstream tests and a clean transfer,
then failed only when executing the consumer under `env="conanrun"`.

## Root cause

`cpp_info.requires` supplies transitive link/include relationships, but Conan
2 `VirtualRunEnv` does not necessarily infer every transitive dependency
`libdir` for a direct consumer. The tested package therefore exposed
`librasterlite2.so` without exporting the minizip runtime directory in the
consumer's `LD_LIBRARY_PATH`.

## Recommended solution

1. Keep the complete dependency graph in `cpp_info.requires`.
2. In `package_info()`, iterate dependency `cpp_info.libdirs` and prepend each
   directory to `self.runenv_info` under `LD_LIBRARY_PATH`.
3. For an isolated producer regression, remove consumer-side libdir
   reconstruction and run the unchanged consumer under `env="conanrun"` on
   the target. If the consumer also reconstructs dependency libdirs, report
   the result as a combined runtime-closure validation.
4. Require both the complete upstream inventory and all consumer assertions;
   do not turn a loader error into `NOT_RUN`.

## Forbidden shortcuts

- Do not remove minizip or any dependency to hide the loader error.
- Do not replace the consumer execution with a link-only check.
- Do not add OHOS conditional source macros for a Conan runtime contract.
- Do not reuse the consumed R107 launch; create a new freeze and W3 successor.

## Verification

R107 is immutable failure evidence: transfer/preflight/prepare passed,
`launch_count=1`, remote cleanup closed ownership, upstream was `71/71`, and
the consumer failed with the exact `libminizip.so.1` loader error. The r196
successor added producer `runenv_info` propagation, while `test_package` also
reconstructed every dependency libdir before execution. Its one real-device
launch completed upstream `71/71`, the consumer's `14/14` assertions, runner
RC 0, cleanup PASS, and closed ownership. This proves the combined runtime
closure and source-level producer fix, not producer propagation as an isolated
single-variable test. Neither consumed run may be replayed or relabeled.
