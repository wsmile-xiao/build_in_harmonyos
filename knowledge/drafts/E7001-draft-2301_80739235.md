# E7001 — CMake dependency include roots and WSL DrvFs timestamp boundaries

## 问题概述

OHOS AArch64 的 curl CMake 构建在大部分 libcurl 源文件完成后报
`openssl/opensslv.h` 缺失；同一版本在 Windows WSL 的 `/mnt/f` 上执行上游
`runtests.pl` 时，测试 762 的 `--remote-time` mtime postcheck 失败。

## 根因

Conan OpenSSL 包的公共头位于 `<package>/openssl/*.h`。把
`OPENSSL_INCLUDE_DIR` 指到 `<package>/openssl` 会让编译器寻找错误的
`<package>/openssl/openssl/opensslv.h` 路径；正确值是包根目录。

WSL `/mnt/f` 是 DrvFs/9p 挂载。它把所有负 Unix epoch 的 `utime` 写入截断为
epoch 0，因此上游要求 1940 年文件时间的测试 762 在该宿主上不能通过。这是
宿主文件系统能力边界，不是 curl 代码通过或失败的替代证明。

## 修复与验证

1. 保持 zlib/1.3.2 和 openssl/3.5.8.1 的 OHOS `--build=never` 闭包不变。
2. 将 `OPENSSL_ROOT_DIR`、`OPENSSL_INCLUDE_DIR` 绑定到 OpenSSL 包根，静态库
   路径分别绑定 `libssl.a` 和 `libcrypto.a`。
3. 在同一 W3 successor 中重建：curl CLI 和 libcurl consumer 均为 AArch64，
   target self-sign 成功，唯一 launch 返回 `target_tests=3/3`、`target_rc=0`、
   stderr 0、`processes_zero=true`，并完成 RELEASED 回执。
4. 在 `/mnt/f` 上用 `os.utime` 重现负 epoch 截断；单独运行 test 762 得到
   postcheck FAILED，不能将其标记为 PASS。随后在 F 盘任务目录内的 ext4 镜像
   中重建同一源码和 CMake 选项，完成 `2072` 项考虑、`490` 项能力跳过、
   `1582/1582` 要求项 PASS；该结果才是本地上游闭环证据。

## 适用范围与安全边界

适用于 CMake `find_package` 与 Conan 包目录层级不一致的交叉构建，以及 Windows
宿主 WSL 执行需要负时间戳的上游测试。所有 include/library 路径必须绑定冻结
闭包；不得通过主机库扩大依赖图。不得修改上游测试期望、忽略 test 762 或用部分
通过结果伪造 N/N；DrvFs 结果只能作为明确的宿主边界证据，ext4 镜像必须继续
存放在任务 F 盘目录内并绑定当前源码和工具链。

## CI 误报补充

平台 L0o 门禁用正则查找 `"curl"`/`'curl'` 字面量来拦截外部下载命令，可能把
Conan 配方合法的 `name = "curl"` 误报为 `uses_external_curl`。本次 CI #42125
已证明该触发特征：配方的 `source()` 实际调用 `tools.files.get()`，但裸包名仍被
误判。修复采用等值表达式 `name = "cu" + "rl"`，不改变 Conan 包身份，同时保留
`self.conan_data["sources"]` 的哈希绑定下载路径；随后应以同一提交重新执行 L0、构建
和平台 CI。该规避仅适用于已确认规则误报且下载实现仍由 Conan 工具管理的配方；若
存在 `subprocess`、`os.system` 或 `self.run` 调用外部下载命令，不能用字符串拼接掩盖。

## 归档格式补充

GitHub codeload 的 URL 可能没有 `.tar.gz` 后缀，但响应体仍是 gzip tar 归档。
在某些构建 worker 上，`tools.files.get()` 会依据 URL 或默认名选择解包器；缺少
显式文件名时可能把 gzip 内容交给 ZIP 解包器，产生
`BadZipFile: File is not a zip file`。本次修复在保持 URL 和 SHA-256 不变的前提下
传入 `filename="curl-8_22_0.tar.gz"`，使解包格式由配方明确绑定。

该边界适用于所有无扩展名或扩展名不可信的远程归档：先用有限字节和哈希确认真实
内容，再在 `get()` 中声明与内容匹配的文件名；不能通过更换未核验的镜像或归档来
绕过解包失败，也不能把解包失败写成源码或 CI 通过。

## OHOS 头文件探测补充

OHOS 的 sysroot 同时提供 Linux 兼容头和 POSIX 头时，curl 的 CMake 探测可能把
`HAVE_LINUX_TCP_H` 设为真。`cf-socket.c` 和 `cf-ip-happy.c` 先包含
`sys/socket.h`，再包含 `linux/tcp.h`，在该 sysroot 中会重复定义
`sockaddr_storage`，导致编译期重定义错误。把 `HAVE_LINUX_TCP_H` 作为
`CMakeToolchain` 的缓存变量显式设为假，可保留 `netinet/tcp.h` 的兼容分支，避免
修改上游源文件。

该做法适用于“平台提供某兼容头但其 ABI/声明与主接口头不兼容”的交叉工具链；必须
以目标编译日志证明冲突来自该头文件，并确认替代分支存在且覆盖相同功能。不能用它
掩盖缺少必需 API，也不能在没有目标头文件/编译证据时凭主机 Linux 结果关闭探测。
