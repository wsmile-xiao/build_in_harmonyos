# Shared 库的上游测试可能仍依赖静态归档

## 现象与根因

有些老式 `Makefile.in` 同时构建共享库和静态库，但注册的测试程序始终以静态归档为前置依赖。若 Conan 配方为了交付 shared 包而加 `--disable-static`，库本身可以构建，`make test` 却缺少必需归档；只跑新加的消费者会漏报上游测试缺失。Mini-XML 4.0.6 的 `Makefile.in` 中，`test: testmxml`，而 `testmxml: $(LIBMXML_STATIC) testmxml.o`，正是这个结构。

## 修复与验证

先读测试目标的真实链接依赖，再在 shared 包构建中保留 `--enable-static`，签名目标系统上的测试 ELF，运行完整上游 `make test`；另用已安装包编译消费者，验证所交付的共享 ABI。真机日志 `cc98559b7609ed1cf89c6c274ed63498e3a7b2c970a27c102edabe3c3b083e8c` 显示静态归档、测试程序与共享库均被构建，文件、字符串、文件描述符三个比较组全部通过（3/3），安装包消费者通过（1/1）。

## 范围和边界

适用于测试目标显式依赖静态归档的 Makefile 工程；不是要求所有 shared 包都额外交付静态库。检查目标和日志后才能决定是否保留归档。与既有 E543 的“无 VPATH 的 out-of-source 构建找不到源文件”不同，这里即使改为 in-source 构建，静态测试链接前置仍独立存在。不能用消费者测试代替上游 `make test`，也不能把构建出测试程序等同于执行通过。
# Worker 配置阶段的增量边界（2026-10-12）

CI #85292 在 `config.status` 写入 `subs1.awk` 时 Permission denied，尚未进入测试归档链接。共享库仍保留静态测试输入并不能消除该前置文件系统问题。复用已验证的 Autoconf/HMDFS 模式：严格匹配 release 的三处临时目录生成语句，把主分支和 fallback 都放入任务私有 TMPDIR，使用独占 mkdir 与 umask007；mktemp 自带0700不受外层 umask 影响，不能只改外层 umask。保留失败清理、完整 test 目标与安装消费者，不改共享缓存、不放宽其他目录权限。修复后验证必须由新的完整 Conan 事务给出，不沿用旧测试日志。
