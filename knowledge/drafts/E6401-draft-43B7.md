# E6401 — clang `-pedantic` 拒绝 GNU `##__VA_ARGS__` 变参宏扩展

> 草稿（draft），未入索引。来源：zcfan 1.4.0 适配。

## 错误特征

```
zcfan.c:26:51: error: token pasting of ',' and __VA_ARGS__ is a GNU extension
               [-Werror,-Wgnu-zero-variadic-macro-arguments]
#define err(fmt, ...) fprintf(stderr, "[ERR] " fmt, ##__VA_ARGS__)
                                                  ^
...
10 errors generated.
make: *** [Makefile:22: zcfan] Error 1
```

同一份源码用 GCC 编译**完全无告警**；报错只在 clang 下出现，且因上游自带 `-Werror`
直接致命。

## 触发条件

- 构建系统：任何调用 clang 的构建系统（make / cmake / meson 均可）
- 阶段：compilation
- 触发变量：源码使用 `##__VA_ARGS__`，且编译参数含 `-pedantic`（或 `-Wpedantic`）+ `-Werror`

## 根因分析

`##__VA_ARGS__` 是 GNU 的**变参粘贴扩展**：当可变参数为空时，它吃掉前面那个多余逗号。
这是 glibc/GCC 生态的常见写法（C99 标准下 `, __VA_ARGS__` 在空参时会产生悬空逗号），
GCC 即使在 `-pedantic` 下也**静默接受**（它是 GCC 文档化的扩展，不视为违规）。

clang 的立场不同：它把该写法判为 GNU 扩展，在 `-pedantic` 下产生
`-Wgnu-zero-variadic-macro-arguments` 诊断；叠加上游 `-Werror` 即致命。

**为什么上游 CI 是绿的**（本任务实测的上游形态）：

| 上游 CI 步骤 | 是否暴露该问题 |
|---|---|
| `make lint`（clang-format） | ❌ 不编译 |
| `make clean clang-tidy` | ❌ 显式带 `-Wno-gnu-zero-variadic-macro-arguments` |
| `make clean clang-everything` | ❌ 同样显式带 `-Wno-` 该告警 |
| 裸 `make`（含 `-pedantic -Werror`） | ⚠️ **会失败，但上游 CI 从不执行** |

所以这是"GCC 干净 + 上游 CI 覆盖盲区"叠加产生的、只在 clang 工具链（如 OHOS）上
暴露的移植缺陷。

## 解决方案

### 推荐方案

改为**无命名形参的全变参宏**——`__VA_ARGS__` 恒含至少一个实参（格式串），悬空逗号
不存在，`##` 自然不再需要：

```diff
-#define info(fmt, ...) fprintf(stderr, "[INF] " fmt, ##__VA_ARGS__)
-#define err(fmt, ...) fprintf(stderr, "[ERR] " fmt, ##__VA_ARGS__)
+#define info(...) fprintf(stderr, "[INF] " __VA_ARGS__)
+#define err(...) fprintf(stderr, "[ERR] " __VA_ARGS__)
```

- 展开与原实现**逐字节等价**：`err("boom\n")` → `fprintf(stderr, "[ERR] " "boom\n")`
- 标准 C99，`-pedantic` 零告警
- 不引入平台宏（R8 / PF5 合规），不改变平台分支
- 前提：所有调用点至少传格式串（改写前 `grep -nE '\b(info|err)\(' src.c` 清点）

### 回退方案

追加 `-Wno-gnu-zero-variadic-macro-arguments`，且**必须排在 `-pedantic` 之后**
（后出现的 `-pedantic` 会重新启用该子诊断）。注入点首选上游构建系统的扩展变量
（若 Makefile 的 `CPPFLAGS` 为空则可用）；**不要**用命令行 `CFLAGS`——GNU make 的
命令行赋值会整体替换 `:=` 赋值的上游告警集。

### 禁止做法

- ❌ 用 `#ifdef __OHOS__` 包裹宏 —— 无必要且违反 R8 / PF5，会被 create-pr 前置闸拦截
- ❌ `-Wno-error` / `-Wno-error=pedantic` / `-w` 整体放宽 —— 掩盖真实诊断，审计降档

## 验证

```bash
clang -std=gnu99 -pedantic -Wall -Wextra -Werror src.c -o /dev/null
# 未修复 -> error: token pasting of ',' and __VA_ARGS__ is a GNU extension
# 已修复 -> 无输出，exit 0
```

四向对照（zcfan 1.4.0 实测）：

| 源码树 | 上游默认 `make` 参数 | 上游 `clang-everything` 参数 |
|---|---|---|
| `.orig`（原样） | ❌ exit 1，10 errors | ✅ exit 0 |
| `.work`（含补丁） | ✅ exit 0 | ✅ exit 0 |
