# E341 — X11 客户端库无 X server 的消费者测试方法：强类型重定位 + ABI 布局固定

## 错误特征

X11 扩展客户端库（Xcomposite/Xinerama/Xdamage/Xrandr 等）上游通常**没有任何
自动化测试**（`make check` 为空）。直接补上游测试需要 X server（Xvfb）与完整
X 会话，在 OHOS CI worker 上不可行。常见错误做法是：写一个链接库后什么都不验证的
空 test_package（"只要链接成功就算过"），结果 ABI 里函数签名/版本常量/结构体布局
退化时完全无声。

## 触发条件

- 目标库: X11 家族客户端库，上游 `check_PROGRAMS`/`TESTS` 为空。
- test_package: 需要在不连接 X server 的前提下验证产物 ABI 完整。
- CI: OHOS worker 无 Xvfb/显示服务。

## 根因分析

- 纯链接测试（`#include <X11.h>` + `int main(){return 0;}`）只验证了
  `-l` 能找到库，**不验证导出符号集合**，也不验证**类型/常量契约**。
- 上游多数 X11 客户端库的 ABI 由三部分构成，必须分别钉住：
  1. **导出符号**（`XineramaQueryScreens` 等函数指针）；
  2. **协议版本常量**（如 COMPOSITE major/minor/revision）；
  3. **公开结构体布局**（如 `XineramaScreenInfo` 的字段偏移）。
- 调用任何真实函数会触发 X 连接失败，所以不能直接调用；用"取函数地址 + 类型
  断言"即可在无 X server 时强校验符号存在且签名正确。

## 解决方案

### 1) 导出符号：强类型重定位（api_surface.c）

```c
#define DECLARE_SYMBOL(name) \
    static __typeof__(&name) volatile probe_##name = &name
DECLARE_SYMBOL(XineramaQueryScreens);
int main(void) {
    (void)probe_XineramaQueryScreens;   /* 活重定位，链接期即校验 */
    return 0;
}
```

`__typeof__(&name)` 让编译器在编译期核对签名；`volatile` 指针 + 取地址强制
生成**活重定位**，任何缺失/改名符号在链接或加载期失败，而不是运行时崩溃。
覆盖上游头文件声明的**全部**导出函数。

### 2) 版本/常量契约（version_contract.c）

用宏/常量断言钉住协议版本：`XCOMPOSITE_MAJOR == 0`、`XCOMPOSITE_MINOR == 4`、
`XCOMPOSITE_VERSION == 402`、重定向模式选择器取值等。

### 3) ABI 布局固定（offsetof 断言）

对公开结构体用 `offsetof`/`sizeof` 钉死布局：

```c
CHECK(sizeof(XineramaScreenInfo) == 12, "...");
CHECK(offsetof(XineramaScreenInfo, width) == 8, "...");
```

任何字段顺序/宽度变化立即在 CI 失败。

### 4) 测试接线

- CMake: `-Wall -Wextra -Werror`，两个可执行文件 `api_surface` +
  `version_contract`，均 `target_link_libraries(... <pkg>::<pkg>)`。
- test_package/conanfile.py: `test_type="explicit"`，可运行（`can_run`）时逐个
  运行；OHOS 上先用 `binary-sign-tool` 签名再运行（`_sign_ohos_elf`）。
- MANIFEST.yml 记 cases/assertions 数，供 CI 统计。

## 禁止策略

- 不写"只链接不验证"的空 test_package。
- 不调用真实 X 函数（无 X server 会运行期崩溃）。
- 不用弱引用/`dlopen` 兜底掩盖缺失符号——必须让缺失在链接期失败。
- 不改上游头文件或源码来让测试"通过"。
