# E545 草稿：`init-build --url` 不接受 Git 仓库 URL

## 错误特征
执行 `init-build swuniq 0.5 --url=https://github.com/mterron/swuniq.git` 后只输出 `下载: https://github.com/mterron/swuniq.git`，连接迟迟不结束（本次手动终止），没有产生 `.orig/.work`。不是 Conan 依赖缺失，也不是 C 编译错误。

## 根因与影响
`init_build.py` 中 `_guess_tar_format()` 不识别 `.git`，回退 `tar.gz`；`_download_one()` 走 urllib 下载而非 `git clone`，默认最长 300 秒。即使拿到仓库 HTML 页面，也不是 gzip 压缩包。该问题影响把仓库地址当源码归档 URL 的所有 `init-build` 使用者；与已入库的 `E483`（Conan `get()` 误把无扩展名 tarball 当 zip）不同。

## 解决方案
先核对**指定版本** Git tree 的 gitlink（mode `160000`）。本例 v0.5 commit `59521c1ba7cd02b6532bdec1d48cad95be599753` 的官方 tree 已包含 `utarray.h`、`utringbuffer.h`、`xxhash.h`，无需按新版主线递归子模块。使用官方版本归档 `https://codeload.github.com/mterron/swuniq/tar.gz/refs/tags/v0.5`，下载 sha256 为 `82ff7f406e6581b2e1edce12d519aebfb3bbf372acb5ac13c88d370cd26403b2`。若指定 tag 确有 gitlink，则应按其固定 commit 递归拉取，不应混用 HEAD。

## 验证
`python3 scripts/ohc-run.py init-build swuniq 0.5 --url=https://codeload.github.com/mterron/swuniq/tar.gz/refs/tags/v0.5` 成功产生 `.work/Makefile` 和 4 个 vendored headers；`lang-preflight` 判断 C 通过，交叉编译及 `make check` 通过。

## 禁止
不要将 `.git` 仓库 URL 直接传给 `init-build --url`，也不要用最新版子模块覆盖旧标签 vendored 头文件。

## 关联
`E483` 仅解决 **Conan get()** 下载无扩展名 codeload URL 的 zip 格式误判，不能解决 `init-build` 的 `.git` 地址类型错误。
