# E2185: Reconstruct unregistered upstream self-checks for library-only packages

## Symptom

An upstream CMake tree has a directory named `test/`, but `ctest -N` reports
zero registrations. The directory builds several command-line programs, while
the downstream package intentionally removes the directory to publish only the
library. Reporting zero upstream tests loses real self-check coverage; counting
every program as a test instead includes data utilities that cannot run without
external files.

## Root cause

CMake executable targets, CTest registrations, and runnable test cases are
different inventories. A test directory can mix deterministic no-argument
self-checks with converters or analyzers whose command line requires input
fixtures. Library-only packaging is allowed to omit both groups from the
installed artifact, but that packaging decision does not erase eligible
upstream checks from the validation obligation.

## Fix

1. Inventory `add_executable` and `add_test` declarations separately and record
   both denominators.
2. Inspect each executable's entry point and input contract. Classify only a
   deterministic no-argument program with a real nonzero failure path as an
   eligible self-check.
3. Keep the production build and install library-only. In a separate target
   validation transaction, compile each eligible unchanged upstream source
   against the installed package rather than re-enabling utility installation.
4. Sign every target executable when the platform requires it, run each once,
   and bind its return code and output hash to the same source and package
   identity.
5. Report zero CTest registrations, eligible self-checks as `N/N`, excluded
   fixture-required utilities by name and reason, and package-consumer results
   as separate scopes.

## Evidence and verification

GKlib 5.1.1 declares ten executables in `test/CMakeLists.txt` and no CTest
entries. Source inspection showed that `strings.c` and `gksort.c` have
no-argument entry points and execute internal checks; the other eight programs
accept input file arguments and the release archive supplies no task-local test
fixture set for them. W3 r003 rebuilt the two eligible sources against the
installed `libGKlib.a`, signed both executables and ran them on OHOS with
return code zero. The upstream denominator was 2/2, while a separate package
consumer passed 1/1 programs and 7/7 assertions. The immutable 12-receipt chain
ended at SHA-256
`243766dfd14a6675cb81b0995b15019af68d478f8458b7eb98466323e6fe8616`
and postrelease readback reported `BASE_ABSENT`.

## Applicability and safety boundaries

Use this pattern for C or C++ libraries whose upstream test directories mix
self-checks and file-oriented utilities, especially when downstream packaging
removes utility targets. It does not authorize selecting a subset from a real
registered suite, treating a usage/error exit as success, fabricating fixtures,
or replacing target execution with host compilation. The reconstructed sources
must be unchanged, linked to the installed package and executed on a compatible
target; consumer assertions remain a distinct denominator.
