# NetSurf 构建系统隐式宏与宿主代码生成器迁移（libcss 0.9.2 实证）

> 草稿：DRAFT-libcss-0.9.2-netsurf-implicit-macros-and-host-codegen
> 关联：DRAFT-libsvgtiny-0.1.8-netsurf-nsshared-standalone-makefile-gperf-fallback（NSSHARED→standalone Makefile 主路径，本条目收增量子模式）

## 现象（三层，层层隐蔽）

1. **链接期 duplicate symbol**：`ld.lld: error: duplicate symbol: _ALIGNED`，
   引用点分散在多个翻译单元（libcss 是 src/stylesheet.h 的
   `struct css_rule {...} _ALIGNED;` 与 computed.c/各测试程序）。
2. **生成文件编译失败**：`fatal error: 'bytecode/bytecode.h' file not found`
   ——仅 autogenerated_*.c 报（一手 .c 全过）。
3. **上游构建规则不可复刻**：netsurf-buildsystem 的 PRE_TARGETS/
   AUTOGEN 规则在外置包里，tarball 无实体。

## 根因

- netsurf-buildsystem 的 `Makefile.clang` 在 CFLAGS 隐式注入：
  ```make
  CFLAGS := $(CFLAGS) -D_ALIGNED="__attribute__((aligned))" -DSTMTEXPR=1
  ```
  源码树无任何 `#define _ALIGNED`——宏完全来自构建系统。standalone
  Makefile 替换（libsvgtiny 先例）只摘源文件清单时编译**静默通过**
  （_ALIGNED 退化为结构体标签，语法合法），**链接期才爆** duplicate
  symbol（每个翻译单元各一个同名标签符号）。
- netsurf-buildsystem 源码可从 GitHub 镜像查证（官方
  git.netsurf-browser.org 已 404）：
  `lightpanda-io/netsurf-buildsystem` makefiles/Makefile.clang 第 29 行。
- libcss 的属性解析器由构建期宿主生成器产生：gen_parser（由
  css_property_parser_gen.c 编出）吃 properties.gen 吐 119 个
  autogenerated_*.c。netsurf-buildsystem 的 PRE_TARGETS 规则负责这个
  顺序，standalone 化必须显式写两阶段。
- GNU make 陷阱：若生成对象放独立变量（GEN_OBJ）而模式规则只挂
  `$(OBJ): %.o: %.c`，GEN_OBJ 走**隐式规则**——COMPILE_CFLAGS 整个
  丢失（-I/宏全没），于是只有 autogenerated_*.c 报"找不到内部头"。

## 修复（standalone Makefile 三件事）

1. COMPILE_CFLAGS 显式补宏：
   ```make
   COMPILE_CFLAGS := -D_BSD_SOURCE -D_DEFAULT_SOURCE -std=c99 \
       '-D_ALIGNED=__attribute__((aligned))' -DSTMTEXPR=1 \
       -I$(CURDIR)/include/ -I$(CURDIR)/src/ $(WARNFLAGS) $(DEP_CFLAGS) $(CFLAGS)
   ```
2. 两阶段构建（宿主生成器）：
   ```make
   gen_parser:
   	$(BUILD_CC) -o $@ src/parse/properties/css_property_parser_gen.c
   $(GEN_SRC): src/parse/properties/properties.gen gen_parser
   	for p in $(GEN_PROPS); do \
   		./gen_parser -o src/parse/properties/autogenerated_$$p.c \
   			"$$(grep "^$$p:" src/parse/properties/properties.gen)"; \
   	done
   ```
   BUILD_CC 在 conanfile 里与 CC 同值（OHOS 本机 aarch64 可直接跑）。
3. 生成对象与一手对象共用同一条模式规则：
   ```make
   $(OBJ) $(GEN_OBJ): %.o: %.c
   	$(CC) $(COMPILE_CFLAGS) -c -o $@ $<
   ```

## 测试驱动迁移（testrunner.pl 等价复刻）

上游 `make test` 由 netsurf-buildsystem 的 testrunner.pl（perl）按
`test/data/<套件>/INDEX` 清单逐文件调起测试二进制。平台无
netsurf-buildsystem 时：测试程序本身是独立 C 程序（数据驱动 +
testutils.h assert 宏，任一断言失败 exit(EXIT_FAILURE)），零修改直接
编译；驱动语义用 shell 循环等价复刻（每套件 × 每数据文件 → 退出码
计 PASS/FAIL）。libcss 0.9.2 实证：8 测试二进制 × 55 数据文件 =
2759/2759 用例全 PASS。

## 验证

- `grep -rn "_ALIGNED" src/ include/`——有声明处即必补宏
- `nm libcss.a | grep -w _ALIGNED`——修复后无独立标签符号
- libcss/0.9.2 本机 conan create 绿：上游 2759/2759 + 消费者 6/6
  （解析内联 CSS 含 @media/@import → select computed style 断言
  color=#ff0000 命中、body 规则 specificity 正确不误用）
- PR #12105（任务 #14003）

## 适用面

全部 NetSurf NSSHARED 家族大库（libcss/libdom/libhubbub/…凡带
_ALIGNED 声明或 PRE_TARGETS 构建期生成器者）；泛化为"构建系统隐式
注入宏 + standalone Makefile 替换"通病模式——替换后编译静默通过、
链接期才爆的，第一反应查原构建系统的 CFLAGS 注入项。
