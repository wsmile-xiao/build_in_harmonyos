# E345 - Zero-dependency Meson library pattern for OHOS Conan

> Contributor: 2301_76770579 | Status: DRAFT | Created: 2026-08-27

## Scope

Use this pattern when adapting a small C library whose upstream Meson build
links no pkg-config packages (only optional system libs) to the aarch64 OHOS
Conan track. It is based on the libxcvt 0.1.3 adaptation. The library exposes a
handful of pure functions, installs one shared object plus headers, and carries
no `requirements()` in the Conan recipe.

## Failure pattern

A zero-dependency Meson library can still fail on the OHOS worker for four
independent reasons:

1. The OHOS profile declares only clang/clang++ under
   `tools.build:compiler_executables`. Meson therefore writes no `ar`/`ranlib`
   into `conan_meson_native.ini` and the archive step fails with a missing
   binutils tool.
2. The worker has no writable `/tmp`. clang's temp-file creation and ninja
   scratch files fail with "C compiler cannot create executables" unless
   `TMPDIR`/`TMP`/`TEMP` point inside the build folder.
3. The upstream `cc.find_library('m', required: false)` is the only external
   probe. On bionic the math functions are in libc; the optional probe must not
   abort setup.
4. Meson-installed shared libraries are unsigned ELF. They load in the buildbot
   sandbox but are rejected on the device until stamped with a `.codesign`
   section.

## Root cause

Each failure comes from the gap between the profile's minimal toolchain
declaration and what Meson/ninja assume: archive tools, a POSIX `/tmp`, and a
runtime loader that accepts unsigned ELF. The recipe must close all four gaps
in one pass.

## Recommended solution

The libxcvt recipe (`archives/l/libxcvt/0.1.3/conanfile.py`) shows the full
pattern:

1. Build with `MesonToolchain`, `default_library=shared`, `wrap_mode=nodownload`.
2. Install meson on demand: prepend the Python user bin, then
   `python -m pip install --user meson` if `shutil.which("meson")` is empty.
3. Provide a minimal pkg-config shim when neither `pkg-config` nor `pkgconf`
   exists, and point the Meson native file's `pkgconfig =` at it.
4. Inject `ar = <llvm-ar path>` and `ranlib = <llvm-ranlib path>` into
   `[binaries]` of `conan_meson_native.ini`. Resolve them next to clang first,
   then via PATH.
5. Create `build/tmp` and export `TMPDIR`/`TMP`/`TEMP` to it before `meson
   configure`/`build`.
6. `Meson.install()`, copy `COPYING` into `licenses/`, then sign every packaged
   `.so`, `.so.*`, and `bin/` ELF: `llvm-objcopy --remove-section .codesign`
   (ignore failure) followed by `binary-sign-tool sign -inFile -outFile
   -selfSign 1`.
7. `package_info`: `libs=["xcvt"]` (the name after `lib` in `libxcvt.so`),
   `includedirs=["include"]`, `pkg_config_name="libxcvt"`. The upstream
   `shared_library('xcvt', version: '0.1.3')` produces `libxcvt.so.0.1.3`, so a
   consumer links `-lxcvt`.

## Verification

- `meson setup` reports host cpu aarch64 and `Library m found: NO` (or YES via
  bionic libc) without aborting.
- `ninja` completes and `Meson.install()` places `lib/libxcvt.so.0.1.3`,
  `lib/libxcvt.so.0`, `lib/libxcvt.so`, `include/libxcvt/*.h`,
  `lib/pkgconfig/libxcvt.pc`, and `bin/cvt`.
- test_package compiles a consumer with `find_package(libxcvt CONFIG REQUIRED)`
  and runs two executables: an API-surface relocation probe for
  `libxcvt_gen_mode_info` and a version contract that calls
  `libxcvt_gen_mode_info(1920, 1080, 60.0f, false, false)` and checks the
  returned mode fields.
- `readelf -SW` on the packaged shared object shows exactly one `.codesign`
  section.

## Forbidden shortcuts

- Do not sign a shared object without first removing an existing `.codesign`
  section (duplicate sections corrupt the signature).
- Do not hard-code `/tmp`; pin `TMPDIR` into the build folder.
- Do not add `requirements()` for system `libm`; bionic provides it in libc and
  the optional `find_library('m', required: false)` handles both cases.
- Do not assume a pkg-config binary exists on the worker; ship the shim.
