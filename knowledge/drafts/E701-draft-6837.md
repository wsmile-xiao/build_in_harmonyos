# E701 — 64 位目标上的窄整数指针截断导致运行时崩溃

## 错误特征

在 aarch64/LP64 目标上，Clang 对类似下面的代码给出窄化警告：

```text
warning: cast to smaller integer type 'unsigned int' from 'char *'
```

如果该值随后用于地址对齐或指针恢复，程序可能在第一次执行对应路径时报告：

```text
Segmentation fault (core dumped)
```

## 触发条件

- 构建系统：Autotools、Makefile 或其他可调用 Clang 的 C/C++ 构建系统
- 目标：指针宽度大于 `unsigned` 的 64 位平台，典型为 aarch64
- 代码形态：自定义分配器、对齐宏、地址哈希或指针暂存使用显式 `unsigned`/`int` 转换

## 根因分析

GNU Bool 0.2.2 的 `src/mem.h` 定义了 `ALIGN(p)`，把地址显式转换为 32 位 `unsigned` 后再执行掩码运算。设备上的 clang 15 产生 `cast to smaller integer type` 警告；首次探索构建虽然完成链接，但上游测试 18 个目标中只有 3 个通过，其他 15 个目标在调用内存分配路径时 SIGSEGV。

这不是对齐粒度不足，而是地址整数表示宽度不足：aarch64 指针的高位在转换为 `unsigned` 时丢失，恢复后的地址不再指向原分配块。它与 E213 的“隐式 int 返回值截断指针”同属指针宽度问题，但本条针对的是显式窄整数地址/对齐运算；E420 则针对缺失 API 声明导致的隐式返回类型，均不能替代本条的修复。

## 已尝试方案

1. 首次源码构建：`make` 成功但出现 `mem.h` 指针截断警告；`make check` 为 3/18 通过、15/18 失败、0 跳过，失败日志均为 SIGSEGV。
2. 仅使用 `-Wno-pointer-to-int-cast` 或 `-Wno-error` 会隐藏诊断，不能改变截断后的地址，因此未采用。
3. 将 `ALIGN` 中地址运算改为 `uintptr_t`，加入 `<stdint.h>`，不改变分配边界或掩码含义。

## 最终方案

```c
#include <stdint.h>
#define ALIGN(p) ((uintptr_t)((p) + ALIGNBYTES) & ~(uintptr_t)ALIGNBYTES)
```

用项目的 `refresh-patch --auto` 生成 `src/mem.h` 补丁。该表达式保持原有按 `ALIGNBYTES` 向上对齐的语义，同时保证中间地址值能够容纳目标指针宽度。

## 适用范围、反例与风险

- 适用于显式把指针转换为可能更窄的整数并参与地址运算的旧 C/C++ 代码。
- 若问题是分配器返回地址没有满足 `max_align_t` 契约，应检查 E476；不能用本条替代分配器实现分析。
- 若是函数缺少声明导致隐式 int 返回指针，应检查 E213/E420；应补齐真实声明而不是套用对齐宏。
- `uintptr_t` 必须由目标标准库提供；极老工具链可使用经过 `sizeof` 和运行时验证的等宽整数类型，但不应凭经验直接选择 `unsigned long`。
- 禁止通过关闭指针转换警告来宣称适配成功。

## 真实验证

```text
Before: make -j1 check -> TOTAL 18, PASS 3, FAIL 15, SKIP 0; SIGSEGV
After:  make -j1 check -> TOTAL 18, PASS 18, FAIL 0, SKIP 0
After:  Conan G2 -> conan create success; upstream 18/18; test_package 1/1
After:  W3 -> build_and_test.sh pass
```

Bool 的消费者测试又执行了安装包 `bin/bool` 的版本、布尔匹配/不匹配、固定字符串和缺失文件状态，返回码为 0。

## 查重与新增价值

已对 E063、E213、E420 及其文档/关键词查重：现有条目覆盖编译器诊断、隐式函数返回值截断和缺失直接声明，但没有覆盖“显式窄整数对齐宏在 64 位目标导致运行时 SIGSEGV”的触发签名、最小修复和前后测试对照。因此本条可作为跨旧 C/C++ 仓库复用的知识扩展。
