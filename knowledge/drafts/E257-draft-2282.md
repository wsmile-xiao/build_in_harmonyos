# E257: adapt 纯 Python 意图解析套件的完整执行与语义验证

## 问题现象

adapt-parser 1.0.0 的上游 `run_tests.sh test` 使用 shell glob 将 `test/`
目录下的模块逐个传给 pytest。测试文件名是 `IntentTest.py`、`TrieTest.py`
等非标准形式，直接运行 `pytest test` 会返回 `no tests ran`，而只运行
`IntentEngineTest.py` 也会漏掉上下文、实体展开和 Trie 行为。

## 适配要求

先校验并解包官方归档，再按上游 runner 实际展开的八个模块执行：

```text
pytest test/ContextManagerIntegrationTest.py test/ContextManagerTest.py \
  test/DomainIntentEngineTest.py test/EntityExpanderTest.py \
  test/EntityTaggerTest.py test/IntentEngineTest.py test/IntentTest.py \
  test/TrieTest.py -q
76 passed in 0.24s
```

Conan `test_package` 还应从安装后的 `site-packages` 导入 Adapt，注册实体并
用 `IntentBuilder` 构造意图，至少断言意图名称、实体槽位和 confidence。这样
能同时覆盖打包路径和 Adapt 的核心语义，而不是只证明模块可以 import。

## 本次证据

- 上游归档：`adapt` release/v1.0.0，commit
  `6cac0e499a586fda160f5252c52272cc822912bb`。
- 上游测试：8 个模块、76 个用例全部通过；官方 flake8 选择性检查通过。
- 消费者测试：`archives/a/adapt/1.0.0/test_package/test_adapt.py`，4 项运行时断言。
- L1e：移走 Conan 包内 `lib/` 后消费者测试失败，证明测试依赖打包产物。
