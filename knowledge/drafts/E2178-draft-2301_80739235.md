# E2178: OHOS target linker invocations need compiler-relative runtime binding

## Context

An OHOS Conan worker can invoke a target clang from an SDK bundle. The clang
driver may execute `lld`, which itself dynamically loads libraries shipped next
to the SDK rather than in the worker's global runtime search path.

## Symptom

All target C objects compile, but the final link fails with messages such as
`Error loading shared library libxml2.so.16`, `Error relocating ... lld`, or
`clang-15: error: unable to execute command`.

## Root cause

The target compiler path identifies the SDK installation, but the worker's
`LD_LIBRARY_PATH` does not necessarily include that SDK's `llvm/bin` and
`llvm/lib` directories. Object compilation can therefore succeed while the
linker process fails before writing an ELF.

## Fix

1. Keep the target compiler path from Conan's structured toolchain settings.
2. Derive the compiler directory and its sibling `lib` directory from that
   exact path.
3. Prepend those directories to `LD_LIBRARY_PATH` for target compile/link
   commands on POSIX workers, retaining the existing environment.
4. Keep Windows command construction unchanged and do not modify global system
   library directories.

## Validation

CI #39466 for scdoc 1.11.3 compiled the target objects but failed at the final
link because `lld` could not load `libxml2.so.16`. The recipe change binds the
compiler-relative runtime directories at the command boundary; a successor CI
run must show a produced target ELF and complete the package/test stages.

## Reusable decision rule

When a cross compiler's linker reports a missing shared library, derive the
runtime closure from the exact compiler installation and bind it only to that
invocation. Do not treat successful object compilation as link success and do
not repair the worker globally.

## Safety boundary

This is a task-local environment binding for the frozen target compiler. It does
not authorize copying SDK libraries to shared locations, changing worker
configuration, suppressing linker errors, or treating a host-only build as an
OHOS target result.
