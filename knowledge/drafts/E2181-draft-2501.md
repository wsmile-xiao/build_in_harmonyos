# E2181 draft: A Debian `+ds` orig tar may need a matching build-time source sidecar

A Debian-repacked `orig.tar` is not always independently buildable. If CMake reports a missing referenced source file, first compare the matching `.dsc`, `debian/copyright` `Files-Excluded` list, and `debian/rules`; do not assume the upstream CMakeLists is stale. Debian may move the implementation into its `debian.tar` and copy it back immediately before configure. This is a multi-archive source-identity and licensing issue, not a reason to stub the algorithm or drop it from the build.

MathGL 8.0.3+ds.2 demonstrated the pattern. The exact orig tar SHA-256 `951ce522b84627062e28e6a45e0e9f8d1ced04835f271a488d152fece699d1db` omits `src/s_hull`, but CMake still lists `s_hull/s_hull_pro.cpp`. The first HarmonyOS PC run failed at CMake generation. The matching Debian tar SHA-256 `6b00f972103701e600d614fcc3742c3531bb6b13ed13839bf45403de4aaed73c` contains both files, and `debian/rules` performs `cp -r debian/s_hull src/` before configuration. Their individual SHA-256 values are `54d52cb27aaa361a155ed5b9b4b82cefcfca19153db31ef92608a70691af215d` and `f90fbb58be683931140635443fb4a6db46b5ba23d426ee45fe0f6eb4698be429`.

The Conan recipe exports only these original sidecar files and Debian's copyright record, checks the declared hashes, then restores them before CMake. The files are GPL-3-only, so the combined static package is not labeled LGPL merely because an optional CMake mode exists. The final target run completed upstream native render/test cases **150/150**, installed-package PNG consumer **1/1**, and a single-launch W3 release/postrelease validation; full log SHA-256 `adf59f18d6c1fc010f9fe32e98ccf4738068a00d9c2525e4fe89e4106472e3d0`.

For other `+ds` packages, require the matching Debian revision and verified file hashes, inspect licensing for every restored file, and fail closed if the sidecar is missing or altered. If the Debian source split cannot be established, use a complete authoritative upstream release rather than an invented replacement. A successful CMake configure alone is insufficient: run the upstream driver and a packaged consumer to prove the restored implementation has not been omitted.
