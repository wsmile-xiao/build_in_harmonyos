# E769 — 64 位目标上整数优先联合体未完整初始化指针

## 错误特征

wreport 3.36 在鸿蒙 PC 真机上可编译，但 C++ 上游测试 `var.get_set` 在复制字符串变量时收到 SIGSEGV。测试定位到 `Var::copy_value`：源指针有效，新对象的 `m_value.c` 却是非空垃圾地址，因此 `allocate()` 跳过分配，随后的 `memcpy` 写入无效地址。

## 根因

`m_value` 是含 `int32_t i` 和 `char* c` 的联合体；构造函数写 `m_value{}` 时仅初始化第一个成员 `i`。在 AArch64 上，4 字节整数清零不保证 8 字节指针的高 4 字节也清零。之后将 `c` 当作可空指针读取属于未定义行为。

## 适配方法

令 `char* c` 成为联合体的第一个成员，使现有各构造函数的 `m_value{}` 初始化覆盖整个指针宽度。联合体大小和偏移不变；无需禁用测试或绕过复制路径。其他代码若存在同类联合体，也应检查每个构造路径是否完整初始化指针成员。

## 验证

在目标机 `10.62.210.132:2222` 上，修复前单独执行 `TEST_ONLY=var.get_set` 稳定失败；修复后该方法通过。完整上游 Meson 测试 2/2 套件通过，随后 `conan create` 连同真实 API 消费者测试通过。
