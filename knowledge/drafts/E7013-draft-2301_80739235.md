## Problem

Custom bootstrap projects often compile a small vendored dependency and then
produce a command-line executable. A host-side recipe can appear healthy while
the target Conan run fails before compilation with `WinError 2`, a target
self-rebuild later stops with `ios_base::failure: Operation not permitted`, or
an upstream test run discovers testscript files but fails because raw file paths
were passed where the build system expects typed `testscript{stem}` targets.

## Root cause

The recipe was relying on an ambient compiler name and temporary directory. A
closed OHOS Conan environment instead exposes the target compiler through
`tools.build:compiler_executables` and may reject writes to `/tmp` or to parts
of user storage. In particular, `tempfile.mkdtemp()` inherits a worker's
`TMPDIR`; on one worker that resolved to `/storage/Users/.../.cache/tmp`, where
Phase 1 was executable but Phase 2 file operations failed with
`ios_base::failure: Operation not permitted`. A later worker root under
`/data/storage/el2/base/cache` passed basic create/write/rename checks but
still failed when build2 replaced its existing executable target, reporting
`failed to update .../build2/b/exe{b.}`. The probe therefore has to test
replacement-over-existing (including execute mode), and `/data/local/tmp` is
preferred before the app cache for the next candidate. The process can also inherit
`HOME=/storage/Users/currentUser`, so moving only the source tree still leaves
build2 configuration and lock files on restricted storage. In build systems with typed test
targets, a `*.testscript` source path is not necessarily the runnable target;
directory buildfiles may declare `testscript{stem}` and load `common.testscript`
as a harness. These are separate boundaries: binding compiler, selecting and
probing a permitted OHOS work root, target syntax, and inventory accounting is
required before a full test claim. The OHOS SDK adds a separate runtime
boundary: its `clang++` wrapper can invoke `llvm/bin/lld`, while
`libxml2.so.16` lives beside it under `llvm/lib`; without that directory in
`LD_LIBRARY_PATH`, the linker fails after compilation with unresolved `xml*`
relocations.

## Reusable repair

1. Resolve the target C++ compiler from Conan conf and require an absolute path;
   do not depend on `${CXX}`, `${CC}`, or a host `PATH` entry.
2. Keep a vendored dependency source tree inside Conan's source folder and
   bind it explicitly to the bootstrap command.
3. On restricted targets, try known task-owned application-cache parents before
   inheriting `TMPDIR`; for each candidate, require create, write, rename,
   delete, permission-change, file-lock, and nested-directory probes before
   copying the source tree. Export a task-owned temporary directory below the
   selected root before the first compiler invocation. Bind `HOME`, XDG cache
   paths, `TMP`, and `TEMP` to that same root so child tools cannot fall back to
   restricted user storage.
4. Run the target version probe and consumer test as separate terminal checks,
   and record package revision, package ID, PREV, binary bytes, and hashes.
5. For build2-style suites, derive the runnable target IDs from each directory
   buildfile, invoke the official root runner (`b/b config.bin.lib=static -s
   test`), and keep source-file discovery, runnable targets, common harnesses,
   and executed terminals as separate fields. Do not shrink the denominator to
   hide helper files or pass raw paths that resolve to `file{...}` targets.
6. If a later self-rebuild encounters a permission error, keep that failure in
   the immutable log and publish only phases whose executable, consumer test,
   and complete upstream test terminal have authoritative PASS results.
7. If the target reaches a generic `failed to update` terminal, enable the
   bootstrap runner's verbose (`-V`) mode in the next candidate so the nested
   compiler/linker failure is recorded before choosing another functional fix.
8. For SDK wrappers whose helper binaries have sibling shared libraries, derive
   the sibling `llvm/lib` from the resolved compiler path and known SDK layout,
   prepend it to `LD_LIBRARY_PATH`, and record the bound directory.
9. When a bootstrap project's later phase includes headers from a vendored
   dependency, inspect that dependency's exported build configuration instead
   of guessing an include directory. In build2 0.18.0,
   `libbuild2/cc/pkgconfig.hxx` includes `libpkg-config/pkg-config.h`, while
   `libbutl/build/export.build` is the authoritative import entry. Pass
   `config.import.libbutl=<copied-libbutl-root>` to the Phase 2 driver. CI
   #37895 showed that omitting this import fails before the complete suite, so
   it is a configuration defect to repair rather than a missing test entry.
10. CI may clone the current target `main` and then apply a historical PR diff.
    If `main` has since gained tracked root marker files that the whitelist does
    not allow, the package PR can fail before its own gates even though its
    source tree is clean. Merge the current `main` into the feature branch and
    explicitly delete only the known marker files so the deletion is present in
    the next PR diff; do not broaden the whitelist or hide unrelated files.
11. A vendored dependency can be present in the source tree while its exported
    build configuration still refers to a separately published subproject. In
    build2 0.18.0, the libbutl release archive contains dangling links under
    `libbutl-pkg-config/libpkg-config/` to `upstream/libpkg-config`, so merely
    copying libbutl and setting `config.import.libbutl` leaves
    `libpkg-config/pkg-config.h` unavailable. Inspect the export graph, download
    the authoritative subproject archive in `source()`, bind its digest, and
    only then rerun the full target build and upstream suite. Worker-installed
    headers or a WSL-only copy are not valid substitutes for the recipe closure.
12. Conan's `basic_layout` can put `self.build_folder` below
    `self.source_folder`; copying the entire source folder into a task work root
    then imports generated `build-release/conan` metadata. A root-level recursive
    test operation may descend into that directory and fail with
    `no explicit target for build-release/:dir{conan/}`, falsely making every
    discovered test appear failed. Compute the build-folder path relative to the
    source root and exclude only that root entry during `copytree`; preserve the
    upstream source tree and keep the full typed-target inventory. This boundary
    is required before interpreting an upstream test failure as a platform defect.
13. When a CI worker cannot reach an upstream archive host, first verify an
    authoritative mirror by downloading the exact tag archive and comparing its
    byte count and SHA-256 with the pinned source. If the digest is identical,
    switching `conandata.yml` to that official mirror removes the network
    dependency without changing the source closure or the upstream test
    denominator. A successful mirror download is only a source-stage fix; the
    next CI run must still execute the complete build and test terminals.
14. File-operation probes alone do not prove that child shells can resolve the
    selected working directory on a sandboxed target. Before launching a
    testscript suite, run the resolved `bash` or `sh` with `cwd=<candidate>` and
    require a zero exit code and empty stderr. Reject a candidate that emits
    `shell-init: error retrieving current directory` and fail closed on OHOS
    instead of falling back to a Conan `/storage` path that makes upstream tests
    false-fail.
15. If every permitted test root remains under a filesystem where Bash performs
    a failing startup `getcwd()`, moving the tree between sibling paths is not a
    functional fix. Preserve the upstream files and process arguments, put a
    task-private `bash` launcher first in the test process `PATH`, obtain the
    actual cwd from `/proc/self/cwd` without trusting inherited `PWD`, export
    that exact path as the child `PWD`, and execute the real Bash with the
    original cwd and arguments. Require a
    pre-suite probe with exact cwd, empty stderr and zero exit; hash every
    upstream test input before and after the run so the launcher cannot mask a
    test rewrite.
16. A target build can reach the official tests and still fail when an upstream
    runtime backend calls `dlopen()` for a fixed SONAME that the target OS does
    not ship. First prove a published target provider exists with
    `--build=never`, then require a static PIC archive from that exact
    RREV/Package ID/PREV. Use the target C compiler to materialize a task-private
    shared ELF with the exact SONAME (for example, `libuuid.so.1`) and make its
    directory part of both the immediate test environment and the packaged
    Conan run/build environments. Before an expensive bootstrap, start a new
    target process that loads the library by SONAME rather than absolute path,
    calls the real ABI, and validates semantic output. This proves loader search,
    target acceptance and the required symbols together; `readelf`, a successful
    link, or an in-process absolute-path load alone does not. Do not patch the
    upstream runtime to return a synthetic value, remove the affected test, or
    count only the targets that ran before the loader failure.
17. A target runtime probe must not introduce an unrelated interpreter extension
    closure. If the library under test is native, compile a minimal target-native
    executable with the same target compiler, link it against the generated
    shared library, and require the exact SONAME in `DT_NEEDED`. Start that
    executable as a new process with the production loader path and make it call
    the real ABI. A Python `ctypes` probe is not equivalent when `_ctypes` itself
    requires an unavailable library such as `libffi.so.8`; that failure says
    nothing about the native library being probed. Local cross-link inspection
    may prove the ELF/SONAME edge, but only the target run proves loader acceptance
    and runtime semantics.
18. An upstream suite can require a GNU command option that a target system applet
    does not implement even when the command name exists. Inventory the unchanged
    upstream external-command call sites and keep the original runner. For the
    missing semantic surface only, compile a task-private target helper and put it
    first in the test process `PATH`; delegate ordinary calls to the real platform
    command resolved before the PATH change. Require exact target probes for both
    the added option and the passthrough path before starting the full suite. Do
    not edit the testscript, remove the failing case, or count only the targets
    that happened to finish before the missing option was reached.

## Applicability and safety boundary

This applies to custom Make/bootstrap recipes on restricted target storage and
to build systems whose test files are mapped to typed runner targets, not only
build2. It also applies when a CI whitelist is evaluated against a moving main branch:
root files introduced by main are not package-test evidence and must be represented in
the candidate diff before deletion. It does not permit guessing tool paths, accepting a host build as target
evidence, suppressing a filesystem failure, or claiming full self-hosting from
a Phase 1 bootstrap. A successful basic filesystem probe or a linker library-path
binding is only a prerequisite gate, not proof that target execution or all
upstream tests pass; any expanded phase or target-platform claim requires a new
writable-storage validation and a new immutable candidate/evidence binding.
The stable-cwd launcher is limited to Bash startup on roots already selected by
the recipe's filesystem probes; it must not redirect or filter stderr, alter
test inputs, relax expected output, or convert a nonzero runner into a pass.
Likewise, a private SONAME may only be produced from a hash-bound published
target provider whose static archive is PIC, then verified by a fresh target
process and packaged without modifying shared caches or system directories. A
native probe should keep its dependency closure to the target compiler, loader,
and library under test; interpreter modules are permitted only when their own
runtime closure is independently present and bound. A task-private command
helper is allowed only after a concrete target option failure, must preserve
ordinary command behavior through a tested passthrough, and cannot modify the
upstream test bytes, expected outputs, runner status, or denominator.
