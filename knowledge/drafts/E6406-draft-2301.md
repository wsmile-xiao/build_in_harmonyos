# E6406 - POSIX path conversion must canonicalize case through directory enumeration

## Symptom

The upstream `PathConversion.SimpleTest` exercises a Windows-style path,
`tests\\files\\PATHS\\EMPTY.TXT`, while the fixture is stored as
`tests/files/paths/empty.txt`. On a case-sensitive POSIX filesystem the
resolver falls through to `glob()` and returns the stored spelling. On a
case-insensitive POSIX mount, however, the same test receives
`tests/files/PATHS/EMPTY.TXT`: the normalized lookup succeeds and the resolver
returns the caller's spelling before it can enumerate directory entries.

The failure is significant beyond the assertion. A path that is merely
reachable on the current mount can become unusable after the package or its
test data is relocated to a case-sensitive target. It also makes the result
dependent on the spelling chosen by a caller rather than on the filesystem's
directory entries.

## Root Cause

The POSIX API contract accepts both native and Windows separators and promises
case-preserving resolution for case-insensitive input. `path_exists()` is a
reachability predicate; it does not expose whether each component matched with
the exact stored case. Returning after `path_exists(posix_path)` therefore
collapses two distinct states:

1. the requested spelling is an exact directory entry; and
2. the mount accepted a case-variant lookup and hid the stored spelling.

The existing glob resolver already provides the required directory-entry
projection and deterministic ordering. The early return prevented that logic
from running on compatibility mounts. Textual case folding is not an
equivalent repair: it is locale-sensitive, cannot recover mixed-case names,
and cannot resolve per-component ambiguity.

## Fix

1. Normalize backslashes to POSIX separators before constructing the resolver
   pattern.
2. Remove the POSIX early returns based on `path_exists()` so that both exact
   and case-variant spellings are resolved through `glob()`.
3. Keep `GLOB_TILDE`, the existing escaping rules, and the documented
   alphabetic first-match behavior unchanged.
4. Preserve the separate Windows implementation, whose contract explicitly
   returns an existing path unchanged.
5. Treat an absent match or a glob error as an empty result; do not synthesize
   a path or silently fall back to a foreign directory.

## Validation

The production CI failure was Buildbot global build `49513`, builder-local
`43329`, step `conan-build-test`, with thirteen tests passing and the single
`PathConversion.SimpleTest` assertion failing. Source acquisition, the
portability patch chain, Meson configuration, compilation, and linking had
already completed. The successor patch must be replayed with `patch_ng` and
the focused upstream test must be run on a mount exhibiting the failing
case-insensitive lookup. The complete replacement CI build is the authoritative
cross-environment validation; its `ci_revision` must equal the new PR HEAD.

The new `0021-fs-utils-case-canonicalization.patch` parses successfully with
`patch_ng 1.19.1` and applies with `strip=0`, `fuzz=False` to the previously
validated production patch-chain snapshot. The resulting resolver contains no
`path_exists()` shortcut before `glob()` and passes the exact source readback
check. This local replay validates patch integrity and source identity; it does
not replace the authoritative replacement Buildbot run.

## Applicability and Safety Boundary

This pattern applies to Unix-like implementations that translate foreign path
syntax and promise case-preserving lookup. It is useful for HMDFS, network
mounts, compatibility layers, and test runners whose lookup case policy can
differ from the host's default. It does not authorize changing fixture names,
disabling the upstream assertion, globally lower-casing user input, or adding a
platform-specific system call without an explicit contract. Windows behavior,
symlink policy, permissions, and package transfer remain separate concerns.
The canonical result must be derived from the same filesystem that will run the
consumer, and CI evidence must remain bound to the exact candidate revision.
