# E321: conan patch 默认 strip=0，refresh-patch a/b 前缀补丁需显式 strip:1

> **Contributor**: 6290 | **Status**: Draft | **Updated**: 2026-08-28
> **Severity**: 3 (blocking) | **Category**: conan / patch / packaging

## 错误特征

refresh-patch 生成的补丁（Git 风格 `a/xxx` `b/xxx` 前缀）在 conan 的
`apply_conandata_patches()` 应用时报错：

```text
ERROR: ekg2/0.3.1@ohpcd/stable: Error in build() method
  apply_conandata_patches(self)
  ConanException: Failed to apply patch: .../patches/0001-Makefile.am.patch
  source/target file does not exist
```

或 export 阶段：

```text
ConanException: Patch file does not exist: '.../patches/0001-xxx.patch'
```

错误信息指向"文件不存在"，不指向 strip 参数问题，容易误导排查方向。

## 触发条件

- 构建系统: 任意（patch 应用阶段）
- 阶段: export_sources / build（apply_conandata_patches）
- 平台: 所有（conan 通用行为）

## 根因分析

1. `refresh-patch --auto` 生成的是 **Git 风格补丁**：路径带 `a/xxx` / `b/xxx` 前缀，
   应用时需要 `-p1`（strip=1）剥离前缀。
2. conan 的 `apply_conandata_patches()` 调用底层 `patch()` 时**默认 `strip=0`**
   （不剥离前缀），`patch_ng` 按 `a/xxx` 找文件自然不存在。
3. 错误文案 "source/target file does not exist" 未提示 strip 问题，新手容易
   误判为补丁路径错误或文件缺失。

## 解决方案

在 conandata.yml 的每个 patch 条目显式加 `strip: 1`：

```yaml
patches:
  - patch_file: "patches/0001-Makefile.am.patch"
    patch_description: "Remove po/ from SUBDIRS"
    patch_type: "platform"
    strip: 1
```

`strip` 作为 kwargs 透传给 conan `patch()`（`patch(strip=1, ...)`），
`patch_ng` 按 -p1 剥离 `a/` `b/` 前缀后正常应用。

## 验证

```bash
conan create archives/e/ekg2/0.3.1 \
  -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64 \
  --build=missing --user=ohpcd --channel=stable
# → 所有 patch 应用成功，无 source/target file does not exist
```
