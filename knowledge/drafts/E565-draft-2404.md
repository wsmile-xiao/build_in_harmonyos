# E565（草稿）— qtbase 6.11 QCOMPARE 严格化：QString 与自定义 helper 的双向 operator== 重载

> 状态：pending-editor-review（拟编号 E565，最终由主编确认）
> 实证：kio 6.26.0 PR #9560，CI 构建 #44355
> 编号迁移：原 E543 因与既有草稿冲突改为 E565

## 错误特征

上游 Qt/KDE 测试源码在 qtbase 6.11 + cppstd=17（OHOS ohos-aarch64 profile）下编译失败：

```
QtTest/qtestcase.h:689:38: error: invalid operands to binary expression
      ('const QString' and 'const CaseInsensitiveStringCompareHelper')
            return compare_helper(t1 == t2, "Compared values are not the same",
                                  ~~ ^  ~~
autotests/kfileitemtest.cpp:73:5: note: in instantiation of function template
      specialization 'QTest::qCompare<QString, CaseInsensitiveStringCompareHelper>'
```

候选函数不命中：

```
QtCore/qstring.h:905:5: note: candidate function not viable: no known conversion
      from 'const CaseInsensitiveStringCompareHelper' to 'const QString' for 2nd argument
    Q_DECLARE_STRONGLY_ORDERED(QString)
```

## 根因

- `QCOMPARE(actual, expected)` 宏展开为 `QTest::qCompare<QString, Helper>(actual, expected, ...)`，模板实例化先推导 `t1 == t2` 二元表达式（actual 左、expected 右）。
- qtbase 6.11 中 QString 的比较运算符集合（`Q_DECLARE_STRONGLY_ORDERED` 展开）只声明 `QString == QStringView/QLatin1String/...` 方向，**不隐式转换接收自定义 helper**。
- helper 类的成员 `operator==`（`helper == QStringView`）在**反向操作数顺序**（QString 在左）下不参与重载决议——单加一个 `helper == QString` 成员重载不够，仍编译失败。
- OHOS profile pins `cppstd=17`，无 C++20 的宽松推导，问题必现。

## 解法（双向重载补丁）

1. helper 结构体内补三向成员重载：`operator==(QStringView)`、`operator==(const QString&)`、`operator==(QLatin1String)`；
2. **同时**补反向自由函数 `inline bool operator==(const QString&, const Helper&)`——qCompare 推导 `t1 == t2` 时 QString 在左侧；
3. 以 autotests 补丁随 conandata.yml 声明，仅 OHOS 构建 apply。

完整代码块见 .kv 的 solution 字段。

## 降级方案

- 测试不关键：autotests/CMakeLists.txt 补丁移除该测试 target；
- 或 `_run_upstream_tests` 里 `ctest -E` 排除；
- 均优先级低于双向重载（后者保留上游断言语义）。

## 红线

- 禁止改断言期望值本身（只加运算符重载，不改比较语义）；
- 补丁只在 OHOS 构建 apply（`if self.settings.os == "OHOS"`），不影响其他平台。

## 验证

- kio 6.26.0：补丁 0006 应用后 kfileitemtest 编译通过并执行（53 passed / 22 failed——失败项为沙箱权限/mime 数据库环境差异，与本条编译问题无关）；
- CI 构建 #44355（PR #9560）全绿。
