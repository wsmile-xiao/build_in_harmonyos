# E2183: Gate allocator tests by target runtime capability

## Symptom

The allocator library and its test binaries compile and link on a Linux-like
target, but optional malloc proxy tests terminate with `SIGTRAP` and the
memory-compliance test fails immediately. Other allocator tests pass.

## Root cause

The failing tests require runtime contracts that are not implied by the
`__linux__` compile macro: glibc-style allocator interposition and enforceable
`RLIMIT_AS` address-space limits. A non-glibc OHOS runtime can accept the same
source and linker inputs while rejecting the interposition path or ignoring
the limit, so the test binary fails only when executed.

## Fix

1. Keep `TBB_TEST=ON` and identify the exact optional component or CTest
   registration that requires the missing runtime capability.
2. Disable only the malloc proxy component when allocator interposition is not
   supported; keep the core allocator and ordinary consumers enabled.
3. Omit only the address-space compliance registration when the target cannot
   enforce the required limit.
4. Record the named exclusions and reasons, then run the complete remaining
   target CTest inventory. Never convert a trapped or unexecuted test into a
   pass marker.

## Validation

Buildbot #41540 on PR #8474, bound to revision
`86d839949a99972094c6f0cde46510f041e41689`, passed compilation and reached all
141 CTest executions. It failed only the allocator compliance test and four
malloc proxy tests with the target runtime symptoms above. The successor
recipe sets `TBBMALLOC_PROXY_BUILD=OFF` for OHOS and the patch omits the
`test_malloc_compliance` registration while preserving the remaining tests.

## Applicability and safety boundaries

Use this pattern only when the target capability is proven absent by a
reproducible runtime result or a precise capability contract. Do not disable
the entire upstream suite, skip core allocator tests, or treat a successful
cross-build as runtime evidence. If the target later provides the capability,
the optional component and its tests must be re-enabled.
