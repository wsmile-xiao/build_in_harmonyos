# E550（草稿）：Qt 模块宿主工具签名 + 兄弟模块 .pri 合并 + QTest offscreen 组合适配

> 状态：pending-editor-review（草稿）｜来源：qt5-qtscxml 5.15.2 适配（PR !14820，任务卡 #14908，j669539）
> 拟提升编号：E550（最终由主编确认）

## 一句话

qmake addon 模块在 OHOS 构建宿主机上的三类平台差异组合解法：**宿主侧 code generator 工具（qscxmlc）必须在构建期首次运行前 binary-sign-tool 自签**、**兄弟模块 mkspecs/modules/*.pri 合并进可写 Qt prefix**、**纯逻辑 QTest 套件 QT_QPA_PLATFORM=offscreen 运行 + 确定性 LD_LIBRARY_PATH**。

## 错误特征（error_signature）

- `Operation not permitted`（执行 qscxmlc 时）
- `qscxmlc: cannot execute` / tst_compiled 无法生成 STATECHARTS 产物
- `qtHaveModule(qml)` 为假 → `src/imports` 与相关测试**静默跳过**（无任何报错，产物直接缺失）
- 测试子进程报 `Error relocating ... symbol not found`（宿主注入的 libc++_shared.so 副本遮蔽系统版本）

## 根因（root_cause）

OHOS 构建宿主环境对**一切本机 ELF 可执行文件**强制签名校验——不止目标架构产物。
Qt addon 模块构建期需要运行宿主侧 code generator（qtscxml 的 `tools/qscxmlc`，
host_build）把 `.scxml` STATECHARTS 编译成 C++（tst_compiled 经
QMAKE_EXTRA_COMPILERS 调用）。该工具刚被 make 产出时未签名，OHOS 加载器直接
拒绝执行，构建/测试链断裂。

与既有条目的区别：
- **E077**：包内产物 patchelf/strip 破坏签名后 **post-install 重签**
- **E083**：Java JNI 库**运行时**签名
- **E538**：pangomm 包内产物打包阶段签名
- **本条（E550）**：**构建流水线内部的中间工具必须在使用前预签**——时间点在
  `build()` 而非 `package()`；moc/rcc 已随 qtbase 处理，一切 "Qt 模块自带 host
  code generator" 的 addon（qscxmlc/qlalr/qdoc 类）都会踩同一坑

第二支柱：qmake 的 `qtHaveModule(qml)` 探测依赖 mkspecs/modules/ 下的 `.pri`
模块档案。qt5-qtdeclarative 的 `.pri` 不在可写 prefix 里时该探测为假，
`src/imports`（QML 插件）与相关测试**静默跳过**——没有报错，只有产物缺失，
极易误判为"上游不含该部分"。

第三支柱：纯逻辑 QTest 套件（无 GUI）在无显示环境运行须设
`QT_QPA_PLATFORM=offscreen`；且测试子进程**不得继承**宿主注入的
LD_LIBRARY_PATH（不兼容 libc++_shared.so 副本会遮蔽系统版本）。

## 解法（solution）

```python
# conanfile.py —— 宿主工具签名（make 后、首次调用前）
def _sign_binary(self, path):
    if self.settings.os != "OHOS" or not os.path.isfile(path):
        return False
    signer = (os.environ.get("OHOS_SIGN_TOOL", "")
              or shutil.which("binary-sign-tool")
              or "/data/service/hnp/bin/binary-sign-tool")
    signed = f"{path}.signed"
    self.run(f'"{signer}" sign -inFile "{path}" '
             f'-outFile "{signed}" -selfSign 1', quiet=True)
    os.replace(signed, path)
    os.chmod(path, 0o755)
    return True

# build(): make 完成后立即签名 qscxmlc，再跑 STATECHARTS 相关测试
# package(): 对包内 bin/ 全部 ELF 统一自签（常规产物签名，与 E077 汇流）

# .pri 合并（_build_qt_tree 内）：
#   qt_root = <可写 prefix>（symlink qtbase mkspecs）
#   for pri in (qtdecl_pkg/mkspecs/modules/*.pri):
#       合并写入 qt_root/mkspecs/modules/，.pri 内 prefix 路径改写到可写 prefix

# 测试运行环境：
#   QT_QPA_PLATFORM=offscreen
#   LD_LIBRARY_PATH = 源树 lib + 依赖包 lib + toolchain lib（不继承父级）
```

## 降级方案（fallback）

- 非 OHOS 宿主：签名按平台跳过（warning 提示）
- 签名器不可得：只跑纯逻辑套件（parser/statemachine/statemachineinfo/
  dynamicmetaobject），tst_compiled 内联豁免并注明"宿主工具签名不可用"
- .pri 合并无降级路径——缺它 qml 子树整体静默消失，必须合并

## 验证（verify_builds）

- PR !14820（qt5-qtscxml 5.15.2，本地 conan create 全绿）：
  - 五套件真跑 80/80（parser 42 / statemachine 20 / statemachineinfo 3 /
    dynamicmetaobject 4 / **compiled 11**——STATECHARTS 由已签名 qscxmlc 真实编译）
  - test_package 冒烟 1/1（QScxmlStateMachine::fromData 解析+驱动至 final 态）
  - scion 套件 226 例受 OHOS JIT 沙箱限制豁免（与 qt5-qtdeclarative 先例同根因，非本条范围）

## 红线（forbid）

1. **禁止把 host 工具签名推迟到 package() 之后**——qscxmlc 在 build() 阶段就要
   运行（编译 STATECHARTS），推迟签名会让 tst_compiled 直接无法构建，被误判库缺陷
2. **禁止测试子进程继承宿主注入的 LD_LIBRARY_PATH**——不兼容 libc++_shared.so
   副本会遮蔽系统版本，导致 "Error relocating ... symbol not found"

## 推广价值

一切 "Qt 模块自带 host code generator 工具" 的适配场景（qscxmlc/qlalr/qdoc/uic
类，moc 之外的 addon 工具）；一切依赖兄弟 Qt 模块 .pri 启用子树的 qmake 工程；
一切纯逻辑 QTest 套件的无头运行。qt5 系后续模块（qtserialbus/qtcharts 等带
工具或 qml 插件的 addon）可直接复用。
