# E550 — C/C++ 库测试夹具目录内嵌 vendored Go 工具触发 lang-preflight 误判 mixed(go)

## 错误特征
```
任务标记 cpp，实测源码为 mixed（go），无法按 cpp 适配
detected_language: mixed
language_evidence: build_system=go / manifest=go.mod 存在 / 源文件 43 个（c:31, go:9, perl:3, bash:1）
```

## 触发条件
- 构建系统: autotools / cmake（C 库）
- 阶段: preflight（R47 语言预检）

## 根因分析
`lang_detect.py` 的源码统计按全树扩展名计数，未排除测试夹具目录中的 vendored 工具。
libmaxminddb 1.13.3 的 `t/maxmind-db/` 是官方附带、用于生成测试数据库的 Go 工具
（9 个 .go + go.mod），被误计为主体语言 → 与任务语言 cpp 判 mixed → 自动写
`env_unsupported` 终态。按 R47 边界规则「辅助脚本/夹具不算主体」，库主体
（src/include 3.c + 3.h，autotools）是纯 C，属 c↔cpp 兼容族，应正常适配。

## 推荐方案
遇 lang-preflight 报 detected=mixed 且 go 文件全部位于测试夹具目录时：
①核对库主体（src/include/bin）语言与构建系统；②确认 go.mod 只属于夹具工具；
③人工复核后按任务语言继续适配，保留预检输出为证据；
④终态用 `result --force` 覆盖误写的 env_unsupported。
不改框架、不删夹具工具。

## 验证
修复后 configure/make/make check 全通过；终态 result --force 覆盖成功（本任务实测）。

## 适用边界
一切 C/C++ 主体、测试目录附带 vendored Go/Python/Ruby 等夹具生成工具的库。
不适用于 go 文件确为库主体实现（非测试夹具）的库。
