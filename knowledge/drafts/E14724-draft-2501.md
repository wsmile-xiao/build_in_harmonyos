# E14724 draft: same-named release files can turn Make command targets into no-ops

Legacy Makefiles sometimes leave `install` as an ordinary target. If the release source also contains a file called `install`, Make may decide that target is already up to date and return success without installing anything. A successful command exit is not proof that the Conan package contains the promised files.

For Rplay 3.3.2, the authoritative Debian source has a top-level `install` file and `Makefile.in` has an `install:` rule without `.PHONY`. In the temporary Conan source copy, match exactly one rule, insert `.PHONY: install`, execute `make install -j1`, and require both `librplay` and `rplay.h` to exist in the package. Target W3 `w3-rplay-20261004T072553Z` passed, including a real installed-library network PING consumer (1/1, four assertions). Raw Conan log SHA-256: `23ba69c28c561ac384a7d1ba923789336b3041e019741819c3b8ec96c68ad061`.

Reusable check: when an installation target exits zero but the package is empty, inspect the Make target's phony declaration and names of ordinary files in the release before changing compiler or install prefix. Apply a narrowly anchored `.PHONY` correction only to an actual command target, and verify concrete package files afterward. Do not mark genuine generated-file targets phony indiscriminately or claim test coverage from a packaging check. The upstream release contains no registered test suite; its 0/0 is not applicable, while the Conan consumer is an added test.
