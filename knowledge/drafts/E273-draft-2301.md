# E273 - Four-Way Staged-Tree Binding before Device Access

## Symptom

A one-shot device wrapper atomically claims a free endpoint, but the inner
controller immediately fails `HEAD/tree drift` before evidence creation or
SSH. The freeze and live `git write-tree` are current while the allocation
record contains a predecessor tree.

## Root Cause

The outer wrapper and inner controller each owned a copied tree constant. A
successor generator updated the product freeze but did not rebind those two
independent constants. Earlier offline fixtures used the same stale tree, so
they proved internal consistency with the predecessor rather than consistency
with the final candidate.

## Recommended Fix

Treat the staged tree as one authority value. Before claim, require byte-exact
agreement among the live `git write-tree`, final authority, controller
constant, and wrapper-generated allocation object. Run the real production
controller through an offline complete transaction using an allocation built
by the real wrapper, then bind both script hashes into final W4.

## Validation

ITK r30 failed locally with zero SSH, zero transfer and zero launch, then
released only its exact owner record. The create-new regression corrected both
constants to tree `b430046f8eddc714a40495e8faa17b8bfae051c0`; the target contract
passed 12/12 and the complete offline claim/transaction/release matrix passed
6/6, including explicit controller-tree and wrapper-allocation-tree checks.

## Deduplication

Exact knowledge searches found entries about stale allocation lifecycle and
freeze cross-binding, but none required this wrapper/controller/authority/live
tree four-way equality before a one-shot claim.

## Safety Boundary

Do not retry the consumed run, weaken `HEAD/tree drift`, or edit the claimed
allocation evidence. Preserve the failed attempt and create a new run identity
with a fresh freeze and independent W4.
