# E351 — OHOS Autotools 交叉工具链完整接线：PkgConfigDeps+AutotoolsDeps + relocatable linker view + .pc 相对化

## 错误特征

X11 家族 autotools 库在 OHOS worker 上构建时，若只给 `--host=aarch64-linux-ohos`
而不做完整工具链接线，configure 找不到依赖的 pkg-config 模块（`Package 'x11' not
found`）、链接期找不到 `-l` 库、或产物 `.pc`/`.la` 携带绝对路径导致消费者不可重定位。
libXcursor 1.2.3 复用 libxrender/0.9.12 实证的完整交叉配方后一次通过。

## 触发条件

- 构建系统: Autotools，依赖多个 pkg-config 模块（x11/xext/xfixes/xorgproto 等）。
- 需要 OHOS 交叉三元组（build≠host，见 E350）。
- 依赖库已在同轨 cmd-pkgs 发布（libx11/6.4.0、libxext/6.4.0、xorgproto/2025.1）。

## 根因分析

- autotools 的 configure 靠 pkg-config 找依赖（`PKG_CHECK_MODULES`），靠
  `AC_CHECK_LIB` 找符号。只有同时给对 PKG_CONFIG_PATH、`--host`、工具链 flags，
  才能把"依赖头文件 + 依赖库 + 交叉编译器"三者接上。
- Conan 的 AutotoolsDeps/PkgConfigDeps 生成的 env（.pc 路径、CPPFLAGS/LDFLAGS）
  默认指向 build 目录/包缓存的**绝对路径**。直接使用会让安装后的 `.pc` 携带绝对
  prefix，消费者（其他库的 configure/test_package）换机器/目录即不可重定位。
- libtool 生成的 `.la` 文件引用绝对路径与依赖清单，打包后污染下游链接。

## 解决方案

1. `generators = ["AutotoolsDeps", "PkgConfigDeps"]`：让 conan 生成交叉工具链 env
   与依赖 `.pc` 引用。
2. **build 目录私有 relocatable linker view**：把依赖的 include/lib 以可重定位视图
   挂到 build 目录下，链接器经此视图解析，避免包缓存绝对路径进入产物。
3. `--host=aarch64-linux-ohos`（build≠host）交叉 configure；交叉 configure 需经
   `/system/bin/sh` 执行，避免沙箱对脚本解释器的限制。
4. **.pc 相对化**：对生成/安装的 pkg-config 文件把绝对 prefix 改为 `pcfiledir`
   相对引用，保证包可重定位。
5. **移除 .la**：package 时删除 libtool `.la` 文件，避免绝对路径与依赖链泄漏。
6. `package_info`: `libs` 与 `.so` 文件名一致（`libXcursor.so.1` → `libs=["Xcursor"]`），
   `pkg_config_name` 与上游 `.pc` 名一致（`x11`/`xcursor` 等）。

验证：configure 日志各依赖模块 `found`；`readelf -d libXcursor.so.1 | grep NEEDED`
只含预期链接依赖；安装后 `.pc` 无绝对 build 路径；test_package 以 `find_package`
消费成功。

## 禁止策略

- 不省略 AutotoolsDeps/PkgConfigDeps（configure 将找不到依赖）。
- 不把包缓存绝对路径留在 `.pc`/`.la` 中（产物不可重定位，下游必挂）。
- 不省略 `--host` 进入原生模式（见 E350 works-check 陷阱）。
- 不用 `--build==--host` 跳过交叉判定。
