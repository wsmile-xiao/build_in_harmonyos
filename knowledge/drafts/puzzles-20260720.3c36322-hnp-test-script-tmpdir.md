## 错误特征

```
fuzzpuzz-setup 无法生成存档            # /tmp/fuzzsave 写入失败
ohos-save FAIL                        # /tmp/ohos_save 写入失败
（CI test_package 阶段，其余 38 项 PASS、12 项 FAIL 中含此 2 项）
```

症状：测试脚本把存档/中间产物写到 `/tmp`，HNP worker 上 `/tmp` 不可写 → 存档类测试
失败。本机 macOS 上 `/tmp` 可写，因此只有远程 worker 暴露该问题。

## 根因分析

HNP/HarmonyOS worker 的 `/tmp` 为只读或未挂载（沙箱/文件系统策略），shell 测试脚本
硬编码 `/tmp/fuzzsave`、`/tmp/ohos_save` 时 `open`/`mkdir` 失败。这是环境差异而非
软件缺陷——测试脚本必须以可写位置动态创建自己的工作目录。

## 解决方案

**主方案**: tmpdir-or-pwd-savedir-pattern

```sh
SAVEDIR="${TMPDIR:-$PWD}/puzzles-save-$$"
mkdir -p "$SAVEDIR"
trap 'rm -rf "$SAVEDIR"' EXIT
# 全部 /tmp 引用替换为 "$SAVEDIR"
```

要点：

- `TMPDIR`（conan/worker 通常注入）优先，无则回退 `$PWD`（worker 上可写）；
- `$$` 保证并发/多次运行不冲突；
- `trap ... EXIT` 清理，避免在 worker 留垃圾；
- 禁止兜底到 `/tmp`（`${TMPDIR:-/tmp}` 仍在 worker 不可写）。

## 回退方案

ci-injected-writable-dir：若 `TMPDIR` 与 `$PWD` 均不可写（极端环境），由 CI 注入
已确认可写目录环境变量，脚本优先读取：

```sh
WRITE_DIR="${CI_WRITABLE_DIR:-${TMPDIR:-$PWD}}"
```

## 禁止做法

| 做法 | 原因 | 后果 |
|---|---|---|
| 硬编码 `/tmp/xxx-save`、`mktemp -d /tmp` | HNP worker /tmp 不可写 | fuzzpuzz-setup/存档类测试 FAIL（#66276 实例） |
| `${TMPDIR:-/tmp}` 兜底 | TMPDIR 不可用时仍落 /tmp | 换环境仍红，修复不彻底 |
