# E7004: Keep consumer semantic checks active in Release

## Symptom

A Conan consumer test uses `assert(actual == expected)` and then prints a
success marker. In the default Release build, `NDEBUG` removes the assertion,
so an incorrect result can still be reported as PASS.

## Root cause

`assert` is a diagnostic facility rather than a release validation contract.
Cross-built `test_package` executables are commonly compiled with Release
flags, and the preprocessor removes the expression entirely when `NDEBUG` is
defined.

## Fix

Use an explicit condition that reports the mismatch and returns a non-zero
status before printing PASS. Keep the check in the consumer executable so the
same semantic validation runs in host and target configurations. If assertions
are kept for debugging, pair them with the explicit status check.

## Validation

Compile the consumer with Release/NDEBUG, verify that a deliberate mismatch
returns non-zero, and then run the real oneTBB consumer. The corrected
`test_onetbb.cpp` checks all 1000 `parallel_for` results explicitly and only
prints PASS after every check succeeds.

## Applicability and safety boundaries

This applies to package consumers and validation binaries whose result is used
as a CI or target-pass claim. It does not require removing useful debug
assertions, and it does not replace target runtime evidence with a host-only
test.
