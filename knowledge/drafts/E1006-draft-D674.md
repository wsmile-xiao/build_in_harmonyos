# E1006 — OHOS musl libc 缺 glibc/BSD 专属符号：逐个移植标准等价物

## 错误特征
编译/链接期出现（OHOS aarch64）：
- `implicit declaration of function 'rindex'`
- `implicit declaration of function 're_comp'` / `'re_exec'`
- `'versionsort' undeclared`（glibc scandir 比较器）
- `HZ undeclared` / `#error HZ`（sys/param.h 无 HZ）
- `undefined reference to 'qsort_r'`（链接期，头文件声明了但 sysroot libc 没有）

## 触发条件
- 平台: HarmonyOS PC (OHOS, aarch64, musl libc)
- 构建系统: 任意（C 源码用 glibc/BSD 扩展即触发）
- 阶段: compilation / linking

## 根因分析
OHOS 基于 **musl libc**，若干 glibc 下"默认存在"的符号缺失。pcp 7.1.5 实测 5 例：

| 符号 | glibc 行为 | musl/OHOS | 等价替换 | 实例（pcp 7.1.5） |
|------|-----------|-----------|---------|------------------|
| `rindex` | BSD 函数，可用 | 未声明 | `strrchr` | qa/src/multithread10.c |
| `re_comp`/`re_exec` | BSD regex（`_REGEX_RE_COMP` 下声明） | 无 | POSIX `regcomp`/`regexec`/`regfree`，保留 1/0/-1 语义 | linux_proc/config.c, lex.l |
| `versionsort` | glibc scandir 比较器 | 未声明 | `NULL`（顺序无意义）或自定义比较 | linux/proc_stat.c:114 |
| `HZ` | sys/param.h 提供 | sys/param.h 无 | `#ifndef HZ #define HZ 100` | linux_proc/proc_pid.c |
| `qsort_r` | 可用 | 头文件 `__linux__` 分支声明，但 sysroot libc.so 无 | 路由到 `sort_r_simple`（`!defined __GLIBC__` 条件） | libpcp3/src/sort_r.h |

**两个关键陷阱**：
1. **sysroot libc ≠ 设备 libc**：`pthread_cancel`、`qsort_r` 等设备 `/system/lib64/libc.so` 有，但 sysroot 链接用 libc.so 没有 → 链接期 `undefined reference`，运行期却可能 OK。链接错误优先走"可移植实现"，不要 `--allow-shlib-undefined` 掩盖。
2. **头文件多副本**：同一头文件源树里可能有多个副本（pcp：`src/external/sort_r.h` 与 `src/libpcp3/src/sort_r.h`）。只改一个，漏掉另一个 → 仍 `undefined reference`。

## 解决方案

### 推荐方案
逐个替换为标准 C/POSIX 等价物（见上表）。qsort_r 用 `!defined __GLIBC__` 条件判定（qsort_r 是 glibc 专属扩展，非 glibc libc 无此函数）路由到自包含 `sort_r_simple`，无需平台宏（R8 合规），勿依赖 `__linux__`。

### 禁止做法
- ❌ 用 `--allow-shlib-undefined` 掩盖 qsort_r/pthread_* 缺失（链接期缺陷）
- ❌ 只改一个头文件副本就认为完成（多副本全改）
- ❌ 空壳 stub 降级（R8：须有实质逻辑）

## 验证
```bash
grep -rn "rindex(\|re_comp(\|versionsort\|\bHZ\b\|qsort_r" \
  src/ --include='*.c' --include='*.h' \
  | grep -v strrchr | grep -v sort_r_simple
# 预期：0 行（除注释外无残留 glibc/BSD 专属符号）
```
