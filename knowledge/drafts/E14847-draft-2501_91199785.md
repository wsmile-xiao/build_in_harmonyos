# AF_UNIX 客户端库：用任务私有短路径验证真实握手

## 现象与根因

设备客户端库可能依赖未安装的守护进程，直接调用公开 API 只会得到“连接失败”，无法验证打包后的协议实现。为测试临时启动服务端时，又容易使用 `/tmp`（目标策略可能拒绝 pathname `bind`）或过长的 Conan 缓存绝对路径（`sockaddr_un.sun_path` 长度有限）。这些是测试端点选择问题，不等于应把 AF_UNIX 客户端改成空实现。

## 修复与验证

在 OHOS 应用私有的 `/data/storage/el2/base/files` 下用 `mkdtemp` 创建唯一短目录，以库支持的 `SPNAV_SOCKET` 覆盖其中的 socket 端点。不能只缩短相对路径：CI #80121 的消费者在 HMDFS 构建目录退出 1；可写目录并不必然支持 socket inode。测试线程真正 `bind`/`listen`/`accept`，验证客户端请求高位协议标识并回送版本 1，然后调用安装包的 `spnav_open`、`spnav_fd`、`spnav_protocol`、`spnav_close`，逐项检查返回值。监听 readiness、接收和发送等待均有 5 秒边界；所有已启动线程路径都 join，失败输出具体阶段，结束时仅删除自己的 socket 和目录。

修复候选真机事务 `libspnav-w3-20261010T102600Z` 完整 Conan 编译、安装包消费者握手 PASS（1/1），12 阶段回执通过并证明 runner/任务子进程退出。原始日志 SHA-256 `d32d2d8f6eebb6452ff72df0a5a5c83ec9896a7452a592095ee5bbda50954f4f`。上游发布包没有注册测试目标，故上游统计仍为 0/0。

## 范围和边界

这个结论仅证明指定应用私有 native 目录下的 pathname AF_UNIX 和打包客户端握手可用，不证明 `/tmp`、cache、任意 writable 目录或真实 6-DoF 硬件可用。E024/E341 记录了其他路径或沙箱中的 `bind` 拒绝；本次增量纠正“短相对路径即可”这一不充分条件，并补齐 peer 等待与失败清理。不能从单次失败推断所有 AF_UNIX 均不可用，也不能从本次通过推广为全局允许。路径选择失败必须 FAIL，不能跳过握手或改为不调用被测包的空壳。
