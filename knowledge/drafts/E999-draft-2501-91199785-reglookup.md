# SCons 工具缺位时，提取可审计的 SConstruct 构建图

reglookup 1.0.1+svn296 的上游 `SConstruct` 很短：共享/静态 `libregfi` 来自五个 `lib/*.c`，两条命令行程序分别只编译一个入口 `src/*.c`，`src/common.c` 被入口直接包含。它也硬编码了 `/usr/include`、`/usr/local/lib` 等搜索目录。HarmonyOS PC 目标机既没有 SCons，已发布的 Conan 仓库也没有 SCons 工具配方。

在这种小而完整的构建图中，可以逐项映射 `lib_src`、`SharedLibrary`、`Program`、`LIBS` 至 Conan 配方里的 clang/llvm-ar 调用，并从已发布 talloc 包的 `cpp_info` 获取头文件与库路径，而不是默认系统目录。保留共享库 SONAME、静态库、两条上游 CLI，安装后用 C 程序调用公开 `range_list` API，验证增加、计数、查找、空隙、重叠拒绝等 8 个断言。真机首轮事务 12/12 收据 `W3_PASS`。

边界非常重要：这不是通用的“绕过 SCons”建议。若 `SConstruct` 有实质代码生成、自定义 Builder、平台探测或复杂依赖图，应先封装 SCons 构建工具；不能用几条手写编译命令悄悄丢失功能。reglookup 的 DocBook 手册和 Python 绑定不随本次核心 C 产物交付，必须在 README/PR 明示。上游无注册测试和样本 hive，所以 `range_list` 消费者通过不等于真实 hive 解析端到端通过。

与既有 `DRAFT-10175-rmlint-2.10.3-scons-sandbox-bootstrap-env-inline` 的区别：那条是保留 SCons 并解决工具环境；本条仅适用于无可用 provider 且源码图可完整枚举的窄场景。
