# 发布包中没有注册测试时，校对素材后执行上游示例

preseq 3.2.0 的正式发布包包含 `configure`、`Makefile.am` 与 `data/`，但没有 Automake `TESTS` 或 `check_PROGRAMS`。因此 `make check` 的成功仅说明构建目标完成，不能写成“上游测试 100% 通过”。

README 提供 mapped、BAM、histogram、coverage 四类命令。直方图示例写的是 `SRR1301329_1M_read.txt`，包内实际文件是 `SRR1301329_1M_hist.txt`。只把调用路径校正为真实文件，保持样本原始字节和上游源码不变，然后逐项执行并检查产出的表格非空。Conan 安装后的消费者测试再单独读取同一正式样本，核对表头及数据行。

## 可复用判别

1. 以正式发布包为准枚举测试入口和素材；不要把 GitHub 自动生成的 tag 归档与 release asset 混用。
2. 若 `TESTS` / `check_PROGRAMS` 为空，记录上游注册测试 `0/0`，而不是 `100%`。
3. README 示例可以成为补充的上游功能证据，但必须逐条核对实际文件名、运行退出码和非空/结构化输出。
4. 把“示例 4/4”与“安装后消费者 1/1”分开统计，避免覆盖率口径混淆。

边界：如果上游已有测试只是被可选框架的 configure 守卫关闭，应先恢复原框架，不能拿 README 示例代替。此情况已有 `DRAFT-10251-libnfc-tools-1.8.0-autotools-test-framework-guard`；本条针对上游确实无注册用例、但发布包提供可运行样本的情形。

实证：HarmonyOS PC 单次冻结输入事务 `preseq-w3-20260930T160025Z`，四类示例 4/4、消费者 1/1、12/12 收据 `W3_PASS`；日志 SHA-256 `a6c6a29cc83dea3afcb29f9d3222f71ae1267f7261c4e193d675fd5cec4de6c8`。
