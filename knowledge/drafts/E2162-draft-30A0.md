# E2162 — 消费 clang/LLVM 包时 find_package(Clang) 被 CMakeDeps 生成的 ClangConfig 遮蔽

## 错误特征

```
Target "ccls" links to target "clangIndex" but the target was not found
No rule to make target clangIndex
```

上游 CMake 工程 `find_package(Clang REQUIRED)` 后链接 `clangIndex/clangFormat/clangTooling/...`，
但 CMake 只找到了 Conan CMakeDeps 生成的 `ClangConfig.cmake`（只定义 `clang::clang` 聚合目标），
找不到 clang 包自带的 LLVM `ClangConfig.cmake` 里的组件目标。

## 触发条件

- 依赖：`clang/22.1.8`（包内含 LLVM 官方 `lib/cmake/clang/ClangConfig.cmake` + `lib/cmake/llvm/LLVMConfig.cmake`，`cmake_find_mode=config`）
- 上游构建系统：CMake，且 CMakeLists 链接 clang 组件目标或依赖 `CLANG_LINK_CLANG_DYLIB`/`LLVM_LINK_LLVM_DYLIB`
- 根因：CMakeToolchain 生成的 toolchain 会把 CMakeDeps 输出目录 `PREPEND` 到 `CMAKE_PREFIX_PATH`，
  Conan 生成的 ClangConfig（无组件目标、无 `*_DYLIB` 变量）遮蔽包内自带 config

## 解决方案

1. **推荐**：conanfile `generate()` 只生成 `CMakeToolchain`（**不用 CMakeDeps**），显式设置
   ```python
   tc.variables["CMAKE_PREFIX_PATH"] = ";".join([
       self.dependencies["clang"].package_folder,
       self.dependencies["rapidjson"].package_folder])
   ```
   `find_package(Clang)` 即命中包内 `lib/cmake/clang/ClangConfig.cmake`（CMake 会匹配小写目录名）。
2. 若上游 CMakeLists 读 `RapidJSON_INCLUDE_DIRS` 而 rapidjson 包自带 config 只设 `RapidJSON_INCLUDE_DIR`，
   需额外 `tc.variables["RapidJSON_INCLUDE_DIRS"] = os.path.join(rapidjson_pkg, "include")`。
3. codeload 无扩展名 URL 需在 `get()` 显式传 `filename="<name>-<ver>.tar.gz"`（见 E276）。

## 验证

```bash
grep -E "Clang_DIR|LLVM_DIR" build/CMakeCache.txt   # 应指向 clang 包内 lib/cmake/clang + llvm
grep CLANG_LINK_CLANG_DYLIB build/CMakeCache.txt    # 应为 ON
```

## 实例

- ccls 0.20250306.8（鸿蒙 PC aarch64）：`archives/c/ccls/0.20250306.8/conanfile.py`
