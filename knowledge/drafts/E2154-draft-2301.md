# E2154 - Keep Git metadata on a native filesystem for HMDFS worktrees

## Symptom

An OpenHarmony device workflow needs a real Git repository because the official finish path calls Git-based patch and atomicity checks. Initializing the repository directly under an HMDFS `/storage` worktree first reports:

```text
fatal: detected dubious ownership in repository
```

After the exact worktree is added to `safe.directory`, the next initialization attempt can still fail:

```text
fatal: cannot stat '<worktree>/.git/branches'
```

The ownership exception is therefore necessary but not sufficient.

## Root Cause

`safe.directory` controls Git's repository ownership trust check. It does not change the filesystem operations used for refs, locks, objects, index files, maintenance, or metadata-directory discovery.

HMDFS is suitable for the transferred worktree bytes but may not implement the metadata behavior expected by the device Git build. Creating `.git` directly under `/storage` couples the official workflow to those unsupported semantics.

## Fix

Keep the two roles separate:

1. Copy the immutable project snapshot to the task-private HMDFS worktree.
2. Allocate a collision-checked, task-private Git metadata path on native `/data` storage.
3. Set only the exact worktree as `safe.directory` with process-local `GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_0`, and `GIT_CONFIG_VALUE_0` variables.
4. Run:

   ```sh
   git init --separate-git-dir="$native_git_dir" "$storage_worktree"
   ```

5. In the new repository, set `maintenance.auto=false` and `gc.auto=0` before staging and committing the frozen snapshot.
6. Bind both paths to the run identity and remove both only after terminal result readback.

`GIT_CONFIG_NOSYSTEM=1` can additionally isolate the wrapper from shared system configuration when every required setting is provided explicitly.

## Validation

The libxrender r26 first probe reproduced `cannot stat .../.git/branches` with RC128. A create-new separate-metadata probe then initialized and committed the same worktree at RC0; the initial variant exposed a maintenance warning. After setting `maintenance.auto=false` and `gc.auto=0`, the successor probe again returned RC0 with empty stderr and completed cleanup of both directories.

Official finish r27 used the same contract with its metadata under `/data/storage/el2/base/files`. Git initialization and snapshot commit passed, the unchanged official W3 substep generated the authentic `.ci-result.json`, and the one-shot launch remained `launch_count=1`.

## Safety Boundaries

- Do not use a global or wildcard `safe.directory`; trust only the exact task-private worktree for the current process.
- Do not manually create `.git/branches` and continue. That does not validate refs, locks, objects, index, or maintenance semantics.
- Preflight both paths for absence and bind them to a unique run identity.
- Preserve a failed one-shot attempt and create a successor; do not rewrite or retry a consumed launch.
- Separate Git placement fixes prelaunch filesystem compatibility only. It does not turn later official finish failures into aggregate success.
