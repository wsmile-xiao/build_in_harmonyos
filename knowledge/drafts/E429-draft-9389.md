# E429 — X11 家族 ohpcd 制品仓双命名：libx11/1.8.x 与 6.x 组混用触发 conan graph 版本冲突

## 错误特征

`conan create` / `conan graph info` 在**解析依赖图阶段**（尚未开始编译）直接失败：

```text
ERROR: Version conflict: Conflict between libx11/6.4.0 and libx11/1.8.13 in the graph.
Conflict originates from libxi/1.8.3

Run 'conan graph info ... --format=html > graph.html' and open 'graph.html' to inspect the conflict graphically.
```

典型链条：顶层 `requires("libx11/1.8.13")`，同时依赖 `libxi/1.8.3` 或 `libxtst/1.2.5`
（其 recipe 内部固定 `requires("libx11/6.4.0")`）。

## 触发条件

- 构建系统: conan（任意包管理器消费方；meson/cmake/autotools 均会踩到，因为冲突发生在配方图解析）
- 阶段: configuration（`conan graph info` / `conan create` 的依赖解析）

## 根因分析

ohpcd 制品仓里 X11 家族存在**两套并存的命名**：

| 命名风格 | ref 示例 | 含义 |
|----------|----------|------|
| 上游版本号命名（旧） | `libx11/1.8.13`、`libxi/1.8.3`、`libxtst/1.2.5` | 按上游 tarball 版本 |
| `.so` 主版本命名（新，同源组） | `libx11/6.4.0`、`libxi/6.1.0`、`libxtst/6.1.0`、`libxext/6.4.0`、`libxfixes/6.1.0` | 按 SONAME（如 `libX11.so.6.4.0` → `6.4.0`） |

6.x 组内部互相 pin：`libxi/6.1.0`、`libxtst/6.1.0`、`libxtst/1.2.5` 的 recipe 都固定
`self.requires("libx11/6.4.0")`（`libxtst/1.2.5` 还 pin `libxi/6.1.0`）。
因此只要顶层出现 `libx11/1.8.13`，conan 就同时看到 6.4.0 与 1.8.13 两个不同版本，
图解析阶段抛出 Version conflict。冲突**与代码无关**，纯粹是 ref 选择问题。

## 解决方案

### 推荐方案

把 X11 依赖整体对齐到 **6.x 同源组**（与 SONAME 命名一致），不要混用 1.8.x 旧 ref：

```python
# xclicker 1.5.1 验证通过的一组
self.requires("libx11/6.4.0", transitive_headers=True, transitive_libs=True)
self.requires("libxi/6.1.0",  transitive_headers=True, transitive_libs=True)
self.requires("libxtst/6.1.0", transitive_headers=True, transitive_libs=True)
```

选型前先确认组内每个 ref 都已发布（R35：用 `conan download`，不要用 `conan list` 判 binary）：

```bash
for p in libx11/6.4.0 libxi/6.1.0 libxtst/6.1.0; do conan download "$p" -r=ohpcd --only-recipe; done
conan graph info <recipe_dir> -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
```

### 备选方案

只显式声明**确实直接使用其头文件**的 X11 包（例如需要 `<X11/Xlib.h>` 就声明 `libx11`），
其余交给 `libxi`/`libxtst` 传递解析到同一 6.x 组，避免任何版本 pin 冲突。

### 禁止做法

- ❌ 顶层声明 `libx11/1.8.x` 的同时又依赖 `libxi/6.1.0` / `libxtst/1.2.5` —— 必然触发图冲突，
  构建尚未开始即失败，浪费整轮 CI。
- ❌ 用 `--build=missing` 或本地缓存强行绕过图冲突（R36：不得绕过依赖解析）。

## 验证

```bash
conan graph info archives/x/xclicker/1.5.1 \
  -pr:h=ci/conan/profiles/ohos-aarch64 -pr:b=ci/conan/profiles/ohos-aarch64
# 期望：无 "Version conflict"；Requirements 中 libx11 只出现 6.4.0
```

实测（xclicker 1.5.1）：统一切换到 6.x 组后 `conan create` 一次通过，
`bin/xclicker` 的 `NEEDED` 正确包含 `libX11.so.6` / `libXi.so.6` / `libXtst.so.6`。
