# E6404（草稿）：SysV 多操作信号量迁移时保留跨进程状态与命名共享内存扩容握手

## 现象与根因

当 OHOS 应用沙箱以 `SIGSYS` 拦截 SysV `shmget`/`semget` 时，`errno` 回退无法运行。既有 E577 已给出 SysV 共享内存到 `shm_open`/`mmap`、简单信号量到 `sem_wait`/`sem_post` 的基础映射。不过一组 `semop` 若原本在同一事务内检查和变更多个计数器，逐个改为独立 POSIX semaphore 调用会破坏原子性；若共享段还支持运行期扩容，写端 `shm_unlink` 旧名字、重建新名字之间，读端可能收到通知却在 `shm_open` 上遇到瞬时 `ENOENT`，直接使用失败映射就会崩溃。

Shmdata 1.3.74 的私有 SysV 后端有两个计数器：待完成读者数和写者占用标志。写者等待读者数清零，提交新帧时增加预期读者数；读者完成和断线取消都会递减。该协议由跨进程 Writer/Follower 及动态扩容测试共同验证，不是可以用两次独立 `sem_wait` 无损替代的单计数器场景。

## 可复用决策

1. 先判断 SysV IPC 是否属于可替换的私有后端；若它本身就是公开 API 或与外部 SysV peer 的互通契约，本方案不适用，应如实披露平台限制。
2. 把原子 `semop` 数组转换成一个位于命名共享映射中的状态机，使用 `PTHREAD_PROCESS_SHARED` 的 mutex/condition 在单个临界区检查并修改读者数与写者标志。写入、通知、读完成、断线取消分别对应明确的状态转移。
3. 为共享段使用稳定的键到名称映射。写端创建、截断、映射，读端只附着；所有权决定 `shm_unlink` 时机。扩容通知应传入预期帧大小，读端在 50 ms 的有界窗口内重试瞬时 `ENOENT` 或尚未达到预期大小的段；不得把 `MAP_FAILED` 交给回调。
4. 明确保留原权限语义：POSIX 新建 fd 可被创建者持有，即使模式是 `0000`；若原 SysV `shmat` 拒绝此场景，适配层必须显式拒绝。
5. 保持上游测试注册与断言不变，完整运行跨进程、扩容、权限、工具脚本等用例，并做安装后消费者验证；单次编译或非 IPC 路径通过不足以证明语义等价。

## 验证与边界

Shmdata 1.3.74 最终冻结事务 `shmdata-w3-20260926T090700Z` 的 `conan create` 返回 0，上游注册 CTest 16/16 PASS、0 SKIP、消费者 1/1 PASS、12/12 事务回执 PASS；原始日志 SHA-256 `9e30893ae3aa57907ae0f074dd887a924f2c3d375503836b66c4b67bc3b4d466`。早先独立事务暴露了 SIGSYS、权限差异、扩容时的 `shm_open: ENOENT`，以及 HMDFS 不允许文件套接字绑定的 CI 边界，均未跨 run 拼成通过记录。CI 边界通过构建时实测 AF_UNIX 文件绑定、选择私有测试目录解决，同时保留文件监视和权限断言。

本方案只保证同一 POSIX 后端包构建的 peer 之间的协议；它不是与未经适配 SysV 程序共享同一段的 ABI/IPC 兼容层。E577 解决简单原语迁移，E584 解决不可改写 SysV 公开 API 的平台限制披露；本条的增量是**多操作同步状态机 + 命名共享段扩容时的大小感知附着**。
