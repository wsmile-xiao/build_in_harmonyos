# E547-draft-3028 — 鸿蒙 `/system/bin/sh` 的 here-document：落盘 `/tmp` 失败、不中止、静默空文件

> 状态：草稿（contributor 3028）｜ 触发事件：clitest 0.5.0 PR #11869，CI 构建 #56023
> 近邻：E482（zsh heredoc 走 `$TMPPREFIX`）、E325（test_package 的 shell 与 `mktemp` 落 `/tmp`）

## 现象

test_package 在鸿蒙 PC 真机 CI 上执行 `sh test_clitest.sh <pkg>/bin/clitest`：

```
test_clitest.sh[39]: can't create temporary file /tmp/shzijb99.tmp: Read-only file system
test_clitest.sh[46]: can't create temporary file /tmp/shl5z5d3.tmp: Read-only file system
...
PASS: --version prints 'clitest 0.5.0'
PASS: --help exits 0 and shows usage
FAIL: 3-test file passes and exits 0 -- rc=2 out='clitest: Error: no test found in input file: .../pass.txt'
FAIL: failing file reports 1 of 2 failed and exits non-zero -- ... no test found ...
...
PASS: --prefix tab parses an indented Markdown document
...
generic: 5 passed, 7 failed
```

失败的 7 条全部读取用 `cat > file <<'EOF'` 生成的 fixture；**唯一用 `printf` 生成 fixture
的用例（`--prefix tab`）通过**——被测工具的解析、执行、比对、临时目录在真机上全部正常。

## 三个特征，缺一不可地构成陷阱

1. **here-doc 必落 `/tmp`**：鸿蒙 `/system/bin/sh`（报错格式 `script[行号]: can't create
   temporary file …` 为 mksh 风格；E435 亦记录鸿蒙 sh 为 mksh）为每个 here-document 在
   `/tmp` 建临时文件，而 `/tmp` 只读。
2. **设 TMPDIR 无效**：本次 worker 自带可写 `TMPDIR=/data/storage/el2/base/cache`，脚本还在
   here-doc 之前 `export TMPDIR=<构建目录>/tmp`，here-doc 依然写 `/tmp`。
3. **失败不中止、目标变空文件**：`cat > f <<EOF` 的重定向目标先被创建，here-doc 失败后留下
   0 字节文件，脚本继续往下跑。下游拿到空输入，报出与根因毫不相干的错误
   （clitest：`no test found in input file`）。

第 3 点最危险：错误信息指向被测工具，诱导人去改无辜的工具代码或适配补丁。
CI 自动诊断把它归为「不要硬编码 `/tmp`，把临时路径改到 `$HOME`」——而脚本并没有硬编码 `/tmp`，
把 `TMPDIR` 指向 `$HOME`（HMDFS）正是本次已经做过且无效的事。

### 机制推断（真机未单独复证）

mksh 只有在 `TMPDIR` 是绝对路径、`access(W_OK|X_OK) == 0` 且为目录时才采用它，否则回退编译期
默认的 `/tmp`；而 HMDFS 上目录的 `X_OK` 判定恒为假（R49 / E524 已记录），于是指向 HMDFS 的
`TMPDIR` 被静默拒用。**修法不依赖这条推断成立**——无论机制如何，不用 here-doc 就不会踩。

## 修法

### 推荐：fixture 一律 `printf` 生成，并校验非空

```sh
printf '%s\n' \
    "\$ echo ok" \
    "ok" \
    "\$ printf 'a\\nb\\n'" \
    "a" \
    "b" \
    > "$WORK/pass.txt"

for f in "$WORK"/*.txt; do
    [ -s "$f" ] || { echo "FAIL: fixture $f is empty (shell could not write it)"; exit 1; }
done
```

- 每行一个参数，参数用双引号包裹；行内的 `$` 写成 `\$`，要保留给被测命令的 `\n` 写成 `\\n`。
- 非空校验把「静默空文件」变成指向根因的显式失败。
- 同时建议：只有环境 `TMPDIR` 缺失或不可写时才覆盖它，不要无条件改写 worker 提供的可用值。

### 回退：fixture 作为静态文件随 test_package 分发

内容大、特殊字符多、`printf` 转义过于繁琐时，把 fixture 放进 `test_package/fixtures/`，
脚本只读取不生成。

## 验证

```bash
# 设备上：here-doc 是否落 /tmp（0 字节即命中）
/system/bin/sh -c 'cat > $HOME/hd.txt <<EOF
x
EOF
wc -c < $HOME/hd.txt'

# 非鸿蒙主机离线复现同一静默空文件机制（zsh/bash 的 here-doc 同样落 /tmp）
unshare -rm sh -c 'mount -t tmpfs -o ro,size=1m tmpfs /tmp; cd $HOME && \
  zsh -c "cat > f <<EOF
x
EOF"; wc -c < f'        # 0

# 静态定位
grep -n '<<' test_package/*.sh
```

clitest 0.5.0 实测：旧脚本在「只读 `/tmp` + zsh 驱动」下复现出与 CI 逐条一致的 5 过 7 败；
改为 `printf` + 非空校验后，同场景通用 12/12、鸿蒙专项 9/9（原本 SKIP 的「只读 `/tmp` 回退」
在该场景下转为实跑通过）。

## 禁止

- **禁止**只 `export TMPDIR` 或按 CI 诊断把临时路径改到 `$HOME` 就继续用 here-doc——
  不生效，同一失败下一轮原样复现，白耗一轮修复额度（R44：连续两轮同类即停损）。
- **禁止**依据下游报错去改被测工具或其适配补丁——那只是空输入的结果。
