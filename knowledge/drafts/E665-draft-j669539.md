## 一、问题面（什么时候撞上）

KF5 Tier-1 库（零 KF5 库依赖，只要求 Qt5 Core+Qml）在 OHPCD 的 Qt5 拆包供给下，
顶层 `find_package(Qt5 5.15.2 CONFIG REQUIRED Core Qml)` 找不到能同时分发两个包组件的聚合 config：

| 包 | 形态 | config 供给 |
|---|---|---|
| qt5-qtbase/5.15.2.2 | qmake 原生构建 | 原生 per-module config（Qt5Core/Qt5Network/Qt5Gui/Qt5Test...），配方侧 cmake_find_mode=none 直连 |
| qt5-qtdeclarative/5.15.2 | 仅出库 | CMakeDeps 包级 Qt5QmlConfig.cmake（cmake_file_name=Qt5Qml） |

典型报错：`Could NOT find Qt5 (missing: Qml)`、`Target "Qt5::Qml" ... but the target was not found`、Qt5QmlConfig 内 `find_dependency(Qt5)` 循环重入。

## 二、根因

1. qtbase 原生 Qt5Config 只在自己包前缀内找组件，分不到 qtdeclarative 的 Qml；
2. CMakeDeps 为 qt5-qtdeclarative 的传递 qt5-qtbase requires 生成的小写 qt5-config.cmake 聚合不含 Qml 组件；
3. Qt5QmlConfig 的 `find_dependency(Qt5)` 回调会在聚合 shim 执行中途重入，形成互相 include 的循环。

## 三、解法（可复制）

`generate()` 内 `tc.generate()` 之后写 `generators/Qt5Config.cmake`（generators 在 CMAKE_PREFIX_PATH 最前，精确名匹配优先）：

1. **首行 `set(Qt5_FOUND TRUE)` 防重入守卫**——Qt5QmlConfig 的 find_dependency(Qt5) 回调先读到已 found 即短路；
2. `find_dependency(Qt5Core/Qt5Network/Qt5Gui/Qt5Test)` 指向 qtbase 包内绝对路径 `NO_DEFAULT_PATH`（Network/Gui 被 CMakeDeps 生成的 Qt5Qml target 接口引用，必须先于 Qt5QmlConfig 预物化；Test 服务 autotests）；
3. `find_dependency(Qt5Qml)`（走 CMakeDeps 生成的 config）；
4. 补齐 `Qt5_<Comp>_FOUND` 与 `Qt5_VERSION_STRING`，另写 `Qt5ConfigVersion.cmake`（PACKAGE_VERSION 5.15.2.2 + VERSION_LESS 兼容判定）；
5. `conan_cmakedeps_paths.cmake` 追加搜索路径接线：两包根 PREFIX/LIBRARY/INCLUDE + qtbase 的 lib/cmake + ECM share/ECM/cmake + `${CMAKE_CURRENT_LIST_DIR}`。

完整代码见 kholidays5/5.116.0 `conanfile.py generate()`（PR #14846）。
