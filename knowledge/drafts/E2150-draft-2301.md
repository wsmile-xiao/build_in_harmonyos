# E2150 - Route build-tool introspection through the Conan build environment

## Symptom

A Conan recipe successfully runs Meson setup and compilation through
`self.run()`, then fails at a later metadata query:

```text
FileNotFoundError: [Errno 2] No such file or directory: 'meson'
```

The worker profile contains the Meson directory in `[buildenv]`, so the
failure appears inconsistent with the earlier successful commands.

## Root Cause

Conan 2 activates its generated `conanbuild` environment around
`ConanFile.run()` calls in build scope. Direct Python `subprocess.run()` calls
do not consume that environment file; they inherit the recipe process's
original PATH. Build-tool availability can therefore differ inside one recipe
depending only on which process API launches the command.

## Fix

Use one production helper for machine-readable build-tool commands:

1. Format the argv with the recipe's platform-aware quoting helper.
2. Invoke it with `self.run(..., env="conanbuild", scope="build")`.
3. Capture stdout and stderr with separate `io.StringIO` streams.
4. Use `ignore_errors=True` only to recover the exact return code and error
   text, then raise on every nonzero result.
5. Parse stdout as JSON only after RC0.
6. Preserve exact inventory, duplicate-ID, missing-target, and selector
   projection checks after parsing.

Do not call `shutil.which("meson")` in the recipe process as a substitute: it
observes the same incomplete PATH as the failing bare subprocess. Do not
hard-code the worker's current Meson location.

## Validation

pkgconf 3.0.5 PR #5532 Buildbot build #26332, buildid 29163, compiled all 43
primary targets and completed a second Meson setup through `self.run`, then
failed at the first bare introspection subprocess. This proves both tool
availability in `conanbuild` and its absence from the recipe process PATH.

The repaired production methods passed a 13-case local matrix:

- empty host PATH with explicit `conanbuild/build` routing;
- nonzero stderr and stdout-only diagnostics;
- invalid test and target JSON;
- malformed or drifted test inventory;
- exact 33-name test inventory;
- exact 23-selector target projection;
- missing targets, duplicate IDs, and selector collisions;
- no remaining bare subprocess in either introspection consumer.

Replacement exact-current-HEAD CI remains the final worker integration gate.

## Safety Boundaries

- This only exposes tools already supplied by the Conan build environment; it
  does not allow undeclared library dependencies or ad hoc installation.
- Never suppress a nonzero introspection result or parse partial output as a
  valid inventory.
- Never hard-code a worker-specific executable path or mutate global PATH.
- This fix does not replace upstream tests, device evidence, Review, CI,
  submission, merge, or publication evidence.
