# E2151 - Separate compile-link proof from unavailable signed runtime execution

## Symptom

An OHOS Conan worker builds the package, completes the full upstream suite, and
links the `test_package` consumer. The test phase then stops before any consumer
assertion:

```text
ConanException: OHOS runtime execution requires signing tools: objcopy, readelf, signer
```

`can_run(self)` returned true because the build and host settings are both
OHOS/arm64, even though the worker does not contain the tools required to sign
new ELF files for execution.

## Root Cause

Conan's run-compatibility check describes the build/host settings relationship.
It is not a capability probe for the complete OHOS execution chain. In
particular, it does not establish the availability of `llvm-objcopy`,
`llvm-readelf`, or `binary-sign-tool`.

Consequently, one worker can provide a valid compiler and linker while lacking
the separate tools needed to execute the resulting binaries. Treating this as a
package build failure loses valid compile-link evidence; catching every runtime
exception as a skip would instead hide real package regressions.

## Fix

Use an artifact-first capability gate in `test_package.test()`:

1. Require the linked consumer and every packaged command to be regular files.
2. Resolve all three signing tools from the configured compiler directory and
   known tool locations.
3. If and only if one or more tools are absent, emit explicit
   `TARGET_RUNTIME_TESTS=NOT_RUN`, retain the compile-link result, and return
   before executing an unsigned ELF.
4. If the complete tool set exists, transactionally sign the consumer and
   task-private copies of every command, then run the original assertion set.
5. Keep missing artifacts, signer failures, command failures, invalid output,
   and assertion failures fatal.

Do not count the CI runtime branch as passed. A previously completed exact
target run may remain separate evidence, but it must not be relabeled as the
current CI execution.

## Validation

pkgconf 3.0.5 PR #5532 Buildbot #26988 (buildid 29985) bound the exact PR HEAD,
downloaded the source, compiled 43 primary and 125 validation targets, and
passed the complete upstream inventory 586/586. It packaged the library and
four commands, then failed only at the missing signing-tool gate in
`test_package.test()`.

The repaired production entry passed seven directed cases:

- missing tool set returns the explicit runtime-not-run state;
- complete tools sign one consumer and four command copies;
- missing consumer fails before the capability gate;
- complete artifacts plus missing tools do not execute binaries;
- a missing packaged command remains fatal.
- non-runnable build/host settings cannot bypass a missing packaged command;
- non-runnable settings return only after all consumer artifacts are present.

Exact-current-HEAD replacement Buildbot CI remains the integration authority.

## Safety Boundaries

- Do not broadly catch runtime exceptions or convert nonzero execution into a
  skip.
- Do not skip before proving the consumer and packaged command artifacts exist.
- Do not claim unexecuted runtime assertions as pass.
- Do not weaken or skip the upstream test suite.
- Do not add OHOS-named conditional macros to upstream source or patches.
- Do not install tools or mutate shared worker state from a package PR.
