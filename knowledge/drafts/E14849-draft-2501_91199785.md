# 可选硬件后端的初始化失败可使无关测试全线失败

## 现象与根因

libsigrok 的原始上游 Check suite 真正在真机运行后，76 个检查中有 46 个因 `sr_init() failed: -1` 失败；更早的日志反复出现 `libusb_init() returned LIBUSB_ERROR_IO`。`sr_init()` 在通用上下文创建时无条件初始化已编译进来的 libusb 后端，失败即退出，所以即使某测试只验证格式转换或会话，也会在 fixture 初始化阶段失败。目标机本次 `/dev/bus/usb` 不存在；这不是“缺少 Check 依赖”，也不是把所有 46 个测试分别修补的问题。

## 修复与验证

先确认 USB 后端在该目标上确实不可用且上游提供 `--without-libusb`，再用这个明确的可选配置开关构建，删除不再需要的 libusb 要求，保留 demo 和其他非 USB 功能。不要把 `libusb_init` 失败改写成成功，也不要从测试清单中删除失败用例。当前真机 run `libsigrok-w3-20261003T211200Z` 的完整 Check suite 为 76/76 PASS，注册测试程序 1/1 PASS，安装包 C API 消费者 1/1 PASS；Conan 日志 SHA-256 为 `cf56fff52cf1d01e97cff6413c54b1e41543062ad7f097f07327dc98d5153dc8`。上游 76 是 Check 测试用例数，不是测试程序个数。

## 适用范围和边界

此办法只适用于上游明示可选、目标硬件总线不可用、而库的其余功能仍有独立价值的后端。它**不**证明 USB 采集设备支持，不能用在硬件后端为任务核心验收目标的场景。既有 E581 讨论未检查 libusb 失败导致崩溃，E548 讨论消费者把环境返回值当常量；本条的增量是全局初始化阻断大量本不需要 USB 的上游用例时，如何以真实 configure feature gate 保留全量剩余测试、明确缩小交付功能，而不是放宽断言。

## 2026-10-10 增量：区分后端能力失败与生成脚本权限失败

关闭不可用可选后端并不解决所有 configure 错误。Worker #80119 的首个真实失败是 `config.status` 写入 `subs*.awk/sed/out` 被拒绝，尚未进入后端初始化或 Check suite；不能再禁用更多驱动来规避它。诊断应先按失败阶段区分生成脚本的文件系统行为与运行时硬件能力。

在 HMDFS 身份映射下，仅 owner 可访问的临时目录可能无法由实际执行身份写入。`mktemp -d` 固定创建0700目录，所以只调整外层umask或事后chmod并不足够。严格匹配 release 两个创建分支，在配方任务 TMPDIR 下以umask007排他mkdir；保留创建失败、cleanup和trap，父scratch创建后恢复调用者umask。此增量补充已有HMDFS知识：检查创建工具的固定mode以及primary/fallback完整覆盖，不改变系统权限，不共享或复用scratch，不适用于其他无关的Permission denied。

# Worker 测试诊断的增量边界（2026-10-12）
