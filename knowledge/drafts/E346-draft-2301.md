# E346 — X11 子库 configure 期依赖不可拉入图的 pkg-config 模块时，用桩 .pc + vendor 头满足它

## 错误特征

libXi 1.8.3 的 `configure.ac` 声明 `PKG_CHECK_MODULES(XFIXES, [xfixes >= 5])`，
注释明确标注 "CFLAGS only"。在 cmd-pkgs（Track B）依赖图（`libx11/6.4.0` +
`libxext/6.4.0` + `xorgproto/2025.1`）上直接 `conan create` 时，configure
阶段报 `Package 'xfixes', required by 'virtual:world', not found`。

## 触发条件

- 构建系统: Autotools，X11 家族扩展库。
- 目标轨道: cmd-pkgs Track B（`libx11/6.4.0` 不打包 `libX11.la`）。
- 依赖的 pkg-config 模块其 Conan 包（`libxfixes/6.0.2`）被 pin 在 Track A。

## 根因分析

- 已发布配方 `libxfixes/6.0.2` 依赖 `libx11/1.8.13`（Track A），且其
  libtool-shadow 机制硬性要求 libx11 包内存在 `libX11.la`。
- Track B 的 `libx11/6.4.0` 不打包 `.la` 文件，无法满足该机制。
- 若把 libxfixes 拉入本图，将与 `libxext/6.4.0 -> libx11/6.4.0` 形成
  同一图中两个 libx11 版本的冲突，无既有配方先例可解。
- XFIXES 的依赖本质上是**编译期**的：`XInput2.h` `#include <X11/extensions/Xfixes.h>`
  只消费 `PointerBarrier` typedef（`XIBarrier.c` 使用），产物 libXi.so 的
  动态依赖中没有 libXfixes.so。

## 解决方案

### 推荐方案：桩 .pc + vendor 头（构建期，不安装）

1. `generate()` 写入一个 pkg-config 桩 `xfixes.pc`（`Version: 6.0.2`），
   使 `PKG_CHECK_MODULES(XFIXES, [xfixes >= 5])` 通过。
2. 把 libXfixes 6.0.x 的 `Xfixes.h`（仅 `PointerBarrier` typedef）vendor 到
   源码 include 树 `include/X11/extensions/`（libXi 的 `AM_CPPFLAGS` 已含该目录）。
3. 两个产物都只在构建期使用，**不进入安装产物**。

`readelf` 口径验证：产物 libXi.so 的 NEEDED 中不含 libXfixes.so。

### 回退方案：整图保持在 Track A

若整个依赖图原本就在 `libx11/1.8.13`（打包 `.la`）上，直接
`requires('libxfixes/6.0.2')` 即可，无需桩方案。仅在跨轨时才必须使用桩。

## 禁止策略

- **禁止**在 Track B 图上 `requires('libxfixes/...')` 并依赖 `libx11/6.4.0`：
  libtool-shadow 机制要求 `libX11.la`，会在 make 阶段静默失败或形成双
  libx11 版本冲突。
- **禁止**把 vendor 的 `Xfixes.h` 安装进产物：它会污染下游头文件视图，
  掩盖真正的依赖缺口。
