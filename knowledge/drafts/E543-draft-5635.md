# E543 — OHOS 上 Boost.Test 预编译依赖不可用时使用已校验源码头文件

## 错误特征
上游 CMake 测试配置出现 `Could NOT find Boost (missing: Boost_INCLUDE_DIR
unit_test_framework)`；若先做 Conan 依赖安装，还可能出现
`ERROR: Missing prebuilt package for 'boost/1.84.0', 'zlib/1.3.1'`。

## 触发条件
- 构建系统: CMake + Conan
- 阶段: configure / testing
- 平台: HarmonyOS OHOS arm64

## 根因分析
上游测试工程把 `Boost::unit_test_framework` 当作链接库使用。设备的
OHOS host profile 没有匹配的 Boost 和传递依赖 zlib 二进制时，Conan
无法解析该图；不带 Conan 依赖的原始 CMake 测试配置也无法找到 Boost
头文件和测试框架库。这是测试依赖缺失，不是 header-only 被测库的
编译或链接问题。

## 解决方案

### 推荐方案
不要把不可用的 Boost 二进制加入被测包的运行时 `requires`。在
`conandata.yml` 中记录官方 Boost 1.86.0 源码归档及 SHA-256，作为
`test_sources` 下载；在 build 目录生成一个只把
`boost/test/unit_test.hpp` 替换成
`boost/test/included/unit_test.hpp` 的测试入口，编译未修改的全部上游
测试源文件，并使用 `BOOST_DISABLE_THREADS` 运行测试。sparse-map/0.7.0
在 OHOS arm64 上实测输出 `Running 156 test cases`、`*** No errors detected`。

### 禁止做法
- ❌ 不要因上游测试需要 Boost.Test 就添加不可用的 Boost/zlib 运行时依赖。
- ❌ 不要只编译一个自定义 smoke test 后把上游测试统计写成通过。
- ❌ 不要修改上游测试源文件；入口替换应发生在私有 build 目录。

## 验证
```bash
conan install --requires=boost/1.84.0 --build=never
cmake -S tests -B build
clang++ -std=c++17 -DTSL_DEBUG -UNDEBUG -DBOOST_DISABLE_THREADS \
  -isystem<verified-boost-root> -I<package-include> \
  <generated-main.cpp> <all-five-upstream-test-sources.cpp> \
  -o upstream-tests -pthread
./upstream-tests --log_level=test_suite --color_output=no
```
