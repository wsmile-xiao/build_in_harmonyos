# 共享库符号链接导致系统 Shell 崩溃的教训

## 事故经过

在编译 Python curses 模块时，发现 `libncursesw.so.6` 符号链接缺失，导致模块加载失败。尝试创建符号链接时：

```bash
cd $HOME/usr/local/lib
ln -sf libncursesw.so.6.4 libncursesw.so.6
```

结果导致系统 shell (zsh) 无法启动，所有终端命令都无法执行。

## 根因分析

1. **zsh 依赖 ncurses**：系统的 `/bin/zsh` 动态链接了 `libncursesw.so.6`
2. **符号链接断裂**：创建链接时可能破坏了原有的库链接关系
3. **库搜索路径问题**：系统在加载库时找不到正确的 `libncursesw.so.6`

## 影响范围

- 所有使用 zsh 的终端无法启动
- 系统命令无法执行
- 需要通过其他方式（如新终端、bash）恢复

## 教训总结

### 1. 不要轻易修改系统依赖的共享库

鸿蒙系统的 shell (zsh) 可能依赖用户自定义路径下的共享库。修改这些库时必须极其谨慎。

### 2. 优先使用静态库

对于系统关键依赖（如 ncurses、readline），建议：
- 编译为静态库
- 使用静态链接编译依赖它的软件
- 避免共享库问题影响系统稳定性

### 3. 编译前检查依赖关系

```bash
# 检查命令依赖的库
ldd /bin/zsh 2>/dev/null || readelf -d /bin/zsh | grep NEEDED

# 检查库文件是否被系统使用
find /bin /usr/bin -type f -exec ldd {} \; 2>/dev/null | grep libncurses
```

### 4. 恢复方法

如果不幸发生崩溃：

```bash
# 方法1：新终端中修复
cd /storage/Users/currentUser/usr/local/lib
ln -sf libncursesw.so.6.4 libncursesw.so.6

# 方法2：重新安装 ncurses
cd ncurses-source-dir
make install

# 方法3：删除自定义库，使用系统库
rm -f $HOME/usr/local/lib/libncursesw.so*
```

## 最佳实践

1. **隔离编译环境**：使用独立的 prefix 目录
2. **静态优先**：系统关键依赖优先编译静态库
3. **备份重要文件**：修改前备份原有库文件
4. **测试环境验证**：先在测试环境验证修改的安全性
