# 鸿蒙系统编译开源软件最佳实践

## 核心原则

### 1. 静态库优先

**原因**：
- 避免共享库符号链接问题影响系统
- 鸿蒙系统的 shell 可能依赖用户路径下的库
- 静态链接更稳定，无运行时依赖

**实施**：
```bash
./configure --prefix=$HOME/usr/local --without-shared
```

### 2. 独立安装目录

**建议目录结构**：
```
$HOME/usr/local/
├── bin/          # 可执行文件
├── lib/          # 库文件（优先静态库）
├── include/      # 头文件
└── share/        # 共享数据
```

**原因**：
- 不影响系统目录
- 方便管理和清理
- 避免权限问题

### 3. 编译前检查依赖

```bash
# 检查系统是否已有该库
pkg-config --exists <library> && echo "已安装"

# 检查库版本
pkg-config --modversion <library>

# 检查头文件位置
find /usr $HOME/usr/local -name "<header>.h" 2>/dev/null
```

## 常见问题处理

### 问题1：找不到头文件

**症状**：
```
fatal error: 'xxx.h' file not found
```

**解决**：
```bash
# 查找头文件
find /usr $HOME/usr/local -name "xxx.h" 2>/dev/null

# 添加 include 路径
CFLAGS="-I/path/to/include" ./configure ...
```

### 问题2：找不到库文件

**症状**：
```
cannot find -lxxx
```

**解决**：
```bash
# 查找库文件
find /usr $HOME/usr/local -name "libxxx*" 2>/dev/null

# 添加库路径
LDFLAGS="-L/path/to/lib" ./configure ...
```

### 问题3：符号未定义

**症状**：
```
undefined reference to `xxx'
```

**解决**：
1. 检查是否需要特定的编译宏（如 `-D_XOPEN_SOURCE_EXTENDED`）
2. 检查库版本是否正确
3. 考虑静态链接

### 问题4：影响系统稳定性

**症状**：
- shell 无法启动
- 系统命令无法执行

**预防**：
1. 优先编译静态库
2. 避免修改系统依赖的共享库
3. 使用独立的安装目录

**恢复**：
```bash
# 删除有问题的共享库
rm -f $HOME/usr/local/lib/libxxx.so*

# 或重新安装
cd source-dir && make install
```

## 推荐编译顺序

```
基础工具 → 压缩库 → 终端库 → 数据库 → Python → 其他
```

### 详细顺序

| 阶段 | 软件 | 编译选项 |
|------|------|----------|
| 1 | GNU coreutils | 基础工具 |
| 2 | GNU sed | 基础工具 |
| 3 | zlib | `CFLAGS="-fPIC"` |
| 4 | bzip2 | 修改 Makefile 添加 `-fPIC` |
| 5 | xz/lzma | 标准配置 |
| 6 | ncurses | `--without-shared --enable-widec --enable-overwrite` |
| 7 | readline | `CFLAGS="-fPIC" --with-shared` |
| 8 | openssl | 根据需求配置 |
| 9 | sqlite | 标准配置 |
| 10 | libffi | `--enable-shared` |
| 11 | Python | 根据需求配置 |

## 经验总结

1. **静态库是安全的选择**：虽然文件大，但不会影响系统
2. **路径隔离很重要**：使用独立目录，避免污染系统
3. **检查依赖很关键**：编译前了解系统已有的库
4. **备份是好习惯**：重要修改前先备份
5. **文档要记录**：编译过程和问题都要记录下来
