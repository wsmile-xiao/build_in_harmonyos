**问题 1（rule1，PR 模板格式 FAIL）**：

- 根因：PR 正文**整段缺失** `## 补全测试用例说明` 小节；且「上游测试用例修改说明」
  下只有 `否` 二字、未使用模板的 `- [ ] **否**，…` 复选框行。生成器只写了散文式答复，
  未按 `templates/积分赛事PR模板.md` 输出可解析的复选框。
- 修复：按模板逐字补齐两个小节的双行复选框（勾选态用 `[x]`），并与模板用词一致

- 教训：模板里的**可解析标记（复选框行）属于格式契约**，不能替换成等义散文。

**问题 2（rule12，鸿蒙特有测试 FAIL）**：

## 建议

### SKILL 设计改进

1. **把 PR 模板的复选框列为"必须逐字保留"的格式契约**：在 PR 正文生成步骤增加一条门禁/自检，
   断言 `## 上游测试用例修改说明` 与 `## 补全测试用例说明` 下各含两行 `- [ ] **…**，…`
   （勾选态为 `[x]`），任一行缺失即 FAIL。本次 FAIL 的本质是"散文等义替换了可解析标记"。
2. **在 `finish`/`submit` 之前增加"测试类型覆盖自检"**：按软件类型（可执行程序 / 库）检查
   是否存在至少一个**完整消费者端到端用例**，而不是只有冒烟断言。
   本次 rule12 的 N=0 完全可在提交前拦截。
3. **门禁脚本自身的健壮性检查**：`verify_build.py` 的门禁对**所有**软件恒告警（见问题 3），
   这类"门禁失效"应被识别为基础设施故障并显式报错，而不是降级为 ⚠️ 混入 PASS 判定。

### 模板改进

1. **PR body 模板自动填充覆盖率不足**：`补全测试用例说明` 与 `上游测试用例修改说明`
   两节的复选框未被生成器输出，是本次 FAIL 的直接原因。建议由生成器**直接渲染模板原文**
   （含复选框行），只替换勾选态，禁止自由发挥散文。
2. **`生成`占位符清理**：本次 `feedback/SKILL_FEEDBACK_*.md` 生成产物中存在
   `{BUILD_SYSTEM}`、`(请填写)` 等未替换占位符（上游仓库填"(未知)"、最终状态矛盾等），
   建议在输出前做一次占位符残留检查。
3. **test-report 模板缺少"消费者端到端 / 平台特有"两类的固定小节**：本次为记录
   `test_e2e.sh` 与 `test_ohos.sh`，需自行扩展模板结构；建议固化这两个小节。

### 自动化补全

1. **PR 正文格式自检自动化**：提交前用正则校验复选框契约 + 5 个基本信息字段 +
   `编译状态` 非空非占位符，可把 rule1 类失败消灭在本地。
2. **「鸿蒙特有测试」指标自动计数**：从 `test_package/` 的测试脚本中自动抽取用例/断言数
   （脚本已输出 `N 个用例 / M 条断言` 的汇总行），直接填入适配后统计表，
   避免人工填 0 或漏填。
3. **门禁 ⚠️ 的自动归因**：对 `verify_build.py` 的 ⚠️ 提供"是否工具侧限制"的判定提示
   （如本次 G3 的 `file` 不识别 OHOS `.codesign`），减少人工排查成本。

### 知识图谱覆盖

1. 建议新增 E-entry：**「CMakeDeps 生成的 `<Pkg>-Target-release.cmake` 以空 `_BUILD_DIRS_RELEASE`
   覆盖 `CMAKE_MODULE_PATH`，抹掉 conan 预置的 CMake 模块路径」**——本次 `Catch.cmake`
   找不到的直接根因。
2. 建议新增 E-entry：**「依赖制品的 `cpp_info.includedirs` 含子目录（如 `include/spdlog`），
   使被依赖方头文件（如 `fmt/ranges.h`）先命中该制品自带 shim，反向遮蔽真头」**。
3. 建议新增**流程类**条目：**「PR 正文模板中的复选框属于格式契约，散文等义替换会导致提审
   NEEDS_MANUAL_CHECK / FAIL」**——这一模式不属编译错误，但同样可沉淀复用。
